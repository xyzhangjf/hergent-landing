# AI 副驾回复格式 vs WorkBuddy 真实实现 · 对比分析与优化方案（v408）

> 范围：Hergent `hergent-cn-v2` 前端 AI 副驾（CopilotDrawer）的回复渲染，对照电脑中 WorkBuddy 桌面端（`/Applications/WorkBuddy.app`）真实 CSS 实现。
> 目标：① 找出我们在排版 / 结构 / 可读性上的真实差距；② 给出可落地的优化方案。本轮已落地部分见「四、本轮已落地」。

---

## 一、我们的 AI 副驾回复渲染链（现状）

| 环节 | 文件 | 作用 |
|---|---|---|
| 聊天容器 + 输入框 + 回复气泡 | `src/components/CopilotDrawer.vue` | 抽屉布局、footer 内 composer（输入框卡片）、气泡 |
| Markdown 渲染器 | `src/utils/md.js` | 自研轻量渲染器，**先转义防 XSS**，再输出带类名的 HTML |
| 类名约定 | 渲染产物 | `.md` / `.md-h1~3` / `.md-table`(元素选择器 `.md table`) / `.md-blockquote` / `.md-code` / `.md-hr` / `.md-pre` |
| 注入方式 | `v-html` | 把渲染结果塞进回复气泡 |

支持的语法：标题 `#/##/###`、粗体、斜体、行内代码、有序/无序列表、表格、引用、分割线、围栏代码块；`MEDIA:` 标记抽成文件卡。

**结论**：渲染链本身是完整可用的，问题集中在「渲染出来的 CSS 节奏」——层级平、间距小、表格不约束宽度。

## 二、WorkBuddy 桌面端真实实现（实地读码，非凭印象）

探查路径：`/Applications/WorkBuddy.app/Contents/Resources/app.asar.unpacked/resources/extensions/`

### 1. 输入框下方的「提示」范式（与本需求直接相关）
- 多行输入框 = `.wb-textarea`，外层包 `.wb-textarea-affix-wrapper`（wrapper 是视觉容器：边框/背景/圆角，textarea 去边框填满）。
- **计数器 `wb-textarea__count` 走在「正常流、位于 textarea 下方」，与内容物理隔离、不重叠。**
- 字段提示 `.ca2-fld-hint`：`color: var(--wb-color-text-tertiary, #8a9098); font-size: 12px; font-weight: 400` —— **三级灰字 + 小号字 = 低强调提示**，不抢视线。

> 这意味着：WorkBuddy 自己就是把「次要提示」放在输入框下方、用三级灰字表达。我们 v408 的 `.cp-ai-note` 采用 `--t3(#94a3b8) + 11.5px + 居中` 与之一致，范式正确。

### 2. Markdown 正文容器
- 主程序与多个扩展使用 `.prose` / `.markdown-content` 语义容器（样式类出现 50+ 处），由 Tailwind typography 提供**默认标题层级 + 纵向节奏 + 表格/列表/引用排版**——层级与留白由框架保证，不会出现「标题和正文一样大」。

## 三、差距分析（排版 / 结构 / 可读性）

| 维度 | 我们（修改前） | WorkBuddy | 差距影响 |
|---|---|---|---|
| **标题层级** | `h1/h2/h3 = 1.05 / 1.0 / 0.94em`（几乎与正文同高） | typography 默认明显分级（约 1.5–2.25em 起） | 长回复「平铺一片、没有骨架」，经销商一眼扫不清结构 |
| **纵向节奏** | 段间距 `p{margin:0 0 6px}`、行高 `1.65` | 段/标题间距由 typography 拉开 | 信息密度高但难扫读，结论淹没在文字里 |
| **表格** | `.md table` **无 `table-layout:fixed`**，单元格不强制换行 | 表格有边框 + 合理尺寸约束 | 窄气泡里长编码/单号/金额**溢出撑破布局** |
| **结构能力** | 无 TOC / 无章节折叠 / 无卡片化 | 依靠组件化 + prose 层次 | 长文（如经营建议）可读性弱 |
| **提示位** | 此前输入框下方无任何常驻提示 | 输入框下方有三级灰字提示位 | 缺少 AI 免责声明（本轮已补） |

**根因一句话**：我们的渲染器输出的是「元素选择器 + 裸字号」，而 WorkBuddy 用的是「语义容器 + 框架级排版节奏」。我们不是缺功能，是缺「层级与留白的纪律」。

## 四、本轮已落地的优化（v408，已构建验证）

| 项 | 修改前 | 修改后 | 文件位置 |
|---|---|---|---|
| 标题层级 | `1.05 / 1.0 / 0.94em` | `1.45 / 1.22 / 1.06em` + `font-weight:700` | `CopilotDrawer.vue` `<style>` |
| 段间距 | `6px` | `8px` | 同上 |
| 行高 | `1.65` | `1.7` | 同上 `.md{...}` |
| 列表/引用/分割线/代码块 | 偏小 | 间距同步放大 | 同上 |
| 表格 | 无约束 | `table-layout:fixed` + 单元格 `overflow-wrap/word-break` | 同上 `.md table` |
| **输入框下方免责提示** | 无 | 常驻「内容由AI生成，请核实重要信息」（三级灰字、居中、带图标） | `CopilotDrawer.vue` footer 模板 + `.cp-ai-note` |

构建验证（`dist-v408`）：`内容由AI生成` 命中、`copilotTurn` 0 命中、`采购结算` 0 命中、`1.45em`/`table-layout:fixed`/`14.5px` 均命中 → 隔离干净，仅含 v408。

## 六、关于本次「输入框下方提醒」的设计说明（给用户）

- **展示位置**：副驾抽屉 `footer` 内、输入框卡片（composer）正下方、模式横幅上方。整行居中。
- **样式**：三级灰字（`--t3` ≈ `#94a3b8`）、`11.5px`、左侧一个小信息图标、不抢视线（不是红色警告，是常驻免责声明）。
- **触发逻辑**：**抽屉打开即常驻显示**，每次进副驾都能看到；不依赖是否已发问/已收到回复（与 ChatGPT/Claude 的「AI 可能犯错」提示同范式，被动免责而非条件触发）。
- **可改项**：若日后想改成「仅在收到首条 AI 回复后显示」，把 `v-if` 换成 `store.chat.messages.some(m => m.role === 'assistant')` 即可（已在代码注释标注）。
