**维护规则**

1. **范本页改，规范跟着改**。范本页的骨架不是"大致这样"，而是逐条可指认的类名与

3. **数值只在范本页调，不在这里发明**。本文件不定义新值；要新值先改范本页再回来写。
4. **每次大改建单页后跑 §10.1 的类差集审计**，差集必须为空。

### R.2 行高与垂直密度

| 元素 | 实测高度 | 构成 |
| --- | --- | --- |
| 表头行 `thead tr` | **38.5px** | th padding 4px×2 + 内容 |
| 数据行 `tbody tr` | **31.8px** | td padding 2px×2 + 行内最高控件 22px |
| 明细格 文本态 `.‹pfx›-v` | **18px** | `min-height:18` + `line-height:18` |
| 明细格 输入态 `.‹pfx›-in` | **22px** | |
| 表单头字段框 | **32px** | 30px 控件 + 上下各 1px 边框 |
| 表单头框内控件 | **30px** | |
| 底部动作条 | **41px** | padding 4px×2 + 32px 按钮 |
| 表正文 `line-height` | 20.8px | 13px × 1.6 |
| `body` | 14px / lh 22.4px | `html` 16px |

🔴 **「31.8px」的传导路径**：改 `.‹pfx›-in` 的高度 = 改**整表行高**。这是"改一个控件、整表变高"最常踩的一处。
🔴 **行内最高控件决定行高**（v447 实测补记）：行高 = `td` 内距(2×2) + **行内最高的那个控件**。
   销售建单页行高一度是 **35px** 而非 31.8 —— 罪魁不是输入框，而是操作列的删除按钮用了全局
   `.btn-icon`(**30×30**)：30 + 4 ≈ 35。换成 26×26 的 `.btn-row-ic` 后立刻回到 31.8。
   ⇒ **改一个图标按钮的尺寸 = 改整表密度**，从按钮本身完全看不出这层关系（见 R.4）。
🔴 **18px → 22px 的 5px 跳变是刻意的**（v417j「点哪格哪格才是输入框」），密度收益就在这 5px。见 §11 #12。

## 1. 页面骨架：三层高度链

单据页的**全部**骨架问题都归到一件事：**底部动作条要在「内容不足一屏」时也钉在视口底沿**
（对齐舟谱 —— 合计与保存落在最底一行），内容超一屏时由页内滚动区接管。

链上有三层，缺一层就退回原状：

| 层 | 位置 | 规则 | 作用 |
|---|---|---|---|
| ① 容器 | `InventoryShell.vue` | `.page{display:flex;flex-direction:column;min-height:100%}` ＋ `.page > :deep(*){flex:1 1 auto;min-width:0}` | 让中间层**不吃掉高度**，百分比链能继续往下解析 |
| ② 页面根 | 建单页 | `.inv-page{display:flex;flex-direction:column;min-height:100%}` | 本页是竖排容器（`margin-top:auto` 在块布局里不生效，必须 flex） |
| ③ 直接子元素 | 建单页 | `.inv-page > .page-hd, > .*-hd, > .*-strip, > .*-bottom { flex: 0 0 auto }` | 除滚动区外**只取内容高度**（覆盖容器那条 `flex:1 1 auto`） |
| ④ 滚动区 | 建单页 | `.*-body{flex:1 1 auto;min-height:0;overflow:hidden}`，其内 `.table-wrap{flex:1 1 auto;min-height:0;overflow:auto}` | 唯一占满剩余高度的滚动容器 ⇒ 新增行永远落在滚动区内，不被底部条盖住 |

出处：`InventoryShell.vue` 的 `<style>`（v403 打通高度链，注释写了「改前中间层高度 auto
⇒ 百分比链断开」的实测）＋ `InvPurchaseNew.vue` 的 `.inv-page` / `.ipn-body` 段（v431）。

🔴 **`min-height:0` 不能省**：flex 子项默认 `min-height:auto`，会让滚动区被内容撑开、
`overflow:hidden` 失效 —— 表现是「表格能滚、底部条被顶到屏幕外」。
🔴 **`margin-inline:-20px` 与 Shell 的 `.view-wrap{padding:20px}` 是唯一耦合点**：
那份 padding 改了，底部条的负边距要跟着改（`InvPurchaseNew.vue` 已注明）。

## 2. 表单头：框式字段（复刻舟谱）

**观感目标**：舟谱建单头是「**一个描边框**里左边标签、右边值」（`*供应商: 🔍`｜
`*经办人: 请选择 ▾`），**不是**「标签在框外、旁边再放一个框」，也**不是**标签在上、
框在下两层。后者每格约 48px（12px 标签 + 4px 间距 + 32px 框），前者压到 **32px**，
且一行能并更多字段 —— 舟谱那排紧凑感就来自这里。

### 2.1 结构

```html
<div class="<pfx>-hd <pfx>-hd-flat <pfx>-hd-box">
  <div class="<pfx>-f">
    <label class="<pfx>-lb"><span class="<pfx>-req">*</span>供应商</label>
    <input class="input <pfx>-kw" ... />
    <select class="input <pfx>-sel" ...></select>
  </div>
  <div class="<pfx>-f <pfx>-f-grow"> <!-- 唯一吃余量的格 -->
    <label class="<pfx>-lb">备注</label>
    <input class="input <pfx>-note-in" maxlength="500" />
    <span class="<pfx>-cnt">0/500</span>
  </div>
</div>
```

`<pfx>` = 页面级前缀（`ipn-` 采购建单 / `isn-` 销售建单）。**同一件事在不同页用同一个
后缀名**（`-hd` / `-hd-flat` / `-hd-box` / `-f` / `-f-grow` / `-lb` / `-req` / `-sel` /
`-strip` / `-body` / `-bar` / `-tip` / `-bottom` / `-total` / `-save`），前缀区分页面。

### 2.2 关键规则（每条都对应一个真实的坑）

| 规则 | 出处 / 为什么 |
|---|---|
| `.‹pfx›-f{display:flex;flex-direction:row;align-items:center;gap:6px;flex-wrap:wrap;flex:none}` | `flex:none` **必需**：少了它 `flex-shrink` 会把没有 `min-width` 的格挤窄，格内「标签 + 控件」随即被 `flex-wrap` **拆成上下两行**（老板实际报障过「经办人/部门/入库仓库」三格） |
| 外层头 `.‹pfx›-hd{align-items:center}` | 标签与框同行后，一行内没有「底部对齐」可言，居中才齐（原为 `flex-end`） |
| `.‹pfx›-hd-flat{padding:0;background:transparent;border:0;box-shadow:none}` | 页面底与 `.card` 同色，那圈框本来只是 border+shadow。scoped 特异性 0,2,0 > 全局 `.card` 0,1,0，覆盖必然生效（不需要 `!important`） |
| 框 = `.‹pfx›-hd-box .‹pfx›-f{padding:0 6px 0 10px;background:var(--bg3);border:1px solid var(--bd);border-radius:var(--radius-sm);flex-wrap:nowrap}` | 框本身就是那一格，标签与值是框内的 flex 子项 |
| 框内控件 `{width:auto;height:30px;padding:0 2px;border:0;border-radius:0;background:transparent;box-shadow:none}` | 🔴 全局 `.input` 是 `width:100%` —— 在横排框里会解析成「撑满整框」并把标签挤出去；且不去边框就是「框里再套一个框」 |
| `:focus-within` 上移到框：`border-color:var(--p-dark);box-shadow:0 0 0 3px var(--p-bg)`，并关掉框内控件的 focus 环 | 否则一大一小两层环 |
| 标签冒号由 `::after{content:'：'}` 生成 | **不改模板文案** —— 文案里加冒号会在窄屏换行时被留在行尾 |
| 框内控件宽度用**实测值**写死（下拉 112 / 日期 120 / 备注 `flex:1`） | 112 是「本租户仓名『东津仓』3 字 + 日期串 `2026/10/10` 完整显示」的实测下限，再窄会把日期控件的日历图标挤掉 |
| 窄屏媒体查询里要**重新写一遍**框内控件宽度 `{width:auto;flex:1;min-width:0}` | 定宽规则的特异性 0,3,0 高于 `.‹pfx›-sel` 0,1,0，不重写会把「全宽」顶掉，留下 112px 短框 + 右半行空白 |
| 退货模式头**不套** `-hd-box` | 那排有**只读格**（§2.4），虚框是"这格不可改"的既定语义 |

### 2.3 必填与选填

- **必填**：`<span class="‹pfx›-req">*</span>` 放在标签**最前**，色 `var(--dan)`。
  **不写「必填」两个字** —— 每个必填格省 2 个字宽，一行更容易并下全部字段。
- **选填**：**什么都不写**。无红 `*` 即选填，与「有 `*` ＝必填」配成一对。
  🔴 撤掉「选填」小字后**不要**顺手加校验 —— 撤的只是文案（`InvPurchaseNew.vue` 的
  「经办人 / 部门」至今仍是选填，改文案没改行为）。

### 2.4 只读格

非编辑态的值用 `<span class="‹pfx›-ro">`：`min-height:32px` + **虚线**边框 +
`background:var(--bg2)`。

🔴 **不要用 `disabled` 的 input** —— 那会让人以为「点一下就能改」。
虚线才是「这一格不可改」的通行读法。

## 3. 读数条（`-strip`）

位置：表单头之下、明细之上。一行放**跨行的派生读数**（供应商应付/预付余额、账期、
已录项数、合计…）。外观：品牌色浅底 `var(--p-bg)` + `var(--p-border)` + `--radius-md`。

两条口径（都来自 `InvPurchaseNew.vue` 的实测）：

1. **没有值就整条不渲染**。未选供应商时把 `-strip` 隐藏 —— 空态下它与上方表单、
   明细标题行、底部合计**三处重复**，白占一行。
2. 🔴 **「不知道」写 `—`，不写 `0`**。读取中显示 `…`；读取失败或字段不存在显示 `—`；
   读到了即便 `¥0.00` 也照实显示。把「没读到」显示成 `0` 就是编数
   （本仓反复出现的静默失效）。

## 4. 明细表与列设置齿轮

### 4.1 表格

- 表容器：`.table-wrap`（滚动，见 §1）内 `<table class="tbl ‹pfx›-tbl">`。
- **第一列固定为「序号」**（`<td class="seq-cell"><span class="seq-num">`），
  且该表头格**被列设置齿轮占用**（§4.2）。
- 数字列 `class="num"` + `font-variant-numeric:tabular-nums` + 右对齐。
- 金额列加 `white-space:nowrap`（「¥1,234.00」断行会把行高顶起来）。
- 🔴 **出厂预设 15 行空行**（`PRESET_ROWS = 15`，两页同值，见 §4.3）。
  空行不参与校验、不落库（`submit` 前过滤掉没选商品的行）。
- 行内可编辑控件 `class="input ‹pfx›-in"`。
  🔴 **v444 起可编辑格一律 `background:transparent`**（只留极淡描边）—— 见 §4.5。
  （v436 曾给它们铺 `var(--bg3)` 底色，15 行 × 13 列铺下来是满屏灰底方块，压过了数据。）
- 行内操作按钮用 `<Icon>` 图标按钮（不是文字链接）：`新增` / `删除` 占位更小，
  不会和「行备注」列在扫读时混在一起。
- 解释性小字（换算、原单数量）用 `.‹pfx›-conv`：11px + `var(--t3)` + `nowrap`。
  它是**解释**不是数据（数据以输入框里的为准）。

### 4.2 列设置齿轮（必须用共享实现）

  <button class="col-cfg gear" @click.stop="openColMenu" title="列设置">
    <Icon name="settings" :size="15" />

<!-- 面板：常驻挂载，内部 v-if 控制显隐 -->

import { useColSettings } from '../../composables/useColSettings.js'

const COLS = [

`ColMenuPanel.vue`（面板 + 现算定位）＋ `src/styles/col-menu.css`（长相，已在

🔴 **不许在页面里再写一份**：
- 页面**不要**自己 `useColMenu()` + `useColPrefs()` 手写 `colVis/isVisible/toggleCol`；
- 页面**不要**再写 `.col-menu*` / `.col-gear-th` / `.col-cfg.gear` 的 scoped 样式

- 同理不要删掉页面里那几个类的**绑定**：绑定承载语义，删了看不出"这里本该有样式"。

`<page-key>` 决定云端偏好键。**收敛实现时页面键不能改** —— 改了等于把用户已保存的
列显隐设置全部重置。

> 边界：列表页那套面板（`InvPurchaseList.vue`）带**自定义字段增删**与**方案管理**，
> 是共享面板的**超集**，不套本节；它用自己的面板实现，但齿轮按钮与 `.col-menu` 外壳
> 仍走全局层。

### 4.3 明细表的必填项：**红 `*`**（v444）

表头里**必填列**打一枚红 `*`，用的**必须是与表单头「供应商 / 客户」同一枚标记**
（采购页 `.ipn-req` / 销售页 `.isn-req`）—— 这是"统一"唯一的机械判据，
**不许**为表头另起一个类名或另写一份色值。

```html
<th class="ipn-c-prod"><span class="ipn-req">*</span>商品<ColResizeHandle … /></th>
```

🔴 **红心的集合由 `validate()` 决定，不是由"看起来该填"决定** —— 两处必须逐字对账：

| 页面 | 打 `*` 的列 | 对账对象（实际拦人的那个函数） |
|---|---|---|
| 采购订单表 | 商品 / 采购价 / 订单数量 | `validate()`：数量 > 0、采购价非空且 ≥ 0 |
| 采购退货表 | 退货数量 | `validateReturn()`：至少一行 > 0 且不超可退 |
| 销售订单表 | 商品 / 数量 / 单价 | `validate()`：数量 > 0、单价非空且 ≥ 0 |
| 销售退货表 | 退货数量 | `validateReturn()`：同上 |

**不打 `*` 的**：金额（算出来的）、单位（系统带出）、条码 / 库存 / 参考价 / 批次 / 行备注。
自动对账方式：探针 `v444-psi-new-e2e.mjs` 的 B 相会读出每枚红心所在的列名，
与这张表逐字比对（多一枚少一枚都 FAIL）。

### 4.4 列宽拖动（v444）

每列（**除序号列与 sticky 的操作列**）在表头挂一枚手柄：

```html
<th class="ipn-c-prod" :style="wStyle('prod')">商品<ColResizeHandle col="prod" :start="startResize" :reset="resetColW" /></th>
```

```js
import { useColResize } from '../../composables/useColResize.js'
import ColResizeHandle from '../../components/ColResizeHandle.vue'

const { wStyle, startResize, resetColW } = useColResize('<page-key>', COLS)
```

**四条实现约束**（都是实测出来的，别改回去）：

1. `wStyle()` 必须同时给 **`width` 和 `min-width`** —— CSS 里 `.ipn-c-prod{min-width:240px}`
   这类既有规则会**挡住拖窄**，只内联 `width` 时"往窄拖不动"。
2. `startW` 从 th 的 `getBoundingClientRect()` **现量**，不从 CSS 常量读
   （真实宽度是浏览器按内容算的，写死会和实际差几十像素 ⇒ 一按下列宽就跳）。
3. `mousemove` / `mouseup` 挂在 **document** 上（手柄只有 7px 宽，挂手柄上拖出去就断）。
4. 上限 `MAX_W = 2400` **必须高于任何列的默认宽**。实测销售建单页在 1600px 屏上
   「商品」列默认就有 **794px**，把上限设成"看起来够用"的 720 会让**拖宽变成越拖越窄**。

**交互**：拖动手柄调宽；**双击手柄 = 恢复该列默认宽**（不改全局、不影响其它列）。
手柄样式在全局 `styles/col-menu.css`（`.col-rsz`），**不在页面 scoped 里**。

🔴 **列宽只存本机 `localStorage`，不上云** —— 与列**显隐**（上云，v411）刻意不同：
列宽跟**这台设备这块屏**走，把 27 寸上拖好的宽度推给笔记本甚至手机端是负价值。
详见 `useColResize.js` 文件头。

> 订单模式与退货模式**各一份宽度**（`useColResize('<page-key>')` 与
> `useColResize('<page-key>-ret')`）—— 同一张表两种模式下列不同，共用一份 key 会互相顶掉。

### 4.5 明细表输入框：**不许有底色**（v444）

```css
table.ipn-tbl .ipn-in:not(:focus) { background: transparent }   /* 采购 */
table.isn-tbl .isn-in:not(:focus) { background: transparent }   /* 销售 */
/* v445 起连描边也不画（三态见 §4.6） */
.ipn-v { background: transparent; box-shadow: none }
```

🔴 **必须显式写 `transparent`，不许靠"删掉规则"来撤底色**：全局
`.input{background:var(--bg3)}` 还在，删规则只会让输入框**退回全局灰底** ——
这是典型的「样式看着改了、实际没生效」。

「哪里能填」改由 **hover / focus 反馈**承载，不再靠底色 —— 描边的三态见 **§4.6**：
- 常态：**无底也无框**；
- 行 hover：浮出 `var(--bd)` 淡灰描边；
- 格 focus：描边变 `var(--p-dark)` 品牌青 + 3px 外发光。

🔴 **只撤明细表**：表单头的**框**（`.‹pfx›-hd-box .‹pfx›-f`，就是「供应商 / 客户」那一格）
**仍保留 `var(--bg3)` 底色** —— 用户要的是"明细表不压抑"，不是"全页无底色"。
这条由探针 C 相反例自证（表单头框必须非透明）。

### 4.6 明细表输入框：**边框三态**（v445）

v444 撤的是**底色**，v445 撤的是**边框** —— 两步合起来才是"默认态整行就是一排文字"。

```css
/* 默认：无框（🔴 只切 border-color，border 宽度仍是 1px ⇒ 盒模型不变 ⇒ 零抖动） */
table.ipn-tbl .ipn-in:not(:focus) { background: transparent; border-color: transparent }
/* 悬浮：淡灰描边，**整行一起浮起** */
table.ipn-tbl tr:hover .ipn-in:not(:focus):not(:disabled):not([readonly]) { border-color: var(--bd) }
/* 聚焦：品牌青描边 + 淡青外发光 */
table.ipn-tbl .ipn-in:focus { border-color: var(--p-dark); box-shadow: 0 0 0 3px var(--p-bg) }
/* 禁用 / 只读：永不浮框 */
table.ipn-tbl .ipn-in:disabled, table.ipn-tbl .ipn-in[readonly] { border-color: transparent; box-shadow: none }
/* 校验错误：红框默认可见，连聚焦发光也要写回红色 */
table.ipn-tbl .ipn-in.err, table.ipn-tbl .ipn-in.err:focus { border-color: var(--dan) }
table.ipn-tbl .ipn-in.err:focus { box-shadow: 0 0 0 3px var(--dan-bg) }
```

四条约束（改错任何一条都会留下难查的坑）：

1. 🔴 **用 `border-color: transparent`，不许 `border: none`**：写 `border:none` 输入框宽高各缩
   2px，15 行 × 13 列一起跳 ⇒ 整表抖动。保留 1px 透明边框是"预留占位" —— 切换只改颜色、
   **不改盒模型**，这是"零尺寸抖动 / 零行位移"唯一的可靠做法。
2. 🔴 **focus 的"更清晰"靠"换色 + 外发光"，不许加粗 border**：加粗同样改盒模型 ⇒ 同样抖。
   外发光是 `box-shadow`，不占布局，是这里唯一安全的加强手段。
3. 🔴 **hover 与 focus 必须是"颜色 + 发光"双重区分，不能只靠深浅**：深浅在深色/浅色两套主题下
   总有一边看不出来；灰(`--bd`) ⇄ 青(`--p-dark`) 在两套主题下都成立。悬浮**不给**外发光，
   发光是聚焦专属 —— 这样两态一眼可分。
4. 🔴 **三条必须显式写回**：「默认透明」的选择器权重 (0,3,1) **高于**全局
   `.input.err` / `.input:disabled` / `.input[readonly]` 的 (0,2,0) ⇒ 不写回就会把
   **校验红框一起变没**（典型静默失效）。禁用 / 只读同理：给它们浮框等于承诺"这格能填"，
   点了没反应比没框更糟（退货明细「退货数量」无可退量时就是 `disabled`）。
   另外 `.err:focus` 的**红色外发光**也要写回，否则被上面的青色外发光盖成"红框配青光"。

采购页的文本态格（`.ipn-v`，v417j「点哪格哪格才是输入框」）同口径，但描边用
`inset box-shadow` 而不是 `border` —— 它是 span，加 border 会把行高顶起来（紧凑档会切字）：

```css
.ipn-v { background: transparent; box-shadow: none }
table.ipn-tbl tr:hover .ipn-v { box-shadow: inset 0 0 0 1px var(--bd) }
.ipn-v:focus { outline: none; box-shadow: inset 0 0 0 1px var(--p-dark), 0 0 0 3px var(--p-bg) }
```

⚠️ **采购页点击激活成输入框时行高会从 18px 变 22px** —— 那是 v417j「文本态比输入框态矮约
5px」的**既有设计**，**不是**边框切换引起的抖动。因此「零抖动」的硬判据放在**销售页**
（常驻 input，三态切换盒模型一字不变）；采购页只验"悬浮前后**同一个 `.ipn-v`** 尺寸不变"。
判据见 §10.5。

### 4.7 明细格「两态值一致」：字号 / 内距 / 圆角（v447）

输入态 `.‹pfx›-in` 与文本态 `.‹pfx›-v` 是**同一个格的两种形态** ⇒ 除"这格能编辑了"以外，
视觉上必须**逐值一致**。只写 `width/height` 的话，其余属性会走**继承**（全局 `.input` + `body` 字号），
于是"点激活"的那一刻三处同时跳，像换了个控件：

| 属性 | 文本态 `.‹pfx›-v` | 输入态（**只**写 width/height 时） | 输入态（正确写法） |
| --- | --- | --- | --- |
| 字号 | 13px（显式写） | **14px**（继承 `body`） | **13px** |
| 内容内距 | `0 4px` | **`0 14px`**（全局 `.input`） | **`0 3px`** + 真边框 1px = **4px** |
| 圆角 | `var(--radius-sm)` = 8px | **`var(--radius-md)`** = 12px（全局 `.input`） | **`var(--radius-sm)`** = 8px |

```css
.‹pfx›-in { width: 100%; height: 22px; font-size: 13px; padding: 0 3px; border-radius: var(--radius-sm) }
```

🔴 **内距为什么是 3px 而不是 4px**：输入态有**真边框 1px**（占位），而文本态 `.‹pfx›-v` 的描边是
`inset box-shadow`（**不占位**）⇒ `1 + 3 = 4`，两态内容内距**逐像素相等**，点激活时文字左右不动
（真机实测 `textLeft` 两态完全相同，Δ=**0px**）。

🔴 **这三个值在页面 CSS 里一个都看不到** —— 它们是**继承**来的。只读源码会以为"没写就没问题"，
**必须真机 `getComputedStyle` 量**才看得见（探针见 §10.6）。
同理，新写建单页时**不要**照抄"只写 width/height"的写法。

⚠️ **高度不在此列**：文本态 18px / 输入态 22px 那 5px 是 v417j 的**刻意设计**（密度收益）。
且实测它**不改变行高**（所在 `tr` 两态都是 31.8px）—— 只记录，不"抹平"。

## 6. 模式与路由：一条 path，两个 query

进销存把「订单 / 退单」做成**同一 path + 不同 query**，从侧栏「＋」带入：

| query | 含义 |
|---|---|
| `?kind=order` / 缺省 | 建单 |
| `?kind=return` | 建退货单 |
| `?type=self_pickup｜vehicle_sale｜transfer` | 出货方式（销售路线） |

🔴 **模式必须写成 `computed` + `watch`，绝不能取一次性常量**：
同一 path 下 query 变化时，vue-router **复用同一个组件实例** ⇒ `onMounted` 不会再跑，
页面会停在旧模式/旧数据上，而且**零报错**（`InvPurchaseNew.vue` 头部注释、
`InvSaleNew.vue` 文件头都记了这条）。

```js
const kind = computed(() => String(route.query.kind || 'order'))
const isReturn = computed(() => kind.value === 'return')
watch([qType, kind], () => { reinit() })          // 可重入的初始化
```

`reinit()` 的两条纪律：
1. **可重入**（能反复跑，不累积状态）；
2. **清空对方的模式状态** —— 不清就会出现「退货页面上挂着几张采购/销售明细」
   这种自相矛盾的屏幕。

另外：**未知 query 值一律不认**（`ORDER_TYPE[qType] ? qType : 'self_pickup'`）。
把脏 query 传下去 / 拿它当筛选条件，会静默筛出空列表。

## 7. 数据绑定与单位口径

### 7.1 绑定

- 文本：`v-model.trim`（首尾空格几乎总是误输入）；数字：`v-model` + `Number()` 转换。
- 数字框一律加 `inputmode="decimal"`（唤起数字键盘，手机上差一整个键盘）。
- `v-for` 的 `key` **不能用下标**：用 `uid`（删中间一行会让后面所有行的 DOM 复用错位，
  输入框内容跟着串）。退货明细行可用 `product_id + '-' + i`。
- **空行不参与校验、不提交、不计项数**：预设的空行是给用户预备的
  （`filledRows = items.filter(r => r.product_id > 0)`）。留着空行就提交不了是最常见的
  「表单太严」抱怨。

### 7.2 单位口径（🔴 两条路线**不同**，别互相抄）

| | 采购路线 | 销售路线 |
|---|---|---|
| 明细表换算比列 | **有**（`base_qty` / `base_ratio`，v409 建单时快照） | **没有** |
| 单位可选档位 | 三档（小/中/大，后端 `unit_options` 下发） | **不可选**，只显示商品档案的报单单位 |
| 前端是否换算 | **不换算**（只读 `ratio` 显示「折小单位价/量」两行提示，入库折算由后端现算并快照） | **不换算**（只有一个量纲，没有第二份实现可写） |

- 报告单/录入单位**永不落大单位**。单位唯一权威是 `products.order_unit`
  （`refs().products[].order_unit`），回落到 `unit` 时**要用弱色标注**，不静默。
- 🔴 **换算比的唯一实现在后端**（`db/queries/units.py`），页面**不许**自己乘除。
  换算比来源列是**混类型**（`medium_ratio` 有 191 行是空串），`'' > 0` 在 SQLite 为真、
  在 JS 为假 ⇒ 同一条规则两端结论相反。这也是为什么退货的「可退量」由**后端算**
  （`return-preview` 端点）。
- 复用说明文案前先看它讲的是哪条路线：`PSI_NOTES.unit` 讲的是**采购**的三档单位，
  销售建单页照抄会把用户引到错的操作上（`InvSaleNew.vue` 已注明不用它）。

## 8. 校验、交互反馈与「不许静默」

### 8.1 校验

- **前端校验只用于「提前告知」**。唯一强制的判据在后端（例：退货上限
  `quantity ≤ 可退量` 在 `psi_sale_return` 端点重算；信用额度在
  `routers/sales.py::create_sale` 体内，**不在 db 层**）。
  前端再写一份 = 同一规则两个实现，边界上必然分岔，且「界面说没超、后端 400」
  是最伤信任的组合。
- 校验函数返回**首错字符串**，`toast(bad, 'warn')` 后 `return`。错误文案要能定位：
  `第 3 行：数量要大于 0`，不是「参数错误」。
- 后端 400 的中文原因**原样显示**（`toast(e.message, 'error')`），不改写、不吞掉。

### 8.2 交互反馈

| 场景 | 做法 |
|---|---|
| 提交中 | `saving` ref 同时禁用主按钮并改文案「提交中…」 |
| 防重复提交 | **幂等键**：进页面生成一次 → 提交带上 → **成功后立刻换新键**。<br>🔴 不换键的后果：第二次提交会被后端当成第一次的重放，**静默什么都不做** |
| 成功 | `toast(..., 'success')`，然后**跳到一个"能看见这次操作结果"的地方** |
| 失败 | `toast(e.message \|\| '…失败', 'error')`。**禁止 `catch {}`** |
| 加载中 | `<div class="state-empty">正在读取…</div>` |
| 空 | `<div class="state-empty">` + **一句人话说明为什么空** |
| 读取失败 | `<div class="state-error">` + 原因 + 「重试」按钮 |
| 阻断原因 | 后端给了 `reason` 就**照显** —— 不许让用户对着一个点不动的按钮猜为什么 |

### 8.3 「不许静默」的三条硬判据

1. **「没查到」≠「是 0」**：`rows` 里没有某个 id ⇒ 查过了、真的是 0；
   只有**请求失败**才显示 `—`。用失败去显示 0 就是编数。
2. **恒空/恒 0 且零报错 = 静默失效**，按缺陷处理。
3. **失败必须显式**：写操作要区分「真没有」与「参数没传对」。

> 本规范自证了一次：`InvSaleNew.vue` 的退货成功**不跳**「退单列表」，而 `InvPurchaseNew.vue`
> 的**跳**。这不是不一致 —— 采购退货会回写源单状态（`purchase_orders.status='returned'`），
> 那张列表筛得出来；**销售退货不回写**源单状态，跳过去会是一张空表。
> 所以两边各自选了"能看见结果"的落点：采购回列表，销售**就地刷新**可退明细。

🔴 **本探针踩过的三个坑**（同族任务必看，前两个直接造成了假 FAIL）：

1. **聚焦后必须等过渡走完再量**：把 `el.focus()` 与 `getComputedStyle` 写在同一个 `eval` 里，

2. **数值型量测不要拿字符串比**：`getBoundingClientRect().height` 量出来是**数字** `22`，
   判据写成 `=== '22px'` 会恒 FAIL —— 而它**打印出来就是 `22`**，看着完全正确，最难发现。
   假 FAIL 比漏测更耗时间。
3. **"首屏行数"不能当对齐判据**：两页结构不同（销售页明细区上方多「客户条 + 提示条」）⇒
   滚动容器高度差 73px，行数天然不等（22.33 vs 20.03）。**行高相等**才是可判据的那一项（见 §R.9）。
