## 5. 🔴 三个必须先解决的缺口

### 5.1 🔴🔴 `/api/psi/sale-orders` 压根不接收 `order_type` —— 独立页面会变成「只改皮」

**证据链**：
1. `server/routers/sales.py:123-145` 的 `db.sale_order_create(...)` 调用是**位置传参**，
   列举完 20 个位置参数后是 5 个 `getattr(payload, …)`（`customer_po_no` / `promise_date` /
   `tax_rate` / `tax_amount` / `skip_credit_check`）—— **通篇没有 `order_type`**。
   `grep -n "order_type" server/routers/sales.py` 只命中 `208`（list 的入参）与 `245`（list 的调用）。
2. `server/db/queries/sales.py:101-104`：`order_type` / `sub_order_no` **只在非空时**进 INSERT。
3. 全仓 `sale_order_create(` 的调用点里，**只有** `server/routers/zhoupu_documents.py:734`
   传了 `order_type=head["order_type"]`（舟谱文档导入通道）。
4. 生产实证（`tenant_1.db`，2026-10-11 直连查询）：
   `self_pickup` **22254** / `transfer` **251** / `vehicle_sale` **0**。
   —— 251 张 `transfer` 全部来自舟谱导入；**车销一张都没有**。

**后果**：① 自提 / 车销 / 调拨三个订单页建出来的单，**落库完全相同**（一律 `self_pickup`）；
② 清单页按 `order_type` 筛（`server/db/queries/sales.py:364`）**永远筛不出车销**；
③ 老板要的「独立页面」在业务上**没有任何区别**，只是三个长得不同的皮。
⇒ **这一条不修，独立页面等于白做。**

### 5.2 🟡 销售侧「部门」无处落
`sale_orders.department` 列在库里，但 `sale_order_create` **没有** `department` 参数
（对比：`purchase_order_create(..., department_id=0, ...)` `server/db/queries/purchases.py:187-188`）。
⇒ 舟谱表单头的「*部门」在销售侧要么补后端参数，要么不做。

### 5.3 🟡 调拨的「调出仓 → 调入仓」在 `sale_orders` 里表达不了
`sale_orders` 只有**一个** `warehouse_id`。系统里**另有**一条真正的双仓通道：
`transfer_order_create(product_id, product_name, from_wh, to_wh, quantity, operator_id, note, items)`
（`server/erp_db.py:14218`）→ 表 `transfer_orders`（含 `from_warehouse_id` / `to_warehouse_id`）
→ 端点 `POST /api/inventory/transfer-orders`（`server/routers/inventory.py:215-230`）
→ 过账 `POST /api/inventory/transfer-orders/{tid}/complete`。
**但**：`transfer_orders` 生产 **0 张**，且 `hergent-cn-v2` 前端**完全没有**调用它
（grep `transfer-orders` 无匹配）⇒ 这是一条**已存在但从未接过 UI** 的通道。
（`transfer_stock` `server/db/queries/inventory.py:290` 是即时库存移动原语，**不建单**，
唯一调用方是 `POST /api/inventory/transfer` `server/routers/inventory.py:193`。）

⇒ 调拨页有**两条路**，代价差别很大（见 §7 决策 B）。

| 自提订单 | `/inventory/sale/self-pickup/new` | `SelfPickupOrderNew.vue` | 新建自提订单 |
| 自提退单 | `/inventory/sale/self-pickup-return/new` | `SelfPickupReturnNew.vue` | 新建自提退单 |

### 6.2 目录与共享内核（🔴 不复制实现 —— 规范 §10.7 白名单）

```

  ├─ docTypes.js              ← 7 份类型配置（path / title / 副标题 / 表单头字段 / 明细列 / 接口 / 校验）
  ├─ DocFormShell.vue         ← 唯一渲染内核（页面头 / 表单头 / 读数条 / 明细表 / 底条），按配置渲染

  ├─ PurchaseReturnNew.vue    │

  ├─ VehicleSaleReturnNew.vue │
```
