# 模块开发通用规范（从「仓配 → 资金管理」两轮沉淀 · v465d 立 / v469 补「能力闸门配方」）

> 定位：给**下一个模块**（数据报表 `/reports/*`、市场营销 `/mkt/*`…）用的「开工手册」。
> 它只保留**跨模块可复用**的骨架与纪律；各域细节仍写在各自的域规范里
> （`docs/仓配模块开发规范.md`、`docs/资金管理模块开发规范.md`）。
>
> 一句话方法论：**先把界面上的"入口"立起来占位，再按"落真身四步"逐页替换，
> 全程守"唯一源"纪律（一处定义、多处引用），每步都用实测证据收尾。**

---

## 1. 起手式：后端能力盘点（别凭印象造轮子）

做任何写操作前，先回答三件事，**用命令回答，不用记忆回答**：

```bash
# ① 这个域现存哪些后端前缀
grep -rn "prefix=" <后端>/routers/*.py

# ② 归哪个权限模块（注意：首个 startswith 命中即停）
grep -n "_PATH_MODULE_MAP" -A 60 <后端>/server.py | head -80

# ③ 带真实 token 实测（这一步才是判据，前两步只是猜）
curl -H "Authorization: Bearer $TOKEN" <域名>/api/xxx
```

🔴 **「有模块 / 有页面 / 标签写着XX」都不等于「真的能用」**。只有第 ③ 步通过了才算数。
（这是本项目反复证明的一条：设计稿和文档会骗人，curl 不会。）

## 1.2 并行会话先查占用（每次开工前 3 分钟，省 3 小时）

```bash
git status --short          # 有没有别人改了一半的东西
git worktree list           # 有没有并行 worktree
```
**并行开发的铁律：按「缝」切分 + 门口串行。** 改入口表（`pages.js`）和路由表
（`router/index.js`）时尤其小心 —— 这两处是全站共享的窄口，冲突概率最高。
本次资金模块**只新增资金域文件 + 只改资金相关的登记行**，没碰仓配/报表的实现。

## 2. 🔴 落真身四步（通用骨架）

占位页 → 真实页，少一步就是本站定义的两种"假"之一：

| 步 | 在哪改 | 漏了的后果 |
|---|---|---|
| 1 | `constants/pages.js`：从 `PLACEHOLDER_PAGES` **移出**，`PAGE_RULES` 写正式行 | 不移出 ⇒ 被合并循环**覆盖**；移出不补行 ⇒ `ruleFor` 返回 null ⇒ **对所有角色全开**（丢了窄名单） |
| 2 | `router/index.js`：在 `...PLACEHOLDER_PAGES.map(...)` **之前**加真实路由 | 缺路由 = **假封锁**（入口在、点了 404/占位） |
| 3 | 三处名字对齐：`meta.title` = `pages.js` 的 `title` = `Shell.vue` 的 `name` | 不一致 = 守卫提示"你没有访问「旧名」的权限" ⇒ 提示比界面早一代 |
| 4 | 构建 + **服务端实测**（双向，见 §5） | 只跑 build = 自欺欺人 |

> 第 2 步的「之前」是硬要求：vue-router 按声明顺序/打分匹配，占位 map 放最后当兜底。

## 3. 唯一源纪律（一处定义、多处引用）

| 东西 | 唯一源 | 反例（禁止） |
|---|---|---|
| 页面可见性 | `constants/pages.js::PAGE_RULES` | 在 `Shell.vue` 里另写 `v-if` |
| 单据中文名 / 状态 / 对方类型 | `constants/fundLabels.js` 这类词表 | 各页 hardcode「收款单」 |
| 金额显示 | `psiLabels.fmtMoney` | 各页自己 `toFixed(2)` |
| 列表单位/口径 | 域规范里先写死再实现 | 边写边定 |

🔴 唯一源失效的典型表现：**改了一处、界面不变**（因为还有第二处没改）。

## 3.5 🔴 把某模块做成「真·能力闸门」的五处同批配方（v469 沉淀）

**什么叫「真·能力闸门」**：权限页 (`Settings.vue`) 里能对该模块**单独勾选开关**，
而不是只靠角色名单（`roles: [...]`）来放行。区别在于 ——
纯角色轴只能"按身份一次性给全"，能力闸门才能"给这个客户开、那个客户不开"（这正是要卖 SaaS 的前提）。

🔴 **五处同批，缺一即坏**（v469 资金管理实测；每缺一处的具体病症都写在括号里）：

| # | 在哪 | 改什么 | 漏了的后果 |
|---|---|---|---|
| ① | 后端 `core._ALL_MODULES` | 加入模块键（如 `"funds"`） | 包括 boss 在内**所有人都看不到入口**，且**静默不报错** |
| ② | 后端 `core.MODULE_LABEL` | `"funds": "资金管理"` | 权限页那一行与 403 文案会指到一个**不存在的开关**上 |
| ③ | 后端 `core.MODULE_IMPACT` | 加该模块的 `entries`（页面中文名列表） | 护栏 G 段转红（`entries` 必须与 `pages.js` **逐项一致**） |
| ④ | 后端 `server._PATH_MODULE_MAP` | `"/api/funds": "funds"` | **假闸门**：页面能勾、接口不拦；运行时接口被 fail-closed 判 403 |
| ⑤ | 角色授权 `_DEFAULT_PERMS` **＋ 各租户库 `role_permissions`** | 给该给的角色补键 | 有框有闸门、但没人被授权 ⇒ 全体 403 |

🔴 **第 ⑤ 处的双份陷阱**：`perms_for(tid) = {**_DEFAULT_PERMS, **_read_custom_perms(tid)}` ——
租户库里的行是**整表覆盖**，`_DEFAULT_PERMS` 只对"没被租户库覆盖"的角色生效。
⇒ **只改 `_DEFAULT_PERMS` 对存量租户（tenant_1 / tenant_10）无效**，必须**同批迁库**
（脚本范式：`server/tools/v469-funds-gate-migrate.py`；用 SQLite 官方 `Connection.backup()` 备份，
硬断言"未触碰角色逐字节相同 ＋ 被触碰角色差异恰好 `+funds`"，幂等可重跑）。

**前端两处**（与后端同批）：
- `constants/pages.js`：该域各行由 `module: null` → `module: '<键>'`
- `constants/permView.js`：`PERM_SIDEBAR_GROUPS` 加该区（名字必须与 `Shell.vue::NAV` 一级项**逐项且顺序**一致）

### 3.5.1 🔴 等价性原则（最容易漏、也最容易被当成"加固"的坑）

**开闸门前，先列出"迁移前谁能看见"** ——
`module: null` 时走的是**纯角色轴**（如资金管理 28 页 = `[...ADMIN_ROLES, 'accountant']`）。
⇒ 翻成真实模块键后，**必须给这批角色补授权**，否则 `canModule('<键>')` 为假会让**会计静默消失**。
那是**行为变更，不是加固**。（与 v349 拆 `loss` 同一条纪律。）

**做完的自检清单**（缺一不可）：
1. 护栏 `role-registry-consistency-check.py` **全绿**（v469 前是 112/114：`MODULE_IMPACT["stock"]`
   少了 9 页、`PERM_SIDEBAR_GROUPS` 8 组 ≠ NAV 12 组 —— 都是"改了 `pages.js` 没回头跑护栏"的欠账）。
   🔴 **动 `pages.js` 任何一行的 `module`，收尾必跑护栏。**
2. 服务端：`perms_for(1|10)` + `_perm_granted` → 该有的角色 `True`、不该有的 `False`。
3. 真机**三层取证**：未认证 `401` / 有权限 `200` / **受控 A/B** —— 临时撤销该键 → 断言 `403`
   （且 403 文案渲染的是**中文标签**「资金管理」而**不是内部键 `funds`**）→ `finally` 恢复 → 断言 `200`。

## 4. 页面写法：能合并就别铺开

- **参数化优先**：N 张同构单据/报表 ⇒ **一个组件 + 路由 meta 驱动**
  （资金 17 张单据 = 1 个 `FundsDoc` + `meta.docType`；4 张成本报表 = 1 个 `FundsCost` + `meta.costMode`）。
  新增一类 = 加一个词表项 + 一条路由，**不改组件**。
- **全局件复用**：`.page / .page-hd / .card / .kpi-strip / .tbl / .tag / .state-* / .input / .btn*`
  —— 一律不重定义。
- **私有类必须有模块前缀**（`fd-` `fs-` `ff-` `fb-` `fbk-` `fc-`…），**新模块先登记一张前缀表**，
  （`.fd-op` 若写成全局 `.op`，会悄悄改掉别人家的表格）⇒ **新模块开工第一天就把前缀分配表写进域规范**。
- **错误处理不许吞**：`api()` 失败会抛 `Error`，页面**必须**显示 `.state-error`，
  禁止 `catch {}` —— 吞掉之后现象是"页面空白但没报错"，排查成本极高。

## 5. 验收：要有证据，不要有感觉

### 5.1 前端构建（会踩一个已知的坑）
`npm run build` 可能被 safe-delete 拦住（vite 清空 `dist/assets` 超过阈值）。
⇒ **用隔离产物目录**：`npx vite build --outDir dist-<模块名>`（全新目录不必清空，绕开护栏）。
判据不看"是否成功"，看**产物里出现了该模块的新 chunk**。

### 5.2 后端/服务侧实测
源码能编译 ≠ 功能可用。必须发真实请求（带 token / `X-Tenant-Id`），断言具体数字：
- 断言**具体数值**而非"非空"（如「银行 8000 / 现金 -500 / 总额 7500」），
  只断言非空会放过"多算了 / 串了别的账户"这类真账错。
- **干净数据**：换租户号先建表（`init_funds_db(100)`），别拿真实 `tenant_1` 练手。

### 5.3 本地探针的几个坑（本机实测）
- `grep "A\|B"` 会**静默返回空**（看着像"没匹配"）⇒ 多模式用 `-e A -e B`。
- `| head -N` / `&&` 短路会把决定性命中截掉 ⇒ **"搜不到"先怀疑"搜错了范围"再当成事实**。
- 后台服务别用 `&` 挂起（会被回收）⇒ 用工具的后台执行模式。
- 端口探测别只看"连得上"：`curl` 经本地代理时，服务挂了也会返回 502 ⇒ **判据要看 http code == 200**。

## 6. 数据与 money 红线

- **多租户 = 一租户一个库文件**，任何新模块的 SQL 都带 `tenant_id=?`。
- **SQLite 禁止嵌套连接**：事务里再开 `get_db()` 会 `database is locked`。
  ⇒ 辅助函数加可选 `conn` 形参，由调用方传入**已打开的连接**。
- **金额/往来类写操作**：只允许通过"过账 → 写流水 → 重算余额"这条链，
  「直接 UPDATE 余额」是禁品；作废必须反向冲回。
- **UI 数字必须带中文单位**，禁用 `pp/avg/QoQ` 这类英文缩写（用户是给不懂技术的经销商做的产品）。

## 7. 交付纪律

🔴 **不提交、不部署，直到用户明确说"提交/部署"。**
（v465d 那轮资金模块按此执行：代码全部保留在工作区，未 `git add`、未上传生产。
**v469 拿到授权后**才提交 + 部署：后端 `core.py` / `server.py` scp 到 `/opt/hergent-erp`
＋ 重启 `hergent-erp.service`；前端 `vite build` → `rsync dist-v469/ → /opt/hergent-cn-v2/`，
以**三方 md5 相等**收尾。）
交付摘要里要写清：改了哪些文件、能交付什么证据（自测通过数 / build chunk 列表）、
**以及在等什么授权**（例如等部署时再把 `module: null` 翻成真实模块键）。

🔴 **提交走「受控提交」**：本仓与后端仓都是长期脏工作区 ＋ 多会话共用
⇒ 只提本轮文件，提交信息里写明逐文件改动与验证证据（见技能 `hergent-scoped-commit`）。
