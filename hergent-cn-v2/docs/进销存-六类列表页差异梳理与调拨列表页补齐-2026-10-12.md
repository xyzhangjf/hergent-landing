# 进销存六类列表页：差异梳理 + 调拨列表页补齐（2026-10-12）

> 以**采购单列表页 `InvPurchaseList.vue`** 为统一模板与基准，逐类梳理
> 采购退单 / 自提订单 / 自提退单 / 车销订单 / 车销退单 / 调拨单 六类，
> 指出与模板的差异，并按模板的代码风格与结构完成优化改造。

## 一、先澄清一个架构事实（最重要）

「六类列表页」**不是 6 个文件**。实测代码落点如下：

| 组件 | 服务路由 | 通过 query 切换的类 |
|---|---|---|
| `InvPurchaseList.vue`（1709 行，模板本体） | `/inventory/purchase` | `kind=order` 采购订单 / `kind=return` **采购退单** |
| `InvSaleList.vue`（597 行，v473 已对齐模板） | `/inventory/sale` | `type`(自提/车销/调拨) + `kind`(订单/退单) → 实际只服务 **自提×2 + 车销×2 = 4 类** |
| **（缺失）** | `/inventory/transfer` | **调拨单列表页完全不存在** |

调拨单的现状是两个「错配」：
- 侧栏「调拨单」入口（`Shell.vue:445`）指向 `/inventory/sale?type=transfer`
  → 出来的是 `sale_orders` 里 `order_type='transfer'` 的**舟谱导入单**（单仓，与真实调拨不是同一批数据）。
- `docTypes.js` 的 `TRANSFER_DOC_TYPES.listPath` 已正确写成 `/inventory/transfer`，
  但 `router/index.js` 下**没有这条路由、也没有组件**承接。

⇒ 本轮「优化改造」的真实落点 = **补齐缺失的调拨单列表页** + 修正指向错误数据集的假入口 + 修后端分页总数 bug。
（采购退单、销售 4 类本就与模板同源/已对齐，无需重写。）

## 二、模板基准（`InvPurchaseList.vue`）要点

1. **结构**：页头(标题+新建+刷新) / 筛选(常用项一行+「更多选项」折叠) / 工具栏(计数+排序提示+导出+打印) / 表格(齿轮列设置+可排序列+行内操作) / 分页器(页码窗+条页+跳页)。
2. **筛选**：`baseFilter()` 初值 + `watch(入口)` 切换时重置并归零排序；`hasFilter` 决定空态文案（「还没有单」vs「没有符合条件的结果」）。
3. **渲染**：`visibleCols` 由列设置驱动；`colText()` 是**唯一取值口径**（导出与表格共用），空值统一显示 `—`（铁律「没有 ≠ 是零」）。
4. **分页**：服务端 `limit/offset`；`pageNums` 页码窗（当前页居中、最多 7 页）；跳页。
5. **排序**：v470 服务端排序，`SORT_KEY` 映射（列 key ≠ 后端列名），`SORTABLE` 与后端白名单逐键一致。
6. **操作**：批量(采购特有)、行内 审核/反审核/取消/编辑/打印/复制/退货；权限 `canWrite` + 状态机决定按钮可见性。
7. **样式**：统一 `.btn` / `.isl-*` 体系；齿轮与列设置面板走全局 `styles/col-menu.css`。
8. **复用**：`useColSettings` + `ColMenuPanel`；`psiApi` 数据层；`canDo` 权限门禁。

## 三、六类 vs 模板差异表

| 列表页 | 字段 | 查询条件 | 状态流转 | 操作权限 | 交互细节 | 一致性结论 |
|---|---|---|---|---|---|---|
| **采购订单** (`InvPurchaseList`, kind=order) | 全字段+关联列(入库/货款/退货) | 供应商/仓库/经办/部门/审核人/来源/打印态/商品关键字/标记 | draft→待审→已确认→已入库→部分入库→已取消(+已退货) | 编辑/审核/反审/取消/批量/退货(已入库·部分) | 批量7项、打印数、草稿区、关联穿透 | **模板本体 ✅** |
| **采购退单** (`InvPurchaseList`, kind=return) | 同上（无关联列、无编辑） | 同上，状态钉 `returned` | returned | 仅审核/反审/取消 | 草稿区显示 | ✅ 同一组件，零额外成本对齐 |
| **自提订单** (`InvSaleList`, type=self_pickup,kind=order) | 单号/客户/金额/状态/出货方式/下单/交货 | 状态+日期+出货方式+客户 | draft→已确认→已发货→已签收→已驳回→已退货→已取消 | 无审核流；仅打印 | 无批量、无打印数；v473 已加服务端排序/导出/打印/筛选折叠 | ✅ v473 已对齐模板 |
| **自提退单** (`InvSaleList`, type=self_pickup,kind=return) | 同上 | `status=returned` | returned | 仅打印 | 同上 | ✅ |
| **车销订单** (`InvSaleList`, type=vehicle_sale,kind=order) | 同上 | 同上 | 同上 | 仅打印 | 同上 | ✅ |
| **车销退单** (`InvSaleList`, type=vehicle_sale,kind=return) | 同上 | `status=returned` | returned | 仅打印 | 同上 | ✅ |
| **调拨单**（**缺失→本次新建**） | 单号/调出仓/调入仓/商品/数量/状态/创建时间/备注 | **仅 status**（后端不支持日期/关键字） | draft→已过账→已取消（**无退货**） | 仅 打印 + 过账(草稿) | 无排序(后端无 `order_by`)、无批量、无打印数、行内「过账」 | 🔴→✅ **本次补齐** |

### 有意差异（明确不是缺陷，不应「对齐」成假控件）

- **销售 4 类无审核流 / 无批量 / 无打印数**：业务规则使然（销售单无审核；后端无销售批量接口、无打印计数接口）。造一排点了 404 / 刷新归零的按钮才是缺陷。
- **调拨无退货**：老板 2026-10-11 拍板，舟谱也没有这个类型。
- **调拨无排序**：后端 `transfer_order_list` 只接受 `status/limit/offset`，**无 `order_by`** ⇒ 表头不可点、不摆排序指示器（摆了点了没反应=假控件，正是本仓反复付学费的那种）。默认按后端 `ORDER BY id DESC`（最新在前）。
- **调拨筛选项少**：双仓数据结构不同，后端仅支持 `status` 过滤，不放日期/关键字假下拉。

### 7.2 每处改动的原因与影响范围

- **服务端排序（不是前端重排）**：本页服务端分页（`LIMIT ? OFFSET ?`）。若前端对当前页 20 行重排，翻页即用另一批 20 行、顺序基准不同 ⇒ 散架。排序键必须映射（列 key `from_wh`/`to_wh`/`product_name` ≠ 后端列名 `w1.name`/`w2.name`/`to_.product_name`），由 `SORT_KEY` 显式对应；白名单 `_TRANSFER_ORDER_SQL` 见 `erp_db.py`，**未登记键一律回落 `to_.id DESC`**（= v477 之前行为，老前端不传参零观感变化）。尾缀 `, to_.id DESC` 是决定性 tiebreaker，防止同值行翻页重复/丢失。
- **「备注」列不进排序白名单 = 有意差异（不是漏做）**：自由文本排序无意义，且不在后端白名单 ⇒ 该列表头不可点、不摆指示器。若强行把 `note` 加进 `SORTABLE`，点了会静默回落 id 排序，反而像「点了没反应」的假控件——正是本仓反复付学费的那种。
- **日期 / 商品走后端过滤（不放前端 filter）**：前端 filter 只作用于当前页行数 ⇒ 假结果。后端 `_transfer_order_where` 用 `created_at >= date_from 00:00:00 AND <= date_to 23:59:59` 区间筛 + `order_no OR product_name LIKE %kw%`。
- **参数顺序保持 `(status, limit, offset, ...)`**：兼容 `routers/inventory.py:226`（关键字调用）与 `tools/v449-listfix-harness.py:93` 的**位置传参** `("", 1, 1)`，新参数插在 `offset` 之后，不破坏旧调用。
- **筛选/排序不进 `hasFilter`、排序不进 `f`**：排序是「怎么看」不是「看哪些」，混进 `f` 会被「重置」清掉、还会让空结果文案答错。
