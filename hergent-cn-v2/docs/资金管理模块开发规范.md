## 2. 后端：落库 + 路由（两个文件，可整体下发生产）

| 文件 | 职责 |
|---|---|
| `server/funds_db.py` | 数据层。纯 stdlib `sqlite3`，多租户按库分文件（`tenant_<id>.db`） |
| `server/funds_api.py` | FastAPI 路由，`prefix=/api/funds`；底部 `__main__` 可独立起 `:8787` 自测 |

**五张表**：`fund_accounts`（资金账户）、`fund_docs`（单据主表）、`fund_doc_items`（明细行）、
`fund_flow`（流水账）、`cost_snapshots`（成本快照）。

### 2.1 🔴 三条资金铁律（写错就是真金白银的账错）
1. **只有过账才改余额**：单据 `draft → posted` 时写 `fund_flow` 并重算账户余额；`void` 必须反向冲回。
2. **方向符号统一在后端算**：收/入为正、付/出为负，`transfer` 写**两条**流水（A 出 B 入）；
   前端只负责彩色显示（`amountCls`），**绝不自己带符号运算**。
3. **`party_name` 兜底**：对账按 `party_name` 分组（用 `MAX(party_id)` 取值），
   因为自测数据里 `party_id` 可能为 0 —— 按 `party_id` 分组会把多行并成一行。

### 2.2 🔴 已踩的两个后端坑（务必别复现）
- **`database is locked`**：事务里嵌套 `get_db()`（同一个连接管理器被开两次）会锁死。
  ⇒ 修法：`_recompute_account_balance` / `_last_balance` 增加可选 `conn` 形参，
  由调用方把**已打开的连接**传进去；`bank_reconcile` 同理把 `flow_list` 挪到 `with` 之外。
  **纪律：一个请求周期只允许一条连接；读辅助函数要么复用传入 conn，要么在 with 之外调用。**
- **`bank-reconcile` 串了非银行账户**（2026-10-11 自测发现）：`flow_list` 在 `account` 为空时
  返回**全部账户**流水 ⇒「现金」的行混进「银行流水对账」（实测返回 2 笔、应 1 笔）。
  ⇒ 修法：先取 `type='银行'` 的账户名集合，**恒先卡「必须 ∈ 银行类」**，再按显式 `account` 收窄
  （问「现金」得到空表，而不是把整本账吐出来）。

### 2.3 本地自测（不部署也能验)

/Users/zhangjunfeng/.workbuddy/binaries/python/envs/funds-test/bin/python <仓库>/server/funds_api.py
# 2) 干净租户：换 X-Tenant-Id 头即可（先 init 建表），不碰 tenant_1 的真实数据

⇒ 银行 8000 / 现金 -500 / 总额 7500；流水 2 笔；**银行对账只含银行 1 笔**；对账各 1 家；

## 3. 前端：三工程化要点

### 3.1 词表唯一源 `constants/fundLabels.js`
页面**不许** hardcode「收款单 / 已过账」这类字。`FUND_DOC_META` 一张表定义 17 类单据的
`label / partyType / partyLabel / itemMode / dir`，`FUND_DOC_STATUS` 定义状态中文与徽标类。
改一处、全站一致（含列表/详情/守卫提示文案）。

### 3.2 参数化引擎 `pages/funds/FundsDoc.vue`
```js
const docType = computed(() => route.meta.docType || 'receipt')
const meta    = computed(() => FUND_DOC_META[docType.value] || { ... })
```
由 `meta` 派生：标题、`itemMode`（是否要明细行）、`dir`（转账/成本/收付的特殊分支）、列表列是否显影。
🔴 **同一个 path 两段 query 这种用法这里没有**，但相邻坑要记：`FundsDoc` 依赖 `route.meta`，
若将来改成同一组件靠 `?tab=` 切换，**必须改 computed + watch**（`onMounted` 不会再跑且零报错）。

### 3.3 CSS 前缀分配（不许复用、不许改全局件）
全局件直接复用：`.page / .page-hd / .card / .kpi-strip / .tbl / .tag / .state-empty / .state-error / .input / .btn*`。

## 4. 🔴 落真身四步（本次实操版）

1. **`pages.js`**：把该页从 `PLACEHOLDER_PAGES` **移出**；在 `PAGE_RULES` 写正式登记行。
   ⚠️ 不移出会被合并循环覆盖；移出了不补行 ⇒ `ruleFor` 返回 null ⇒ 变**对所有角色全开**（丢失窄名单）。
2. **`router/index.js`**：在 `...PLACEHOLDER_PAGES.map(...)` **之前**加真实路由（children 用相对路径）。
3. **`meta.title`** 必须与 `pages.js` 的 `title`、`Shell.vue` 的 `name` **逐字一致**
   （它就是守卫那句「你没有访问「xxx」的权限」的文案）。
4. **构建验证**：见 §5（产物必须出现该页 chunk）。

### 4.1 权限轴的处置（本次决策要记住）
现在 28 行是 `module: null` + `roles: [...ADMIN_ROLES, 'accountant']`（钱只给老板/管理员/会计）。
为什么不是 `module: 'funds'`：**`funds` 模块还没在后端权限系统注册**，挂上会让
`canModule('funds')` 恒 false ⇒ 连老板都看不到。**部署时**后端 `app.include_router(funds_router)`
并注册 `funds` 模块后，把这 28 行的 `module` 翻成 `'funds'` 即可（一字改动，不动页面）。

## 5. 🔴 构建与交付纪律（本次实操）

- **`npm run build` 会被 safe-delete 拦**：vite 清理 `dist/assets`（>50 个文件）触发批量删除护栏。
  ⇒ 用隔离产物目录：`npx vite build --outDir dist-funds`（全新目录无需清空，绕开护栏）。
- **构建判据看 chunk 名**：产物里必须出现 `FundsDoc / FundsStatement / FundsBalance / FundsFlow /
  FundsBankReconcile / FundsStaffDebt / FundsCost` **7 个** chunk + `funds-*.js`（API 层）。
  本次实测全部齐备（322 modules transformed）。
- **前端构建 vs 后端功能必须分开验证**：vite build 只证明能编译，
  **服务端一定要用带 token/租户头的脚本实测**（§2.3），别把"编译通过"当"功能可用"。
