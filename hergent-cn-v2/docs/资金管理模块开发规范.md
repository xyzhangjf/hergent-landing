## 2. 后端：落库 + 路由（两个文件，可整体下发生产）

| 文件 | 职责 |
|---|---|
| `server/funds_db.py` | 数据层。纯 stdlib `sqlite3`，多租户按库分文件（`tenant_<id>.db`） |
| `server/funds_api.py` | FastAPI 路由，`prefix=/api/funds`；底部 `__main__` 可独立起 `:8787` 自测 |

**五张表**：`fund_accounts`（资金账户）、`fund_docs`（单据主表）、`fund_doc_items`（明细行）、
`fund_flow`（流水账）、`cost_snapshots`（成本快照）。

### 2.1 🔴 三条资金铁律（写错就是真金白银的账错）
1. **只有过账才改余额**：单据 `draft → posted` 时写 `fund_flow` 并重算账户余额；`void` 必须反向冲回。
2. **方向符号统一在后端算**：收/入为正、付/出为负，`transfer` 写**两条**流水（A 出 B 入）；
   前端只负责彩色显示（`amountCls`），**绝不自己带符号运算**。
3. **`party_name` 兜底**：对账按 `party_name` 分组（用 `MAX(party_id)` 取值），
   因为自测数据里 `party_id` 可能为 0 —— 按 `party_id` 分组会把多行并成一行。

### 2.2 🔴 已踩的两个后端坑（务必别复现）
- **`database is locked`**：事务里嵌套 `get_db()`（同一个连接管理器被开两次）会锁死。
  ⇒ 修法：`_recompute_account_balance` / `_last_balance` 增加可选 `conn` 形参，
  由调用方把**已打开的连接**传进去；`bank_reconcile` 同理把 `flow_list` 挪到 `with` 之外。
  **纪律：一个请求周期只允许一条连接；读辅助函数要么复用传入 conn，要么在 with 之外调用。**
- **`bank-reconcile` 串了非银行账户**（2026-10-11 自测发现）：`flow_list` 在 `account` 为空时
  返回**全部账户**流水 ⇒「现金」的行混进「银行流水对账」（实测返回 2 笔、应 1 笔）。
  ⇒ 修法：先取 `type='银行'` 的账户名集合，**恒先卡「必须 ∈ 银行类」**，再按显式 `account` 收窄
  （问「现金」得到空表，而不是把整本账吐出来）。

### 2.4 🔴 接入生产（v468b 实操，三个坑全部本地测不出）

**部署落点**（生产是 **FLAT 布局 + `routers/` 包**，别照搬仓库结构）：

| 仓库 | → 生产 |
|---|---|
| `server/funds_db.py` | `/opt/hergent-erp/funds_db.py` |
| `server/funds_api.py` | `/opt/hergent-erp/routers/funds.py` |
| `server.py` | 加 `from routers.funds import funds_router` + `app.include_router(funds_router)` |

**坑一：❌ 库路径硬编码（最贵的一个）**
原写法 `ERP_DIR = os.path.expanduser("~/Library/Application Support/hergent-erp")` 在 macOS 本地正确，
**到 Linux 会展开成 `/root/Library/...`** ⇒ 后端能起、接口能通、`200 OK` 一切正常，
**但每个租户都写进自己的空库** —— 页面永远空白，且没有任何报错。
⇒ **纪律**：库目录**三级解析**，绝不写死——

```python
def _resolve_erp_dir():
    env = os.environ.get("ERP_DB_PATH")
    if env:
        return os.path.dirname(os.path.abspath(env))
    try:
        from db.connection import DB_DIR as _DB_DIR   # 生产唯一真相源
        return _DB_DIR
    except Exception:
        return os.path.expanduser("~/Library/Application Support/hergent-erp")  # 本地自测
```

**判据**：部署后先跑 `print(funds_db.ERP_DIR)`，必须是 `/opt/hergent-erp`。**这一步不能省。**

**坑二：❌ 自己解析租户头**
生产 `server.py::tenant_middleware` 对所有 `/api/` 业务路由 **fail-closed**：
不在 master/public 白名单 ⇒ 必须带租户，否则 403；放行前已 `set_tenant_context(tid)`。
⇒ 新 router **只读** `db.connection.get_tenant_context()`，**不要**再自己解析 header
（「第二处租户真相」正是本项目跨租户串数据的经典成因）。
🔴 **拿不到上下文 ⇒ 403 fail-closed，绝不 `return 1`** —— 默认落租户 1 会让
「不带租户头的请求」读到老板的数据。

> ℹ️ `server.py::_TENANT_REQUIRED_PREFIXES` 看着像「必须登记的前缀表」，但它**定义了却从未被引用**
> （末尾那个 `"/api/{full_path:path}"` 通配也从未生效）= 死代码。
> 中间件实际只用 master/public 白名单 ⇒ **新前缀无需登记**。（又一个「死代码里的多层缺陷」。）

**坑三：❌ 忘了建表**
接口没有建表调用 ⇒ 租户首次访问撞 `no such table: fund_accounts` **报 500**。
⇒ 在租户取值处挂一个**幂等自动建表**（`CREATE TABLE IF NOT EXISTS` + 进程内按租户缓存）：

```python
_ENSURED_TENANTS = set()
def _ensure_tables(tid):
    if tid in _ENSURED_TENANTS: return
    db.init_funds_db(tid); _ENSURED_TENANTS.add(tid)
```

🔴 **为什么本地测不出**：自测时都显式 `init_funds_db()` 过 ⇒ 表早就在了。
**只在真实租户上才会炸。** 验证法：删掉测试库（`rm tenant_102.db*`）**再**打接口，
看是否 200（而不是 500）。

**部署检查单（缺一不可）**

| # | 动作 | 判据 |

| 1 | 备份 `server.py` + 目标租户库 | 库备份用 **SQLite 在线备份 API**，不要 `cp`（WAL 下 `cp` 可能拷到不一致快照） |

## 3. 前端：三工程化要点

### 3.1 词表唯一源 `constants/fundLabels.js`
页面**不许** hardcode「收款单 / 已过账」这类字。`FUND_DOC_META` 一张表定义 17 类单据的
`label / partyType / partyLabel / itemMode / dir`，`FUND_DOC_STATUS` 定义状态中文与徽标类。
改一处、全站一致（含列表/详情/守卫提示文案）。

### 3.2 参数化引擎 `pages/funds/FundsDoc.vue`
```js
const docType = computed(() => route.meta.docType || 'receipt')
const meta    = computed(() => FUND_DOC_META[docType.value] || { ... })
```
由 `meta` 派生：标题、`itemMode`（是否要明细行）、`dir`（转账/成本/收付的特殊分支）、列表列是否显影。
🔴 **同一个 path 两段 query 这种用法这里没有**，但相邻坑要记：`FundsDoc` 依赖 `route.meta`，
若将来改成同一组件靠 `?tab=` 切换，**必须改 computed + watch**（`onMounted` 不会再跑且零报错）。

### 3.3 CSS 前缀分配（不许复用、不许改全局件）
全局件直接复用：`.page / .page-hd / .card / .kpi-strip / .tbl / .tag / .state-empty / .state-error / .input / .btn*`。

## 4b. 🔴 能力闸门的完整配方（v469 实操，**给下一个模块照抄**）

一个模块要成为「老板能在权限页单独开关的闸门」，**必须五处同批**。缺任何一处都有特定病灶：

| # | 位置 | 缺了会怎样（实测） |
|---|---|---|
| ① | `core._ALL_MODULES` 加 `"funds"` | `module` 轴恒 false ⇒ **包括 boss 在内所有人都看不到入口**，静默 |
| ② | `core.MODULE_LABEL` 加 `"funds": "资金管理"` | 403 文案渲染**内部键**（「没有「funds」的使用权限」）——护栏会红 |
| ③ | `core.MODULE_IMPACT` 加 `funds.entries`（= 该模块管的**全部页面标题**，逐项） | 权限页「对应页面」列为空，老板不知道勾了会发生什么；护栏 G 段会红 |
| ④ | `server.py::_PATH_MODULE_MAP` 加 `/api/funds` → `funds` | **假闸门**：页面有勾选框但接口不拦（护栏「能勾的模块必须有接口映射」会红） |
| ⑤ | 角色授权：`_DEFAULT_PERMS`（+ **各租户库 `role_permissions`**） | 有框有闸门但**没人被授权** ⇒ 谁都进不去 |

**🔴 ⑤ 的租户库部分不可省 —— 这是最容易漏的一格：**
`_DEFAULT_PERMS` 只管「**没有被租户库覆盖**」的角色；而 tenant_1 / tenant_10 的 boss / accountant
都是**存量整表覆盖** ⇒ 只改代码对他们**不生效**（v293 / v325 / v332 / v347 在同一处栽过四次）。
⇒ 必须跑迁移脚本（本次：`server/tools/v469-funds-gate-migrate.py`，幂等 + 在线备份 + 硬断言）。

**🔴 等价性原则（开闸门不许顺手关功能）：**
迁移前这 28 行是 `module: null` + 纯角色轴，**会计看得见**。开闸门时必须给 boss / accountant
**都补 `funds`**，否则等于「顺手把会计关在资金管理外面」—— 那是**变更**，不是加固。

**顺带另一条护栏（v390）：** `permView.js::PERM_SIDEBAR_GROUPS` 的组名必须**逐项且同序**
等于 `Shell.vue::NAV` 的一级项名。v465 新增的 4 个侧栏区（仓配/资金/市场/报表）**当时没同步**
⇒ 护栏自 v465 起一直红着（本次 v469 一并补上，并把 `stock`/`reports`/`goals` 从「更多」组归位）。

## 5. 🔴 构建与交付纪律（本次实操）

- **`npm run build` 会被 safe-delete 拦**：vite 清理 `dist/assets`（>50 个文件）触发批量删除护栏。
  ⇒ 用隔离产物目录：`npx vite build --outDir dist-funds`（全新目录无需清空，绕开护栏）。
- **构建判据看 chunk 名**：产物里必须出现 `FundsDoc / FundsStatement / FundsBalance / FundsFlow /
  FundsBankReconcile / FundsStaffDebt / FundsCost` **7 个** chunk + `funds-*.js`（API 层）。
  本次实测全部齐备（322 modules transformed）。
- **前端构建 vs 后端功能必须分开验证**：vite build 只证明能编译，
  **服务端一定要用带 token/租户头的脚本实测**（§2.3/§2.4），别把"编译通过"当"功能可用"。
- ⭐ **只改注释 ⇒ 不必重新部署**：构建会**剥离 JS 注释**，`bundle hash` 不变。
  v468b 实测：改完 `pages.js` 注释后 `npx vite build` 出的 `index.html` md5 与生产**完全相同**
  ⇒ 省掉一次部署（以及一次与并行会话互相覆盖的风险）。
  **但必须用 md5 比对证明**，不能想当然 —— 万一是真实代码改动，不部署就是生产落后。
