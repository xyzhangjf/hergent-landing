二、五个维度的真实发现

1. Git 状态 — v89 全部未提交

35 个文件改动停在暂存区，git HEAD 还在 v88

当前分支 upgrade/v84-international，最近提交是 841e792 docs: v88 handbook update。v89 的所有代码改动（server/core.py、erp_db.py、main.py、db/connection.py、db/queries/*、Dockerfile 等）都在工作区里，没 commit。

风险：任何 git checkout / git stash / 分支切换都可能丢失这批工作。服务器上跑的是不是这版代码也不确定——本地源码和线上版本可能已经分叉。

2. 测试 — 全过，但环境装不起来

163 passed / 28 skipped / 0 failed（14 秒跑完）

测试本身健康，conftest 用临时 DB 自包含，不依赖真实数据。但首次按 requirements.txt 装依赖跑测试，直接 ImportError——缺 cryptography。补装后 14 个 CSRF/tenant 测试又因缺 python-multipart 失败。全部补齐后才跑通。

requirements.txt 缺 4 个运行时依赖

审计报告(8.7)早已指出，到 v89 仍未修：

影响：新人 clone 后 pip install -r requirements.txt 跑测试直接崩。这不是"缺文档"问题，是"按官方步骤走不通"问题。

3. 数据库 — 本地是空壳，真实数据在服务器

251 张表，但本地 erp.db 几乎没有业务数据

交接文档说"舟谱真实数据已导入：371 商品 + 672 客户 + 38 供应商 + 525 订单"。实测本地 server/erp.db：products 仅 6 条、journal_entries 0 条、最大的业务表是 chart_of_accounts(25 行)。舟谱数据在服务器 47.113.224.140 上，不在仓库里。

另有 8 个 tenant_*.db（多租户架构），本地也都是空的。本地开发时看不到真实业务数据，只能靠测试 fixture。

4. 技术债 — erp_db.py 是最大的一笔

erp_db.py：10,368 行 / 674 个函数，单体文件

平均 15 行/函数，但总量已经大到难以维护。db/queries/ 目录已拆出 11 个查询模块（contacts/products/sales/purchases/finance/journal/coa/gl 等），但 erp_db.py 本体还没拆。交接文档把拆分列为"中期"——建议提前，每加一个功能都是在加深这笔债。

28 个 skipped 测试

测试虽然 0 failed，但有 28 个 skip。交接文档"后续路线图"提到"测试 skip 恢复"但还没做。skip 的测试是定时炸弹——覆盖面有缺口。
