## 2. 小程序 ↔ Web 数据链是否互通？—— **主体通，有两个已知断点**

### 链路矩阵（生产实测）

| 数据 | 共享载体 | 小程序 → Web | Web → 小程序 |
|---|---|---|---|
| **商品主档** | `products` 表 + `is_active` | ✅ 同源 | ✅ 小程序每次进入重新拉取，**Web 改了立刻生效** |
| **期次** | `forecast_periods` 表 | ✅ 同一张表 | ✅ 但**过滤不同**（见下） |
| **报单数据** | `forecast_submissions` + `forecast_submission_items` | ✅ **完全打通** | ❌ 断点 1 |
| **期次汇总** | `/api/forecast-submissions/summary` | ✅ 小程序提交即时可见 | — |

### 关键证据

**小程序 → Web 打通了。** Web 端 `Forecast.vue` 的汇总交叉表数据源就是
`forecast_submission_summary()`（`erp_db.py:14876`），SQL 为：

```sql
FROM forecast_submission_items i JOIN forecast_submissions s ON i.submission_id=s.id
WHERE s.order_date BETWEEN ? AND ? AND s.status NOT IN ('rejected','recalled')
```

实测（用 SQL 复刻，因测试账号无 summary 权限）：

| 动作 | 结果 |
|---|---|
| 小程序提交 pid 1353 × 7 件 | Web 汇总**即时出现** `[('链路验证商品', 7)]` ✅ |
| 撤回该单 | 汇总**立即消失** ✅ |
| 孤儿数据检查 | 0 条 ✅ |

**期次数量差异的真因（与上次结论一致）**：Web 端 `/api/forecast/periods`
用 `db.forecast_period_list()` **返回全部期次（含 closed）**；小程序用
`forecast_open_periods_all()` **只返回 status=open**。同一张表、不同过滤，
不是数据不同步。生产实测 Web 端返回 4 条（含 closed 的 id=7），小程序返回 3 条。

### ❌ 断点 1：Web 端「改单」的结果，小程序看不到

Web 端 Forecast.vue 保存走 `/api/forecast-submissions/save-matrix`
（写 `forecast_extra_qty` 等），小程序**没有任何地方读这个结果** —— 小程序只看
自己提交的历史。所以管理员在 Web 端调整过的量，销售在小程序里看不到。

### ❌ 断点 2：Web 端「今日报单」（无期次）的单，小程序看不到

生产库 81 单中 **60 单 `period_id = 0`**（Web 端用户无期次时提交，落到"今日报单"窗口）。
小程序必须选期次，因此这部分单在小程序里不出现。属于设计使然，不是 bug。

### 顺带发现的一个权限事实

`/api/forecast-submissions/summary` 返回 **403「仅管理员/老板可看汇总」**。
我用 `mptest`（sales）测时拿不到数据 —— 这是**权限设计**，不是链路断。

## 3. 提交后不清空 · 跨期次沿用 —— 已实现

### 需求还原

> 本期报单提交后，这一次的数据不清除，便于下次报单时知道上次报了什么；
> 不想改的话，选对应期次后可直接提交。

### 设计：两套存储，各管一件事

| Key | 维度 | 内容 | 用途 |
|---|---|---|---|
| `fs_last_cart_${storeId}` | **门店** | `{ periodId, periodName, at, count, qty, items[] }` | 换期次仍在 → **一键带入** |
| `fs_sub_${storeId}_${periodId}` | **门店 + 期次** | `{ sid, count, qty, at }` | 本期已报过 → **防重复提交** |

### 三态界面

| 状态 | 显示 | 操作 |
|---|---|---|
| ① 本期已提交 | 绿条「✓ 本期已报 3 项 / 42 件 · 内容已保留，可继续修改」 | 查看我的报单 |
| ② 有上次记录 + 当前为空 | 青条「上次「9月提审期」报了 3 项 / 42 件」 | **一键带入** |
| ③ 有上次记录 + 已有内容 | 同上 | **清空重填** |

### 重复提交保护（关键）

提交前查 `fs_sub_${storeId}_${periodId}`；若已有记录，先弹确认：

```
本期已报过
永诺旗舰店 在「9月提审期」已报 3 项 / 42 件（单号 187）。
再提交会新增一单，确定继续？
        [去查看]  [仍要提交]
```

取消 → 跳「我的提交」。**没有这个保护，数据留着就会变成误重复下单的陷阱。**

### 改了哪些代码

| 文件 | 改动 |
|---|---|
| `fill.js` data | 新增 `lastOrder` / `submittedInfo` |
| `fill.js` | 新增 `_lastKey()` / `_subKey()` / `refreshBanners()` / `applyLastOrder()` / `applyQtyToRows()` / `goSummary()` |
| `fill.js` `submit()` | 提交前重复校验；成功后**不再清空**，写两份快照 + `refreshBanners()` |
| `fill.js` | `loadStores` / `loadPeriods` / `onStoreChange` / `onPeriodChange` / `pickRecent` 后调 `refreshBanners()` |
| `fill.wxml` | 新增两条 banner（三态互斥 `wx:if / wx:elif`） |
| `fill.wxss` | `.last-bar` / `.last-bar-done` / `.last-txt` / `.last-go` |

### 🐛 顺手修的既有 Bug

`submit()` 里两处 `wx.switchTab({ url: '/pages/summary/summary' })` ——
**summary 已从 tabBar 移除**（app.json tabBar 只有 fill / mine），
`switchTab` 只能跳 tabBar 页面，**这两处跳转会静默失败**。
已改为 `/pages/mine/mine`（"我的提交"，在 tabBar 内，且语义就是"我的报单"）。
