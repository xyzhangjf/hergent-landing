> 需求：① 进入预报页即全量铺开可预报单品，不用逐个搜索 ② 保留搜索过滤入口 ③ 查明「Web 端 4 个期次、小程序只显示 1 个」的原因 ④ 商品多时分页加载不卡顿 ⑤ 与 Web 端商品配置一致、配置变更能同步。

## 一、期次差异根因（已查明并修复）

### 生产库真实数据（`tenant_1.db` 的 `forecast_periods`）

| id | 名称 | 报单窗口 | 到货 | 状态 | 今天(09-06)在窗口内 |
|---|---|---|---|---|---|
| 7 | 8月26报单-8月29到货 | 08-26 ~ 08-26 | 08-29 | closed | — |
| 8 | 8月28报单-9月2日到货 | **08-28 ~ 08-28** | 09-02 | open | ❌ 已过 |
| 9 | 9月提审期-开放填报 | 08-30 ~ 09-15 | 09-18 | open | ✅ |
| 10 | 9月3日报单9月8日到货 | **09-03 ~ 09-03** | 09-08 | open | ❌ 已过 |

### 根因

`erp_db.forecast_open_periods()` 的 SQL 过滤是：

```sql
WHERE status='open' AND ? BETWEEN order_start AND order_end   -- ? = 今天
```

id=8、id=10 是**单日窗口期次**（`order_start = order_end = 同一天`），那天一过就被日期条件过滤掉；但管理员**没在 Web 端关闭**，状态仍是 `open`，所以 Web 端期次管理里看得到 4 条，小程序只剩 1 条。

**一句话**：不是数据不同步，是小程序比 Web 端多了一层「今天必须在窗口内」的日期过滤。

### 修复方式（不动提交逻辑）

| 函数 | 用途 | 改动 |
|---|---|---|
| `forecast_open_periods()` | **提交时自动选期次**（`forecast_submissions.py:81`） | **保持原样**（语义必须严格，否则补报会落到过期期次） |
| `forecast_open_periods_all()` | **列表展示**（新增） | 返回所有 `status='open'` 期次 + `in_window` 标志，**窗口内的排最前** |

`/open-periods` 路由改用新函数。安全网：

- 提交接口对 `period_id` 仍有二次校验（`status=open` 且今天在窗口内），选中过期期次提交会被 **400 拒绝**，不会写脏数据；
- 前端选中过期期次时，顶部弹红色提示条 + toast 预警。

## 二、商品全量铺开（已实现）

### 后端：`server/routers/data.py` → `/api/products/fill-search`

| 项 | 改前 | 改后 |
|---|---|---|
| 分页 | 只有 `limit`（默认 20），无 offset | 新增 `offset`，返回 `total` |
| 库存/日均 | **每个商品 2 次子查询 = N+1**（428 商品 = 856 次查询） | **批量 IN 预取，查询次数恒定 4** |
| 参数防护 | 无 | `limit` 截到 1~200，`offset` 非负 |
| 空关键词 | `like='%'` 取前 20 条 | 同样全量铺开，只是分页返回 |

搜索字段**完全没动**（`name / spec / product_code / pinyin_first`），`q` 有值时只作为过滤条件，语义与原来一致。

### 前端：`pages/fill/`

| 文件 | 改动 |
|---|---|
| `fill.js` | 新增 `products / total / pageSize(30) / hasMore / loadingMore`；`loadProducts(kw, append)` 支持分页追加；新增 `onReachBottom` 触底加载、`clearSearch`；期次加 `display` 标签与 `in_window` 提示 |
| `fill.wxml` | 「搜索结果」区 → **常驻「可预报商品」列表**（带总数、加载中、已全部显示）；期次 picker 用 `range-key="display"`；新增已过窗口红色提示条、搜索清除按钮；移除「常用品」横条（全量铺开后已冗余） |
| `fill.wxss` | 新增 `.prod-head / .load-more / .load-end / .search-clear / .period-warn` |
| `fill.json` | 新增，`onReachBottomDistance: 120`（提前 120px 预加载，滚动更顺） |

**一致性保障**：数据源与 Web 端商品档案**同一张 `products` 表 + 同一 `is_active` 过滤**，无独立副本、无同步任务；`onShow` 每次进页面重新拉第一页，**Web 端配置变更后小程序即时生效**。

## 四、待确认 / 建议

1. **过期期次建议后台关闭**：id=8、10 的到货日已过（09-02、09-08），建议去 Web 端期次管理把 status 改为 closed，列表自然干净。
2. **购物车位置**：全量铺开后商品列表很长，「本次预报（N 项）」区在列表下方，加购多了要滚很久才能改数量。可选改进：购物车吸顶 / 改底部弹窗 / 顶部「N 项」做成可点击跳转。**要不要做，等你定。**
3. 每页 30 条是权衡值（首屏 0.125s）。商品再涨到上千时可考虑加分类筛选或首字母索引。
