## 一、前端修复（miniprogram/）

| 问题 | 文件 | 修复要点 |
|---|---|---|
| **F1 门店静默重置** | `pages/fill/fill.js` | `loadStores()` 不再强制把 `store` 重置成 `stores[0]`；选中门店持久化到 `wx.setStorageSync('fs_store_id')`，`onShow` 优先恢复上次选择，`onStoreChange` 同步落盘。购物车跨 tab 不再错配门店。 |
| **F2 鉴权流断点** | `pages/login/login.js` | 新增 `onLoad`：已登录（`fs_token` 存在）直接 `reLaunch` 到填报页，不再见空登录框。 |
| **F2 鉴权流断点** | `utils/api.js` | 401 分支除清 `fs_token` 外，额外清 `fs_user`/`fs_tenant_id` 内存与存储态，并 `wx.reLaunch` 到登录页，杜绝卡在无权限态。 |
| **F3 搜索竞态/风暴** | `pages/fill/fill.js` | `onSearch` 加 300ms 防抖；`loadProducts` 引入请求序号 `_seq`，响应返回时若非最新则丢弃，避免过期响应覆盖。 |
| **F4 静默吞错** | `pages/fill/fill.js` | 商品/门店加载失败由静默 `catch{}` 改为 `wx.showToast` 明确报错（区分「无结果」与「出错」）。 |
| 防御增强 | `pages/fill/fill.js` | `submit()` 增加门店非空校验（`!store.id` 拦截），与后端 B1 双重保险。 |

## 二、后端修复（hergent-erp/server/）

| 问题 | 文件 / 函数 | 修复要点 |
|---|---|---|
| **B1 门店越权** | `routers/forecast_submissions.py` → `create_submission` | 提交前校验 `store.id ∈ employee_stores_get(emp_id)`；不在范围返回 `403`；门店名以服务端授权范围为准（不信任客户端 `name`）。`emp_id<=0`（boss/admin）放行。 |
| **B2 product_id 容错** | `routers/forecast_submissions.py` → `create_submission` | `int(product_id)` 全部包 `try`，非法值跳过该明细（不再 500）；`pid<=0` 的明细直接丢弃；空清洗结果返回 400（提示「商品无效」）。 |
| **B3 汇总排除 rejected** | `erp_db.py` → `forecast_submission_summary` | 聚合 SQL 与来源明细 SQL 均加 `AND s.status != 'rejected'`，被驳回的预报不再计入订货总量。 |
| **B4 提交幂等** | `routers/forecast_submissions.py` → `create_submission` | 同 `(user_id, store_id, order_date=今天)` 已存在记录时：若已 `approved` 返回 `409`（需管理员）；若为 `pending/rejected` 则覆盖更新（先删旧再建），避免重复提交叠加放大汇总。 |
| **B5 汇总性能** | `erp_db.py` → 新增 `_forecast_product_cached` | AI 建议量（每 SKU 调预报引擎 + 365 天销量扫描）改为带 1h TTL 的模块级缓存；汇总与待审两处引擎调用统一走缓存，反复刷新汇总页秒开。 |
