# 预报订单小程序 · 灰度发布与回滚方案

> 适用范围：前端小程序 + 后端 `forecast_submissions` 相关改动（含本次 recall 端点）。
> 原则：**前端零停机灰度（微信平台能力）+ 后端受控单独部署（rsync 指定文件 + restart）**。

---

## 一、发布流程（前端）

1. **开发者工具上传**：打开 `forecast-order-miniprogram-20260812T023419087Z/` 目录，点「上传」生成体验版（含 A3/E2/D1 + 埋点/我的提交/移动审批全部改动）。
2. **体验版内部验证**：内部人员（你 + 文员 + 督导）扫码，跑 E1-E12（真机 E2E 清单 P0）。
3. **提交审核**：在微信公众平台提交，审核材料含《隐私保护指引》（`隐私保护指引.md`）+ 类目选择「商家自营-农资/生鲜」类（低温奶属食品生鲜，需对应类目）。
4. **分阶段灰度发布**：审核通过后，发布页选「分阶段发布」：
   - 阶段1：1%（≈1 个门店试点）
   - 阶段2：10%（扩大至 1 个经销商多门店）
   - 阶段3：50%
   - 阶段4：100%
   每阶段观察 ≥24h 再放量。
5. **全量**：100% 后观察 3 天无异常即稳定。

## 二、前端回滚

- 微信公众平台「版本管理 → 线上版本 → 版本回退」：一键回退到上一**已发布**稳定版（无需重新审核）。
- 注意：回退只影响前端代码，**后端若已部署 recall 端点则保留**；若同时需回退后端见第三节。
- 回退后旧前端无「撤回/审批」入口，但调用旧接口不受影响（向后兼容）。

## 三、后端灰度与回滚

### 本次后端改动范围
- `server/routers/forecast_submissions.py`：新增 `POST /{sid}/recall`
- `server/erp_db.py`：`forecast_submission_recall()` + 汇总两处过滤 `NOT IN ('rejected','recalled')`

### 部署方式（已验证）
- 仅同步这 **2 个文件**（不碰分支上其余未推送改动）：
  ```
  rsync -a --no-owner --no-group server/erp_db.py root@47.113.224.140:/opt/hergent-erp/erp_db.py
  rsync -a --no-owner --no-group server/routers/forecast_submissions.py root@47.113.224.140:/opt/hergent-erp/routers/forecast_submissions.py
  ssh ... "chown hergent:hergent ... && systemctl restart hergent-erp"
  ```
- 验证：`curl health=200` + `recall/pending` 假 token 返回 401（路由已注册非 404）。

### 后端回滚
- 回退这 2 个文件到上一稳定版（git 取历史版本 rsync 回去），restart。
- **数据兼容性风险提示**：新端点会把单子置 `status='recalled'`。若回滚到旧版后端，**旧汇总过滤仅排除 `rejected`，会把 `recalled` 单重新计入总表**。处理二选一：
  1. 回滚前先把 `recalled` 单 `UPDATE ... SET status='pending'`（撤回即作废，需重新提交）；或
  2. 接受短暂多计、待重新部署新版后自动恢复。
- 属**非破坏性 schema 变更**（未加列、未改表结构），仅 status 取值扩展，风险低。

## 四、监控指标（灰度期重点看）

| 指标 | 来源 | 告警阈值 |
|---|---|---|
| API 错误率 | 后端 access log / `api_error` 埋点 | >5% 持续 5min |
| 登录转化率 | `login` / `login_fail` 埋点 | 失败率 >20% |
| 提交成功率 | `submit` / `submit_fail` 埋点 | 失败率 >10% |
| 审批转化 | `approve` / `reject` 埋点 | 待审积压 >48h 预警 |
| 崩溃/白屏 | 微信后台「异常监控」 | 任意新增 crash 聚类 |
| 502/504 | nginx error.log + Hermes 上游 | 出现即查 |

## 五、回滚触发条件（任一项命中即回退）

1. 关键漏斗（登录/提交）成功率骤降 >30%。
2. 出现无法绕过的崩溃（基础库兼容问题）。
3. 后端健康检查非 200 或 recall/approve 接口 5xx。
4. 用户集中反馈数据错乱（如撤回单仍计入汇总且影响采购）。

## 六、责任人 & 节奏

- 发布动作：需你本人在微信公众平台操作（A1/A2/B1 非代码可解）。
- 后端部署：AI 已可外科手术式执行，灰度期保持「单文件 rsync + restart」纪律，避免带入分支其余未评审改动。
- 放量节奏：每阶段 ≥24h，全量前至少 3 天观察。
