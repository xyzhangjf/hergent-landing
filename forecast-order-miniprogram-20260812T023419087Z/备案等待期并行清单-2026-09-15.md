## 二、等待期四件事（按价值排序）

### ★★★ ① 后台配置：隐私保护指引 + 合法域名

**这是一件事的两个字段，半小时能做完，且是唯一还剩的平台侧硬门。**

**1-a. 用户隐私保护指引**
- 路径：`mp.weixin.qq.com` → **设置 → 服务内容声明 → 用户隐私保护指引** → 更新
- **信息类型只勾一个：剪切板**（其余一律不勾）

  依据：按微信官方《小程序用户隐私保护指引内容介绍》的「接口 ↔ 个人信息」映射表**逐条核对**，需声明的只有「读取你的剪切板」一项（`wx.setClipboardData`，`pages/summary/summary.js:49`，汇总表复制）。

  ⚠️ 另有两个接口**不在该必填清单内** —— 无需申报，但已在隐私文本里如实说明：`wx.getNetworkType`（断网提示，不上传、不存储）、`wx.reportAnalytics`（微信原生统计，仅上报业务事件名与角色/门店名/数量合计）。

### ★★ ② 试传一次代码，看备案期间能否出体验版

- 用开发者工具点「**上传**」，留意是否被拦截、被拦时抄下原文。
- 若能上传 → 去后台「版本管理」把该版本**设为体验版**。
- 若能出体验版 → **立刻让 1~2 个真销售走完整流程**：登录 → 选门店 → 搜商品 → 填数量 → 提交 → 我的提交 → 撤回。
- 价值：真机才会暴露的问题（键盘遮挡、下拉越权、期次归属）现在就能抓出来，而不是等上线后。
- ⚠️ **不确定性要说清**：规则确定的是「未备案**不能提审、不能发布**」；但「能否上传代码 / 能否生成体验版」各来源说法不一，**必须实操验证**。上传不消耗任何配额，试一次就知道。

**2026-09-20 核实补充（本地代码侧已查清）**

| 项 | 实测 | 含义 |
|---|---|---|
| 备案卡口在哪道门 | 上传**不卡**；提审 / 发布**卡** | 上传只把代码放进后台「开发版本」库，不对外 |
| 与备案是否互相影响 | **否**，两套独立流程 | 上传不消耗配额、不重排备案队列，放心试 |
| 全仓域名个数 | **1 个**：`https://hergent.cn`（`app.js:5`、`utils/perm.js:30`、`utils/session.js:20`、`utils/track.js:56-57`） | 后台「服务器域名」只配 **1 条** request 即可 |
| `project.config.json` → `urlCheck` | **`true`（已开）** | 模拟器即按线上真实规则校验 ⇒ 不会出现"本地好、体验版坏" |
| `appid` | `wxf8ce9b8e4b5693be` | 上传时核对别选错项目 |

🔴 **必须先配域名再上传体验版**：体验版**强制校验**合法域名（不像开发者工具可勾"不校验"绕过）。没配就出体验版 = 打开即接口全失败、看起来像"代码坏了"，白折腾一轮。
🔴 **上传 ≠ 提审**：上传不会自动进审核队列，备案通过后仍需手动点「提交审核」。

### ★★ ③ 修三条数据准确性技术债（我改代码，你批）

| # | 问题 | 后果 |
|---|---|---|
| 1 | 首页「本期待报 TOP3」仍按**日期区间**取数 | 期次归属口径已改，这条没跟 → 期末会显示到错期的数 |
| 2 | `save-matrix` 期次解析按**时间窗口匹配** | 两个窗口相同的期次取 id 最大者 → 可能写错期次 |
| 3 | 幂等键 `(user_id, store_id, order_date)` **不含 period_id** | 同一天补报不同期次，会被判成重复提交而丢弃 |

**为什么现在做**：销售真机一跑就会踩到，且全在生产上。这三条都属于「数字会错但不报错」的静默问题，最伤信任。

## 三、这段时间别做的事

| ❌ | 原因 |
|---|---|
| 不要为「快」而放松交易 / 订单写的准确性 | 三条遗留债就是这类问题，先还债 |
| 不要在小程序任何对外可见处再出现「AI / 智能 / 智慧 / 机器人」 | 驳回原文专门点了 AI 字样；后台名称、简介、页面标题、分享文案都要干净 |
| 不要在没有明确新理由时反复重提备案 | 每次都重新排队，只会更慢 |
| 不要把「预上线」当捷径 | 那是报备类目（社交、新闻等）的机制，工具/企业服务类不适用 |
