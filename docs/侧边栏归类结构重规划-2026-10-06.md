# 侧边栏归类结构重规划（v4 · 学舟谱的两层归类 + 「列表/创建」双入口）

> 老板指令沿革：
> - v1（21:30）进销存做成可展开容器 → **被否决**「进销存是高频操作，不能藏在二级菜单里」
> - v2（21:50）取消折叠、全部平铺一级直达 → 保住高频可达，**但丢掉分类表达力**
> - v3（21:40~22:30）学舟谱**两层结构**：一级按职能切区 + 悬停弹窗**按业务对象分列**

>   ⇒ v3 只学了「分列」，漏了**行内的双入口**。v4 补上，并由此**反推出一条信息架构约束**（见 §4.4）。

## 一、v1 / v2 / v3 的教训（保留，避免重犯）

| 版本 | 提法 | 判定 |
|---|---|---|
| **v1** | 「进销存」= 可展开容器（点击展开 → 再点采购/销售） | 🔴 **错**。这就是二级菜单 —— 2 次点击、展开态还占位 |
| **v2** | 取消折叠，11 项平铺一级直达 | ✅ 方向对（高频可达），⚠️ 但只剩一个平面，没有分类表达力 |
| **v3** | 一级按职能切区 → 悬停弹窗按业务对象分列 | ✅ 兼得 1 次点击 + 分类表达力，⚠️ **但行内只有「进列表」一个动作** |
| **v4** | v3 + 行内**双入口**：`对象名`（进列表）｜`创建`（进空表单） | ✅ 把**最高频动作（开单）**提到弹窗里 |

**根因链**：v1 把「归类」做成了「层级」；v3 破题 —— 归类靠「弹窗分列」实现，不必靠菜单层级；
v4 再进一步 —— **弹窗不仅要回答「去哪」，还要回答「去干什么」**（看历史 / 开新单 是两种意图）。

## 二、舟谱到底怎么归类（逐张截图实读）

### 2.1 第一层：侧栏一级 = 按职能/业务对象切 12 类

自上而下：**常用功能 · 档案管理 · 采销管理 · 仓配管理 · 资金管理 · 财务管理 · 对账助手 · 市场营销 · 员工考核 · 数据报表 · 应用中心 · 设置**

分类依据 = **「哪个科室在用」**，不是「做什么动作」。每个一级项右侧带 `›` 箭头。

### 2.2 第二层：弹窗内 = 分类列（列标题）+ 条目平铺

| 规律 | 舟谱实例（实读截图） | 我们怎么用 |
|---|---|---|
| **① 列标题 = 业务对象 + 后缀**（`相关`/`作业`/`管理`/`设置`） | 档案管理：`商品相关/往来相关/资金相关/财务相关/员工相关/自定义/期初录入`；仓配管理：`仓库作业/配送作业/库存作业/库存查询`；资金管理：`客户相关/供应商相关/内控相关/库存成本` | 档案管理区四列：`商品相关/往来相关/组织相关/仓储相关` |
| **② 对偶对称**（甲方 ↔ 乙方） | 资金管理「客户相关」与「供应商相关」**一一对应**：`收款单↔付款单`、`客户费用单↔供应商费用单`、`客户收入单↔供应商收入单` 乃至 `预收款单↔预付款单`、`预收退款单↔预付退款单` | 进销存区 `采购↔销售` 两列对称 |
| **③ 动作成对**（主单 + 反向单） | `访销订单/访销退单`、`采购订单/采购退货订单`、`其他入库单/其他出库单` | `采购进货/采购退货`、`销售出货/销售退货` 同列相邻 |
| **④** ⭐ **行内双入口**（**本轮新增 · 见 §2.4**） | `采购订单 ｜ 创建`、`收款单 ｜ 创建` | **每个单据型条目都带「创建」** |
| **⑤ 行内徽标**（第三类表达） | `[明细]` 蓝标、`[可催收]` 红字、列标题 `物料管理[冰箱、瓶盖]` 橙标 / `促销活动[短信推送]` 蓝标 | 可选：标注「仅车销」「仅低温」 |

### 2.3 弹窗的版式与交互（实读）

| 项 | 舟谱做法 |
|---|---|
| 触发 | 一级项右侧有 `›` 提示；鼠标移到一级项上即弹出浮层 |
| 位置 | 紧贴一级项**右边缘**、与一级项**顶部对齐**（好在不同截图里都验证过：悬停越靠下的一级项，浮层顶部也越低） |
| 形态 | **浮层**（不推挤右侧内容），白底卡片 + 浅阴影 |
| 列结构 | 多列并排；列间有**竖向细线**；每列顶部**加粗列标题** + 标题下**横向细线**，再列条目 |
| 列宽 | 随内容自适应；条目多就**加列**（数据报表弹窗宽到 **7 列**） |
| 收起 | 鼠标移开即收起 |

## 三、⭐ §2.4 本轮核心发现：「列表 + 创建」双入口模式

> 老板原话：**「有很多弹窗都是列表和创建在一起的，比如：采购订单旁边是创建，点击采购订单即可展开采购订单列表，点击旁边的创建即可进入创建订单界面」**

我把 9 张截图全部放大到 3 倍逐行核对，**这条规律完全成立，而且是舟谱弹窗设计里最实用的一层**。

### 3.1 一行 = 两个可点区域（行结构解剖）

```
 ┌─────────────────────────────────────────────┐
 │  采购订单                     创建           │   ← 一行
 └───┬────────────────────────────┬─────────────┘
     │                            │
     ▼ 点左边（深色·主入口）        ▼ 点右边（浅灰·次入口）
   采购订单【列表页】             采购订单【新建表单】
   （看历史单据 / 查询 / 打开）     （直接开一张空单）
```

| 特征 | 左：对象名 | 右：创建 |
|---|---|---|
| 文字颜色 | **深色**（近黑） | **浅灰**（明显弱化） |
| 字号 | 正常 | **略小** |
| 对齐 | 左对齐（列内） | **右对齐**（贴列右缘） |
| 语义 | 进入**列表/查询**页 | 直接进**新建表单**（跳过列表） |
| 视觉权重 | 主 | 次（不抢戏，但一眼可见） |

🔴 **它仍是「一级项」**：整行不产生第三层菜单 —— 只是**同一行承载两种意图**。

### 3.3 判据：什么条目才配「创建」？（从实测反推）

**一句话判据 ——「能不能由人凭空开一张单」。**

| 有「创建」 | 没有「创建」 | 原因 |
|---|---|---|
| 采购/销售/访销/车销/自提/调拨/退货 各类订单、**盘点单、报损单** | 入库单、出库单、拣货单 | 出入库由**上游单据流转生成**，不手工新建 |
| 收款单/付款单/核销单/费用单/预收款单/资金转账/成本调价 | 销售结算单、采购结算单 | 结算由**期末/流程生成** |
| 凭证管理 | 总账、明细账、期末结转、业务结账、报表 | 查询 / 报表 / 流程 |
| 借货/还货/预订货单、费用合同、物料采购/投放/回收/核销单 | 陈列类型、订货模板、返利模板、物料档案、组合搭赠… | **档案 / 模板 / 活动配置**（没有"新开一张"的语义） |
| — | 档案管理 / 员工考核 / 数据报表 / 设置**整组** | 基础资料 / 统计 / 报表 / 配置 |

⇒ **判据可执行化**：条目有「新建」语义 ⇒ 才挂「创建」。这条**将来能写成代码判据**（页面元数据加一个 `creatable` 位），**不靠人记清单**。

### 3.4 同行的另外三种徽标（与「创建」并列的第三类表达）

| 徽标 | 位置 | 实测实例 | 语义 |
|---|---|---|---|
| `[明细]` **蓝底小标签** | 条目**右侧** | `库存成本汇总 明细`、`应收款汇总表 明细`、`盈亏汇总表 明细` | 我还有一层**下钻明细表** |
| `可催收` **红字**（无底框） | 条目**名右侧** | `应收款汇总表 可催收` | 业务状态提示 |
| `[冰箱、瓶盖]` **橙底** / `[短信推送]` **蓝底** | **列标题**右侧 | `物料管理 [冰箱、瓶盖]`、`促销活动 [短信推送]` | 该列的**适用范围/渠道** |

⇒ 舟谱把「创建 / 明细 / 状态 / 范围」全部压缩进**同一行的水平空间**，这一行信息密度很高但**视觉层级清楚**（名 → 标 → 创建，颜色深浅分明）。

## 四、我们的现状（改造前）与 v3 的缺口

### 4.1 现状

`Shell.vue::NAV` —— **一层平铺、3 组 11 项**，全部单击直达：

```
── 经营 ──   经营工作台 · 预报订货管理 · 目标与返利 · 招投标雷达 · 进销存
── 核算 ──   货损核算 · 算工资
── 配置 ──   档案管理 · AI 引擎 · 定时任务 · 设置
```

问题：① 只有一层，无分类表达力；② 新功能无处安放（进销存 P0/P1 ≈10 项会把「经营」撑爆）；③ 分区维度不统一（场景/动作/系统混用）。

### 4.2 v3 的缺口（老板本轮点出）

v3 弹窗里每个条目**只有一个动作** —— 点进去 = **列表页**。而要开一张新单，用户还得：

```
v3 路径：悬停「进销存」 → 点「销售出货」 → 等列表加载 → 点页面里的「新建」    = 4 步
舟谱路径：悬停「进销存」 → 点「创建」                                    = 3 步，且不用等列表
```

对**每天要开十几张单的业务员**，这不是小差别 —— **最容易点错、最花时间的那一步（在列表里找"新建"按钮）被省掉了**。

### 5.4 ⭐ 由「双入口」反推出的一条信息架构约束（重要）

舟谱能挂「创建」，是因为它的**列表页 与 创建页 是两个独立页**：

```
采购订单列表  /purchase-order              ← 点"采购订单"
采购订单新建  /purchase-order/create       ← 点"创建"
```

而**我们现有页面大多是「列表 + 弹窗表单」同页**（如 `Forecast.vue`）—— 这种情况下**没有「创建」这个独立目标**，点了只能落到列表页。

⇒ 🔴 **约束 = 进销存的「建单」必须有独立路由**：

| 方案 | 形态 | 能否挂「创建」 |
|---|---|---|
| **A（舟谱式）** | 列表页 + **创建页（独立路由）** | ✅ 能 |
| **B** | 列表页 + 同页弹窗表单 | ⚠️ 只能"跳到列表页并自动打开表单"（`?new=1`），本质仍是跳列表 |
| **C** | 列表页 + 抽屉表单 | 同上 |

**建议 A**，理由：① 完全对齐舟谱；② **创建页字段多**（一单十几个字段 + 明细行），独立页比弹窗宽敞得多；③ 深链可分享（`/inventory/purchase/create`）；④ 与 v380 能力闸门天然兼容（新路由还是判 `inventory` 模块）。

> 🔴 这条要在**进销存 P0 页拆设计时就定下**，否则后面改要动路由 + 所有开单入口。**现在成本为零，返工成本很高。**

## 六、关键澄清：弹窗 ≠ 折叠容器（v2 原则全保住）

| | v1 的「可展开容器」（❌ 已否决） | v3/v4 的「悬停弹窗」（✅） |
|---|---|---|
| 触发 | **点击**展开 | **悬停**即弹出（不算点击） |
| 面板 | **常驻**、占位、推挤内容 | **浮层**、不占位、移开即收 |
| 到子项几次点击 | **2 次**（展开 + 点进） | **1 次**（点进 / 点创建） |
| 高频操作体验 | 每天开单都多一步 | **比平铺还快一步**（可直接落"创建"） |

**三条硬约束**原样保留：
1. **高频项不许只存在于弹窗深处** —— 弹窗内**每一条都是 1 次点击**；
2. **权限判据一行不动** —— 可见性仍由 `canSee(path)` → `pages.js` **唯一裁决**；弹窗只负责**排版**（v291 纪律：不在模板补 `v-if`）；
3. **分组标题由条目算出来** —— 不写第二份判据（v311 纪律）。

## 七、交互规范

| 场景 | 行为 |
|---|---|
| **桌面 · 鼠标** | 悬停一级项 → 弹窗展开（收起**延时 180 毫秒**，防「移开就消失」的焦虑 —— 对舟谱即时收起的**有意改良**）；悬停到条目行，**左半高亮=进列表 / 右半「创建」单独高亮**（让"两个区域"可感知） |

| **「创建」的权限判据** | 🔴 只判 `canSee(path)` **不够** —— 还要 `canDo(module,'create')`：没开单权限的人**不该看见「创建」**（舟谱是 SaaS 全功能，无此问题；我们是 RBAC，必须做） |

## 八、落地步骤与风险

| 步骤 | 做什么 | 风险 | 可回退 |
|---|---|---|---|
| **L0** | `NAV` 结构升级 `{label, items}` → `{name, icon, groups:[{label, items}]}`；`Shell.vue` 新增弹窗组件 + 版式 CSS；**档案管理区先落地**（页最全，且**整区无创建** ⇒ 先验骨架不碰双入口） | 中 | ✅ |
| **L1** | 给条目加 `creatable` 位 + 「创建」行内按钮；**先在「订货管理·预报订货管理」试点**（该页已有"新建预报"能力，可零新页验证交互） | 中 | ✅ |
| **L2** | 其余 5 区按 §5.3 落地；手机抽屉继续读 `groups` 平铺 | 低 | ✅ |
| **L3** | 🔴 **进销存 P0 页拆设计时，按 §5.4 采用「列表页 + 独立创建页」**（这是信息架构决定，不是 UI 决定） | 中 | ⚠️ 返工贵 |
| **L4** | 手机端把最高频 1~2 个进销存项考虑进底部栏 | 中 | 需回归手机 |

**风险与规避**：
1. 🔴 **弹窗内也要按 `canSee` 收窄，空列/空弹窗必须隐藏** —— 否则业务员会看到空的「往来」列标题，导购/司机会看到**没有条目的空弹窗**。实现：`groups.map(c=>({label:c.label, items:c.items.filter(canSee)})).filter(c=>c.items.length)`，再由「所有列都空 ⇒ 整个一级项隐藏」收口。**这是唯一新增的判据点，必须与 `canSee` 同源，不许另写清单。**
2. 🔴 **「创建」必须判 `canDo(module,'create')`** —— 否则只读角色（如 `guide`）会看到一个点了 403 的按钮（比不显示更糟）。
3. ⚠️ **图标名必须存在于 `Icon.vue`**（写错静默变齿轮，肉眼难发现）。
4. ⚠️ **一级项不可点** ⇒ 已存书签（如 `/archive`）需保留路由不变 + redirect 兜底。
5. ⚠️ **诚实的体量判断**：我们现在只有约 15 个页面，6 个弹窗多数只有 **2~4 个条目**，弹窗会显得「比内容重」（舟谱一个弹窗 10~20 项，因为它有几百个入口）。**建议先落地结构、随进销存上线逐步充实**；「订货管理」「经营分析」目前各只有 2 项，若觉得太空可先保持直达 —— 但**同屏内保持一致**，别有的弹有的不弹。
6. ⚠️ **行内两个可点区有误触风险** —— 舟谱靠**颜色深浅 + 左右分离 + 右对齐**区隔。我们应额外加**悬停分区高亮**；手机端改用 `＋` 图标（语义更明确，不靠位置）。

## 九、一句话总结

**舟谱的归类是两层的**：一级按**职能**切 12 区，悬停弹出浮层，浮层内**按业务对象分列**；
**每个单据型条目又是双入口** —— `对象名` 进列表、`创建` 进空表单（约 20% 条目有创建，判据 =「能不能由人凭空开一张单」）。

**v4 照这个骨架重做**：一级 6 个职能区 + 直达首页；每区悬停弹窗按类型分列；**单据型条目挂双入口**。

**v4 与 v3 的唯一新增**：行内「创建」；**但它反推出一条信息架构约束** —— 进销存的建单**必须有独立路由**，否则「创建」无处可落（§5.4）。
