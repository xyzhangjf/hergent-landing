### 1.3 兼容性红线（🔴 P0 / 动后端先查）

🔴 **任何后端改动，必须先核查是否被 Web 端 + 小程序端共享的 11 个接口调用**——破坏性改签名 / 返回结构会同时砸 Web 与小程序（小程序提审周期长、回滚慢）。

| 检查项 | 做法 |
|---|---|
| 改动前 | `grep` 这 11 个接口路由定义 + 前端 / 小程序调用点，列出影响面 |
| 改签名 / 返回体 | 必须向后兼容（加字段不删字段；字段改名 = breaking，需双写过渡期） |
| 改完 | 小程序侧至少跑一遍登录 + 报单主链路，确认未被静默破坏 |

- ✅ **token 安全加固**：readonly / disabled gating + token 哈希，已部分落地。评审新接口时沿用同一套，不另起炉灶。

## 二、多租户安全评审要点（🔴 硬约束）

1. **真实租户（tenant_1 / tenant_10）只读**；写须用户显式授权 + 在线备份 + 逐项断言（§7.1 规范）。
2. **自动化只准写隔离租户 9997+**（§7.2）。
3. **隔离沙箱失真**：克隆会把 `forecast_submissions.order_date` 全改成今天 ⇒ 凡依赖日期窗口 / 期次归属的口径，**去真实库只读手算**，沙箱结论不可信（§7.3）。
4. **脱敏红线（⛔）**：返利率 / 进货价 / 客户名 / 区域销量 / 厂家政策严禁出系统、进日志、落 `outputs/`；含生产凭据的仓库须 private；**禁止数据转售**（§7.4）。
5. **跨租户铁律**：只共享算法口径（参数名 + 量级桶），金额 / 工资 / 客户 / 进货价 / 返费率属商业秘密红线。

## 三、代码评审准入清单（Checklist）

> 每条 PR / 改动合并前，评审人逐条打勾；任一 🔴 未过 = 打回。

- [ ] **无硬编码凭据**（S1–S3 类回归防护）：密钥 / 口令全部走 `.env`，`pre-delivery-gate.py` 的 C2 检查 + `git secrets` 扫描通过（S1–S3 已闭环，仅防回归）
- [ ] **未破坏 11 个共享接口**的 Web / 小程序调用（§1.3）
- [ ] **新增接口沿用 readonly/disabled gating + token 哈希**，未另起鉴权方式
- [ ] **无静默失效**：无 `except: pass`、缺数据显式回退 + 回报行数
- [ ] **回落写法显式标记**，无 accessor 自递归（§5.4 规范）
- [ ] **多租户**：真实租户无未授权写；脱敏字段未泄露（§二）
- [ ] **版本号已实搜三处、无撞号**（§4 规范）
- [ ] **改动可独立回滚**，未把半成品带进共享构建目录
- [ ] **附带五段交付摘要 + 文件清单 + 已知风险**（§10 规范）

## 五、给评审人的"为什么"

- **硬编码凭据为什么最致命**：仓库（即便 private）有历史、有协作者、有 CI 日志，密钥一旦进去就"到处都是副本"，只能轮转不能删。
- **11 个共享接口为什么不能动签名**：小程序提审一次要数天，Web 与小程序共用后端，后端一枚改签 = 两边一起挂，回滚窗口极慢。
- **沙箱为什么不可信期次口径**：克隆脚本把日期全刷成今天，任何"按月份 / 期次统计"在沙箱里都命中全部数据，看着对实则假。

## 附：自动闸门 `pre-delivery-gate.py`（Checklist 可执行版）

> 位置：`.workbuddy/tools/pre-delivery-gate.py`。它是《发布前自查清单》里**能确定性判定**的硬判据的可执行版；凡需 SSH / 部署 / 人工判断的项，在报告里标 `SKIP` 并指向 Checklist 对应章节，由人打勾。

### 自动跑的检查（命中即输出"未过清单"）

| 编号 | 对应章节 | 检查内容 |
|---|---|---|
| A1 | A 起号 | 起号撞号搜索（`--version vNNN` 必带，否则 SKIP）：`.workbuddy/memory` + `.workbuddy/tools` + 迁移名 `_safe_migrate('vNNN_` + `scoped_stage_by_marker.py`，用 `grep -e`（**禁用 `grep "A\|B"`**） |
| B1 | B 编码 | 静默失效扫描：tracked `.py` 的 `except…: pass` 空吞、`.js/.vue` 的空 `catch{}` |
| B2 | B 编码 | 复用 `direct-self-recursion-check.py`（§5.4 accessor 自递归） |
| C1 | C 部署前 | 复用 `credscan-untracked.py`（未跟踪文件凭据） |
| C2 | C/S1–S3 | tracked 源码凭据 + **回归防护**：`hergent2026` / `hergent-prod-gateway-key` 再现 = FAIL（防已闭环债复活）；私钥块 / Bearer 长令牌 / 明文口令赋值 = FAIL |
| B3 | B 编码 | `grep "A\|B"` 反模式扫描脚本 / 文档（WARN） |

### 用法

```bash
python3 .workbuddy/tools/pre-delivery-gate.py --version v500   # 起号时带版本号
python3 .workbuddy/tools/pre-delivery-gate.py --json           # 机器可读输出
```

**退出码**：`0` = 无 FAIL（WARN/SKIP 不阻断）；`1` = 有 FAIL（应阻断本轮交付，回到 Checklist 对应章节处理）。

> ⚠️ 本工具只跑**本仓库**能静态判定的项；erp 后端仓库的安全债（S1–S5）需在那个仓库独立跑本工具复核。
