# v733 · 移动端工作台任务行：标题逐字竖排（既有 P0）

## 现象

375px 视口打开工作台，「今日要务」列表里的任务标题变成**一列竖排单字**：

```
绿 环
（义
乌
店）
·
应收
逾期
```

单张卡片被撑到 **410px 高**，一屏连一张都看不全。副驾那一行「欠款¥1,677；已逾期1037天」
看着是横排的，其实**已经溢出卡片边界**（`overflow:visible`），压在按钮底下。

**这是既有 bug，不是 v732 引入的** —— v731 生产版基线图里一模一样。
它是做 v732 字号拆分、第一次建立 375 基线时被顺手照出来的。

---

## 根因：固定项之和超过容器，可压缩项被压到 0

不是"宽度算错"，是**算不平**：

| 项 | 值 |
|---|---|
| 卡片宽度（375 − 页面边距） | 313 |
| 减 border + padding（18 左 / 16 右） | 277 ← **可用内容宽** |
| `.tag`「应收逾期」 | 64 |
| `.task-acts`（两个按钮，`flex-shrink:0`） | 189.8 |
| `gap` × 2 | 24 |
| **固定项合计** | **277.8 > 277** |

```css
.task-main{ flex:1; min-width:0 }   /* ← 唯一可压缩项，且 min-width 允许压到 0 */
.task-acts{ flex-shrink:0 }         /* ← 一个像素都不让 */
```

超了 0.8px，于是**整份亏空都由 `.task-main` 承担**，宽度算成 **0px**。

文字没有跟着消失，因为 `overflow:visible`：

- `.task-title`（14px）在 0 宽盒子里每个字换行 ⇒ 高 218.5px
- `.task-sub`（12px）同样换行，但溢出后横着显示 ⇒ 看着"正常"，实际已出界

DOM 实测（v732 线上）：

```
.task-main      w=0      h=380.4
.task-title     w=0      textW=28.2   h=218.5
.task-sub       w=0      textW=49.5   h=149.3
.task-row       h=410.4
```

---

## 修法：窄屏改两行

```css
@media(max-width:768px){
  .task-row{flex-wrap:wrap}
  .task-main{flex:1 1 60%}
  .task-acts{flex:0 0 100%;justify-content:flex-end}
}
```

第一行「徽标 + 标题」，第二行「按钮右对齐」。行间距由已有的 `gap:12px` 提供，不额外加 margin。

**为什么 `flex-basis:60%` 而不是 `calc(100% - 76px)`**：76 是「徽标 64 + gap 12」，
但徽标宽度随文案变（「应收逾期」/「库存预警」），而 `.task-ic` 分支只有 36px。
写死 76 会在其它分支留 40px 空洞。60% 是"先占住六成，剩下的交给 flex-grow"，
**不依赖任何固定项的具体数值**。

---

## 修复后（DOM 实测）

| 指标 | v732 | v733 |
|---|---|---|
| `.task-main` 宽 | **0px** | **201px** |
| `.task-title` 高 | 218.5px（竖排） | **17px**（一行） |
| `.task-sub` 高 | 149.3px | 15px（一行） |
| 单卡高 | **410.4px** | **114.6px** |
| 横向溢出 | 375 = 375 | 375 = 375 |

标题文本宽 167px，容器 201px ⇒ 一行放下，不再换行。

## 记一条判据

**"某个文字容器被压到 0" 的症状不是空白，而是竖排。**
因为 `overflow:visible` 下文字仍在，只是每个字都触发换行。
看到竖排先查 `getBoundingClientRect().width === 0`，再去看 `flex-shrink` 与固定项之和 ——
这类问题用肉眼看"像字体坏了"，用 DOM 一量就现形。
