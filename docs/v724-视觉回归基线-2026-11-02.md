# v724 · 视觉回归基线

> 2026-11-02。这是 v723 评审里「最该投的一项」的落地。目标只有一个：**改了 CSS，别的页被顺带改坏时能自动发现**。

## 为什么探针不够

v717–v723 连续七版做视觉整改，每版都靠探针验收（对比度、图标尺寸、焦点环、表头冻结）。但探针只验证**被写进探针的那些判据**：

| 场景 | 探针 | 用户肉眼 |
|---|---|---|
| 某页按钮底色变了一档 | 若不在判据里 ⇒ **0 缺陷** | 一眼看出来 |
| 某页行高被连带改了 4px | 不在判据里 ⇒ **0 缺陷** | 觉得「这页怪怪的」 |
| 深色某些徽标变灰 | 对比度探针能抓（已抓过） | — |

v723 第二轮改的是 `.btn.on`、`--pri`、`--p-dark` 这些**共享令牌/共享类**，一处改动波及哪些页面，只能靠人记住。缺一层兜底。

## 怎么做的

两个工具，零新依赖：

- `.workbuddy/tools/visual-baseline.mjs` —— 自研 CDP 驱动（`lib/cdp-lite.mjs`）抓图。**没有用 puppeteer**：本机 Chrome 153 与 puppeteer 23/25 都有 `Requesting main frame too early!` 的已知冲突。
- `.workbuddy/tools/visual-diff.py` —— PIL 逐像素比对，**不给前端仓加 npm 依赖**。

### 三个设计决定（都有代价，写清楚）

**① 只截视口 1440×900，不截整页。**
整页高度随数据量变化（表格行数）⇒ 天天不一样，基线根本不能用。视口覆盖「首屏信息层级」，正是设计评审最在意那一层。要查表格下半部分，用 `v721-scroll-region-audit.mjs` 和对比度探针，不走这里。

**② 阈值来自实测，不拍脑袋。**
先跑 A/A（同一构建连抓两次）再比：

```
24 张全部 0 像素；A/B 两组 PNG 字节完全相同
```

渲染是完全确定性的（GPU 已禁用、字体已 `document.fonts.ready`、动效已关、滚动条显式归零）。所以默认阈值压到 `px ≥ 800 且 pct ≥ 0.05`。

**③ 必须分清两种噪声 —— 这条决定工具能管什么。**

| | 来源 | 量级 | 谁管 |
|---|---|---|---|
| 渲染噪声 | 字体回退 / 滚动条宽度 / 动画中间态 / 焦点环 | 实测 **0** | 阈值 |
| 数据噪声 | 表格多一行、金额变了 | **无上界**（一行表格 ≈ 4.4%） | **抓图时间窗** |

推论：**阈值再严也拦不住数据变化**。所以真正的纪律是——基线在改完之后、部署之前抓，候选在部署后立刻抓，两趟控制在几分钟内。白天有单进来时，列表页的差异不能归咎于样式。

### 灵敏度实测

在 `inv-purchase` 首屏上合成纯色块：

| 合成改动 | 像素 | 占比 | 结果 |
|---|---|---|---|
| 40×20 | 861 | 0.07% | 报「变化」（刚好压线）|
| 60×30 | 1891 | 0.15% | 报「变化」 |
| 120×60 | 7381 | 0.57% | 报「变化」 |

⇒ 一个徽标/按钮换色这个量级就能抓到。

### 四条硬校验（照 v723 假「0」的教训写的）

抓图脚本对每页断言，任一不过**退出码 2、不出基线**：

1. 页面文本不含「登录已过期 / 请重新登录」——SPA 不报错、不跳登录页，只在页面上写一行字；
2. 节点数 ≥ 200 —— 白屏或静默回退时会掉到个位数；
3. `location.hash` 真的落在目标路由 —— 失败时所有页都渲染成工作台；
4. 顶栏用户名不是「我」—— 这是未登录的兜底显示。

外加截图字节数 < 3000 判空白页。

v723 就是靠「节点数从 12k 掉到 3.3k」这个信号才发现探针整体失效的，这四条是把它固化下来。

## 日常用法

```bash
# 1. 动手改之前，先抓一份「改之前」的基线（此时线上还是老构建）
HG_TOKEN=xxx node .workbuddy/tools/visual-baseline.mjs --set before

# 2. 改、构建、部署

# 3. 抓「改之后」
HG_TOKEN=xxx node .workbuddy/tools/visual-baseline.mjs --set after

# 4. 比
python3 .workbuddy/tools/visual-diff.py \
  --baseline .workbuddy/visual-run/before \
  --candidate .workbuddy/visual-run/after \
  --out .workbuddy/visual-run/diff
```

退出码 1 = 有页面超出阈值，可以挂进 pre-push 或部署脚本。
`--out` 会为每张有差异的图生成 `<theme>__<slug>.diff.png`：未变区域压淡、变化处涂红，一眼看出改在哪儿。

## 已知局限（别指望它做它做不到的事）

- **只管首屏**。滚动区中部/底部的回归看不到。
- **管不住数据变化**。见上面「两种噪声」。
- **不判断好坏**，只报「变了」。变了可能是修好的，也可能是改坏的 —— 仍要人看一眼 diff 图。
- **基线要随每次验收更新**：确认某页的变化是「想要的」，就把候选覆盖进 `.workbuddy/visual-baseline/`，否则下次会一直报同一处差异。
