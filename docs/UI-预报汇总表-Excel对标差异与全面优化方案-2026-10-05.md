## 零、结论摘要（先看这个）

**一句话**：我们的表格交互**已经覆盖了 Excel 的"高频主干"（选择/键盘/剪贴板/填充/冻结/缩放/导出），
但有三类真实缺口 —— ① **少数"写了但不可达"的假实现**（比没写更危险）；② **少数"会静默改坏数据"的语义缺口**；
③ **交互能力全部锁在一个页面、一个 13,539 行文件里**，另外 27 个表格页近乎零。

| 类别 | 项数 | 说明 |
|---|---|---|
| **🔴 数据安全 / 假实现（必须修）** | **5** | 排序改底层+不重置选区、粘贴覆盖空值、Ctrl+End 不可达、打印假按钮、缺规格静默不计 |
| **🟡 体验缺口（该修）** | **14** | Shift+方向键、活动格分层、多列筛选、双击自适应列宽、冻结多列、筛选 `>0`… |
| **🟢 可放大资产（Excel 没有的）** | **12** | 沿用上一期、配方建议、单位换算、交叉表粘贴、错误一键修复… |
| **🏗 结构性问题** | **3** | 网格内核未提取、单文件 1.35 万行、语义口径分裂 |

**三条最重要的判断**（与直觉相反，建议先读）：

1. **最该修的不是"缺功能"，是"假实现"。**
   `Ctrl+End` 的代码写了、注释写了、`lastDataPos()` 也实现了，但**永远走不到**（被普通 `End` 抢走）；
   「打印」按钮存在，但只调裸 `window.print()`，**没走仓内已有的 `printable.js` 基建**。
   这类缺口**不报错、不失效、只是不动**，与"功能没做"相比更难被发现。

2. **Excel 的通用功能里，有一半我们"不该抄"。**
   Excel 是**通用**电子表格；我们是**周期性矩阵录入 + 口径强约束**的业务表。
   公式栏、多工作表、自定义数字格式、自动序列（1,2,3）、行高拖拽 —— 抄进来是负担不是能力。
   本文 §一 明确列出**「不抄清单」及理由**。

3. **真正的护城河在"反向差异"里，且已经存在。**
   「沿用上一期清单」「配方建议」「单位换算拦截」「缺规格不计入合计并显式报数」「交叉表粘贴（按商品名×客户名匹配）」
   —— 这些 Excel **做不到**。优化方案的一半篇幅应该是**放大它们**，而不是补 Excel 的通用功能。

## 一、对标标尺：拿 Excel 的哪一层当标尺

Excel 的能力可以拆成三层，我们对三层的策略**不同**：

| 层 | 内容 | 我们的策略 | 理由 |
|---|---|---|---|
| **① 交互契约层** | 选中什么高亮什么、方向键走位、复制粘贴、撤销重做、冻结、填充 | **全抄，且必须一致** | 用户的肌肉记忆来自 Excel。**不一致 = 手感错**，代价最高 |
| **② 通用数据工具层** | 排序筛选、查找替换、条件格式、列宽自适应 | **按业务价值选抄** | 有些我们已有更好的等价物（见 §三） |
| **③ 排版与通用计算层** | 公式栏、多工作表、自定义数字格式、自动序列、行高 | **明确不抄** | 与业务模型冲突或纯负担 |

### 🔴 「不抄清单」及理由（防盲目堆功能）

| Excel 功能 | 不抄的理由 |
|---|---|
| **公式栏 / 单元格公式** | 我们的"计算列"是**服务端权威口径**（最终下单、下单金额、合计箱数）。让用户在前端写公式 = 造第二套口径 → 与后端对账冲突。**现在的"计算列不可编辑"是正确设计** |
| **多工作表 / 工作表标签** | 我们的"多表"语义 = **期次**（`period`），是**有业务状态机**的实体（open/closed/void + 授权改单），不是 UI 标签页。做成标签页会丢状态 |
| **自定义数字格式（0.00/千分位/百分比）** | 用户明确要求**整数显示**（"包/箱不带小数"，见 `.workbuddy/memory` 用户偏好）。可配置格式会破坏这个约定 |
| **自动序列（1,2,3… / 等差）** | 报单表填的是**数量**，没有"序列"业务。填充柄只该做"复制值" |
| **行高拖拽** | 行高固定 34px 是**刻意**的（保证一屏行数可预期）。可拖拽只会让表参差不齐 |
| **色筛 / 条件格式编辑器** | 我们的"条件格式"是**业务规则驱动的**（安全库存/短保/缺规格/MOQ），用户自己配颜色 = 让业务告警失去统一语义 |
| **合并单元格** | 交叉表是矩阵，合并会破坏 `<td>` 坐标系（`data-r`/`data-c`），而坐标系是选区/粘贴/键盘的全部地基 |

> ✅ **对标纪律**：任何"Excel 有这个功能所以我们也该有"的提案，必须先回答
> **「它在我们这张矩阵上解决哪个具体录入痛点」**。回答不了就不做。

## 四、业务特性驱动的专项优化 G（12 项）

> 判据：**"它在我们这张矩阵上解决哪个具体录入痛点"**。每条给出可失败的验收判据。

### G-1 🔴 列级权限：从"前端展示级"加固为"双端一致"（P0·★★★★★）

**现状（实证）**：机制**已接线** —— `store/index.js:164` 会把登录角色落到 `store.user.role`，
`bizRole`（`:4117`）优先取它，`canSeeCol`（`:4132`）在 `:4072` 真正参与列过滤，`dist_price` 仅 `admin/boss/accountant` 可见。

**❗但代码里的注释 `:4097-4108` 声称"全仓无人给 store.user.role 赋值"—— 这条注释已过期**（子扫描据此误判为"空转"）。
**真实残留风险**：① `bizRole` 的 UI 切换器已撤（`:4119` 自陈"当前无 UI 入口"），行为完全依赖 `store.user.role` 被正确填充；
② **仅前端展示级隐藏** —— 列头/导出/接口是否也隔离，取决于后端。

**方案**：① 修正 `:4097-4108` 的过期注释；② 真机验证 `dist_price` 在 accountant 角色下确实不渲染；
③ 后端对同名列做**同源**的字段级过滤（前端隐藏 ≠ 安全边界）。
**判据**：`grep -c "user.role = " src/store/index.js` ≥ 1；真机以 `accountant` 登录，`dist_price` 列 `getComputedStyle` 不存在。

### ~~G-2 🔴 「只看本期有报单的商品」一键筛选（P0·★★★★★）~~ → ⚠️ **已撤回（功能本已存在）**

> 🔴 **2026-10-05 实测更正，本节作废**：`hideZeroReport`（`:3070`）＋勾选框「仅显示有报单」`(:768/:1020)`
> 就是本项要的东西，且已在 `rowShown`/`filteredRowsForExport`/打印副标题三处生效。
> 原判「不存在」的**漏检原因**：只沿 `colFilter` 一族查，没查独立 ref —— 教训是「查『有没有 X』
> 不能只按一种实现命名去 grep」。留本节原文仅为追溯，**不要照此施工**（会做出第二个重复开关）。

**痛点**：主表行底恒为**全量在售商品档案**（428 行量级），本期实际有量的常只有 ~100 行。
录数时要在 300 多行空行之间反复穿越。
**现状**：`filterText`（全局搜索）只支持"按商品名/编码搜"，**无"按数量筛"**；`colFilter` 只有一个且是"包含"语义。
**方案**：工具栏加**一键筛选芯片**：`只看有量` / `只看本期有量` / `只看报警`（复用现有 `.filter-chip` 样式），
与 `findText`/`colFilter` **叠加**生效（需先做 G-3 的多条件框架）。
**判据**：点"只看有量"后 `document.querySelectorAll('.edit-tbl tbody tr:not([style*="display: none"])').length`
= 本期 `rowSum>0` 的行数（真机读数，非估算）。

### G-3 🔴 排序语义统一 + 选区安全（P0·★★★★★）

**痛点（数据风险）**：`applySort`（`:7301`）与 `sortByCol`（`:6706`）**直接 `cross.value.rows.sort()` 并 `saveDraftNow()`**
—— 改的是**底层数据顺序**并**持久化**；而只读态排序是对副本排序。
后果：① 编辑态排序后 `selected.r` 指向别的行（注释自陈"属于既有行为"）⇒ **按 Delete 删错行**；
② 行序被写进草稿 ⇒ 刷新后行序变了。
**方案**：① 排序改为**视图层**（`displayRows` computed），底层 `cross.rows` 永不动；
② 若必须落库行序，则排序**必须同时重置选区**（或按 `product_id` 重定位 `selAnchor`）。
**判据**：排序后立刻按 Delete，被清空的 `product_id` == 排序前的活动格 `product_id`。

### G-4 三列并排：本期 / 上期 / 同期（P1·★★★★★）

**痛点**：经销商判断"这个月报多少"的核心依据是**对比**。现有 `comparePrev`/`yoyDelta` 是**单列差值**，
看不出"上期到底报了多少"。
**方案**：列方案预设「对比视图」= 本期量 + 上期量 + 同期量 + 差异率（4 列一组，`colVis` 一键切换）。
数据源复用既有 `snapshot`（快照对比）机制，**不新增后端接口**。
**判据**：切换列方案后同屏出现 3 个量列，且上期量与 `/api/forecast/...` 返回的上期值逐行相等。

### G-5 交叉表粘贴的"匹配回执"（P1·★★★★）

**痛点**：R-5 的名称匹配是**静默**的 —— 匹配不上的商品/客户被跳过，用户不知道漏了什么。
**方案**：粘贴后回执改为三行式：`写入 N 格 ｜ 未匹配商品 M 个（名称：…）｜ 未匹配客户 K 个（名称：…）`，
复用现有 `toast` + `cellErrDot` 机制把未匹配项标黄。
**判据**：构造含 1 个不存在商品名的粘贴文本，回执里该名称出现且 `M=1`。

### G-6 配方建议的「采纳/忽略」留痕（P1·★★★）

**痛点**：`suggest` 列算出建议值，但无人知道业务员是否采纳。
**方案**：单元格加微标（采纳 = 值等于建议；偏离 = 显示偏离比例），并把采纳率汇总进冲刺看板。
**判据**：修改一格使其等于/不等于建议值，微标随之切换。

### G-7 均单/目标反馈从"有条件显示"改为"常驻+说明缺什么"（P1·★★★★）

**痛点（静默失效）**：v324 的均单提示有**四个前置**（目标 + 换算 + 到货规则 + 行内单位同源），
**缺任一就静默不显示** —— 用户看不到任何东西，也不知道为什么。
**方案**：前置不全时**显示占位条 + 明确缺哪一项**（如"缺到货规则 ⇒ 去『到货节奏』配置"），
复用现有 `.gate-bar` 常驻横幅范式（`:28-65` 已有 4 处同款）。
**判据**：删掉到货规则后，该条以"缺 X"文案出现（现在是无任何元素）。

### G-8 编辑网格行渲染窗口化（P0·★★★★★，与 F-1 同项）

**痛点**：428 行 × ~30 input ≈ 1.2 万节点，分页只 `display:none`。行数越多越卡。
**方案**（不动业务逻辑，三步）：
① `rowShown` 由 `v-show` 改 `v-if`（**最小改动、最大收益**，DOM 节点直接降 90%）；
② 参照只读表的 `vsWindow` 给编辑表加同款窗口化（`ROW_H=34` 已具备常量）；
③ 补 `v-memo` 到 `<tr>`。
**判据**：真机 `document.querySelectorAll('.cell-qty').length` 从 ~3234 降到 ≤ `pageSize × 客户列数`

### G-9 单位混输提示（P1·★★★）

**痛点**：报单单位铁律"永不落大单位"。若用户在"小单位"列手输按箱的量，数值会被当小单位直接落库。
**现状**：有 IME/全角容错（R-3），**无"量级异常"提示**。
**方案**：与本列单位换算比对照（`products.large_ratio`），偏离超阈值时弹软提示（**不拦截**，仅高亮 + 悬停原因），
复用 `rowWarn` 那套"软警告不拦保存"的范式。
**判据**：在小单位列输入恰好等于 1 箱的数量，出现软提示且保存仍成功。

**判据**：点"打印"打开的是新窗口（不是浏览器原生打印 428 行整页），且第 2 页仍有表头。

### S-1 🏗 网格内核未提取：交互能力锁死在一个页面（P1·★★★★★ 战略）

**方案（三步，风险递增）**：
1. **先抽 composable**（不改 UI）：把选择模型（`selected/selRange/selAnchor/selAxis`）、

3. **最后抽组件** `<DataGrid>`：新页面（客户档案/商品档案/价格方案）直接复用。

**判据**：第 1 步后 `Forecast.vue` 行数下降 ≥ 15%，且 v377/v378 回归探针**零差异**。
**风险**：这是**重构**不是新功能 —— 必须一趟一趟来、每趟都跑回归，**不要在业务迭代期夹带**。

### S-2 🏗 单文件 13,539 行 / 914 KB（P2·★★★）

`Forecast.vue` 已超过多数编辑器的舒适区，也让"改一处读全文件"的成本极高。
**方案**：与 S-1 同源 —— 抽 composable 的同时自然瘦身；优先把 **CSS 块**（约 2,000 行）与 **列注册表** 拆出。
**判据**：文件 ≤ 10,000 行，且无新增构建体积。

### S-3 🏗 语义 / 口径分裂（P2·★★★）

实证到的分裂：
- **同一个量两个 key**：只读表"合计(小单位)"=`qty`，编辑网格=`sum`（`:3523-3524` 自陈"历史命名分裂"）。
- **排序两套**：只读态副本排序 vs 编辑态改底层（G-3）。

**方案**：① 统一 `qty`/`sum`（保留别名过渡）；② 排序统一（G-3）；③ 金额口径由业务裁决（E-14）；

**判据**：`grep -c "注释已过期"` 归零即为完成。
