# v724 · 圆角阶梯收敛与护栏

> 2026-11-02。起因：v723 评审里「圆角令牌采纳率 39%，527 处字面量，无护栏」。

## 改前是什么样

全站 `border-radius` 有 **14 档字面量**：`2 / 3 / 4 / 5.5 / 8 / 11 / 12 / 14 / 16 / 18 / 20 / 22 / 24 / 99 / 999px`。
令牌只有 4 档（sm 8 / md 12 / lg 16 / xl 22），所以 8/6/12/16/22 之外的**全是各页自己拍的**。

真正的问题不是「档位多」，而是**其中一批数字其实在表达「胶囊」，只是写成了半高**：

| 位置 | 元素高度 | 写的圆角 |
|---|---|---|
| `.md-switch` | 22px | `11px` |
| `.tb-copilot`（顶栏 AI 按钮） | 34px | `18px` |
| `.cp-demo` | ~33px | `20px` |
| `.wx-...`（天气格） | 13px | `5.5px` |
| `.la-chip` / `.cc-chip` / `.df-*-tag` | 20–30px | `11 / 20px` |

后果很具体：**元素高度一改，这个数字就不再是胶囊了**，角会突然变成「圆角矩形」。
这类值应该写 `999px`（不管多高都半圆），而不是写一个恰好等于当前高度一半的常数。

## 改成什么样

9 档，每条都有明确分工（写在 `variables.css` 的注释里，护栏报错时也会打印）：

| 令牌 | 值 | 用途 |
|---|---|---|
| `--radius-hair` | 2px | 1–3px 的指示条 / 图例小点 / 拖动把手 |
| `--radius-2xs` | 4px | 单元格、小标签（10–16px 高那一档）|
| `--radius-xs` | 6px | 小控件 |
| `--radius-sm` | 8px | 按钮 / 输入框（**主档，占比最大**）|
| `--radius-md` | 12px | 卡片 |
| `--radius-lg` | 16px | 大卡片 / 面板 / 空态图标盒 |
| `--radius-xl` | 22px | 弹窗 / 大面板 |
| `--radius-pill` | 999px | 胶囊 |
| `--radius-circle` | 50% | 正圆（头像、圆点）|

**关于 `--radius-hair` 为什么不并进 `2xs`**：2–3px 圆角用在 8×8 的图例点、5px 高的进度条上，它柔化的是 1px 的边，不是组件的角。把它提到 4px，8px 方块就成半圆了 —— 这是两类不同的东西，合并是错的。

## 护栏

挂进 `scripts/check-tokens.mjs`（`npm run build` 前的 `prebuild` 自动跑），判据三行：

> `border-radius` 的值剥掉 `var(--radius-*)` / `0` / `inherit` / `!important` 之后，
> 还剩任何字符 ⇒ **构建失败**。

```bash
node scripts/check-tokens.mjs
# ✓ 设计令牌护栏通过（存量待清：0 个文件 / 0 条）
# ✓ 图标尺寸护栏通过（允许 14 / 16 / 18 / 22 四档）
# ✓ 圆角护栏通过（只许 --radius-* / 0 / inherit）
```

阳性对照已验证：往 CSS 里塞一句 `border-radius:13px` 立刻报错，退出码 1。

### 护栏设计里踩到的两个坑（都跟「假阳性」有关）

1. **`0 !important` 被冤枉**。第一版只放行 `0`，忘了 `!important` 是优先级声明不是取值 —— 一跑就报 `MonthlyAchvChart.vue`。护栏第一跑就冤枉一个正确的地方，人就不信它了。已放行。
2. **`grep` 的 `\s` 在 macOS BSD 版不存在**。用它查残留时连续返回空，差点得出「已经清干净了」的结论；实际源码里是 `var(--radius-xs, 6px)`（逗号后有空格），换成字面量子串才查得到。同族的坑还有 `grep "A\|B"` 静默失效 —— **多模式一律 `-e`，带空白的匹配别用 `\s`**。

## 留给以后的两件事

- **`var(--radius-xs, 4px)` 那两处原意可能是 4px**（芯片 1px padding + 11px 字）。现在按死兜底处理成 6px，未改外观。要改成 4px 属于设计判断，需单独确认。
- **登录页 / 副驾抽屉没进视觉基线**（前者需要登出态、后者需要打开抽屉），而这两处的圆角这轮都动过（`.login-card` 20→22、`.cp-composer` 24→22）。要靠人眼确认一次。
