### 2.3 根因定位（只读取证，未做任何修改）

**关键事实一：定时任务确实被触发了**（不是「没跑」，而是「跑了但没执行成功」）：

```text
$ grep -i "hergent-backup" /var/log/syslog | tail -5
Sep 24 22:16:01 … cron[707]: (*system*hergent-backup) RELOAD (/etc/cron.d/hergent-backup)
Sep 25 02:00:01 … CRON[2582237]: (root) CMD (runuser -u hergent -- /bin/bash -c '/usr/bin/python3 /opt/hergent-erp/scripts/backup.py >> /var/log/hergent-backup.log 2>&1 && /opt/hergent-erp/scripts/sync_to_oss.sh >> /var/log/hergent-oss-sync.log 2>&1')
Sep 25 03:20:01 … CRON[2582524]: (root) CMD (runuser -u hergent -- /usr/bin/python3 /opt/hergent-erp/scripts/check_backup_alive.py >> /var/log/hergent-backup-alert.log 2>&1)
```

**关键事实二：任务行写法把「输出重定向」放进了以 `hergent` 身份运行的外层 `bash -c` 里**：

```text
$ cat /etc/cron.d/hergent-backup
…
0 2 * * * root runuser -u hergent -- /bin/bash -c '/usr/bin/python3 /opt/hergent-erp/scripts/backup.py >> /var/log/hergent-backup.log 2>&1 && /opt/hergent-erp/scripts/sync_to_oss.sh >> /var/log/hergent-oss-sync.log 2>&1'
…
20 3 * * * root runuser -u hergent -- /usr/bin/python3 /opt/hergent-erp/scripts/check_backup_alive.py >> /var/log/hergent-backup-alert.log 2>&1
```

对比：**03:20 那条能正常工作的巡检任务**，重定向写在 `runuser` **之外**（由 root 打开，故可写 root 属主的日志）；而 **02:00 那条**重定向写在 `bash -c '…'` **内部**（由 hergent 打开 ⇒ 无权限）。

**关键事实三：以 `hergent` 身份实测，确认权限不足**（探测未产生任何写入）：

```text
$ runuser -u hergent -- /bin/bash -c "test -w /var/log/hergent-backup.log && echo WRITABLE || echo NOT-WRITABLE"
NOT-WRITABLE

$ runuser -u hergent -- /bin/bash -c "echo probe >> /var/log/hergent-backup.log"
/bin/bash: line 1: /var/log/hergent-backup.log: Permission denied
```

**关键事实四：改动发生在昨天 22:15（晚于昨天 02:00 的成功备份），故昨夜是首次命中**：

```text
$ ls -l /etc/cron.d/
-rw-r--r-- 1 root root 1101 Sep 24 22:15 hergent-backup
-rw-r--r-- 1 root root  759 Sep 24 22:06 hergent-backup.bak-20260924-221553
```

**因果链**：cron 触发 → `runuser -u hergent` 成功降权 → 外层 `bash` 在建立 `>> /var/log/hergent-backup.log` 重定向时被拒 → **bash 直接报错退出，`backup.py` 根本没有被启动** → 备份目录未生成、备份日志无新增行 → 因 `&&` 连接，**`sync_to_oss.sh` 同样没有执行** ⇒ 本地快照与阿里云异地副本**同时缺失**。

**副作用确认**：该 bash 的错误信息输出到 cron 的 stderr（未重定向），系统无本地邮件投递（`/var/mail/root`、`/var/spool/mail/root` 均不存在），故这条错误**没有任何人能看到**。
