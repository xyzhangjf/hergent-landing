设计要点（**每一条都对应一个已踩过的坑**）：

1. **用 `date --iso-8601=date` 而非 `date +%F`** —— `cron.d` 里 `%` 是特殊字符（会被转成换行 + stdin），`+%F` 会把该行写坏。
2. **三段用 `;` 而非 `&&`** —— 护栏失败**不得**阻断备份本身；失败痕迹用 `2>>` 写进备份日志（不静默）。
3. **`chmod 700`** —— 与 `backup.py` 自建目录的形态一致（实测 `backups/2026-09-25/` 即 `700 hergent:hergent`），保证产物权限沿革一致。
4. **不改 `backup.py`** —— 该脚本在 git 仓库内且与生产逐字一致（md5 `d72630d0a9d6b51ad9e9e62d6a990f55`），本轮**不动它**，避免多出一条待提交的在途改动。
