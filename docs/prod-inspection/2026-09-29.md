### 2.2 根因（只读定位，含**数值自证**）

调用顺序（`scripts/backup.py::main()`）—— **先备份、后清理、清理在打印之前**：

```python
target  = os.path.join(ab.BACKUP_ROOT, date.today().strftime("%Y-%m-%d"))
results = ab._do_backup(target)      # ← ① 备份写入 backups/2026-09-29/（7/7 成功）
removed = ab._cleanup_old()          # ← ② 立刻执行保留策略清理
print("[%s] backup done: %d/%d ok, ... cleaned %d old dir(s) -> %s" % (...))
```

保留策略（`routers/admin_backup.py::_cleanup_old()`）—— **按「目录名」倒序排序，保留前 28 个，其余删除**：

```python
MAX_KEEP = max(DAILY_KEEP, WEEKLY_KEEP * 7)      # = 28
dirs = sorted([d for d in glob.glob(BACKUP_ROOT + "/*") if os.path.isdir(d)], reverse=True)
candidates = [d for d in dirs if not os.path.basename(d).startswith(("_", "pre_"))]
for d in candidates[MAX_KEEP:]:
    shutil.rmtree(d)
```

🔴 **缺陷本质**：排序键是**目录名字符串**，而 `YYYY-MM-DD` 以**数字**开头（ASCII 0x32），**字典序永远小于** `pre-v…` / `v…-pre` / `tenant_…` / `dami_memory_…` / `code…` 这类字母开头的目录。在 `reverse=True`（倒序）下，**日期目录恒定排在队尾 ⇒ 恒定第一批被删**。该目录下**非日期目录一旦累计超过 28 个，日期快照就会被全数清除**。

数值自证（在生产上以只读方式重放同一段逻辑）：

```text
总目录数 = 28
候选数(排除 _ / pre_) = 28
MAX_KEEP = 28
desc 排序后第26~27名：code / 20260709_v2   ← 队尾已全是非日期目录
日期目录剩余 = 0
```

- **候选数恰等于 28**（= MAX_KEEP）⇒ 与日志「cleaned 5 old dir(s)」完全吻合：**当天正是它把队尾的 5 个日期目录（含当天刚建好的 09-29）删掉的**。
- 时间线亦吻合：09-26 / 09-27 日志为 `cleaned 0`（未触顶），09-28 起变为 `cleaned 4`、09-29 为 `cleaned 5` ⇒ **触顶发生在 09-28**（当天新增 `pre-v302`/`pre-v307`/`pre-v312`/`pre-v313` 等非日期目录把日期目录挤出）。
- **`03:20` 告警脚本的期望值 7 个 / 50.1 兆**与备份日志的 `7/7 ok, 50.1 MB` **逐字吻合** ⇒ 交叉证明「备份本身是成功的，是产物被删了」。
