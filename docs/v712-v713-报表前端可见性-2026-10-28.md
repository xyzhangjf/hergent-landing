# v712 / v713 报表前端可见性修复（2026-10-28）

> 本轮起点是用户选的 **B：验证「前端报表是否体现 v707–v709 的新口径」**。
> 结论：**没有体现**，而且不是「显示得不准」，是**那个页面根本打不开**。
> 查证过程中又挖出两个同类根因，一并修掉。

## 一、验的是什么（先锁定唯一展示窗口）

| 候选前端 | 归属 | 是否调报表接口 |
|---|---|---|
| `/opt/hergent-cn-v2`（hergent.cn，Vue） | 预报 / AI 副驾 | **0 命中**（`balance-sheet`/`trial-balance`/`资产负债表` 全无） |
| `/opt/static`（erp.hergent.cn，静态 JS） | 进销存 ERP 后台 | **4 个 chunk 命中**，且 `index.html` 实际加载 `main-CWrK_ez4.js` |

⇒ **v708/v709 的报表口径，唯一能被「看见」的地方就是 `erp.hergent.cn`。**
（此前记忆里「前端仍是 v704」「前端无入口」的判断，是在 cn-v2 目录里 grep 出来的，属于**搜错目录**。）

## 二、三个根因（都是「静默失效」家族）

### 1. `window.statCard` 从未定义 ⇒ 报表面板永远转圈

- `main-CWrK_ez4.js` 里有 **885 处** `try{window.X=X}catch{}` 形式的导出。
- 运行时实测其中 **407 处 `window.X` 是 `undefined`** —— 模块里根本没声明，
  `ReferenceError` 被**空 catch 吞掉**，页面永远不知道少了个函数。
- `statCard` 是其中之一，却有 **26 处调用**（10 处 `window.statCard`）：
  固定资产页、工作台若干卡片、利润表(权责)、资产负债表(权责)、税务报表。
- 实测调用 `switchRptTab('bs-gl')` 抛 `window.statCard is not a function`
  ⇒ 面板 `innerHTML` 停在 spinner 上，**永远不动**。

**为什么没被发现**：`catch{}` 把错误吃干净，控制台无红字；面板只是「一直在加载」。

**修法（v712）**：不改 1.4MB 的 chunk，在 `index.html` 里、`<script type="module">`
之前插一段内联脚本定义 `window.statCard`：
- main chunk 是 `type="module"` ⇒ 天然延迟执行，内联经典脚本必定先跑；
- chunk 里那句 `try{window.statCard=statCard}catch{}` 仍会抛错被吞，**不会覆盖**；
- 语义按 CSS 契约反推：`.stat-card` + `.sc-blue|green|amber|red` 的 `:before/:after` 色条。
- `index.html` 与 `assets/*` 都是 `cache-control: no-cache, no-store` ⇒ 刷新即生效。

### 2. 明细字段从来不存在 ⇒ 7 行永远 `¥0.00`

前端读的是：

```
assets.cash / assets.ar / assets.inventory / assets.fixed_assets_net
liabilities.ap
equity.paid_in_capital / equity.retained
```

而 `get_balance_sheet_gl()` 只返回三个 `{"total": x}`。老 `get_balance_sheet()`
返回的是**顶层** `cash / ar / inventory_val / ap`，且取自 `receivables`/`accounts`/
`inventory` **业务表**，不是 GL —— **两边从来没对上过一次**。

⇒ 合计是真数、明细恒为 0。这比空着更糟：老板会以为「账户没钱、没有库存」。

**修法（v713）**：在 `get_balance_sheet_gl()` 里按科目编码前缀补明细，
仍走 v708 的「叶子有效」不重复计父子。**纯加法**：`total`/`balanced`/`unclosed_profit` 逐字未动。

| 行 | 口径（生产 COA 实测） |
|---|---|
| 现金及存款 | `10*`（库存现金 / 银行存款 / 微信 / 支付宝 / 个人户） |
| 应收账款 | `1122` |
| 库存商品 | `1405` + `1406`（两套编码同名，实账都有余额） |
| 固定资产净值 | `1601` + `1602`（固定资产 − 累计折旧） |
| 应付账款 | `2202`（贷方取正） |
| 实收资本 | `4001`（贷方取正） |
| 留存收益 | `4103` 本年利润 + `4104` 利润分配 + `unclosed_profit` |

每组另给一个 `other`（合计 − 已列明细），用于自证「明细 + other == 合计」，
也方便将来前端显示「其他」。

### 3. 全局 `scroll` 监听在 document 上取 `.closest` ⇒ 每次滚动都抛错

```js
document.addEventListener("scroll", function(t){
  var e = t.target.closest(".page-inner");   // t.target 可能是 document，没有 closest
```

⇒ 滚动即 `TypeError`，页面顶部弹红条 `JS Error: Uncaught TypeError`，
**表头吸顶（`thead.scrolled`）也随之失效**。

**修法**：`var e=t.target&&t.target.closest?t.target.closest(".page-inner"):null;`
（`assets` 是 `no-cache`，原地替换即可生效；已留 `.bak-v712b`）

## 四、还没修的（已定位、需拍板）

1. **利润表(权责) 显示的是全期累计简化口径**：`/api/reports/pnl?month=2026-10`、
   `?month=2026-06`、不带 month，**三次返回同一组数**（收入 8,786,105.85）。
   根因是 `get_pnl()` 走 `sale_orders` 现金制，且 GL 版在该月收入类无分录时回落；
   前端把「累计」当「当月」展示，还标着 `月份: 2026-10`。
   这是记忆里已登记的待拍板项（改它要动仪表盘 KPI），本轮**未动**。
2. **老口径「资产负债表 (BS)」tab 显示 `—` / `¥0.00`**（总资产 `—`、现金/应收款/库存价值全 0）。
   它读的又是另一组字段，与接口返回不匹配 —— 同一类「按从未存在的字段写」。
3. **税务报表 tab 点开弹的是「增值税报表」弹窗**（不是面板内容），且脚本化点击时
   会触发 `t.target.closest` 系列的另一处错误；本轮只修了 scroll 那一处。
4. **407 / 885 导出静默失效**：这是系统性债务，不可能逐个补。建议的做法是
   给 `try{...}catch{}` 块加**统一的失败上报**（一次性产出缺失清单），而不是继续点修。
