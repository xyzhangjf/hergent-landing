# Hergent 管理后台（hergent-admin）体验审计与世界一流对标

> 审计对象：`laozhangai-product/hergent-admin`（独立子站，部署 `/opt/hergent-admin`，经 nginx `/admin/` 访问）
> 审计方式：**逐文件实读全部 24 个源文件**（8 个页面 + 8 个组件 + 2 store + 2 工具 + api/样式/路由/入口），并对关键结论做 `grep` 实测取证，不凭印象下结论。
> 对标基准：Stripe Dashboard、Linear、Notion、Google Cloud Console、Vercel、Supabase、GitHub Settings。
> 日期：2026-09-24

> **实施进度（2026-09-24 19:5x 更新）**：**P0 七项 + P1-1 响应式已全部落地并上线** —— 前端 commit `560abd5`（14 文件，+380/−95），构建产物 `index-C5EadM2S.js` / `index-B6_R5k_5.css`，三层 md5 全等（本地 mac = 生产 FS = 公网 HTTPS）。
> **实测读数改善**：`@media` **0 → 2**；语义 `aria/role` **1 → 44**；可点击 `<span>` **清零**；内联 `style` **22 → 1**（仅余动态宽度绑定）。

## 〇、结论先行

**一句话**：hergent-admin 是一份**工程底子干净、令牌体系扎实、但"单机运营工具"层级**的后台——代码质量在业余项目里属上乘（组件化、无脏依赖、确认弹窗/空状态/字段校验都做了），但它离"可对外示人的 SaaS 控制台"还差三块：**① 防误操作与键盘/无障碍基础（P0）；② 响应式与数据可下钻（P1）；③ 效率与规模化准备（P2）**。

**八维度成熟度打分**（5 分制，证据驱动）：

| 维度 | 得分 | 一句话判据 |
|---|---|---|
| 信息架构 | ★★★☆☆ 3.0 | 浅而清晰，但有**死胡同指标**（KPI 不可点）、无面包屑、详情页无 Tab |
| 导航设计 | ★★★☆☆ 2.5 | 侧栏清晰；但无折叠、无 ⌘K、无全局搜索、无快捷键、`document.title` 从不更新 |
| 数据可视化 | ★★☆☆☆ 1.5 | 全站仅 1 个横向条形图（套餐分布），无任何趋势/环比/sparkline |
| 操作效率 | ★★★☆☆ 3.0 | 排序/分页/校验/确认齐备；但**无批量、无导出、无刷新**，且筛选分页全在前端 |
| 交互体验 | ★★★☆☆ 3.0 | ConfirmDialog 带后果说明是亮点；但模态无 Esc/焦点管理、确认策略不一致、无 Undo |
| 视觉一致性 | ★★★☆☆ 3.5 | 令牌化 CSS 体系良好；但 **22 处内联样式 + 13 处硬编码色**，4 套重叠徽标语义 |
| 可访问性 | ★☆☆☆☆ 1.0 | 实测语义 `aria/role` **仅 1 处**、键盘处理**仅登录页 2 行**、对比度不达 AA |
| 响应式适配 | ☆☆☆☆☆ 0.5 | 实测 `@media` **0 处**，侧栏固定 220px，手机上不可用 |

**总分 18.5 / 40**。**最高性价比的 5 个动作**（P0）：破坏性操作统一确认、模态可用性收口、可点击元素键盘可达、对比度修正、页面标题同步——**全部可在不动后端、不引新依赖的前提下当天完成**。

## 一、技术栈基线与架构事实（实测）

### 1.1 技术栈

| 层 | 选型 | 实测证据 |
|---|---|---|
| 框架 | **Vue 3.5**（Composition API + `<script setup>`） | `package.json` `vue ^3.5.13` |
| 构建 | **Vite 5.4**，`base:'/admin/'` | `vite.config.js:8` |
| 路由 | **vue-router 4，hash 模式** | `router/index.js:26` `createWebHashHistory()` |
| 状态 | **Pinia 2.2**（2 个 store：auth / toast） | `store/auth.js`、`store/toast.js` |
| UI 库 | **无**（100% 手写 CSS 令牌体系） | `package.json` 仅 3 个依赖 |
| 图标 | 自研 `Icon.vue`，内联 SVG，**7 个图标** | `Icon.vue:22-43` |
| HTTP | 自研 `fetch` 薄封装 + Bearer token（localStorage） | `api/client.js` |
| 语言 | **JavaScript（无 TS）**；无 lint / 无测试 / 无 CI | 无 eslint/prettier/test 配置 |
| 构建产物 | **单 bundle、无代码分割**、sourcemap 关 | 无动态 `import()` |

> **评价**：依赖极简（仅 3 个运行时包）是**优点**——对一人团队意味着零升级维护面、零供应链风险。**建议保持此路线**，不要引入 Ant Design/Element Plus 这类重组件库（对 8 个页面的后台是杀鸡用牛刀，且会带来长期升级负担）。

### 1.2 页面与路由（8 条）

| 路由 | 组件 | 名称 | 交互能力 |
|---|---|---|---|
| `/login` | `Login.vue` | 登录 | 表单 + Enter 提交 + 失效提示 |
| `/` | `Overview.vue` | 平台总览 | 只读（7 统计卡 + 1 条形图） |
| `/tenants` | `Tenants.vue` | 租户管理 | CRUD + 启停 + 筛选/搜索/排序/分页 |
| `/tenants/:id` | `TenantDetail.vue` | 租户详情 | 只读信息 + 用量 + **成员增删** |
| `/invite-codes` | `InviteCodes.vue` | 邀请码管理 | 生成 + 启停 + 删除（带确认） |
| `/registrations` | `Registrations.vue` | 注册流水 | 只读 + 日期筛选 |
| `/audit-logs` | `AuditLog.vue` | 操作审计 | 只读 + 动作/日期/关键字筛选 |
| `/users` | `Users.vue` | 平台用户 | 只读 |

### 1.3 布局骨架

```

├─ aside.sidebar (220px 固定, 深色 #1f2329)
│   ├─ .brand (logo + 标题, 60px)

│   │            .nav-group-title「治理」    → 邀请码 / 注册流水 / 操作审计 / 平台用户
│   └─ .side-foot (版本号)
└─ .content (flex column)

    └─ main.content-scroll (overflow-y:auto, padding:24px)
```
`App.vue:4-52`｜`styles.css:66-183`

### 1.4 关键交互流程

- **鉴权**：登录 → `POST /api/auth/login` 取 token → `whoami` 二次校验 `platform_admin` → 非管理员**立即清 token 并抛错**（`store/auth.js:24-35`）→ 路由守卫 `beforeEach` 首次进入校验（`router/index.js:30-42`）→ **api 层 401 自动跳登录并带 `?reason=expired`**（`api/client.js:40-47`，这个"会话失效可解释"设计是**优秀实践**）。
- **写操作范式**：字段级校验 → `saving` 态禁用按钮 → `POST/PUT` → `toast.ok` → 关闭弹窗 → **重新 `load()` 全量刷新**。
- **破坏性操作**：`ConfirmDialog` 携带 `text` + `consequence`（后果说明）——**这是全站最好的设计**，比 Stripe 的确认框更显性。

## 二、八维度逐项对标

> 每维度结构：**① 现状（实读证据）→ ② 世界一流标准 → ③ 差距 → ④ 改进方向**。

### 维度 1｜信息架构（IA）　★★★☆☆

**① 现状**
- 两级导航、8 个叶子，层级浅、认知负担低 ✅
- 总览 7 张 KPI 卡**全部不可点击**（`Overview.vue:6-40`）——看到"已停用 3 家"无法一键跳到那 3 家 ❌
- 详情页无面包屑，只有 `← 返回租户列表`（`TenantDetail.vue:4`）
- 注册流水/审计页里的**租户名是纯文本**，不可点击跳详情（`Registrations.vue:54`）
- 详情页 **3 张卡纵向堆叠**、无 Tab（`TenantDetail.vue:9-104`），用量增长后会变成超长滚动

**② 世界一流标准**
- **Stripe Dashboard**：每张 metric 卡都可点击下钻到"该条件下的记录列表"；详情页一律 Tab 化（Overview / Payments / Customers / Logs）。
- **Linear**：全局 `⌘K` 可跳转到任意实体的详情；面包屑 + 实体间互链。
- **Notion**：任何提及实体的地方都可点击进入。

**③ 差距**：**"看数"与"查数"断裂**——指标是死胡同；实体间无互链；详情页缺二级导航。

**④ 改进**：KPI 卡可点 → 带条件跳转列表；注册流水/审计的租户名 → 链接；详情页 Tab 化；加面包屑。

---

### 维度 2｜导航设计　★★★☆☆

**① 现状**（实测）
- `@media` **0 处**；侧栏 `220px` **恒定、不可折叠**
- **无 ⌘K 命令面板、无全局搜索、无快捷键**（全站键盘处理仅 `Login.vue:14,18` 两行 Enter）
- **`document.title` 从不更新**（grep 0 命中）→ 浏览器多标签时全是"Hergent 管理后台"
- 侧栏徽标仅 1 处（注册流水条数，`App.vue:31,91-101`），且是**全量拉取后取 length**（`App.vue:94-95`）——数据量上来会浪费一次全量请求
- 激活态设计良好（左侧 3px 高亮 + 底色，`styles.css:124-128`）✅

**② 世界一流标准**
- **Stripe / Linear**：`⌘K` 是**第一入口**——可搜索实体、执行动作、跳转页面。
- **GCP / Vercel**：项目（≈租户）切换器常驻顶栏；侧栏可折叠为图标条。
- 页面标题 ⇄ 路由联动是标配。

**③ 差距**：缺"非鼠标"路径（键盘/搜索/命令），缺侧栏折叠，缺标题联动。

**④ 改进**：先补 `document.title` 联动（5 分钟）；再评估侧栏折叠；⌘K 列为 P2（收益高但需新组件）。

---

### 维度 3｜数据可视化　★★☆☆☆

**① 现状**
- 全站**仅 1 个图表**：套餐分布的横向条形图（`Overview.vue:47-53`，纯 div + 宽度百分比手绘）
- 7 张 KPI 卡**无趋势、无环比、无 sparkline**
- 详情页用量是**裸表格行数**（`TenantDetail.vue:47-65`）
- **无图表库**（依赖里没有 ECharts/Chart.js）

**② 世界一流标准**
- **Stripe**：每张 KPI 卡带 30 天 sparkline + 环比百分比；点击进入时序明细。
- **Vercel / Supabase**：用量页有面积图 + 阈值线 + 预测。
- **Linear**：克制的迷你图 + 数字并置，不喧宾夺主。

**③ 差距**：**零时序视角**——看不到"增长/下滑"，只能看到"当下快照"。对经营决策（哪家在增长、最近注册是不是放缓）几乎无信息量。

**④ 改进**：给 KPI 卡加环比与 sparkline（可继续手绘 SVG **不引新依赖**，与现有风格一致）；注册流水页顶部加"近 30 天注册趋势"迷你图。

### 维度 4｜操作效率　★★★☆☆

**① 现状**
- ✅ 已有：列排序（`SortTh`）、分页（`Pager`，`PAGE_SIZE=20`）、搜索、筛选 pills、字段级校验、确认弹窗
- ❌ 缺失：**批量操作**（无多选列）、**导出**（无 CSV/Excel）、**手动刷新**（仅 `onMounted` 拉一次）、**自动刷新**
- ⚠️ **筛选/排序/分页全在前端本地完成**（`utils/table.js:5` 注释自陈："数据量上千后改为后端"）——当前是**技术债定时炸弹**
- ⚠️ 侧栏徽标为拿一个数字**额外全量拉取注册流水**（`App.vue:94`）
- ⚠️ 详情页加成员要求**手敲精确账号名**，无联想/搜索（`TenantDetail.vue:74`）

**② 世界一流标准**
- **Stripe / GCP**：表格多选 + 批量操作工具条；**导出 CSV** 是标准动作；服务端分页/筛选（URL 可分享）。
- **Linear**：筛选条件即 URL（可分享/收藏），列表支持保存视图。
- **GitHub**：批量操作 + 键盘 `x` 选中。

**③ 差距**：一人运营**高频重复动作无捷径**（无批量、无导出）；且**规模天花板低**（前端全量）。

**④ 改进**：批量选择（P1）→ 导出 CSV（P1，纯前端零后端）→ 服务端分页就绪（P1，需后端配合）→ 成员添加改下拉联想（P2）。

### 维度 5｜交互体验　★★★☆☆

**① 现状**
- ✅ 亮点：`ConfirmDialog` 带**后果说明**（`ConfirmDialog.vue:32-36`）；`EmptyState` 分"无数据/无匹配"两种文案并给行动按钮（`Tenants.vue:53-61`）；字段级校验错误贴输入框（`Tenants.vue:227-229`）
- ❌ **模态可用性缺陷**（`Modal.vue` 全文仅 23 行）：
  - 无 `Esc` 关闭、无**焦点陷阱**、打开**不自动聚焦**、关闭**不还原焦点**
  - 关闭按钮是 `<span>×</span>`（`Modal.vue:7`）——**键盘不可达**
  - 无 `role="dialog"` / `aria-modal`
  - **不锁 body 滚动**（背景可滚）
- ❌ **确认策略不一致**：移除成员/删除邀请码**有**确认；**租户"停用"（影响一个真实客户）却是单击即生效、零确认**（`Tenants.vue:255-263`）——**这是当前最危险的交互**。
- ❌ 无 Undo（删邀请码永久）；无骨架屏（只有"加载中…"文字）；无路由过渡；无 404 页（`router/index.js:22` 直接重定向 `/`）

**② 世界一流标准**
- **Linear**：可逆操作**不打断**（用 Undo toast），不可逆才确认；`Esc` 关闭一切浮层；焦点严格管理。
- **Stripe**：危险操作要求**输入名称二次确认**（如删项目）。
- 骨架屏 > spinner > 文字。

**③ 差距**：**安全性与键盘可达性不足**；确认策略不统一（危险操作反而无确认）。

**④ 改进**：租户停用加确认（P0）；Modal 补 Esc/焦点/滚动锁/语义（P0）；危险操作引入"输入名称确认"（P1）；可逆操作改 Undo（P2）。

### 维度 6｜视觉一致性　★★★☆☆

**① 现状**
- ✅ **令牌体系扎实**：`styles.css:5-45` 定义品牌/侧栏/内容/文本/语义色 + 圆角 + 阴影 + 字体，全站复用
- ⚠️ **22 处内联 `style=`**（实测）——如 `TenantDetail.vue:72` 用 `style="flex:1"` 重造已有的 `.spacer` 类；`style="font-size:14px;color:var(--text-3)"` 在 `Overview`/`TenantDetail` 重复出现
- ⚠️ **13 处硬编码 hex**（实测）：`Overview.vue:101` 渐变 `#06b6d4/#22d3ee`、`AuditLog.vue:226-229` 四种 tag 色、`Registrations.vue:53` / `InviteCodes.vue:22` 的 `code` 芯片 `#f3f4f6`、`styles.css:231` 表头 `#fafbfc`
- ⚠️ **4 套语义重叠的"徽标"**：`.badge`(246) / `.pill-group .pill`(345) / `.tag`(AuditLog) / `.obj-type`(AuditLog) —— 圆角、字号、配色各不相同
- ⚠️ `InviteCodes.vue:26-30` **手写**了与 `StatusBadge.vue` 完全相同的徽标结构，**未复用组件**
- ⚠️ 顶栏 `subtitle` 仅租户详情有、其余为空（`App.vue:84-87`）→ 标题基线跳动
- ⚠️ 登录页用深色渐变、后台用浅色——**同站两种语言**（可接受，但登录页未复用侧栏色 token）

**② 世界一流标准**
- **Linear / Stripe**：**零内联样式**，全部原子类或组件封装；一套 `Badge` 覆盖所有状态语义；字号/间距严格 4/8px 栅格。

**③ 差距**：令牌层好，但**应用层回退到内联/硬编码**，长期易漂移。

**④ 改进**：抽 `.code-chip`、`.metric-unit` 类；tag 色入 token；统一徽标为 `Badge` 组件（variant）；统一 `.spacer` 用法。

### 维度 7｜可访问性（A11y）　★☆☆☆☆ ← **最薄弱**

**① 现状（实测，均为硬证据）**
- 语义 `aria-*` / `role=`：**全站仅 1 处**（`Icon.vue:12` 的 `aria-hidden="true"`）
- 键盘处理：**全站仅 2 行**（登录页 Enter）
- **可点击的 `<span>`**：筛选 pills（`Tenants.vue:5-7`、`Registrations.vue:19-25`、`AuditLog.vue:13-21`）、模态关闭（`Modal.vue:7`）——**键盘完全不可达、无 `role`/`aria-pressed`**
- **排序表头** `<th @click>`（`SortTh.vue:2-9`）——键盘不可达、无 `aria-sort`
- **表单标签未关联**：`<label>` 无 `for`、`<input>` 无 `id`（全站表单）→ 屏幕阅读器无法关联
- **必填仅视觉**：`.req` 是红色 `*` 文本（`styles.css:283`），无 `aria-required`
- **错误无播报**：`.field-error` 无 `role="alert"` / `aria-describedby`
- **对比度不达标**（WCAG 2.1 AA 要求正文 4.5:1）：
  - `--text-3: #98a1ad` 于白底 ≈ **2.6:1** ❌（却用于卡片 label/foot 等正文）
  - `--side-text-dim: #6b7682` 于 `#1f2329` ≈ **3.5:1** ❌（用于侧栏分组标题/页脚）
- **聚焦可见性弱**：`outline:none` 仅改边框色（`styles.css:289,320`），无 `:focus-visible`
- Toast **无 `aria-live`**；表格**无 `scope="col"` / `<caption>`**；**无跳转到主内容链接**

**② 世界一流标准**：Stripe / Linear / GitHub 均达 **WCAG 2.1 AA**：全键盘可操作、语义化标签、`aria-live` 播报、聚焦环清晰、对比度达标。

**③ 差距**：基本**未做**。若未来要卖给**企业客户**（他们常有采购无障碍合规要求）或做**政府/国企**生意，这是硬门槛。

**④ 改进**：见 P0 清单（对比度 2 个 token 改动即达标；pills/表头转 button；Modal 语义化；表单 `for/id` + `role="alert"`）。

### 维度 8｜响应式适配　☆☆☆☆☆ ← **几乎为零**

**① 现状（实测）**
- `@media` **0 处**
- 侧栏 `220px` **恒显**，`.layout { height:100vh; overflow:hidden }`（`styles.css:66-80`）
- 唯一的响应式原语：`grid-template-columns: repeat(auto-fill, minmax(200px,1fr))`（统计卡/用量卡，`styles.css:203`）
- 表格靠 `.table-wrap { overflow-x:auto }` 横向滚动兜底（`styles.css:222`）
- 模态 `max-width:92vw`（可接受）
- `.toolbar` 有 `flex-wrap:wrap`（部分自适应）；但 `.search` 固定 `240px`（`styles.css:317`）
- 顶栏标题 + 副标题 + 用户块在窄屏**会挤压/溢出**
- **无触摸目标尺寸考量**、无 `prefers-reduced-motion`、无 `prefers-color-scheme`

**② 世界一流标准**
- **GCP / Vercel**：三档断点（桌面全侧栏 / 平板图标条 / 手机抽屉）；表格小屏转卡片或保留 sticky 首列；顶栏收纳为汉堡菜单。
- 触摸目标 ≥ 44×44px。

**③ 差距**：**手机上完全不可用**。对一个"老板常在手机上看"的产品，这是**可感知的产品缺陷**。

**④ 改进**：至少 3 档断点（≥1024 / 768–1024 / <768）；`<768` 侧栏改抽屉 + 顶栏汉堡；表格保留横向滚动 + 首列 sticky；模态小屏全屏化。

## 四、约束与"不做什么"（重要）

结合**团队规模（1 人 + AI）**与**业务阶段（SaaS 早期，1 家真实租户）**，以下**明确不建议**：

1. ❌ **不引入重型 UI 组件库**（Element Plus / Ant Design）——8 个页面属"小而精"，引入会带来**长期升级/样式定制负担**，反而背离当前"零依赖"优势。**继续自研 + 令牌化**是正确路线。
2. ❌ **不做完整 i18n**——当前单语中文，无海外需求。
3. ❌ **不做 Storybook / 完整单测 / TS 迁移**——对一人团队的 ROI 为负，等有第 2 位开发者再说。
4. ⚠️ **⌘K / 全局搜索放 P2**——收益高但**依赖后端搜索接口**与实体规模；现在 8 个页面、1 家租户，收益不抵成本。
5. ✅ **优先做"防错"而非"炫技"**——P0 全部围绕**防误操作 + 可用性地基**，这在一人运营、误操作无人兜底的前提下价值最高。

## 五、建议执行顺序（路线图）

```
第 1 步（当天）P0-1 ~ P0-7   ── 防误操作 + 可用性地基 + 视觉收敛   [不动后端]
第 2 步（本轮）P1-3/4/6/8/9  ── 低成本高效率项（导出/刷新/互链/Badge/二次确认）
第 3 步（本轮）P1-1          ── 响应式三档（移动端可用）
第 4 步（下一轮）P1-2/5/7/10 ── 需后端配合（下钻/服务端分页/批量/Tab）
第 5 步（规模化后）P2-*      ── 命令面板/全局搜索/可视化/暗色
```

**验收方法**（每项交付时执行）：
1. `npm run build` 构建通过（当前基线：单 bundle，`chunkSizeWarningLimit:1200`）
2. 三层 md5 一致性（本地 mac / 生产 FS / 公网 HTTPS）
3. 回归清单：登录 → 8 页面逐一打开 → 每个写操作走一遍 → 键盘 Tab 走一遍（P0 后应全程可达）
4. 对比度：用 Lighthouse / axe DevTools 复核（P0-4 后应 ≥ AA）
