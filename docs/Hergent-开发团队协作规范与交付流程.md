## 三、协作节奏与指令协议

**结论**：老板用极简祈使短指令驱动（"部署""做 M1""全做""推""要"）。AI 必须**先侦察 / 可行性评估，再端到端执行**（改代码→构建→部署→真机验证），且**部署必须 grep / 探针 / 双侧 md5 核实，禁止静默失效**。

### 3.1 标准五段节奏

1. **极简指令**：老板给方向（如"做 M1"）。
2. **侦察评估**：AI 先查现状、可行性、影响面、撞号风险（见第四章），不急着动手。
3. **方案对比**：给老板**先推荐、后理由**——"建议做 A，因为…；备选 B 的代价是…"。⚠️ 不要只丢一个方案。
4. **短词确认**：老板用 `要 / 做 / N`、`A+C`（采纳+补充）这类短词拍板。**"全做"= 先侦察，再批量端到端**，不是边想边改。
5. **端到端执行 → 交付摘要**：改完必须跑构建+部署+真机验证，最后给固定五段摘要（见第十章）。

### 3.2 "全做"模式铁律

🔴 **"全做"不是"全部一股脑改"**：先侦察全局，把改动按"可独立上线"拆批，逐批端到端（改→构建→部署→验证→摘要），**每批都能回滚**。否则一个半成品进构建目录，会被并发会话连带着推上线（见 §6.5）。

### 3.3 给老板的"为什么"

> 为什么 AI 不能直接上手改？因为这条流水线里**绝大多数事故是"改完看着没问题、其实根本没生效"**（静默失效）。先侦察再端到端，是为了每一步都有"证据"证明真的成了，而不是凭感觉。

## 四、版本号与变更追踪规范

**结论**：版本号是**全局共享序列 `vNNN`**，当前已到 **v499**，下一号 **v500**。起号前**必须实搜三处**，绝不用 `grep "A\|B"`（静默失效），撞号按"后到改号 + 行号白名单逐个替换"处置。

### 4.1 起号前必搜三处（缺一处就会撞车）

🔴 跑三条搜索，且**必须用 `-e` 多条件**，禁用 `grep "v204\|v205"`：

```bash
grep -rn  -e "v500" -e "V500"  .workbuddy/memory/ .workbuddy/tools/   # ① 记忆与工具
grep -rn  "_safe_migrate('v500_"  .                          # ② 迁移名（最硬证据）
grep -n   "v500"  .workbuddy/tools/scoped_stage_by_marker.py # ③ 已注册 spec 名
```

### 4.2 禁用 `grep "A\|B"`

🔴 **zsh 下 `grep "A\|B"` 会静默返回空**，而空结果恰好看起来像"这个号没人用"——曾一天连撞三次。一律用 `grep -e A -e B`。

**大白话**：这条命令"查不到"不是真没查到，是命令自己坏了还一声不吭，会让你误以为某个号空闲。

### 4.3 "号码出现 ≠ 号码被占用"——判据顺序

🔴 搜到某号≠它已被用。必须读那一行，看它是"已实现"还是"仅评估"：

1. 有没有 `_safe_migrate('vNNN_…')` / 源码引用（**最硬**，说明已在代码里生效）；
2. 有没有已在途的 `git diff` 代码改动；
3. 只是报告 / 记忆里的"预案"。

①② 都空 ⇒ 该号实际未被占用，**先落代码者得**。`_safe_migrate` 可能属于**还没提交的并行会话**，所以**只看记忆文件必漏**。

### 4.4 撞号处置（实测成本：注释 9 处 + 工具改名 4 个 + 一次重建重部署）

🔴 顺序：

1. **先判谁上线在先**（`git log` + 是否已上生产）→ **后到的改号**；
2. 改号按**行号白名单逐个替换**，并断言"文件内旧编号计数 == 原计数 − 我改的处数"；⛔ **绝不用 `replace_all`**（同一文件常混着别人的同号注释，批量替换会连别人一起改坏）；
3. 生产备份名若含旧号，一并 `mv` 成新号，避免回滚路径指向"属于别人的号"。

### 4.5 并行会话同改一行的取舍

🔴 若我的改动与别人在途改动落在**同一行**（典型："下次从 N 起编"这种双方都想更新的提示行），**放弃本轮回改**，改由当日日志 / 域名主题文件传达，并在交付报告列为"未处理待接手"——硬拆同一行没法只提交一半，整块认领=夹带别人的在途改动。

## 五、编码与提交规范

**结论**：改代码要"一次一处 + 改完立刻 grep 复核"；提交要"范围化 + 不带 pathspec"；**任何地方都不许静默失效**；同一规则只留一份实现，回落写法必须显式标记。

### 5.1 one-Edit-at-a-time + grep 复核

🔴 同一消息里多个 Edit 可能被**静默丢弃**部分。每改一处，立刻 `grep` 复核落点与计数，确认真的写进去了再改下处。

### 5.2 scoped 提交：`git commit -F` 不带 pathspec

🔴 长期脏工作区里只提交本轮：`git commit -F <msg>`。⛔ **绝不带 pathspec**（如 `git commit src/ x.py`）——它会让索引被工作区覆盖，筛好的 hunk 全失效。

### 5.3 不静默失效

🔴 **禁止 `except: pass`、禁止空 `try` 吞错**。缺数据时必须**显式回退 + 回报行数**，绝不能静默归零。⚠️ "跑一句 SQL 看看通不通"的自证不成立——幽灵句柄照样返回成功（见 §6.6）。

### 5.4 同一规则只留单一常量 / 函数

🔴 **同一规则 / 集合的第二份拷贝 = 静默漂移温床**，立刻收敛成单一常量或单一函数。⚠️ 漂移常藏在"回落写法"里：`MAP[x] || x` / `ROLE_TEXT[r] || r` 这类兜底会把**缺配置显示得跟正常值一模一样**，肉眼永远发现不了 ⇒ 回落必须**显式标记**（如 `未知角色( xxx )`），不是原值。

🔴🔴 **给 accessor 写兜底时，兜底分支绝不能回落到 accessor 自己**：曾出现 `function unitCount(){ return Array.isArray(cross.value.units) ? unitCount() : 0 }`——想防"读 undefined.length"，结果变成**自递归无出口**，整页 `RangeError` 崩溃，且症状与"要防的那个"长得一模一样，越改越崩。

### 5.5 注释口径 ≠ 代码口径，必须看 SELECT

🔴 读价格 / 口径类代码**必须直接看 `SELECT` 列表**，不能信注释。新增列参与必填判定时，缺数据必须**显式回退 + 回报行数**，绝不静默归零。

### 5.6 查含方括号 / 特殊字符的代码一律 `grep -F`

🔴 `grep "store_map.setdefault(s[\"employee_id\"]…)"` 返回 0 是**假阴性**（`[...]` 被当字符类）。凡含 `[` `]` `|` 的，用 `grep -F`。

### 5.7 生产只读探针必须带 service 环境

🔴 裸跑 `python3 xxx.py` 缺 `ERP_SECRET` ⇒ 函数抛错 ⇒ 外层 `try` 吞掉 ⇒ 返回值缺字段，看着像"代码没生效"。姿势：`set -a && . /opt/hergent-erp/.env && set +a && python3 …`。裸调业务函数还需 `set_tenant_context(N)`（见 §7.3）——**两件事都要做**。

## 六、部署规范（生产铁律）

> ⚠️ **生产落点三件套（部署前必 `ls`/`systemctl cat` 实核）**：① 后端 API = `/opt/hergent-erp/`（FLAT，服务 `hergent-erp.service`）；② 前端主站（hergent-cn-v2 / AI 副驾）= `/opt/hergent-cn-v2`；③ 前端管理后台（`/admin/` 别名，hergent-admin）= `/opt/hergent-admin`。三者**别混**；`hergent-server.service` 是另一回事（见 §6.2，遗留 Credits Server，别误重启）。

**结论**：后端 `/opt/hergent-erp` 是**扁平布局**（无 `server/` 前缀）；前端有两个独立根——主站 `/opt/hergent-cn-v2` 与管理后台 `/opt/hergent-admin`（`/admin/` 别名），**三者别混**。重启服务名写错会拉起一年前的遗留服务。rsync 只同步本轮 `dist-vNNN/` 产物、绝不 `--delete`。判定上线成功 = 三方 md5 + 当轮真机探针，且"线上跑的是不是本轮构建"要看 `index.html` 入口 + 其 CSS 是否含本轮新增类名。

### 6.1 生产落点三件套，别混

| 面 | 生产目录 | 布局 | 服务名 |
|---|---|---|---|
| 后端 API | `/opt/hergent-erp/` | **FLAT**（直接是 `routers/ db/ …`，无 `server/` 子层） | `hergent-erp.service`（cwd `/opt/hergent-erp`） |
| 前端主站（hergent-cn-v2 / AI 副驾） | `/opt/hergent-cn-v2/` | 构建产物 `dist/`，无 `package.json` | nginx 静态，免 restart |
| 前端管理后台（`/admin/` 别名，hergent-admin） | `/opt/hergent-admin/` | 构建产物 `dist/` | nginx 静态，免 restart |

🔴 **曾把主站推到管理后台根（或反之）= 错目标 rsync 覆盖**。各前端目录有回滚脚本，如 `bash /opt/hergent-admin/scripts/release.sh rollback <tag>`（主站 `hergent-cn-v2` 同理，部署前 `ls` 实核脚本路径）。生产 `assets/` 是**历次构建并集**，任何 `--delete` 都会误删历史产物。

### 6.2 🔴🔴 服务名铁律：重启 `hergent-erp.service`，不是 `hergent-server.service`

- ✅ **`hergent-erp.service`**：当前后端，cwd `/opt/hergent-erp`，`ExecStart=/usr/bin/python3 server.py`。
- ⛔ **`hergent-server.service`**：**遗留 Credits Server**，cwd `/opt/hergent/server`，原本是停的。

🔴 **重启错了 = 既加载不到新代码，还会拉起一年前的遗留服务**，新代码根本没生效、且零报错。

**判据（怎么确认重启对了）**：
```bash
ss -ltnp | grep 8700          # 取 pid
readlink /proc/<pid>/cwd      # 必须是 /opt/hergent-erp
systemctl show hergent-erp.service -p ActiveEnterTimestamp   # 确认启动时刻晚于文件 mtime
```

**大白话**：这两个服务名只差一个词，但一个是现在的系统、一个是去年废弃的老系统。重启成老名字，你改的代码一行都没跑，界面还一切"正常"，你永远不知道错了。

### 6.3 rsync / 部署命令铁律

🔴 **后端**：用 `scp` 具名单文件到完整路径（如 `scp routers/forecast.py root@h:/opt/hergent-erp/routers/forecast.py`），部署后 `grep -c <新符号> /opt/hergent-erp/routers/forecast.py` 验证落点，**别信 rsync 的 OK**。⛔ 禁用整目录 rsync `--delete`（会删 Hermes 运行时 `hermes-engine/`）。

🔴 **前端**：`rsync` 必用**绝对路径**且**只同步 `dist-vNNN/`（或本轮隔离 outDir 产物）**，**绝不拷本地仓库根**（仓库根 `index.html` 是营销页），**绝不 `--delete`**。

🔴 标准前端流程（顺序不可换）：
```bash
# ① 部署前先给线上留档（否则部署后没得回退）
ssh root@h 'bash /opt/<前端根>/scripts/release.sh snapshot'   # 主站=/opt/hergent-cn-v2，后台=/opt/hergent-admin
# ② 同步，绝不加 --delete
rsync -av /tmp/vNNN-build/ root@h:/opt/hergent-cn-v2/   # 主站根；管理后台改推 /opt/hergent-admin/，勿混
# ③ 记新版本 + 控制体积
ssh root@h 'bash /opt/<前端根>/scripts/release.sh snapshot && bash /opt/<前端根>/scripts/release.sh prune 5'
```

### 6.4 🔴 部署判据：三方 md5 + 当轮真机探针

🔴 **判定上线成功不能只看"rsync 退出码 0"**。必须：
1. 后端具名文件 `md5` vs 生产 **双侧全等**；
2. 前端产物 `md5` vs 生产（经公网拉取比对，本机 HTTP 代理会缓存 `index.html`）；
3. **生产真机探针当轮复核**（见第八章）——且探针结论**有过期保质期**，部署后必须重跑。

⚠️ "双侧 md5 一致"只证明**传输没坏**，不证明**进程已加载新代码**。必须 `systemctl restart` 后探活 + 进程内实测常量。

### 6.5 🔴🔴 "线上跑的是谁的构建" = index.html 入口 + 其 CSS 新增类名

🔴 只看 chunk 文件名会**误判**：旧 chunk 仍在 `assets/` 并集里。正确判据 = **`index.html` 的 entry + 该 entry 的 CSS 里是否含本轮新增类名**（如本轮新加的 `.psi-tabn`）。判别串必须"**同有同无**"：单一正向命中**没有判别力**，必须正反例一组一起看（正反例同结果 = 探针作废）。

🔴 **并行会话活跃时前端必须隔离构建**：`vite build --outDir /tmp/vNNN-build --emptyOutDir`。共享 `dist/` 是别人也可能写的目录，"我的构建成果被别人替换"是真实竞态；隔离构建还会把别人**未提交**的半成品带上生产（曾把已验收改动连根抹掉）。

### 6.6 🔴🔴 换 / 删库文件后必须重启进程（幽灵 inode）

🔴 服务运行中 `os.remove` 掉 `tenant_<id>.db` 再重建同名文件 ⇒ 进程缓存的 Connection **仍指向已删旧 inode**：写入落进幽灵文件、读取返回旧数据、**全程零报错**。`conn.execute("SELECT 1")` 对幽灵句柄照样成功 ⇒ 任何"跑一句 SQL 看看通不通"的自证都不成立。**顺序：先删文件 → 再 restart。**

### 6.7 回滚

🔴 回退：`release.sh list` 找目标 → `release.sh rollback <js-hash>` → 用**公网** `index.html` 核对引用是否**成对**变化（禁用 `grep "A\|B"`，用 python 解析）。

## 七、多租户与数据安全红线

**结论**：真实租户（tenant_1 / tenant_10）**只读**；自动化只准写隔离租户（9997+）；隔离沙箱会改数据导致期次失真；脱敏红线与禁数据转售是硬约束。

### 7.1 真实租户只读，写须显式授权

🔴 真实租户数据异动时：**先归因，再认错**。要写须**用户显式授权 + 先在线备份（`sqlite3` backup API）+ 改完逐项断言**。E2E 带 `POST/PUT/DELETE` 必须先断言租户 id 不在 `(1, 10)`；回收用**真租户逐字对照**（`ZERO_RESIDUE_OK`）证明零污染。

### 7.2 自动化只准写隔离租户

🔴 我的自动化只准写隔离租户（**9997+**）；真实租户（tenant_1 / tenant_10）**只读**。

### 7.3 隔离沙箱失真 → 去真实库只读手算

🔴 隔离沙箱克隆后会把**全部** `forecast_submissions.order_date` 改成今天 ⇒ 任何按期次 / 日期窗口过滤的行为**全部失真**（窗口只要含今天就命中全部报单）。

**判据**：沙箱**能**验证 行取值 / 单元格渲染 / 列统计 / 筛选 / 复制 / 金额 / 布局 / 交互（与日期无关）；**不能**验证 期次归属 / 跨期不重复计入 / 时间窗口筛选 / 达成月归属 / 任何依赖 `order_date` 的口径 → 一律去**真实库只读手算**。

### 7.4 脱敏红线（⛔ 硬约束）

🔴 以下**严禁出系统 / 进日志 / 被未授权方看到**：返利率、进货价、客户名、区域销量、厂家政策。仓内含生产凭据明文 ⇒ 远端仓库须 private；PII 不落 `outputs/`。⛔ **禁止数据转售**。

### 7.5 归因三证据（别去"修"没坏的东西）

🔴 判"某未提交改动是否早已上线"用 nginx access.log 的 `hash + 字节数` 序列。但 `body_bytes_sent` 是 **gzip 压缩后值**，只能同型对比大小，**绝不能当原始字节反推 JSON 内容**（曾按原始字节反推，最高场景全部对不上，白跑两轮）。

## 八、质量关与验证规范

**结论**：验证必须上生产真机跑探针；探针有固定陷阱（字符串求值、空对照、多目标同结果）；断言必须**双向**；"代码里没调用点 ≠ 没人用"，结论必须去生产数一遍。

### 8.1 真机探针三陷阱

🔴 **`page.evaluate` 传字符串参数会被当表达式求值**——要传数据就用函数体 + 参数，别塞字符串。
🔴 **对照断言必须选"原本非空"的格**：拿一格本来空的当对照，"清空后仍为空"恒真 = **空断言假 PASS**。
🔴 **多个不同目标返回同一结果 = 没打到目标**（先怀疑测试本身）。

### 8.2 双向断言

🔴 **单向断言在"本来就对"时也会通过** ⇒ 每条断言都要带 HEAD 反证（"改之前它该是 X、改之后该是 Y"）。验证脚本的"变更集封印"会随轮次演进——上一轮的"登记 N 条白名单"在本轮（已进 HEAD）必然报 missing，那是封印在提示"HEAD 推进了、登记集合该重写"，**不是代码出错**，正确做法是把白名单**收紧**成"零差异"。

### 8.3 🔴 "代码里没有调用点 ≠ 这个功能没人用"

🔴 逐行读码后判定某表"长期为空（写入路径不可达）"，**生产实测 72 行、状态全 success**——真实写入路径走 Hermes 侧，不在被扫的函数里。

> **凡"某表是空的 / 某功能没人用 / 某能力没上线"这类结论，必须去生产数一遍，再写进任何材料或结论。** 代码静态分析只能证明"我读到的地方没有"，不能证明"不存在"。

⭐ **同一铁律的两个方向**：**读到的数字要落地看行内容；没读到的数字要回头数。**

### 8.4 判端点 / 路由是否生效，不信 HTTP 状态码

🔴 `rbac_middleware` 在路由匹配**之前**跑且用**静态前缀表** ⇒ 删了的路由仍可能因前缀匹配返回 403/404，**HTTP 状态码不可用**。正确判据两条腿：① 生产 `grep` 端点定义 + 查表 / 索引；② 进程内实测该接口。

### 8.5 判"某能力属于哪条业务线"要读它干了什么

🔴 名字像装饰的可能是最高频，名字像运维的可能是最核心（"天气面板"是全站调用量第一；"定时任务"= 主动推送引擎，正是副驾核心）。**别靠名字猜归属。**

## 九、记忆与知识沉淀规范

**结论**：记忆分三层；daily log 只追加不覆盖；`MEMORY.md` 只留路由索引（≤4.3k 字），细节下沉 `topics/`；改某文件前先读它；topic 章节 > 日表格行；新事实出现主动更新前轮结论。

### 9.1 working memory 三层

| 层 | 位置 | 用途 |
|---|---|---|
| 云记忆 | 远端（团队共享） | 跨机可召回的索引与结论 |
| 用户级记忆 | `~/.workbuddy/memory/` | 个人偏好、长期事实 |
| 工作区级记忆 | `<repo>/.workbuddy/memory/` | 本项目路由索引 + 按日期 daily log + `topics/` 分域细则 |

### 9.2 daily log append-only

🔴 每日日志 `YYYY-MM-DD.md` **只追加、不覆盖**。改长文档前先 `wc -l` 与 HEAD 核数——**工作区文件会被静默回退**。

### 9.3 MEMORY.md 只留索引

🔴 `MEMORY.md` 目标 ≤4.3k 字，只放**路由 + 召回锚(§) + 硬判据**；细节一律下沉 `topics/`。再涨就先下沉，别在本文件堆流水。

### 9.4 引用事实前先看权威源

🔴 引用"状态类"事实（备案 / 上线 / 提审 / 版本号）前，先看 topic 章节有没有更新的结论。⚠️ 曾按一条**日表格行**写"备案未获批"，而同记忆树的 topic 章节与目标文件自身都写着"备案已通过"——那条表格行是当天早些时候的快照、已被推翻。

> **两条铁律**：① **topic 章节 > 日表格行**；② **改某份文件前先读一遍它**（新增段落可能与该文件第 7 行自相矛盾，读一眼就能发现）。

### 9.5 新事实主动更新前轮结论

🔴 同一条判据被老板提两次 = 上次没被固化 ⇒ 修完必须把判据写进记忆，别只改字。新踩坑结论出现，**主动更新前轮记录**，保持记忆是单一可信源。

## 十、交付物规范

**结论**：每次交付固定**五段摘要** + 文件清单 + 已知风险；给老板看的 UI 文案数字须带中文单位（禁用 pp/avg/Δ 等英文缩写）；不自然的 UX 主动重设计而非辩护。

### 10.1 固定五段交付摘要

每次交付，给老板的摘要必须含：

1. **交付**：本轮做了什么（人话，不堆术语）。
2. **变更**：动了哪些文件 / 哪个版本号（vNNN）。
3. **构建**：构建产物、部署落点、双侧 md5 / 探针结果。
4. **对齐效果**：真机验证"改前 vs 改后"的对比结论（带双向断言）。
5. **需确认事项**：哪些要老板拍板、哪些有已知风险、哪些待接手。

### 10.2 给老板的文案数字口径

🔴 UI 文案 / 摘要里的数字**必须带中文单位**：`件 / 箱 / 元 / 公斤 / 天`，禁用 `pp / avg / Δ / %`（`%` `¥` `kg` 有共识可用）。

**大白话**：老板看不懂 `环比 Δ+3.2pp` 这种缩写，要写"比上个月多了 3.2 个百分点"或"多了 3.2%"。

### 10.3 不自然 UX 主动重设计

🔴 遇到"按钮点了没反应""说明像在自证""一个开关拆两处放"这类不自然交互，**主动重设计而非辩护**。判据：
- 界面不许出现"可由操作或记录自证"的多余说明（三条同时成立才删：① 控件已表意 ② 点一下自证 ③ 不承载口径/格式/规则/风险）。
- "模式开关"进入点/退出点必须同处一容器；"跨视图入口"不得下移到视图专属容器。
- 一个 ref 不得同时承担"用户在看哪条"与"数据落到哪条"。

### 10.4 文件清单 + 已知风险

🔴 交付物须附**文件清单**（改了哪些、落在生产哪个路径、md5 是否双侧全等）与**已知风险**（哪些没覆盖、哪些待老板确认、哪些可能影响其他模块）。
