## 一、焦点样式：为什么最后用了「双伪类」

### 1.1 起点

v716 实测（销售单 Tab 遍历 14 个元素）：outline 被抑制 0 个（好事），但自定义焦点环也是 0 个 —— 焦点全靠浏览器 `outline:auto`：

```
button.wx-now    outline=auto 3px rgb(8,145,178)   ← 品牌青
button.tb-btn    outline=auto 1px rgb(0,95,204)    ← 浏览器默认蓝
a.sb-item        outline=auto 2px rgb(98,108,125)  ← 灰
button.sb-item   outline=auto 3px rgb(110,110,115) ← 另一种灰
```

`outline:auto` 会按背景反推对比色，设计师控制不了，也无法在品牌底色上保证可见。

### 1.2 定值依据

```css
:where(button,a,input,select,textarea,summary,[tabindex]):focus-visible:focus-visible{
  outline:2px solid var(--p-dark);
  outline-offset:2px;
}
```

| 决策 | 依据 |
|---|---|
| 2px | 全站最粗处的观感上限，再粗喧宾夺主 |
| `outline-offset:2px` | 工具栏 `.tb-btn` 之间 gap 只有 6px，0 offset 时相邻焦点圈会重叠 |
| `--p-dark` 不用 `--p` | 亮青 `#06b6d4` 白底 2.43:1，焦点属 UI 组件需 3:1；`--p-dark` 是 5.36 且深色已适配 |
| 不写 `border-radius:inherit` | outline 本就跟随元素圆角，再写会拉平胶囊按钮（`.tb-copilot`）的圆角 |
| 只对 `:focus-visible` | 鼠标点按钮也出圈是老板最反感的那种「多一层框」 |

### 1.3 🔴 双伪类的由来（两次返工的教训）

**第一版**用 `:where(...)` 把特异性降到 **0**（实际是 (0,1,0)），本意是"让组件自己写的焦点样式能覆盖"。这个想法是错的：

- `.input{… outline:none …}` 是**基类**，特异性同为 (0,1,0)，而后加载者胜
  ⇒ **315 个 `.input` 的焦点环当场被吃掉**，键盘聚焦时 `outline-style: none`，零指示。
- 同类还有 `.cp-input`（副驾输入区）、`.cmd-input`（命令面板）、`.cp-search-input`
  —— 都是无边框输入，删掉 outline 就什么都没有。

**第二版**叠一个 `:focus-visible` 把特异性抬到 (0,2,0)：

```css
:where(...):focus-visible:focus-visible   /* 匹配集合不变，只是权重变高 */
```

同一伪类重复两次**不改命中集合**，只提高权重，能压过任何「单类 + 单伪类」的抑制规则。
组件若确有更合适的焦点表达，可以写 ≥(0,2,0) 的规则覆盖回来，但**必须给出可见的替代指示**。

同时：
- 删掉 `.input` 基类的 `outline:none`
- 清掉 9 处局部 `:focus{outline:none}`（CopilotDrawer 2、ReportMapping 1、PriceChannels 2、Forecast 2、LossAccounting 2）
- 这些位置原来用的 `border-color:var(--p)`（亮青 2.43:1，不够 3:1）一并改 `--p-dark`
- 删掉 `.fld:focus` / `.input:focus` 的 `box-shadow:0 0 0 3px var(--p-bg)` ——
  `--p-bg` 是 `rgba(6,182,212,.06)`，6% 在白底上肉眼看不见，等于没有

唯一保留 `outline:none` 的是 `.cross-tbl.edit-tbl:focus`（预报交叉表编辑容器）：
选中单元格自己有 `.cell-active` 的 2px outline，容器再加一圈反而噪。

### 1.4 探针本身也修了

复测时两次误判，都是探针的问题，不是产品的问题：

| 现象 | 真相 | 修法 |
|---|---|---|
| 侧栏项报 `solid 3px rgb(106,106,112)` | 侧栏有 `transition:all`，outline 被一起做动画。立刻采样拿到的是「UA 默认 3px + currentColor」→「2px 品牌青」的**中间态** | Tab 后等 260ms 再读 |
| 统计仍报「自定义焦点环 0 个」 | 旧判据只认 `box-shadow` 环（v717 之前焦点全是 `outline:auto`）。新实现是 outline ⇒ 新实现也被判成"没有" | 判据改成 outline 三要素：`solid 2px` + `rgb(14,116,144)` + `offset ≥ 1px` |

改后生产实测：

```
outline 被完全抑制（零指示，不可接受）   0
符合规范（solid 2px rgb(14,116,144) + offset≥1px） 14
有指示但不合规（宽度/颜色/offset 不统一）    0
阳性对照 8/8 ✅（注入 *{outline:none!important} 后全部识别为无指示）
```

## 二、设计令牌

### 2.1 过渡时长

新增 `--dur-fast:120ms` / `--dur-base:150ms` / `--dur-slow:200ms`。

| 原值 | 处数 | 归到 |
|---|---|---|
| `.15s` | 119 | `--dur-base` |
| `.2s` | 31 | `--dur-slow` |
| `.18s` | 21 | `--dur-base` |
| `.12s` | 13 | `--dur-fast` |
| `.16s` | 8 | `--dur-base` |
| `.25s` | 6 | `--dur-slow` |

合计 **198 处**。只剩 8 处（`.3s/.35s/.4s/.5s`）是进度条/长动画的刻意值。

顺带补了全局动效降级（原报告列为 P2 §八，但它与时长收口是同一件事）：

```css
@media (prefers-reduced-motion: reduce){
  *,*::before,*::after{
    transition-duration:.01ms !important;
    transition-delay:0s !important;
    animation-duration:.01ms !important;
    animation-iteration-count:1 !important;
    scroll-behavior:auto !important;
  }
}
```

用 `.01ms` 而不是 `0s`：有些组件靠 `transitionend` 推进状态，`0s` 时事件可能不触发。

### 2.2 控件高度：**没按评审说的收到 3 档**

评审建议 `--h-sm:28 / --h-md:32 / --h-lg:36` 三档。实测后判断这个数字不对：

- 评审说的「40 种高度」把装饰性高度也算进去了（图标 14px、圆点 8px、分隔线 1px）。
  **真正的交互控件只有 13 档 / 135 处**。
- 三档会把两件**刻意**的东西压平：
  - 建单页行内控件 **22px** —— 由 `tests/psi-order-form-density.contract.mjs` 锁死。
    我一开始把 22 当"越界值"统一改 24，契约当场挂 **4 条断言**，已回退。
  - 顶栏 `.tb-btn` / `.tb-copilot` / `.wx-now` 的 **34px** —— 顶栏高 `--topbar-h:48px`
    是按 (47−34)/2 = 6.5px 呼吸位定的，并跑 `tests/shell-topbar-h.contract.mjs`。

最终定为 **6 档语义档位**，并把真正的问题（输入类 7 档）收掉：

| 档 | 值 | 用途 |
|---|---|---|
| `--h-xs` | 22px | 建单页**行内控件**（契约锁死） |
| `--h-compact` | 24px | 紧凑档表格内控件（`data-density="compact"`） |
| `--h-sm` | 28px | 分页按钮 `.psi-pg` / 行内小图标按钮 |
| `--h-md` | 32px | 工具栏筛选与开关（`.fld` / `.btn-sm` / `.tb-toggle`） |
| `--h-lg` | 36px | 主按钮 `.btn` |
| `--h-xl` | 40px | 大表单输入 `.input`（315 处，表单页主档） |

输入类收敛明细：30→32 **17 处**、34→32 **3 处**、38→40 **1 处**（共 21 处）。
7 档 → 6 档。

### 2.3 CI 护栏（`scripts/check-tokens.mjs`）

挂在 `prebuild`，`npm run build` 前必跑。判据不是"看见 `#` 就报错"（那样没人会用它），而是**按文件的允许色值集合**：

| 情况 | 结果 |
|---|---|
| 文件不在 baseline、出现任何 hex 颜色 | ❌ 报错（新文件必须走令牌） |
| 文件在 baseline、用了集合外的**新**色值 | ❌ 报错（不许发明新颜色） |
| 用了集合内的旧色值 | ✅ 放行（存量，分批清） |
| `#fff/#ffffff/#000` 及其带 alpha 写法 | ✅ 永远放行（结构性白/黑，不值得令牌化） |

存量：**45 个文件 / 166 条**走 baseline。

```bash
npm run tokens:check    # 检查
npm run tokens:list     # 按文件列出待清量，便于分批
npm run tokens:update   # 清完存量后重写 baseline
```

**已过阳性对照**：注入 `#123456` 后 `exit 1` 并打印改法；还原后 `exit 0`。

## 三、状态标签：根因不是"缺组件"，是"三套并行"

### 3.1 实测拓清

| 实现 | 造型 | 用量 |
|---|---|---|
| 全局 `.badge` / `.badge-green|red|amber|blue` | 胶囊（radius 10 / 高 20） | 6 处 |
| 全局 `.tag` / `.tag.ok|warn|bad|info` | 圆角矩形（radius 6 / 高 22） | 64 处 |
| 页面级重定义 | 各写各的 | 7 个页面 / 15 条规则 |

后果：「已签收」在销售单是一个绿，在本期预报是另一个绿（`--suc #0F7B3F` vs `--ok-green #0F6E56`）。

更糟的是**未定义的类名**：

```
class="tag danger"  → 全站无 .tag.danger   （只有 ReportMapping 自己定义）
class="tag suc"     → 全站无 .tag.suc
class="tag purple"  → 全站无 .tag.purple
risk / hot          → 同
```

`risk` 由多个页面的 `statusOf(r).cls` 这类辅助函数动态返回（Rebate / Forecast / ImportMapping / Workbuddy / FundsReconcile / OutboundList…），换个页面用同名类就**静默退回灰底** —— 看起来"是标签但没颜色"。

### 3.2 收口动作

1. 全局 `.tag` 变体补齐：`ok / suc / warn / bad / danger / risk / info / purple / teal / hot / off / neutral`
2. 全部前景色改走 `--st-*-txt`（v717 建，浅/深各一套，均过 AA）
3. 新增 `--st-teal-txt`：原 `--teal #1d9e75` 当文字只有 **3.39:1**，本底 4.69
4. 删掉 7 处页面重定义（ReportMapping 5、BrandArchive 2、WarehouseArchive 1、
   RoleManage 1、Rebate 2、Forecast 3、RebateSprint 1），统一继承全局
5. `off` 与 `neutral` 分开：
   - `off` = 停用/已关闭 → 灰底 + 红字（灰底说明"不是当前状态"，红字说明"被关掉了"）
   - `neutral` = 无状态 → 纯灰
   两者不能混用，否则「停用」会被误读成「没设置」

### 3.3 `StatusBadge` 泛化

原来：只支持 `active` 布尔、走 `.badge` 胶囊、**使用 0 处**。
现在：`tone` + `label`，走 `.tag`；`active` 保留为兼容写法。

```vue
<StatusBadge tone="ok" label="已签收" />
<StatusBadge :active="p.is_active" />          <!-- 等价 启用/停用 -->
```

已接入：商品档案（原 `.pa-status` 2 处 + 3 条死 CSS 已删）、员工档案（原 `.df-acc` 2 处 + 2 条死 CSS 已删）。

> 🔴 组件**不重写** padding/圆角/字号 —— 造型就是 `.tag`。在这里另写一套就又多出第三套。

## 四、空态

| 问题 | 实测 |
|---|---|
| 全局 `.state-empty` 定义了两次 | variables.css「空/错态」段与「空态」段各一份，值完全相同 |
| 5 个页面各改一版 | ProductArchive 22px、BrandArchive 22px、LossAccounting 22px/12px、AiHub 14px、AiOps 14px |
| 结果 | 同一个「暂无数据」在商品档案占 22px、在客户档案占 **48px** |

改法：去重 + 收成两档，删 4 处页面重定义，AiHub/AiOps 的 9 处改用 `.state-empty.sm`。

```css
.state-empty,.state-error{padding:48px 20px;text-align:center;color:var(--t3);font-size:13px}
.state-empty.sm,.state-error.sm{padding:12px 4px;font-size:12px}
```

**没做的**：把 129 处手写 `class="state-empty"` 全换成 `<EmptyState>`。
其中绝大多数是**单行纯文字**（`<div class="state-empty">正在加载待办…</div>`），
换成组件会无条件加一个 48px 图标块 —— 那是变啰嗦不是变统一。
真正该换的是「图标 + 标题 + 描述」的三段式手写块，量不大，留到下一轮按页处理。
