# Hergent 进销存模块差距分析与分阶段开发计划

> 主笔：产品经理 许清楚（Xu）｜定位：项目级战略文档
> 受众：老板（非技术、产品决策人、蒙牛低温奶经销商老张）+ 未来技术合伙人 / 投资人
> 一句话定调：**交易层（进销存）只求对标舟谱"可替换、敢卖"，护城河是 AI 经营副驾，不是交易层本身。**

---

## 一、执行摘要（结论先行）

1. **核心交易闭环已经跑通**：采购、销售、库存三大件都已闭环，FEFO 先到期先发货、效期预警、盘点差异、库存预警都有——老板自己用，基本能记账、能管货。
2. **但"敢卖给别的经销商"还差三道硬门槛**：① 报表全空（三十张页面全是"开发中"占位），老板和买家都"看不懂账"；② 整模块目前只对老板一个人可见、没有按岗位分权、没有审批流，"雇个会计也登不进系统，没法分工"；③ 单据可追溯有断点（销售退货建完就不在列表里、采购谁审核没留痕、调拨搬运费填了不存库），对账时说不清。
3. **多租户隔离还没验证**，这是"卖产品给别家"的物理前提——A 家的数据绝不能让 B 家看见。
4. **策略排序**：差距分两层——"达标线"（卖之前必须补齐的硬缺口，不补不敢卖）和"差异化"（锦上添花，护城河在 AI 副驾）。把力气花在达标线上，差异化留给 AI。
5. **建议分四个阶段**：P0 老板自用跑顺 → P1 敢卖（分权＋报表＋对账）→ P2 差异化（高级分析＋自动化）→ P3 多租户 SaaS 化＋生态。

---

## 二、评估方法与口径说明

**打分依据（双来源）**
- **实测绘**：对 `hergent-cn-v2/src` 只读实测，现状全部来自真实代码侦察（见下文各维度证据与文件指向），不凭空编。
- **对标 ERP 公开能力**：SAP S/4HANA（MM/SD/FI/WM）、用友 YonSuite / U9、金蝶云·星空 / 星辰，以及大厂供应链中台（京东物流、菜鸟、美团库存中台）的公开产品能力。

**分层原则（最关键）**
- **达标线（红 / 黄且影响"可替换、敢卖"）**：不补就不敢卖给同行，是售卖的第一硬门槛。
- **差异化（黄且属增值）**：专业 ERP 也有、但非售卖阻断项，优先让 AI 经营副驾来体现，不在交易层过度投入。

**状态图例**
- ✅ 已具备 ｜ ⚠️ 部分具备或有缺口 ｜ 🔴 缺失或未闭环

## 三、八维度差距分析

### 维度总览表

| # | 维度 | 判定 | 对"敢卖"权重 | 一句话定位 |
|---|---|---|---|---|
| 1 | 采购管理 | ✅/⚠️ | 中 | 闭环已通，补审核留痕即可 |
| 2 | 销售管理 | ✅/⚠️ | 高 | 退货可追溯是信任底座 |
| 3 | 库存管理 | ✅ | 高 | FEFO/效期达标，缺占用锁定 |
| 4 | 财务对账 | ⚠️ | 中高 | 自动勾对缺失，靠人工 |
| 5 | 报表分析 | 🔴 | 极高 | 三十张全空，售卖第一缺口 |
| 6 | 权限与流程审批 | ⚠️ | 极高 | 整模块老板硬锁，最大结构缺口 |
| 7 | UI / 信息密度 | ✅/⚠️ | 中 | 效率项，不阻断售卖 |
| 8 | 数据准确性 / 自动化 | ✅ | 中 | 工程素养已到位，是优势 |

---

### 1. 采购管理 ✅/⚠️
- **现状**：订单 → 入库（分批 `confirmPurchase` / `receivePurchase`）→ 退货（`returnPreview` 后端算余量）→ 结算（`settlementCandidates` / `confirmSettlement`）闭环完整；候选单仅靠 `returnable:1` 粗筛。
- **对标**：SAP MM 有发票校验与审批策略；用友 U9 采购全程跟踪＋多级审批；金蝶云·星空 订单—收料—检验—入库—发票—付款全链路；京东采购中台有供应商协同＋三单自动匹配。
- **具体差距（带证据）**：
  - 候选列表粗筛，`returnPreview` 能逐行算 `returnable_qty` 却未反向过滤整单列表，仍可能列出"已退完"的采购单。
  - 采购单 `approver` 从不记录，**审核人无留痕**（合规审计线索断裂）。
  - 无多级审批流。
- **权重**：中。核心闭环已通，卖前补"审核留痕＋候选过滤"即可达标。

### 2. 销售管理 ✅/⚠️
- **现状**：自提 / 车销 / 退单四型，FEFO 发货、签收应收；调拨双仓已支持；但**独立销售退货单无列表出口**。
- **对标**：SAP SD 销售订单—交货—开票—收款＋信贷管理；用友 / 金蝶 销售全流程＋信用额度；美团库存中台 门店要货—配送—退货闭环。
- **具体差距（带证据）**：
  - 独立销售退货单建完即"消失在列表外"，违背"任何单据可追溯"。*为什么重要：经销商最怕"钱货对不上还说不清"，一张退单找不到，信任当场崩。*（注：此缺陷已在 `InvSaleList` 改用服务端 `status='returned'` 闭环，见第五节。）
  - 调拨缺搬运费 / 部门、退货缺部门，`docTypes.js` 自陈"填了不落库"——弱于舟谱。
- **权重**：高。销售是经销商命脉，退货可追溯是信任基础。

### 3. 库存管理 ✅
- **现状**：实时库存、预警 `StockAlert`、盘点 `Stocktake`＋差异、效期 `ExpiryReport`、FEFO 均已具备；调拨列表页已存在。
- **对标**：SAP IM/WM 批次—序列号—货架位；金蝶 库存—批次—序列号—锁库；菜鸟 / 京东库存中台 占用 / 锁定＋全渠道库存。
- **具体差距（带证据）**：
  - 批次三列（生产日期 / 效期 / 批号）选填非强制，且**无"批次追溯查询"页**（仅建单时登记）。*为什么重要：低温奶出质量问题，批号查不到源头，召回和索赔都做不了。*
  - **无占用 / 锁定概念**（`psi.js` 自承"没有占用/锁定"）——可用库存＝可销售，多单并发易超卖。*为什么重要：两笔单同时卖同一批奶，系统都说有货，实际发不出，就是客诉。*
- **权重**：高。FEFO/效期已达标，但占用锁定是防超卖硬项，建议卖前补。

### 4. 财务对账 ⚠️
- **现状**：`FundsBankReconcile` 真实页存在；应收应付 / 往来账走 `getPurchasePayments` 等接口，但**自动勾对 / 对账算子未见**。
- **对标**：SAP FI 自动清账；用友 总账—应收应付—自动勾对；金蝶 智能对账。
- **具体差距**：自动勾对缺失，依赖人工逐笔核对。*为什么重要：老板最关心"钱对不对"，自动勾对省下会计两天活，还是卖点。*
- **权重**：中高。

### 5. 报表分析 🔴
- **现状**：三十个 `/reports/*` 页面**全部为占位页**（仅"开发中"卡片），毛利 / 均单 / 库存周转 / 账龄等专业 ERP 标配分析全缺失。
- **对标**：SAP 利润分析（COPA）；用友 经营看板 / 毛利分析；金蝶 经营分析报告；大厂 BI 中台。
- **具体差距**：分析能力为零。*为什么重要：经销商老板买系统，第一句话就是"我能看到我赚了多少吗"，看不到就不敢买。这是售卖第一硬缺口。*
- **权重**：极高。

### 6. 权限与流程审批 ⚠️
- **现状**：列设置云端同步、状态页签服务端计数、角色闸门已具备；但**整 PSI 区目前只对 boss 可见（v472 开发期硬锁）**，无细粒度角色分权、无多级审批流；采购单审核人无留痕。
- **对标**：SAP 权限对象＋审批策略；用友 角色权限＋工作流引擎；金蝶 BOS 流程平台。
- **具体差距**：
  - 整模块老板硬锁，仓管 / 会计 / 业务员无法各自登录分工。*为什么重要：等于雇个人也登不进系统，老板自己被绑死在电脑前，根本没法当产品卖。*
  - 无多级审批流；审核留痕缺失。
- **权重**：极高。这是从"自用"到"卖产品"最大的结构性缺口。

### 7. UI / 信息密度 ✅/⚠️
- **现状**：列齿轮、密度切换、列宽拖拽、复制上期已具备；缺批量操作栏（仅采购有 `batchPurchases`）、缺全屏查看、缺一键导出 CSV。
- **对标**：用友 / 金蝶 列表标配批量审核 / 打印 / 导出 / 自定义筛选方案。
- **具体差距**：批量操作仅采购有；无 CSV 导出、无全屏、无自定义筛选方案。
- **权重**：中。影响体验但不阻断售卖。

### 8. 数据准确性 / 自动化 ✅
- **现状**：服务端计数、`has_items=false` 显示"—"不显零、换期不传染零行、幂等键防重复提交均已具备；批次三列选填非强制。
- **对标**：专业 ERP 强制校验＋自动化算子。
- **具体差距**：批次选填非强制；自动勾对 / 自动预警规则等自动化算子少。
- **权重**：中。基础准确性的工程素养已到位，**这是我们的优势，应在文档里讲给投资人听**。

## 四、五大优化轴专项

| 优化轴 | 当前短板 | 目标态 | 具体可优化点 |
|---|---|---|---|
| **功能完整性** | 报表全空、销售退货无列表、分权审批为零、批次追溯缺、调拨/退货部门费不落库 | 单据全生命周期可追溯、报表可用、分权审批建立 | 交付毛利/均单/周转/账龄四报表；销售退货列表出口；岗位角色＋审批流；批次追溯页；调拨搬运费/部门落库 |
| **性能** | SQLite 多租户并发写入与占用锁定时可能瓶颈；批量处理能力未验证 | 单租户日千单无感；多租户隔离下性能稳定 | 写入串行化/连接池；关键列表分页＋计数缓存；必要时租户库迁 Postgres |

| **数据准确性** | 批次选填非强制、审核留痕空、`col-prefs` 后端 400 降级 | 关键字段强制＋全链路留痕＋配置接口自愈 | 批次三列弱强制；操作日志补全审核人/入库人；`col-prefs` 后端修复 |
| **自动化程度** | 自动勾对缺失、无占用/锁定、预警规则手动 | 自动勾对＋占用锁定＋规则化预警 | 银行流水自动勾对；库存占用锁定防超卖；效期/低库存自动预警推送 AI 副驾 |

## 六、分阶段开发计划（核心交付物）

> 工作量口径：本项目是一人＋AI 模式，以"端到端交付批次"近似人日（一个批次＝从需求到上线可验收的一轮迭代）。

### ▍P0 阶段：达标线补齐（老板自用跑顺）
- **阶段目标**：把老板自己用这套系统跑顺、跑稳，修掉所有"对账说不清、单据找不到"的断点。
- **包含需求 / 改造项**：
  1. P0-1 销售退货单列表出口（验收：销售退货单在列表可检索并展示状态页签计数）
  2. P0-2 采购退货候选列表按可退量过滤（`returnable_qty=0` 不列）
  3. P0-3 采购单审核人留痕＋操作日志记录审核/入库人（补合规审计线索）
  4. P0-4 调拨搬运费/部门、退货部门落库（修复 `docTypes` "填了不落库"）
  5. P0-5 库存占用/锁定概念引入（补 `psi.js` 现有"没有占用/锁定"，防超卖）
  6. P0-6 `col-prefs` 后端 400 根因修复
  7. P0-7 `?copy` 空单号阻断渲染
- **优先级**：P0（必须）
- **预估工作量**：约 6–8 个端到端交付批次
- **验收标准**：老板连续自用零事故；任意单据类型列表可检索且状态计数正确；调拨/退货部门费落库；启用占用锁定后并发下单不超卖。

### ▍P1 阶段：分权审批＋报表＋对账（敢卖）
- **阶段目标**：让系统"能雇人、能看账、钱能对"，达到可替换舟谱、敢卖给同行的达标线。
- **包含需求 / 改造项**：
  1. P1-1 岗位角色分权（boss/仓管/会计/业务员各自可见模块与操作闸门，解除整模块 boss 硬锁）
  2. P1-2 多级审批流（采购单/退货单/调拨单可配审批节点并留痕）
  3. P1-3 核心报表四张：毛利分析、均单分析、库存周转、应收账龄（从三十占位中优先交付）
  4. P1-4 自动勾对/对账算子（银行流水 vs 应收应付自动匹配，差异高亮）
  5. P1-5 批次追溯查询页（批号—效期—序列号全链路）
  6. P1-6 列表通用批量栏＋CSV 导出＋自定义筛选方案（从采购 `batchPurchases` 抽象到全列表）
- **优先级**：P1（必须，售卖门槛）
- **预估工作量**：约 10–14 个端到端交付批次
- **验收标准**：非 boss 角色登录仅见被授权模块；审批流按配置触发并留痕；四报表抽样核对数据正确；自动勾对准确率不低于九成五；任一列表可一键导出 CSV。

### ▍P2 阶段：高级分析＋自动化（差异化增值 / AI 副驾叠加）
- **阶段目标**：在交易层之上叠加数据分析与自动化，让 AI 经营副驾有料可喂，形成差异化。
- **包含需求 / 改造项**：
  1. P2-1 高级分析：利润贡献品项、客户/渠道毛利、促销投入产出比、现金流量预测
  2. P2-2 自动化：效期/低库存自动预警推送副驾；补货建议；自动生成经营周报
  3. P2-3 序列号/货架位管理（对标 SAP WM）
  4. P2-4 与 Hergent AI 经营副驾数据打通（经营指标实时喂给副驾问答）
- **优先级**：高（增值，不阻断售卖）
- **预估工作量**：约 8–12 个端到端交付批次
- **验收标准**：副驾能基于真实交易数据回答"本月哪款奶最赚""临期库存还有多少"；预警自动触发且可溯源到单据。

### ▍P3 阶段：多租户 SaaS 化＋生态（规模化变现）
- **阶段目标**：从"自用"到"卖产品"，完成多租户隔离与生态，支撑对外售卖与投资人叙事。
- **包含需求 / 改造项**：
  1. P3-1 多租户隔离验证与加固（租户库 `tenant_<id>.db` 物理隔离＋越权测试）
  2. P3-2 注册 / 开通 / 计费 / 试用流程
  3. P3-3 开放接口 / Webhook（对接舟谱迁移、第三方物流与财务）
  4. P3-4 数据迁移工具（舟谱 → Hergent 一键迁）
  5. P3-5 安全债清偿（S1–S5、生产凭据 private）
- **优先级**：中（规模化阶段）
- **预估工作量**：约 12–16 个端到端交付批次
- **验收标准**：新租户独立库隔离，A 租户不可读 B 租户；迁移工具跑通百家级数据；安全扫描无高危项。

## 七、风险与依赖

- **技术债（已知安全债 S1–S5）**：仓内含生产凭据须 `private`——卖前必须清偿，否则投资人或买家做尽调时一票否决。
- **多租户隔离**：SQLite 每租户独立库已具备物理隔离雏形，但隔离边界、越权、备份恢复**尚未验证**，是 P3 的前置硬依赖。
- **卖前"三关"（上线售卖前的及格线）**：① 老板连续自用三个月零事故；② 跑通不少于一百笔真实跨采购/销售/退货/调拨交易；③ 数据隔离验证通过。
- **依赖关系**：AI 副驾差异化依赖 P1/P2 数据层打通；技术合伙人引入节奏直接影响 P2/P3 速度。

## 八、给老板的决策建议

1. **下一步先投哪条线**：先投 P0（跑顺自用），并立刻并行启动 P1 的"报表"与"分权"两条线——因为这两件事直接决定"敢不敢卖"，也是买家第一眼看的。其余（自动化、生态）可后放。
2. **是否现在就排技术合伙人**：建议在 P0 跑顺、P1 启动后引入；技术合伙人重点补"分权审批＋多租户＋安全债"三块工程厚度。若近期要见投资人、对方看重工程底子，可提前引入更稳。AI 副驾差异化可继续自营。
3. **AI 副驾差异化怎么在交易层之上叠加**：交易层只求对标舟谱"可替换"，把省下的精力压在 AI 经营副驾——它吃交易层数据，做"老板问一句、副驾答一屏"的经营参谋。这是舟谱没有、大厂 ERP 也贵且笨的差异化。**卖点话术：进销存对标舟谱免费级，经营副驾对标咨询公司收费级。**
