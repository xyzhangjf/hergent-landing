## 0. 一句话结论

在既有「单元格矩形选区」之上加了两条**互相独立但互斥**的选择轴：**行轴**（点行号 / 点只读格 → 整行；
竖向拖动 → 连续多行）与**列轴**（点表头 → 整列；横向拖动 → 连续多列），并让右键菜单**按轴分流**。
三条轴共用**同一套选区数据结构**，所以复制 / 清空 / 批量填入 / 导出 / 选区统计 / CSV / Markdown
这些下游消费者**一行都不用改**就同时支持行粒度与列粒度。

## 1. 三轴模型：互斥关系与联动关系（需求 ③）

### 1.1 状态与不变式

| 项 | 值 |
|---|---|
| 状态 | `selAxis: 'cell' \| 'row' \| 'col'`，默认 `'cell'`（**默认轴 = 既有行为逐字不变**） |
| 选区数据 | `selRange{r0,c0,r1,c1}` + `selected{r,c}` + `selAnchor{r,c}` —— **三轴共用同一套** |
| 行轴不变式 | `c0 = 0`、`c1 = 最后可编辑列`（**恒满宽**） |
| 列轴不变式 | `r0 = 0`、`r1 = 最后一行`（**恒满高**） |
| 写入口 | 唯一：`setAxisRange(axis, 锚点, 当前端)`。拖选/单击都必须走它 —— 两处写必然漂移 |

### 1.2 互斥：任一时刻只有一个轴生效

「同时选中整行又选中整列」没有无歧义的语义（是整行×整列的交叉区？还是并集？），
所以设计上**不做叠加**，只做互斥。互斥在三个层面都被落实，不只是数据层面：

| 层面 | 保证 |
|---|---|
| 数据 | 切换轴时 `setAxisRange` 整体覆写 `selRange`；任何点输入格的 `mousedown` 都会把轴复位为 `'cell'` |
| **视觉** | 行轴下**不画列高亮**、列轴下**不画行高亮** —— 否则「整行亮着 + 表头还有一列是选中样式」会把互斥这条规则在界面上推翻 |
| 出口 | `Esc`、`clearSel()`、选区统计条的关闭按钮、菜单的「取消行选中」，一律**连轴一起复位**（只清选区不清轴 ⇒「轴还是 row、选区已空」的错位态：界面没有任何高亮，右键却弹行菜单） |

**一个刻意的例外（不是叠加，是锚点）**：被点中的那一格仍保留 `.selected` 的 2px 描边。
它表达「键盘/操作当前落在这一格」（方向键、Delete、填充的起点），**不表达「这一格被选中」**；
行轴、列轴下它都只有一个，且在轴切换时跟着走。

### 1.3 联动：共用一套矩形，所以下游零改动

行轴恒满宽、列轴恒满高 ⇒ 下游所有按「矩形区间」取数的消费者天然支持行/列粒度，**未改一行**：

复制（TSV）· 复制为 CSV · 复制为 Markdown · 导出选中行 · 清空选区 · 批量填入相同值 ·
选区统计（格数/求和/平均）· 删除行（行轴下整段删）· `Ctrl+Enter` 批量写入

对应地，选区统计条按轴改口径，说的和做的同源：

| 轴 | 文案 | 计数 | 单位 |
|---|---|---|---|
| cell | 选区统计 | 行数 × 列数 | 格 |
| row | 行选中 | `r1-r0+1` | 行 |
| col | 列选中 | `c1-c0+1` | 列 |

> 计数**只从 `selRange` 派生**，不另立第二套计数 —— 否则「说清了 5 行、实际清了 12 格」这种错位迟早出现。

## 2. 落点 → 轴：进入规则（需求 ① ②）

判据是**列元数据**（`edit === 'text' | 'num'` + 数量列 + 两个 calc 输入列），**不是 DOM 目标**。

> 🔴 为什么不能用 `e.target.tagName === 'INPUT'` 判：可编辑格的**内边距**点下去 target 是 `td`，
> 按 DOM 判会把「点在自己要编辑的那一格边缘」误判成「点了非输入区 ⇒ 选整行」。

| 落点 | 左键操作 | 结果轴 | 说明 |
|---|---|---|---|
| 输入格：可编辑主档列（`edit=text/num`） | 单击 / 拖动 | **cell** | 行为**逐字不变**（原「点一次全选内容、点第二次进输入态」两态保留） |
| 输入格：数量列（各报单对象） | 单击 / 拖动 | **cell** | 同上 |
| 输入格：计算列里的「加单(箱)」「单价(进价/箱)」 | 单击 / 拖动 | **cell** | 这两格列号是**哨兵值**，必须显式认下，否则会被归到「非输入区」⇒ 左键选不中、右键走错菜单 |
| **非**输入格：只读主档列 | 单击 / 竖向拖动 | **row** | 点哪儿选哪行 |
| **行号格** | 单击 / 竖向拖动 | **row** | 行轴最主要的使用姿势 |
| 计算列：合计 / 箱数 / 建议 / 最终下单 / 金额 / 对比 / 迷你图 / 同比 | 单击 / 竖向拖动 | **row** | 这些格没有统一列号（`SEQ_CI = -1`），只贡献「行」 |
| 操作列（删除该行按钮） | 单击空白处 | **row** | 里面的按钮/链接**放行**，不抢它的点击 |
| 表头 `<th>`（主档列 / 数量列） | 单击 / **横向**拖动 | **col** | 列宽拖拽手柄已 `@mousedown.stop.prevent` ⇒ 与列宽调整不冲突 |

**退出路径**（全部会同时清轴，不留错位态）：

| 路径 | 类型 |
|---|---|
| `Esc` | **显式**退出（唯一的显式退出键） |
| 方向键 / Home / End / PageUp·Down / Ctrl+方向键 | **隐式**退出（经 `selectCell` 回单元格轴） |
| `Ctrl/Cmd + A` | 回单元格轴（= 全选编辑区的**满表矩形**，不是行轴） |
| 单击任一输入格 | 回单元格轴 |
| 行菜单「取消行选中」/「清空选中行」 | 显式清轴 |

## 3. 右键菜单：触发区域与可用操作项（需求 ④）

### 3.1 路由表（唯一判定处 `onTbCtx`，优先级从上到下）

| 优先级 | 触发区域 | 判定 | 弹出 |
|---|---|---|---|
| 1 | 表体任意处 | 批量填入子模式已打开（`ctxMode === 'fill'`） | **子模式优先**，不受轴影响（否则行轴一右键就永远打不开它） |
| 2 | 表体，落点在**列选区**内 | `selAxis==='col' && inColSpan(落点列)` | **列菜单**（复用表头那份，只换锚点） |
| 3 | 表体，落点在**行选区**内 | `selAxis==='row' && inRowSpan(落点行)` | **行菜单**，**保留整段多行选区**（作用于整段） |
| 4 | 表体，其它 | — | **行菜单**，并把选区迁到该行（Excel 心智：右键哪行就管哪行） |
| — | **表头 `<th>`** | 恒 | **列菜单**（`openHdrCtx`），与上表并行、不冲突 |

### 3.2 行菜单（触发区域 ①②③④）

抬头：`行选中 N 行`，并按**真实原因**追加两栏 ——
`，其中 M 行已被筛选隐藏`（该去清筛选）／`，另有 K 行不在当前页`（翻页就能看到）。

| 分组 | 菜单项 |
|---|---|
| 复制导出 | 复制选中行（TSV）· 复制为 CSV · 复制为 Markdown · 导出选中行 |
| 批量 | 批量填入相同值… `Ctrl+Enter` · 清空选中行 `Delete` |
| 行结构 | ↑ 在上方插入行 · ↓ 在下方插入行 · 复制此行到下方 · **删除选中行（N 行）** |
| 其它 | 本行加备注 · 让 AI 分析这行（有 AI 权限时） · 此列统计（落点列有统一列号时） |
| 退出 | 全选所有行 · 取消行选中 `Esc` |

- **删除**是行轴感知的：在行选区里右键就是**整段删**，一次 `snapshot()` = **一次撤销可回**（不是按 N 次 Ctrl+Z）。
- 行菜单里**不再混入单元格轴入口**（无「全选编辑区域」「粘贴」「向下填充」）——
  已用 A/B 断言钉住（BEFORE 侧的老表体菜单恰好有「全选编辑区域」，AFTER 侧没有）。

### 3.3 列菜单（触发区域：表头 / 选中的列）

抬头：`列选中 N 列`。

| 分组 | 菜单项 | 作用粒度 |
|---|---|---|
| 新增（v377） | 复制选中列 · 清空选中列 `Delete` | **整个列选区** |
| 既有（原样保留） | 修改字段 · 增加列 · 删除列 · 列统计 · 筛选此列… · 按唯一值筛选… · 按此列分组小计 · 复制列名 · 设置列宽… · 按此列升序 · 按此列降序 · 隐藏此列 · 冻结此列 | **右键点中的那一列** |

⚠️ **本菜单内部粒度不对称，是刻意的**（并且已在菜单里用抬头点明「列选中 N 列」）：
新增的两条面向**整个列选区**；既有十几条本来就是**单列动作**（列配置 / 单列筛选 / 单列排序 / 列宽），
把它们改成「对每列各做一次」会牵动列配置与筛选语义 —— 那是另一件事，不在本轮范围。

**未选中列时的表头右键**：抬头位置改为一条 `选中整列` ——
让「表头能选整列」这件事在菜单里也说得出来，而不只靠用户去试。
已断言「**菜单点了真生效**」（菜单不撒谎）：点它之后该列表头确实进入列轴选中态。

## 4. 边界情况（需求 ⑤）

### 4.1 拖动起止

| 情形 | 处理 |
|---|---|
| 单击无拖动 | 选中在 **`mousedown` 那一刻就完成**；`mouseup` 时**不再改写**（否则 `selectCell` 会把轴复位 ⇒「整行刚选中就散架」） |
| 拖动结束 | `mouseup` 收尾；**另挂 `window` 的 `blur` 兜底**：切 App / 系统弹窗抢走 `mouseup` 时，若不兜底 `dragging` 会**永远停在 true**，此后鼠标划过表格就一通乱选 |
| 拖动中越界（拖出行/列范围） | 端点**夹取**到 `[0, 边界]`，不抛错、不越界写 |
| 空表（无行或无列） | `maxR/maxC < 0` 时直接 `clearSel()`，不进任何轴 |

### 4.2 跨行、跨列、反向拖

| 情形 | 处理 |
|---|---|
| 反向拖动（下→上 / 右→左） | 区间取两端的 `min/max`；实测 `4..6` 与 `6..4` 得到同一区间 |
| 行轴拖动横扫过其它列 | **只动行**。轴在 `mousedown` 那一刻**锁定**（`_dragAxis`），中途越过输入格、左右横扫都**不会把行选区变形为矩形** —— 那是最容易让人觉得「表格乱选」的失败模式 |
| 列轴拖动的纵坐标变化 | 只动列，同上 |
| Shift+单击 | 行轴：以**行锚点**为基准扩展；列轴：以**当前焦点列**为基准扩展（跨轴转换时锚点取 `selected.c` 才有意义） |
| 矩形选区被拖成不存在 | `clampSelection` 里按轴恢复不变式；若区间整体作废，**轴一并回中**（不留错位态） |

### 4.3 与单元格编辑输入态的冲突 ★

这是本轮**最容易静默丢改动**的一条，处理方式是「进轴之前先提交」：

> 行/列轴的 `mousedown` 会 `preventDefault()`（禁止浏览器默认的焦点转移），
> 于是原先聚焦的输入框**不会失焦** ⇒ 它的 `change` 永不触发 ⇒ `onCellChange` 不执行 ⇒
> 刚改的那一格**既不进撤销栈、也不点亮「未保存」**。
> 用户眼里「我明明改了」，系统眼里「什么都没发生」。

因此 `onCellDown` / `onHeadDown` 的**固定顺序**是：先 `commitPendingEdit()`（主动 `blur()`），
**后** `preventDefault()`。已用真机断言钉住：改一格 → 点行号切到行轴 →
① 值仍在格内 ②「有未保存的改动」仍然点亮。

配套的焦点处理：编辑网格加了 `tabindex="-1"`，行/列轴选中后调 `focusGrid()` 把焦点**交还表格本体**。
少了这一步：`blur` 之后焦点落在 `body` ⇒ `@keydown` 收不到事件 ⇒
**Delete / 方向键全失效**，而「选中整行再按 Delete」正是行轴最主要的使用姿势。

### 4.4 看不见的行（筛选 / 分页）★

行区间是**行号连续**的（与矩形选区同一语义，不另立一套），所以被藏起来的行**也会被一起操作**。
唯一能做的是**把它说出来**，不让用户在看不见的地方丢数据 —— 并且**按真实原因分两栏说**：

| 原因 | 用户该做什么 | 菜单抬头 |
|---|---|---|
| 被搜索词 / 隐藏零量 / 列筛选挡掉 | 去清筛选 | `，其中 M 行已被筛选隐藏` |
| 只是不在当前页（分页模式） | 翻页就能看到 | `，另有 K 行不在当前页` |

> 🔴 原先两种原因**混成一个数**：分页开着时「全选所有行」会报出「104 行已被筛选隐藏」，
> 而用户明明没开任何筛选 —— 让他去翻一个根本不存在的筛选器。**说了话但是假话，比不说更坏。**
> 已拆开（`rowBaseShown` 只管筛选类、`rowShown` = 它 && 分页可见），
> 并在真机上断言：分页下「全选所有行」的抬头必须是「另有 104 行不在当前页」，且**不得**出现「已被筛选隐藏」。
> 删除行的提示同样按两栏报（`已删除 154 行（含 104 行不在当前页）`）。

**已真机造出的场景**：搜索词把 154 行筛到只剩 3 行 → 竖向拖出一个 0..5 的区间（其中 4 行被筛掉）
→ 右键抬头实测 `行选中 6 行，其中 4 行已被筛选隐藏` → 操作作用于**连续 6 行**。

### 4.5 列轴不参与批量应用

批量编辑面板的「应用」以 `selectedRows()` 为作用域。列区间是**满高**的 ⇒
若不拦，点一下表头选整列、再点「应用」就会**静默改写整张表**。
故 `selectedRows()` 在列轴下**只认当前焦点行**，面板提示同步改为
`列选中不参与批量应用，请先选中要改的行`。

### 4.6 填充柄只在单元格轴出现

填充的实现（`doFill`）以**锚点格**为准、**不读 `selRange`** ⇒ 在整行/整列选区下，
它会填出一个「从锚点算起的矩形」，而界面上显示的是整行/整列 —— **显示与行为不一致**。
故填充柄的显示条件收紧为 `selAxis === 'cell'`（原先只排除了行轴，列轴会漏出来）。

### 4.7 哨兵列：宁可不出按钮，也不出会做错事的按钮

「加单(箱)」「单价(进价/箱)」两格的列号超出 `visibleCols + units` 的取值范围。
凡是**与某一列绑定**的动作（插入列 / 删除列 / 此列统计 / 按安全库存补齐），
在落点是哨兵列时**直接不出按钮**（`ctxColOpsOk` 门禁），而不是带着越界下标去执行。

### 4.8 单元格轴拖动横扫过哨兵列

行号格 / 计算列 / 操作列在单元格轴拖动里传进来的是 `SEQ_CI = -1`。
若原样写进 `selected.c` 与选区左端，「当前列」会变成一个**不存在的列**，
随后方向键 / 填充 / 右键「此列统计」全部指向空格（不报错、就是不对）。
⇒ 单元格轴下这些格**只贡献行**，列沿用锚点列。

## 5. 两轴的视觉语言（怎么一眼分清）

| 轴 | 表头 | 表体 | 左端 |
|---|---|---|---|
| 行 | 无 | 整行底色（`--p-bg`，含计算列/操作列 —— 它们没有统一列号，只能靠 `tr` 级类一次覆盖） | **3px 主色竖条** + 行号变色加粗 |
| 列 | 青底 + 青字 + **2px 主色下划线**（与全站激活态同一语法） | 整列左右 1px 描边 + 覆盖 | 无 |

行轴的整行底色**必须** `!important`（数量格底色由 `heatOf()` 以内联 `:style` 写死，类选择器压不住）；
新增行的 3px 竖条由 `.new-row` 按更高特异性负责，两者不抢。
深色模式走同一批 CSS 变量（`--p-bg` / `--p-ink` / `--p-border`），无新增硬编码颜色。

## 9. 附：一次值得记下的构建学现象

为证明「改一条注释零行为影响」，我做了这样一次对照，并**没得到预期的结论**：

- 同一源码连跑两次构建 ⇒ chunk 名**完全一致**（构建是确定的）；
- 但**仅改一条被剥掉的注释**（已证：`显式/隐式/错位态` 在产物里命中 0）后重建 ⇒
  `Forecast` 与**入口 `index`** 两个 chunk **同时改名**；
- 逐字节比对两份产物：**长度完全相同（449,869 B），首个差异在 offset 378 —— 正是 `index-*.js` 的依赖名**。

⇒ 入口与页面 chunk 之间存在 `__vite__mapDeps` 式的**循环引用**，chunk 名的最终取值是
占位符迭代收敛的结果；**连一条注释都足以把入口 chunk 改名**。
这给既有的那条铁律又添了一个实例：**chunk 文件名什么都判不了，永远比字节、不比名字。**
（本轮 A/B 证据不受影响 —— 它跑在 **dev server** 上，按源码实时编译，与任何构建产物无关。）
