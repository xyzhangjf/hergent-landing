## 二、逐项冗余判定与优化方案

### 组 1｜空态双按钮重复 — 冗余

| 项 | 内容 |
|---|---|
| **重复方** | `:28` 「去创建目标」 ↔ `:89` 「去创建品牌目标」（`MonthlyAchvChart` 的 `#empty-action`） |
| **原因** | 两者都在"无数据"时渲染，`@click` 完全相同（`mainTab='rules'`）。触发条件不互斥：rules 为空 → `dashboardModel.items` 为空（显示 :28）且 `chartMatrix` 为空（显示 :89），**同屏同时出现** |
| **潜在影响** | 用户看到两个几乎相同的按钮，文案差异（"目标" vs "品牌目标"）让人误以为功能不同；占位重复、视觉噪音；两个按钮都不带 `openCreate('brand')`，跳过去还要再点一次，转化路径长 |
| **优化方案** | **移除 `:89` 的 slot 按钮**（保留 `:28`）。理由：页面级空态是"整页无数据"的首要引导，职责优先；图表 slot 属次级空态。 |
| **增强建议** | 把保留的那个按钮改为**直达创建**：`@click="openCreate('brand')"` 而非只切 tab，少一跳。 |

---

### 组 2｜排行行内双算式入口 — 冗余（最直接）

| 项 | 内容 |
|---|---|
| **重复方** | `:117` 「算式」按钮 ↔ `:132` 「看算式」链接 |
| **原因** | 同一行内两处，`@click="openCalc(it.simData, it.rule.rule_name)"` **函数与参数完全一致**，渲染条件同为 `it.simReady` |
| **潜在影响** | 一眼可见的重复按钮，用户会疑惑"算式"与"看算式"是否有差别；一行出现两个同义入口降低专业感 |
| **优化方案** | **移除 `:117` 的「算式」按钮**，保留 `:132` 的「看算式」链接。理由：链接紧贴"预计返利 ¥X"数值，形成"看到金额 → 追问怎么算的"自然动线，语义上下文更强。 |
| **备选** | 若希望入口常在，则保留 `:117` 并删除 `:132`，但需把按钮移到金额旁。**二选一，不要并存**。 |

### 组 3｜无数据提示两处重复 — 冗余 + 缺操作

| 项 | 内容 |
|---|---|
| **重复方** | `:73` dash-nodata（"本月在达成填报里还没录入数据，进度条按 0% 显示…去达成填报录一笔"）↔ `:1250` anomalies 的 nodata 条（"X 个生效目标本月尚未填报达成"） |
| **原因** | 表达同一事实（本月未填报）。前者是整段长文案，后者是异常清单的一条 |
| **潜在影响** | 同屏两段相似提示，用户不知该读哪个；两处都只是"说明"，**都没有"去填报"按钮**，看完仍需自己找路径 |
| **优化方案** | **删除 `:73` 的 dash-nodata**，把它的引导价值**合并进异常区的 nodata 条**：给该条加"去填报"按钮（跳 `mainTab='achv'`）。一举两得——消除重复 + 补上缺失的操作闭环。 |

### 组 4｜两套图例同屏 — 重叠（保留但需区隔）

| 项 | 内容 |
|---|---|
| **重叠方** | `:66-72` 页面级状态图例（已达标/预警/推进中/时间进度）↔ 组件 `:42-53` 数据系列图例（可点击开关） |
| **原因** | 两套都是"小色块 + 文字"形态，同屏出现；前者解释条形排行，后者控制柱状图，但视觉相似度高 |
| **潜在影响** | 用户需判断"哪个图例管哪块"，认知负担；状态色与数据系列色可能语义打架 |
| **优化方案** | **两套都保留（各有职责）**，但做归属与权重区隔：把页面级图例从"悬浮在中间"改为**内联到排行区标题行右侧**（小字、弱化），明确它属于排行区；图表图例留在组件内不动。 |
| **理由** | 图例本身有用（首次理解必需），问题只是"归属不清"而非"多余"。 |

### 组 5｜两个时间控件 — 重叠（保留，建议联动）

| 项 | 内容 |
|---|---|
| **重叠方** | `:19` 页面「统计月份」(month) ↔ 组件 `:9` 图表「年份」(select) |
| **原因** | 同屏两个时间选择器，粒度不同（月 / 年）；部分联动（月份只影响 KPI/排行/异常，年份只影响柱状图） |
| **潜在影响** | 用户易误以为改月份也会改图表、或改年份会影响 KPI，切换后"没反应"造成困惑；"部分联动"模型需靠 `:54` 的说明文案补救 |
| **优化方案** | **保留两个（职责确实不同），按成本分两步**：<br>**A（推荐，小改）**：给月份控件加"单月视图"、年份旁加"全年视图"标签，明确区分作用域。<br>**B（后续优化）**：把图表年份**锚定到月份控件所在年份**（改月份时自动同步图表年份到同年），减少一个独立控件——需先确认跨年数据可用性。<br>**C（不建议）**：合并成统一时间轴，改动过大、收益不成比例。 |

### 组 6｜"达成率"同名两种口径 — 重叠（业务风险最高）

| 项 | 内容 |
|---|---|
| **重叠方** | KPI「平均达成率」(`:49`，`Rebate.vue:1889` `achSum / activeRules.length`，**算术平均**) ↔ 图表「达成率」视图（组件 `:52` 注明"合计达成 ÷ 合计目标"，**加权**） |
| **原因** | 两个都叫"达成率"，但一个按规则条数平均、一个按金额加权 |
| **潜在影响** | **同一屏两个数字打架**，用户对比后必然认为其中一个错了；当品牌目标体量悬殊时，算术平均会被小目标规则显著拉偏，与加权值差距明显，直接损害数据可信度 |
| **优化方案** | **统一为加权口径**：KPI「平均达成率」改为"整体达成率 = Σ达成 ÷ Σ目标"，与图表达成率一致；KPI 下加"加权"小字说明。<br>**备选**：若坚持保留算术平均，则改名为"规则平均达成率"（明确它是规则维度的平均），绝不可继续叫"平均达成率"。 |
| **理由** | 老板关心的是"总共完成了多少"，加权才符合业务直觉；统一口径消除数字冲突。 |

## 三、非冗余但低效的项（建议一并优化）

### 项 7｜异常预警区不可点击 — 信息聚合无操作闭环

- **现状**：`:95-104` 聚合 3 类异常（未填报 / 风险 / 冲突），但每条仅为 `text` + `items` 纯文本列表，无任何跳转
- **影响**：用户看到"3 个目标预计月底不达标"却无法一键定位；看到"1 组目标重复"无法跳到冲突规则。看完仍需手动切 tab 逐个找，聚合价值被浪费
- **方案（性价比最高）**：条目可点击，按类型分流
  - `nodata` → 跳「达成填报」`mainTab='achv'`
  - `risk` → 滚动并高亮对应排行行
  - `conflict` → 跳「目标与返利」并带冲突筛选 `filterContract`/冲突过滤
- **理由**：改动集中在一个 `@click` + 跳转逻辑，却把"只读警告"升级为"可闭环处理"，是本次审计投入产出比最高的改进

### 项 8｜排行行元信息过载 — 6 项并列

- **现状**：`:125-134` 每行并列 6 项：目标 / 已填报 / 距目标 / 档位 X→Y / 达下一档多赚 ¥Z / 预计返利
- **影响**：单行信息密度高，扫读吃力；其中「档位 X → Y」与「达下一档多赚 ¥Z」是同一件事的两面
- **方案**：合并为「档位 X→Y，多赚 ¥Z」一项，行内元信息 6 → 5 项；其余保留（都是决策必需）

### 项 9｜risk 行双重警告 — 表述重复

- **现状**：`:135-140` rr-vs（"落后时间进度 X 个百分点"）与 `:141-144` rr-warn（"预计月底仅达成 Y%，还差 Z，建议补单"）在 risk 行**同时显示**，都表达"落后"
- **影响**：同一行两条警告，信息冗余、视觉压迫
- **方案**：risk 行合并为一条——保留 rr-warn 的"预计月底"预判信息，把 rr-vs 的时间进度差值并入其文案；非 risk 行维持 rr-vs 不动

### 项 10｜时间进度提示重复 — 全局说明 + 逐行重复

- **现状**：`:63` dt-hint（"虚线＝时间进度：条形超过虚线＝超前…"）与每行 rr-vs 的"超前/落后时间进度"重复解释
- **方案**：保留 dt-hint 作为首次说明，rr-vs 精简为"超前 / 落后 X pp"，去掉重复解释语

### 项 11｜KPI 说明文案暴露反直觉设计

- **现状**：`:54` "以上 KPI 始终统计全部品牌，不随下方图表的品牌筛选变化"
- **判定**：**不是冗余，是设计补偿文案**。它出现说明"筛选后 KPI 不动"是个容易被误解的行为
- **方案**：**保留**（全局 KPI 是仪表盘锚点，不应被筛选改掉），但**视觉弱化**为小字灰色，并合并进 KPI 区标题行，不要单独占一行

## 五、跨页重叠说明（仪表盘 vs 预报页「返利冲刺看板」）

| 维度 | 仪表盘 | 预报「返利冲刺看板」 |
|---|---|---|
| 达成口径 | **填报达成**（已录入实际） | **填报 + 本期预报贡献**（实时） |
| 时间基准 | 用户选定的统计月份 | 当前期次到货月 |
| 独有能力 | 全年柱状图、档位进度、异常聚合 | 到货机会次数、**均单追加建议**、推荐加单品 |
| 重叠 | 都展示"目标 vs 达成 vs 缺口" | 同左 |

- **判定**：**分工成立，不应合并**。仪表盘答"这个月整体完成得怎么样"，冲刺看板答"这单还要加多少"。副标题 `:16` 的跨页指引是对的
- **唯一风险**：两个都叫"达成"，口径不同（填报 vs 含预报），用户易混。**建议**在仪表盘副标题把口径写明："本页为**已填报**达成；含预报的实时达成见预报页冲刺看板"
