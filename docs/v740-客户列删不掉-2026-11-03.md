# v740 · 「易胜玲那一列为什么删不掉」

> 报障（2026-11-03）：「易胜玲那一列为什么删不掉呢？是因为她本期已报单吗？」

## 一、结论：跟「本期已报单」无关

删列 = 把**列名**写进 `forecast_hidden_units`（隐藏名册），名册查询走 `NOT EXISTS` 过滤，
与「这一期有没有报单」没有任何关系。唯一的前提是**这个名字在历史报单里出现过**
（后端 `INSERT ... WHERE EXISTS (SELECT 1 FROM forecast_submissions WHERE store_name=?)`
—— 只隐藏真实存在过的客户名，避免给自建的空列留下无用残留）。

她本期**确实报了单**：`forecast_submissions` 里今天 1 条 `role=distributor / status=pending`，
另有 3 条 `role=导入`（2026-10-14 ~ 11-03）。但这只是「她有数据」，不是「她不能删」。

## 二、真正的原因：删列这件事有两个静默

生产实测（改单态点客户列表头 ✕，不保存）：

| 步骤 | 结果 |
|---|---|
| 点 ✕ | 客户列 23 → 22，屏幕上确实少了一列 |
| 保存载荷 | `customers` 22 个（不含「易胜玲」）、`hidden_customers: ["易胜玲"]`、`rows` 187 行 |
| 不点保存就刷新 | 列**回来了**（`forecast_hidden_units` 仍是空的两条） |

所以功能本身是好的，让人「删不掉」的是两处**没有任何提示**：

1. **只读态没有删除入口。** 表头右键菜单里原本只有一句灰字
   「增删列 / 改字段请先点上方『改单』进入编辑态」—— 纯文字、点了没反应。
   用户视角：这一列明明在屏幕上，菜单里却没有删除项。
2. **改单态删完零反馈。** 列当场从屏幕消失，但落库要等 `save-matrix` 的
   `hidden_customers`。不点保存 → 刷新即回来，且**没有任何一句话提示过要保存**。

两处叠加，用户唯一的合理结论就是「删不掉」。

> 同族历史：v611 撤掉查看态「删除该行」时的理由写得很清楚 ——「查看态根本没有保存按钮
> ⇒ 行当场消失、刷新又回来，比改数更误导」。列这一侧当时没跟着改。

## 三、改法（v740）

1. 只读态右键菜单里的那句灰字 → **可点按钮**「去改单里删列 / 改字段」
   （受 `data/delete` 权限门禁；点击直接 `enterEdit()`，期次已关闭 / 无权限这些闸门
   仍只由 `enterEdit` 自己 toast 说明，不另起一套判据），下面补一句明确的操作说明。
2. `delCol` 删完立刻 toast：
   **「已删除客户列「X」· 点「保存」才会真正生效」**。

两处都只做「说清楚 + 给入口」，不改落库链路 —— `hidden_customers` 仍是删列的唯一载体，
删错可逆（工具行「新增客户」填同名，后端会反向 DELETE 隐藏记录）。

## 四、护栏

`tests/forecast-delcol-persistence.contract.mjs`（第 ㉖ 组，三组共 11 条）：

- 只读态必须有**可点**入口，且带 `data/delete` 门禁、位置在改单态结构块之后；
- 该入口只许转调 `enterEdit()`，不得自带 `periodLocked / canDo` 判据（两套闸门必然漂移）；
- `delCol` 的 toast 文案必须提到「保存」，且仍登记 `hiddenUnits`。

每条都带坏样本自证；另做了**真实突变**：撤掉按钮 / 给入口加 `periodLocked` / 删掉 toast
⇒ 报出 5 条，证明判据不是恒真。

## 五、验收（生产，CDP 真实鼠标事件）

- 线上 `data-build = v740`，入口闭包 274/274 全 200；
- 只读态右键「易胜玲」：菜单出现「去改单里删列 / 改字段」+ 说明；
- 点它 → 直接进改单、菜单关闭；
- 改单态点 ✕ → 列 23→22，toast 原文：`已删除客户列「易胜玲」· 点「保存」才会真正生效`；
- 验收脚本全程点「取消」退出，**未写库**：`forecast_hidden_units` 仍是
  `永诺旗舰店 / 沃尔玛` 两条，刷新后 23 列、易胜玲仍在。

## 六、以后要删列（三步，约十秒）

1. 点表格上方「改单」；
2. 横向滚到那一列，点表头名字右边的 **✕**（鼠标移上去会变红）；
3. 点上方「保存」—— 只到这一步列才真正消失（所有期次都不再显示）。

⚠️ 删掉后她这一列的数（含本期那条待审报单）在汇总表里也不再出现；要加回来，
用工具行「新增客户」填**同名**即可。

## 七、探针自身踩的坑（记一笔）

`.ctx-menu` 是 `position: fixed` ⇒ `element.offsetParent` **恒为 null**。
首版探针用 `offsetParent !== null` 判「菜单是否打开」，得到「菜单没开」的假结论，
差点把「入口不存在」当成另一个 bug 报出去。判可见性一律用 `getClientRects().length > 0`。
