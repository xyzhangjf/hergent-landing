## 二、根因：写侧的占位数据是「承重」的，漏的是读侧

`save_matrix`（Web 端「保存汇总表」）在**为本期没有数量的列**也会建一条报单，
明细是一行 `product_id=0 / '__列占位__' / 数量 0`。源码原注释：

```python
# 客户列本周期无正数量商品：仍保留占位记录，使客户列持久化、刷新不丢
# （否则 save 后再 loadEditGrid 会因 summary 无该客户 sources 导致整列消失）
```

🔴 **所以这些行不能删** —— 删了那一列在 Web 汇总表刷新后会**整列消失**。
**真正的漏是读侧没把它剔掉**：您在 Web 端每保存一次汇总表，就有十几条空单落进**您账号**下，
小程序「我的提交」原样列出，还带「撤回」按钮。

**生产实测完全吻合这个机制**：83 单里 **71 单是空单**，全部 `user_id=2`（您的账号）、
全部 `role='导入'`、全部挂在真实期次上，集中在 4 个日期 —— 正是「每期保存一次、
每次为每个空列建一单」。

| 日期 | 空占位单数 |
|---|---|
| 2026-10-02 | 16 |
| 2026-09-28 | 18 |
| 2026-09-22 | 18 |
| 2026-09-20 | 19 |

## 四、修法（一处，SQL 内）

`erp_db.forecast_submission_list` 增加一个「这单真有内容吗」的判据：

```sql
AND EXISTS (SELECT 1 FROM forecast_submission_items si
            WHERE si.submission_id = forecast_submissions.id
            AND si.product_name != '__列占位__'
            AND COALESCE(si.quantity, 0) > 0)
```

三条设计取舍：

| # | 取舍 | 为什么 |
|---|---|---|
| 1 | 🔴 **过滤写在 SQL 的 `WHERE` 里**，不是 Python 端后过滤 | 后过滤会被 `LIMIT` 先截走 ⇒ 真单在第 51 条之后 ⇒ **列表直接空掉** |
| 2 | 判据取「**有量**」而不是「有行」 | `product_name != '__列占位__'` 只证明有明细行、不证明有量；而数量侧唯一实现 `normalize_qty` 已硬判「负数非法、0 = 未填」⇒ **真实明细必 `quantity > 0`** ⇒ 精确不误伤 |
| 3 | 只改这一处 | 全仓核实：**唯一调用点是小程序 `/my`**（Web 端零调用）⇒ 不动 Web 汇总表 |

## 八、附带记录一个工具坑

写护栏时，`Read` 把 `os.path.abspath` **显示**成 `os.path.abspath`，
而磁盘上的**真实字节是 `os.abspath`**（少一段 `path.`），
报 `AttributeError: module 'os' has no attribute 'abspath'`，查了三轮才定位。

🔴 **纪律：改完代码必须 `grep` / `od` 复核真实字节，不能只信 `Read` 的显示。**
（`sys.path.insert(...)` 报的是**内层**表达式失败，盯着外层看会一直绕。）
