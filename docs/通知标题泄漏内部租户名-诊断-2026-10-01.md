# 诊断：通知里出现内部租户名「测试企业A」（2026-10-01）

> 用户报告原话：「我的账号看到这条**测试企业**的通知，这是不应该发生的。」
> 附带通知原文：标题 `10月01日 经营卡简报 · 测试企业A`，正文
> `📦 货损：近30天无已审批报损，但 54 个在库批次未录到期日，临期风险查不出来 👥 工资：本月提成合计 ¥0（11人），关联销售额 ¥0 💰 返利：当前无未结返利合同`

## 一、结论（先看这三行）

| 判定 | 内容 |
|---|---|
| ✅ **不是**跨租户泄漏 | 写端落库正确、读端收口正确，均有实测反证（见 §三） |
| 🔴 **是**「内部租户名泄漏到用户可见文案」 | 通知标题把租户名拼了进去，而该租户名是注册时的**种子名「测试企业A」**，从未改过 |
| ⚠️ **另有**一颗多租户地雷 | 渠道推送的「全局 webhook 兜底」在多租户下会把**任意租户**的简报推到同一个群 |

## 四、真正的问题（按严重度）

### 🔴 D1 · 用户可见的通知标题里拼了**内部租户名**

- **位置**：`server/scheduler.py::_push_copilot_brief_current`
  ```python
  suffix = f" · {tenant_label}" if tenant_label else ""
  title = f"{today} 经营卡简报{suffix}"
  ```
  `tenant_label` 来自主库 `tenants.name`（`_push_copilot_cards_brief` 在**主库上下文**一次性取好）。
- **为什么是缺陷**：租户名是**内部标识**，不该出现在客户看到的通知里。本例它还是**种子默认名**，所以看起来像系统出故障。
- **连带缺陷（比标题本身更隐蔽）**：事件键由标题现算
  （`message_send` 无 `event_key` 参数 ⇒ `ekey = norm_event_key(title)`），
  实测存下来的 `event_key` 就是 `经营卡简报 · 测试企业A`。
  而前端「按类静音 / 频率 / 暂停」**全挂在这个键上** ⇒
  **租户一旦改名，用户此前设的全部静音规则会静默失效**（同一类通知换个名字继续进来）。
- **应该怎样**：站内通知标题**永不带租户名**；只有走**多方共享的全局渠道**（会混多个租户的简报）才需要区分，而那时应标识**目标渠道**，而不是把租户名硬编进标题、再由标题反推事件键。

### 🔴 D2 · 承载真实生产经营数据的租户，名字还是注册时的种子名

主库 `tenants` 全量只有两条：

```text
id=1   name='测试企业A'          subdomain='测试企业a'
id=10  name='张记乳品（演示）'    subdomain='demo'
```

而 tenant_1 里是**真实业务**：11 名员工（刘小顶 / 刘善涛 / 郝洋 / 唐成 / 仲嫚嫚 / 程欢欢…）、
21,364 条通知、简报正文「54 个在库批次未录到期日」与既有记录逐字吻合。
tenant_10（演示）只有 1 人。

⇒ 「测试企业A」这个名字会持续出现在：站内通知标题、企业微信推送、以及任何引用 `tenants.name` 的地方。

### ⚠️ D3 · 渠道兜底是一颗多租户地雷（今天没爆，但已就位）

`_push_tenant_channels` 的既定逻辑：

> ① 租户配过任一渠道 → **只走租户渠道，绝不回落全局（防串台）**；
> ② 租户完全没配渠道 → **回落全局 env webhook**（注释写：「保持既有单租户行为不回退」）。

而全局 webhook 的口径是**「一个部署一个企微群」**（`notify/wecom_notify.py::get_wecom_webhook` 自己写明）。

⇒ 今天它没爆，只是因为**全局 webhook 恰好没配**（主库 `system_config.wecom_webhook_url` = 空、环境变量无 `WECOM_WEBHOOK_URL`）。
**一旦为了收某个租户的简报而配上它，所有「没配渠道的租户」的简报都会进同一个群**——
包括演示租户，以及**未来第二家真实客户**。

🔴 对照证据：同仓 `server.py:5375` 对「今日经营要务」这条推送**明确写了保护**——

> `# 演示租户不推送（避免演示数据推到老板企微）`

**同一份保护在简报这条路径上完全不存在。**

## 五、处置选项（等用户拍板，未动任何生产代码/数据）

| # | 动作 | 效果 | 代价 / 风险 |
|---|---|---|---|
| **A** | 改 `_push_copilot_brief_current`：**站内标题不再拼租户名**；事件键固定为 `经营卡简报` | 根除「用户看到内部租户名」；静音键不再随租户改名失效 | 需发后端；**「全局渠道兜底」场景会失去区分度 ⇒ 必须与 D 同批做** |
| **B** | 把租户 1 从 `测试企业A` 改成**真实企业名** | 「测试企业」字样从所有引用 `tenants.name` 的地方消失 | 需用户给名字；改名后**旧的静音键会变**（与 A 同批即可规避） |
| **C** | 关掉租户1 的企业微信推送（`hermes_tenants.remove_channel(1,"wecom")`） | 个人企微不再收到该租户简报 | 若他确实想收，就不要做 |
| **D** | 给简报路径补上「演示/测试租户不推送」+「多租户下禁止回落全局 webhook（fail-closed）」 | 拆掉 D3 的地雷 | 需发后端；会让「没配渠道的租户」彻底不推外部渠道（符合多租户正确性） |

**推荐：A + B + D**（一次发版做完，互相咬合）；**C 由用户决定**。
