## 二、审查问题清单

### 高（1 项）

#### H1 · 舟谱导入全员账号写死默认口令 `hergent2026`
- **位置**：`hergent-erp/server/import_zhoupu.py:428`
- **问题描述**：账号创建分支将所有通过导入开通的账号统一用 `pw = core._hpw('hergent2026')` 哈希。即凡经舟谱导入开通的账号，口令恒为公开字符串 `hergent2026`，且代码中明文留存。
- **可能影响**：一旦该默认口令外泄（源码入库即可能），所有经导入开通的账号可被轻易登录；多租户场景下跨租户横向风险显著。
- **最小修复建议**：① 不再写死口令，改为生成随机初始口令并强制首登改密（与既有 `password_changed=0` 机制对齐）；② 至少把默认口令抽成环境变量 / 配置项，避免明文入库；③ 已开通账号择期批量重置。
- **状态**：前轮（2026-09-24）已报为 HIGH，本轮确认**仍未修复**。

### 中（3 项）

#### M1 · 副驾代理层硬编码默认网关密钥
- **位置**：`hergent-erp/server/routers/copilot_proxy.py:36`
  `HERMES_KEY = os.environ.get("HERMES_GATEWAY_KEY", "hergent-prod-gateway-key-2026")`
- **问题描述**：网关密钥的**默认值**以明文硬编码在源码中，且默认值本身带 `prod` 字样。生产若未显式设置 `HERMES_GATEWAY_KEY` 环境变量，将用该硬编码值向内部 Hermes 网关发起 Bearer 鉴权。
- **可能影响**：源码入库使密钥暴露；若生产漏配环境变量，等于用公开密钥通信，可被冒用代理通道。
- **最小修复建议**：默认值改为空串，未配置时**拒绝启动 / 拒绝代理**（fail-closed），而非用硬编码密钥兜底；密钥仅由环境变量或密钥管理注入。

#### M2 · Hermes API Key 明文落 localStorage
- **位置**：`hergent-cn-v2/src/pages/Settings.vue:443`
  `localStorage.setItem('hergent_v2_key', key.value.trim())`
- **问题描述**：用户在「设置 → Hermes API Server Key」填写的密钥以明文存入浏览器 localStorage，且无过期/隔离。
- **可能影响**：任何同源 XSS 或本地取证即可读取该密钥；多租户共享浏览器设备时互相可见。
- **最小修复建议**：① 密钥仅在内存中持有，提交后端后清掉本地副本；② 若必须缓存，使用 `sessionStorage` 且加密，并避免在 localStorage 持久化；③ 评估改为后端代管密钥、前端不下发明文。
- **状态**：前轮（2026-09-24）已报为「中」，本轮确认**仍未修复**。

#### M3 · 跨租户共享「红线」过滤为脆弱子串匹配
- **位置**：`hergent-erp/server/routers/experience_loop.py:35-46`（`RED_LINE_TOKENS` + `is_caliber_safe`）
- **问题描述**：跨租户 `industry_caliber` 表的"红线"防护仅靠 `all(tok not in k for tok in RED_LINE_TOKENS)` 子串包含判断。一方面**过度拦截**（如参数名含 `rebate/salary/cost/margin` 等即被拒，可能误伤无害参数）；另一方面**可被绕过**——一个不含任一 token 但实为商业秘密的参数（如 `vip_rebate_rate` 不含 `rebate`？其实含 `rebate` 会被拦；但 `gross_profit_share`、`settlement_split` 等未被覆盖词命中则可能入库）。
- **可能影响**：作为模块明确声明的"红线"安全控制，其可靠性取决于参数命名习惯，无法保证不泄露金额/返利等敏感口径的聚合值。
- **最小修复建议**：将"红线"由黑名单子串改为**白名单 / 显式分类**——只有经产品经理标注为"可共享的脱敏口径"的参数才允许进入 `industry_caliber`；或在落表前对 `recommended_value` 做类型/量级二次校验。

### 低（8 项）

#### L1 · 三元 + `or` 运算符优先级导致 `source_ref` 在 `advice_id=0` 时被忽略
- **位置**：`hergent-erp/server/routers/experience_loop.py:144`
  `ref = source_ref or f"advice:{advice_id}" if advice_id else (f"manual:{param_key}")`
- **问题描述**：Python 解析为 `(source_ref or f"advice:{advice_id}") if advice_id else f"manual:{param_key}"`。当 `advice_id` 为 0（手动覆写）时，无论调用方是否传入 `source_ref`，`ref` 都被强制改写为 `f"manual:{param_key}"`，丢失调用方指定的 `source_ref`（如带 scenario 的 `manual:{param_key}:{scenario}`）。
- **可能影响**：手动覆写溯源信息精度下降（缺 scenario 维度），但下游 `if not ref:` 守卫不会触发，功能不报错。
- **最小修复建议**：改写为显式分支：`if advice_id: ref = source_ref or f"advice:{advice_id}" else: ref = source_ref or f"manual:{param_key}"`。

#### L2 · 恒真守卫（死代码）
- **位置**：`hergent-erp/server/routers/experience_loop.py:254`
  `if not ref:` —— 上方 `ref` 已由 f-string 构造，必为非空字符串，该分支恒不进入。
- **可能影响**：无功能影响，仅代码可读性噪音，易误导后续维护者以为 `ref` 可能为空。
- **最小修复建议**：删除该行及无用分支（或改为对原始 `source_ref` 入参的校验）。

#### L3 · `_module_of_param` 未命中时默认归为 `loss`
- **位置**：`hergent-erp/server/routers/experience_loop.py:270-278`（末尾 `return "loss"`）
- **问题描述**：参数名未匹配 loss/payroll/forecast 任一族时，统一落入 `loss` 模块，可能产生语义错归（自动提案挂在错误配方模块下）。
- **可能影响**：跨模块口径聚合轻微失准，不影响主流程。
- **最小修复建议**：默认返回 `None` 并在落 `recipe_proposals` 时按"未知模块"单独处理或拒绝。

#### L4 · 临期标签/文案分支冗余
- **位置**：`hergent-cn-v2/src/pages/Workbench.vue:311-324`（`expiryTag` / `expiryText`）
- **问题描述**：`expiryTag` 中 `days<=0` 与 `days<=7` 均返回 `'bad'`；`expiryText` 中 `days<=7` 与 `days<=14` 两段输出完全一致（`X天到期`），属冗余分支。
- **可能影响**：无功能错误，仅可维护性。
- **最小修复建议**：合并重复分支，或明确区分"已过期/临期/预警"三档文案。

#### L5 · Hermes 返回空 `choices` 时解析会抛 IndexError（虽已被外层兜底）
- **位置**：`hergent-erp/server/routers/ai_judgement.py:48`
  `data.get("choices", [{}])[0].get("message", {})...`
- **问题描述**：若上游返回 `choices: []`（非缺失），`[{}]` 默认值不生效，`[][0]` 触发 `IndexError`，被 line 51 的 `except Exception` 捕获后 soft_fail。
- **可能影响**：上游异常返回时诊断静默失败（已降级，不报错），但会误报 `soft_fail=True`。
- **最小修复建议**：改为 `choices = data.get("choices") or [{}]; first = choices[0] if choices else {}`。

#### L6 · 大单位换算门禁的 `not ... > 0` 表达易误读
- **位置**：`hergent-erp/server/routers/product_targets.py:365`
  `if not float(arc.get("large_ratio") or 0) > 0:`
- **问题描述**：依赖 `not` 优先级低于 `>`，实测逻辑正确（无大单位换算则 422），但阅读极易误判为"有换算反而拒"。
- **可能影响**：仅可读性风险，无运行错误。
- **最小修复建议**：改写为 `if not (float(arc.get("large_ratio") or 0) > 0):` 或 `if float(arc.get("large_ratio") or 0) <= 0:`。

#### L7 · 键盘提示中的方向符号（可选整改）
- **位置**：`hergent-cn-v2/src/components/CommandPalette.vue:37` `<kbd>↑↓</kbd>`；`hergent-cn-v2/src/components/CopilotDrawer.vue:251` `<kbd>↑↓</kbd> · <kbd>↵</kbd> · <kbd>Esc</kbd>`
- **问题描述**：站点 UI 规范（site-wide）要求统一 Lucide `<Icon>` 线性 SVG、避免装饰性符号图标；`<kbd>` 内的 `↑↓`/`↵` 为键盘键位符号而非图标，属可接受范围，但与"一律 Icon"口径略有出入。
- **可能影响**：无功能影响；一致性观感。
- **最小修复建议**：若追求彻底统一，可将 `<kbd>↑↓</kbd>` 替换为文字"上下键"或 `<Icon name="chevron-up"/>`+`<Icon name="chevron-down"/>` 组合；否则维持现状并记入规范例外。

#### L8 · 新建目标页"无月份"提示复用了错误态样式
- **位置**：`hergent-cn-v2/src/pages/ProductTarget.vue:408`
  `if (!m) err.value = '提示：不选月份时列表不计算「已达成 / 均单」…'`
- **问题描述**：将"中性使用提示"写入 `err`（错误态，渲染为琥珀色告警 `pt-err`），用户可能误以为出错。
- **可能影响**：轻微误导，无功能错误。
- **最小修复建议**：改用独立的 `hint` 提示态字段渲染，与 `err` 错误态区分。
