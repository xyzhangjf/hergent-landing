## 二、问题清单（按严重程度）

### 🔴 高（1）

#### H1 · 舟谱导入为所有账号写死默认口令
- **文件 / 行号**：`hergent-erp/server/import_zhoupu.py:428`
- **代码**：
  ```python
  username = pinyin or name
  pw = core._hpw('hergent2026')          # ← 写死默认口令
  ...
  conn.execute("INSERT OR IGNORE INTO users (username,password_hash,display_name,role,phone) VALUES (?,?,?,?,?)",
               (username, pw, name, user_role, phone))
  ```
- **问题描述**：舟谱「员工列表」导入时，凡「账户状态=正常 + 是否开通账号=是」的员工，均用同一写死口令 `hergent2026` 落库。该口令明文存于源码，且所有导入账号共享。
- **可能造成的影响**：账号口令全局一致且可推测；一旦该字符串在仓库/镜像/历史提交中泄露（本仓已被标记含明文凭据），任一导入账号可被直接登录；横向移动风险高。系统虽有「首登强制改密」机制，但导入路径绕过了随机初始口令。
- **最小修复建议**：改为随机初始口令（如 `secrets.token_hex(8)`）或读环境变量 `HERGENT_DEFAULT_IMPORT_PASS`；落库同时置 `password_changed=0` 强制首登改密。彻底移除源码中的字面量 `hergent2026`。

### 🟠 中（2）

#### M1 · 副驾代理层硬编码默认网关密钥
- **文件 / 行号**：`hergent-erp/server/routers/copilot_proxy.py:36`
- **代码**：`HERMES_KEY = os.environ.get("HERMES_GATEWAY_KEY", "hergent-prod-gateway-key-2026")`
- **问题描述**：生产兜底密钥硬编码在源码中，作为 `HERMES_GATEWAY_KEY` 未设置时的默认值。
- **可能造成的影响**：环境变量缺失即回退到仓库内明文密钥，密钥轮换必须改代码；密钥随镜像/提交扩散。
- **最小修复建议**：生产环境缺失密钥时**失败关闭**（raise / 禁用代理）而非回退明文；或统一从密钥管理读取，代码中只留 `os.environ["HERMES_GATEWAY_KEY"]`。

#### M2 · Hermes API Key 明文落浏览器 localStorage
- **文件 / 行号**：`hergent-cn-v2/src/pages/Settings.vue:443`
- **代码**：`localStorage.setItem('hermes_v2_key', key.value.trim())`
- **问题描述**：用户在「设置」页填写的 Hermes 网关 Key 以明文持久化到 `localStorage`。
- **可能造成的影响**：同源任意脚本（含潜在 XSS）/ 共用电脑 / 浏览器同步均可读取该密钥，等于长期暴露 AI 网关凭证。
- **最小修复建议**：仅存内存（Pinia/ref）或 `sessionStorage` 并加短 TTL；如需持久化则经 `crypto.subtle` 用用户口令派生密钥加密后再存；或改为后端代管、前端不持有明文。

### 🟡 低（4）

#### L1 · 快照保存时 JSON.parse 未包裹 try
- **文件 / 行号**：`hergent-cn-v2/src/pages/Forecast.vue:7773`
- **代码**：`const list = JSON.parse(localStorage.getItem(SNAP_KEY()) || '[]')` （位于 `saveSnap()`，函数内**无 try/catch**；同文件 `loadSnaps()` 7770 已正确包裹）
- **问题描述**：`saveSnap()` 读取既有快照时直接 `JSON.parse`，未做异常保护。
- **可能造成的影响**：若 `localStorage` 中快照 JSON 因某次异常写入损坏，`saveSnap` 抛未捕获异常，用户点击「保存快照」无反馈、快照未写入。
- **最小修复建议**：改为 `let list = []; try { list = JSON.parse(...) } catch { list = [] }`，与 7770 的 `loadSnaps` 保持一致。

#### L2 · 双重否定表达式易误读（当前逻辑正确但脆弱）
- **文件 / 行号**：`hergent-erp/server/routers/product_targets.py:492`
- **代码**：`if not float(arc.get("large_ratio") or 0) > 0:`
- **问题描述**：依赖 Python 运算符优先级（`>` 高于 `not`），实际等价于 `if not (large_ratio > 0)`（即 `large_ratio <= 0` 时触发），**当前结果正确**。但「`not ... > 0`」写法极易被后续维护者误判为「`not` 先结合」而「修正」成错误逻辑。
- **最小修复建议**：改写为显式 `if float(arc.get("large_ratio") or 0) <= 0:`，消除歧义。

#### L3 · 后端运行时目录 `var/` 未加 .gitignore
- **文件 / 行号**：`hergent-erp/server/var/`（untracked，无 `.gitignore` 覆盖）
- **问题描述**：`var/holidays/2026.json` 等运行时数据目录处于未跟踪状态且未被忽略；`git status` 已将其列为 `?? var/`。
- **可能造成的影响**：一旦误执行 `git add .`，运行时/缓存数据会被提交进仓库，造成噪音且可能携带环境相关状态。
- **最小修复建议**：在 `server/.gitignore`（或仓库根）追加 `var/`（若该 json 是需版本化的种子数据则改为显式提交指定文件、其余忽略）。

#### L4 · 用 os.popen 拼接 shell 命令（值非用户输入，安全但属风格加固）
- **文件 / 行号**：`hergent-erp/server/server.py:4941`
- **代码**：`mem_mb = round(os.popen('ps -o rss= -p ' + str(os.getpid())).read().strip()) / 1024`
- **问题描述**：通过字符串拼接调用 `os.popen` 启动 shell。所拼接的 `os.getpid()` 是整数、非用户输入，**无注入风险**；但 `os.popen` 已不推荐，且 shell 字符串拼接是不良范式。
- **最小修复建议**：改为 `subprocess.check_output(['ps','-o','rss=','-p',str(os.getpid())], text=True)` 或读取 `/proc/self/statm`，避免 shell 解释。
