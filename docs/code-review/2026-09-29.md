## 三、本轮新增问题

### 低-新1 · 前端 fire-and-forget 调用静默吞错（4 处新实例）

- **问题描述**：多处「点火即忘」的异步调用用 `.catch(() => {})` 吞掉异常，失败时无任何日志 / 提示，相关可选数据静默缺失。
- **真实代码行（均在 09-28 02:00 后改动文件中）**：
  - `hergent-cn-v2/src/pages/Rebate.vue:2498` — `await loadClaims().catch(() => {})`（位于 `finally` 块内，申领状态加载失败被静默丢弃，合同卡片徽标不更新）。
  - `hergent-cn-v2/src/pages/Forecast.vue:4201` — `loadPrevUnits().catch(() => {})`（上期「按客户」数量加载失败被静默丢弃，影响候选数量与软警告黄角标）。
  - `hergent-cn-v2/src/pages/Forecast.vue:7451` — `genSuggestions().catch(() => {})`（补货建议计算失败被静默丢弃，用户仍看到「已算出建议量」成功提示，但建议列为空）。
  - `hergent-cn-v2/src/components/CopilotDrawer.vue:1833` — `}).catch(() => {})`（副驾某异步链失败被静默丢弃）。
- **可能影响**：非关键路径，但用户侧表现为「点了没反应 / 数据缺一块却无报错」，排障困难。
- **最小修复**：对确需忽略的（导航类）保留；对「加载可选业务数据」类，改为 `.catch(err => console.warn('[xxx] 加载失败', err))`，至少留日志。无需改功能逻辑。

### 低-新2 · 后端错误处理用 `print` 落 stdout 而非日志系统（可观测性缺口）

- **问题描述**：`except` 分支用 `print(...)` 把异常打到进程 stdout，未走统一日志（`logging` / 结构化日志）。生产环境 stdout 通常被接管 / 不持久化，错误难追溯。
- **真实代码行（09-28 02:00 后改动文件内）**：
  - `hergent-erp/server/routers/forecast.py:767 / 797 / 843 / 1019 / 1111 / 1123 / 1235 / 1295 / 1329 / 1453 / 1607`
  - `hergent-erp/server/routers/import_router.py:583 / 892`
  - `hergent-erp/server/routers/forecast_submissions.py:718 / 1215`
- **可能影响**：错误未进日志系统，线上排查时「零报错但功能不对」类问题无法回溯；属代码质量 / 可观测性，不影响逻辑正确性。
- **最小修复**：将这些 `print(f"[...] ...error: {e}")` 改为 `logger.warning(...)`（复用模块已有 logger，或新增 `import logging; logger = logging.getLogger(__name__)`）。属批量替换，风险低。
