# 工具条弹层「遮挡带」修复（v704）

> 起因：v703 交付时顺口提到的瑕疵「导出下拉展开时，同行『到货周期』按钮压在面板上」。
> 修完发现它不只是难看——**点击被静默劫走**，属于功能性缺陷。

## 一、问题真身（先取证，不猜 CSS）

1600×1000 视口，期次 37，「导出」下拉展开：

| 对象 | 几何 | z-index |
|---|---|---|
| `.tb-pop-panel`（导出面板） | `top=156 left=899 242×356` | **1101** |
| `.tb-pop`（导出触发按钮） | `(1041,118) 100×32` | 1120 |
| `.tb-pop`（品牌） | `(812,221) 100×32` | 1120 |
| `.tb-pop`（到货周期） | `(920,221) 126×32` | **1120** |
| `.tb-pop`（复制报单） | `(1054,221) 126×32` | 1120 |

面板从导出按钮下方展开、向下 356px，正好罩住**表体工具行**那三个按钮。
而触发按钮 1120 > 面板 1101 ⇒ 那三个按钮**浮在面板之上**。

`elementFromPoint` 在面板矩形内取 5 个纵向采样点：

```
y=168 IN-PANEL ✓  DIV.tb-pop-panel
y=251 HIJACK  ✗  BUTTON.btn.btn-sm.btn-ghost | 到货周期     ← 就是这一条
y=334 IN-PANEL ✓  DIV.tb-pop-panel
y=417 IN-PANEL ✓  BUTTON.grp-btn
y=500 IN-PANEL ✓  DIV.tb-pop-panel
```

⇒ 不只是视觉遮挡：**点面板那个位置，打开的是到货周期筛选**。

## 二、为什么不能靠"抬面板"修

页面内浮层天花板 **1121** 已被天气面板 `.wx-pop` 占用，且这是四处注释共同契约的基准：

- `Shell.vue:1781`（侧栏弹窗不得低于它）
- `styles/forecast-modal.css:18`（页面级模态 1125/1130 的分档依据）
- `WeatherWidget.vue:557`（「1121 即为此定：高于页面内所有下拉浮层」）
- `Forecast.vue` 内同名注释

抬到 1121 ⇒ 与天气面板同档、按 DOM 顺序互撞。

## 三、正解：把触发按钮降回它真正的需求档

`--z-page-bar:1120` 用在 `.tb-pop` 上的理由，注释里写得很清楚：

> z 高于 `.pop-overlay`(1100)：弹层开着时仍可直接点触发按钮做互斥切换

**1101 就满足这个需求。** 那多出来的 19 档没有任何契约要求，是本轮遮挡的全部成因。

新增两个令牌（`variables.css`）：

```
--z-page-trigger:1101   /* 触发按钮容器：> 遮罩 1100，< 面板本体 */
--z-page-pop:1116       /* 弹层本体：压过按钮与列菜单，仍低于天气 1121 / 外壳 1122 / 模态 1125 */
```

修复后的全序：

```
遮罩 1100  <  触发按钮 1101  <  面板 1116  <  天气 1121  <  外壳浮层 1122  <  模态 1125  <  toast 1200
```

> `--z-page-menu:1101` 与 `--z-page-trigger:1101` 同值但语义独立 —— 沿用项目既有做法
> （`--z-mask` 与 `--z-toast` 同为 1200，注释里写明「同值，语义独立」）。

## 四、连带修掉的一个新风险（同一个改动引出来的）

`positionTbPop()` 原先把尺寸**写死**：`w=240`、`estH=320`；实测面板是 242×356。

面板层级一旦高于按钮，"翻到按钮上方"这条分支就变危险：

```js
if (top + estH > window.innerHeight - 8) top = Math.max(8, r.top - estH - 6)
```

估小 36px 会让面板底部**侵入按钮约 30px** ⇒ 面板盖住自己的触发器：看不见"正开着"，也点不掉它关闭
（只剩点遮罩一条路）。三处一起改：

1. **宽高实测**（调用点在 `nextTick`，元素此时已挂载；量不到才退回保守估值）。
2. **方向改成"选空间更大的一侧"**，不再"下方放不下就硬翻上去"。
3. **装不下就把高度钳到该侧空间**（`popStyle.maxHeight`）。空串时 Vue 移除该属性 ⇒
   `.brand-pop` 的 `62vh`、`.batch-pop` 的 `min(70vh,440px)` 等既有 CSS 照旧生效，互不打架。

另外给 `.tb-pop-panel` 补兜底：`max-height:calc(100vh - 16px); overflow-y:auto`
—— 矮视口下宁可内部滚动，也不许溢出视口到点不到（1366×420 实测面板高 256px、内部可滚）。

## 六、探针踩到的两个坑（都会伪装成功能 bug）

1. **工具栏弹层不监听 ESC**（ESC 是 `Modal.vue` 的事）。拿 `keyboard.press('Escape')` 当"关闭"会**静默失效**，
   下一轮 `click()` 反而把它 toggle 掉 ⇒ 查不到面板 ⇒ 报 `{"err":"missing"}` 的假 FAIL。
   **关闭态要判触发按钮的 `.on` 类。**
2. `.brand-pop` / `.copy-pop` 也带 `.tb-pop-panel` 类 ⇒ `querySelectorAll('.tb-pop-panel').length` 数不准。
   判"导出面板还在不在"要**按内容识别**（`:has-text("导出全部")`）。

顺带把 `tests/perf/v703/copy.mjs` 里 `build === 'v703'` 的写死断言改成 `>= v703`：
每版都冒一条与功能无关的假 FAIL，只会训练人忽略红字。
