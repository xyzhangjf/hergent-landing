# v735 · 强调文字色与导航层级（A+B）

**起因**（用户原话，两句都成立）：
1. 「我怎么感觉侧边栏的字体在浅色模式下不够黑，深色模式下不够白」
2. 「请先全站排查一下还有没有类似的问题」

上一轮只做了排查、没动代码。本轮 A+B 一起落地。

---

## 一、两个独立问题，不是同一个

### A. 导航借了"次要文字"的令牌（语义错位）

`.sb-item` 是**一级导航**，全站被点最多次的入口，却写成 `color:var(--t2)` ——
那是 v717 合并两级灰时给"能被读的**次要文字**"定的档。导航不在这个类别里。

实测（1440×900，v734 线上）：

| | 改前 | 同屏 h1 | 落差 |
|---|---|---|---|
| 浅色 `.sb-item` | `#6a6a70` on `#fcfcfd` = **5.25** | 16.83 | **3.2 倍** |
| 深色 `.sb-item` | `#b4b4b8` on `#202022` = 7.83 | 15.63 | 2.0 倍 |

浅色的 5.25 只比 WCAG AA 的 4.5 高 0.75，而侧栏是 **13px 中文** ——
中文笔画密度远高于拉丁字母，这个对比度下笔画会"发虚"，用户看到的"不够黑"就是这个。
深色的 7.83 数值不低，但 `#b4b4b8` **是灰不是白**，挨着近白标题就显脏，所以"不够白"。

### B. 更强的一条：层级是倒的

排查发现全站 **247 处** `color:var(--p-dark)`。它在白底 5.36、在 `--p-bg` 上只有 **4.96**：

| | 对比度 |
|---|---|
| 侧栏**未选中** | 5.25 |
| 当前**已选中** | **4.96** |

**选中的比没选中的还淡。** 这不是"某处灰"，是整屏找不到"深"的锚点 ——
正文 `--t1` 是 16.8，然后直接掉到 5.2，中间 7~15 那一整段是空的。

## 二、改了什么

### A · 侧栏 / 弹窗二级项 / 手机底栏

| 位置 | 改前 | 改后 |
|---|---|---|
| `.sb-item` | `--t2` | `--t1` |
| `.sb-item:hover` 底色 | `--bg`（纯白） | `--bg2` |
| `.sb-item.router-link-active` | `--p-dark` | `--p-ink` |
| `.sb-pop-item` | `--t2` | `--t1` |
| `.sb-pop-item:hover` 底色 | `--bg` | `--bg2` |
| `.sb-pop-item.cur` / `.sb-pop-new` | `--p-dark` | `--p-ink` |
| `.mnav-item`（手机底栏） | `--t3` | `--t1` |
| `.mnav-item.router-link-active` | `--p-dark` | `--p-ink` |

**两处必须同批上线，否则更差**：原来 hover 的**唯一**可见变化就是"字从灰变黑"
（`--bg` 纯白与侧栏底 `#fcfcfd` 只差 3/255，本来看不见）。默认字色一改黑，
hover 就毫无反应 ⇒ 底色必须同时换 `--bg2`。

🔴 **手机底栏原来写 `--t3`，而 `--t3` 与 `--t2` 同值**（v717 两级灰合并的结果）
⇒ "把 `--t3` 改成 `--t2`"是**零变化**，截图和肉眼都看不出。必须直接压到 `--t1`。

### B · 强调文字色收成一个名字

- `--p-ink` 浅色 `#0e7490` → **`#0a5a6d`**（深色 `#22d3ee` 不动，本就 7.65）
- **247 处** `color:var(--p-dark)` → `color:var(--p-ink)`
- **`--p-deep` 并入 `--p-ink` 并删除** —— 它那 10 处用法**全部**是 `color` on `--p-bg`，
  与 `--p-ink` 语义完全重合，深色下两者本来就同值 `#22d3ee`。又一个"同值两个名字"。

**为什么实心底 `--p-solid` 不动**：用户选的是"只分文字侧"。
`--p-dark` 保留 57 处**图形**用途（border-color 50 / accent-color 7 / SVG 描边），
门槛是 UI 组件 3:1，5.36 够用；加深边框只会让它显得粗重。

### 顺带修掉一个被本轮放大的既有缺陷

`.mnav-item` 是 `<router-link>`（渲染成 `<a>`），而本仓没有 `a{text-decoration:none}` 全局重置。
原来文字是灰的，下划线跟着淡到看不见；压到 `--t1` 后下划线同步变黑，**深色下尤其刺眼**。
⇒ 补 `text-decoration:none`。不补就是用一次修对比度换来一次视觉退步。

## 三、实测（线上 v735，1440×900）

| | 改前 | 改后 |
|---|---|---|
| 侧栏未选中·浅 | 5.25 | **16.44** |
| 侧栏未选中·深 | 7.83 | **14.85** |
| 当前选中·浅 | 5.07 | **7.20** |
| 当前选中·深 | 5.70 | **7.65** |

**层级修好了**：未选中 16.44 > 已选中 7.20，符合"未选中是主体、选中靠青底区分"的正常秩序。

全站可点文字（12 页 × 2 主题，按 AAA 7:1 判）：

| | 组数 | 最低 | 全部 ≥7 |
|---|---|---|---|
| 浅色 `#0a5a6d` | 86 | **7.15** | ✅ |
| 深色 `#22d3ee` | 86 | **7.65** | ✅ |

`#0e7490` 作为**文字**的剩余量：**0 组**（261 处全部迁移）。

## 四、护栏（`scripts/check-tokens.mjs`）

新增 `checkAccentText()`，三条：

1. **`color` 不许用 `--p-dark`** —— 只拦文字位，放行 border / accent / outline 等图形位
2. **导航项不许用 `--t2` / `--t3`** —— 指名检查 `.sb-item` / `.sb-pop-item` / `.mnav-item`
3. **`--p-ink` 对 `--p-bg` ≥ 7:1**（浅深两套都算，取最亮基底 `--bg` 作保守下界）
   + `--p-deep` 不许复活

**四态阳性对照**（注入坏样本 → 必须 exit 1 且命中对应报错 → 还原后 exit 0）：

| 态 | 注入 | 结果 |
|---|---|---|
| ① | `color:var(--p-dark)` | ✅ 拦下 |
| ② | `.sb-item` 改 `--t3` | ✅ 拦下 |
| ③ | `--p-ink` 改回 `#0e7490` | ✅ 拦下 |
| ④ | `--p-deep` 复活 | ✅ 拦下 |

🔴 **踩到的坑**：首次四态全部"通过"，原因是"全部通过 → `process.exit(0)`"那个大 if
里没把 `accentBad` 加进去 ⇒ 违规也不会打印、直接 exit 0。**护栏没接进判定等于没写**。
