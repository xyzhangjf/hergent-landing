## 二、A 组【最优先】20 个商品的进价疑似记成了大单位（组 / 板 / 包 / 提）

这 20 个商品的**库内单位**是「组 / 板 / 包 / 提」这类**多件包装单位**，而采购报表里同一条码给出的是「杯 / 瓶 / 袋」这类**小单位价**。两者比值 **2.2 ~ 17.8 倍，且大多不是整数倍**。

### 危害（方向与「缺价」相反，更隐蔽）

- 缺价商品：成本记 0 → 毛利**虚高 / 假赚**，一眼能看出（毛利率接近 100%）。
- **本组**：成本被**高估数倍** → 毛利**虚低 / 假亏**，甚至可能显示负毛利，反而「看起来很正常」，不会触发任何告警。
- 即：`get_profit_report()` 对这批商品的成本是**系统性偏高**的。

### 当前影响面

20 个商品**全部处于活跃状态**，但：

- 近 45 天销售额：全部为 **0**（尚未动销）
- 生命周期有销售记录的：仅 **1 个**（#1439，销售额约 ¥200 量级）
- 但在采购报表里非常活跃：单个商品 9/1–10/15 期间采购次数 **1 ~ 37 次**

⇒ **即时影响极小，但一旦动销就会立刻暴露**。而且这些商品频繁出现在采购明细、却几乎不出现在销售明细里，本身就是一条重要线索（见下方「两种可能」）。

### 两种可能（需要老板判断是哪一种）

**可能 ①：这些是「采购 / 排单专用档案」，不是销售商品。**
证据：商品名里大量带内部标记——「（恒滋下单）」「+4到货」「单号下单」「双号排期」「+3发货」「16连」；且它们在采购明细里高频出现、在销售明细里几乎为零。
⇒ 若成立，问题不是「进价记错单位」，而是**这些档案不该参与毛利报表**（成本口径对它们没有意义），或者应该与销售侧的小单位商品档案**建立对应关系**（把采购量/采购额归到真正的销售商品上）。

**可能 ②：它们是正常销售商品，只是进价档案填成了大单位价。**
⇒ 若成立，应把进价改为小单位价（除以包装内含数），成本才与按小单位计量的销量对得上。

### 建议的确认步骤（按顺序做，不要跳）

1. **看档案**：逐个打开这 20 个商品，确认 `unit`（小单位）、`default_sale_unit`、`large_unit` / `medium_unit` 与 `large_ratio` / `medium_ratio` 分别填的是什么。
2. **看销售开单单位**：在销售订单里查这批商品实际是按「组 / 板 / 包 / 提」开单，还是按「杯 / 瓶 / 袋」开单。
   - 若**销售也按大单位开单** → 进价口径没问题，是采购报表侧的小单位价需要先乘包装内含数再比。
   - 若**销售按小单位开单** → 进价档案确实记成了大单位价，需要除以包装内含数改成小单位价。
   - 若**这些商品压根没有销售单** → 大概率是可能 ①（采购侧档案），应处理「是否参与毛利报表 / 与销售侧档案对齐」，而不是改进价。
3. **验证包装内含数**：用商品名里的规格反推（如「125*2杯*12组」= 1 组 2 杯），不要直接用「库内价 ÷ 小单位价」的倍数——那个倍数大多不是整数倍，说明还叠加了促销/返利/运费，不能当换算系数用。
4. **先试一条再推广**：挑 1~2 个改完，重跑毛利报表看单品毛利率是否回到正常区间（参考：现有商品毛利率四分位约 11%~20%），确认后再批量。

## 六、口径说明（避免以后报数对不上）

「缺进价商品到底多少个」历史上出现过 42 / 143 / 132 三个数字打架，根因是**报数时没写口径名**。以后一律按下表分层报数：

| 口径名 | 定义 | 当前数量（本轮写入后） |
|---|---|---|
| **全量缺价** | `products` 全表 `purchase_price` 为 0 的商品 | **132** |
| **活跃缺价** | 上者中 `is_active = 1` 的 | **68** |
| **活跃且有销售明细** | 上者中在 `sale_order_items` 里有过销售记录的 | **22** |
| **活跃且近 45 天有销售明细** | 上者中近 45 天（delivered / signed）有销售明细的 | **4** |
| **活跃且近 45 天有实际销售额** | 上者中金额 > 0 的（第 4 个是零金额赠品行） | **3**（合计 ¥2,180.38） |

补充口径事实：

- `products` 共 **473** 个商品，其中活跃 **363** 个（毛利报表只统计活跃商品）。
- 缺进价的 132 个商品**生命周期销售额合计约 ¥4.32 万**，占全库销售额比例极小 ⇒ 缺价对总量影响有限，但对**单品毛利分析**影响致命（成本记 0 → 毛利率显示 100%）。
- 上一轮记录的「42」= v507 时点的「**缺价 ∩ 活跃 ∩ 有过销售明细**」口径（对应上表第 3 层，当前 22）。演变链 42 → 32 → 22 与两轮各写入 10 / 11 条完全闭环，**不是数据打架**。

### 另两个会影响判断的口径特性（非 bug，但要记住）

1. **报表单品毛利率会被赠品行打负**：`get_profit_report()` 的 `cost = SUM(quantity) × 进价` 把 `amount = 0` 的赠品 / 内部领用行也算进销量，而 `revenue = SUM(amount)` 不含赠品。所以本轮新写入的 11 条里，7 条在报表口径下显示负毛利——这是口径特性，不是价格错。若做单品毛利分析，需单独剔除赠品行（只统计 `amount > 0` 的明细）。
2. **`products` 有三套条码列**：`barcode` / `medium_barcode` / `large_barcode`。批量改价必须三列都试，本次有 15 条是靠中 / 大单位条码才匹配上的。

## 七、通用复核方式

1. **看进价**：进销存 → 商品档案 → 搜索商品 id 或名称 → 查看进货价字段。
2. **看成本影响**：数据报表 → 毛利分析 → 按商品维度查看该商品的销售额 / 成本 / 毛利 / 毛利率。
3. **交叉核对采购价**：舟谱系统导出《采购订货明细报表》（选择「展示方式：小单位」）→ 按条码搜该商品 → 看「采购价」列。
