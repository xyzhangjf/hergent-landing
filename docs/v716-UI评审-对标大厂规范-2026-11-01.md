# Hergent 前端 UI 评审报告（对标一线大厂体验规范）

> 评审对象：`hergent.cn` 生产站 构建 v713（169 个页面 / 38 个共享组件 / 215 个样式文件）
> 方法：静态代码审计（全量扫描）+ 生产真机量化采样（8 个代表页面，1440×900 与 375×812 双视口，CDP 真鼠标/真键盘）
> 日期：2026-11-01

---

## 零、总体判断

**底子不差，问题在「规范写了，但没被强制执行」。**

已经具备的东西比多数自研系统好：

| 已有 | 证据 |
|---|---|
| 设计令牌体系 | `variables.css` 834 行，200+ 变量，含语义色/图表色/热力色分层 |
| 共享组件库 | 38 个（Modal / EmptyState / ConfirmDialog / PsiPager / Skeleton / StatusBadge / Toolbar / InactiveToggle…） |
| 真语义表格 | 72 个文件用原生 `<table>`，不是 div 拼的伪表格 |
| 无障碍意识 | `aria-label` 130 处、`role=` 100 处 |
| 响应式底线 | **8 个页面在 375px 下横向溢出全部为 0px** |
| 图标统一 | 自研 `<Icon>` 组件（Lucide 线性风格）覆盖 75 个页面 |

但四条硬指标全面失守，而且都属「规范明明写了却没用」：

1. **对比度**：核心文字/状态/主按钮**全部**低于 WCAG AA 4.5:1
2. **令牌**：204 个硬编码色值、23 档字号（含 `10.8333px` 这种计算产物）、40 种控件高度
3. **复用**：`EmptyState` 只被 6/169 页使用、`ConfirmDialog` 只 1 页、`StatusBadge` **0 页**
4. **焦点**：全站放任浏览器默认 `outline`，同屏出现 3 种宽度、3 种颜色

一句话：**这是一套"设计系统只有设计、没有系统"的典型样本。**

---

## 一、P0：文字对比度全线不达 WCAG AA

这是唯一一项**用户每天都会感知、且直接影响数据可信度**的问题。以下为生产实测值（alpha 合成后真实对比度，非估算）。

### 1.1 次要灰文字 `#A1A1A6` —— 全站影响面最大

| 场景 | 实测 | 要求 | 出现次数（单页最高） |
|---|---|---|---|
| 灰字 on 白底 | **2.57:1** | 4.5:1 | 商品档案 **245 处**（序号、条码、规格、跟随） |
| 灰字 on 表头底 `#F5F5F7` | **2.36:1** | 4.5:1 | 全站所有列表页表头 |

问题实质：`#A1A1A6` 是 Apple 的 **tertiary label**，设计用途是"装饰性辅助层级"。这里被拿来当**业务数据文字**（条码 `6934665091`、序号、规格）——这是用户要核对的真实信息，不是装饰。

**改法**：新增 `--t3-ink` 专用于"需要被读的次要文字"，保留 `#A1A1A6` 仅用于分隔符/占位符。

```
--t3-ink: #6E6E73;   /* 白底 5.07:1、表头底 4.66:1，均达 AA */
```
替换范围：`variables.css` 的 `--t3`，以及全站直接写 `#A1A1A6` / `#a1a1a6` 的 11 处。

### 1.2 状态标签 —— 老板最需要"一眼看清"的东西，对比度最差

| 标签 | 实测 | 判定 |
|---|---|---|
| 启用（绿 `#34C759` on 浅绿 `#E7F8EB`） | **2.01:1** | ❌ |
| 未录 / 待处理（橙 `#FF9F0A` on 浅橙 `#FFF2DD`） | **1.86:1** | ❌ |
| 主管（靛 `#6366F1` on 浅靛 `#E9EAFD`） | 3.75:1 | ❌ |
| 导购（紫 `#A855F7` on 浅紫 `#F3E7FE`） | 3.33:1 | ❌ |
| 停用（红 `#FF3B30` on 白） | 3.55:1 | ❌ |

商品档案有 46 个"启用"、15 个"未录"标签处于 2:1 —— 相当于**浅色字印在浅色纸上**。

**改法**：底色不动（浅底是对的），只把**前景色压深**：

```
--st-ok-txt:   #0F7B3F   /* on #E7F8EB → 4.85:1 */
--st-warn-txt: #B45309   /* on #FFF2DD → 4.54:1，配 #FFFBEB → 4.84:1 */
--st-info-txt: #4338CA   /* on #E9EAFD → 6.64:1 */
--st-cust-txt: #7E22CE   /* on #F3E7FE → 5.88:1 */
--st-off-txt:  #C62828   /* on 白 → 5.62:1 */
```

### 1.3 主按钮与危险按钮 —— 全站最常点的两个控件

| 控件 | 现状 | 实测 |
|---|---|---|
| `.btn-primary` 白字 on `--p-dark #0891B2` | `variables.css:431` | **3.68:1** ❌ |
| 危险实底 白字 on `--dan #FF3B30` | — | **3.55:1** ❌ |
| 品牌青当文字色 `#0891B2` on 白 | 销售单 101 处（单号、状态） | **3.68:1** ❌ |

**这条特别值得说**：项目里**早就有正确答案**——`--p-ink: #0e7490` 的注释明确写着「对选中青底 4.87:1（原用 `--p-dark` 仅 3.34:1，违反 UI-SPEC §5.6）」。也就是说规范当年就算过、写下了、然后**没人用**。

**改法（一行）**：
```css
.btn-primary{background:var(--p-deep);color:#fff}   /* #0E7490 → 5.36:1 */
```
危险按钮同理改用已有的 `--danger-solid: #DC2626`（4.83:1）。

### 1.4 警告橙不可当文字

`--war #FF9F0A` on 白 = **2.06:1**（工作台 8 处、商品档案若干）。橙色只能做**底色/图标**，不能做文字。文字请用 `--sev-warn` 那套（`#BA7517`）。

## 二、P0：字号下探到中文不可读区间

全站 1968 处硬编码 `font-size`，23 个不同值：

```
12px ×730   13px ×400   11px ×270   12.5px ×186   11.5px ×125
14px ×81    10px ×37    16px ×24    13.5px ×17    10.8333px ×48 ← 计算产物
10.5px ×11  9px ×4 ...
```

两个问题：

**① 9–11px 出现在中文界面。** 汉字在 10px 以下笔画粘连，`9px ×4` / `10px ×37` / `11px ×270` 基本不可读。看板页 95 个 11px 元素是全页主体（占比最高）。

**② `10.8333px`（48 处，商品档案）是计算产物**，说明某处写了 `font-size: 65%` 或 em 复合值——它不在任何阶梯上，换字号时无法预测结果。

**改法**：收敛到 7 档，最小不低于 11px（中文下限）：

```
--fs-2xs: 11px   /* 角标、单位，仅限非关键信息 */
--fs-xs:  12px   /* 表格密集数据 */
--fs-sm:  13px   /* 正文默认 */
--fs-md:  14px   /* 表单/按钮 */
--fs-lg:  16px   /* 卡片标题 */
--fs-xl:  20px   /* 页面标题 */
--fs-2xl: 24px   /* KPI 数字 */
```
配套一次性清理：`grep -rn "font-size:\s*[0-9.]*px" src/` 全量替换为变量；`12.5` → `12`、`11.5` → `12`、`10.5` → `11`、`10.8333` → `11`。

## 三、P1：设计令牌形同虚设

| 维度 | 唯一值数 | 现状 |
|---|---|---|
| 硬编码色值 | **204 个**（563 次） | 已有 200+ 令牌，却仍手写 `#2f6bff`、`#357`、`#354`、`#355`（3 位缩写） |
| 字号 | **23 档** | 见上节 |
| 控件高度 | **40 种** | 20/22/24/26/28/30/32/34/36/39/40… 几乎每 2px 一档 |
| 圆角 | 7–9 档/页 | 尚可，但与 `radius-xs/sm/md/lg/xl` 五档令牌不对齐 |
| 过渡时长 | `.15s ×109`、`.2s ×29`、`.18s ×19`、`.12s ×11`、`.16s ×8`、`.25s ×6` | 6 种时长，无 `--dur-*` 令牌 |

**最刺眼的两个并存色**：`#06b6d4`（品牌青，16 处）与 `#2f6bff`（另一个蓝，6 处）。同一个系统里两套蓝，用户会以为来自两个产品。

**改法**：
1. 高度收敛到 3 档：`--h-sm:28px` / `--h-md:32px` / `--h-lg:36px`，39px 侧栏项改 36/40 二选一。
2. 加一条 CI 校验（比人肉 review 可靠）：构建前跑脚本，`src/**/*.{vue,css}` 里出现 `#[0-9a-f]{3,8}` 且不在 `variables.css` 内 → 报错。当前存量 563 处可分批清理，但**新增必须拦住**。
3. 时长收敛为 `--dur-fast:120ms` / `--dur-base:150ms` / `--dur-slow:200ms`。

## 四、P1：共享组件造了，几乎没人用

这是**最容易修、收益最大**的一类债——组件已经写好、测试过、就在仓库里躺着。

| 组件 | 使用页面数 / 169 | 后果 |
|---|---|---|
| `EmptyState` | **6** | 空态用了 **12 种**自定义类名（`state-empty` 129 处、`pr-empty` 11、`pc-empty` 7、`rb-params-empty` 4、`bp-empty` 4、`nt-empty` 3…），103 个文件手写「暂无」 |
| `PsiPager` | **3** | 分页各写各的，翻页交互与「每页条数」位置不一致 |
| `ConfirmDialog` | **1** | 危险操作确认各实现一套，文案口径不一 |
| `StatusBadge` | **0** | 状态标签散落各国，颜色/圆角/字号各不相同（这正是 1.2 节对比度失控的根因） |
| `Toolbar` | **1** | 工具栏 28–67 个按钮/页，排布无统一规则 |
| `StatusTabs` | 3 | 状态筛选页签样式分裂 |

旁证：加载态 `Skeleton` 覆盖 45 个文件，剩下 100+ 页是文字 loading；文案还分裂成「加载中」24 处 / 「载入中」2 处。

**改法（按投入产出排序）**：
1. **把 `StatusBadge` 接上**（0 → N）。它同时解决 P0 的状态对比度、和 P1 的状态样式分裂，**一个组件治好两个问题**，性价比最高。
2. 抽 `useToast`（当前无统一 toast 入口，各页自己有几百种提示写法），统一成功/失败/警告三种。
3. `EmptyState` 分两批替换：先替换 12 个高频列表页（销售单、商品档案、员工、客户、供应商、调拨、采购、报表），再扫剩余。
4. 加 ESLint 规则：页面里出现 `class="*empty*"` 或新写分页 DOM → 提示用共享组件。

## 五、P1：焦点样式完全不受控

实测（销售单页，Tab 遍历 14 个可聚焦元素）：

```
button.wx-now    outline=auto 3px rgb(8, 145, 178)   ← 品牌青
button.tb-btn    outline=auto 1px rgb(0, 95, 204)    ← 浏览器默认蓝
a.sb-item        outline=auto 2px rgb(98, 108, 125)  ← 灰
button.sb-item   outline=auto 3px rgb(110, 110, 115) ← 另一种灰
```

**14 个元素：outline 被抑制 0 个（好事），自定义焦点环 0 个（问题）。**

也就是说焦点是**浏览器自己算的**：宽度 1/2/3px 三种、颜色三种（含两种灰）、无 offset。Chrome 的 `outline: auto` 会根据背景反推对比色，设计师无法控制，也无法在品牌深色底上保证可见。

> 已做阳性对照：注入 `*{outline:none!important}` 后探针识别 8/8 为"无指示"，证明探针有效，上述结论不是假阴性。

**改法**（大厂通行做法，2px ring + 2px offset）：

```css
:where(button, a, input, select, textarea, [tabindex]):focus-visible{
  outline: 2px solid var(--p-dark);
  outline-offset: 2px;
  border-radius: inherit;
}
```
加 `outline-offset` 是关键细节——密集工具栏里贴着边的焦点圈会被相邻元素"吞掉"。

## 六、P2：视觉层级 —— "主按钮太多，等于没有主按钮"

| 页面 | 主按钮数 | 主按钮文案 | 按钮总数 |
|---|---|---|---|
| 销售单 | **2** | "查询" + "新建销售单" | **67** |
| 工作台 | **2** | "登记回款" + "诊断近期掉量商品" | 33 |
| 本期预报 | 1 | "改单" | 28 |
| 商品档案 | 1 | "+ 新增" | 49 |
| 销售报表 | 0 | — | 18 |

两个问题：

1. **销售单把「查询」做成了主按钮**，而「新建销售单」才是主操作。查询是高频但低权重的动作，应为主按钮配 `查询` 次按钮（`btn-sm`）。
2. **销售单 67 个按钮同屏**。大厂规范里工具栏一般 ≤5 个可见操作 + "更多"收纳。这里已经明显过载（且历史记忆里也有"工具栏不停加按钮"的痕迹）。

**改法**：
- 每页限 1 个主按钮（`btn-primary`），其余转 `btn`/`btn-sm`/`btn-icon`；超过 5 个操作的收进「更多」下拉（项目里 `RowMoreMenu` 已有范式）。
- 销售单把"查询"降级为次按钮。

### 标题层级缺失

- 工作台、本期预报：**无页面级 `h1`**
- 销售报表：用 `h2 20px` 当页面标题
- 看板：`h1` 是 `18px`，内容是"经营趋势"（其实是卡片标题）
- 工作台的四个 `b 15px/600`（今日要务/近效期预警/客户回款/AI 洞察）是卡片标题却用 `<b>`

**改法**：统一 `h1 = var(--fs-xl) 20px/600` 作页面标题（每页唯一），`h2 = 16px` 作卡片标题，把 `<b>` 换成 `<h3>`。**同一时间点的字号×字重组合不超过 4 种**，超过就没有层级可言。

## 七、P2：交互目标尺寸

统计 <28×28px 且可点击的元素（按类型）：

| 页面 | 总数 | 复选框 | 图标钮 | 标签页 | 行内文字链 | 表单控件 | 其它 |
|---|---|---|---|---|---|---|---|
| 销售单 | 168 | **51** | 10 | 5 | 50 | 0 | 50 |
| 开单单据 | 95 | 0 | 12 | 6 | 0 | **45** | 30 |
| 员工档案 | 54 | 0 | 16 | 8 | 0 | **28** | 0 |
| 商品档案 | 15 | 1 | 8 | 4 | — | — | — |

**要区分场景判断，不能一刀切**：

- ✅ **可接受**：桌面数据密集表格里的 22–24px 行内按钮、13×13 视觉复选框。ERP 桌面端沿用 32px 触控标准会让一屏少看 40% 数据，这不是错。
- ❌ **必须修**：
  - **复选框热区 13×13**（销售单 51 个）。视觉 13px 可以，但**点击热区必须 ≥28×28**——用户点不准就会误选行，进而误操作单据。这是"看起来能点但点不中"。
  - **开单页 45 个表单控件高 24px**。开单是高频录入，控件高度低于 28px 时，误触与"点不中要重按"直接拖慢报单速度。
  - **图标按钮 16×16**（`.tab-ic` 刷新/关闭，8 个/页）。关闭标签页时点歪 = 关错页。

**改法**：
```css
/* 视觉不变，扩热区 */
.xxx-checkbox::before{content:'';position:absolute;inset:-8px}   /* 13 → 29 热区 */
.btn-icon{width:30px;height:30px}        /* 已有，别再缩到 16 */
.fld{height:32px}                         /* 开单页统一到 32，与 .btn-sm 同高 */
```

## 八、P2：动效无降级

- `transition` 235 处，`prefers-reduced-motion` **仅 3 处**
- 前庭敏感/晕动症用户无法关闭动画；低端机上也白烧性能

**改法**（一处全局即可覆盖）：
```css
@media (prefers-reduced-motion: reduce){
  *, *::before, *::after{ animation-duration:.01ms !important; transition-duration:.01ms !important; }
}
```

## 十、结论

- **视觉**：不达大厂标准的不是"不好看"，而是**读不清**——对比度、字号下探这两条决定了它是"能用"而非"专业"。
- **交互一致性**：不是没有组件，是**组件蓄水池没接管道**。`StatusBadge` 尤其典型：造了、零使用，于是每个页面自己发明标签。
- **可用性**：375px 零溢出、真 `<table>` 语义、aria 130 处这些底线守住了；失守的是对比度、焦点控制、点击热区。

**一句话**：这套 UI 的差距不在设计能力，而在**「规范 → 执行」之间缺一道强制**。前三项修复（2 个变量 + 1 个组件 + 6 行 CSS）就能把最刺眼的问题全部消掉，成本以小时计。
