## P0-6 col-prefs 后端 400（✅已落地 v504）

- **真实根因（已核实，推翻原假设）**：不是 `cfg`/`pref` 字段名不对称——前端 `useColPrefs.js` 本就按 `GET` 读 `pref`、`POST` 发 `cfg` 的约定写，两端对齐。**真正根因是后端 `db/queries/ui_prefs.py:61` 的白名单 `COL_PREF_PAGES = ("forecast","purchase","settlement")` 严重过时**：v411 定义时只有 3 个页面键，但 v432 起 `useColSettings(page,…)` 统一封装被 **25+ 页面**调用，各自传独立键（`inv-stock`/`CUSTOMER-ARCHIVE`/`purchase-new`/`ui-density`/`INV-SALE-LIST`…）。这些键全不在白名单 → `_clean_page` 抛 `ValueError` → 路由转 **400** → 前端 `useColPrefs` 捕获后 offline 降级。即**几乎全站的列设置都不上云**（只活 localStorage），不止"部分页面"。
- **修复（v504，纯后端，无需前端改动）**：
  - `db/queries/ui_prefs.py`：把"枚举白名单"改为"**格式校验**"——`page` 满足 `^[A-Za-z0-9_-]{1,48}$` 即放行（保留长度/字符边界 + `_MAX_CFG` 体积上限挡滥用）。根除"后端维护前端键清单=第二套口径漂移"的病根。
  - `col_pref_pages()` 改为从库 `SELECT DISTINCT page` 动态返回（不再依赖会过期的写死清单）。
  - **踩坑修复**：删 `COL_PREF_PAGES` 后 `erp_db.py:68` 的 `from … import (COL_PREF_PAGES, …)` 导致服务 ImportError 崩溃；已把该符号从 import 元组移除（已 grep 确认全仓仅此一处引用），服务恢复 active。
- **涉及文件**：`/opt/hergent-erp/db/queries/ui_prefs.py`、`/opt/hergent-erp/erp_db.py`（生产机扁平部署，非 git 仓库，改后 md5 比对 + 重启 `hergent-erp.service` + 备份至 `backups/p06/`）。

## 交付纪律（每批次必做）

1. 开工前：实搜三处确认 `vNNN`；跑 `Explore`/grep 复核当前实现（勿信记忆）。

3. 提交：scoped 提交（`git commit -F`，不带 pathspec），只 add 本轮文件。
