# Hergent 发布前自查清单（Checklist）

> **用途**：每次"改代码 → 构建 → 部署 → 真机验证 → 交付"一轮，必须逐条打勾。**任何一条没勾 = 这轮没交付完，不算验收通过。**
> **兜底硬卡点**：缺「第十章五段交付摘要」= 不验收（哪怕代码改对了）。
> **配套文档**：《Hergent 开发团队协作规范与交付流程》——本清单是它的最小可勾选版，括号里标了对应章节，踩坑的解释见规范正文。

  - [ ] 搜 `scoped_stage_by_marker.py` 已注册 spec 名
- [ ] **判据顺序已走**（§4.3）：搜到的号看了那一行，确认是「已实现」还是「仅预案」——①② 都空才认领
- [ ] **并行会话在途改动已排查**：没和别人落在同一行抢「下次从 N 起编」类提示行（§4.5）；撞号按「后到改号 + 行号白名单逐个替换、绝不用 replace_all」（§4.4）

## B. 编码与提交

- [ ] **价格 / 口径类代码直接看 `SELECT` 列表**，没信注释（§5.5）
- [ ] **含方括号 / 特殊字符的搜索用了 `grep -F`**（§5.6）

## D. 部署执行

- [ ] **后端用 `scp` 具名单文件到完整路径**，部署后 `grep -c <新符号> /opt/hergent-erp/...` 验证落点（§6.3，别信 rsync 的 OK）
- [ ] **前端 rsync 只同步 `dist-vNNN/` 产物、绝对路径、绝不拷仓库根、绝不 `--delete`**（§6.3，生产 `assets/` 是并集）
- [ ] 🔴 **重启的是 `hergent-erp.service`，不是 `hergent-server.service`**（§6.2）—— 重启后 `ss -ltnp | grep 8700` → `readlink /proc/<pid>/cwd` 必须是 `/opt/hergent-erp`
- [ ] 🔴 **换 / 删过库文件 ⇒ 已先删文件再 restart**（§6.6，幽灵 inode 静默写入旧文件）
- [ ] **脱敏红线守住**：返利率 / 进货价 / 客户名 / 区域销量 / 厂家政策没有出系统、没进日志、没落 `outputs/`（§7.4）

## E. 验证（真机探针 + 双向断言）

- [ ] **三方 md5 双侧全等**（§6.4）：后端具名文件 / 前端产物（经公网拉取，绕过本机 HTTP 缓存）
- [ ] 🔴 **当轮生产真机探针已重跑**（§6.4，探针有过期保质期）
- [ ] 🔴 **「线上跑的是不是本轮构建」看 `index.html` entry + 其 CSS 新增类名**（§6.5），不是只看 chunk 文件名
- [ ] **探针避开三陷阱**（§8.1）：`page.evaluate` 不传字符串当表达式 / 对照格选原本非空的 / 多目标同结果即作废
- [ ] **双向断言**：每条带 HEAD 反证（改前该是 X、改后该是 Y）（§8.2）
- [ ] **「代码里没调用点 ≠ 没人用」**：涉及"某表空 / 某功能没人用"的结论，已去生产数一遍（§8.3）
- [ ] **端点 / 路由生效不信 HTTP 状态码**：生产 `grep` 端点定义 + 进程内实测（§8.4）
