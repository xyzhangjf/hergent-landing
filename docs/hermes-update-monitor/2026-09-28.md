## ② 与 hergent 生产 v0.19.0 的差距

- hergent 近期 AI 优化 90% 走自有 `server/hermes_core.py` 直连 DeepSeek，**与 Hermes 进程解耦**，因此 Hermes 版本跃迁对副驾主链路无直接增益。
- 真实耦合仅 5 处（见 ③）。v0.21.x 引入的全新 `gateway/` 运行时（默认端口 8642、API_SERVER_KEY、进程监管）、桌面插件 SDK、多 profile 隔离、state.db 重构等，**90% 为桌面/多机器人向，对 hergent 服务端部署增益≈0**。
- 4 个新 tag 的修复（state.db 可靠性、远程会话过期、网关单例锁、cron 交付修复等）均面向 Desktop/Cloud 多 profile 场景，**无一命中 hergent 当前依赖或痛点**。

## ④ 结论与建议

**结论：A —— 无需升级，维持生产 v0.19.0。**

理由：
1. **升级会破坏契约 ③（定时任务全挂）**，且无解耦后的平替——这是硬否决项，在 v0.21.x 全部 tag（含最新 v0.21.5）中 cron bridge 都未回归。
2. **4 个新 tag 无 hergent 需要的修复或能力**：均为桌面/多 profile/state.db/网关会话类修复，对 hergent 服务端单 profile 部署无增益。
3. **收益/风险严重失衡**：hergent 90% AI 走自有 `hermes_core`，v0.21.x 新能力（插件 SDK、Connectors 页、语音快捷键、多 profile 隔离）对当前业务直接增益≈0；而升级需改 hergent `cron_tasks.py`（重写）+ config 软迁移 + 多进程网关/反代核对 + 全量 staging，任一环节出错即影响线上副驾/每日简报/Excel 对账。
4. **生产机无外网仍是部署硬阻塞**（无法 `pip install` v0.21.x 依赖），落地需 Docker 构建 Linux venv 或临时开网——纯工程成本无对应收益。
5. **安全触发未达阈值**：PyPI 残留的未修复漏洞记录（≤0.12.0 + 飞书 webhook）针对古老版本，hergent 单 profile 服务端暴露面小、无飞书 webhook，不构成升级理由；v0.21.2 的凭据隔离修复面向多 profile Desktop，与 hergent 无关。

## ⑤ 风险提示与最小改动清单（仅作建议，本次未改动生产）

若未来触发升级（见下），最小改动清单：
1. `server/routers/cron_tasks.py:13`——删除 `sudo .../hermes_cron_bridge.py`，改为调 Hermes gateway 的 HTTP cron API（list/create/pause/resume/trigger/delete），并确认 gateway 常驻 + api_server 绑定 + 鉴权（API_SERVER_KEY）。
2. `config.yaml` 适配——`platforms.api_server.{port,key,cors_origins}` 经桥接读取仍可用，但需 staging 实测确认 nginx（`/hermes/` → 18765）→ 新网关（8642/API_SERVER_KEY）端口与反代路径。
3. `server/routers/ai_skills.py:26`——当前 `/v1/skills` 在 v0.21.x 已恢复，**无需改动**（比 v0.20.6 评估时更宽松）。
4. 部署——先破无外网阻塞（Docker 构建 Linux venv 或临时开网）→ staging 独立端口跑 5 探针 → 生产切换 + 回滚锚点。

**升级触发条件（沿用，未变）**：
- 官方出现 headless/server 正式发行说明；或
- 修复 cron bridge / config 迁移 / 18765 兼容，使 ③ 不再为否决项；或
- 出现波及 v0.19.0 暴露面的严重安全公告。
