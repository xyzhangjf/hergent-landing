## ③ 5 个耦合点兼容性核查（基于 /tmp/hermes-2112-src，v0.21.2 源码 grep）

### ① 前端 SSE `POST /hermes/v1/chat/completions` —— ✅ 兼容
- v0.21.2 证据：`gateway/platforms/api_server.py:80` `("chat_completions", ("POST", "/v1/chat/completions"))`；`:1543` `("POST", "/v1/chat/completions", self._handle_chat_completions)`；handler 在 `gateway/platforms/api_server_openai_routes.py:410`。
- 判定：路由与 OpenAI 兼容语义均保留。**形态变化**：新运行时默认端口 8642（非 18765）+ `API_SERVER_KEY`，nginx 反代与调用地址需重配。

### ② `server/routers/ai_skills.py:26` 调 `GET /v1/skills` —— ✅ 兼容
- v0.21.2 证据：`gateway/platforms/api_server.py:86` `("skills", ("GET", "/v1/skills"))`；`:1531` 路由注册；`:2637` `"""GET /v1/skills — deterministic JSON listing of installed skills"""`。
- 判定：v0.20.6 的"改纯 `/api/skills`"已被**逆转回 `/v1/skills`**，hergent 现调用路径在新版仍存在。（`/api/skills` 仍在，是桌面/Web UI 用的另一套。）

### ③ `server/routers/cron_tasks.py:13` 硬编码 `sudo .../hermes_cron_bridge.py` —— ❌ **断裂（否决项，未修复）**
- v0.21.2 证据：全仓 grep `cron_bridge|hermes_cron_bridge` → **零命中**（连续第三轮确认）。
- 官方替代路径：`gateway/platforms/api_server.py:1550-1557` 新增完整 cron CRUD —— `GET/POST /api/jobs`、`GET/PATCH/DELETE /api/jobs/{job_id}`、`POST /api/jobs/{job_id}/{pause,resume,run}`；另有 `POST /api/cron/fire`（Chronos NAS→agent 回调，需 NAS 签发 JWT）。
- 鉴权：`_cron_request_guard` → `_check_auth(request)`，即需 `API_SERVER_KEY`（与 chat 同源），**不是** sudo 本地脚本。
- 判定：升级后 hergent 的定时任务创建/管理链路**必然全挂**，必须把 `cron_tasks.py` 从"sudo 调本地脚本"改写为"带 API Key 调 `POST /api/jobs`"。**这是当前升级的最大单点成本。**

### ④ 生产 `~/.hermes/config.yaml`（`model` / `platforms.api_server` / `cors_origins` / `mcp_servers.spreadsheet` stdio） —— ⚠️ 软兼容，需 staging 实测

- 判定：相对 v0.21.0 评估时的"必手改迁移"，v0.21.2 已内置旧键桥接，属**软迁移**；但桥接只覆盖 `platforms.api_server` 的 5 个键，其余 schema 差异仍须在 staging 用真实 config.yaml 实跑确认。

## ④ 结论与建议

### **结论：A —— 无需升级，维持生产 v0.19.0。**

理由（四条，按权重）：

1. **新版本收益对 hergent 为零。** v0.21.2 的全部实质内容 = 修 v0.21.0 自引入的 state.db 回归 + 桌面/多机器人向能力（Bot Mode、peer、凭据保险库、插件目录、Nous 免费额度）。生产 v0.19.0 **不含**该回归，且 hergent 近期 AI 优化 90% 走自有 AI loop（`server/hermes_core.py` 直连 DeepSeek），与 Hermes 版本解耦 —— 官方新能力对业务**无直接增益**。

2. **升级成本项（cron 桥接断裂）连续第三轮确认仍未修复。** `hermes_cron_bridge.py` 在 v0.21.2 全仓零命中，官方替代品是需 `API_SERVER_KEY` 的 gateway HTTP `/api/jobs`。这意味着升级 = 必须改写 `cron_tasks.py` + 重配 nginx 端口（18765→8642）+ 实测 config 桥接，属**破坏性升级**，与《hermes-v0.20.6-compat-report.md》结论一致。

3. **无触发升级的必要事件。** 无新增安全公告；PyPI 两条历史漏洞上界均早于 v0.19.0，生产不在受影响区间。无 headless/server 正式发行说明。

4. **风险不对称。** 升级需承担新运行时（gateway/ + API_SERVER_KEY + 8642）引入的部署/回滚风险，而收益为零 —— 典型的不划算交易。

### 升级触发条件（保持监测，满足任一条即重新评估为 B/C）
- 官方发布 headless/server 侧的正式发行说明，或明确恢复/提供与 v0.19.0 等价的 cron 本地入口；
- 出现**波及 v0.19.0 暴露面**的严重安全公告（CVE / GHSA 上界 ≥ v0.19.0）；
- 官方提供 `18765` / 旧 config 键的完整兼容层或自动迁移工具；
- hergent 业务出现必须依赖 v0.21.x 新能力的明确需求（当前无）。
