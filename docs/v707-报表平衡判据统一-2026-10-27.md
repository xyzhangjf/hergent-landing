## 四、更严重的 4 个问题（本轮**未修**，需拍板）

### ① 期初凭证本身借贷不平 379 万

`tenant_1` 有一笔 `ref_type='opening'`、`summary='舟谱导入期初余额'`、`date=2026-06-01` 的凭证，
**208 行，借 12,601,306.36 / 贷 8,807,411.20，差 3,793,895.16**。

原因：舟谱导入把**科目树的父节点也当末级科目写了借方**（如 `1002 银行存款` 与其 7 个子科目
`100201~100207` 各写一行、金额相同），贷方却没有对应项。

⇒ 试算表 2026-06 必然红叉。这是数据问题，改判据解决不了。

### ② 父/子科目被重复计入（资产虚高）

`chart_of_accounts` 是扁平树，父子都 `is_active=1`，而 `get_balance_sheet_gl()` 用
`WHERE account_code IN (...)` 一次性汇总整类 ⇒ 父子同在其中、按层级重复累加。

实测：`1002 银行存款` = 414,602.56，恰好等于其 7 个子科目之和 ⇒ 被算了两次；
`1231 / 123101 / 123102` 又重复两层。这是资产负债表差 389 万的直接来源。

### ③ 不带 `as_of` 时根本不算平衡，前端却显示「✓ 借贷平衡」（假绿灯）

`GET /api/reports/balance-sheet`（前端默认调用形态）走的是简化版 `get_balance_sheet()`：

| | 资产 | 负债 | 权益 | balanced 字段 |
|---|---|---|---|---|
| 不带 `as_of`（简化版） | **1,416,968.40** | 920.004 | 1,416,048.39 | **不存在** |
| 带 `as_of`（GL 版） | **12,383,452.20** | 205,844.00 | 8,285,388.04 | `false` |

两个问题叠在一起：

1. **两套口径差 8.7 倍**（简化版按 `accounts.current_balance`+库存×进货价，GL 版按 journal_entries）
2. 前端判定写的是 `y.balanced !== !1`（即 `!== false`）⇒ 字段**缺失时也判"平衡"**
   ⇒ 老板看到的是 **「✓ 借贷平衡」**，而这个结论**从来没被计算过**

这比红叉危险得多：红叉至少是诚实的。

### ④ 「凭证模板」整个功能不可用（5 个数据函数全缺）

`routers/voucher_templates.py` 和 `voucher_engine.py` 调用
`db.voucher_template_list / create / update / delete / apply`，
而 `erp_db.py` 里**一个都没有**（全后端 `grep "def voucher_template_"` 无命中）。

`voucher_templates` 表存在、**0 行**（播种接口也 500）。

前端有完整入口（`<div class="page-hd">凭证模板</div>` + 列表/新建/编辑/开关/播种），
点进去每个操作都是「内部错误」。

`feature_flags` 表里没有 `voucher_templates` 记录 ⇒ `is_voucher_templates_enabled()` 恒 False
⇒ 自动记账**不受影响**（一直走硬编码分录），只是管理页是坏的。

修它需要写 5 个 CRUD 函数 + 确认表结构意图，属**新功能开发**，不是判据问题。

### 还有一个次要口径（第 2 处对账匹配，本轮未动）

`erp_db.py:18675` 银行对账 `matched/mismatch`、汇兑重估 `abs(diff)>0.01`（7122/7140/7145）
仍用浮点字面量。它们语义是"差异是否值得入账/是否算对上"，改了有业务后果（可能少生成 1 分的汇兑凭证），
按上轮结论应单独一版 + 双算。
