# v728 · 行高令牌化：11 档，全站最后一次"一行松一行紧"

>
> 前置：v727 完成了字号与间距的令牌化，并在文档里留下"行高单独一版"这项。

## 一、问题：不是"值太多"，是"同一个字号配了太多种"

改之前全站 **0 个行高令牌**，475 处 `line-height` 声明散在 21 种取值里。

但值只有 21 种并不算多（v727 的间距有 43 个值）。真正的病是 **同一字号配了多少种行高**：

| 字号 | 配了几种行高 | 折算后的范围 |
|---|---|---|
| `--fs-sm` 12px（提示文字） | **23 种** | 12px ～ 25.2px |
| `--fs-xs` 11px（角标） | **18 种** | 11px ～ 23.1px |
| `--fs-base` 13px（表格） | 13 种 | 13px ～ 46.8px |

12px 的提示文字，同时用过 `1`、`1.15`、`1.2`、`1.25`、`1.3`、`1.35`、`1.4`、`1.45`、
`1.5`、`1.55`、`1.6`、`1.65`、`1.7`、`1.75`、`1.8`、`1.85`、`1.9`、`1.95`、`2.1`，
外加 `11px`/`13px`/`14px`/`15px`/`16px`/`18px`/`20px`/`22px`/`24px`/`26px`/`32px` 一堆绝对像素。

**同一张卡片里两行说明文字，一行 1.5 一行 1.7** —— 这就是"看起来不够整齐"在排版层的来源，
比字号问题更贴近阅读体验（字号影响"大小层级"，行高影响"呼吸是否均匀"）。

## 二、令牌设计：11 档倍数，不用 px

```css
--lh-none:1;      /* 单行：图标按钮、单行控件垂直居中 */
--lh-flat:1.1;    /* 过渡｜大数字（24px+） */
--lh-title:1.2;   /* 过渡｜标题 */
--lh-mid:1.3;     /* 过渡｜中间档 */
--lh-tight:1.4;   /* 密排：表格单元格、列表项、标签 */
--lh-snug:1.5;    /* 过渡｜次要 */
--lh-normal:1.6;  /* 正文主力 —— 全站最多 */
--lh-relaxed:1.7; /* 说明文字主力 —— 第二多 */
--lh-loose:1.8;   /* 长段落 */
--lh-prose:1.9;   /* 过渡｜长段落（更松） */
--lh-double:2;    /* 过渡｜双倍 */
```

### 为什么必须是倍数，不能是 px

WorkBuddy 的做法是"每档字号绑一个绝对行高"（12/18、13/20、14/22…）。它成立，因为它是
对话式界面，字号档位少且几乎不变。

我们不适用：同一个 12px 提示文字，窄屏 KPI 会降级到 18px，宽屏回到 22px；
同一个「卡片标题」类在档案页 17px、在密集表格里 15px。**写死 px 行高，字号一变就不同步** ——
这正是改造前那 25 处 `line-height:16px/18px/22px` 的由来，它们本来就是在跟字号的漂移做局部补丁。

倍数只需选一次，字号怎么变都跟着走。

### 为什么是 0.1 步长而不是 WorkBuddy 的粗档

原值分布里 `1.45/1.55/1.65/1.75` 这几个 **0.05 档**合计 47 处，是真实在用的
（"比紧一点再松一点"，作者是凭手感微调的）。直接砍到 0.2 步长会让 164 处位移 ≥1.2px，
在卡片里累积成明显的高度变化。

所以先按 0.1 建档，把 0.05 的往最近的 0.1 靠（最大误差 0.85px）。
**归一（11 档 → 5–6 档）留 P1**：那时改令牌值一行，全站跟着动，再跑视觉回归逐页看。

## 三、必须保留字面量的三类（护栏已放行）

| 写法 | 处数 | 为什么不能归一 |
|---|---|---|
| `line-height:0` | 4 | **不是"行高为 1"**，是用来消除 inline-block 之间的空白符、让图标贴合容器。归一会让图标错位 |
| `line-height:normal` | 1 | 让浏览器算（UA ≈1.2），只出现在 `<button>` 复位类规则里 |
| `var(--fc-cell,20px)` / `calc(…)` | 4 | 图表单元格的**行高尺寸**，跟数据密度走，不是文字行距 |
| 同块 `height` 与行高相差 ≤2px | 24 | 见下 |

### 第四类最关键：**「用 line-height 当高度」**

```css
.tb-bell-n   { height:15px; line-height:15px }   /* 顶栏未读徽标 */
.pin-clr     { height:16px; line-height:16px }   /* 列表里的标签 */
.listadd-badge{height:14px; line-height:14px }   /* 新增标记 */
.hd-sel      { height:26px; line-height:24px }   /* 表头筛选下拉（差 2px = 上下边框） */
[data-density="compact"] .ipn-v{min-height:16px;line-height:16px}  /* 紧凑档单元格 */
```

它们是靠 `line-height` 把单行文字撑到容器高，**换成一个不等于 height 的倍数会立刻错位**。
判据写进了护栏：同块里有 `height`/`min-height`，且与行高值相差 ≤2px ⇒ 视为这一类，放行并计数。

> 这类本身是技术债（正确做法是 flex 居中），但它是"用行高控高"而不是"控制行距"，
> 混进归一里只会制造 bug。护栏会打印放行数（当前 25 处），P1 应改成 `display:flex; align-items:center`。

## 四、踩到的坑：迁移脚本比护栏先跑，漏了同块 height

第一轮迁移完 455 处、部署上线，视觉回归立刻报 **10 页显著变化（最大 10.84%）**。
查下来其中一类是真问题：

```diff
-.tb-bell-n{ height:15px; line-height:15px }
+.tb-bell-n{ height:15px; line-height:var(--lh-tight) }   /* = 15.4px，徽标文字偏 0.4px */
```

**迁移脚本只做了「px → 倍数」的换算，没做「这是不是高度」的判断**；而护栏写了这条判断，
所以护栏看到 `var(--lh-*)` 就放行了 —— **两边的判据不一致，问题就从缝里过去了**。

修法：把护栏的判据搬进迁移脚本，重跑。18 处徽标/输入框/紧凑档格子全部保留字面量。

> 🔴 **教训：批量迁移脚本与护栏必须共用同一套判据。**
> 否则"迁移改错了 + 护栏放行"会同时发生，而且两边都看着正常。

## 五、契约的固有冲突：倍数额回不到整数 px

`psi-order-form-density` 契约要求开单页 `.ipn-v` 的 `line-height = 18px`（与 `min-height` 一致，
否则密集表格逐行漂移）。

改造后是 `var(--lh-tight)` = 1.4 × 13px = **18.2px**。`13 × n = 18` 需要 n = 1.3846，倍数表达不了。

修法不是回退，而是**改契约比的东西**：从"是否写了 18px"改成"行高是否撑满 min-height（±0.5px）"。
后者才是契约本意（格子高度由 min-height 定，行高必须与它一致），0.5px 是渲染取整级别。
同时补了一条判别力自证（`min-height:18px; line-height:24px` 必须被判定为不合格）。

## 六、验证：10 页变化的完整归因

视觉回归 24 页，10 张超出阈值（`px≥800 且 pct≥0.05`）。**逐页用"注入回退值"归因**：

| 页 | 原样 vs v727 | 注入回退值后 | 源头 |
|---|---|---|---|
| 资金流水 funds-flow | 10.84% | **0.01%** | `.page-hd` 1.35→1.4 |
| 库存周转 rp-turnover | 6.96% | **0.01%** | 同上 |
| 毛利分析 rp-gross-profit | 5.55% | **0.01%** | 同上 |
| 往来对账 funds-party | 0.80% | **0.01%** | 同上 |
| 工作台 workbench | 3.95% | **0.05%** | `.task-sub`/`.ig-sub` 1.55→1.5 |
| 其余 14 页 | 0.01%（119px） | — | 顶栏天气，数据噪声 |

**只有两个源头**：

1. `.page-hd :is(h1,h2)` 从 `1.35` 到 `1.4` —— 20px 标题 27px → **28px**，整页下移 1px。
   DOM 实测：`pageHd` 高度 50.39→49.39，`firstCard`/`table`/`tblWrap` 的 `top` 全部精确 **Δ1.00**，
   而所有元素的 `height` **Δ0.00**（表格 6040px 都没变）。⇒ 纯位移，无挤压、无换行、无溢出。
2. 工作台的 `.task-sub`/`.ig-sub` 从 `1.55` 到 `1.5`（12px 下 0.6px，5 条列表累积约 3px）。

两个都是"往 0.1 整数档靠"的正当结果（28px 对 20px 标题正是 1.4，比 27px 更规整），
不是缺陷。归因清楚后基线刷新到 v728。

> 🔴 **判据：一行像素差被算成"显著变化"时，先查它是不是"整体位移"。**
> 整体位移的特征是「所有下游元素 top 同向等量变化，而 height 全部不变」——
> 这与"某个元素被挤高/换行"是两件事，后者才是 bug。

## 八、P1：把 11 档归一

现在改令牌值就是全站生效，所以归一不再需要动 434 处：

```css
--lh-snug: 1.5 → 1.6    /* 收进正文主力 */
--lh-mid:  1.3 → 1.4    /* 收进密排 */
```

风险从低到高：

| 步 | 动作 | 影响处数 |
|---|---|---|
| 1 | `--lh-snug` 1.5 → 1.6（与 normal 合并） | ~60 |
| 2 | `--lh-mid` 1.3 → 1.4 | ~5 |
| 3 | `--lh-prose` 1.9 → 1.8（与 loose 合并） | ~25 |
| 4 | `--lh-flat` 1.1 / `--lh-double` 2.0 按实际用法决定去留 | ~7 |
| 5 | 25 处「用行高当高度」改 flex 居中，行高回归文字本义 | 25 |

目标：**5 档（none / tight / normal / relaxed / loose）**，与 WorkBuddy 的粗档一致。
每一步都只需改一行令牌 + 跑一次视觉回归。
