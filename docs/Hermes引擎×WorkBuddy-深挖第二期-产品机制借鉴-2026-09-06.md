# Hermes 引擎 × WorkBuddy · 深挖第二期：产品机制层借鉴

> 日期：2026-09-06　|　方法：逐文件核实 hergent 真实实现（`server/memory.py`、`scheduler.py`、`hermes_core.py` TOOLS/confirm、前端 `CopilotDrawer.vue` 产物面板）
> 定位：第一期（四维度差距）讲的是「技术栈/呈现层」，本期挖的是 **WorkBuddy 作为 AI agent 平台最值钱的东西——产品运行机制**：它如何做到「越用越懂你、越用越安全、越用越自动」。这才是垂直副驾真正该抄的，而非通用能力。

## 0. 结论先行（先纠正一个认知，再给增量）

**第一期的「记忆弱」判断被低估了。** hergent 已经有三个成型的底子（详见 §1），本期真正的缺口不是「能力」，而是把能力**从"功能"升级为"产品机制"**——即可见、可切换、可追溯、越用越懂。

**一句话：hergent 缺的 7 个增量，本质是「信任的分级」「记忆的沉淀」「结果的交付」三件事的产品化。**

| 优先级 | 借鉴项 | 一句话 |
|---|---|---|
| ★ P0 | ① 主动澄清 + 结构化选项 | 信息不足时**反问**而非瞎猜（已确认目前完全缺失） |
| ★ P0 | ② 每日经营日志（append-only）+ 跨会话回忆 | 简报结论/关键数字**沉淀**，老板能问"昨天/上周" |
| ★ P0 | ③ 动作分级护栏统一（动手级别开关） | "只建议"从散落 confirm 升级为**可切换的产品开关** |
| ◆ P1 | ④ 结果统一呈现（文件卡片+预览） | AI 产出的表/报告一键下载预览 |
| ◆ P1 | ⑤ 可视化意图路由（自动选型） | 趋势/对比/占比按数据形态**自动选图** |
| ◆ P1 | ⑥ 长期画像 + 30 天蒸馏 | 日志提炼成"这家客户的画像"注入每次对话 |
| ▽ P2 | ⑦ 技能/配方自进化 + 审计 | 服务中发现的口径**自动沉淀** + 变更可追溯 |

## 1. 先澄清：hergent 已有的三个底子（别重复建设）

本期核查**推翻/修正**了第一期的「记忆弱」与「自动化是硬编码」两条判断：

| 底子 | 真实现状（代码证据） |
|---|---|
| **记忆自进化** | `memory.py` 三表：`corrections`（纠错）/`patterns`（行为模式）/`interaction_log`（交互日志），含 `auto_learn_from_action`（从成功操作自动学模式）、`get_smart_suggestions`（历史记忆给当前操作建议）。**"越用越聪明"已实现** |
| **定时任务自助创建** | `erp_db.py:885` 有 `scheduled_tasks` 表（name/freq/run_time/prompt/role），`routers/platform.py:321` 与 `cron_tasks.py:43` 有 `create_job` 接口。**用户可自助建定时任务**（非纯硬编码） |
| **动作分级确认** | `hermes_core.py` 写操作全带 `risk_level`(high/medium/low) + `confirm_text`：开单/收款/采购/建客户/建商品均有确认提示 |

> 这三个底子是**资产，不是债**。本期借鉴是在它们之上"补机制"，不是"推倒重来"。

## 2. 七大增量借鉴（逐条：WorkBuddy 机制 → hergent 现状 → 借鉴什么）

### ① 主动澄清 + 结构化选项 —— ★ P0（确认完全缺失）

- **WorkBuddy 机制**：执行中信息不足时，`AskUserQuestion` 抛出 2–4 个**结构化选项**（推荐项置顶 + 每项带说明），而非硬猜；选项永远留"自定义输入"。
- **hergent 现状**：`hermes_core.py` 与前端副驾组件**均无 clarify/反问/选项机制**（grep 已确认）。副驾遇到"客户名模糊匹配到多个""数量/金额缺失""口径有歧义"时，只能硬猜或报错。
- **借鉴**：协议层加"澄清指令"（信息不足→生成 2–4 个选项 + 推荐标注）；前端加选项渲染组件（点选即回填，SSE 新增 `clarify` 事件）。
- **收益**：出错率↓、老板体感"AI 真懂我"；与"AI 只建议"定位天然契合。
- **工作量**：3–5 人日（提示词协议 + 前端选项卡 + 事件）。

### ② 每日经营日志（append-only）+ 跨会话回忆 —— ★ P0

- **WorkBuddy 机制**：工作区**每日日志 append-only**（自动记录实质工作）；`conversation_search` 跨会话检索；30 天后**蒸馏**进长期画像。
- **hergent 现状**：memory 三表是"纠错/模式/交互"，**无经营日志维度**——每天 8:05 简报的结论、关键数字、老板的决策全散在对话里，**第二天清零**。检索是字符级关键词匹配（`find_similar_corrections`），无"昨天库存多少"的跨会话回忆。
- **借鉴**：新增 `daily_log` 表；简报生成 + 关键交互（开单/收款/异常）自动 append；检索支持时间锚点（"昨天/上周/上月"）。
- **收益**：副驾"越用越懂这家客户"，这是 M1 记忆分层的**具体落地**，直接服务多租户变现。
- **工作量**：4–6 人日（日志表 + 落日志钩子 + 时间检索）。

### ③ 动作分级护栏统一（动手级别开关）—— ★ P0

- **WorkBuddy 机制**：工作模式 **Agent/Plan/Ask 三档可切换**；高风险操作有完整护栏（只读扫描→警告→列清单→确认→回收站）。
- **hergent 现状**：`confirm_text`+`risk_level` 已覆盖写操作，但"只建议不擅自下单"是**散落的、隐式的**，老板无法全局切换"让 AI 直接做 vs 事事确认"。
- **借鉴**：给副驾一个**可见的"干预级别"开关**：`只读（纯建议）/ 需确认（默认）/ 自动（低风险免确认）`；把散落的 risk_level 统一映射成体系 + 低风险白名单。
- **收益**：把"只建议"这条铁律**产品化**——保守老板放心用、激进老板省事；信任根基可见。
- **工作量**：4–6 人日（前端开关 + 分级映射 + 白名单）。

### ④ 结果统一呈现（文件卡片 + 预览）—— ◆ P1

- **WorkBuddy 机制**：`present_files` 统一把产物（报告/图/表/代码）以**文件卡片 + 预览面板**呈现，HTML 直接开预览。
- **hergent 现状**：有"产物右栏"（artifacts panel），但产物以文本卡为主，缺"文件卡片 + 一键下载/预览"的统一形态。
- **借鉴**：AI 产出的 Excel/CSV/报告/图表，统一进产物栏为**可下载文件卡片**（老板拿去直接进 ERP 下单/发微信）。
- **收益**：交付从"看"升级为"拿"，直击经销商"要能拿去用"的真实需求。
- **工作量**：4–6 人日（产物模型扩展 + 文件卡片组件）。

### ⑤ 可视化意图路由（自动选型）—— ◆ P1

- **WorkBuddy 机制**：Visualizer 按意图路由到 diagram/chart/interactive/mockup/art 五类。
- **hergent 现状**：`ResultCard` 只有 sparkline 单一形态。
- **借鉴**：**趋势→折线、对比→柱状、占比→环形、关系→图示**，后端返回图表类型 + 数据，前端按类型自动选图（延续零依赖自绘 SVG 路线）。
- **收益**：经营卡信息密度↑、更直观，不引入外部图表库。
- **工作量**：3–5 人日（VizCard 多形态 + 后端 chart.kind）。

### ⑥ 长期画像 + 30 天蒸馏 —— ◆ P1

- **WorkBuddy 机制**：日积月累的日志，30 天后**蒸馏**成长期画像（偏好/习惯/口径）。
- **hergent 现状**：`patterns` 表有"习惯"，但无"蒸馏成画像"机制，画像分散、不注入每次对话。
- **借鉴**：从经营日志 + patterns 提炼"这家客户的长期画像"（付款习惯/常看指标/口味），注入每次对话 system。
- **收益**：副驾"开口就懂这家客户"，多租户差异化的地基。
- **工作量**：5–8 人日（画像表 + 蒸馏任务 + 注入逻辑）。

### ⑦ 技能/配方自进化 + 审计 —— ▽ P2

- **WorkBuddy 机制**：`SkillManage` AI 自动沉淀经验为技能；`skills-security-check` 安装前审计。
- **hergent 现状**：`recipe_sync` 手动/半自动渲染；配方/技能变更**无审计日志**。
- **借鉴**：服务中发现的**新口径/规则→自动提案沉淀进配方**；配方/技能变更**全审计**（谁改/改什么/影响哪家）。
- **收益**：护城河自进化 + 多租户变更可追溯（防"改了口径某家客户受影响"）。
- **工作量**：10–15 人日（配方提案机制 + 审计表）。

## 3. 优先级排序与执行建议

```
Step 1（本周）① 主动澄清  → ③ 动作分级护栏  → ② 经营日志
        ↓ 先把「信任 + 记忆沉淀」两个地基补上（都是低成本、直击变现体验）
Step 2（2-3周）④ 结果统一呈现 → ⑤ 可视化意图路由
        ↓ 交付从"看"到"拿"
Step 3（1月）⑥ 长期画像蒸馏
        ↓ 越用越懂
Step 4（季度）⑦ 技能/配方自进化 + 审计
        ↓ 护城河自进化
```

**最该先做的一项：① 主动澄清。** 它是唯一"确认完全缺失"、且零架构风险、纯提示词+轻前端的改动；一旦落地，副驾从"硬猜"变"会问"，是体感收益最高的单点。

## 4. 明确不学的（重申，避免跑偏）

| 项 | 理由 |
|---|---|
| 通用专家市场（100+ 角色） | 护城河是**一个行业的深度**，不是角色数量 |
| 多模态生成（文生图/视频/3D） | 与经营副驾无关，纯成本 |
| 通用代码沙箱/文件操作代理 | 目标用户是老板非开发者 |
| 多 Agent 并行框架 | 只有"月度经营分析"值得试点，不建通用框架 |
| 追 Hermes 大版本 | 维持 v0.19.0（已两次核查确认） |
