# v725 · 加载态不再「先下结论」

**日期**：2026-11-02
**范围**：27 处 / 12 个文件
**结果**：全站 A 类缺陷 0（有骨架时空态仍可见），视觉回归 24 页零实质差异

---

## 一、这一版到底在修什么

不是「补骨架屏」，而是修一句话：**加载中不要说出一个结论。**

空着让人等一下，结论让人放心。老板扫一眼看到「暂无待审提案」就关掉页面了，
不会等两秒再回来看它变成三条待办。

v724 已经修了工作台的三句（`¥0`、`0 项待处理`、`无临期批次，保持节奏`）
和银行对账一句。这一版把清单剩下的补齐，并在过程中发现两个新病根。

判据是「这句话会不会让人得出错误的经营判断」，不是「它出现在空态位置」。

## 三、两处误判（都值得记住）

### 误判一：`#extra` 插槽被祖先挡住了

初判：报表副表（按供应商 / 调拨明细）的空态在 `loading` 期间也成立，
主表在转骨架、副表说「暂无数据」，同一屏两个相反的结论。

**实际**：整个 `#extra` 插槽位于 `ReportTable` 的 `<template v-else>` 内 ⇒
`loading` 期间**根本不渲染**。我加的 `v-else-if="loading"` 是死代码。

**怎么发现的**：限速实测骨架峰值为 0（不是「有小问题」，是「一次都没出现」）。
如果只看代码就交付，会得到一个「看起来修好了但其实没跑过」的分支。

> 🔴 判「加载中会不会误报」，不能只看 `v-if` 的条件，
> 还要看它的**祖先有没有被 loading 挡住**。后者静态看不清，只能跑。

### 误判二：仓储策略那 2 处

它们确实没有 `v-if="loading"` 保护，但都在 `<template v-else-if="dock.data">` 内 ⇒
只有数据到达后才渲染。`dock.data` 加载中是 `null`，走的是另一个分支。
**「没有 loading 判断」不等于「会在加载中渲染」。**

## 四、三个新病根

### 病根 A：把加载态画成空态样式（12 处）

```html
<div v-if="pendingLoading" class="state-empty">加载中…</div>
```

`.state-empty` 的视觉语言是**虚框 + 居中 + 灰字**，读作「这里是空的」。
文案写「加载中…」也没用 —— 人先看形状再读字。

全站 12 处同构：品牌档案 1、员工档案 2、返利 4、采购单详情 2、
损耗 / 冻结盘 / 盘点 / 盘点差异 / 组合单各 1。另外副驾抽屉 1 处是
用三元表达式在「正在加载」与「还没有」之间切换，两者共用空态样式。

**改法**：换 `.sk-block` 骨架。11 处同构的直接脚本批量替换（保留缩进与条件），
副驾那处拆成两支（`v-if="…&& sessionsLoading"` / `v-else-if="…"`）。

### 病根 B：`loading` 初始值写成 `false`，首帧闪一下错误

`onMounted` 在**首次渲染之后**才执行。所以：

```js
const skillLoading = ref(false)   // 首帧 → 「AI 技能暂时连不上，请稍后重试」
```

界面先报一个错、再改口。这比「晚一点显示内容」糟得多 ——
用户如果刚好在这一帧截图或扫一眼，得到的是错误信息。

**改法**：凡是 `onMounted` 必然会发起的请求，`loading` 初始值取 `true`。

### 病根 C：一个页面里各块独立加载，只保护了其中一块

AiOps 五个卡片、AiHub 四个区块都是 `onMounted` 并发加载，但全都没有 loading 标志
（只有版本那块有 `verLoading`）。这页是**安全位**：备份、审计日志、兜底事件说「没有」，
等于告诉老板数据无人守护。

**改法**：每块一个独立标志，不共用一个 `bootLoading`
—— 共用会让慢的那块把快的几块也拖在骨架里。

## 五、探针自己踩的两个坑

### 坑一：全局限速测出「58 页全无骨架」

第一版用 `emulateNetworkConditions` 限速 350KB / 1100ms，结果 58 页全报「无骨架」。
原因是 3.7 秒内 **SPA 主包 + Shell chunk 都没下完**，Vue 根本没挂载，
既无骨架也无空态。而同一时刻单独测 AiOps 明明有 4 块骨架。

**改法**：只延迟 `fetch('/api/…')` 1100ms，静态资源全速。
这才是「后端慢」的真实场景 —— 而骨架屏本来就是为后端慢设计的。

### 坑二：数骨架只数 `.sk-block`，漏了裸 `.skel-line`

工作台的骨架是 `<span class="skel-line sk-h22">`，没有 `.sk-block` 容器 ⇒
v724 明明加了骨架，这一版探针却把工作台判成「整页无骨架」。

**判据要按「骨架」这个语义收集，不能按我上一版新加的容器类名收集。**

## 八、判据小结（可直接复用）

1. **加载中说出结论，比空白严重得多**。空白让人等一下，结论让人放心走开。
2. **`.state-empty` 不能表达加载中**。它的形状语言是「空的」，文案盖不过形状。
3. **`loading` 初始值取 `true`**，只要 `onMounted` 必然会发那个请求。
   `onMounted` 在首次渲染之后才跑，初始 `false` 必闪一帧错误结论。
4. **判「会不会误报」要看祖先**。`v-if` 条件成立 ≠ 会渲染，祖先可能已被 loading 挡住。
5. **每块独立 loading，不共用**。共用会让最慢的那块拖住最快的几块。
6. **测加载态只能延迟 API**，不能全局限速 —— 后者会让页面根本没挂载，测出假阴性。
7. **骨架判据按语义收集**（`.sk-block` / `.ui-skeleton` / `.skel-line` 都算），
   不能只数自己新加的类名。
8. **「骨架峰值为 0」是重要信号**：不是「小问题」，而是「这段代码没跑过」。
