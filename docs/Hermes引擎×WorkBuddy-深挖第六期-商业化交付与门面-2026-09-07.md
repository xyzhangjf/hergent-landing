# Hermes 引擎 × WorkBuddy 深挖第六期：从「造得稳」到「卖得动」

> 日期：2026-09-07 ｜ 视角切换：前五期把 WorkBuddy 当**工程范本**抄，本期把它当**商业范本**抄
> 审计方式：回代码核对，不采信"已上线"口径

---

## §0 一句话结论

**前五期造的东西，客户一个都看不见；而客户看得见的地方，有 3 个洞。**

更刺骨的一句：**如果你明天签下第一个客户，你现在连给他开号都要 SSH 上服务器敲命令。产品的瓶颈已经从"技术"转移到"你自己"了。**

## §1 为什么本期要换视角

| 期数 | 挖的是什么 | 结果 |
|---|---|---|
| 一~三 | 记忆/反馈/调度/会话机制 | 补齐 AI 交互骨架 |
| 四 | 交付洞察与商业化（报告/配额/画像） | AiHub 落地 |
| 五 | AI 工程化/数据治理/反脆弱（备份/可观测/审计/兜底） | 5 个新路由全上线 |

第五期结束时我自己做了全量审计：40 项建议，完成 32，刻意不做 6。**工程侧的借鉴已经接近边际收益枯竭**——再往下挖就是 Postgres 迁移、全链路 Trace、MCP 市场，这些对一家还没收到钱的公司是纯负债。

所以本期换问题：**WorkBuddy 作为一个"要卖钱的产品"，它的哪些机制是 hergent 完全没有的？**

## §2 现状盘点（全部回代码核对）

### 2.1 客户门面上的 3 个洞

| # | 洞 | 代码证据 | 后果 |
|---|---|---|---|
| **洞1** | **护城河算法不在菜单里** | `Shell.vue:39-49` 侧栏共 9 项，路由表里存在但**侧栏无入口**的有：`/loss`（货损）、`/payroll`（工资）、`/reconciliation`（对账）、`/data-fill` | 你最值钱的三个算法（记忆里定义护城河＝货损/工资/返利/预报），老板要靠猜才能找到 |
| **洞2** | **交付物带不走** | AiHub 报告只能导出 **Markdown**；全站无长图/PDF/可打印成品页（`print_templates.py` 只有 A4 单据级） | B2B 老板不会转发 `.md` 给合伙人/厂家。产品失去自传播能力 |
| **洞3** | **通知有"假通道"** | `salary_send.py:194/212/220` 微信、邮件、短信均为 stub，注释写着 *"In production: use smtplib"* | **这是事故不是缺口**：工资条界面显示"已发送"，员工其实没收到 |

### 2.2 交付链路上的 3 个瓶颈

| # | 瓶颈 | 代码证据 | 卡住什么 |
|---|---|---|---|
| **瓶1** | **开号靠命令行** | 后端无 `invite` 相关代码（grep 零结果）；开号走 `erp_db.staff_account_create` + SSH 上生产机 | 卖 3 家还行，卖 10 家你就是瓶颈。每单都要你手工交付 |
| **瓶2** | **配方无版本、覆盖无解药** | `recipe_io.py` 有 `schema_version`，但**没有内容版本与回滚**；文件头注释自述"只能手动改，覆盖无解药" | 你卖的就是配方。它是**产品资产**，却按运维工具在用 |
| **瓶3** | **新客激活无追踪** | 注册后只有 Login.vue 一次性弹窗；无进度落库、无漏斗数据 | 注册了没上传数据的客户，你不知道有几个、卡在哪一步 |

### 2.3 一个结构性观察

侧栏 9 项，**没有分组标题**，硬编码在 `Shell.vue`，仅靠空行形成三段视觉分组。这意味着：
- 每次加/减功能要改组件源码，无法按租户/角色配置菜单
- 新客户看到的菜单和你的菜单完全一样（含"定时任务""AI 中心"）

## §3 六项提议（按 ★ 价值排名）

> 门面标准（上期确立）：**谁会为它付费？谁会天天看它？答不上来＝运维自保，不许进客户门面。**

---

### ★★★★★ P1. 假通道排雷（事故级，先修）

- **WorkBuddy 借鉴点**：WorkBuddy 的破坏性操作必须显式确认并返回真实结果，绝不让 UI 假装成功。
- **洞在哪**：`salary_send.py` 微信/邮件/短信三个渠道是空壳，界面却统一回"已发送"。
- **怎么做**（最小修复，半天）：
  1. 后端：三个渠道返回 `status: "not_configured"`，不再混入成功态
  2. 前端：发送结果列表显示真实状态——`已送达 / 渠道未启用`
  3. 未启用的渠道在发送前 UI 置灰 + 提示"该渠道未配置，请联系管理员"
- **为什么最优先**：功能缺失客户会问，**假成功客户会信**。工资条没发到员工手里，是信任事故。
- **过门面标准**：✅ 客户天天看，且直接关系信任。

---

### ★★★★★ P2. 护城河算法回门面

- **洞在哪**：`/loss`、`/payroll`、`/reconciliation` 路由已存在，侧栏无入口。
- **怎么做**（1 天，纯前端）：
  1. `Shell.vue` 侧栏加**分组标题**（经营 / 数据 / 算法 / 系统），不再靠空行暗示
  2. 算法页进"算法"分组：货损分析、算工资、对账
  3. ⚠️ **执行前必须真机验证**这三个页面是否功能完整——如果它们是半成品，就不能放上菜单（放个不能用的页面比藏起来更伤）
- **为什么高价值**：**成本几乎为零，卖点从"藏着"变成"看得见"。** 你跟客户讲"我有货损算法"，不如让他自己点开看。
- **过门面标准**：✅ 这就是客户买单的理由本身。

---

### ★★★★ P3. 交付物可带走（可打印成品页）

- **WorkBuddy 借鉴点**：`present_files` —— 任务结束**必须**产出可查看、可下载、可分享的成品；还有"发布为应用"把成果变成一个链接。
- **洞在哪**：报告导出 Markdown 就结束了，`.md` 不是 B2B 的交付物。
- **怎么做**（1.5 天）：
  1. AiHub 报告 + 货损/工资/对账结果页，加「导出成品」→ 生成**自包含 HTML**（内联样式、可打印）
  2. 浏览器打印即得 PDF；或直接接现有 `reportlab` 出 PDF
  3. 成品页带品牌页眉（公司名/日期/口径说明）
- **克制边界**：❌ **不做公网分享链接**。客户经营数据出公网＝合规红线（三条红线里"合规禁踩"）。只做"客户自己下载/打印后转发"。
- **过门面标准**：✅ 老板会把它转给合伙人、发给厂家——这是产品的自传播钩子。

---

### ★★★★ P4. 配方版本化 + 一键回滚

- **洞在哪**：`recipe_io.py` 有 `schema_version`（结构版本），但**没有内容版本**；注释自己写着"覆盖无解药"。
- **怎么做**（1 天）：
  1. 导出 JSON 增加 `content_version`（递增）+ `content_hash` + `changed_at` + 变更摘要
  2. 导入前**自动快照当前配方**到备份表（不是文件，落库，跟着租户走）
  3. 提供「回滚到上一版」——改坏了点一下就回来
  4. 可选：跨客户分发时比对差异（A 客户调好的参数推给 B 客户前先看 diff）
- **为什么它从"运维"升级为"资产"**：配方 IO 上期我判定"本质是运营后台，可砍"。**加上版本和回滚，它就从运维工具变成可交付、可回滚、可定价的产品资产**——这是你唯一能按客户差异收费的东西。
- **过门面标准**：⚠️ 不进门面（客户不配配方），但它是**资产保护**，不是运维自保。

---

### ★★★ P5. 客户开通后台（解你自己的瓶颈）

- **WorkBuddy 借鉴点**：连接器/专家市场的**自助安装**——用户自己点一下就装好，不需要平台方人工介入。
- **瓶在哪**：新客户＝你 SSH 上生产机敲 `staff_account_create`。
- **怎么做**（1.5 天，内部页，非客户门面）：
  1. 后端：把建租户/建号/配角色/设配额封装成 `POST /api/platform/onboard`（复用现有 `platform.py:115 create_tenant` + `register_user_and_tenant`）
  2. 前端：`设置 › 客户开通` 表单——公司名/管理员账号/初始套餐/默认角色 → 一键生成账号密码（可复制）
  3. 开通后自动落一条审计
- **定位澄清**：这是**创始人的后台**，不是运维自保——它直接决定你能不能同时服务 10 家客户。
- **过门面标准**：❌ 不进客户门面（客户看不到），✅ 但解除你本人的交付瓶颈。

---

### ★★★ P6. 新客激活漏斗（可后置）

- **WorkBuddy 借鉴点**：onboarding 是可度量的流程，不是一次性弹窗。
- **瓶在哪**：注册后一次性弹窗，无进度落库。
- **怎么做**（1 天）：`租户激活步骤表`（注册→上传数据→生成首份报告→邀请成员），`设置` 页显示进度条。
- **⚠️ 建议后置**：现在真实外部客户≈0，漏斗没有样本。**等有 3 个以上真实注册客户再做，价值翻倍。** 现在做是给自己造仪表盘看空气。
- **过门面标准**：✅ 客户看得到进度条。

## §4 本期刻意不做（及理由）

| 不做 | 理由 |
|---|---|
| **计费/订阅/支付** | 还没到收费阶段（"先验证→再产品化"），且涉及资质与合规。quota 保持"成本限流"定位，不升格为计费 |
| **公网分享链接** | 客户经营数据出公网＝合规红线。**只做本地下载/打印** |
| **邀请码/试用期的完整商业化流程** | 等真有客户再建，否则是空转 |
| **再新增任何 AI 运维卡** | 上期已定：运维不许再增厚。本期所有提议要么进门面，要么解交付瓶颈 |
| **侧栏配置化（菜单存库/按角色渲染）** | 现在只有你自己一个租户，硬编码够用。等第 3 个客户配置不一样时再拆 |

## §5 建议组合（请你拍板）

| 选项 | 内容 | 工作量 | 说明 |
|---|---|---|---|
| **A**（推荐） | P1 + P2 + P3 | ~3 天 | **全部落在客户门面**：修事故、让护城河可见、让成果可带走。客户能感知到 |
| **B** | A + P4 + P5 | ~5.5 天 | 门面 + 资产保护 + 解除你的交付瓶颈。**要准备签客户就选这个** |
| **C** | 全部六项 | ~6.5 天 | 含 P6 漏斗（建议等有客户再做，现在做了也是空仪表盘） |

我的判断：**选 B**。理由——P1 是事故必须修，P2 成本几乎为零收益极大，P3 是产品自传播的唯一钩子，P4 保护你唯一的定价资产，P5 决定你能不能同时服务多家。**P6 现在做是浪费。**

## §6 验收方式（沿用既定标准）

1. 每项改动后 `py_compile` + 前端 `npm run build`
2. 部署后 SSH 内用 demo 租户 token 跑 E2E（不污染真实数据）
3. 门面类改动（P2/P3）必须 **agent-browser 真机验证**：直连不走代理 + hash 路由 + `.demo-btn` 登录
4. **报告写"已上线"不算数，回生产代码 grep 符号验证**
