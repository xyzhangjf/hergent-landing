# 目标配置 · 作用对象统一为供应商（v702，2026-10-27）

> 需求由老板提出：「优化新建/编辑目标页面，使作用对象的选取维度统一为系统中的供应商。
> 支持按供应商搜索、筛选与多选，明确选中供应商的范围与生效规则，并在页面中提示当前所选供应商；
> 编辑目标时正确回显已绑定的供应商，避免出现非供应商维度的作用对象选项。」
>
> 三条口径由老板当场拍板：
> **多选 = 每个供应商各自独立一条目标 / 保留「品牌目标、商品目标」两个入口、只换作用对象候选 / 存量规则原样保留＋提示改选**。

---

## 一、改造前的真实状态（实测，非印象）

| 项 | 生产实况 |
|---|---|
| 目标规则表 | `rebate_target_rules` 共 **4 条**，`dimension` **全部是 `brand`** |
| 作用对象存法 | `scope_key` = `scope_name` = 品牌名（`简爱` / `蒙牛低温` / `蒙牛鲜奶` / 空=全部） |
| 作用对象怎么选 | 一个纯文本 `<input>` + `<datalist>`，候选来自 **品牌档案（只有 4 条）** 或商品名 |
| 供应商档案 | `contacts` 里 `type='supplier'` **38 条**（福宝低温、恒滋低温、蒙牛鲜奶（7579）各是独立户头） |
| 后端维度白名单 | `DIMENSIONS = (brand, product, category, customer, channel)` —— **没有 supplier**、也没有供应商概念 |
| 品牌名 ↔ 供应商名 | `简爱`、`新希望` 同名可对上；**`蒙牛低温`、`蒙牛鲜奶` 对不上任何单个供应商** |

**为什么必须改**：返利目标是按「厂家户头」谈与结算的，而作用对象只能从 4 条品牌里手打 ——
目标挂不到真实户头上，也无法一次给多个户头设目标。

## 二、方案（为什么不是"新增 supplier 维度"）

老板选了「保留两个入口、只换作用对象候选」，所以：

- `dimension` **仍是 `brand` / `product`**（决定表单形态：品牌页 = 12 月分解 + 阶梯返利 + 报单节奏；商品页 = 按数量冲量）
- **作用对象一律从供应商档案选**
- 后端 **一行没改**（维度白名单、校验、返利计算、月度锁、判重全部不动）

### 2.1 为什么 `scope_key` 存名称而不是供应商 id

这不是省事，是被上下游锁定的：

1. 后端 `routers/rebate_rules.py:1125` 对 `dimension == 'brand'` **强制** `scope_key = scope_name` ——
   前端传 id 进去也会被覆盖成名称。
2. 返利计算按 `(月份, 维度, scope_key)` 把**规则**与**达成**配对，而达成记录（`rebate_achievements`）
   的 `scope_key` 是 Excel 导入的**名称原文**。规则侧若用 id，两边**永远配不上**，返利一笔都算不出来。

⇒ 前后端统一用供应商**名称**作 key。实测第一次跑扇出时我按 id 传，被后端覆盖成名称，
探针因此亮红 —— 这条是被测试逼出来的正确口径，不是设计时想到的。

代价（已知边界）：供应商改名后，旧目标会失联。缓解方式 = 编辑时按 **id → 名称** 双重匹配回显
（现在 key 是名称，id 分支留给将来若要改存 id 的场景）。

### 2.2 多选怎么落地：扇出，不是合并

选 N 个供应商 ⇒ 保存时循环创建 **N 条独立规则**：

- 每条只改 `scope_key` / `scope_name`，其余（目标值、12 月分解、阶梯、报单节奏）原样复制
- 规则名自动加 ` · 供应商名` 后缀（否则列表里 N 行同名，分不出谁是谁）
- 目标值**各为同一个数、互不影响**，之后可分别调整 —— 提示区明确写「不是这几家合计」

**不选合并口径的理由**：合并要求把匹配键从单值改成多值，会牵动
达成导入 / 月度锁 / 判重 / 冲刺看板 / 返利计算 **5 处**，而生产只有 4 条规则、改错的代价是真金白银。

### 2.3 编辑态为什么只允许单选

一条已有记录改成多选 = 「一条变多条」，原记录怎么处理（改？删？拆？）没有任何界面能表达清楚。
⇒ 编辑态单选，要建多个请用「创建」—— 提示区直接写这句话。

## 三、页面与交互

### 3.1 作用对象区（`SupplierPicker.vue`，新增组件）

| 能力 | 实现 |
|---|---|
| 已选提示 | chips 列表（名称 + ×），多个时给「全部清空」 |
| 搜索 | 名称 / 编码，包含即命中、不区分大小写 |
| 筛选 | 按供应商分类（`supplier_category`），选项从候选自身聚合，不建第二份分类字典 |
| 多选 | 新建 = 复选框；编辑 = 单选（点已选项不取消，避免手滑清空变"全部供应商"） |
| 批量 | 「全选当前筛选」（只对筛选结果生效，不会把所有供应商选上） |
| 计数 | 底部「当前筛选 N 个 · 已选 M 个」 |
| 空结果 | 提示去「档案管理 › 供应商档案」建档，不给空白 |

**形态选择**：内嵌展开面板，不是绝对定位浮层。
原因：目标弹窗的 body 是 `.ui-modal-body`（`overflow-y:auto`），任何 absolute 浮层都会被裁剪，
表现为「点了没反应 / 只露半行」。

**不承诺拼音搜索**：生产 38 个供应商的 `pinyin` / `pinyin_first` **实测 0/38 有值**。
字段照读（将来补了自动生效），但界面只写「名称 / 编码」——
探针里有一条反向断言专门守这条，防止以后有人把「拼音」写回 placeholder。

## 四、一个必须记住的坑：候选异步晚到会让回显永久落空

`init()` 在弹窗打开瞬间跑完，而供应商列表由父页**异步**加载。
深链打开（`?edit_rule=N`）或首屏还没拉完供应商时，`init()` 拿空候选去匹配 ⇒
「简爱」这种本来能对上的对象被**永久**判成「未绑定」（`init` 只跑一次、不会重试）。

探针第一次就是这么红的（38 项里 3 项 FAIL，同一个根因）。
修法：监听 `supplierOptions.length`，**只在「还没选过任何供应商 且 正处于未绑定」时**补一次匹配 ——
绝不覆盖用户已经改过的选择。

## 六、已知边界（不藏）

1. **供应商改名会让旧目标失联**（key 是名称，与后端强制口径一致）。改名后请编辑该目标重新选一次。
2. **编辑态不支持多选**：要一条目标覆盖多个供应商，请用「创建」逐个建，或建多条。
3. **多选扇出没有事务**：逐条创建，中途失败会**如实报**「已建 X 条，Y 条没建成：谁、为什么」，
   不会静默当成功，也不会回滚已建成的。
4. **不做合并口径**：跨供应商的目标合计（N 家一起冲一个数）本版不支持。
5. **存量 4 条规则的作用对象未迁移**：仍存品牌名，编辑时提示改选，不强制、不自动改写
   （「蒙牛低温」这类词能匹配到 5 个供应商，自动选错比不选更危险）。
6. **依赖供应商档案**：新供应商要先在「档案管理 › 供应商档案」建档，否则这里选不到
   （空结果文案已指明这条路）。
