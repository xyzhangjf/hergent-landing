# v729 · 行高归一：11 档 → 5 档

> 2026-11-02。纯令牌收口，**不改任何用法、不改任何颜色**。
> 前置：v728 把 475 处散落的行高收成 11 档（0.1 步长）；v729 把这 11 档按**语义**并成 5 档。

---

## 一、为什么 11 档不是一套阶梯

v728 建完 11 档，每个引用都合规、护栏全绿，但回头看引用分布：

| 档 | 值 | 引用 |
|---|---|---|
| none | 1 | 45 |
| flat | 1.1 | 5 |
| title | 1.2 | 8 |
| mid | 1.3 | 6 |
| tight | 1.4 | 37 |
| **snug** | **1.5** | **84** |
| **normal** | **1.6** | **105** |
| **relaxed** | **1.7** | **96** |
| loose | 1.8 | 27 |
| prose | 1.9 | 24 |
| double | 2.0 | 3 |

1.5 / 1.6 / 1.7 三档相邻，13px 下相差 **1.3px** —— 眼睛分不出，却把同类文字分成了三种。
这不是"细腻"，是**选择成本**：下一个人写新样式时要在 5 个近似值里挑，挑哪个都不会被护栏拦住。

> 判据不是"档位多就是坏"，而是：**一个档位若无法用一句人话说清它和邻居的区别，它就不该存在。**

## 二、归并口径（按语义，不按数值就近）

| 语义 | 令牌 | 值 | 吸收 | 理由 |
|---|---|---|---|---|
| 单行居中 | `--lh-none` | 1 | —（45 处） | 图标按钮/单行控件靠行高撑高，**动一下就错位** |
| 标题·大数字 | `--lh-title` | 1.2 | flat 1.1(5) + mid 1.3(6) | 字越大越不需要行距，三档实为一档 |
| 密排 | `--lh-tight` | 1.4 | —（37 处） | 表格单元格：行高直接决定密度，必须独立 |
| 正文 | `--lh-normal` | 1.6 | snug 1.5(84) + relaxed 1.7(96) | 取**中间值**，总位移最小；中文字在 1.6 最舒展 |
| 长段落 | `--lh-loose` | 1.8 | prose 1.9(24) + double 2.0(3) | 说明文字、帮助文本 |

**共 440 处引用**（改档 217 处 + 未动的 none/tight 82 处 + 已有 normal/loose 141 处），
6 个令牌定义从 `variables.css` 删除。

为什么正文取 1.6 而不是 1.5：三者里 1.6 是当前主力（105 处），取中间值让**总像素位移最小**；
若取 1.5，201 处会同时收紧，整站观感一次性变密 —— 那不是"归一"，是"改设计"。

## 三、护栏：锁死阶梯（`checkLineHeightRamp`）

v728 只拦"没用令牌"，v729 补一条**反方向**的护栏：`variables.css` 里的 `--lh-*`
只许这 5 个名字、这 5 个值，多一个/改一个/删一个都报错。

阳性对照（注入坏值自证）：

```
--lh-normal: 1.55   ← 值应保持 1.6
--lh-mid: 1.3       ← 新增档位
```

两条都被抓到，失败时 exit=1。

## 四、视觉回归：24 张，10 页有变化，全部归因

工具：`visual-baseline.mjs` + `visual-diff.py`，12 页 × 浅深，1440×900。
A/A 底噪实测 0 像素，阈值 `px≥800 且 pct≥0.05`。

| 页 | 浅色 | 深色 | 归因 |
|---|---|---|---|
| 工作台 | 4.36% | 4.17% | 今日任务每行 +1px（两行文字的 1.5→1.6），卡片累计 +5px |
| 目标与返利 | 4.94% | 4.92% | KPI 卡片文字 1.5/1.7→1.6，卡片实测 +3px（205→308 底边），下方整块下移 |
| 商品档案 | 0.06% | 0.06% | 仅页脚 1px |
| 采购建单 | 0.09% | 0.09% | 页脚 + 底部条 1px |
| 设置 | 0.08% | 0.08% | 页脚 + 标题行 1px |
| **采购/销售/看板/毛利/周转/资金/往来** | 0.06% | 0.06% | **只有页脚 1px**，表格与卡片零变化 |

**三类现象，逐类核过：**

1. **页脚 1px（24 张全有，恒定 744px，bbox 恒为 (59,873)-(187,886)）**
   备案号那行文字的行盒从 1.5 → 1.6 高 0.1em，基线下移 1px。内容、字号、颜色都不变。
2. **正文密集区 +1~5px**：任务行、KPI 卡片。逐条量过边界（`/tmp/rowedges.py`）：
   `291,306,330,…,392` 完全相同，从 404 起开始 +1、+2、+3 —— 是**逐行累积的位移**，
   不是换行、不是撑破、不是重叠。左右并排看图**肉眼无差**。
3. **表格页零变化**：因为表格走 `--lh-tight` 1.4，本次未动。这也反证了"密排必须独立成档"。

**没有出现的坏现象**（逐页确认）：文字换行变化 0、元素被挤出容器 0、裁切 0、重叠 0、
颜色/对比度变化 0（本次没碰任何色令牌）。

结论：**接受**，基线刷新到 v729。

## 五、这次最贵的一课：探针身份用错了人

第一次抓图，24 张里有 5 页（毛利分析 / 库存周转 / 资金流水 / 往来核销 / 设置）报
「hash 未落在目标路由（实际 #/workbench）」，节点数一律 353~356 —— 与 v724 那次
「token 过期静默回退工作台」的签名一模一样，看起来像 v729 把页面搞挂了。

实际原因：`probe_token.py` 硬编码 `user_id=1`，而 **user 1 是 `admin`（role=admin），
user 2 才是 `boss`**。`REPORT_VIEWER_ROLES = ['boss','supervisor']` ⇒ admin 进不了这几页，
路由守卫 `return { path:'/workbench', query:{ denied } }`，Shell 弹完提示再把 `?denied=`
清掉 —— **URL 里一点痕迹都不留**。

换成 user 2 后 5 页全部正常（525 / 2021 / 2251 / 705 / 204 节点，标题正确）。

已就地加固 `probe_token.py`：

- 默认 `user_id=2`，并在文件头写清原因；
- 插入前 `SELECT role`，**不是 boss 直接 assert 失败**，不给"静默重定向"留机会。

> 通用判据：**"全站都变成工作台"要先怀疑身份，别先怀疑代码。**
> 区分方法只有一条 —— 看是不是**部分页面正常、部分页面全变成工作台**；
> token 过期是**全部**页面都变工作台，权限不足是**部分**。

## 六、没做的（留给后续）

   护栏放行并计数，正解是改 flex 居中。这批不能靠改令牌解决，要逐个改结构。
2. **间距 12 档归一**：6→8(668 处) / 14→16(405) / 10→8|12(758) / 18→16|20(113) / 2·1px。
   风险高于行高（间距直接改变布局密度），建议按上述顺序一版做一档。
