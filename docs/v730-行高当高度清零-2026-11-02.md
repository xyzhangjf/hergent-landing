## 1. 这个技术债是什么

```css
.tb-bell-n { height: 15px; line-height: 15px; }   /* 靠行高把单行文字撑到容器高 */
```

它**不是**文字行距，是「垂直居中」。写法的代价：

- 字号一动（如窄屏 KPI 从 22 降到 18），`line-height:15px` 不动 ⇒ 文字被裁或浮空
- 它和真正的行高声明长得一样，**v728 的迁移脚本一度把它当行距改成倍数**，`.tb-bell-n` 从 15px 变 15.4px
- 所以 v728 的护栏只能「放行 + 计数」，每版都打印 `放行 25 处，P1 应改 flex` —— 一年后还是 25

**v730 把它清到 0 待办。**

## 2. 13 处改成 flex 居中

改法固定：

```css
/* before */
display:inline-block; height:15px; line-height:15px; text-align:center;
/* after  */
display:inline-flex; align-items:center; justify-content:center;
height:15px; line-height:var(--lh-none);
```

| 文件 | 选择器 | 尺寸 | 说明 |
|---|---|---|---|
| `Shell.vue` | `.tb-bell-n` | 15 | 顶栏未读角标，24 页全可见 |
| `LossDashboard.vue` | `.rk-tag` | 20×20 | 行种类标记，grid item |
| `WeatherWidget.vue` | `.wx-hb` | 11 | 休/班角标，absolute |
| `KbdHelp.vue` | `.kbd-chip` | 20/18 | **本来就是 inline-flex**，只需清冗余行高 |
| `SprintChip.vue` | `.sprint-chip` | 20/18 | 同上 |
| `ConnectCenter.vue` | `.cc-action` | 32 | 连接按钮 |
| `LossAccounting.vue` | `.la-badge` | 15 | 体检角标 |
| `InvPurchaseList.vue` | `.ipl-overdue` | 16 | 到货逾期标识 |
| `Forecast.vue` | `.pin .pin-clr` | 16 | 页脚「清除」按钮 |
| `Forecast.vue` | `.listadd-badge` | 14 | 「待上架」角标 |
| `Forecast.vue` | `.listdel-badge` | 14 | 「撤下」角标 |
| `Forecast.vue` | `.edit-tbl .mini-btn` | 16/14 | 编辑表「采纳」 |
| `PurchaseOrderForm.vue` | `.ipn-copy-err-ico` | 22×22 | 复制错误提示圆点 |

**两个改法上的坑（都已避开）：**

1. **`text-align:center` 在 flex 容器里对匿名 flex item 无效** —— 必须换成 `justify-content:center`，只改 display 会让文字左贴。
2. **`.rk-tag` 原本没有 `display` 声明**（是 `<span>`），但它父级 `.rk-row` 是 `display:grid` ⇒ 作为 grid item 被 blockify，`width/height` 才生效。直接加 `display:flex` 是安全的，但**如果它是普通 inline span，加 flex 会让它从「按内容宽」变成「固定 20px 宽」** —— 视觉会变。

## 3. 剩下 12 处：真的不能改，已冻结

`check-tokens.mjs` 新增 `LH_AS_HEIGHT_FROZEN`（按文件冻结数量），把「待办 12 处」变成「已冻结 12 处」。

**A 类 · `.ipn-v` 明细格文本态 × 10**（`InvPurchaseNew` / `ProductCombo` / `PurchaseOrderForm` / `PurchaseReturnForm` 各 2，`wh/Strategy` / `wh/WhItems` 各 1）

```css
.ipn-v {
  min-height:18px; line-height:18px;
  white-space:nowrap; overflow:hidden; text-overflow:ellipsis;
}
```

改成 flex 容器后，文本成为**匿名 flex item**，而 `text-overflow` 只作用于块容器自己的行盒 ⇒ **省略号消失**，长商品名被硬裁。那正是 v417j 加 ellipsis 要解决的「把表格推出横向滚动」。要改必须先包一层内层 `span`，属结构改动，收益不抵风险。

**B 类 · `<select>` × 2**（`EmployeeArchive.vue .hd-sel`、`styles/col-menu.css .cm-sel·.cm-in·.scheme-name-ipt`）

原生下拉不吃 `align-items`（UA 内部渲染 popup，不参与 flex 布局），`line-height` 本来就是它唯一的垂直居中手段。

## 4. 护栏：从「放行计数」改成「冻结清单 + 新债报错」

```js
const LH_AS_HEIGHT_FROZEN = new Map([
  ['src/pages/inventory/InvPurchaseNew.vue', 2],
  ...  // 共 8 个文件 / 12 处
])
```

三条判定：

| 情况 | 结果 |
|---|---|
| 命中清单内、总数不超 | 放行，打印 `12 处已冻结` |
| **新增**（不在清单的文件 / 超出该文件数量） | **报错**，并直接给出改法 |
| 冻结清单**用不满** | **报错** —— 说明那处被删或写法变了，清单该同步收缩 |

第三条容易被忽略：只写「上限」会让清单慢慢变成「允许这个文件里出现 N 处」的空白支票。

**阳性对照（两个方向都自证过）：**

- 往 `LossDashboard.vue` 注入 `.zz-test{height:20px;line-height:20px}` ⇒ `✗ 行高护栏` + exit=1
- 把 `EmployeeArchive.vue` 的 `line-height:24px` 改成令牌 ⇒ `✗ 冻结清单数量对不上` + exit=1
- 还原后 exit=0

## 5. 视觉回归：24 张，排除数据噪声后**零像素差异**

比对 v729 基线 → v730 候选：

```
24 页全部：94 像素，bbox 恒为 (1269, 12, 1284, 22)
```

bbox 一模一样、像素数一模一样 —— 这是**顶栏未读角标**的位置。放大看：

- 基线数字 `68`，候选数字 `69` ⇒ **未读数变了 1**，不是布局位移

**证据链**：如果 flex 改动让徽标位移，红色圆角矩形的边缘一定会跟着变，bbox 会远大于数字所在区域。实测 bbox 只包住数字 ⇒ 红色徽标边界**逐像素相同**。

排除该矩形后重算：**24 / 24 页 0 像素差异**。
