## 1. 为什么这一版收得很小

v727 把字号从 23 档收到 12 档，但留下一条尾巴：`--fs-h2`、`--fs-h3`、`--fs-h4` 三个过渡档。

**字号归并与行高风险不是一个量级**：

| | 行高 | 字号 |
|---|---|---|
| 影响维度 | 只有垂直 | **横向也会变** |
| 后果 | 位移 1–3px | **换行、截断、表格列宽** |
| v729/v730 实测 | 10 页变化，全部无害 | — |

所以这一版只做**两类零风险/低风险的档**，43 处引用的 15px 原封不动。

## 2. 收掉的两档

### A. `--fs-h2` 20px ≡ `--fs-xl` 20px（同值重名）

```css
--fs-xl:20px;    /* 页头 h2 / 二级页头 */
--fs-h2:20px;    /* 等同 --fs-xl，保留是历史引用 */   ← 注释自己都承认了
```

2 处引用：`.page-hd :is(h1,h2)`（全站页面标题）、`.dash-hd h1`（大盘页标题）。

**这是最难被发现的一种债**：用的人只会想「我该用 `h2` 还是 `xl`」，而答案永远是「都一样」。它不影响任何渲染，所以任何视觉回归、任何对比度探针都发现不了。

⇒ 删 `--fs-h2`，2 处改指 `--fs-xl`。**零视觉变化**（同值）。

### B. `--fs-h3` 17px（4 处，夹在 16 与 18 之间只差 1px）

| 位置 | 用途 | 改为 | 理由 |
|---|---|---|---|
| `.cp-ai-img` | 32×32 圆形图标里的字符 | `--fs-lg` 16 | 盒子固定 + flex 居中，字号只影响字符大小 |
| `.wf-icon` | 40×40 方形图标里的字符 | `--fs-lg` 16 | 同上 |
| `.err-title` | 错误边界标题 | `--fs-lg` 16 | 它是标题，归 lg |
| `.arr-stat-i b` | 到货节奏的统计值 | `--fs-stat` 18 | **它本来就是统计值语义**，只是当年写错了档 |

17px 消失。

**结果：12 → 11 档**（11 / 12 / 13 / 14 / 15 / 16 / 18 / 20 / 22 / 24 / 26）。

## 5. 15px 为什么不动：它的语义已经冲突了

`--fs-h4:15px` 有 43 处引用 / 28 个文件，用途分三类：

| 类别 | 约数 | 例子 |
|---|---|---|
| 标题 / 面板头 | ~20 | `.pf-hd`、`.cp-w-title`、`.cc-name`、`.ipd-info-hd`、`.panel-hd b` |
| 统计值加粗 | ~10 | `.sup-stat b`、`.bk-v`、`.ipd-total-amt`、`.pin .big b` |
| 输入框 / 控件字号 | ~5 | `.cmd-input`、`.cp-input`、`.md-item` |

**而它同时还是移动端正文字号**：

```css
@media(max-width:768px){ body{font-size:var(--fs-h4)} }
```

也就是说，同一个令牌既是「四级标题」又是「移动端 body」。这不是"多了个过渡档"，是**两个语义挤在一个名字里**。

任何单向归并都会伤到另一头：

- 全改 16px ⇒ 移动端 body 从 15 涨到 16，正文变宽 6.7%，小屏换行全变
- 全改 14px ⇒ 20 处标题缩水，层级塌陷

**所以它需要一次单独的决策，不是一次机械迁移。** 建议下一版按用途拆分（标题归 16 / 统计归 18 / 移动端 body 单独命名），先只在移动端视口做视觉回归。
