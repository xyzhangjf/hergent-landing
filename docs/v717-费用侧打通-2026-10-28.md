# v717 费用侧打通：从「只有毛利」到「有净利」

> 2026-10-28 ｜ 生产（`/opt/hergent-erp` + `/opt/static`）已部署并重启 ｜ 回滚脚本齐全

## 一句话结论

利润表「只有毛利、没有净利」不是口径问题，是**费用从来没进过账**：全仓只有
`sale / payment / purchase / cogs` 四个自动过账函数，**没有 expense**。
本次把「费用单 → 凭证 → 利润表净利」整条链打通，并顺手修掉三个让这条路走不通的硬故障。

## 改前实测（不是推断）

| 项 | 改前状态 |
|---|---|
| `POST /api/expense-orders` | **500** `TypeError: expense_order_create() takes from 3 to 12 positional arguments but 15 were given` |
| `GET /api/expense-orders` | **500** （路由传 11 个实参给只收 3 个的函数） |
| `GET/POST /api/income-orders` | **500**（同一类缺陷） |
| 「营销 → 费用」页 | 整页打不开（列表接口就 500） |
| 费用凭证 | **不存在**任何 `auto_journal_for_expense` ⇒ 建了单也不进 GL |
| 费用分类科目 | 9 条 `gl_account` **全是 `6602`**（管理费用），客户费用也记管理费用 |
| `GET /api/expense-categories` | 只返回 3 条 `customer` 分类（内部/供应商分类被裁掉，选不到） |
| 利润表「费用明细」卡 | 前端读 `sell_expense/admin_expense/fin_expense/other_expense`，后端**一个都不返回** ⇒ 三行恒为 ¥0.00 |

5000 元占位草稿、`cash_flow` 支出仅 4 条共 956 元（2026-06 测试）。
⇒ **没有任何真实费用数据**，与进货单、银行流水属同一类缺口。

## 做了什么（4 个补丁 + 1 个口径修正）

### v717 主补丁 `tools/hergent/patch_v717_expense_ledger.py`

1. **修 5 个路由**（费用单增/查/付、收入单增/查）
   只传真实存在的参数，**不补幽灵列** —— 被删的 7 个实参
   （`discount_amount / settlement_status / department / settlement_unit_id /
   employee_name / product_info / generation_method`）对应的列在 `expense_orders`
   里一个都没有，补列只会把半成品伪装成能用的功能。
   顺带：列表补 `offset` + `total`（前端一直在传 offset，老后端**收到就丢** ⇒ 翻页永远同一批）。

2. **新增两个过账函数**（`db/queries/finance.py`）
   - `auto_journal_for_expense(eid)`：**借 费用科目 / 贷 2202 应付账款**，幂等（按 `ref_type='expense'` 判）
   - `auto_journal_for_expense_pay(eid, amount, account)`：**借 2202 / 贷 现金或银行**，
     **故意不幂等**——部分付款每笔都是真实现金流出
   - 与 `post_ledger` **解耦**：`post_ledger` 管「往来账 + accounts 余额」，
     `post_journal` 管 GL。舟谱历史费用导入传 `post_ledger=False`（不该凭空造应付），
     但 `post_journal` 仍为 True，否则导进来的费用在利润表上不存在。

3. **科目映射**：9 条 `expense_categories.gl_account` 从「全 6602」改为真实末级

   | 分类 | 类型 | 改后科目 |
   |---|---|---|
   | 陈列费 | 客户 | `64020101` 主货架陈列费 |
   | 促销费 | 客户 | `640201` 客户费用 |
   | 返利 | 客户 | `64020105` 指标达成返利 |
   | 运费 | 供应商 | `66020207` 运输费 |
   | 装卸费 | 供应商 | `66020206` 卸货费 |
   | 办公费 | 内部 | `66020205` 办公用品费 |
   | 差旅费 | 内部 | `660203` 差旅费/交通费 |
   | 工资 | 内部 | `660209` 工资 |
   | 房租 | 内部 | `66020201` 仓库租金 |

   代码里另有一份**按分类名兜底**的映射：`gl_account` 这一列**没有任何 Python 代码创建**
   （属账外裸 DDL），老库有、全新建的租户库可能没有 ⇒ 读它必须容忍缺列。

4. **利润表补四段分解**：`sell_expense`(6601) / `admin_expense`(6602) /
   `fin_expense`(6603) / `other_expense`（6402 客户费用、6403/6405 税金及附加、
   6411/6421、6701/6711/6801/6901）+ `other_revenue`。
   `total_expense` 与 `net_profit` **逐分未变**。

   🔴 加了**逐分硬断言**：四段之和 ≠ `total_expense` 就 `raise ValueError`。
   宁可整页报错，也不让「合计对、明细不对」的账静默流到老板眼前。

   前端「费用明细」卡原来只有 4 行（销售/管理/财务/合计），
   在 `/opt/static` chunk 里**手术式**加了一行「其他费用」（备份 `.bak-v717`）——
   否则 6402 客户费用会让「合计 > 三项之和」，看起来像坏了。

### v717b `patch_v717b_expense_followup.py`（探针抓出的两处漏项）

- `income_order_list` 仍是 3 形参而路由传 8 个 ⇒ 收入单列表继续 500。补齐并同样返回 `{items,total}`。
- `GET /expense-categories` 写死 `("customer")` 只返 3 条 ⇒「新增费用」弹窗里
  选「内部」挑不到办公费/差旅费/工资/房租，选「供应商」挑不到运费/装卸费。改为返回全部 9 条。

### v717c `patch_v717c_report_entry.py`（入口按钮自愈注入）

chunk 里那段注入代码 `setTimeout(..., 300)` 后才找 `#rptBtn_cf`，而实测按钮
**~1000ms** 才出现 ⇒ 条件不成立、整段跳过、按钮**永远不插**。
轮询 20×500ms 实证：`rptBtn_cf` 从 1000ms 起稳定存在，`rptBtn_pnl-gl`/`rptBtn_bs-gl` 全程 false。

⇒ 在 `index.html` 末尾加内联经典脚本（比 module chunk 先跑），
「轮询 + MutationObserver」双保险，严格幂等。恢复「利润表(权责)」「资产负债表(权责)」两个入口。

### v717d `patch_v717d_pnl_fallback.py`（口径修正）

2026-10 只有 1 张采购单（920.00，已收货，有凭证 `1405/2202`），但都不是损益科目
⇒ `has_data=False` ⇒ 回落现金制 ⇒ **把进货当成了费用**，净利显示 **−920**。
老板打开利润表第一眼（默认当前月）就会看到这个错数。

⇒ 回落判据从「该月有没有**损益**凭证」放宽为「该月有没有**任何**凭证」：
有凭证就按权责如实报（损益 0 就报 0），一点凭证都没有才回落。

## 遗留（需要老板拍板 / 需要数据）

1. **费用数据是空的**。链路通了，但 `expense_orders` 仍是 0 张 ⇒ 利润表费用仍是 0、
   净利仍等于毛利。要看到真净利，得有二选一：
   - 现在开始用「营销 → + 新增费用」逐笔录（每天几笔，一个月就有数）；
   - 从舟谱导 9 个月费用明细（导入管线 `zhoupu_expense` 已存在，且现在会一并生成凭证）。
2. **工资还没进账**。`salary_details` 7 行全是 5000 元占位草稿（`status=draft`），
   且没有 `auto_journal_for_salary`。要有真实工资表才能做（借 660209 工资 + 单位社保 / 贷 2211 应付职工薪酬）。
3. **`gl_account` 是账外裸 DDL**：`expense_categories.gl_account` / `requires_receipt`
   两列**没有任何代码创建**，新建租户库可能没有。本次已用「缺列容忍 + 按名兜底」绕过，
   要根治得走 `migrations/patches/`。
4. **付款贷方银行账户是猜的**：`银行` 默认落 `100201 公户：工商银行`。账套里有 7 个银行账户，
   真要精确得让用户选账户（`expense_order_pay` 目前只收账户名，不收账户 id）。
5. **`/opt/static` 仍无源码仓库**：v717（chunk 加一行）/ v717c（index.html 内联）都是
   就地改生产文件 + `.bak-*`，下次有构建产物覆盖时会被冲掉，需要回填到源头。
6. **日记账入口**：chunk 里对 `日记账` 按钮的注入同样依赖 `u.querySelector('div:has(...)')`，
   本次未修（不在 C 范围）。若老板要看那 88,776 行凭证，需另开一版。
