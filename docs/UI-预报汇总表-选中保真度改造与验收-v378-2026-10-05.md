## 0. 一句话结论

> **缺陷不是「列高亮太强」，而是「一条视觉通道被当成两条语义用了」。**
>
> 旧实现把「**选中跨度**」与「**定位指示**」这两个语义，塞进了同一个类名（`sel-col`）、同一个令牌（`--p-bg`）、
> 外加一条整行底（`tr.sel-row > td`）。于是**单击一个格**同时点亮了：整列（列覆盖）、表头强态、整行底 ——
> 用户看到「整行整列都被选中了」，而实际只选了一个格。
>
> 改造＝**拆成两条互不重叠的通道**：
> ① **选中跨度**（`spanHas()`）—— **唯一**允许在数据区上色的依据；
> ② **定位指示**（`isCurColHd()` / `isCurRowHd()`）—— **只画在表头 / 行号格**，中性灰、不进数据区。
>
> 改完后：单击一格 ⇒ 数据区**只有 1 格**有色（155 格青底中 154 格是设计性的「最终合计列」，与本改动无关）；
> 点列头 ⇒ 仍是**整整一列**（Excel 语义，刻意保留）。

## 1. 审核：旧实现到底是怎么画的

### 1.1 三处机制（改造前，`Forecast.vue` 备份 `/tmp/Forecast.vue.bak-before-v378`）

| # | 机制 | 绑定位置 | CSS | 作用范围 |
|---|---|---|---|---|
| A | `td.sel-col` **列覆盖** | `isColHL(ci)` | `.cross-tbl td.sel-col{box-shadow:…,inset 0 0 0 100vmax var(--p-bg)}` | **整列**（`100vmax` 内阴影铺满） |
| B | `th.sel-col` **表头强态** | `isColHL(ci)` | `.cross-tbl th.sel-col{background:var(--p-bg);color:var(--p-ink);font-weight:500;box-shadow:inset 0 -2px 0 var(--p)}` | 表头 1 格（青底＋青字＋加粗＋2px 下划线） |
| C | `tr.sel-row > td` **整行底** | `selected.r === ri` | `.cross-tbl tr.sel-row > td{background:rgba(6,182,212,.05)}` | **整行** |

而旧引擎 `isColHL()` 的判据是：

```js
function isColHL(ci) {
  if (selAxis.value === 'col') return inRange(0, ci)      // 列轴：覆盖整个列区间 ← 正确
  if (selAxis.value === 'row') return false               // 行轴：不画列 ← v377 已修
  return selected.value.r >= 0 && selected.value.c === ci // 单元格轴：画「当前列」← 🔴 病灶
}
```

### 1.2 病灶：**一个令牌承担两种语义**

`--p-bg`（6% 半透明青）同时表达了两件事：

* 「这一块**被选中了**」（机制 A/B/C 在列轴、行轴下）
* 「光标**正停在这一列**」（机制 A/B 在**单元格轴**下）

用户在单元格轴下单击一格，看到的是 **A + B + C 三者叠加**：

```text
单击 1 格  ⇒  整列青底（A） + 表头青底青字下划线（B） + 整行 5% 青底（C）
```

**实测证据（BEFORE，跑在已验证上线的 `dist-v377` 产物上，真机探测）：**

| 场景 | `selArea`（有色数据格） | `colOverlay`（列覆盖格） | `extraCyan`（无通道解释的青底） | 表头强态 |
|---|---|---|---|---|
| 单击 1 格 | **154** | **154** | **35** | **1** |
| 拖选 4×3 矩形 | **162** | **154** | **33** | 0 |
| 点列头 | 154 | 154 | 35 | 1 |
| 点行号 | 37 | 0 | 0 | 0 |

即：**单击 1 个格，界面上有 154 个格看起来是「选中」的** —— 用户的误判是**被设计出来的**，不是错觉。

> 📌 这**不是** bug 而是**上一版的设计决定**。`docs/UI-预报汇总表-列选中态-视觉设计方案-2026-10-04.md`（v376）
> 明确写「列选中 = 表头… ＋ 整列…」。当时的意图是「让列选中看得见」（因为更早的版本列选中**完全没反馈**），
> 修复了「看不见」，但引入了「**过度可见**」。本版是在这两者之间找正确的档位。

## 2. 对标 Excel：选中与高亮规则

Excel 的心智模型是**两套严格分离的信号**，本改造完全照此设计：

| Excel 行为 | 高亮范围 | 对应概念 | 本系统实现 |
|---|---|---|---|
| 单击一个单元格 | **只有该格**有选区边框；数据区其他格**一点色都不上** | 选中跨度 | `spanHas()` ⇒ `td.selected` 1 格 |
| 单击时行号 / 列标变灰 | **只有行头 / 列头**变色（中性灰，非主题色） | **定位指示** | `isCurRowHd()` / `isCurColHd()` ⇒ `cur-row-hd` / `cur-col-hd`，中性灰 |
| 拖选一个矩形 | **恰好矩形内**有底色 | 选中跨度 | `spanHas()` ⇒ `td.range-sel` |
| **单击列标** | **整列**被选中并高亮（含列头），**行号不动** | 选中跨度（整列就是选区） | 列轴 ⇒ `selRange` 满高 ⇒ `inColSpan()` ⇒ **整列** ✅ |
| **单击行号** | **整行**被选中并高亮，**列标不动** | 选中跨度（整行就是选区） | 行轴 ⇒ `selRange` 满宽 ⇒ `inRowSpan()` ⇒ **整行** ✅ |
| 高亮强度 | 选区用主题色；定位用中性灰，**永不混用** | —— | 选中＝青底＋青字＋2px 下划线；定位＝中性灰 16%，**无主色 / 无下划线 / 不加粗** |

**关键取舍（必须说清）**：本改造**刻意保留**「点列头 ⇒ 整列点亮」。
因为在 Excel 里点列标**就是**选中整列，此时 `selRange` 本身就是满高的 ——
**整列高亮是正确的**。要修的从来不是「列头点亮点太多」，而是「**点一个格却点亮整列**」。
所以判据是 **`selAxis` 决定「什么算选中」**，而不是「一刀切禁止列高亮」。

## 3. 新设计：两条互不重叠的通道

```text
                     ┌───────────────────────────────────────────────┐
   selAxis='cell'    │ ① 选中跨度  spanHas('c'|'r', i)                │ → 数据区上色（唯一依据）
   selAxis='row'     │    有矩形(selRange) 用矩形；没有(单击)用活动格 │    · td.selected  (锚点格)
   selAxis='col'     │    ⚠️ 守 selected.r < 0（Esc 后残留）          │    · td.range-sel (矩形)
                     │                                               │    · tr.row-sel  (行轴)
                     │                                               │    · td.sel-col  (列轴)
                     └───────────────────────────────────────────────┘

                     ┌───────────────────────────────────────────────┐
   **仅** selAxis=    │ ② 定位指示  isCurColHd(ci) / isCurRowHd(ri)    │ → **只在表头 / 行号格**
       'cell'         │    = selAxis==='cell' && spanHas(...)          │    · th.cur-col-hd
                     │    ⛔ 永不进入数据区                           │    · tr.cur-row-hd > td.seq-cell
                     └───────────────────────────────────────────────┘
                                        中性灰 rgba(var(--t3-rgb),.16)
                                     无主色 · 无下划线 · 不加粗
```

### 3.1 引擎（`Forecast.vue:7758-7765`）

```js
/* ① 选中跨度：有矩形用矩形、没有（单击）用活动格 —— 唯一允许在数据区上色的依据。
   ⚠️ `selected.r < 0` 守卫不能丢：Esc 之后 selRange 已为 null 而 selected 可能仍有值
      （clearSel 只清 selRange 与轴，不清 selected），少了它冷启动就会点亮一整行/一整列。 */
function spanHas(axis, i) {
  const sr = selRange.value
  if (sr) return axis === 'c' ? (i >= sr.c0 && i <= sr.c1) : (i >= sr.r0 && i <= sr.r1)
  if (selected.value.r < 0) return false
  return axis === 'c' ? selected.value.c === i : selected.value.r === i
}
/* ② 定位指示：只画在表头 / 行号格，且只在单元格轴。表达「我在这一行/这一列」，不是选中。 */
function isCurColHd(ci) { return selAxis.value === 'cell' && ci >= 0 && spanHas('c', ci) }
function isCurRowHd(ri) { return selAxis.value === 'cell' && ri >= 0 && spanHas('r', ri) }
```

### 3.2 样式（`Forecast.vue:12924-12925`）

```css
/* 定位指示（弱通道）—— 用 background-image 叠一层，而**不是** box-shadow。
   🔴 用 box-shadow 会把冻结列的 1px 分隔线（.frozen 的 box-shadow）整条顶掉。
   🔴 令牌 --t3-rgb 两套主题都有定义（浅 161,161,166 / 深 142,142,147）⇒ 深浅自适应、零裸色值。 */
.cross-tbl th.cur-col-hd{background-image:linear-gradient(rgba(var(--t3-rgb),.16),rgba(var(--t3-rgb),.16))}
.cross-tbl tr.cur-row-hd > td.seq-cell{background-image:linear-gradient(rgba(var(--t3-rgb),.16),rgba(var(--t3-rgb),.16))}
```

## 6. 验收：三通道真机 A/B

**方法**：BEFORE ＝ 已验证上线的 `dist-v377` 产物；AFTER ＝ 新构建的 `dist-v378`。

## 7. 探针自身的四个假判据（自我纠错，必读）

本版最有价值的部分之一：**首跑 AFTER 有 6 条失败，全部是探针自己的缺陷，不是产品缺陷。**
三条判据在 AFTER 侧**不可能通过**（恒假 / 恒零），若不复核就会得出「改造失败」的错误结论。

### 7.1 假判据①：`__sig` 看不见 `background-image`

```js
// 旧
window.__sig = function (el) { var s = getComputedStyle(el); return s.backgroundColor + ' | ' + s.boxShadow }
```
弱指示器用 `background-image` 渐变 —— 这两项**一个都不变** ⇒ 该指纹对它**永久失明**，
「有视觉差异」这条断言在 AFTER 侧**恒假**（P2/P7 共 3 条假红）。
**修**：补 `backgroundImage`，并新增独立通道 `__eff`（有效绘制色），不再依赖单一属性。

### 7.2 假判据②：`nrWeak` 的类挂在 `<tr>` 上，探针却在 `<td>` 上找

```js
o.nrWeak = t.querySelectorAll('tbody td.seq-cell.cur-row-hd').length   // 恒 0
```
模板是 `<tr :class="{'cur-row-hd': …}">`、CSS 是 `tr.cur-row-hd > td.seq-cell` ——
**类在 `<tr>` 上**。该计数器与 CSS 对错**无关地恒为 0**（P2/P3 共 3 条假红）。
**修**：改为 `tbody tr.cur-row-hd > td.seq-cell`；`nr_same` 改查 `__seq(r).parentElement`。

### 7.3 假判据③：像素采样点被表头里的白底输入框 pill 盖住

表头不是纯文字标签，而是**白底输入框**（`cell-input cell-cust`：客户名 + 删除按钮）。
中心众数读到近白 `254`，与底色 `250` 混在一起 ⇒ 冷选两侧读数相同 ⇒ 假绿。
**修**：改采单元格**顶部内边距带**（`top+4`，在白 pill 之上、边框之下的纯底色带）。

### 7.4 同族陷阱（操作纪律，已记进技能）

> 🔴 **探针的 `HELPERS` 是模板字符串** ⇒ 里面
> ① **禁止出现反引号**（本会话踩到第 6 次）；
> ② **正则的反斜杠必须双写**（`\\(` `\\)` `\\d` `\\s`）——
> 单写会被求值阶段吃掉：`/rgba?\\(([^)]+)\\)/` 变成 `/rgba?(([^)]+))/`，
> `m[1]` 拿到 `"(250, 250, 250"`（带左括号）⇒ `parseFloat` = NaN ⇒ 有效色算成 `NaN,250,250`。
> 本文件既有正确写法见 `__bigInset` / `__esc`。
>
> 🔴 **任何新判据上线前必须自问：它在 AFTER 侧有没有可能通过？** 恒假判据比没有判据更危险。

### 7.5 假判据④（**上线后才暴露**）：第三态标签静默落回 BEFORE 侧期望

**症状**：上线后拿同一支探针直打生产（标签不是 `BEFORE` 也不是 `AFTER`，而是 `LIVE`），
`exit=1`，**19 条 ★ 断言全红**，例如：

```
★P4 点列头：选的是列，就不许有行被点亮（基线外新增青底）  期望="before"  实测=0
★P5 切回单元格轴：整列底消失                             期望=154      实测=0
```

而同一时刻 `[LIVE] 关键信号 = {"cellClick":{"sel":1,"col":0,...},"colClick":{"sel":154,"col":154,"extra":0,"hs":1}}`
—— **逐项与本地 AFTER 侧读数完全相同**。也就是说：**被测对象是对的，判据错了。**

**根因**（判据侧，不是产品侧）：

```js
const IS_AFTER = LABEL === 'AFTER'   // ← 三元只有两侧，第三态必落入 else
```

`BEFORE / AFTER` 是设计的**二态**模型，但上线后必然出现**第三态**（`LIVE`＝直打生产、`PRE`＝预发、`POST`＝灰度）。
二元判断把「不是 AFTER」一律当成「是 BEFORE」⇒ 拿**改造前**的期望去量**改造后**的线上，于是全部反着判。

**修**（语义应当是「**只有显式 BEFORE 才是改造前**」，默认侧为「已改造」）：

```js
const IS_AFTER = LABEL !== 'BEFORE'
```

复跑 ⇒ **76/76 通过，exit=0**（76 = 原 74 + 本次新增 2 条零写入断言）。

> 🔴 **推论（写进技能）：任何「二态判据」在迎来第三态输入时，默认落哪一侧必须先想清楚。**
> `x === A ? before : after` 这种写法在探针里是**定时炸弹**——它不会报错，只会在你第一次
> 拿它量新环境时给你一整屏假红，且假红的形态**酷似真缺陷**。判据的取值域必须与它将面对的
> 输入取值域**同宽**；做不到时，选择**fail-safe 的一侧**（把未知态当"新"而不是当"旧"）。
