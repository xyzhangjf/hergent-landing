# 返利整合 · 阶段2 落库设计：品牌目标「金额层 + 返利层」两层结构

> 日期：2026-09-06 ｜ 状态：待实现 ｜ 关联：阶段1（删 3 维度 + 改名，已上线）

## 1. 背景与口径（已固化 MEMORY.md）

- **品牌目标(金额) = 厂家年度合同的月度分解**，同一数据源，不是两个独立对象。
  例：蒙牛年度 1200 万 → 8月 110 万 / 9月 90 万，品牌目标就是这两个月值。
- **月返以品牌月度目标为基准**（金额层固定，基本不变）；**返利率月度浮动**（本月返 10 个点、下月返 8 个点）。
- 结论：品牌目标 = **金额层(年框+12月分解,固定) + 返利层(按月一条,浮动)**，两层分开存。
- 单品目标天然按月一条（目标+坎级都按月），独立体系，不动。
- 用户已拍板：返利规则放「目标规则」里；品类/客户/渠道 3 维度已删（阶段1）。

## 2. 现状（代码调研结论）

| 对象 | 存储 | 现状问题 |
|---|---|---|
| 品牌/单品目标规则 | `rebate_target_rules`（1 条=1 品牌/1 单品×1 目标值+1 套返利） | 品牌目标「金额+返利绑死在一行」，无法表达「金额年框固定 + 返利按月浮动」 |
| 年度合同 | `rebate_contracts` + `rebate_contract_months`(月度 target_amount) + `rebate_accruals`(计提) | 品牌目标金额其实已有月度分解载体，但与规则表割裂、双录入 |
| 达成填报 | `rebate_achievements`(period_month 键) | 正常，不改 |
| 冲刺看板 | Forecast.vue 前端拉 `/api/rebate-rules` 后按生效月过滤计算 | 目标取 `rule.target_value` 单值，不识月度分解 |
| 计提 | erp_db.accrue_rebate 按合同挂规则按月算 | 阶段3 引用品牌目标后再适配 |

## 3. 落库设计（兼容旧数据，新老并存）

`rebate_target_rules` 增 2 列（JSON 字符串，租户库三处补丁）：

| 新列 | 格式 | 语义 |
|---|---|---|
| `monthly_amounts` | `{"01":1100000,"08":1100000,"09":900000,...}` 键=月份(01-12)，值=当月目标金额(元) | 金额层月度分解；缺省月 = 无目标 |
| `monthly_rates` | `{"01":0.10,"08":0.10,"09":0.08,...}` 值=当月返利率(小数 0.1=10%) | 返利层月度浮动；缺省继承最近前月，再缺省用顶层 `rebate_rate` |

- `target_value` 仍存**年度总额**（金额口径，元），列表/卡片顶部展示年框用。
- 顶层 `rebate_rate` = 全年兜底率（未在 monthly_rates 指定的月用它；与老数据兼容）。
- 带 monthly_* 的品牌规则建议 `effective_start/end` 自动覆盖该自然年，`period_type='year'`。
- **旧数据兼容**：老规则无 monthly_* 列值 → 消费端一律回退 `target_value/rebate_rate`，行为零变化。

## 4. 消费端取月解析（同一契约，前后端各一份）

输入：规则 dict + 目标月份 `ym`(YYYY-MM)。输出：当月生效的 (目标金额, 返利率) 或「当月无目标」。

```
目标金额 = monthly_amounts[MM] 若有值 → 用之；否则 target_value（年框，兼容老数据）
返利率   = monthly_rates[MM]   若有值 → 用之；否则向前找最近有值的月 → 否则 rebate_rate(顶层)
```

适配点：
1. **rebate_rules.py** `simulate / simulate-batch`：支持 `month` 入参，按月度解析后再试算。
2. **Forecast.vue rebateSprint**：target 从「单值」改为「当月 monthly_amounts」，gap/均单不变。
3. **列表/卡片**：带月度分解的品牌规则展开 12 月小表（金额/返利/达成?达成另拉）。

## 5. 变更清单

**后端 hergent-erp**
- erp_db.py：租户补丁循环 + 新建租户 init + 主库 _safe_migrate 三处补 2 列（幂等）。
- routers/rebate_rules.py：
  - `_row_to_dict` 输出 `monthly_amounts/monthly_rates`（解析为对象，含 is_monthly 标记）；
  - `validate_rule`：接受可选 monthly_*，校验月份键 01-12、金额≥0、返利 0~1；
  - `create_rule/update_rule` SQL 带 2 列；
  - simulate 支持 month。

**前端 hergent-cn-v2**
- pages/Rebate.vue（品牌维度表单+列表+详情）：
  - 品牌+年度形态增加「月度分解（金额层）」与「月度返利（返利层）」12 行编辑器；
  - 提供「全年均分 / 差额补平」快捷（金额层）；「继承上月 / 全月相同」快捷（返利层）；
  - 列表规则卡片带月度标记，展开看 12 月明细。
- pages/Forecast.vue：rebateSprint 目标取当月金额（缺省回退 target_value）。

## 6. 不做（边界）
- 达成填报/计提/结算仍按现有链路；返利结算引用品牌目标 = **阶段3**。
- 单品维度不加月度分解（天然按月一条，保持现状）。
- 阶梯(坎级)返利不并入品牌月度（返利层只有比例；坎级体系属于单品，用户口径如此）。

## 7. 风险与验证
- 改动面集中在 rebate 家族；老规则无 monthly_* → 全链路回退旧值，须回归：规则列表/试算/冲刺看板旧品牌规则目标不变。
- 验证：本地 py 校验 + 前端构建 + 生产 E2E（demo 租户建一条带月度分解的品牌规则 → 列表/试算/冲刺看板取数正确）。
