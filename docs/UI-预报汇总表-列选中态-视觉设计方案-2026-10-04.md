## 0. 一句话结论（推荐方案 A）

**列选中 = 表头「青底 + 青字 + 2px 主色下划线」＋ 整列「左右 1px 主色边线 + 6% 半透明青覆盖」，全部复用现有令牌，用 `box-shadow` 实现（不抢背景），与「行选中」「当前格」形成三套互不混淆的视觉语言。**

---

## 1. 问题定位（代码佐证）

用户反馈：编辑态下点选某一列「功能生效、视觉无感知」。逐行核对后，**列选中视觉只做了一半**：

| 对象 | 模板绑定的类 | 现有 CSS（Forecast.vue） | 实际效果 |
|---|---|---|---|
| 表头 `<th>` | `'sel-col': selected.r>=0 && selected.c===ci`（:1155、:1161） | `.cross-tbl th.sel-col{background:var(--p-bg);color:var(--p-dark);font-weight:600}`（:12494） | ✅ 有：**只有一点 6% 淡青** |
| 表体 `<td>` | **never** —— 主档 td 只绑 `selected`（:1192）、数量 td 只绑 `selected`（:1253） | `.cross-tbl td.sel-col{background:var(--p-bg)}`（:12495） | ❌ **死规则**：无任何 td 带 `sel-col` |
| 整行 | `tr.sel-row`（:1191） | `.cross-tbl tr.sel-row > td{background:rgba(6,182,212,.05)}`（:12493） | ✅ 有：整行 5% 淡底 |
| 当前格 | `td.selected`（:1192、:1253） | `.cross-tbl td.selected{outline:2px solid var(--p);background:var(--p-bg);z-index:3}`（:12492） | ✅ 有：仅单格 |

**根因三条**：
1. **不对称**：`行`有整行反馈（`.sel-row`），`列`却只有表头一点淡青 ⇒ 用户扫表体时感知不到「选了哪列」。
2. **死 CSS**：`td.sel-col` 规则存在但从不生效（模板没绑）。
3. **太淡**：即便表头，`--p-bg` 仅 6% 透明青，在白底/深底上都接近"没有"。

> ⚠️ 术语界定：本项目代码里**没有独立的「列选中」状态**，唯一的列级状态是从**当前选中格**派生的 `selected.c`（`Forecast.vue:5554` 注释："统一列索引"）。因此本方案的「列选中」= **当前选中格所在的那一列**（无论是点击、方向键导航、还是右键表头菜单带出的目标列）。

---

## 2. 设计目标

1. **一眼可辨**：不放大、不靠颜色猜——列选中必须**同时有位置与颜色两类线索**。
2. **不与语义色抢戏**：数量列有热力色（`heatStyle` inline 底色）、错误格有红底（`.invalid`）、警告行有红底（`.cond-warn`）——列高亮**不得覆盖**它们。
3. **三态正交**：行选中（面）/ 列选中（带）/ 当前格（框）三者叠加仍能各自辨认。
4. **零新令牌、零新类**：只复用 `UI-SPEC §1` 已定义的令牌与既有 `sel-col` 修饰符（§6.1）。

---

## 3. 方案对比

| 方案 | 做法 | 优点 | 风险 | 结论 |
|---|---|---|---|---|
| **A（推荐）** | 表头下划线 + 整列**左右边线** + **6% 半透明青覆盖**（`box-shadow` 实现） | 识别度最高；与行/格正交；**不抢背景**（热力/错误色仍可见）；暗色自动适配 | 无 | ✅ **采用** |
| B | 整列直接加实底 `background:var(--p-bg)!important` | 实现最简单 | 🔴 **会抹掉数量列热力色、红/琥珀警告色**（`!important` 盖过 inline 与语义色）⇒ 反而丢信息 | ❌ 不采用 |
| C | 仅表头加粗 + 左侧色条（Excel 式列标），表体不动 | 改动最小 | 表体仍难感知；"功能可感知"目标不达标 | ❌ 不采用 |

**为什么 A 用 `box-shadow` 而不是 `background`**：数量列的底色来自 **inline `heatStyle`**（:1253，值≥100 时返回 `{background:var(--heat-*)…}`），inline 优先级高于样式表；要覆盖它只能 `!important`，而那会一并压掉语义色。改用 `box-shadow` 的 **inset 半透明覆盖**（rgba 带 alpha），是在**既有底色之上叠加一层可透穿的青**——底色依旧可见，且**完全不参与优先级竞争**。本项目已有同样的手法：`.new-row` 用 `box-shadow:inset 3px 0 0 var(--p)`、`.frozen` 用 `box-shadow:1px 0 0 var(--bd)`。

## 4. 视觉规格（精确到令牌）

### 4.1 表头（`th.sel-col`）——"这是哪一列"

| 属性 | 取值 | 令牌 |
|---|---|---|
| 底色 | `var(--p-bg)`（浅 `rgba(6,182,212,.06)` / 深 `.10`） | 现有 |
| 文字色 | `var(--p-dark)`，字重 `500` | 现有 |
| **选中标识** | **底部 2px 主色下划线**：`box-shadow: inset 0 -2px 0 var(--p)` | 现有 |

> 下划线是本方案的**核心辨识点**：它与全站「激活态」的既有语言**逐字同源**——见 `UI-SPEC §2.1` 的 `.btn.on`（浅底+主色字+主色边）与 `variables.css:390` 的 `.main-tab.on::after`（**2px 主色下划线**）。列选中=表头激活态，沿用同一语法，用户无需重新学习。

### 4.2 表体整列（`td.sel-col`）——"这一列被选中"

| 属性 | 取值 | 令牌 |
|---|---|---|
| 整列半透明覆盖 | `box-shadow: inset 0 0 0 100vmax var(--p-bg)` | 现有（rgba 带 alpha ⇒ 透穿热力/错误色） |
| 左边缘线 | `inset 1px 0 0 var(--p-border)` | 现有（浅 `rgba(6,182,212,.28)` / 深 `rgba(34,211,238,.30)`） |
| 右边缘线 | `inset -1px 0 0 var(--p-border)` | 现有 |

**合成写法（一行，三个 inset 阴影叠加）**：
```css
.cross-tbl td.sel-col{
  box-shadow:
    inset 0 0 0 100vmax var(--p-bg),
    inset  1px 0 0 var(--p-border),
    inset -1px 0 0 var(--p-border);
}
```
> 两条竖边线是「列」独有的识别特征：**行是"面"（通铺淡底）、列是"带"（左右两条边）**，即使行列交叉也不会混淆。

### 4.3 当前格（`td.selected`）——保持不变

沿用现有 `outline:2px solid var(--p); outline-offset:-2px; background:var(--p-bg); z-index:3`（:12492）。它比列底更强（实底线 + 2px 完整描边），自然"浮"在列底之上，无需改 z-index。

### 4.4 行号列 / 冻结列

- 行号列（`.seq-cell`）不属于任何数据列，**不参与列高亮**。
- 冻结列（`.frozen`，`z-index:6`）：被选中时同样加 `sel-col`；其左右边线画在 td 内部（`inset`），不会破坏冻结列的右侧分隔线（`.frozen` 的 `box-shadow:1px 0 0 var(--bd)`，:12046）。

## 5. 不同编辑状态下的显示效果

代码里编辑态有两个正交开关：`cellTyping`（导航态 / 输入态）与 `selRange`（是否拖框选区）。列高亮的规则如下：

| # | 编辑状态 | 表头 | 表体整列 | 当前格 | 说明 |
|---|---|---|---|---|---|
| 1 | **导航态**（单击/方向键选中，未输入） | 青底+青字+下划线 | 边线 + 6% 覆盖 | 2px 描边 | 默认态，列高亮**常亮** |
| 2 | **输入态**（双击 / F2 / 已选中格再按一次，正在输入） | 同 1 | 同 1 | 同 1 | 🔴 **绝不因输入而消失**（否则又回到"感知不到"） |
| 3 | **拖框选区存在**（`selRange`） | 同 1 | 边线**保留**；6% 覆盖让位给选区实底（`.range-sel`，12%） | 描边保留 | 选区是更强的"当前操作对象"，覆盖层退让，**但列边线不消失** |
| 4 | **右键菜单打开**（`hdrCtx.show`） | 被操作列 = `hdrCtx.key`，一并高亮 | 同 1 | — | 增强：让用户明确「我在操作哪一列」（可选，见 §8.3） |
| 5 | **无选中**（`selected.r < 0`） | 无高亮 | 无高亮 | 无 | 与现状一致 |
| 6 | **表体全屏**（`gridFullscreen`） | 同 1 | 同 1 | 同 1 | 全屏是布局变化，不影响列高亮 |
| 7 | **只读/查看态**（`!editMode`） | 不适用 | 不适用 | 不适用 | 本方案只作用于编辑网格 |

## 6. 叠加与优先级（冲突裁决）

列高亮与既有状态的叠放规则（**从强到弱**，强者保留、弱者退让但可共存）：

| 优先级 | 状态 | 视觉 | 与列高亮的关系 |
|---|---|---|---|
| 1 | 错误格 `.invalid` / `.cond-warn` | 红底（`background:…!important`） | 🔴 **红底不被夺**；列的两条边线（`box-shadow`）**照常叠加在上** |
| 2 | 拖框选区 `.range-sel` | 12% 青实底（`!important`） | 覆盖层让位；边线保留 |
| 3 | 当前格 `.selected` | 2px 描边 + 6% 底 | 浮于列底之上 |
| 4 | **列选中 `.sel-col`（本方案）** | 边线 + 6% 覆盖 + 表头下划线 | —— |
| 5 | 行选中 `.sel-row` | 整行 5% 底 | 列带与行面正交，可同时显示 |
| 6 | 热力色（数量格 inline `heatStyle`） | 琥珀/橙/红底 | 透过 6% 青覆盖仍可辨（**不被抹除**） |
| 7 | 新行 `.new-row` | 9% 青底 + 左侧 3px 竖线 | 与列边线叠放，不冲突 |

**关键约束**：字段级/行级"错误"永远压过"选中"——用户不该因为"选中了一列"而看不到红格。

## 7. 与 UI 设计规范的衔接（逐条）

| 规范条目 | 本方案如何衔接 |
|---|---|
| §1.1 品牌色令牌（禁止裸写颜色） | 只用 `--p` / `--p-dark` / `--p-bg` / `--p-border`，**无裸色值**；暗色由 `:root.dark` 同名令牌自动覆盖（`variables.css:201-202`） |
| §1.2 中性色 | 未新增背景/文字色 |

| §2.1 按钮激活态 `.btn.on` | 表头选中态 = 浅底 + 主色字 + 主色边，**同一语法** |
| §2.5 页内 Tab `.main-tab.on` | 表头 2px 主色下划线与其**逐字同源**（`variables.css:390`） |
| §4 交互状态 | 本方案补的是规范缺口的「**选中态**」——此前只有 default/hover/focus/disabled/loading/error |

| §6.1 命名与修饰符 | 复用既有 `sel-col` 修饰符，不新增类名 |
| §6.2 同一视觉语言不写第二份 | 与 `.sel-row`（行）、`.selected`（格）**同一青系语言、不同形态**，不复制视觉 |
| §7.1 类差集审计 | 不新增类 ⇒ 差集仍为 0 |

## 8. 建议的最小实现（供实施时参考，本次不改代码）

### 8.1 模板：给表体 `td` 补 `sel-col`（2 处）

- **主档列**（`Forecast.vue:1192`）：在 `:class` 对象里追加
  `'sel-col': selected.r >= 0 && selected.c === ci`
- **数量列**（`Forecast.vue:1253`）：追加
  `'sel-col': selected.r >= 0 && selected.c === visibleCols.length + ui`
- 表头两处（`:1155`、`:1161`）**已有**，无需改。

### 8.2 样式：改写两条既有规则（`Forecast.vue:12494-12495`）

```css
/* 原：.cross-tbl th.sel-col{background:var(--p-bg);color:var(--p-dark);font-weight:600}
       .cross-tbl td.sel-col{background:var(--p-bg)} */
.cross-tbl th.sel-col{
  background:var(--p-bg);color:var(--p-dark);font-weight:500;
  box-shadow:inset 0 -2px 0 var(--p);          /* 新增：2px 主色下划线 */
}
.cross-tbl td.sel-col{
  box-shadow:                                   /* 改：box-shadow 覆盖，不抢 background */
    inset 0 0 0 100vmax var(--p-bg),
    inset  1px 0 0 var(--p-border),
    inset -1px 0 0 var(--p-border);
}
```
> 只改这 2 条 + 模板 2 处，**无需新增令牌、无需新增类名**。

### 8.3（可选增强）右键菜单打开时高亮目标列

把 `hdrCtx.show` 的列也纳入 `sel-col` 判据，用户在列菜单里操作时明确"目标是哪一列"：
`'sel-col': (selected.r>=0 && selected.c===ci) || (hdrCtx.show && hdrCtx.key === c.key)`

### 8.4（可访问性）`aria-current`

选中表头 `<th>` 加 `aria-current="true"`（`selected.r>=0 && selected.c===ci` 时），键盘/读屏用户也能获知当前列。

## 9. 验收判据（可失败）

1. **可见性**：编辑态选中任一列后，该列**表头有下划线、表体左右有边线**；在 100% 缩放下截图，列边界像素可辨（非主观"感觉"）。
2. **不夺语义色**：选中含热力色（数量≥100）或错误格（`.invalid`）的列后，**这些格的底色仍为原热力/红色**（对比像素：列的青覆盖叠加、原色未被替换）。
3. **三态共存**：同一屏内「行选中 + 列选中 + 当前格」三处标记可同时拍到、互不遮挡。
4. **输入不消失**：进入编辑格的输入态后，列高亮仍在（无闪断）。
5. **暗色一致**：`:root.dark` 下青覆盖与边线自动变亮（由令牌覆盖），无需单独写样式。
6. **类差集为 0**：实施后跑 `UI-SPEC §7.1` 类差集审计，差集仍为空；`grep 'sel-col'` 命中 = 模板 4 处 + CSS 2 处。

## 附：暗色模式

`--p-bg` 在 `:root.dark` 下为 `rgba(6,182,212,.10)`、`--p-border` 为 `rgba(34,211,238,.30)`（`variables.css:201-202`）。本方案**全部走令牌**，因此暗色下：覆盖层自然加深、边线自然提亮，**零额外代码**。这也是必须用令牌、不得裸写颜色的实证理由。
