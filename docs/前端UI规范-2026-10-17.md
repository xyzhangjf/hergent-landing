## 一、通用组件层（已落地，Phase 0.1）

全部位于 `src/components/`，自包含 scoped、复用 cn-v2 token 体系（`--p/--t1/--dan`），**不依赖 hergent-admin 旧 token**。

| 组件 | 用途 | API 要点 |
|---|---|---|
| `Modal.vue` | 通用弹窗 | `:show` + `title` + `width`（px）+ `@close`；已内置 ESC / Tab 焦点陷阱 / 背景滚动锁 / aria-modal / 焦点归还 |
| `ConfirmDialog.vue` | 危险操作确认 | 红色危险按钮 + busy 防重复 |
| `PromptDialog.vue` | 输入型弹窗 | 单行 input（Enter 确认）+ 可选 textarea |
| `EmptyState.vue` | 空态 | `title` + `desc` + `icon` + `actionLabel` + `actionIcon` + `@action` |
| `Skeleton.vue` | 骨架屏 | `:rows`；主 loading 用 |
| `StatusBadge.vue` | 状态徽章 | **待接线**（见 §五） |
| `Breadcrumb.vue` | 面包屑 | **待接线**（见 §五） |

**全局命令式弹窗（store）**：`confirm(msg)` / `prompt(msg, opts)` 返回 Promise，App.vue 挂全局宿主。**新增弹窗一律走这两个命令式入口或 Modal 组件，禁止再写 `window.confirm` / `window.prompt`。**

**已收敛**：v539 全站 `window.confirm` 22 文件约 40 处；v540 全站 `window.prompt` 3 处。剩余白名单仅 Forecast.vue（13800 行高风险件，Phase 3 拆分时一并收敛）。

## 二、token 红线（Phase 0.3 结论：别名是兼容层，不是技术债）

### 2.1 canonical 令牌（值的唯一源，改它全站生效）

`src/styles/variables.css` 的 `:root`（浅色）+ `:root.dark`（深色）是**单一可信源**：

- **品牌**：`--p` / `--p-dark` / `--p-deep` / `--p-ink`（强调态文字）/ `--p-bg` / `--p-border`
- **语义**：`--suc` / `--dan` / `--war` / `--purple` / `--teal`
- **图表**：`--chart-1` ~ `--chart-8` + `--chart-up`（涨红）/ `--chart-down`（跌绿）等
- **中性面**：`--bg` / `--bg2` / `--bg3` / `--bg4` / `--t1` / `--t2` / `--t3` / `--bd` / `--border-subtle`
- **层级**：`--z-*`（含页面级 `--z-page-*`）
- **字号/间距/圆角/阴影**：`--fs-*` / `--sp-*` / `--radius-*` / `--shadow-*`

### 2.2 兼容别名（v362 有意保留，**不要清理**）

`--border` / `--bd1` / `--bd2` / `--b2` / `--bg1` / `--ok` / `--danger` / `--err` / `--warn` 等，是「引用旧名」的兼容层，值全部指向 canonical 令牌。**清理它们会让引用旧名的页面静默失效**——这是 v362 明确记录的「反清理」教训。

### 2.3 三条铁律

1. **新增颜色必须走 token，不许在页面写 `#hex`**（除非是第三方品牌识别色 / 图表数据系列色，见 §2.4）。
2. **`--radius-*` / `--fs-*` / `--sp-*` 跨主题共用**（在 `:root` 定义、dark 块不重复）——它们本就不随明暗变化，**「深色缺失」是伪命题**。
3. **图表组件（`src/components/chart/`）导出 PNG 必须内联实际色值**：孤立文档拿不到 `:root`，不内联即全黑块（v491 教训）。图表渲染层颜色只写 `var(--chart-N)`，但导出前要解析成实际 hex。

### 2.4 硬编码色值区分（「158 行」是印象派）

真实情况：大部分 `#hex` 是 `var(--x, #hex)` 的 **fallback 兜底值**（合法、安全）；真正无 `var` 包裹的，几乎全是**有意为之的语义色**，归一反而破坏设计：

- **第三方品牌识别色**（ConnectCenter 的畅捷通橙/金蝶青/舟谱紫/飞书蓝/钉钉蓝）——不可归一
- **角色徽章色**（EmployeeArchive 的 admin/boss/accountant/sales 等）——不可归一
- **图表数据系列色**（LossDashboard 的 `--c-gross/--c-net/--c-ded/--c-rate`）——不可归一

## 三、图标规范（Icon.vue 是唯一图标源）

### 3.1 铁律

1. **图标一律走 `<Icon name="..." :size="N" />`**，禁止手写内联 `<svg>`（Shell.vue 已注明此约定）。
2. **新增图标必须先查 `ICONS` 表**（`Icon.vue`），名字不存在会**静默兜底成齿轮**（`ICONS[name] || ICONS.settings`）——构建零报错、探针零报错，只有肉眼能发现。
3. **新增图标必须「逐字转 path」**：Icon 组件只渲染 `<path>`，不识别 `<circle>` / `<line>` / `<polyline>` / `<rect>`。转换规则：
   - `<circle cx cy r>` → `M cx+r cy a r r 0 1 1 -2r 0 a r r 0 0 1 2r 0Z`
   - `<line x1 y1 x2 y2>` → `M x1 y1 l (x2-x1) (y2-y1)`
   - `<rect x y w h rx>` → 圆角矩形 path
   - **对不上就新增一个原样图标，别在图库里凑「差不多」的**（「差不多」= 静默换视觉）。

### 3.2 内联 SVG 收敛的「零视觉变化」纪律（v545 实践）

收敛内联 SVG → Icon 前，必须逐项检查三类**替换成本**，有则保留原样：

| 依赖 | 例子 | 处置 |
|---|---|---|
| `stroke-width ≠ 2` | ProductTarget 展开箭头 2.5 | 保留（Icon 固定 2，会变细） |
| 自定义 `class`（带 margin/opacity/color） | Shell `tb-user-caret` | 保留（Icon 不接受 class） |
| `:style` 旋转动画 | Rebate 月度展开箭头 rotate(90°) | 保留 |
| `title` tooltip | Rebate 锁定 `title="已计提，已锁定不可改"` | 保留（Icon 无 title） |
| **同名不同形** | Shell 的标准 Lucide sun vs Icon 表 v542 转的 sun（射线位置不同） | 保留 |
| 简版 vs 标准版路径 | ProductTarget 简版 trash | 保留 |

**v545 已收敛**：ConnectCenter(5) + ProductTarget(3) + Login(6) = 14 处；新增 `eye` / `eye-off` 图标（lock 作为通用图标一并补齐）。

**仍未收敛（有保留理由）**：CopilotDrawer 54 处（复杂组件，独立立项）、Shell/Rebate 特殊 SVG（上表）、chart 几何 SVG、ResultCard 装饰图形。

## 四、可访问性分级策略（「165 处 div@click」是印象派）

真实分布 **201 处**（197 未带 role/tabindex），但**机械全量加 role 是错的**——会打乱 Tab 顺序、造成嵌套交互元素、引入回归。分级：

| 级别 | 对象 | 处置 |
|---|---|---|
| **A** | 明确动作型 div@click（「删除」「编辑」单个动作、无嵌套 button） | 改 `<button>` 或加 `role="button"` + `tabindex="0"` + `@keydown.enter/space` |
| **B** | 容器型（行点击/卡片点击，内部有 button/link） | **不改**（内部已有键盘入口） |
| **C** | 高风险件（Forecast 53 处、CopilotDrawer 27 处） | 单独立项，拆分时一并处理 |

**目标用户校准**：Hergent 是经销商自用 + 待卖的 B2B SaaS，屏幕阅读器用户占比极低。可访问性优先级 **低于** 视觉一致性 / 交互体验 / 性能（Forecast 拆分）。

## 六、评估报告「印象派」结论表（重要）

评估报告用 grep 计数得出了「视觉/复用/a11y 三项高风险」，但逐项核实后，多数数字是**印象派**。下表是「计划数字 vs 真实情况 vs 处置」的权威结论，**后续开发前必读，避免按错误数字盲目铺开**：

| 计划项 | 计划数字 | 真实情况 | 处置 |
|---|---|---|---|
| 空态→EmptyState | 230 处 | 180 处已统一（全局 `.state-empty`），仅 6 带按钮 + 4 内联 SVG | ✅ v542 已做 |
| 「加载中」→Skeleton | — | 45 处主 loading | ✅ v544 已做 |
| 硬编码色值归一 | 158 行 | 大部分是 `var(--x,#hex)` fallback + 有意语义色 | ❌ 不做 |
| token 别名清理 | 3-4 名同值 | v362 有意兼容层 | ❌ 不做 |
| 深色补 token | — | 伪命题（radius/fs/sp 跨主题共用） | ❌ 不做 |
| 手写 modal 收敛 | 12 处 | 结构已统一 + 有 Transition 动画，替换反丢动画 | ❌ 不做（可补 aria，见下） |
| div@click 加 role | 165 处 | 201 处，需分级，机械加是错的 | ⚠️ 分级做（§四） |
| 内联 SVG 收敛 | 116 处 | 24 散点 + CopilotDrawer 54，散点中仅 14 可无损 | ✅ v545 已做 14 处 |

**结论**：这个前端代码库的质量**远好于评估报告描述**。真正剩下的、有实质价值的工作只有：

1. **Forecast 拆分**（13800 行，性能隐患）——唯一高价值大项，高风险，需专项护栏（Phase 3）。
2. **可访问性打磨**（aria 语义、t3 对比度）——低价值，对目标用户收益小。
3. **手写 modal 补 aria**（不加行为，只加 `role="dialog"` + `aria-modal` + `aria-label`）——低风险零视觉变化，可作为 Phase 2 的轻量子集。

## 七、执行纪律（沿用）

- 改动前先定位 `文件:行号` 证据 → 一处一改 → grep 复核 → 构建验证。
- 构建用隔离 outDir（`vite build --outDir dist-vNNN`），**不碰 `npm run build` 的 emptyOutDir 删除**。
- 部署：备份生产 index.html → rsync 无 `--delete` → 探针验证（新 entry 接线 + 双侧 md5 + 零回退）→ push。
- 验证「改的页面进没进产物」前，先查该组件是否被路由/其他组件引用（死文件改了等于白改）。
- macOS BSD grep 不支持 `\|`，多模式用 `grep -E -e A -e B`；中文文案会被 esbuild 转 unicode 转义，探针搜英文 prop 名。
