## 二、三个动作

### ① 修判据（`erp_db.py:6886`，`auto_journal_for_cogs`）

```python
# 改前
if total_cost <= 0: return
# 改后
if to_cents(total_cost) == 0: return
```

退货单金额为负 ⇒ 成本也为负 ⇒ `<= 0` 把**整张退货单的成本红冲跳过**，只冲收入不冲成本。生产实测 **3,925 张负额单（−29.27 万销售额）**被吞，成本虚增、毛利被低估 **2.79 个百分点**（8.79% → 11.58%，副本试算）。

顺带把 `from db.precision import round_money, money_balanced` 扩成含 `to_cents`，走 v705/v706 立的唯一精度口径。

> 同类判据 `erp_db.py:7025`（`recalculate_weighted_average_cost`）**不改**：那里「没有成本就不更新档案价」是正确语义。

### ② 清孤儿

判据用 `NOT EXISTS (业务主表)`，**不按 ref_type 整批删**——同样 `ref_type='purchase'` 里还混着 2 行有效分录（采购单 179 是 `received`），整批删会误伤。

| 类型 | 总数 | 孤儿 | 处置 |
|---|---|---|---|
| sale | 22 | 22 | 删 |
| cogs | 0 | 0 | — |
| purchase | 16 | 14 | 删孤儿，保留 2 行有效 |
| revenue_recognition | 6 | 6 | 删（合同不存在或合同客户不存在） |

共删 **42 行**（36 孤儿 + 6 孤儿收入），顺带删 1 个孤儿合同。

### ③ 批量补过账

口径照抄 `auto_journal_for_cogs` 的**回退分支**（`batch_trace` 那条路永不命中，系统实际走的就是这条）：

```
成本 = SUM(soi.quantity × IFNULL(products.purchase_price, 0))
```

| 分录 | 借方 | 贷方 | 行数 |
|---|---|---|---|
| 销售 | 1122 应收账款 | 6001 主营业务收入 | 44,128 |
| 结转成本 | 6401 主营业务成本 | 1405 库存商品 | 44,448 |
| 采购入库 | 1405 库存商品 | 2202 应付账款 | 158 |

凭证号前缀 `JB`/`JBC`/`JBP`（backfill），避开既有 `J`/`JC` 号段；序号按「该日期已有凭证数」续编，避免重号。

## 三、途中抓到的 6 个坑（每个都能单独打死一版）

### 1. 调拨单不能当销售结转成本 🔴

251 张 `order_type='transfer'` 单，`total_amount=0` 但成本 **55.16 万**。调拨是仓库间转移，不是销售。跟着过账会让主营业务成本凭空多 55.16 万，毛利率被压掉 **6.3 个百分点**。

> 副本试算时它们被 `if amt == 0: continue` 顺手跳过了；改成「只跳过收入分录、成本照算」后立刻暴露——**这是改动引入的新风险，靠 dry-run 的数字比对才发现**。

### 2. 幂等漏洞：0 元单永远缺 sale 分录 🔴

原实现一条 SELECT（`NOT EXISTS sale`）同时生成 sale 和 cogs 分录。191 张 0 元赠品单**永远不会有 sale 分录** ⇒ 每次重跑都被选中 ⇒ 已生成的 cogs 分录**被重复插入**。

修法：拆成两条独立查询，**各自按自己的 ref_type 判重**。验证：第二次 apply `inserted = 0`。

### 3. 缺 `(ref_type, ref_id)` 索引 ⇒ 查询卡死 🔴

`journal_entries` 只有 `(date, account_code)` 索引，而所有 `auto_journal_*` 的幂等检查都是 `WHERE ref_type=? AND ref_id=?` ⇒ 全表扫。

- 过账前 84 行：84 × 22,505 ≈ 190 万次，无感
- 过账后 88,782 行：22,505 × 88,782 ≈ **20 亿次比较** ⇒ dry-run 直接被 SIGTERM

建 `idx_journal_ref` 后同一查询 **0.02 秒**。这也解释了 `gl_compensation_sweep` 为什么在生产上从来跑不动。

### 4. `%` 格式化与 SQL 里的 `LIKE '6%'` 冲突

`"SELECT ... LIKE '6%' ... IN (%s)" % ph` ⇒ `ValueError: unsupported format character`。改用字符串拼接。

### 5. `SUM(credit-debit)` 对一借一贷恒为 0

拿它统计"孤儿收入多少钱"得到 0.0 这个假数（借方 +7 万、贷方 −7 万相抵）。只算损益腿（`account_code LIKE '6%'`）才是 9 万。

### 6. `datetimes` 时区：临时会话被判过期

`datetime('now','+2 hours')` 是 **UTC+2**，而比对用的是 `datetime('now','localtime')`（服务器 UTC+8）⇒ 有效期算成"6 小时前过期"。必须写 `datetime('now','localtime','+2 hours')`。
