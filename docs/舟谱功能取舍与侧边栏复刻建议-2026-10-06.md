# 舟谱功能板块取舍分析 + 侧边栏复刻建议

> 分析对象：`~/Documents/舟谱截图/档案管理/` 下 9 张舟谱云管家侧边栏弹窗截图
> 对比对象：Hergent 现有侧边栏（`hergent-cn-v2/src/components/Shell.vue` 的 `NAV`）
> 日期：2026-10-06 ｜ 背景：舟谱即将到期，自研进销存（v380 闸门已搭、未上线）

---

## 一、结论速览（先看这里）

1. **舟谱的 12 个一级板块里，与低温奶经销商强相关的只有 6 个**：档案管理、采销管理、仓配管理、市场营销、员工考核、数据报表。剩下 6 个（财务管理、应用中心等）是「平台化 ERP 的通用件」，我们自用**不该全做**。

2. **舟谱最值得我们抄的不是功能，是两处结构**：① 二级面板的「**分组列**」归类法；② 一级项旁的那个「**›**」展开箭头（表示"这一项下面还有东西"）。

3. **但"打开方式"不要照抄**：舟谱是「**鼠标悬停 → 弹出浮层面板**」，适合它有几百个入口的体量。我们目前只有 11 个入口，悬停浮层是**徒增误触**。建议走「**点击展开、常驻不消失**」的内联树形。

4. **归类逻辑要"借形不借义"**：舟谱按「科室职能」分（档案科 / 仓储科 / 财务科），是**给 ERP 操作员看的**；我们是**给老板看的 AI 经营副驾**，该按「**经营主线**」分（我在做什么生意 → 货怎么进出 → 钱怎么收付）。

5. **进销存是分水岭**：它上线后一级入口会从 11 项膨胀到 25~35 项，**那时平铺必撑不住** ⇒ 现在就该把「可展开的容器」这条交互预埋好，而不是等到拥挤了再返工。

## 二、截图功能板块逐项取舍

### 2.1 十二个一级板块总览

| 舟谱一级板块 | 装什么 | 低温奶是否需要 | 我们的对应物 / 处置 |
|---|---|---|---|
| ① 常用功能 | 高频操作聚合入口 | ✅ 要（是**交互设计**，非功能） | 已有「经营工作台」承担 |
| ② 档案管理 | 商品/客户/供应商/仓库/价格等基础资料 | ✅✅ **要，且是地基** | 已有 `/archive`（6 页签），需按此清单补全 |
| ③ 采销管理 | 访销/车销/自提/采购/调拨 + 各类退单 | ✅✅ **要，是交易核心** | 部分已有（预报订货），进销存 P0 补 |
| ④ 仓配管理 | 出入库/拣货/配送/盘点/报损/拆零/临期 | ✅✅ **要，低温奶命门** | 部分已有（效期补录），进销存 P1 补 |
| ⑤ 资金管理 | 收款付款/往来对账/员工交账/成本核算 | ✅ 要（赊销催收是刚需） | 部分已有（对账），进销存 P1 补 |
| ⑥ 财务管理 | 会计凭证/总账/报表/期末结转 | ⚠️ 大部分**不要**（经销商多外包代账） | 只保留「利润表」级看板 |
| ⑦ 对账助手 | 往来对账、催收 | ✅ 要 | 已有 `/reconciliation` 一族 |
| ⑧ 市场营销 | 陈列/借还货/返利合约/物料(冰柜)/促销 | ✅✅ **要，快消灵魂** | 已有「目标与返利」，需扩陈列+物料 |
| ⑨ 员工考核 | 考勤/外勤线路拜访/提成 | ✅ 要（外勤+提成） | 已有算工资，需扩外勤拜访 |
| ⑩ 数据报表 | 7 大组几十张报表 | ✅ 要（这是我们**最强的地方**，应做得比它好） | 已有经营趋势，是 AI 副驾主战场 |
| ⑪ 应用中心 | 插件市场（截图标注「待续费」） | ❌ **不要**（平台生态，与我们无关） | 不做 |
| ⑫ 设置 | 打印/公司/采销/资金/运营设置 | ✅ 要（轻量版） | 已有 `/settings` |

### 2.2 重点板块的二级功能取舍（逐条给理由）

> 记号：✅要　⚠️可简化/后置　👀观察　❌不要

#### ② 档案管理（7 列）

| 舟谱分组 | 条目 | 取舍 | 理由（结合低温奶） |
|---|---|---|---|
| 商品相关 | 商品档案 / 单位档案 | ✅ | **拆零是低温奶常态**（一箱 12 包、一包 24 瓶）⇒ 三单位换算必须准，这正是我们已建的能力 |
| | 品牌档案 | ✅ | 返利按品牌走（蒙牛/伊利/…），品牌是返利的挂载点 |
| | 价格方案 / 价格体系设置 | ✅ | 一批/二批/零售多级价 + 按客户定价，是我们已建的强项 |
| | 组合规则 | ✅ | 组合装/搭赠装定价要用 |
| | 商品标签 / 上次售价 / 销售类目 | 👀 | 非必需，锦上添花，最后做 |
| 往来相关 | 客户档案 / 供应商档案 / 仓库档案 | ✅ | 三张主档，地基 |
| | 信用管控方案 | ✅ | **经销商普遍赊销**，超额度必须拦，否则坏账 |
| | 客户标签 / 业务类型 | ⚠️ | 可简化（客户分级可用标签，业务类型可并入销售方式） |
| 资金相关 | 账户管理 / 费用类别 / 结算期限 | ✅ | 收付款账户、陈列费促销费归类、账期管理都要 |
| | 收/入类别 / 调拨类型 / 往来标签 | ⚠️ | 可先给一套固定值，不开放自定义 |
| 财务相关 | 科目 / 资产类型 / 增减方式 | ❌ | 会计科目体系，自用**不做**（外包代账公司管） |
| 员工相关 | 员工与部门 / 角色权限配置 | ✅ | 我们已有 |
| 自定义 | 自定义字段 | 👀 | 灵活性加分项，**P2 再做**（做早了是负担） |
| 期初录入 | 应收/应付/预收/预付/科目/库存成本/现金流量期初 | ✅ | **系统上线的必经动作**——不从舟谱/手工带上期初，新系统第一天账就是错的 |

#### ③ 采销管理（6 列）

| 舟谱分组 | 条目 | 取舍 | 理由 |
|---|---|---|---|
| 访销管理 | 访销订单/退单、返配订单 | ✅✅ | **低温奶靠业务员巡店下单**，访销是主渠道 |
| 车销管理 | 车销订单/退单 | ✅✅ | **业务员开车带货、现场交易**是低温奶标配（我们已在做） |
| 自提管理 | 自提订单/退单 | ✅ | 分销商/大客户自己来拉货 |
| 采购管理 | 采购订单/退货 | ✅ | 向厂家/上级商进货 |
| 调拨管理 | 调拨订单 | ✅ | 多仓之间、仓与车之间调货 |
| 综合管理 | 综合订单、单据中心 | ⚠️ | 舟谱的"万能单据"（后端合并展示），我们**可不要**——我们的单据类型清晰，不必造一个"什么都能开"的入口 |

> 🔴 **返配**（退货返仓）这条要特别标记：低温奶**退货率显著高于常温品**（临期、破损、压货），返配不是边缘功能，是日常。

#### ④ 仓配管理（4 列）—— 低温奶的**命门板块**

| 舟谱分组 | 条目 | 取舍 | 理由 |
|---|---|---|---|
| 库存查询 | **临期预警表** | ✅✅🔴 | **低温奶的第一需求**。保质期 2~21 天，临期不预警就是直接报损 |
| | 库存查询 / 车辆商品查询 | ✅✅ | 车仓库存必须单列（车销带货，车就是一个移动仓） |
| | 库存预警 / 返配明细表 | ✅ | 低库存提醒、退货去向可查 |
| 仓库作业 | 入库单/出库单/拣货单 | ✅ | 日常出入库 |
| | 其他入/出库单、出库策略 | ⚠️ | 杂项与策略可后置 |
| 配送作业 | 配送单 / 线路设置 | ✅ | 2 天到货的配送排线 |
| | 司机任务看板 | 👀 | 有价值，**P2 再做**（要司机的手机端配合） |
| 库存作业 | **拆分单 / 组合单** | ✅✅ | **拆零必用**（整箱→散卖）；组合=搭赠打包 |
| | **报损单** | ✅✅ | 低温奶**损耗率天然高**，报损是每天的账 |
| | 盘点盈亏单 / 静态盘点单 | ✅ | 月盘/日盘 |
| | 拣货明细表 / 组合拆分汇总表 | ⚠️ | 明细表类，报表阶段一起做 |

#### ⑤ 资金管理（4 列）

| 舟谱分组 | 取舍 | 理由 |
|---|---|---|
| 客户相关（收款单、对账单、对账表、预收款…） | ✅ 取「**收款单 + 客户对账单/对账表**」 | **赊销催收**是经销商现金流命脉；其余费用单/收入单可后置 |
| 供应商相关（付款单、对账单…） | ✅ 取「**付款单 + 供应商对账单**」 | 与上游对账，其余后置 |
| 内控相关（核销/内部费用/资金转账/员工交账/银行流水对账） | ✅ 只取「**员工交账**」 | **车销司机回款的交账**是刚需；其余内控项对一人公司太重 |
| 库存成本（成本查询、入/出库核算、重算成本价…） | ⚠️ 只取「**库存成本查询**」 | 成本核算（重算/异常查验）留给财务，自用先看个成本数就够 |

#### ⑧ 市场营销（4 列）—— 快消的**灵魂**

| 舟谱分组 | 取舍 | 理由 |
|---|---|---|
| 市场管理（陈列类型、借货单、还货单、市场反馈、市场核检） | ✅ 取「**陈列类型 + 借/还货 + 市场核检**」 | 快消标配：厂家给冰柜（借货）、要求陈列（陈列费挂钩）、业务员拍照核检 |
| 合约管理（预订单、订货模板、**返利模板**、陈列模板、费用合同、兑付协议、供应商返利方案/试算） | ✅✅ **重点** | 我们已有「目标与返利」，这里印证了方向对——**返利是快消经销商最复杂的账**，必须做成核心 |
| 物料管理（物料档案、采购/投放/回收/核销/调拨单） | ✅ | **冰柜是经销商的资产**（截图标签就写着"冰柜、标签"），投了要能追回、能核销 |
| 促销活动（组合搭赠、限时特价、满赠、满减、随单返利…） | ✅ 取「**组合搭赠 + 满赠 + 随单返利**」 | 蒙牛厂家的搭赠/满赠政策是日常，必须能在开单时自动带出 |

#### ⑨ 员工考核（3 列）

| 舟谱分组 | 取舍 | 理由 |
|---|---|---|
| 外勤管理（外勤设置、制定线路、访线计划、任务拜访） | ✅ | **业务员巡店拜访打卡 + 线路规划**是快消管理核心 |
| 提成管理（提成设置、提成统计、历史提成） | ✅✅ | 我们已有算工资/提成，**方向完全一致** |
| 考勤管理（考勤设置/审批/请假） | ⚠️ | 一人公司可先简化，员工多了再补 |

#### ⑩ 数据报表（7 大组）—— 我们要**做得比舟谱更好**

| 舟谱分组 | 取舍 | 理由 |
|---|---|---|
| 经营分析（客户利润/商品铺市/品牌销售/日均售价趋势…） | ✅✅🔴 | **这是我们 AI 副驾的主场**。舟谱给的是"报表"，我们该给"结论+建议" |
| 往来报表 / 资金报表 | ✅ | 应收应付、账户收支 |
| 业财报表（销售/采购/调拨/盈亏汇总） | ✅ | 基础汇总 |
| 市场报表（预订货履约、促销执行、费用兑付、生产批号追溯） | ✅ | 与返利/促销打通 |
| 考勤外勤数据 | ✅ | 与⑨配套 |
| 通用报表（实时概览、个性化报表） | ⚠️ | "个性化报表"是舟谱的付费高级功能，我们可后置 |

#### ⑥ 财务管理（5 列）—— **整体建议不做**

| 理由 | 说明 |
|---|---|
| 经销商普遍**外包代账** | 凭证/总账/明细账/科目余额表/期末结转，都是代账公司的活，老板不直接操作 |
| 固定资产（资产/折旧/清理） | 除非有大量冷库设备要入账，否则**用不上** |
| 🔴 唯一例外 | 「**利润表**」老板要看 ⇒ 但我们**不该做成会计科目报表**，而应做成**经营口径的"这个月赚了多少"看板**（这正是 AI 副驾该干的） |

## 三、侧边栏优化建议

### A. 打开交互方式（现状 vs 舟谱 vs 建议）

**现状**：一级项**点击直接跳页面**，无二级；分组（经营/核算/配置）只是标题，下面平铺 11 项。

**舟谱**：一级项**鼠标悬停 → 弹出浮层面板**，面板内是「多列分组卡片」（如"档案管理"弹出 7 列），列内是三级条目，部分条目带「创建 / 明细」小按钮。

| 对比维度 | 舟谱 | 现状 | 建议 |
|---|---|---|---|
| 触发 | 悬停即弹（Hover） | 点击直跳 | **点击展开**（不悬停） |
| 面板 | 浮层，移开即收 | 无 | **内联展开，常驻** |
| 层级 | 一级 → 浮层分组列 → 条目 | 一级（分组标题+平铺） | 一级 → 内联子项（分组标题） |
| 适用体量 | 几百个入口 | 11 个入口 | 25~35 个入口（进销存上线后） |
| 小屏 | 基本不可用 | 手机另有底栏+抽屉 | 复用同一份表 |

**为什么"悬停浮层"在我们这里不成立**：
- 舟谱是**几十上百个入口**，必须靠浮层一次铺开；我们**现在只有 11 个**，为一个 11 项菜单做浮层＝**徒增一次悬停瞄准 + 移开就消失的焦虑**。
- 我们的用户是**非技术老板**，浮层「鼠标一歪就没了」最容易点错（他自己就说过"经销商看不懂"这类话）。
- **内联展开**（像 VS Code 左侧文件树：点击「进销存」→ 下面就地展开「采购 / 销售 / 库存 / 往来账」）**不用瞄准、不会消失、还能记住展开状态**，对老板友好得多。

**具体交互规则（建议）**：
1. 一级项**有子项**时，右边显示一个「**›**」小箭头（借舟谱的视觉语言）；**没有子项**的（如"经营工作台"）不显示箭头，保持"点击直跳"。
2. **点击整行** = 展开 / 收起（**不跳转**）。要进"概览页"就点组内第一项「总览」。
   - 这解决舟谱一个歧义：它的一级项**既能悬停展开、又能点进页面**，用户常搞不清点下去会怎样。
3. 展开状态**持久化**（记住上次展开的组），下次进来不用重新点。
4. 同屏**最多允许展开一个组**（手风琴式），避免侧栏被撑太长。
5. 子项与一级项**同一套 `canSee(path)` 判据**，不另写权限逻辑（沿用 v291 纪律：唯一真源 `pages.js`）。

> 🔴 **实施时机**：**不是现在**。现在是 11 项、平铺够用。**等进销存 P0 上线、入口超过 ~18 项**再切交互（否则是提前优化）。但**归类结构（下面 B）现在就该调**，因为它是数据问题，改一次即可，与交互相辅相成。

### B. 功能归类结构（现状 vs 建议）

**现状（3 组 11 项）**：

```
经营：经营工作台 · 预报订货管理 · 目标与返利 · 招投标雷达 · 进销存
核算：货损核算 · 算工资
配置：档案管理 · AI 引擎 · 定时任务 · 设置
```

**三个诊断**：

| 问题 | 具体表现 |
|---|---|
| ① 「经营」组过载且将爆 | 已塞 5 项（含「进销存」这种本身是个大板块的项）；进销存 P0~P2 会带来十几个子页 ⇒ **平铺必爆** |
| ② 「进销存」定位尴尬 | 它不是一个"页面"，是一个**板块容器**（含采购/销售/库存/往来账）⇒ 不该和「经营工作台」这种单页平铺在一起 |
| ③ 归类维度不统一 | 「核算」是**动作**维度、「配置」是**系统**维度、「经营」是**场景**维度 ⇒ 混维度，用户难形成心智 |

**建议（借舟谱"两层归类"，但按我们的经营主线重排）**：

```
【经营】                ← 老板每天先看这里
  └ 经营工作台（首页，含实时概览）

【订货】                ← 我们独有的强项，单独立组
  ├ 预报订货管理
  └ 目标与返利

【进销存】              ← 新容器（可展开），对齐舟谱「采销+仓配+资金」
  ├ 采购管理
  ├ 销售管理（访销 / 车销 / 自提 / 调拨）
  ├ 库存管理（含【临期预警】）
  └ 往来账（应收 / 应付 / 对账）

【核算】                ← 轻量版"资金+财务"，只留老板真看的
  ├ 货损核算
  ├ 算工资与提成
  └ 费用与返利兑付

【档案与配置】          ← 把"地基"和"开关"收在一起
  ├ 基础档案（商品/客户/供应商/仓库/价格）
  ├ AI 引擎
  ├ 定时任务
  └ 设置
```

**取舍理由（为什么不照抄舟谱的 12 个一级项）**：

| 舟谱做法 | 我们该怎么做 | 理由 |
|---|---|---|
| 按**科室职能**分区（档案/采销/仓配/资金/财务/营销/考核） | 按**经营主线**分区（经营/订货/进销存/核算/配置） | 舟谱是**给多人分工的 ERP**（仓管看仓配、会计看财务）；我们是**一人公司老板**+AI，老板的心智是"我这盘生意"，不是"今天哪个科室上班" |
| 12 个一级项平铺 | 5 个一级组 | 我们入口少，**组多了反而每个组里空**（导购/司机登录时更明显，侧栏会出现一堆空组） |
| 「市场营销」「员工考核」各占一级 | 并入「核算」与「配置」 | 我们的返利/提成/货损本质是**"算账"**，合在一组更符合老板"月底算总账"的动作 |
| 「数据报表」独立一级（几十张报表） | 提升为**「经营工作台」内的驾驶舱**，不单列成表海 | 舟谱给的是**报表清单**（要用户自己去点、去读）；我们的差异化是**AI 直接给结论**。把报表做成"驾驶舱"而非"表海"，正是护城河 |

**迁移的稳妥做法（避免返工）**：
1. 分组的定义**只改一处**（`Shell.vue` 的 `NAV` 数组的 `label`），**权限判据不动**（仍在 `pages.js`）——沿用 v311「表驱动、标题由条目算出来」的结构，**不会**造出"有标题、下面空着"。
2. 先做**分组重排**（低风险、纯显示层，随时可回退）。
3. 交互（点击展开）**等进销存上线再切**，避免现在为 11 项引入不必要的复杂度。
4. 新的子项（采购/销售/库存…）**逐条登记进 `pages.js`**（v291 纪律），`NAV` 只登记名字/图标/路径。

## 四、落地路线（分步，不建议一次做太多）

| 步骤 | 做什么 | 时机 | 风险 |
|---|---|---|---|
| **S1** | **分组重排**（3 组 → 5 组，按经营主线） | **现在可做** | 低（纯 `NAV` 显示层） |
| **S2** | 「进销存」改为**可展开容器**（点击展开、常驻、记状态） | 进销存 P0 上线时 | 中（新增交互组件，需回归手机抽屉） |
| **S3** | 按 §2 取舍清单，把 P0 功能**逐条进 `pages.js`** | 随进销存开发 | 中（每加一页走三处接线） |
| **S4** | 「数据报表」做成**经营驾驶舱**（AI 给结论，不给表海） | P2 | 低（复用 AI 副驾） |

## 五、一句话总结

**舟谱值得抄的是"两层归类 + 展开箭头"这个骨架；不值得抄的是"12 个科室分区 + 悬停浮层"这个肉身。**
我们的身份是**给老板看的 AI 经营副驾**，不是**给 ERP 操作员用的后台**——所以：
- **归类**按「经营主线」重排成 5 组（借形）；
- **交互**用「点击展开、常驻记忆」替代悬停浮层（改法）；
- **功能**只补低温奶真正吃的 6 个板块，砍掉财务/应用中心等通用件（取义）。
