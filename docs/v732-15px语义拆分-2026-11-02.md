# v732 · 15px 语义拆分（字号 11 档，每个名字只有一个语义）

## 一句话

`--fs-h4:15px` 不是一个"多了的档"，是**两个语义挤在一个名字里**。这一版把它一分为二：
UI 用途 → `--fs-lg` 16、输入框 → `--fs-md` 14、移动端正文独立成 `--fs-body-m`（仍 15px）。

---

## 为什么"机械归一"不行

`--fs-h4` 的 43 处引用分三类用途，而**同一个令牌还兼着移动端正文基准**：

```css
@media(max-width:768px){ body{ font-size: var(--fs-h4) } }   /* 15px = 移动端正文 */
```

任何单向归并都伤另一头：

| 方案 | 后果 |
|---|---|
| 全改 16（`--fs-lg`） | 375px 下正文变宽 **6.7%** ⇒ 每行少一个字，全站移动端换行重排 |
| 全改 14（`--fs-md`） | 二十处面板标题缩水，标题与正文层次消失 |

所以这一版不动"值"，只动"名字"——**把冲突的语义拆开，让每边各走各的**。

---

## 拆分结果

| 用途 | 去向 | 处数 | 理由 |
|---|---|---|---|
| 面板/分区/弹窗标题（`.sec-hd` / `.panel-hd b` / `.dsh-hd b` / `.zp-h2` / `h3`…） | `--fs-lg` 16 | ~24 | 标题档，正文 13/14 → 标题 16 层级清楚 |
| 行内统计值（`.sup-stat b` / `.cas-stat b` / `.zp-stat b` / `.ipd-bmv` / `.ipd-total-amt` / `.wl-type-val` …） | `--fs-lg` 16 | ~13 | **没有**跟着改 18（理由见下） |
| 图标字符（`.task-ic` / `.rc-ic` / `.ctb-icon` / `.isn-arrow`） | `--fs-lg` 16 | ~5 | 盒子固定，只影响字符大小 |
| 输入框（`.cmd-input` / `.cp-input`） | `--fs-md` 14 | 2 | 见下 |
| 移动端正文 `@media(max-width:768px){body}` | `--fs-body-m` 15 | 1 | 语义独立，**值不变** |

### 行内统计值为什么不到 18

`.sup-stat b` 这类是 `12px 标签 + 数值` 的**行内组**：

```css
.sup-stat{font-size:var(--fs-sm);color:var(--t2)}      /* 供应商 共 */
.sup-stat b{font-size:var(--fs-h4);color:var(--t1)}    /* 128 家 */
```

容器是 `display:flex;align-items:baseline` 的工具条。数值提到 18 会：
1. 拉大与 12px 标签的基线落差（1.5 倍字号差）
2. 把工具条行高撑高，挤掉操作按钮

`--fs-stat` 18 只给「独立成块的统计值」（`.kpi-val`、`.zp-grid` 里的卡片）。

### 输入框为什么是 14 而不是 16

副驾消息正文 `.md` 本来就是 **14px**：

```css
.md{ line-height:var(--lh-normal); font-size:var(--fs-md) }
.cp-input{ font-size:var(--fs-h4) }    /* 15px —— 打字时看到的字比发出后大 */
```

输入框 15 意味着**输入态与阅读态不同字号**，这是错位，不是"大一点更舒服"。改 14 是修一致性。

## 护栏：拆开之后要防止再合回去

新增 `checkMobileBodyOnly()`：`--fs-body-m` 只许出现在一条规则里 ——

```
@media(max-width:768px){ body{font-size:var(--fs-body-m)} }
```

出现在任何 UI 规则里就报错，并给出该用 `--fs-md` 还是 `--fs-lg`。

同时 `FONT_RAMP` 名单去掉 `h4`、加入 `body-m:15`（11 档、11 个值不变）。
「同值检测」仍然生效 —— 如果谁再加一个 15px 的名字，会直接报「同值」。

阳性对照：在 `.rk-tag` 前注入 `.zz-test{font-size:var(--fs-body-m)}` ⇒ 报错 + `exit=1`；还原后 `exit=0`。

## 视觉回归：第一次同时跑两套视口

字号改的是**文字宽度**，所以只跑 1440 会漏掉真正的风险面。这一版起抓图工具支持
`HG_VW` / `HG_VH`，移动端产物落到独立目录，不覆盖桌面基线。

### 先证明基线真的是移动端

"抓到 24 张图"不等于"进了移动端布局"，四条硬证据：

| 判据 | 值 | 含义 |
|---|---|---|
| `innerWidth` / `matchMedia('(max-width:768px)')` | 375 / `true` | 媒体查询命中 |
| `getComputedStyle(body).fontSize` | **15px** | 桌面是 14px ⇒ 那条 `@media` 真的生效 |
| 侧栏宽度 | 0 | 桌面侧栏已隐藏 |
| `scrollWidth` = `clientWidth` | 375 = 375 | 无横向溢出 |

### 1440：4 页变化（×2 主题），全是 1–2px 整体下移

| 页面 | 差异 | 归因 |
|---|---|---|
| 工作台 | 4.46% | `.sec-hd` 标题 15→16，行盒 +1.6px ⇒ 整页下移 |
| 库存周转 | 3.10% | 同上（表格本身零变化） |
| 毛利分析 | 2.28% | 同上 |
| 设置 | 0.85% | 同上 |

**另外 8 页零像素差异** —— 表格/档案/建单页正文走 13/14px，没被 15 影响。这也是"改动只在标题"的反证。

位移量的实测（工作台 x=400 竖扫，卡片边框 y 序列）：

```
v731  360  380  384  388  405  410  413  433  444  464
v732  361  381  385  389  407  412  415  435  446  466
差      +1   +1   +1   +1   +2   +2   +2   +2   +2   +2
```

每个特征带的宽度不变（`(405,408)` → `(407,410)` 都是 4px），只有位置 +1/+2 ⇒ **纯位移，无撑高无换行**。
周转页表格行间距 `30/30/29` vs `29/30/30`，同样只是整体下移 1–2px。

### 375：2 页变化，并且暴露了一个既有 P0

设置页 / 工作台各 2–3%。设置页是行盒随字号变化（15→16，`lh 1.6` ⇒ 每行 +1.6px），属预期。

工作台则发现了**与本次无关的既有 bug**：任务行标题逐字竖排、单卡被撑到 410px 高。
基线（v731 生产版）里已是如此 ⇒ 详见 v733。
