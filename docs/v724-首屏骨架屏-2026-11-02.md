# v724 · 首屏骨架屏

> 2026-11-02。起因：v723 评审里「骨架屏覆盖 44/87，`Workbench.vue` 无骨架」。

## 先纠正一个判断：不是「没有骨架组件」

`src/components/Skeleton.vue` 存在（v538 抽的），但**没有任何页面直接 import 它** —— 我第一版统计据此得出「造了没人用」，这是错的：

`components/ReportTable.vue` 里 `import Skeleton from './Skeleton.vue'` + `<Skeleton v-if="loading" />`，
而 **47 个报表页里有 36 个走 ReportTable** ⇒ 这批页的骨架是有的，只是隔了一层。
（教训：数「谁用了组件」时，`grep` 的路径写法会骗你，要顺着组件树往下看一层。）

真正的缺口不在「有没有组件」，而在**页面自己的首屏数据没有加载态**。

## 真正的问题：加载中说了三句确定但错的话

工作台是老板每天第一眼看的落地页，而它 `onMounted` 之后要 await 四个接口。在数据到达之前：

| 位置 | 加载中显示 | 实际含义 |
|---|---|---|
| KPI 五个指标 | `¥0`、`0 单` | 像是「今天没卖出去」 |
| 今日要务徽标 | `0 项待处理` | 像是「今天没事」 |
| 近效期预警 | 空态「近 14 天无临期批次，保持节奏」 | **风控位说一切正常** |

第三条最严重：它不是「空白」，是**主动给了一个结论**。空白最多让人等一下，结论会让人放心。

同类问题还有一个：`funds/FundsReconcile.vue` 里 `v-if="!filteredGroups.length"` 显示
「没有符合条件的组」—— 数据在读取中时这个条件也成立，对账页说这句等于报了「对账没问题」。

## 改法：复用已有 `.skel-line`，不造新组件

`.skel-line` 已经是全站骨架的基本单位（10 个文件 24 处，工作台自己的 AI 区块就在用）。
只补两档高度修饰，让骨架与**它替代的那行文字**等高：

```css
.skel-line{display:block;height:14px;…}
.skel-line.sk-h12{height:12px}   /* 说明文字 */
.skel-line.sk-h22{height:22px}   /* KPI 数值 */
```

为什么要专门调高度：`.kpi-val` 是 22px、`.kpi-sub` 是 12px，全用默认 14px 的话
两头都不对齐，**数据一到就会跳版** —— 骨架屏的价值一半在「不跳」。

### Workbench

- 新增 `bootLoading`，**只盖首屏那四个 await**（dash / expiry / today / recentActions）。
  不盖 AI 晨报 —— 等 AI 会让骨架挂好几秒，晨报自己已有 `aiLoading`。
- KPI：`v-if="bootLoading"` 渲染骨架条，标签保留（标签是静态的，不闪）
- 今日要务：`bootLoading || todoLoading` 时渲染 3 行骨架，徽标隐藏
- 近效期预警：`bootLoading` 时渲染骨架，不再落进那个「保持节奏」的空态

### 银行对账

任一侧 `loadingRows` 时显示骨架，`v-else-if` 才判空。

## 验证：限速抓真机

骨架是瞬时状态，正常网速抓不到。用 CDP 把延迟调到 700ms、限速 600KB/s，然后**轮询**：

```
2988ms  skel-line=21  kpi=5  badge=""           ← 骨架出现
3598ms  skel-line=2   kpi=0  badge=""           ← 路由二次渲染
5741ms  skel-line=3   kpi=5  badge="6 项待处理"  ← 数据到位，剩 3 条是 AI 区块自己的骨架
```

关键三条：加载中**徽标为空**（不是「0 项」）、**错误空态不出现**、数据到达后正常。
剩余 3 条 skel-line 是「本周建议订购清单」等 AI 区块自己的加载态，属预期。

限速快照里五个指标卡与三行要务骨架**等高、无塌陷**。

加载完成后的界面与刷新前基线逐像素比 24 页：**唯一差异是天气 18°→19°**，
即纯数据噪声（见「视觉回归基线」文档里「阈值管不住数据」那一节）。
