## 二、为什么本轮不是「改个边界」那么简单

### 🔴 核心难点：既有实现把「没填」「填了非数字」「填了 0」压成了同一个值

```
_coerce_num('')    → 0
_coerce_num('abc') → 0     ← 三者完全同形，无法区分
float('0')         → 0
```

⇒ 如果只把 `0 < x <= 1` 改成 `0 <= x <= 1`，就会**同时放行空值与非数字**
—— 而这恰好是老板明确要求「保持不变」的两类。

**⇒ 判据必须「两段式」**：第一段判「**是不是显式给出的数字**」，第二段判「**在不在 `[0,1]`**」。

新增能力（后端）：

```python
def _is_num_like(v):
    """v 是否是一个**显式给出的数字**（数字串 '0' / '0.00' 也算）。"""
    if v is None or isinstance(v, bool):
        return False          # 🔴 bool 是 int 子类 ⇒ float(True)=1，不挡会被当合法 100%
    if isinstance(v, (int, float)):
        return True           # 🔴 负数是数字 ⇒ 返回 True，越界交给第二段
    if isinstance(v, str):
        s = v.strip()
        if not s:
            return False
        try:
            float(s); return True
        except ValueError:
            return False
    return False
```

实测取值：

| 输入 | `_is_num_like` |
|---|---|
| `0` / `0.0` / `'0'` / `'0.00'` / `-0.1` / `1` | **True** |
| `''` / `'   '` / `None` / `'abc'` / `True` / `False` / dict / list | **False** |

**⇒ 「负数仍然被拦」是由第二段（范围）实现的，不是靠 `_is_num_like` 返回 False。** 两段职责不能混。

## 三、三处同病（本轮一并收敛）

| # | 位置 | 症状 | 严重度 |
|---|---|---|---|
| ① | 前端 `useRebateTargetForm.js` 月表过滤 `Number(r.ratePct) > 0` | 0 被当「没填」**丢掉** | 🔴🔴 **最贵** |
| ② | 后端 `rebate_rules.py` `not (0 < rebate_rate <= 1)` | 判 0 非法，且分不清空与 0 | 🔴 |
| ③ | 前端 `Rebate.vue` 两处 truthy 判定 | 已合法保存的 0 显示成「—」 | ⚠️ |

### 🔴 ① 才是真金白银的那条（不是「存不了」，而是「存错了别人的数」）

`resolve_month_rate` 对「`monthly_rates` 里**没有这个月**」的规则会**向前回绕找最近有值的月**
（既有语义）。丢 0 的后果：

```
填入  monthly_rates = {"09": 0, "10": 0.1}
  ↓ 前端 `Number(ratePct) > 0` 把 0 丢掉
实际  monthly_rates = {"10": 0.1}
  ↓ 取 9 月返利率时向前找最近有值的月
9 月返利率 = 0.1   ← 🔴 10 月的 10% 被静默套到 9 月
```

**⇒ 凭空多出返利、且零报错。这比「填 0 保存不了」贵得多，是本轮必须修的那条。**

## 五、关键设计决策（为什么这样做）

### 5.1 🔴 「空值」这条判据**只能落在前端**

后端经 `_coerce_num` 后**分不清「空」与「0」**（两者同形）。
⇒ 后端若也判「空必填」，会**连显式 0 一起拦**。
⇒ 分工：**后端只负责「不是数字 ⇒ 拦」；前端负责「空 ⇒ 提示用户去看」。**

### 5.2 🔴 月份锁只认 `monthly_amounts`

`covered_months()` 有 `amounts` 就**只按它的键**展开 ⇒ **只填返利率的月不占锁**，
`monthly_rates` 里放 0 **不会白占月份、挡别的规则**（这是「0 可以安全落库」的前提）。

### 5.3 同屏两列过滤条件**故意不对称**（业务语义差异，不是不一致）

| 列 | 过滤 | 为什么 |
|---|---|---|
| 金额（万元） | `amtWan > 0` | 金额 0 万元 = **该月没有目标** = 应当留空 ⇒ 0 绝不能落库 |
| 比率（%） | `!= null && !== '' && !isNaN()` | 比率 0 = **该月确实没有返利** = 有效事实 ⇒ 0 必须落库 |

🔴 代码注释里已写明「别顺手统一」，防止后续「代码整洁化」把缺陷改回来。

### 5.4 连带确认的既有契约

`update_rule` **先 merge 现有行**（白名单逐字段覆盖 `merged = dict(existing)`）
⇒ `Rebate.vue` 的**局部更新** `update(r.id, { is_active })` **不会被新判据误伤**（已实测钉住）。

## 九、🔴 两条「假绿」教训（本轮踩到，已沉淀进技能）

### 教训 1：「某事之后状态应为 X」的断言，必须先证明「某事之前状态不是 X」

**实例**：界面探针里 `closed === false` 在「弹窗**从未打开**」时也成立
⇒ 把「从没打开」误判成了「创建成功后关闭」。

**修法**：补一条**前置断言**（`openBrand === '创建品牌目标'`），
且所有后续断言写成 `开===true && 关===false`。

### 教训 2：对照组必须至少有一条报错，否则先怀疑参数没传进去

**实例**：真机探针 4 条「应当被拦」的用例**全部返回"无错误"**，
根因是**探针漏传了 kw 参数** ⇒ 四条全用默认 `rebate_rate=0` 在跑。

**修法**：先打**完整响应正文**（不是只 `if err`），看清它收到的到底是不是你传的值。

### 附带：两条我自己的护栏写错（修的是护栏，不是代码）

  ⇒ 我写 `0.1` 表示的是 0.1% ⇒ 换算出 `0.001` 是**正确的** ⇒ 改成 `ratePct = 10`。

## 十二、一句话总结

> **「填 0 保存不了」只是表象；真问题是「空 / 非数字 / 0」三者被判成了同一个值。**
> 修法不是把 `<` 改成 `<=`（那会连空值一起放行），而是**先让三者可分**（`_is_num_like` + 两段式），
> 再顺着这个键往下游走一遍 —— 因为**丢掉一个键，往往会触发「向前找」把别的月份的值搬过来**。
