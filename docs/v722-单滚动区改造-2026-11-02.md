# v722 · 「能做成一个滚动区就不要做成两个滚动区」

> 老板口径（2026-11-02）原话：「能做成一个滚动区就不要做成两个滚动区」。
> 起因：v721 修表头冻结时我给建单页补了 `max-height` 魔数，且当时把详情页的
> 「表内滚 ⇒ 两滚动区」当成业务待拍板项挂着。这句话就是拍板：**不要嵌套**。

---

## 一、判据（先定怎么算「两个滚动区」）

不是「有没有滚动条」，而是**同一屏里存在嵌套的滚动区**：

- 滚动区 = 在真实布局里真的溢出（`scrollHeight > clientHeight+4` 或
  `scrollWidth > clientWidth+4`）且 `overflow` 为 `auto/scroll` 的可见元素；
- `nested` = 该滚动区内还有 ≥1 个滚动区 ⇒ 就是要消灭的形态。

为什么两层特别糟：滚动事件被内层吃掉 —— 鼠标停在表里滚，页面不动；移到表外滚，
表格又跑了。用户会觉得「这页滚不动 / 内容不见了」。

探针：`.workbuddy/tools/v721-scroll-region-audit.mjs`
（`--grow` 给单据明细注入 45 行逼出长内容；`--all` 跑全站 59 页）。
**表头吸附必须逐表测**（只测第一张表会把多表页判错，v722 踩过）。

---

## 二、三种页面形状，对应两套机制（用错就一定两层）

| 页面形状 | 例子 | 机制 | 单滚动区怎么来 |
|---|---|---|---|
| **表格为主体** | 进销存列表 / 单据、商品档案 | `freeze-list`：表格自成滚动区 | **页面不出滚动条**，表格区吃满剩余高度 |
| **单表但页面很长** | 资金流水 / 资金余额 / 库存 / 库存周转 / 本期预报 | 同上（待迁移） | 同上（尚未做） |
| **多区块多表** | 员工档案（3 表）、告警规则（KPI+2 卡+表）、招标雷达（KPI+表） | `freeze-list` | **暂时做不到**，见第五节 |

关键：**宽表必须自带滚动区**（横向），所以「页面也滚」必然导致嵌套。
⇒ 本仓唯一可行的单滚动区模型 = 页面高度锁死 + 表格区内部滚。

## 三、改动清单（10 个页面）

### 1. 高度链的支点：`InventoryShell.vue`

```css
.page { display: flex; flex-direction: column; height: 100%; min-height: 100% }
```

- 只加 `min-height` 不够：`.page` 高度仍是 `auto` ⇒ 子页 `.inv-page{height:100%}`
  解析不出确定高度（百分比在 auto 高度上退化为 auto）⇒ 卡片 / 明细体拿不到
  「剩余高度」这个数，只能靠各自写死的 `max-height` 凑，页头一换行就凑不准。
- 作用域 `scoped`，只影响进销存 8 个子页；长内容仍能溢出并被 `.view-wrap` 滚到
  （溢出量照常计入 scrollHeight），不会「失去滚动」。

### 2. 四个单据内核：`flex: 1 1 0`（治本，删掉魔数）

`PurchaseOrderForm` / `PurchaseReturnForm` / `SaleDocForm` / `TransferDocForm`
的 `.ipn-body` / `.isn-body`：

```css
flex: 1 1 0;        /* 原来是 1 1 auto —— 根因 */
min-height: 120px;  /* 极端矮屏兜底，约 3 行 */
overflow: hidden;
```

`basis:auto` ⇒ 基准尺寸 = **内容高度**（45 行时 1776px）⇒ `.inv-page` 跟着长、
整页出滚动条。改 `basis:0` 后 body 恰好是「剩余高度」，页面永不出滚动条。

`min-height:120px` 的取舍：375×568 这种极端矮屏若单据头就吃掉一屏，宁可整页滚一点，
也不能把明细压成 0（一行都看不见最致命）。

### 3. `variables.css`：删除 `--list-pane-max`

v721 加的令牌（桌面 550 / `≤640px` 340）整个作废 —— 魔数只能「凑」到不溢出，
页头一变高就漏。留一段注释指向新机制，避免有人再加回来。

### 4. `Archive.vue`：把高度链打通到子页

```css
.page { display: flex; flex-direction: column; height: 100% }
.archive-panel { display: flex; flex-direction: column; flex: 1 1 0; min-height: 0 }
```

原因：`.view-wrap` 高度确定，但中间两层（本文件的 `.page`、`.archive-panel`）都是
块级 auto ⇒ 商品档案的「填充版」失效（实测面板只剩 198px、表格 61px）。
对其它档案子页零影响：它们不声明 `flex`，仍是内容高度，超出照旧由 `.view-wrap` 滚。

### 5. `ProductArchive.vue`：填充版

```css
.page { display: flex; flex-direction: column; height: 100%; min-height: 0 }
.card.pa-panel { display: flex; flex-direction: column; flex: 1 1 0; min-height: 200px; margin-bottom: 0 }
.pa-panel .table-wrap.freeze-list { max-height: none; flex: 1 1 0; min-height: 0; overflow: auto }
```

为什么不用「表头吸附页面」：本表横溢（可见 1082 / 内容 1391），必须有内滚容器做横滚；
为什么不再用 `calc(100vh-292px)`：那个 292 是按页头一行高估的，副标题一换行就漏 11px。

## 五、废弃的尝试：`freeze-page`（表头吸附到页面）

**结论：在本仓不成立，代码已删，只留注释。别再试。**

试验过程（真机 + 合成对照）：

| 试验 | 结果 |
|---|---|
| 目标表改 `overflow:visible`，`th` computed `position:sticky` / `top:0` | 声明全部正确 |
| 祖先链检查 | `.card` / `.page` 全 visible，唯一滚动者是 `.view-wrap`（817/2616） |
| 滚 400px 后表头位移 | **恰好 -400**（零吸附） |
| 合成对照：scroller 是普通 div，嵌套 1 / 2 / 3 层 | **全部钉住**（含 `border-collapse:collapse`） |
| 合成对照：同样内容放进 `.view-wrap` 滚 | **钉不住** |
| 把 `.page` 自己变成 scroller | **钉不住** |
| 换成 `thead` / `tr` sticky、`border-collapse:separate`、`overflow:clip`、`flow-root` | 全部无效 |

⇒ 本仓外壳的两个滚动器（`.view-wrap` 是 `flex:1;min-height:0` 的 flex 子项）
无法作 sticky 锚点；只能让「表格自己的父级就是滚动器」。
