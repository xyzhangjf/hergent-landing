## 二、改了什么（A + D 为代码，B 为生产数据）

### A · 简报标题不再拼租户名；事件键固定

`server/scheduler.py`

```python
# 改前
suffix = f" · {tenant_label}" if tenant_label else ""
title = f"{today} 经营卡简报{suffix}"
db.message_send(title, content, "notice", "经营副驾")

# 改后
_BRIEF_EVENT_KEY = "经营卡简报"
title = f"{today} 经营卡简报"
db.message_send(title, content, "notice", "经营副驾", event_key=_BRIEF_EVENT_KEY)
```

🔴 **连带缺陷（比标题本身更隐蔽）**：旧实现下 `message_send` 未传 `event_key` ⇒ 由
`norm_event_key(title)` 现算 ⇒ **事件键也带上了租户名**（生产实测存下来就是
`经营卡简报 · 测试企业A`）。而前端「按类静音 / 频率 / 暂停」（`useNotiPrefs`，本地存储）
**全挂在这个键上** ⇒ **租户一改名，用户已设的静音规则会静默全部失效**。

顺带删掉 `_push_copilot_cards_brief` 里「为了拼标题而预取租户名」的那段
⇒ 少一条「内部租户名流向用户可见文案」的通路，也少一次主库读。

### D · `_push_tenant_channels` 收进两道闸门（唯一实现，所有调用方共享）

| 闸门 | 规则 | 为什么 |
|---|---|---|
| ① | 演示 / 只读租户（`tenants.readonly=1` 或 `subdomain='demo'`）**一律不外发** | 演示数据不能推到真实企微群 / 群机器人。对照：`server.py` 的「今日经营要务」**早就写了**「演示租户不推送」，而简报这条路径一直没有 |
| ② | **多租户（登记租户 ≥ 2 个）禁止回落全局 webhook** | 全局 webhook 的口径是「一个部署一个企微群」（`notify/wecom_notify.py` 自陈），**它没有租户身份**；一旦回落，所有「没配渠道的租户」的简报都会进同一个群（含演示租户与**未来第二家客户**） |

- 读不到租户清单 ⇒ 按多租户处理（**fail-closed**）：泄漏不可逆，少发能补。
- **单租户部署**保留原有的回落行为（历史行为不误伤）。
- 今天这个改动**零行为变化**：全局 webhook 本就未配置，且生产已登记 2 个租户。

### 配套 · `erp_db.tenant_master_all()`（新增助手，本轮踩到的坑）

> 🔴 `tenant_list()` 走 `_connect()`，在 `set_tenant_context()` 之后读到的是
> **租户库自己的影子 `tenants` 表** —— 生产实测 `tenant_1.db` / `tenant_10.db` 里那张表
> **都是 0 行** ⇒ 租户属性（名字 / `readonly` / `subdomain`）会被**静默读成"没有这个租户"**，
> 而且**零报错**。

⇒ 新增「**直连主库读 tenants**」助手，返回 `None`（读失败，未知）与 `[]`（确实无租户）语义不同。
