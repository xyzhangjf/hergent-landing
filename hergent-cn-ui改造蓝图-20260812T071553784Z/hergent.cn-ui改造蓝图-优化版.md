# Hergent.cn UI 改造蓝图 · 优化版

> 基于实例 `hergent-cn-ui改造蓝图-20260812T071553784Z`（v1→v7 演进，最终 v7）优化而成。
> 本次优化**不改变**原图的目标、技术栈与产品定位，只提升方案的可行性与完整性。

---

## 0. 优化原则与「不变项」

**三个不变（锁定，不偏离）**
- **目标不变**：首屏=经营工作台、预报订货=汇总表、AI 经营副驾单一入口、目标/返利可视化。
- **技术栈不变**：前端 Vite + 原生 JS 模块；后端 FastAPI + SQLite；图表用 ECharts；浅色为默认主题（深/浅双主题）。
- **产品定位不变**：低温奶经销商的「AI 经营副驾」，未来卖给其他快消/低温奶经销商（B2B SaaS）。

**六项优化（本次新增）**
1. 更清晰的**模块职责边界**
2. 明确的**阶段优先级与依赖关系**
3. 增强的**异常处理与边界场景**
4. 优化的**组件复用与状态管理**
5. 落实的**移动端适配**
6. 落地的**中文用户体验**细节

## 1. 信息架构与模块职责边界

### 1.1 导航分组（沿用 v7）
| 分组 | 模块 | 角色 |
|------|------|------|
| 经营 | 经营工作台 / 预报订货管理 / 目标与返利政策 / 消息推送 | 老板与运营日常主路径 |
| 数据 | 数据源 / 数据看板 | 数据“进”与“看” |
| 其他 | 设置（MCP/手机连接收进高级折叠区） | 低频配置 |
| 全局 | AI 经营副驾（单一入口，常驻底部输入条） | 对话开单/催报/问返利 |

### 1.2 模块职责边界表（强化，明确“不负责”）
| 模块 | 负责（写） | 不负责 | 数据写入口 | 依赖 |
|------|-----------|--------|-----------|------|
| **经营工作台** | 聚合展示今日批次、未报单、KPI、AI 晨报、待办 | 不直接写业务数据 | 只读聚合 | 预报/政策/推送 |
| **预报订货管理（汇总表）** | 报单录入、商品管理、最终下单定稿、**展示智能审核大脑** | 不配置目标/返利规则 | 报单单元格、加单、停用启用、采纳建议 | 智能审核大脑（P1 引擎） |
| **智能审核大脑** | 计算品牌/单品达成率、给出建议订单 | 不存规则（规则在政策页）、不写最终下单（只建议） | 只读计算 | 目标与返利政策、预报表 |
| **目标与返利政策** | **唯一规则写入口**：销售目标、返利政策、核销台账 | 不做可视化图表、不做原始数据导入 | 目标/返利/核销 | 上传实际数据（P3） |
| **数据源** | **唯一原始数据导入写入口**（舟谱 Excel 商品/发货实绩） | 不配置规则、不做图表 | Excel 导入 | 舟谱连接器 |
| **上传实际数据** | 手工/Excel 登记“实际达成/核销”（补规则所需的实际数） | 不配置规则本身 | 实际数登记 | 目标与返利政策 |
| **数据看板** | **只读消费**：趋势/对比/核销环形图 | 不写任何数据 | 无 | 政策 + 上传实际 |
| **消息推送** | 推送通道配置、推送记录 | 不计算业务（只发 AI 产出） | 通道开关 | 通知后端 |
| **设置** | 账号/公司/套餐、高级（MCP/手机连接） | 不涉及业务 | 配置 | — |
| **AI 副驾** | 对话入口（Hermes 引擎） | 不直接改单（只建议/生成） | 经 API 调用 | Hermes |

### 1.3 边界铁律（写进验收）
- **铁律 A**：规则（目标/返利）只能从「目标与返利政策」页写入；看板/工作台只读。
- **铁律 B**：原始业务数据只能从「数据源」+「上传实际数据」写入；汇总表只改“最终下单”这一列。
- **铁律 C**：智能审核大脑**只建议、不擅自改单**，最终定稿权在审核人（`采纳建议` 才写“最终下单”）。
- **铁律 D**：所有写操作走统一的 `api()` 封装 + 后端 fail-closed（缺密钥/越权即报错，不静默）。

### 1.4 数据流（单向）
```
舟谱/Excel ──▶ 数据源(导入)   手工/Excel ──▶ 上传实际数据
                                      │
目标与返利政策(规则写入口) ──┐         │
                            ▼         ▼
                    智能审核大脑(计算: 达成率+建议订单)
                            │
                            ▼
                    预报订货管理(采纳→最终下单)
                            │
              ┌─────────────┴─────────────┐
              ▼                            ▼
       数据看板(可视化查询)          经营工作台(晨报/待办/ KPI)
```

## 2. 阶段改造优先级与依赖关系

### 2.1 阶段表
| 阶段 | 名称 | 交付物 | 依赖 | 可独立上线 | 风险 |
|------|------|--------|------|-----------|------|
| **P0** | 基础重构 | 导航重组 + 经营工作台首屏 + 全局 AI 输入条 + 视觉令牌对齐 | 无（纯前端） | ✅ | 低 |
| **P1** | 预报汇总表 + 审核大脑 | 汇总表重构 + 智能审核大脑（品牌/单品达成+建议订单） | `/api/forecast-audit` 已在线；需目标/返利数据 | ✅ | 中（依赖 P2 数据才有意义） |
| **P2** | 目标与返利政策 | 政策页（目标/返利/核销台账 CRUD） | **新 DB 表** `sales_targets_mfr` + `achievement_data`；复用已上线的 `rebate_rules` | ✅ | 中（建表+迁移） |
| **P3** | 上传实际数据 | Excel 上传 + 手工登记（补实际达成/核销） | P2 数据模型 | ✅ | 中（匹配/冲突/增量策略） |
| **P4** | 数据看板 | ECharts 三图 + 筛选联动 + 双向跳转 | P2 + P3 数据积累 | ✅ | 中（图表库打包、降级） |
| **P5** | 消息推送 | 企微/飞书通道 + 推送记录 | 通知后端 | ✅（可并行） | 中（渠道授权） |
| **P6** | 数据源深化 | 舟谱连接器/发货实绩同步 | 导入引擎（P3） | ✅（可并行） | 高（舟谱无公开 API） |
| **P7** | 移动端 + QA + 多租户 | 移动导航/响应式 + 权限/租户隔离 + 回归 | 全部前端页 | 阶段性 | 中 |

### 2.2 依赖 DAG（关键路径加粗）
```
P0 ──▶ P1 ──▶ P2 ──▶ P3 ──▶ P4
                      │
        P5 ─┐        ├──▶ P7(收口)
        P6 ─┘
```
- **关键路径**：P0 → P1 → P2 → P3 → P4（价值最大，先跑通能看到返利数字）。
- **可并行**：P5（推送）、P6（数据源深化）不阻塞关键路径，可在 P2 之后并行。
- **收口**：P7 移动端/QA/多租户跨所有页面，最后统一收口，但移动适配规范**从 P0 起就遵守**（避免返工）。

### 2.3 每阶段 DoD（Definition of Done）
- 每个阶段独立可上线、可回滚；不依赖未上线阶段（用演示数据兜底）。
- 写操作全部经 `api()` + 后端校验；读页面有加载/空/错三态。
- 移动端断点（≥1280 / 768–1279 / <768）在该阶段页面达标。

## 3. 异常处理与边界场景（逐模块）

### 3.1 通用异常（所有页面）
- **未授权 401**：登录过期 → 自动跳登录页，保留当前路由，登录后回跳。
- **网络超时/5xx**：API 封装统一捕获 → 顶部红条 + 重试按钮；不静默失败。
- **租户隔离越界**：后端 fail-closed，前端不传 `X-Tenant-Id`（由中间件按 user→租户推导）。
- **乐观更新失败回滚**：采纳建议/停用启用先本地改、失败则回滚并 toast 原因。
- **三态优先**：每个列表/图表先渲染**骨架屏 → 成功/空/错**，杜绝白屏。

### 3.2 数据源 / Excel 导入
| 边界场景 | 处理 |
|----------|------|
| 文件格式错误（非 xlsx/csv） | 上传即拒，红字“仅支持 .xlsx/.csv” |
| 表头不匹配 | 映射预览，缺失必填列标红，不让继续 |
| 编码/BOM 问题 | 解析前去 BOM；CSV 用 UTF-8 |
| 重复行/重复条码 | 按「条码+通道」去重，重复跳过并计入“重复”计数 |
| 部分行失败 | **逐行校验 + 错误报告**（可下载），成功行照常入库，失败行不入库 |
| 超大文件 | 前端先限大小（如 ≤10MB），后端流式解析防 OOM |
| 模板版本漂移 | 模板带版本号，旧模板提示“请下载最新模板” |
| 并发导入 | 同租户串行队列，避免写锁冲突（`database is locked`） |

### 3.3 上传实际数据（补实际达成/核销）
| 边界场景 | 处理 |
|----------|------|
| 名称与已建目标不匹配 | 按「名称+计量方式」匹配，**匹配失败行标红不入库**并提示 |
| 期间格式非法 | 校验 `YYYY-MM`，否则内联红字“统计期间应为 2026-08” |
| 计量方式不一致（如目标按箱、填金额） | 与政策条目的计量方式比对，不一致阻断并提示 |
| 数值为负/非数字 | 内联校验，阻止提交 |
| 同期间重复上传 | 策略明确：**同「名称+期间+计量」覆盖，不同则增量**，上传前提示影响行数 |
| 维度与政策维度不符 | 维度（品牌/商品）必须对应，否则无法匹配 |

### 3.4 智能审核大脑
| 边界场景 | 处理 |
|----------|------|
| 缺库存/缺历史数据 | 该 SKU 显示“缺数据”徽章，不参与建议（不报错） |
| 目标值为 0 / 未建目标 | 达成率显示“—”，不除零 |
| 达成 > 目标（超额） | 进度条封顶 100%，标注“已超额 X%” |
| 时间进度跨月/闰年 2 月 | 时间进度线按自然月天数算（28/29/30/31） |
| 品牌总目标 ≠ 单品之和口径 | 品牌目标与单品目标独立维护，注明“品牌为总盘、单品为明细，口径可不同” |
| 建议量为负 | `max(0, …)`，绝不出现负数建议 |

### 3.5 数据看板
| 边界场景 | 处理 |
|----------|------|
| 无数据 | 空态插画 + “先去「上传实际数据」录入”引导按钮 |
| 单一数据点 | 折线退化为点 + 提示“数据不足” |
| 进行中月份（如 8 月只到 13 日） | 实际线用虚线 + “截至 8/13”标注，目标为满月 |
| 筛选组合无结果 | 图表区显示“当前筛选无数据”而非空白 |
| ECharts CDN 不可用 | **降级为静态 SVG 占位 + 提示“图表库加载失败，请刷新”**（生产应打包进 bundle，不依赖 CDN） |
| 窗口 resize | ResizeObserver 防抖重绘；路由切换时 `dispose()` 旧实例防内存泄漏 |

## 4. 组件复用与状态管理策略

### 4.1 现状问题（v7 原型暴露）
- `state` 扁平全局、全量 `render()` 重渲染 → **输入焦点丢失**（汇总表每改一格重画整表）。
- 事件每次 render 重绑，无 diff。
- 组件以“内联 HTML 字符串”散落，重复度高（进度条/状态徽章/卡片多处复制）。

### 4.2 组件库（提取复用工厂，返回 HTML + 独立 mount）
| 组件 | 复用点 |
|------|--------|
| `KpiCard` / `StatCard` | 工作台 KPI、汇总表 stat-row、看板 dash-kpis |
| `TimeProgressBar` | 品牌/单品目标达成（时间进度线 + 落后/在线/领先三色） |
| `TierTable` | 返利政策档位表（当前档/下一档高亮） |
| `StatusChip` | 核销状态、维度/计量 chip |
| `Modal` / `Toast` / `Confirm` | 全局复用（沿用现有 `modalOpen/closeModal/toast/showConfirm`） |
| `FilterBar` | 看板筛选（期间/维度/计量） |
| `ChartCard` | 三图统一容器（标题/控件/说明/降级） |
| `Skeleton` / `Empty` / `ErrorState` | 三态首类 |

### 4.3 状态管理（单向流 + 作用域重渲染）
- **单一数据源** `store`（分区：`ui` / `forecast` / `policy` / `dashboard`），避免扁平互相污染。
- **作用域重渲染**：`renderRegion(id)` 只重画某个容器（如汇总表只重画 `#forecastTable`），**不重建整页** → 保住其他输入框焦点。
- **事件委托**：页面级 `click`/`change` 委托（v7 已有雏形），render 后无需重绑。
- **乐观更新 + 回滚**：采纳建议/停用启用先改本地、失败回滚并 toast。
- **API 封装**：`api(path, opts)` 统一带 Bearer、标准错误信封、超时；返回 `{success, data}` 或抛 typed error。
- **三态**：所有异步视图以 `status: 'loading'|'empty'|'error'|'ready'` 驱动渲染。

### 4.4 图表治理
- 单一 ECharts 实例管理器（route 切换 `dispose()`，避免泄漏）。
- 生产**打包进 Vite bundle**（不依赖 CDN）；加载失败降级静态 SVG。
- 主题色集中在 `variables.css` 令牌，图表取令牌值，保证双主题一致。
- 按需 `import` 图表类型，控制 bundle 体积。

### 4.5 表单
- 受控组件 + **可复用校验器**（`required` / `regexPeriod` / `numeric` / `matchNameMetric`）。
- 内联红字提示（非仅 toast），提交前整体校验。

## 5. 移动端适配规范

### 5.1 断点
- **≥1280**：桌面完整侧栏（248px）+ 多列网格。
- **768–1279**：平板，侧栏可收起为图标，网格降为 2 列。
- **<768**：手机，**底部 Tab 栏（5 主入口）+ 抽屉式“更多”**；卡片单列；KPI 1–2 列。

### 5.2 导航（手机）
- 底部固定 Tab：`工作台 / 预报 / 政策 / 看板 / 更多(抽屉)`。
- 抽屉放：消息推送、数据源、设置、AI 入口。
- 桌面侧栏在手机隐藏（不缩放硬挤）。

### 5.3 布局
- 汇总表：横向滚动 + **首列（商品）与末列（最终下单）固定**，触控可滑。
- 图表：触摸缩放/tooltip；canvas 自适应（`devicePixelRatio`）。
- KPI/卡片：单列堆叠，关键数字一屏看完（老板常在外）。

### 5.4 触控与输入
- 触控目标 ≥ **44px**；禁 hover 依赖（用 `:active`/`tap`）。
- 数字字段 `inputmode="decimal"/"numeric"` 唤起数字键盘。
- 中文 placeholder 带示例；失焦再校验，避免输入中被打断。

### 5.5 性能
- 图表按需加载；图片 `loading="lazy"`；长列表虚拟滚动（汇总表 400+ 行时）。

## 6. 中文用户体验细节清单

| 维度 | 规范 |
|------|------|
| 货币 | `¥` + 千分位（`¥12,800.00`）；无小数时去尾零 |
| 数量 | 明确单位「箱 / 件」，不混用；折箱保留 1 位 |
| 百分比 | 达成率 `82%`；差额“还差 40 箱”口语化 |
| 日期 | `2026年8月` / `2026-08`；相对时间“3 分钟前”+ 绝对时间 |
| 空值 | 显示「—」而非 `0`；未达成显示“缺数据”而非报错 |
| 加载 | 骨架屏 + 文案“数据加载中…”（不用转圈干等） |
| 错误 | 口语化：“统计期间应为 2026-08”，非“invalid param” |
| 确认 | 破坏性操作弹 `showConfirm`：“确定停用？小程序端将不再显示” |
| 无障碍 | label 关联输入框；正文对比度 ≥ 4.5:1；焦点可见 |
| 一致性 | 同义控件统一（按钮主色/描边/圆角 12–14px 全站一致） |
| 中文排版 | 数字与中文间留空格（`已收 8 / 13 人`）；避免英文混排歧义 |

## 7. 技术栈与落地约束（锁定）

- **前端**：Vite 工程（`static/`），原生 JS 模块 + `ModuleRegistry` 注册；**ECharts 打包进 bundle**（不依赖 CDN）。
- **后端**：FastAPI + SQLite（多租户 `tenant_N.db`），`rebate_rules` 已上线可复用。
- **复用既有**：`api()`、`modalOpen/closeModal`、`toast`、`esc()`、`showConfirm()`、`ModuleRegistry`。
- **视觉**：浅色默认（`variables.css` 令牌），深/浅双主题；品牌青 `#06b6d4`（与原图一致）。
- **安全**：RBAC fail-closed、租户隔离、密钥缺失即报错。
- **部署**：Vite 构建 → `rsync` 硬化（**绝不含 db**）→ `chown hergent:hergent`；前端部署不动后端/库。
