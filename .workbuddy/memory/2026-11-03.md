## v736 品牌色统一（小程序 ↔ Web），用户选方案 ②
- **用户报「小程序和 Web 品牌色不一样」→ 成立**。小程序 v393 用的是 **Web v717 就已修掉的旧值**：亮青 `#06b6d4` 当主色，实心底白字 **2.43:1**；Web 早已改成 `#0e7490`（5.36）。两边从那版起分叉。
- 🔴 **真根因是"一个品牌青长出三个值"**：`#06b6d4`(189°,白字2.43) / `#0891b2`(192°,压浅青底**3.54**) / `#0e7490`(193°,5.36)。`#0891b2` 是卡片副标题，11px 小字压 `#ecfeff` 连 AA 都不到 ⇒ **"觉得不一样"里有半是"看不清"**。
- **做法**：新建 `app.wxss` 声明 `page{--brand:#0e7490}`（本仓首次引入 CSS 变量；`page{}`+`var()` 是微信官方暗色适配的写法，基础库 3.4.3 支持）→ **62 处**字面量收成 `var(--brand)`；装饰项（`.msg-accent` 6rpx 竖条、`.prod-row-flash` 闪边）**也一起收**，否则它们成"全屏唯一亮青"，更像遗留 bug。
- **吃不到 CSS 变量的 5 处必须同批手改**：`app.json` navigationBarBackgroundColor / tabBar.selectedColor、`app.js` 与 `fill.js` 的 `confirmColor`、`privacy-settings.wxml` 的 `<switch color>`。
- 🔴 **最隐蔽的一处是图标**：`assets/tab-*-active.png` 是纯单色位图，颜色**烘在像素里**。只改 json 的 selectedColor ⇒「图标亮青 + 文字深青」并排，比改前更不一致。处理：**只换 RGB、alpha 逐像素不变**（可见像素 1418/1320 与改前完全一致 ⇒ 形状零改动），改后每个文件只剩 1 种颜色。
- **Web 法务页**：`public/legal/{terms,privacy}.html` 自己维护了 `--p:#0d9488`（青绿，色相差 18°）⇒ 改 `#0e7490`，链接 3.5→5.36。已部署 + **同步 `dist/legal/`**（否则下次部署闭包会把线上刷回旧色）。
- **护栏** `.workbuddy/tools/check-miniprogram-brand.mjs` 六条（字面量残留 / 令牌值 / 4 底色+白字对比度 / 5 原生载体 / **PNG 逐像素**（自带最小解码器）/ 令牌使用量下限 50）。**六态阳性对照全拦，还原 exit=0**。
- **刻意不做**：logo 渐变 `#0d9488→#06b6d4` 不动（用户决策，改要重出 6 尺寸+重提审）；`#ecfeff`/`#a5f3fc` 是 tint 家族（背景用）不并令牌。

### 本轮可复用判据
- 🔴 **"两边品牌色不一样"先数色值个数，别比色相**：一个语义位置只要出现第 2 个色值就是 bug，色相差 3° 人眼也能并排看出来。
- 🔴 **同一语义的"图标 + 文字"必须同批改**：文字色在 json，图标色在 PNG，是最典型的"改一半"。
- **PNG 单色图标改色**：保持 alpha、只替换 RGB，可保证形状像素级零变化；先统计可⻅像素的 RGB 种类数确认是单色（±2 噪声属压缩）。
- **令牌化前先确认运行时支持**：WXSS 变量在 `app.json`/`showModal`/组件属性里取不到 ⇒ 这 5 处必须留字面量并单独校验，不能"统一令牌"一刀切。
