## v736 品牌色统一（小程序 ↔ Web），用户选方案 ②
- **用户报「小程序和 Web 品牌色不一样」→ 成立**。小程序 v393 用的是 **Web v717 就已修掉的旧值**：亮青 `#06b6d4` 当主色，实心底白字 **2.43:1**；Web 早已改成 `#0e7490`（5.36）。两边从那版起分叉。
- 🔴 **真根因是"一个品牌青长出三个值"**：`#06b6d4`(189°,白字2.43) / `#0891b2`(192°,压浅青底**3.54**) / `#0e7490`(193°,5.36)。`#0891b2` 是卡片副标题，11px 小字压 `#ecfeff` 连 AA 都不到 ⇒ **"觉得不一样"里有半是"看不清"**。

- **吃不到 CSS 变量的 5 处必须同批手改**：`app.json` navigationBarBackgroundColor / tabBar.selectedColor、`app.js` 与 `fill.js` 的 `confirmColor`、`privacy-settings.wxml` 的 `<switch color>`。

### 本轮可复用判据
- 🔴 **"两边品牌色不一样"先数色值个数，别比色相**：一个语义位置只要出现第 2 个色值就是 bug，色相差 3° 人眼也能并排看出来。
- 🔴 **同一语义的"图标 + 文字"必须同批改**：文字色在 json，图标色在 PNG，是最典型的"改一半"。
- **PNG 单色图标改色**：保持 alpha、只替换 RGB，可保证形状像素级零变化；先统计可⻅像素的 RGB 种类数确认是单色（±2 噪声属压缩）。
- **令牌化前先确认运行时支持**：WXSS 变量在 `app.json`/`showModal`/组件属性里取不到 ⇒ 这 5 处必须留字面量并单独校验，不能"统一令牌"一刀切。

### 08:03 修复「生产含 git 里没有的内容」的禁令级项（hergent-erp 仓）

### 13:20 v738 汇总表前三列不跟斑马纹走（提交 `92b29f6d`，已部署）
- 报障：预报订单汇总表「序号/商品名称/到货周期」三列行底色始终纯白，不跟后面列深浅交替。
- 🔴 **根因不是斑马纹没画上，是画在了被盖住的地方**：斑马纹在 `<tr>`，这三列是**冻结列**，为遮横向滚动内容在 `td` 上写死 `background:var(--bg)` ⇒ 子元素背景盖住父元素背景。两条规则各自都对，单点检查永远看不见 ⇒ 判据只能是**同一行不同 td 的 computed backgroundColor 是否一致**。实测改前 tr=#f5f5f7、前三格=#ffffff、第四格起=#f5f5f7。
- 同一根因压掉三件事（同批修）：hover 在三列内**完全无反应**；选中行/错误行在三列内不上色；**改单网格序号列**同样脱节（走 `nth-child(even)` 不是 `.zebra`）。
- 修法：行状态统一下发 `--row-bg`（zebra/hover/selected/row-error + 改单 nth-child(even)/hover），冻结列只读 `var(--row-bg,var(--bg))`（兜底保证横向滚动仍不透明）。**不给冻结列单独补斑马规则**——那只会修好斑马、hover 依旧死。
- 🔴 选中行原本是半透明 `rgba(6,182,212,.10)`：冻结格刷在 tr 之上，同色刷两遍会叠成 2 倍浓度 ⇒ 必须 `color-mix(in srgb,var(--p) 10%,var(--bg))` 压成**实色**再下发；tr 自己的 `background` 也改成读 `--row-bg`（一个值两处用，不写两份）。
