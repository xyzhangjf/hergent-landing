## 客户列（唐成/黄家伟）消失根因修复（08-24 末，后端 save-matrix）
用户反馈：预报表体"原来有的客户/业务员字段（唐成/黄家伟…）现在没有了"。

### 根因
- 客户列 = 交叉表报单单元 = `cross.value.units`，唯一来源 `loadEditGrid`→`summary` 按 `rows[].sources`（forecast_submission_items）聚合。前端模板（只读 1676 / 编辑 616）**无条件 `v-for cross.units`**，不受列设置/列级权限影响——"消失"只可能是 `units` 为空。
- 链路：前端 `saveEdits`(2127) 传**全量客户名**（含 0 数量）；后端 `save_matrix`（forecast_submissions.py:249 `if qty<=0:continue` + 265 `if not items:continue`）对"本周期无任何正数量商品"的客户**直接跳过、不建记录** → 保存后再 loadEditGrid 时 summary 的 sources 无该客户 → units 重建丢失 → 整列消失。
- 触发：某周期给唐成/黄家伟填数并保存→留住；清空数量或新建期次没填→保存时后端跳过→刷新即丢。确定性 bug，与列设置/权限/期次切换无关。

### 修复
- `server/routers/forecast_submissions.py` `save_matrix`：删 `if not items: continue`，改"即使 items 空也用占位 item（`product_id:0,product_name:'__列占位__',quantity:0`）落库"；`saved_items` 只统计正数量（`sum(1 for it if qty>0)`），保证 0 数量客户列持久化、刷新不丢。
- `server/erp_db.py` `forecast_submission_summary` rows 查询加 `AND i.product_name != '__列占位__'`（排除占位行当垃圾商品行；detail 子查询保留占位以聚合出客户列）。商品行来自 `products.grid()` 不经 summary.rows，占位不影响商品清单。
- 本地逻辑自检：客户[唐成(全0)/黄家伟(有量)]→saved_customers=2，唐成落库占位；py_compile 通过。

### 部署
- `bash deploy.sh`（带 `--exclude='.env'`）；`health HTTP 200` + `systemctl is-active hergent-erp`（首探 000 系 restart 后 curl 过早，sleep2 复探 200 正常）。
- 该修复只保**今后保存**的客户列刷新不丢；当前生产已丢失列需用户在编辑网格底部「客户名」框回车重新加列并保存一次（或员工/小程序补报）恢复——旧期次这些客户已无记录。

### 教训
- 前端"强制全量传清单" + 后端"按有量才落库"会静默丢列（状态不一致陷阱）；凡前端传全量、后端需回显的清单类数据，必须"空值也占位持久化"。
