### boss 登录后瞬间跳回登录页 —— 根因=401 竞态（已修）
- 现象：erp.hergent.cn 登录成功（拿到 token）后极快弹回 #/login，token 被清空。hergent.cn(v2副驾) 不受影响。
- 根因（竞态）：ERP 前端在**页面初始化时就自动并发拉 dashboard 数据**（/api/products、sale-orders、tasks、cron/list、skills/list、ai-mode），此时尚未登录（localStorage 无 token）→ 这些请求 401。401 响应是异步的，可能在用户**登录之后**才到达。
  - `static/js/core/api-client.js` 的 401 处理：**任何** 401 都 `localStorage.removeItem('hergent_token')` + 弹登录层。
  - `static/app.js:385` 全局 `api()`：`if(r===null){if(T){T='';...;location.reload()}}` —— 只要 T 为真就 reload。
  - 于是：登录后写入的 token，被"迟到"的预登录 401 清掉并 reload → 弹回登录页。**间歇性**（取决于 401 响应到达时机），首次复现抓到 #/login、二次抓到 #/dashboard。
- 修复（仅 ERP 前端，未动后端）：
  - `api-client.js` 401 处理加 `hadToken = !!_token()` 守卫：仅当**本次请求确实带了 token** 才清会话/弹登录；预登录的无 token 401 静默返回哨兵 `{_noauth:true}`。
  - `app.js` 全局 `api()` 增加 `if(r&&r._noauth) return null;` 在 reload 逻辑之前，使预登录 401 被忽略（不弹错、不踢出）。
  - 真实会话失效（带 token 仍 401）仍正常清会话+reload 回登录。
- 构建部署：ERP 前端是 Vite 工程，根 = `hergent-erp/static/`，`npm run build`→`dist/`，rsync `dist/` 到生产 `/opt/hergent-erp/static/`（**不用 --delete**，保留 vendor/）。新产物 `main-BLLmbkpP.js`。

## 排查 hergent.cn 副驾首屏 8 个接口 403（结论：生产孤儿后端进程 + nginx keepalive）
- 现象：用户贴 hergent.cn/#/forecast 控制台，8 个 Workbench 数据接口全 403（dashboard/today-profit、batch/expiry-scan、today、forecast-submissions/pending、collections/queue、forecast/periods、forecast-audit/rebate-summary、forecast-submissions/summary）。另有 `COMPUTE_PAGE_FINGPRINT`（浏览器插件噪音，忽略）。
- 逐层排查：
  - 后端对 boss 直接 8700 登录 → 8 端点全 200；经 nginx hergent.cn(boss token) → 全 200。**后端与模块映射健康**。
  - erp.db sessions 查用户公网 IP `27.27.126.231`：403 会话 = user_id=2 / username=boss / role=boss / 未过期 -> 不是 token 失效、不是权限不足。
  - 生产日志(12:17)：该 IP 命中 `403 Forbidden` 的正是这些 forecast/collections 端点；同一后端我的 127.0.0.1 boss 测试(12:22)全 200。
  - 根因：**生产有 2 个 server.py 进程**——systemd 托管的当前进程(1816423/1817783，当前代码) + 一个 Aug02 手动启动的**孤儿进程(1252131，旧代码)**。旧代码的 `_PATH_MODULE_MAP` 未映射这些路径 → `MODULE_NOT_CONFIGURED` 403；nginx upstream keepalive 把用户部分请求路由到该孤儿进程 → 零星 403。
  - 注意：`systemctl restart` 只重启 systemd 单元，杀不掉手动启动的孤儿；且旧进程曾占 8700，restart 后新进程接管 8700，但孤儿仍在、keepalive 残留连接继续服务旧响应。
- 修复（运维操作，未改代码）：`systemctl stop hergent-erp` → `kill -9 1252131`（按精确 PID，勿用 `pkill -f server.py` 会误杀 ssh 自身会话）→ `systemctl start hergent-erp` → `nginx -s reload`（清 keepalive）→ 验证单一进程 + health 200 + boss 轮询 12x 全 200 + 8 端点经 hergent.cn 全 200。
- **部署卫生铁律（记）**：每次重启/部署后端后，必须 (1) 确认 8700 仅被 1 个 systemd 进程持有（ss -ltnp|grep 8700）、(2) `pgrep -f server.py` 确认无孤儿、(3) `nginx -s reload` 清 upstream keepalive。避免 `pkill -f 'server.py'` 自伤 ssh。

## 头像不显示 BUG 修复（用户报「头像没有加载出来」）
- 现象：任务④ 部署后用户实测头像不显示。真机 curl 所有 role 头像 `GET /api/ai/roles/{id}/avatar` 全 401。
- 根因：端点代码虽标注"公开无鉴权"且未调 `_auth`，但被**全局认证中间件 `auth_required_middleware`(server.py:244) 与 `rbac_middleware`(server.py:554) 拦截**——两者用 `_PUBLIC_PATHS` 前缀白名单，头像路径不在其中，而 `<img>` 标签请求**无法携带** JS 从 localStorage 读取的 Authorization token → 401。任务④ 当时 E2E 用浏览器内 fetch（带 token/CSRF）验证，绕过了真实 `<img>` 加载路径，故未抓出（假阴性）。
- 修复（hergent-erp/server）：
  - `server.py` 在 `auth_required_middleware` 与 `rbac_middleware` 开头各加**精确放行**：`if request.method=="GET" and re.match(r"^/api/ai/roles/[^/]+/avatar$", request.url.path): return call_next(request)`（仅 GET、仅该路径，不动其余角色接口）。
  - `ai_roles.py` 加 `find_role_avatar_fallback(role_id)`（无租户上下文时按角色名扫描 `role-avatars/*/<role>.png`，优先 tenant 1）；`server.py` GET 头像端点改为 `get_role_avatar_bytes(tid,role) if tid else None`，读不到再 `find_role_avatar_fallback`（前端单租户无 tenant 概念，`<img>` 不带 tenant，故需服务端回退）。`import re` 已补。
- 部署陷阱：flatten rsync `server/` → `/opt/hergent-erp/` 时**必须 `--exclude='static'`**——生产 `/opt/hergent-erp/static` 是含 `role-avatars/` 的运行目录（运行时落盘头像），若把本地 `server/static` 真实目录同步进去会冲突(abort exit 23)且风险删头像。命令同时排除 *.db/__pycache__。头像 10 文件完好保留。
- 验证：
  - 后端 `py_compile` COMPILE_OK；部署 health=200。
  - 生产 curl **无 token** 5 角色(copilot/accountant/ops/secretary/cs)全部 `200 image/png`（修复前 401）。
  - **前端无头浏览器 E2E（Chrome151+puppeteer，demo-login）真机用 `<img>` 标签加载 5 角色头像**：全部 `ok:true, naturalWidth=256, naturalHeight=256`（真实 256×256 PNG 显示成功）。唯一 console error=favicon 404（无害）。
- **结论**：头像在生产浏览器真实显示，BUG 修复闭环。**铁律重申**：头像/图片类公开资源必须经 `<img>` 标签真机验证，不能只靠 fetch/curl 带 token 验证（后者绕过了 `<img>` 无 token 的真实路径，会假阴性）。
- 复盘：`ai_roles` 表在 `erp.db`（主库）；前端单租户无 tenant 概念，角色头像靠服务端 fallback 扫描 tenant 1 命中。
