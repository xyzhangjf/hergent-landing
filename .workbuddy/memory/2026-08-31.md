## 员工档案编辑弹窗顶部溢出修复
- **现象**：编辑弹窗（已有账号的员工）比添加弹窗高，顶部从屏幕沿溢出一点；添加弹窗位置正常。
- **根因**：`.edit-modal .df-modal-body{max-height:80vh}` 让 body 最高 80vh，加 header/footer 使整体弹窗超过视口；配 `.df-modal` 的 `top:45%+translate(-50%,-50%)` 居中，高弹窗顶部被推出屏幕。
- **修法（EmployeeArchive.vue 样式）**：把高度上限移到**整个弹窗**——`.df-modal` 加 `max-height:88vh;display:flex;flex-direction:column`；`.df-modal-hd/.df-modal-ft` 加 `flex-shrink:0`；`.df-modal-body` 加 `flex:1 1 auto;min-height:0;overflow-y:auto`（内部滚动）；删除 `.edit-modal .df-modal-body{max-height:80vh}` 冗余上限。效果：无论内容多高，弹窗都在视口内居中、不溢出，与添加弹窗表现一致。属通用修复，对所有 `.df-modal` 生效。

## 仪表盘 TDZ 运行时错误修复（线上事故）
- **现象**：用户报「页面出错了：Cannot access 'D' before initialization」。'D' 是 minify 后的变量名。
- **根因**：`dashboardModel` computed（Rebate.vue:781）内部写了 `const rules = (rules.value || []).filter(...)`——局部 `const rules` **遮蔽了外层 `rules` ref**，RHS 的 `rules.value` 引用的是正在声明的局部 `rules`（TDZ），渲染即抛错。之前 `mainTab` 默认 `'rules'`，仪表盘 getter 从不执行，故不暴露；本次把默认改成 `'dashboard'`，一渲染就中招。
- **修法**：局部变量改名 `activeRules`（`.filter`/`for`/`rules.length`×2 同步改），消除遮蔽。另 grep 全文件确认无同类 `const X = (X.value...)` 自遮蔽。
- **构建部署**：重新 `npm run build`（新产物 `Rebate-hgnjvBiJ.js`）→ `rsync` + chown。⚠️ 沙箱未做浏览器真机验证；建议用户硬刷新（Ctrl/Cmd+Shift+R）清旧包缓存。
- **经验**：Vue `<script setup>` 里 computed 内若用 `const` 声明与外层 ref 同名的局部变量并立即 `.value` 访问，必踩 TDZ——computed 惰性不救命，因为 RHS 在声明语句内同步求值。命名务必区分（如 `activeXxx`）。
