### 修复仓库输入框点击无弹窗 (v107.97)

**问题**：点击访销订单页面的仓库输入框，没有弹出仓库选择列表弹窗。

**根因（双重 bug）**：
1. **结构性裁剪**：`.vsf-field{overflow:hidden}` (styles.css:391) 裁剪了 absolute 定位的下拉菜单
   `.searchable-dropdown{position:absolute;top:100%;...}`。dropdown 从输入框底部 top:100% 展开（高度 40-200px），
   必然超出 `.vsf-field` 的 30px 高度，**100% 被裁剪**（实测 visiblePct: 0）。
2. **数据假象**：浏览器调试时发现 warehouses=0 → 后端 `/api/warehouses` 实测返回 3 个仓库
   （临期仓/测试仓库/总仓）。前端拿到空数组是因为伪造 token 401 + safe() 兜底 → 真因是裁剪而非数据。

**修复方案（结构性根治，与客户/业务员弹层同模式）**：

`app.js:3257-3291` 在 `initSearchableSelect` 前新增 `_positionSearchableDropdown(dd, input)` 辅助函数 +
全局滚动/缩放跟随监听（capture:true 捕获所有容器滚动）：
```js
function _positionSearchableDropdown(dd, input){
  var r = input.getBoundingClientRect();
  var w = Math.max(160, Math.min(r.width, window.innerWidth - r.left - 8));
  dd.style.position = 'fixed';  // 关键: 脱离所有父级 overflow 裁剪
  dd.style.top = (r.bottom + 2) + 'px';
  dd.style.left = r.left + 'px';
  dd.style.width = w + 'px';
  dd.style.maxHeight = Math.max(80, Math.min(200, window.innerHeight - r.bottom - 12)) + 'px';
}
```
render() 末尾调用定位 + 加空态提示 + mousedown 加 `if(!id)return;` 保护空态 option 写入 NaN。

`styles.css`：`.searchable-dropdown` z-index 100 → 999999；新增 `.searchable-empty` 样式（居中、灰色、不可点击）。

**副收益**：部门/司机/车辆字段的 dropdown 同样被修复；旧销售/采购表单（ssRbContact 等）dropdown
也脱离 modal overflow 裁剪（绝对净改进）。

**部署**：main-BeBPs7fM.js + main-CXGKN9hs.css，health 200。

**实测（生产 + 真实 token）**：
- 仓库下拉显示 3 个仓库（临期仓/测试仓库/总仓）
- pos:"fixed"、dropdownTop:194 > fieldBottom:192（完全在字段下方）
- 选中"临期仓" → input="临期仓" / hidden=1 / dropdown 关闭
- 视觉截图：白底圆角阴影下拉，悬浮在表单上不裁剪

**教训（★）**：
- **下拉/弹层永远用 fixed 定位**，不要依赖 relative 容器内的 absolute — 父级 `overflow:hidden`
  是隐式裁剪陷阱（field 本身的 overflow 是为了 label ellipsis 等目的，不能去掉）。
  fixed 定位是标准做法（Modal/Vue/Picker 库都用 fixed）。
- 排查"点击 X 没弹窗"时，**先看 DOM 状态**（dispatchEvent 后查 .show / rect）区分"事件没绑"
  vs "绑了但被裁剪" vs "绑了但数据空"，三种根因修复方式完全不同。
- `Promise.resolve([])` 在调试时是常见陷阱（safe 兜底成空），看到前端空数据先确认后端，
  再怀疑前端逻辑。

**需求**：预配送时间（`vsf-delivery-time`）跟随预提货日期（`vsf-delivery-date`）联动，仍可手动修改。

**联动规则**：
- 日期=今天 → 当前时间+2h，取整到半小时（超 22:00 或跨天归次日 08:00）
- 日期>今天 → 08:00（低温奶冷链晨配习惯）

**实现**（app.js showVisitSaleForm 前 + modal 挂载后）：
- 模块级 `_vsfDeliveryTimeTouched` 标记：`_dtEl.addEventListener('input', ...)` 置 true →

  **不用 toISOString()** —— UTC 在凌晨 8 点前会把今天误判为昨天（app.js 里 `today` 变量
  都是 toISOString 有同样 bug，联动函数刻意绕开）
- 绑定：modal appendChild 后 `_ddEl.addEventListener('change', sync)` + 初始调用一次

**实测**：打开表单 17:06 → 19:30（+2h 取整）；改明天 → 08:00；改回今天 → 19:30；

### 日期输入框点击展开日历面板 (v107.99)

**需求**：单据日期/预提货日期 input[type=date] 点击任意位置（含空白区）都展开日历面板。

**实现**（app.js showVisitSaleForm 内 modal 创建后）：
```js
function _vsfOpenDatePicker(ev){
  var el = ev.currentTarget;
  try{ if(typeof el.showPicker==='function'){ el.showPicker(); return; } }catch(e){}
  if(el.dataset._pickerFallback) return;  // 防递归: fallback 的 el.click() 会再次触发 click handler
  el.dataset._pickerFallback='1'; el.focus(); el.click();
  setTimeout(function(){ delete el.dataset._pickerFallback; }, 100);
}
['vsf-order-date','vsf-delivery-date'].forEach(function(id){
  var el=document.getElementById(id); if(el) el.addEventListener('click', _vsfOpenDatePicker);
});
```

**关键**：
- showPicker() 需 transient activation（真实鼠标点击即可；el.click() 也授予 activation）；
  非激活态抛 NotAllowedError 被 catch，fallback 到 focus+click（带防递归标记）
- **不动 value** —— 只触发 showPicker，数据绑定/change 事件/预配送时间联动完全不受影响
- **自动聚焦当前日期**：两字段 value 默认 today，showPicker 打开时浏览器默认高亮/定位 value 日期；
  value 为空时浏览器也默认定位当月高亮今天

**实测**（spy showPicker 验证）：单据日期 click → showPicker 调用 1 次，value 保持 `2026-08-07`；
预提货日期 click → showPicker 调用 1 次。headless Chrome 不渲染原生面板（已知限制），
真实用户鼠标点击一定有 transient activation → 面板正常展开。部署 main-oDuVCCsx.js，health 200。
