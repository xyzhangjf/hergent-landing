## 07:23–07:35 · v333b 权限页「自定义角色」标签**误标在每一列**（老板提问引出）

老板原话：「每个角色下面都写了一个『自定义角色』是什么意思？」

**这是 bug，不是设计。** 该标签本意只标**自建角色**（业务页入口走**角色门槛**，自建角色不在任何名单里
⇒ 给它勾再多模块那些页面也不会出现；不说，客户就认定权限没生效）。
实测生产 `tenant_1` = **9 内置 + 1 自建（库管）** ⇒ 应只有 **1 列**标；实际**9 列全标**。

### 根因 = 后端字段「下发了」，前端对象字面量**没搬** ⇒ `undefined` 恒真

- `server.py::get_role_perms` **确实下发** `"is_default": role in _DEFAULT_PERMS`
  （同行还下发 `end_builtin` / `default_login_scope`）。
- 但 `Settings.vue::loadPerms()` 构造角色对象的**字面量**只搬了
  `name / perms / is_custom / end / endBase / end_is_custom / end_locked_web` —— **漏搬 `is_default`**。
- ⇒ `role.is_default === undefined` ⇒ `!undefined` **恒真** ⇒ 每列都渲染「自定义角色」。

**同一处缺失的第二个症状（一并修）**：`resetAllRoles()` 的 `.filter(r => r.is_default && …)`
**恒空** ⇒「全部恢复出厂」永远回「没有可恢复的系统自带角色」= **功能静默失效**。
⇒ 这正是本仓「静默洞三条」里的**「白名单漏字段」**，又一次。

### 修法：判据从「API 字段」换成「名字」——结构上不可能再被漏搬咬到

`v-if="!isCanonicalRole(role.name)"`（**两处同改**：列头标签 + `resetAllRoles` 筛选）。
理由两条：① `name` 是对象键，**不可能被白名单 map 丢掉**；
② 这正是 `backend-auth.md §2` 已定的判据（`is_custom` 是「本租户有覆盖行」，
**内置角色照样为 true** ⇒ 不能拿它当「自定义角色」）。

### 护栏加固：把两个角色集合「可证相等」锁死

`role-registry-consistency-check.py` B 段原只断言「后端 ⊆ 前端」；补**反向**断言
「`ROLE_NAMES` 无后端不存在的角色」+ **反例自证**（塞一个幽灵名必须转红）。
因为 `isCanonicalRole` 现在承载判据 ⇒ 前端多一个名字会把自建角色**误判成内置**，
还会被「全部恢复出厂」删掉配置行（删行 = 该角色无权限 = 派人的人全员 403）。**101/101 → 103/103**。
