- **默认值本地时间格式化**（不用 toISOString 避免 UTC 偏移——凌晨 0-8 点 UTC 会显示昨天）：
  ```js
  var _p2d = function(n){ return String(n).padStart(2,'0'); };
  var _nowD = new Date();
  var orderDateTime = _nowD.getFullYear()+'-'+_p2d(_nowD.getMonth()+1)+'-'+_p2d(_nowD.getDate())+'T'+_p2d(_nowD.getHours())+':'+_p2d(_nowD.getMinutes());
  ```
- **提交转换**：`value.replace('T',' ')+':00'` → 'yyyy-MM-dd HH:mm:00'（匹配 sale_orders.order_date datetime 格式，后端直接透传无需改）

- 默认值 `2026-08-08T04:45` = **今天本地日期**（若用 toISOString 会错显示昨天 08-07）——跨日/时区验证通过 ✅

### v107.115 预提货日期联动修复（凌晨 05:30）
**根因**：v107.114 升级订单时间 datetime-local 用**本地时间**，但预提货日期默认值仍 `today = new Date().toISOString().slice(0,10)`（UTC）→ 凌晨 0-8 点预提货日期默认"昨天"（比订单时间早一天），且 #154 联动只在 change 时触发、初始不校正 → 用户感知"预提货日期没联动"。
**修复**：① `today` 改为 `orderDateTime.slice(0,10)`（本地，与订单时间同源）；② 打开表单初始校正——预提货日期 < 订单时间日期则提升 + 触发 _vsfSyncDeliveryTime()。
**实测**：05:29 打开 orderTime=08-08T05:29 / deliveryDate=08-08（一致，修复前为 08-07）；改订单时间 08-10 → 预提货提升 08-10、时间 08:00；改回今天 → 保持 08-10（只升不降）；手动改预提货 08-09 → 时间 08:00。
**部署**：main-DUzOSKCP.js，health 200。
**教训**：同一表单内的日期默认值必须同源（本地时间），toISOString(UTC) 与本地混用必然凌晨差一天。
