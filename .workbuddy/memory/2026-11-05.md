## 07:23–07:45 v769：目标配置「品牌目标返利率可留空」

**用户口径**：「在『目标与返利—目标配置』页面创建和编辑品牌目标时，请支持用户可以留空『返利率』字段，因为部分厂家本身没有返利，不应强制填写。当前留空时无法保存，请核实该问题，定位校验逻辑的原因并修复，确保『返利率』为空时品牌目标可以正常创建和保存，同时验证非空返利率等原有场景仍然正常。」

### 根因（两层，实证过）
1. 前端 `TargetFormModal.vue::save()` 的 v126 硬拦「请至少填写一个月的返利率」：
   `monthlyRates` 空 ⇒ 直接 toast + return。创建与编辑共用同一个 `save()`，两条路径都中招。
2. 后端 `routers/rebate_rules.py::validate_rule` 的 v360 `_is_num_like` 兜底：
   空串/None 报「比例返利(rebate_rate)必须是数字」，直连 API 同样 422。

**实证**：改前在生产机跑 `rebate-rate-optional-check.py`（用 `.env` 载入 ERP_SECRET），
A1 空串 / A2 None 两条红，报错逐字为「本月确实没有返利请填 0，不要留空或填非数字」；

### 🔴 最关键的判断：只删硬拦会造成真金白银错误
`resolve_month_rate(rule, ym)` 对「该月不在 `monthly_rates`」会**向前找最近有值的月**
（含跨年回绕）。1 月填 10%、2 月留空不写 ⇒ 2 月被静默套成 10%，零报错多算返利。
自检 R2 反证实测返回 0.1，R1（2 月显式 0）返回 0.0。

**修法**：`buildMonthlyPayloads` 把「有目标金额 + 返利率留空」的月**显式落 0**，
无金额月份不落（不制造 12 个 0、不影响月份锁）。不改动 `resolve_month_rate` 核心计算。
