### 三条真机实测出来的硬事实（都写进了规范）

1. 🔴 **`MAX_W` 不能设成「看起来够用」的 720**。销售建单页在 1600px 屏上「商品」列**默认就有 794px**
   （该表只有 7 列），硬夹 720 的结果不是「拖不动」而是**越拖越窄**（794→720），用户会以为拖动坏了。
   改成 2400（只拦"拖到天上"这种误操作）。这是**首轮探针跑出来的真实缺陷**，已修。
2. 🔴 **必须同时写 `width` 和 `min-width`**：CSS 里 `.ipn-c-prod{min-width:240px}` 会**挡住拖窄**，
   只内联 `width` 时"往窄拖不动"。
3. 🔴 **撤底色必须显式写 `transparent`**，不能靠删规则 —— 全局 `.input{background:var(--bg3)}` 还在，
   删规则只会让输入框退回全局灰底（「以为改了、其实没生效」）。
   **只撤明细表**：表单头的**框**（`.ipn-hd-box .ipn-f`，即「供应商 / 客户」那一格）**仍保留 `var(--bg3)`**。

3. **探针 INIT 里硬编码的 `hergent_v2_user` 必须与 token 是同一账号**：前端用 localStorage 的 `role`

# v445 明细表输入框「边框三态」（默认无框 → hover 灰 → focus 青+发光）

老板原话：「在『产品明细』区域内的所有可编辑输入框上移除默认边框…仅在 hover / focus 时才显示；
悬浮与聚焦要有明显区分；切换不得引起尺寸抖动或行位移；禁用只读不出现悬浮边框；不影响对齐与
校验错误提示」。

🔴 **「产品明细」= 建单页的「商品明细」区**（系统内叫商品明细，舟谱叫产品明细）。
可编辑的只有两个建单页：`InvPurchaseNew.vue:313` / `InvSaleNew.vue:228`；
详情页（InvPurchaseDetail / InvSaleDetail）的同名区是**只读展示**，无输入框 ⇒ 不在范围内。

## 实现（前端两页，后端零改动）
- 默认：`border-color: transparent`（**不是** `border:none` —— 边框宽度仍 1px，盒模型不变 ⇒ 零抖动）
- hover（**行级**）：`--bd` 淡灰描边，整行一起浮起
- focus：`--p-dark` 品牌青 + `0 0 0 3px var(--p-bg)` 外发光（悬浮**不给**发光）
- 采购页 `.ipn-v`（v417j 文本态 span）用 `inset box-shadow` 画框（span 加 border 会顶行高、紧凑档切字）

## 本轮最关键的坑（差点埋雷）
「默认透明」选择器 `table.ipn-tbl .ipn-in:not(:focus)` 权重 **(0,3,1)**，**高于**全局
`.input.err` / `.input:disabled` / `.input[readonly]` 的 **(0,2,0)** ⇒
**不显式写回就会把校验红框一起变没**（静默失效）。同理禁用格会浮框（退货明细 `ret_qty`
绑了 `:disabled="!Number(row.returnable_qty)"`，是真实场景，不是假想）。
另：`.err:focus` 的**红发光**也要写回，否则被青光盖成"红框配青光"。
