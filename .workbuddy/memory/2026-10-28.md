## 10:09–10:40 v714 / v715 利润表口径统一（用户选「按你的建议做」= 定第 2 项）

### 结论先说
改前「利润表(权责)」**显示的数字与任何一个月都对不上**：`?month=2026-10`、`?month=2026-06`、
不带 month **三次都是 878 万**，而 2026-10 真实签收单是 **0 张**。

### 四条根因（实测，不是推断）
1. **科目分类名对不上（主因）**：`get_pnl_gl` 取 `category IN ('收入','成本','费用')`（21 个科目），
   而本账套 **109 个损益科目的 category 是「损益」**，唯一有发生额的 `6001`（98,325）就在里面
   ⇒ `revenue`/`cogs`/`total_expense` **恒为 0** ⇒ 路由 `if revenue>0 or net_profit!=0` 永不成立
   ⇒ **GL 分支从上线起就没走到过**，一律回落现金制全期累计。
2. **5 开头存货科目被算成营业成本**：`category='成本'` 里混着 5001 生产成本 / 5101 制造费用 /
   5201 劳务成本 / 5301 研发支出 / 5401 工程施工。隔离库实测：老代码 `cogs = 9,999`（整笔混入）。
3. 父子科目一起加（同 v708）+ 收入只取 credit、成本只取 debit ⇒ 红冲全丢。
4. `net_profit` 里 `+ (cat_sum(rev,'credit') - revenue)` 恒为 0 —— 死逻辑。

### 改后
- 全集只认 **6 开头**（`category='损益'` 仅补漏 + `unclassified` 上报）
- `60/61/63`=收入、**`6401`=销货成本**、其余=费用（**`6402` 归费用**：它挂的是客户费用/月返/陈列费/配送费）
- v708 叶子有效去重；净额按方向（收入 credit-debit / 成本费用 debit-credit）
- `get_pnl(month)` 新增按月；**不带 month 时 SQL 与返回体逐字不变**（KPI 非回归）
- 回落标 `basis=cash` + `source=fallback_business_docs` + `month` + `note`
