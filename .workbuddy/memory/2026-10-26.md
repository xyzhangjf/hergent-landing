## v688 采购建单表 125% 缩放下不再横滚（老板选 A）

- 数字列（条码/价格/数量/金额/库存/批次）一个没压 —— 截断=读错金额。

**验证**：1536 下订货/退货均 1248/1248 ✅；最不利密度 13 列零截断、行高 30px 不变；

### 🔴 迁移范式的三条硬判据（下次别重新试错）
1. **内部布局必须留在 slot wrapper**（`.ba-fields`/`.df-body`/`.cc-body`…），不能放组件里：
   父页 scoped 的后代选择器（`.xx-modal .xx-field`）命中不到子组件内部元素。
2. **类名透传（overlayClass/panelClass）不是解法**：v-if 挂载下父页规则照样打不到组件内部元素，
   透传只是拿到类名、拿不到对应规则。试过、放弃。
3. **`#header` 只替换标题区，不替换关闭按钮**：否则每个自定义头部的页面都要自己再写一个 X。

### 🔴 收编带来的唯一行为变化必须补齐
16 页原本**没有** ESC / 遮罩关闭。收编后组件统一提供 ⇒ 等于给 18 个表单页开了
「一按就关、改动全丢」的入口。解法：组件加 `guardClose`（默认关），19 页开启。
- 判据 = **纯 DOM 级**：打开后只有真实 `input`/`change` 事件才算「动过」
  （程序化赋值不触发事件 ⇒ 自动带出字段不算改动）；纯查看弹窗无控件 ⇒ 永不拦。
- 交互 = 第一下只提示（`.ui-modal-guard` 琥珀条）、第二下才关。
- 不给 19 页各写 isDirty：那等于把 SupplierArchive 的基线 bug 复制 19 遍。

### 探针抓到的真 bug（已修）
`SupplierArchive.tryClose` 原为 `if (isDirty.value) { closeHint=true; return }`，
**缺 `&& !closeHint.value`** ⇒ 只要改过字段就永远关不掉（ESC/X/遮罩全失效，只能点「放弃改动」）。
与下方 `onCancel` 口径不一致才埋下的。修正为 `if (isDirty && !closeHint)`。

## 大模型对话三点改进方案（模型选择 / 成本 / 积分）— 产出 `大模型对话三点改进方案-2026-10-26.md`

用户提三点：①无模型选择 ②模型偏贵 ③不显示积分。要求参考 WorkBuddy 实现。

### 🔴 实测把用户的第②点推翻了一半
上游 `config.yaml` = `deepseek-v4-flash`（**已是最便宜档**）。账本全期：
2759 次调用 / 897 万输入 tokens / 1.83 亿缓存读 / **$2.38**。⇒ **换模型省不了钱**。
真因（决定性实测）：一句「说两个字」→ `usage.prompt_tokens = **20867**`。
`sessions.system_prompt` = **18,477 字符**（人设/风格/回复骨架/经营卡 JSON/用词白名单 + Hermes 内置
`Finishing the job`/`Parallel tool calls`/`Tool-use enforcement`/`Skills(mandatory)`）。
成本模型 = **每轮 20K 固定开销 × 单会话 34~77 轮**（实测最高 77 次 API 调用 / $0.0818）。
⇒ 省钱的杠杆顺序：**提示词瘦身(最多 55%) > 轮数上限场景化 > 缓存纪律 > 上下文压缩 > 分档路由**，
「换更便宜模型」排最后且收益 0。

### 🔴 第③点的真因：不是缺界面，是**口径错了 3000 倍**
零件全在（`ai_usage` 表 / `ai_quota` / `GET /api/ai/quota` / `copilot_proxy.py:199-227` 硬拦已上线），
但前端上报的是 `input_chars: input.length` —— **用户在输入框打了多少字**。
本月账本 81 次调用只记 10,593 字符，真实是同量级 897 万 tokens。配额形同虚设。
✅ 好消息：**Hermes SSE 末尾自带 usage**（`{"prompt_tokens":20867,"completion_tokens":6}`），
`_iter_upstream` 旁路读一眼即可，**不需要解析再重组**（不破「字节级透传」红线）。

### 🔴 第①点：模型选择曾加过、被主动撤下（2026-09-25）
根因是网关 `config.yaml` **没有 `model_routes`** ⇒ `_resolve_route(alias)` 恒空 ⇒ 传任何模型名
都静默回落 ⇒ 那是「看起来切了其实没切」的控件（账本只有 flash 可证）。
⇒ **前置条件是改网关，不是前端工作量**。恢复三步：网关加 model_routes → 白名单放开 → 前端选择器。
**硬闸门三条判据**：新模型名出现在 `session_model_usage` / 两次请求 `estimated_cost_usd` 不同 /
`prompt_tokens` 不变。⚠️ 只验「请求回显了 model」不算 —— 回显恰恰是当初误判的根源。

### 🔴 归因限制（别踩）
Hermes `state.db` 的 `api_server` 会话 **129 个全部 `user_id=NULL`**、`session_key=NULL`，
`messages.token_count` **6346 条全 NULL** ⇒ **不能读 Hermes 库做用户归因**。
归因必须在代理层做（它握 `u` + `tenant`）。

### WorkBuddy 真实实现（asar 解包读到的，非印象）
- `ModelsSettingsPanel`（CSS 16KB/JS 51KB）：模型 = **带能力声明的配置对象**
  （`capability.tools/images/reasoning/onlyReasoning/canDisableThinking/customProtocol`
  + `efforts.low|medium|high|xhigh|max` + `defaultEffortAuto` + token 上下限 + `testConnection`
  + 本地模型表 `name/description/status/engine/fileSize/computeUnits` + 企业策略 `MEMBER_CUSTOM_MODEL_POLICY_DENIED`）
- `CreditsUsageEmbedPanel`：完整用量在**账号/订阅页**（iframe `/profile/credits-usage?embed=1`）
- `credits-insufficient-bar`：对话内**只在不足时**出现，两档 `billing.credit_low_5`/`credit_low_0`，
  动作 `go_upgrade`/买积分/`dismiss_forever`/`retry`/邀请
  ⇒ 🔴 **教益：不在每轮都显示余额数字**，否则用户每次说话先看余额，对话被打断。
- ⚠️ `reasoning_effort` 在 Hermes 仍**不生效**（旧注释 `copilot_proxy.py:75-76`），要做思考强度必须先复测。

### 积分口径建议
`积分 = (输入 tokens×1 + 输出 tokens×3 + 缓存命中 tokens×0.1) / 1000`
输出贵 3 倍（对齐真实计费方向）、缓存折价 10%（让省下来的看得见）、/1000（量级落在百~千，老板能读）。
free 2000 积分 ≈ 200 万 tokens，与现有 `QUOTA_TIERS["free"]=200_000 字符` 做一次等比换算衔接。

## v692 第 1 期落地：副驾真实 token 计量（用户选 A）

方案文档《大模型对话三点改进方案-2026-10-26.md》的第 1 期，**只做计量、不动界面**。
后端 commit（hergent-erp 仓）8 文件 +1240/−11。

### 🔴 实测确定的三条上游口径（这是本轮全部设计的地基）
1. **一次用户请求只发一个 `usage` 块，且是「整个 agent 循环的累计值」**
   - 单问「说两个字」→ `prompt_tokens = 20,867`
   - 多轮工具（内部 8 次 API 调）→ `prompt_tokens = 185,281`
   - 与 Hermes 账本交叉验证**分毫不差**：`sessions.input_tokens(5,057)` +
     `session_model_usage.cache_read_tokens(180,224)` = `185,281`
   ⇒ **一次请求落一行，绝不按 chunk 累加**（累加会翻 N 倍，这是最容易写错的）
2. **`prompt_tokens` = 未缓存 + 缓存命中**（`134 + 20,734 = 20,868` 对得上）
   ⇒ 作为**用量**准确；但**不能乘全价算成本** —— 那次实际 `$0.00008`，
   按全价估会**高估约 40 倍**
3. usage 里**没有** `cached_tokens` 字段（不像 OpenAI 有 `prompt_tokens_details`）
   ⇒ 缓存命中只能从 Hermes 账本取，而那张表 `api_server` 会话 `user_id` 全 NULL
   ⇒ **不能做用户归因**，只能做租户级总量

另：SSE 里回显的 `model` 是 `hermes-agent`，**不是真实模型**
（账本显示内部会在 `deepseek-flash` / `deepseek-v4-flash` 之间自己切）。

### 实现（`routers/copilot_proxy.py` + `routers/ai_assist.py` + `erp_db.py`）
- payload 加 `"stream_options": {"include_usage": True}` —— 不加就永远采不到数
- `_UsageTap`：旁路只读，**先 feed 再 yield**（反过来的话客户端提前断开就记不上这次真花掉的钱）
  - 按 `\n\n` 切块 + **保留残余** —— `read1(8192)` 必然把 SSE 行从中间切断，
    直接对 chunk 找 `usage` 会**永久采不到**（最贵的一类静默 bug）
  - 多个 usage 块**覆盖不累加**；权威性判据 `object == chat.completion.chunk`
    （防未来 Responses 事件带单轮 usage 把累计值改小）
- `ai_usage_v2` 表（prompt/completion/total/tenant/user/model/source/created_at + 复合索引）
  - **必须登记 `erp_db._TENANT_TABLE_SYNC_SKIP`**，否则启动对账会建到 7 个租户库 = 泄漏
    （实测 4 个租户库均为 0 张，白名单生效）
- `_quota_for` 加读数：`counted_by` / `used_tokens_this_month` / `metered_calls` 等，旧字段一个不少
- 顺手修：`_quota_for` 裸查 `ai_usage`（该表只在 `POST /api/ai/usage` 里 CREATE）
  ⇒ 新装/表被删时 `GET /api/ai/quota` 直接 500 ⇒ 改容错按 0 + 告警

### 🔴 第 1 期的纪律：只加读数，不切拦截
`exceeded` **仍按字符判**。token 阈值是**业务定价问题** —— 老板要先看到
「一月真实用多少、折多少钱」才能定档。现在贸然切，tenant 1（本月实测 897 万 tokens）
**月中就 429**，等于把护栏变成事故。第 2 期切法：`used_tokens > QUOTA_TIERS_TOKENS[tier]` +
tenant 1 豁免。

### 🔴🔴 部署时差点造成事故（已记进 `topics/deploy-ops.md`）
`scp` 整文件覆盖 `erp_db.py` 后，文件从 **1,375,053 字节变成 1,366,850（少 8,203）**，而我
只加了 400 字节。查出来：**线上 23,046 行，git HEAD 只有 22,956 行 ⇒ 生产比仓库多 90 行热修**。
立即从 `.bak.v692` 恢复（md5 一致），改为在线上版本上**精确插入一行**（锚点唯一性校验 + 幂等）。
另外两个文件验过 `git show HEAD:path | md5` == 线上备份 md5，逐字相同，安全。

⇒ 纪律：**推后端单文件前必须比 md5**，行数相同也不算数；不一致就只打补丁不整覆盖。
