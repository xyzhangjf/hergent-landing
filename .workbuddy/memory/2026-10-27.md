## v698：修「采购单审核后 付款/预付款/入库 三个入口全不显示」（P0 事故）

老板早上反馈 v697 上线后线上看不到任何入口。根因是**状态值凭印象写**：

- 生产 `purchase_orders` 状态分布实测：`received=79, confirmed=2, draft=2, cancelled=1`
  —— **`approved` 一张都没有**。真实的「已审待执行」是 **`confirmed`**（v417「保存并审核」定的）。
- v697 判定写成 `_st_v == "approved"` ⇒ 2 张已审单永远拿不到 `prepay`。
- `received_amount` 是 **v403 才加的列**，79 张舟谱导入单（导入时直接标 `received`、没走 confirm）
  这一列全是 0 ⇒ 「已到货」判据不成立 ⇒ 付款按钮也不显示。
- **后端自身状态机断裂（最致命）**：`purchase_order_confirm` 守卫原本是
  `status IN ('draft','approved')`，**不收 `confirmed`** ⇒ 审核通过的单根本入不了库。
  前端 `canConfirm` 与后端逐字对齐 ⇒ 按钮同样不显示。

修法（`tools/hergent/patch_v697c_confirmed_state.py`，8 锚点全命中）：
1. 两处入库守卫补 `confirmed`（`approved` 保留兼容）
2. `pay_mode` 认 `("approved","confirmed")`
3. 新增 `_po_received_amount(o)`：**到货金额的唯一读法**。`received_amount<=0` 且
   `status='received'` ⇒ 真值 = 订单金额。**只对 `received` 兜底，`partial` 不猜**
   （分批到货金额未知，猜就是造数）。`_po_unpaid` / `_po_overpaid` / pay_mode / 接口返回全部改走它。
4. 前端 `canConfirm`/`canReceive`/`inbActionTitle`/`approvalProgressText` 加 `confirmed`。

验证（`tools/hergent/test_v697c_state.py`，**只读**生产真实数据）：28 项全过。
线上真实页面（`tests/perf/v698/real-prod.mjs`，**不 mock**，用老板真实会话）：6 项全过。
部署：v698，三处 md5 双侧一致，线上 `data-build=v698`。

## 🔴 部署踩坑：rsync 不能加 `--no-delete`

我写了 `rsync -av --no-delete` 传 assets —— 该参数不存在，rsync 报用法错误**没传任何文件**，
但后面的 `scp index.html` 照样执行 ⇒ 线上 index.html 已指向**不存在的 chunk**，差点白屏。
发现后立刻用 `rsync -av`（不加任何 delete 参数，默认就不删）重传修复。
**纪律：rsync 与 scp 串在 `&&` 后面时，前者失败不会阻止后者 ⇒ 传完必须立刻 ls 校验新 chunk 存在。**

## 线上真实登录探针的做法（可复用）

前端登录态是**两个 cookie 缺一不可**：
- `erp_token` = 真凭证（httpOnly，后端 Set-Cookie 下发）
- `hergent_auth` = `'1'` 标记 cookie（非 httpOnly，路由守卫 `auth.hasSession` 读它）

只注 `erp_token` ⇒ 守卫恒 false ⇒ 跳回登录页，**看起来像"部署没生效"**，极易误判。
playwright `addCookies` 用 `url` 时**不能同时给 path**（会报 "Cookie should have either url or path"）。
探测脚本必须放在项目目录内（`/tmp` 下 import 不到 playwright）。

## v700：副驾头像「又回退成 🚀」= 租户中间件把 <img> 拦成 403

老板报「副驾的角色头像怎么又回退到火箭图标」。**数据与文件全是好的**，坏的是访问链路。

先纠正一个容易查错的事实：头像**不在** `/opt/hergent-erp/static/role-avatars/`。
`ai_roles.py::_AVATAR_ROOT` 用 `dirname(dirname(abspath(__file__)))` 解析 ⇒ 落在
**`/opt/hergent-data/role-avatars/<tenant>/<role>.png`**（故意放部署目录之外，
避免后端 deploy 的 rsync --delete 误删）。现有 tenant 1 的 5 张：copilot 96928B /
accountant 89033 / cs 95862 / secretary 98690 / ops 97395（一角色一图，256x256）。

根因（四条 curl 实测）：
```
无 cookie                        → 200 image/png 96928B
有效 token（能推导出租户）        → 200
有效 token + hergent_tenant=无权租户 → 403 TENANT_FORBIDDEN
过期/无效 token                  → 403 TENANT_REQUIRED   ← 老板最可能是这条（session 已过期）
```
`tenant_middleware` 对 `/api/ai` 前缀一律 fail-closed 要求租户上下文，而
**`<img src>` 是浏览器自发请求，带不了 `X-Tenant-Id` 自定义头**，只能靠
`hergent_tenant` cookie 或 token 推导。业务接口自己带头（client.js）所以全正常
⇒ **「只有头像坏、别的都好」就是这个形状**。端点 `ai_role_avatar_get` 本身设计是对的
（拿不到租户就走 `find_role_avatar_fallback`），但它根本没机会被执行。

修法（patch_v700_avatar_tenant.py，1 锚点，幂等 + 备份 + 编译校验 + 自动回滚）：
在 G2 强制判定**之前**插头像专用分支 —— GET 且路径匹配 `/api/ai/roles/*/avatar` 时，
能解析到租户就照常用（**租户隔离不放松**），解析不到或无权则 `set_tenant_context(None)`
放行，交给端点走 fallback；非法 tenant id 仍返回 400（校验不吞）。

验证：五条路径（A/B/C/D 全 200、E 非法 id 仍 400，五张头像体积各不相同）；
`tests/perf/avatar/v700-regress.mjs` 线上真实会话 14 项全过，其中 case2 **故意塞
无权 cookie**（修复前必 403 的场景）现在也是 256×256 真图。视觉：顶栏 /
「将由X回答」/ 输入框左侧三处同一张 3D 人像，无 🚀。

🔴 判据（可复用）：**业务接口一切正常、只有图片/附件裂** ⇒ 先怀疑「不能携带自定义头的
请求」被中间件拦了（`<img>` / `<link>` / 下载 / `window.open`）。这类请求只能吃 cookie，
任何「必须带 X-Tenant-Id」的 fail-closed 设计都会在这里出现静默降级。

## v702：目标配置「作用对象」统一为供应商（可搜索 / 筛选 / 多选 / 回显）

老板要求：新建/编辑目标的作用对象只能是**供应商**，支持搜索筛选多选，提示当前所选与生效规则，
编辑正确回显，**不能出现非供应商维度的选项**。三条口径他拍板：
**多选=各自独立一条 / 保留品牌+商品两个入口只换候选 / 存量原样保留+提示改选**。

改造前实测（`tenant_1.db`）：`rebate_target_rules` 仅 **4 条、全 brand**，作用对象是品牌名
（简爱/蒙牛低温/蒙牛鲜奶/空）；品牌档案只有 **4 条**，而 `contacts type='supplier'` 有 **38 条**
（福宝、恒滋、蒙牛鲜奶（7579）各是独立户头）。所以目标根本挂不到真实户头上。

做法：`dimension` 不动（仍是 brand/product，决定表单形态），只把作用对象候选换成供应商，
**后端一行未改**。新建多选 ⇒ 保存时**扇出**成 N 条独立规则（名称加「· 供应商名」后缀）；
编辑恒单选（一条变多条没有界面能表达）。

🔴 四条被实测打出来的口径，别改猜：
1. **`scope_key` 必须存供应商名称，不能存 id**。后端 `routers/rebate_rules.py:1125` 对
   `dimension=='brand'` **强制** `scope_key = scope_name`（传 id 会被覆盖）；更根本的是返利计算按
   `(月份, 维度, scope_key)` 配对规则与**达成**，而 `rebate_achievements.scope_key` 是 Excel 导入的
   名称原文 ⇒ 规则侧用 id 两边**永远配不上**，返利一笔都算不出来。代价：供应商改名旧目标失联。
2. **候选异步晚到会让回显永久落空**。`init()` 在弹窗打开瞬间跑完，而供应商列表由父页异步加载；
   深链 `?edit_rule=N` 时拿空候选去匹配 ⇒「简爱」这种能对上的被**永久**判成未绑定（init 只跑一次）。
   修法 = 监听 `supplierOptions.length`，只在「还没选过 且 正处于未绑定」时补一次匹配，
   **绝不覆盖用户已改的选择**。探针第一次 3 项红全是这一个根因。
3. **`DELETE /api/rebate-rules/{id}` 默认是软删除**（`is_active=0`，行仍在）。测试清理必须
   `?hard=1`，否则"删了还查得到"，而且"没建成就没什么可删"会让清理断言**空转成 PASS** ——
   判据要写「建成 N 条 且 删后残留 0」。
4. **探针做写操作要 CSRF 双提交**：后端校验 `cookie(csrf_token) == header(X-CSRF-Token)`
   （`server.py:323`）。只注 `erp_token` 会 403 `CSRF_REQUIRED`，看起来像"功能坏了"，
   实际是探针缺 cookie。`__Host-csrf` 在浏览器侧要求 Secure 且无 Domain，playwright 注入易被拒 ⇒ 用 `csrf_token`。

两个前端坑（都差点白屏/被裁）：
- **`watch(getter)` 会立即 `effect.run()` 求值**，写在 `const selectedSups` 之前就是 TDZ，
  症状是**整页白屏、控制台无显眼报错**。两个 watch 全部下移到定义之后。
- **弹窗 body 是 `.ui-modal-body`（`overflow-y:auto`）⇒ absolute 浮层会被裁剪**，
  表现「点了没反应/只露半行」。供应商选择器改用**内嵌展开面板**（占布局高度、随 body 滚动）。

还有一个诚实性修正：搜索框本来写了"拼音首字母"，但生产 **pinyin/pinyin_first 实测 0/38 有值** ⇒
那是做不到的承诺（敲 ja 只会看到"没有匹配"）。文案改成「名称 / 编码」，字段照读（补了自动生效），
探针加一条反向断言防止以后被写回去。

验证：`tests/perf/v702/supplier-scope.mjs` **38/38**（不 mock，老板真实会话），
`tests/perf/v702/fanout.mjs` **9/9**（真写库：选 2 个 → 2 条 120000、名称带后缀、key==名称、
硬删后残留 0）。生产事后快照自证：规则总数回到 4、scope_name 原值未变、探针会话残留 0、月锁残留 0。
文档 `docs/目标配置-作用对象统一为供应商-设计-2026-10-27.md`。线上 `data-build=v702`，三处 md5 双侧一致。

## v703（2026-10-27 16:30）一键复制报单数据

**用户口径（原话，逐字记住）**：「只复制数字，列从『周运潘』开始、『备货』结束，行从商品第一行到最后一行，
如果按品牌筛选，行从筛选后的第一行到最后一行。」⇒ 复制的是**报单对象列段**（`cross.units` 全段），
不是整张表：无表头、无商品名、无汇总列。生产实测 units 首列就是「周运潘」、末列就是「备货」，共 19 列
（`all_units` 的 ORDER BY 是 `MIN(s.id)` = 第一次报单的先后）。**这句话本身就是真值校验器**，先查再动手。

**根因：屏幕 / 导出 / 打印三套口径。** 旧 `gridHeaders`/`gridRowCells` 与屏幕差 ——
① 缺 4 个汇总列（合计(小单位)/合计(箱)/加单/最终下单/单价 只有金额和建议）；
② 客户空格写 **0**，屏幕是**空白**（`qtyByUnit` 只为有报单的店建键）；
③ 行序走 `cross.rows` 原始序；另有 `filteredRowsForExport()` **自己重写一遍筛选**（漏品牌与到货周期）。
⇒ 立 `cellRaw/screenRowItems/screenColumns/screenHeaders/screenRowCells` 为**唯一**取数实现
（列=colOrderList、行=flatItems），复制/导出 xlsx/打印全部改走它，三套旧函数**删掉不留空壳**。

**两条取值纪律**（以后任何"进表格文件"的取值都照这个）：
- `cellText()` 是给人读的（千分位、`—`、`/箱`、缺规格）——只服务 tooltip/aria；
- `cellRaw()` 是进文件的（纯数值/空串）。把它俩混用 → TSV 里出现 `¥1,234.00 /箱`，粘进 Excel 是文本，无法求和。
- 无报单 = **空串**，不是 0：写 0 会让主管的均值/计数全错，且"没报"与"报了 0"混为一谈。

**入口**：并入「导出」下拉（`复制整表数据（粘贴 Excel）`），**不新增工具栏按钮**（该行宽度只够一行，
1536 视口曾折过行）。与行首「复制报单」（厂家编码/下单数量）**不是一回事**，文案必须能区分。

**验证（两支探针，线上真实登录+真读剪贴板）**：
- `tests/perf/v703/copy.mjs` 23/23 —— 期次 38 那期生产**报单数 0**，验的是空表结构（294 行×19 列、
  无中文/无 ¥ 千分位、空格保留、行数=屏幕最后序号、搜索后 21 行跟随）。
  🔴 全空**不代表功能坏**：先查 `SELECT COUNT(*) FROM forecast_submissions WHERE period_id=38` = 0 才敢下结论。
- `tests/perf/v703/copy-real-data.mjs` 24/24 —— 期次 37（22 单/29 明细/570 件），
  **剪贴板 / 导出 xlsx / 数据库 SQL 三方逐格等价**（3 个有报单行 ×19 列向量完全一致），
  导出表头 31 列与屏幕逐列同名同序，勾「仅显示有报单」后只复制 3 行，分组后仍 294 行。
- 期望值由 SSH 只读 SQL 生成到 `/tmp`（**不落 outputs/**，客户名/销量是红线），测完删。

**踩到的探针坑（都会伪装成功能 bug）**：
1. 屏幕第一列表头渲染的是**齿轮按钮**（`innerText` 空）⇒ `filter(Boolean)` 会把这一列整根滤掉，
   之后所有列索引左移一位，于是冒出「导出 31 列 vs 屏幕 30 列」的**假 FAIL**。
2. 「分组方式」在**列设置弹层**里，弹层没打开时 `select[aria-label="分组方式"]` 根本没挂载 ⇒ 直接等到超时。
   且勾/取消「仅显示有报单」会触发表体重建，齿轮是**新节点** ⇒ 点击要重试，判据用「弹层真的出现」。
