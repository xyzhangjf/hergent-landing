## S3-4 浏览器点测暴露 eval-order ReferenceError（系统性已修）
- **用户报 staging 报错**：`Uncaught ReferenceError: render_alerts is not defined`（在 main bundle 顶部执行期）。根因：原多 script 下 `alerting.js` 顶部 `window.ModuleRegistry && ModuleRegistry.register(..., render_alerts, ...)` 靠 `&&` 短路掩盖（ModuleRegistry 当时未加载）；打包成单 ESM 后 `window.ModuleRegistry` 在模块顶层执行时已存在，短路失效 → 裸 `render_alerts` 在 `window.render_alerts` 赋值前被求值 → 严格模式 ReferenceError。
- **这是一类 bug（共 26+ 处）**：所有 `ModuleRegistry.register(..., render_x, ...)` 若 `window.render_x` 在本文件后面才赋值，新打包后都会在顶层执行期抛 ReferenceError 并中断该模块初始化。脚本扫描确认：consignment/tax-manager/dunning/payment-run/gl-dimensions/subcontracting/bpm-designer/assembly/bank-api/barcode-ops/batch-print/document-archive/feature-flags/insurance-stats/invoice-scan/merge-orders/payment-import/print-templates/salary-send/smart-import/stock-lock/tax-filing/voucher-templates + dev-dashboard/tenant-admin(renderPage) + ai-assistant(today/datasources/ai-timeline/forecast/trade-fair) 等。
- **系统性修法（不动各模块逻辑）**：
  1. `js/core/module-registry.js` 的 `register()` 改为**存储 renderFn 原值（函数或字符串名）、注册时不再解析**；在 `_doInstall` 的 navTo 包装里**点击时懒解析** `typeof fn==='string' ? window[fn] : fn`。这样 render 函数何时挂 window 都不再影响。
  2. 批量把 31 处 register 第4参数 裸 `render_x`/`window.render_x` → **字符串名** `"render_x"`（字符串字面量在调用点求值不会抛 ReferenceError，且点击时懒解析正确拿到函数）。脚本化改写（re1 裸标识符、re2 window. 形式），幂等；注释里的 `renderFn` 误改已还原。
  3. `alerting.js` 还把 register 调用移到 `window.render_alerts` 赋值之后（双保险）。
- **附带修复**：`public/manifest.json` 图标 `/static/icon.png`(绝对)→`icon.png`(相对，staging 下解析为 /staging/icon.png，消除 404 + manifest 图标报错)；`index.html` 补 `<meta name="mobile-web-app-capable">`（消 apple- 弃用警告）。
