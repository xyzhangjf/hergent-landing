## 二、实现期抓出的两个**真缺陷**（都是静默失效，非探针写错）

### ① 键对账在「两侧都没有共同单号」时返回一份**看起来「完全一致」的空报告**
- 机制：`recon_engine.reconcile_by_key` 的 `_index()` 把 **key 为空的行静默丢弃**（既有特性）。两侧单号列全空 / 两侧编号体系完全不同 ⇒ 两个索引都是空的 ⇒ 返回 `only_in_a=0 / only_in_b=0 / mismatch_count=0`。
- 🔴 **这比「几乎全不匹配」更危险**：后者用户一眼看得见异常，前者会让人直接下结论「账是对的」。原探针把这条断言写成「全不匹配」，**方向写反了**（是探针错，不是代码对——探针错的方向恰好掩盖了真缺陷）。
- 修法（只增键，不删不改）：返回值加 `rows_a_total/rows_b_total/skipped_no_key_a|b/keys_a/keys_b/common_keys/vacuous/warning`；`vacuous=True` 时 `warning` 明说「0 差异不代表一致」，并区分三种成因（两侧空表 / 单号列全空 / 无共同取值）。
- 三态纪律：**「0 差异」有两种成因必须分开** —— 真的逐笔一致 vs 什么都没比出来。

### ② 配置改了但网关没重启 ⇒ 新能力**永不生效**（零报错）
- 机制：Hermes 工具索引是**进程内缓存**。`ensure_mcp_servers` 只写 config.yaml；`ensure_running` 原先见到进程在就直接 `return` ⇒ `needs_restart=True` 被丢掉，只剩一条日志。用户现象：「我明明配了，手机上还是用不出来」。
- 修法：新增 `mcp_config_drift()`（判据 = **进程启动时刻 vs config.yaml mtime**，两者都客观可得）＋ `_proc_start_ts()`（`/proc/<pid>/stat` 第 22 字段 + `/proc/uptime` 换算墙钟）。
  - 接进 `ensure_running`（scheduler **每 60 秒**跑）⇒ **自愈**，不等用户发现。
  - 加 `_MCP_DRIFT_COOLDOWN=600s` 冷却闸门：防「网关自己回写 config ⇒ mtime 恒新 ⇒ 重启风暴」。
  - 状态面 `gateway_status` 加 `mcp_pending` / `mcp_pending_reason` ⇒ 前端用**既有**「重新检测全部」清除。
  - `judged` 三态：判不了（如 macOS 无 `/proc`）时 **judged=False**，既不臆断成待重启（会成风暴），也不假装成「已生效」（静默洞）。

## 五、本机 / 服务器新坑（本轮实测踩到，值得记住）

1. 🔴 **`systemd-run` 复刻服务沙箱时，`PrivateTmp=true` 会让 `/tmp` 里的探针脚本消失** ⇒ 报 `can't open file '/tmp/…': No such file or directory`（看着像路径写错）。
   解法：探针脚本放 `/opt/…` 下，或复刻时**去掉 `PrivateTmp`**（读 `/opt` 与本属性无关）。
2. 🔴 **`hermes send` 是「一次性子进程」⇒ 它的输出不进网关日志** ⇒ 想拿回执必须在**同一进程**里抓 stdout。
   正解：`hermes send --to wecom --json` 直接返回 `message_id` / `chat_id` / `mirrored`。
   ⇒ 判据升级：**「网关日志没记录」不等于「没发出去」**。
3. 🔴 **租户凭据可读性有三个条件，缺一即静默回落全局 webhook**：`hergent` 须在 `hergent_tN` **组**里 ＋ 目录 **setgid** ＋ 服务 `UMask=0007`。
   9/27 19:05–19:11 曾出现 `[ai_channels] 健康检查异常 … Operation not permitted: …/hergent_t1/.env`（3 条），加 `20-l1-umask.conf` 后**再未出现**。
   ⇒ 排查「推送静默不发」时，这条**必须先查**：`id hergent` 看组、再看服务内 `enabled_channels(tid)`。
4. 沙箱与 `ProtectSystem=full` **不阻挡读 `/opt`**（`/opt` 只读但可读）—— 所以租户 home 在 `/opt/hermes-tenants` 下不受 `ProtectHome=true` 影响。
