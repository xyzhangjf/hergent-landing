## 货损核算：「仪表盘 / 数据填报」拆成两个主 Tab（v185）

用户一行：「**请参照目标与返利模块，把仪表盘和数据填报页面分开**」。

**「仪表盘」/「数据填报」**，默认落 `dashboard`（老板每天先看数，录数是手段）。

### 决策与理由（逐条）

1. 🔴 **`.main-tabs` 必须上提全局** —— 原在 `Rebate.vue` 的 `<style scoped>` 里 5 条规则。
   两页各写一份 = 逐轮视觉漂移（铁律「第二份拷贝＝静默漂移」）⇒ 上提 `styles/variables.css`，
   `Rebate.vue` 删本地那份留注释。**本页末尾 `@media print` 里隐藏 `.main-tabs` 刻意保留**（只作用本页）。
2. **两 tab 语义分工**：`dashboard` = 只看数（区间筛选 / 月一览 / 趋势图，全只读）；
   `fill` = 录数与结账（工具条 / 编辑条 / 公司卡 / 主表，**唯一能写的地方**）。
3. **两 tab 共享「当前期次」这一个 ref** —— 不存在"两个 tab 各有一个月份"的错配（对齐返利页月份双向同步）。
   ⚠️ **切 tab 不重新取数**：两 tab 读的是**同一份** `trend` + `bootstrap`，刷新点仍是那 6 个写路径；
   再拉一次只会造出"同一份数据两条刷新路径"。（返利页按需拉取，是因为它两 tab 数据集**不同**。）
4. 🔴 **点柱子 vs 去填报的语义分离**：图上点柱 = 切期次 + **留在仪表盘**（要能连续比各月）；
   月列表「去填报」= 切该月 + **跳填报 tab**（那才是能改数的地方）。操作列文案 `查看` → `去填报`。
5. 🔴 **分 tab 后的诚实性缺口**（本轮最实质的一处）：仪表盘只看**已保存**的数据，草稿在那一屏**不可见**
   ⇒ ① 仪表盘顶部 `v-if="dirtyCount"` 的 `.la-tabnote`：「当前有 N 格录入改动尚未保存 —— 本页读的是
   已保存的数据，切到「数据填报」保存后才会更新」；② **`blockIfDirty(what)`：从仪表盘发起的换期次必须拒绝**
   （点一下柱子就无声丢掉半天录入，是最难自查的一类数据损失），并把人送回填报页。
6. **删掉的补丁**：原「趋势图与月列表已在录入态收起（点完成录入回来）」那句话 + `v-if="!editMode"` 整段收起。
   分 tab 后这层补丁不再需要（正因为用户一进录入态就以为图没了，才需要那句话解释）。
7. **`v-if` 而不是 `display:none`**：两个 tab 的内容真正互斥（对方 DOM 不存在）⇒ 断言据此判定「已移除」。
8. 🔴 **模板重排的 diff 纪律**：公司卡 / 主表两块**保持原缩进**未重排 —— 175 行纯空白 churn 会让
   「本轮改动 vs 在途改动」在 hunk 粒度上更难分辨（本项目按 hunk 归属提交）。
9. `const mainTab = ref('dashboard')` **必须声明在最前**（`switchTab`/`goFill` 虽无 TDZ 风险，
   但后续若有顶层求值引用它，定义靠后会直接抛 `Cannot access before initialization`；返利页 v123 踩过）。

## 18:0x–18:2x 预报「合计(箱) = 合计(小单位) ÷ 规格」（v189）

**用户原话**（一句）：**合计（箱）=合计（小单位）/规格**。这句接的是上一轮登记的遗留项
（`总箱 ${editTotalQty}` 两处推送文案，值实为**小单位**、标签写「箱」，当时留了「等用户一句话」）。

### 一、规则定性：**逐行除再相加**，不是「先合计再除」

生产在售档案 288 个商品里 **192 个规格是描述串**（`250g*24瓶` / `90g*8杯*12组` /
`210g*10瓶*6提手提装`）、**30 个为空** ⇒ 规格异构时「Σ小单位 ÷ 某个规格」**没有定义**
（本地断言实测：同一批 80 个小单位，除三个不同规格得到 0/13/3 三个互不相同的「箱数」，
且都不是正确的 5）。成立的唯一定义是 **Σ round(行小单位 ÷ 行规格)** —— `rowBoxes` 本来就是
这个形态，**用户不是要改链路，是要让箱子算对**。

### 二、真正故障：`parseFloat(spec)` 取到的是**净含量**不是每箱数

四处都写 `parseFloat(r.spec)`：`rowBoxes` / `pricePerCase` / `commitCell` / `loadCross` 行构造。
`parseFloat('200g*12')` = **200（克）**、`parseFloat('1500ML*6桶')` = **1500**
⇒ 箱数被缩小 250 倍。生产只读实测（期次 9）：规格 `200g*12` 的 24 件 → **0 箱**（正确 2）。
波及的不只箱数：`pricePerCase = 厂价 × parseFloat(spec)` ⇒ `1500ML*6桶` 的单价被放大 250 倍，
**下单金额整列错**。

新增 `perCase(spec, unit)` 唯一实现（`Forecast.vue`，紧邻 `rowBoxes`）：
1. 取规格串**最后一个**数字 = 每箱小单位数（`250g*24瓶`→24、`100g*8杯*12组`→12、`1500ML*6桶`→6）；
2. 报单单位比末位更细时**按层级相乘**（`100g*8杯*12组` 且 `unit=杯` → 8×12=**96**；
   `110g*3杯12组` 且 `unit=杯` → 3×12=36 —— 生产里真有这种不一致）；
3. 纯数字规格（`12`）即其本身；4. 不含数字 → **0**（缺规格不换算，界面走「缺规格」分支，不静默当 1）。

生产 449 个档案逐一盘查：**88** 个无数字规格（与旧实现同为零，非本轮引入）、**89** 个新旧一致、
