## 6. 保存报"存在44个单元格录入不合法"——单位列过度枚举校验
- 现象：保存编辑网格提示"存在 44 个单元格录入不合法，请先修正再保存"，表上红的都是"单位"列。
- 根因：`MASTER_COL_DEFS` 里只有 `unit` 列带 `options: ['件','箱','提','杯','袋','瓶','盒','托','板','根']`（1845）；`cellErrMsg`(3259) 对"带 options 的文本列"强制要求值必须落在枚举内，否则返回"应为：…之一"。但真实低温奶/快消单位多样（支/包/个/升/组…），远不止这 10 个 → 大量商品单位被误判红。空值不报错（`raw !== ''` 守卫），所以红的是"有值但不在枚举"。
- 修复：`cellErrMsg` 的枚举校验加 `&& col.enforceOptions` 守卫——默认不强制，options 仅保留作 datalist 下拉候选提示（655 行渲染不变，用户仍可下拉选常用单位、也可自由填其它）。如未来某列确需强制枚举，设 `enforceOptions:true` 即可。
- 部署：npm build（新 chunk Forecast-DOr5bUhV.js）+ rsync dist/ → /opt/hergent-cn-v2/ + chown；已确认旧分块删除、后端 health 200。
- 验证链：`saveEdits`(2150) 遍历 `cellInvalid`(=cellErrMsg!=='') 统计 bad；单位列修复后返回 '' → 红框与报错消失。用户硬刷新重测保存即可。
- 原则：输入候选（datalist）≠ 强制约束；业务自由文本字段（如单位）不应写死枚举做硬校验。

## 16. 修复"切换期次后商品清单不立即刷新"（onPeriodChange 与 gotoPeriod 入口不一致）
- 现象：在「预报订货管理」里从一个期次跳到另一个期次，商品列表（交叉表/编辑网格）不立即刷新，需手动点"刷新"才显示。
- 根因：`editMode` 默认 `true`（Forecast.vue:1520），用户默认落在**编辑网格**。两个期次切换入口行为不一致：
  - 下拉框 `@change="onPeriodChange"`（:18）只调 `loadCross()`，在编辑模式下**不调 `loadEditGrid()`** → 编辑网格不重载（cross.value 被写成只读子集，全量目录丢失/陈旧）。
  - 期次按钮 `gotoPeriod`（:4094）则正确 `if (editMode.value) loadEditGrid(); else loadCross()`。
- 证明（puppeteer 真机，dev 拦截 mock 2 期次各 100 行）：编辑模式下下拉切期次，修复前 `cross.value.rows[0].name="B-商品1"`（loadCross 只读子集），修复后 `="FULL-11"`（loadEditGrid 全量目录）→ 编辑网格已正确重载。只读模式下下拉切换本就正常（loadCross 走通），修复不影响只读路径。
- 修复（Forecast.vue:4753 `onPeriodChange`）：改为 `if (viewMode.value === 'cross') { if (editMode.value) loadEditGrid(); else loadCross() }`，与 `gotoPeriod` 完全对称。
- 部署：移除排查期临时 `window.__fc` 调试全局（onMounted）→ `npm run build`（新 chunk `Forecast-C1ebHjS3.js`，492179B）→ rsync dist/ → /opt/hergent-cn-v2/ + chown。已验证生产落盘新 chunk。
- 教训：所有"切换实体(期次/客户/…)"的入口必须调用**同一套**重载函数，并按当前视图模式(edit/readonly)分派，绝不能让某个入口漏掉某一模式的重载。
