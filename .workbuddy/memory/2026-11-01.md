## 🔴🔴 v710：我的探针判了 PASS，用户肉眼说「没对齐」—— 因为量的对象错了

用户：「全选和清空没有对齐」。而 v709 探针量的是 **label 盒子 vs 清空盒子**：
`topDiff = 0` / `centerDiff = 0` / `headH = 22` ⇒ ALL PASS。
**盒子对齐 ≠ 文字对齐**。真凶是我自己写的一行 `line-height:1`：

| span 的 line-height | 文字渲染中心与「清空」的差 |
|---|---|
| `1`（=12px，v709 当时的值） | **偏高 0.5px** ← 用户看到的就是这个 |
| `14px` / `16px` / `18px` | 偏高 0.5px |
| `19.2px`（**不写**时的继承值） | **偏低 0.31px** |
| `normal` ← 修后 | **0.00px** |

机理：`line-height:1` 把行盒压到与字号同高，12px 字形的 ascent/descent **溢出盒顶盒底**，
字形整体上浮；而右侧「清空」是 `line-height:normal`。两者盒子都由 flex `align-items:center`
居中，所以盒子差 0、字形差 0.5px。

### 定式（判据修正，比这条 bug 本身重要）
- **判「两个控件对齐」必须量各自的文字渲染矩形**：
  `const r = document.createRange(); r.selectNodeContents(el); r.getBoundingClientRect()`
  —— 拿 `t` / `b` / `cy` 三项互比，全 0 才算对齐。
- **不要跟邻居比 `line-height` 数值，要跟它用同一个关键字**（这里双方都是 `normal`）。
  写数值必然要在字体度量上赌一次；`normal` 天然同源。
- 想让某段文字与邻居对齐，**`line-height` 不能空着**（会继承上层 19.2px），也不能写 1。
- 副作用：label 高 17 → 21（热区变大，hover 胶囊有呼吸感），头部 22 → 22.39 基本不变。

### 为什么 v709 会漏（复盘）
v709 的探针有 3 条「与清空对齐」的断言，全部量 `getBoundingClientRect()` 的盒子。
**判据选错了载体 ⇒ 越"严谨"地量错东西，越容易给出一个看起来有证据的假 PASS。**
新脚本 `v710-align-verify.mjs` 改成 Range 量文本，并在**全选态**（文字从「全选」变「取消全选」，
2 字 → 4 字）再量一次，防止字宽变化引入新偏移。

## v711：全站排查「图标与文字未垂直居中」—— 先建扫描器，再动手

### 🔴🔴 最重要的教训：**「全 0」在通过阳性对照之前不算结论**
首版扫描器跑 24 个页面，全部报 0，看起来"全站干净"。
但我做了阳性对照：注入 `.bp-selall span{line-height:1 !important}`（精确复现 v709 的 bug），
**扫描器依然报 0** —— 因为阈值写的是 `if (d <= 0.5) continue`，而实测差值正好 **0.500**，
被自己的过滤线吃掉了。改成 `d < 0.4` 后才抓出来。
⇒ 这是 v710 的**姊妹坑**：v710 是「量的对象错了」（盒子 vs 文字），
v711 是「判据边界吃掉了临界值」。**两者都会产出看起来有证据的假 PASS。**
定式：任何"没发现问题"的扫描器，**必须先注入一个已知缺陷验证它抓得到**。
阈值不要取实测值的常见落点（0.5px 是最常见的错位量级，别用 `<= 0.5`）。

### 真问题只有一类，根因统一
`.btn` 早已是 `inline-flex + align-items:center + gap:6px`；
但**自行定义的容器没跟上**，仍在 inline 上下文 ⇒ svg 走 `vertical-align:middle`
（对齐"基线 + x-height/2"），而中文汉字的视觉中心在 baseline 上约 0.38em，
比 x-height 中线更高 ⇒ **图标偏高 1.3~2px**。

| 位置 | 修前 | 修后 |
|---|---|---|
| 导出下拉 7 个菜单项 `.grp-btn` | Δ1.34px | **Δ0px** |
| 弹窗标题 `.panel-hd b`（全局，20+ 页面） | Δ2px | **Δ0px** |
| `.modal-hd b`（Rebate） | Δ2px | 同构（当前无数据未渲染） |

### 🔴 flex 容器里 `vertical-align` 无效 —— 这是定位的关键信号
一开始想全局改 `svg.ico` 的 `vertical-align`，于是做参数扫描（middle/-0.08em/-0.15em/calc…）。
结果侧栏 `.sb-item` 的 Δ0.391px **不随任何参数变化** —— 因为 `.sb-item` 本身就是 flex 容器，
svg 是 flex item，`vertical-align` 根本不参与计算。
⇒ **「改参数但测量值纹丝不动」= 该属性在这个上下文里没生效**，别继续调数值。
⇒ 也说明：inline 上下文才是需要处理的那一小撮，flex 场景本来就已经居中。

### 🔴 量测要跳过尺寸为 0 的隐藏实例
`document.querySelector('.panel-hd b')` 取到的是**h=0 的幽灵**（v-if 未渲染分支的残留节点），
svg 中心 0，与任何文字都差 >14px ⇒ 永远报「附近无文字」。
定式：`[...querySelectorAll(sel)].find(e => { const r = e.getBoundingClientRect(); return r.width > 2 && r.height > 2 })`。
同族：漫游/扫描的主循环里也必须有 `display:none / visibility:hidden / opacity≈0` 过滤。

### 漫游扫描的两个必备纪律
1. **元验证浮层真的打开了**：点击前后比较 DOM 节点数，没增加 ⇒ 判「未打开」，**不能算 PASS**。
   首轮我用 `[class*=modal]` 计数，36/131 才算"打开"，另 95 个被误判 —— 后来改用节点数。
2. **每个场景前必须 reload**：上一个浮层（导出菜单）会吃掉下一次点击（第一次点击被用来"点外部关闭"），
   表现是节点数不增反减。不 reload 就会得到「修改日志面板打不开」的假故障。

### 判定为「不是问题」的（如实记录，不硬改）
- 顶栏 `Δ0.41px`：button 未重置 `line-height`，继承 body 1.6 与邻居 normal 不同源，
  但 flex 居中后只剩亚像素渲染差，低于视觉阈值。
- `tb-bell` 角标 Δ8px：`.tb-bell-n` 是 `position:absolute;top:2px;right:2px`，设计意图。
- 375px 宽表横向滚动 / 图表画布溢出：设计如此。

## v715 企微副驾「三点动画两套上下跳」→ 改纯原生（运维/引擎补丁，非前端发版）

**现象**：企微聊天窗口等回复时两个三点动画一上一下跳，一灰一彩。

## v718 · 落地 P1（焦点 / 令牌 / 状态与空态），已上生产

**第二个教训 —— 探针自身会骗人，且是两次**：
- 侧栏项报 `solid 3px rgb(106,106,112)`，看着像没生效。真相是侧栏有 `transition:all`，**outline 被一起做动画**，Tab 后立刻读拿到的是「UA 默认 3px + currentColor」→「2px 品牌青」的中间态。改成等 260ms 再采样就全对了。

**P2-C 热区 —— 评审给的两条方案有一条根本不成立**：

- 另核：81 处 checkbox 里 **70 处本就包在 `<label class="check-item">` 里**，热区是整行（含文字）远大于 28×28 —— 评审只量了 input 本体。真正裸的只有 11 处。
- `.tab-ic` 伪元素 `inset:-5px -3px`：视觉 16px 不动、热区 22×26。不做 30×30（v677 条目高 26px 是硬约束）；**水平只敢扩 3px**（刷新/关闭相邻、gap 6px，扩 5px 交叠 4px ⇒ 点关闭误触刷新，反向更糟：误关整页）。

**本轮最贵的事故：Python 替换占位符长度不等 ⇒ 吞字符**。`page-hd`(7 字符) 换 `@@DONE@@`(8 字符)，每个处理位吃掉后一个字符 ⇒ 88 个文件变成 `class="page-hd>`，构建报 `Attribute name cannot contain U+0022`。修法不是打补丁，是 `git checkout -- src` 回滚后**按「先补令牌 → 一次重跑兜底删除+映射 → 再按块切片改 h2→h1」的正确顺序重做**（切片方案不回写占位符，从根上消除长度耦合）。**替换占位符的首字符集不能与被替换串首字符重叠，长度也最好相等；否则改用切片。**

**探针三连坑（同一轮踩全）**：
- 应用是 **hash 路由**，写 `https://hergent.cn/archive/products` 会被重定向到 `#/workbench` ⇒ 九页读到同一页，表现为「每页节点数完全相同」。URL 必须 `https://hergent.cn/#` + path。
