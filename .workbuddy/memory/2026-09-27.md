**用户现象**：员工档案「编辑员工」→ 重置密码，输入框提示「**至少 4 位**」，点保存却报「**密码至少需要8位**」。

- 前端 `hergent-cn-v2/src/pages/EmployeeArchive.vue`：`L150` 初始密码 `placeholder="至少 4 位"`、`L156` 按钮 `accForm2.password.length < 4`、`L184` `placeholder="新密码（至少 4 位）"`、`L185` 按钮 `accPwdEdit.length < 4`。**数字 4 是硬编码，v254 之后没人改它。**
- 后端 `server.py:1287`（`POST /api/users/{uid}/password`）走 `core._validate_password` ⇒ **v254 起为「≥8 位 且 同时含字母和数字」**（`core.py:68`）。
- 用户看到的「最少8位」= 后端 400 的 `detail`，经 `src/api/client.js:61` (`throw new Error(detail||…)`) → `resetAccPwd` 的 `catch { toast(e.message) }` 原样弹出。

**🔴 更深一层：`v254` 只修了一半 —— 真有一条口子能用 4 位建号**
全后端 10 个密码校验点，7 处调权威函数、**3 处裸写长度**：
| 位置 | 规则 |
|---|---|
| `routers/forecast_submissions.py:1185` `POST /api/staff-accounts`（**开通员工账号**） | `len(password) < 4` ← **唯一真能用 4 位**，比登录门槛还低 |
| `routers/auth.py:307`（注册） | `len < 8`（**漏了「含字母数字」**） |
| `routers/auth.py:511`（管理员重置） | `len < 8`（同上） |

**生产只读取证**（`/tmp/v289/pwd_policy_probe.py`，跑线上同一份代码）
- 线上产物 `assets/Archive-*.js` **10 个历史版本各含 2 处「至少 4 位」**（=`Archive` 页一直如此，非回归）；`assets/Login-*.js` 却是「密码至少需要 8 位」⇒ **同站两口径并存**。

- 同址还有：旧前端 `hergent-erp/static/index.html:263` + `static/dist/index.html:264` 也写「至少4位」（首登强制改密模态框），对应后端 `auth.py:226` 已是 8 位 ⇒ 同样不实。

## v292 角色权限「默认配置 + 用户自主调整 + 界面联动」（已上线）

老板原话：「为不同角色提供默认权限配置；允许用户自主为角色分配和调整权限；当权限发生变更时，该角色对应的 UI 元素（菜单/按钮/页面入口）应同步动态调整，只展示有权访问的内容。请设计并实现该机制，说明数据模型、权限校验逻辑及界面响应方式。」

### 侦察结论：要的 ① ② 早就有，缺的是 ③ 的「跨会话自动联动」
| 需求 | 现状 |
|---|---|
| ① 默认权限配置 | ✅ `core._DEFAULT_PERMS`（9 角色）+ 租户覆盖回落 |
| ② 用户自主分配 | ✅ `role_permissions(role_name, permissions)` 每租户一份 + 设置页矩阵 + 4 个端点 + `is_custom`/恢复默认 |
| ③ UI 同步联动 | ⚠️ **缺**：保存后只 toast「立即生效」却不刷新本地 `store.perms`（**假承诺**）；跨会话/跨设备**零联动**；客户配置与 `pages.js` 的 `roles` 白名单**判据打架** |

### 实现（v292）
- **后端**（`core.py` + `routers/auth.py`）：新增**只读派生** `perms_rev(tid)`（自定义权限表的内容指纹，sha1 前 12 位）与 `custom_roles(tid)`（本租户**真实改过**权限的角色名）；`/api/auth/permissions` **只加不改**两个键（小程序共用红线）；新增极轻端点 `GET /api/auth/perms-rev`。
- **前端判据**（`constants/pages.js`）：抽出唯一实现 `roleGateOpen(r, role, customRoles)`，`canSeePage` 与 `pageRoleAllowed` 共用；新增第三档「**用户配置优先**」——角色**不在** `roles` 名单里，但本租户**已为该角色真实改过权限**、且本行配有 `module`、且未被 `lock` 锁住 ⇒ **让位**，只判 module。新增 `lock` 字段（`/settings` `/roles` 产品硬锁）。
- **界面响应三层**：① 设置页保存后 `store.loadPerms(true)`（当场重排，**不要** `resetPerms()` 前置 ⇒ 会闪一屏全菜单）② 路由守卫**不 await** 地比对版本（20 秒节流）③ `Shell.vue` 60 秒轮询 + `visibilitychange`（切回标签页立即查）。
- 顺带修两个静默缺陷：`Settings.vue` **保存会把 `ops-workbench`/`perf`/`goals` 从库里抹掉**（`filter(known.has)` = 静默数据丢失）；`[...(v.permissions||[])]` 遇 dict 形态权限**直接抛** ⇒ 权限页整页加载失败。

### 🔴 三个关键判据（本轮最贵）
1. **`custom_roles` 必须按「内容 ≠ 内置默认」判，不能按「表里有行」** —— 设置页保存是**逐角色全量 POST**，点一次保存人人有行；按行判 ⇒ `roles` 轴对所有正常租户失效 = 悄悄拆掉 v291。实测：全量回写后 `custom_roles` 返回 `[]`；生产 tenant_1 只有 2 行（`supervisor`/`库管`），两个都真差异。
2. **「让位」必须要求本行配有 `module`**（安全阀）：`module: null` 的页面若让位就一个判据都不剩 = 全开。实测影响面**恰好 3 页**（`/bid-radar` `/cron` `/roles`），前两页后端只按模块裁决 ⇒ 让位是诚实的；`/roles` 与 `/settings` 已 `lock: true`。
3. **`customRoles` 的 fail 方向与 `perms` 相反**：`perms=null` ⇒ 放行（不藏菜单）；`customRoles=null` ⇒ **不让位**（退回内置门槛）。理由：前者代价是少几个入口，后者代价是每个角色凭空多出「定时任务/AI 团队」，看起来就像权限失效。

  1. `hergent-erp.service` 的 `10-sandbox.conf` `ProtectHome=true` 把 `/root` 挂成 **mode 700 空 tmpfs**；
     🔴 **systemd 挂载命名空间是进程级继承的 ⇒ `sudo`/`exec` 都不重置它** ⇒
     `_bridge()` 里 `sudo -u root`（HOME=/root ⇒ `~/.hermes`）**一样穿不过去**。

  2. **错解已实测证否**：`ProtectHome=true` ＋ `BindPaths=/root/.hermes` **无效**。

     `toast('任务已创建','success')` **谎报成功**，随后列表照旧空 ⇒ 用户以为是"创建成功没显示"。

### 🆕 顺手修掉渲染器一个通用排版坑（`.workbuddy/tools/md2pdf.js`）

**现象**：P6 那张两列表，第一列短标签被压成 ~3 字宽 ⇒「交付测量」渲染成「交付测 / 量」、
「定价校准」成「定价校 / 准」、「补齐入口一致性」成三行。**文本 grep 全绿，只有渲染成图才看得见。**

**成因**：`table { width:100% }` + Chrome 自动列宽；第二列是长段落时，第一列被压到最小内容宽。

**修法**（通用，已落进工具）：
```css
th:first-child, td:first-child { min-width: 6.6em; }
```
只设下限、不禁换行 ⇒ 长标签仍能折行，不会撑破页面；同时把 P6 标签统一压到 4 字
（试点 / 交付计时 / 定价校准 / 配方验证 / 数据入场 / 入口对齐 / 输出追溯 / 口径固化）。

**三列表格的中间窄列没有这条保护** ⇒ **对策是把窄列并掉**：
「来源 | 条数 | 是「AI」吗」→「来源 | 是「AI」吗」，条数写进第一列（`xxx —— **19 条**`）。

🔴 **教训**：`md2pdf` 的验收只做「页数 + 字数 + 填充率」是**不够的** —— 那三项全绿时这一条依然是坏的。
**必须把页渲染成 PNG 用眼睛看一遍。**
