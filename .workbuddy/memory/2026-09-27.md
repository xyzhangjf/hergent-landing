### 🔴 本轮学到的两条（都写进技能了）
1. **共享索引里有他人暂存内容时，绝不能用 `git add` 提交**（会夹带别人的改动）。

   `git add <仅我的文件>` → `git commit` ⇒ **完全不触碰共享索引** ✓
2. 🔴 **临时索引提交后，共享索引会残留「自己文件的旧版本」** —— 因为共享索引没被更新而 HEAD 前进了
   ⇒ `git diff --cached` 显示"撤销我的改动" ⇒ **下次别人 commit 会把我的改动回退成旧版**。
   **必须补一步复位**：`git reset HEAD -- <我的那批文件>`（不动工作区、不动他人暂存）。
   ⚠️ 这一步我差点漏掉，是靠"提交后回头验证共享索引"才抓到的。

## v288（08:40–09:00）员工「登录账号」可修改 —— 老板代改入口

### 病根：不是「没做」，是「只做了一半」
- 后端**早就有**改用户名的能力：`PUT /api/auth/profile`（`routers/auth.py:243`，自带长度校验 + 查重）。

  而员工档案弹窗的账号管理区有「重置密码 / 禁用账号 / 生成重置码」，**唯独没有改账号**。

### 🔴 差点误判成「写错库」的重缺陷（判据记下来，别下次重绕）
- 线索：`db/connection.py::_sqlite_connect` ⇒ `db_path = _tenant_db.get() or DB_PATH`
  ⇒ **有租户上下文就走租户库**；而 `users` 是**主库**表。

- **实测推翻**：`_TENANT_MASTER_PREFIXES` 含 **`/api/users`**、`_TENANT_PUBLIC_PREFIXES` 含 **`/api/auth`**
  ⇒ 这两族端点请求期间 `set_tenant_context(None)` ⇒ `db.get_db()` **就是主库** ⇒ 全部有效。
- 附带实测：主库 `erp.db` 的 users **8 行**（真实账号：admin/boss/demo_boss/18671058882/
  liuxiaoding/liushantao/mptest/mptestsp）vs `tenant_1.db` 里也躺着一份 users **6 行**

### 实现（v288：后端 4 文件 + 1 测试 + 前端 1 文件）
- `core.py`：`validate_username()` + `USERNAME_IMMUTABLE = ("admin",)` —— **唯一校验实现**，
