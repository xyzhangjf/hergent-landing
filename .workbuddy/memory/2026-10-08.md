## v399（2026-10-08 下午）· 统一留白规范：以「本期预报」为基准，全站单据页对齐全宽

**老板原话**：「在进销存模块中创建各类单据时，界面左右两侧存在大量留白。请先查看"预报订单管理--本期预报"界面，

最后将该规范写入开发规范文档。」

### 🔴 结论：留白的**唯一根因是一行**，不是"很多地方都窄"

| 页面（@1920 视口） | 页根 | `max-width` | 占宽比 | 左右留白 |
|---|---|---|---|---|
| 本期预报（**基准**） | `.page` | — | **100%** | **0 / 0** |
| 进销存 8 页（**改前**） | `.page.page-default` | 1200px | 73.5% | **216 / 216** |
| 舟谱导入（改前） | `.zp-wrap`（**连 `.page` 都没有**） | 960px | 58.8% | 336 / 336 |

- **根因 = `inventory/InventoryShell.vue:22` 的 `.page page-default`**（容器自带 1200px 上限）＋ 全局
  `.page{margin-inline:auto}` ⇒ 8 个子页全部被压在 1200px 居中。基准页 `Forecast.vue:4` 只有 `.page` ⇒ 全宽。
- **8 个子页一个字没改**：它们全是 `.inv-page{display:block}`、**零宽度声明** ⇒ 容器一改即自动铺满。

### ③ 🔴🔴 新坑 1：Vue scoped 把 specificity 抬一级 ⇒ 全局类要写满 (0,2,2)

- **现场**：`dist-v402` 部署后首跑探针 → **6 页表头没居中、列宽 50≠46**（报单配置/招投标雷达/货损核算/商品目标/渠道与价格），
  页内均带自己一份 `.xx-tbl th{text-align:left;padding:…}`。
- **根因不是「没生效」而是「被同分覆盖」**：Vue scoped 给 `.xx-tbl th` 补 `[data-v-xxx]` ⇒ specificity
  **(0,1,1)→(0,2,1)**，与全局 `table.seq-host .seq-th` **(0,2,1) 同分**，**页面 CSS 后加载 ⇒ 页面胜**。
- **修法**：全局写 `table.seq-host th.seq-th` / `td.seq-cell` = **(0,2,2)**（元素+类+类）⇒ 稳压 scoped、**与加载顺序无关**。
  这就是「为什么写成 `th.seq-th` 而不是裸 `.seq-th`」的原因。
- 一般化：往全局上提样式、又要覆盖各页 scoped 同名单元格规则时，**必须假设 scoped +1 级**，别指望「后定义就赢」。

### ④ 🔴 新坑 2：CSS 注释块 `*/` 位置错误会吞掉紧随的规则（本轮最严重的自伤）

- **现场**：修 ③ 时一次 Edit 把说明文字写到 `*/` **之外**（注释已在上一行闭合）⇒ 成**裸文本** ⇒ 解析器把这堆乱码
  **连同紧随其后的 `table.tbl th.seq-th{…}` 规则一起吞掉** ⇒ **全站序号列立刻失效**：
  `dist-v402b` 探针 **PASS 从 133 掉到 104 / FAIL 43**（连原本 PASS 的进销存列表页也红）。
- **修法**：删掉中间多余的 `*/`，让注释块延续到末尾。
- 🔴 **判定 = `/*` 与 `*/` 数量必须相等**（本轮 `/*`=149 / `*/`=149、`{`=145 / `}`=145）。
- **固化护栏**：`v402-spec-seq-consistency.py` 的 `[B]` 类 4 条（B1 `/*`==`*/`、B2 `{`==`}`、
