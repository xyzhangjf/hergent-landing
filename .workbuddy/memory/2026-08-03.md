## 经营看板请求风暴修复 (c73cffc) — ai-accuracy 观察者自我循环 + 卡片插入静默失败
- **用户反馈**: Console 刷屏 ERR_NETWORK_CHANGED + 10+ 层 childList→setTimeout→render 堆栈; content.js 扩展报错(已知无关) + beforeinstallprompt(无害)
- **🔴 主风暴源 (ai-accuracy.js)**: render 成功后 appendChild(.aia-root) 到 dashboardContent 内部 → 触发**自身** MutationObserver(无防抖) → 又 render → 又 append → **死循环**. 实测 forecast/accuracy 53次/10s, 并带动 tpb/ra observer 一起风暴(各自 53 次)
  - 修复: observer 回调里 `.aia-root` 已存在(自己 append 的) → 跳过; 外部重渲染才 render; + clearTimeout 防抖 300ms
- **🔴 卡片永不渲染 (today-profit-bar/recent-actions)**: 经营分析卡片化(.dash-ana-card)后 `.stat-grid` 移入卡片内, 不再是 dashboardContent 直接子节点 → `host.insertBefore(bar, dashContent.querySelector('.stat-grid'))` 抛 **NotFoundError 被 .catch 静默吞掉** → 每次 DOM 变化都白打一个请求
  - 修复: 改为 `host.insertBefore(bar, dashContent)` 直接插到 dashboardContent 前
- **🟡 observer 无防抖**: tpb/ra 的 MutationObserver childList 每次触发都 setTimeout(render,200) 堆叠 → 改 clearTimeout+250ms 防抖 + `_inflight` 防并发

- **⚠️ 排查方法论**: 用 fetch hook 统计各 API 请求次数定位风暴源(不是猜堆栈); 发现"静默失败"(catch 吞 NotFoundError) 导致"请求多但 UI 没渲染"的假象 — 先验证 UI 是否真渲染再修, 别只盯着请求数
- **⚠️ 遗留坑**: 任何"querySelector 到子节点 + insertBefore 到父节点"的模式都会被 DOM 结构重构(包卡片)打破 — 全仓搜索 `insertBefore.*querySelector` 排查同类
