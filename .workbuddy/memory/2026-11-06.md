## v785：Excel 粘贴「严格 N 行全覆盖」（Web 前端，已部署）
- **报障**：易胜玲 99 行只进 76 行、唐成 99 行只进 54 行；第 98 个商品 Excel 为 0，系统仍残留旧值 12。用户明确口径：复制 N 行（含空白行）必须写 N 行，空白行/空白格同样占位并覆盖，不得过滤、不得中途截断、不得保留旧值，0 与空白都要能覆盖旧值。
- **🔴 推翻上一版归因**：v784 说「品牌筛选藏行，数据已落库」不成立 —— 藏行不会让旧值 12 留在原地。真因全在前端写入层（`hergent-cn-v2/src/pages/Forecast.vue`）：
  ① `onPaste` 的 `.filter(l => l.trim().length)` 删光空白行 ⇒ 99→76 且后续行上移错位（易胜玲 76 / 唐成 54 两个不同数字＝各自空白行数不同）；
  ② `parseTSV` 的 `while (尾部空) pop()` 把「末行空白」的真实数据行整段剥掉（Excel 复制末行为空时文本正是以 `\n` 结尾）；
  ③ `pasteRegion` 按 `maxWriteR + 1` 撑行 + clears 的 `k.r < rows.length` 越界跳过 ⇒ 尾行不占位、旧值残留；首行取列数还会被压成 1 列的空白行静默丢列。
- **后端不用动**：`save_matrix` 是「删旧建新」、`qty_by_unit` 只发 model 里已存在的 key ⇒ 那格从没被 `writeCellVal` 触达，旧值 12 就永远留库；只要被触达（哪怕写 0）整期 DELETE 就会清掉它。写入层修完即闭合。
- **修法**：`parseTSV` 保留全部行（含尾部空白）｜`onPaste` 不 filter、不 pop 末尾空串｜`pasteRegion` 补行 `needRows = sr + rows`、列数取全块最大列数（`reduce` 不用展开防超长爆栈）、`clears` 逐格全覆盖无越界守卫、`0` 走 writes 写 0、空白走 clears 写空｜`tryPasteCross` 按商品名内容寻址，**空白行只如实报数、不按位置盲清**（盲清会误伤别的商品，比原 bug 更严重），提示引导「需按位置粘贴请点选落点格」｜toast 明确报「N 行 / N 行空白也占位清空 / 清空 N 个空白格」，不静默。
