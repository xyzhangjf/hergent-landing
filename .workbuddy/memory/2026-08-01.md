### 教训
- **共享表格的右键菜单**必须按当前 tab 模块化分发；硬编码 `_openProductForm` 给所有 #dataTbody 行就是这次 bug 的根源
- **缺少 `data-id`** 的时候 `[data-id]` 选择器静默返回 null，整条 if 守卫吞掉错误无任何提示 — 排查时一定要看 `if(id)` 守卫有没有把数据问题藏掉
- **本地 `server/` ↔ 服务器 `/opt/hergent-erp/` 目录映射**（无 server/ 前缀），scp 时要注意
- **deploy 完成后 `/api/health` 502 持续 ~2s 是 uvicorn 启动延迟**，等 2-3s 后再 curl 就 200；不要被启动抖动误导
- **JS 字符串拼接时变量外置很关键**：变量名如果在 `"..."` 内就是字面量。养成"涉及变量就先关串"的习惯
- **多层包裹的 onclick `(...)()` 是隐患**：如果 action 是多语句（带 var/if），语法必错。要么改用 `try { (function(){...})() }`，要么直接 `;` 分隔不包
- **浏览器端到端验证不可或缺**：后端 + 语法 + hash 全过，浏览器一跑就发现两个隐性 bug，永远先浏览器再标"done"

## 23:58 修复：429 风暴 + avatar 404

### 问题 A:`/api/batch/expiry-scan` 429 风暴
- **现象**：console 50+ 次 429，浏览器狂打 expiry-scan 端点
- **根因**：`cold-chain-zone.js` 的 MutationObserver 监听了 dataContent。每次 `render()` 在 dataContent 里 `insertBefore(banner, first)` → 触发 observer → setTimeout(render, 200) → render() 调 API → 插新 banner → 触发 observer → 死循环
- **修复**：
  1. 删除 MutationObserver，改用 1s tick 轮询 `_dataTab` 变化
  2. render() 加 `_inflight` 锁防止并发
  3. 已存在 `.ccz-root` 时只更新 `innerHTML`，不 insertBefore（**observer 监听的 childList 不受 innerHTML 改动触发**）
- **验证**：`fetchCount=1`（修前 50+/秒）

### 问题 B:`/avatars/*.png` 404
- 8 个 AI 助手头像（dami/accountant/secretary/manager/programmer/writer/screenwriter/tutor）从未部署
- `<img onerror="this.style.display='none'">` 已隐藏坏图，但 console 噪音大
- **修复**：创建 1x1 透明 PNG 占位文件，rsync 到 `/opt/hergent-erp/static/avatars/`

### 教训
- **MutationObserver 监听的节点内做 DOM 改动 = 死循环**（除非改动不触发 childList）。最稳的方案：**别用 observer，改用 polling tick 监听状态变量**
- **观察者循环的 3 步识别法**：①observer fires ②handler 改 dom ③dom 改动再触发 observer → 必循环
- **innerHTML 赋值不触发 childList 增删 observer**——更新内容场景用它代替 insertBefore
