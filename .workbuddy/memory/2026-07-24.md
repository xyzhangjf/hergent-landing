## H1b：统一错误信封收尾 — 中间件 envelope + /api 404 catch-all（已部署+已 commit）

- **背景**：core.py 的 H1b（error_envelope + 全局 500 处理器 + X-Trace-Id）此前已上；但 server.py 中三处中间件错误仍用旧 `{"detail":...}` 格式（租户/CSRF/限流），且缺 /api 404 catch-all（已知前缀的未知子路径会落到 SPA handler 返回 index.html 200）。
- **改动（commit `e5ee314`，仅 server.py，22+/-17）**：
  - 导入 `error_envelope`；租户(403 缺上下文/403 无权/400 无效ID/500 上下文失败)、CSRF(403 required/403 mismatch)、限流(429) 七处中间件错误统一改为 `error_envelope(...)`，error_code=TENANT_REQUIRED/TENANT_FORBIDDEN/TENANT_INVALID/TENANT_CONTEXT_FAILED/RATE_LIMITED/CSRF_REQUIRED/CSRF_MISMATCH。
  - 新增 `/api/{full_path:path}` 404 catch-all（GET/POST/PUT/DELETE/PATCH/OPTIONS），注册在全部具体 /api 路由之后、静态 catch-all 之前；已知前缀但不存在的子路径返回 404 envelope（NOT_FOUND）。完全未知 /api/* 仍由 RBAC 返回 403 MODULE_NOT_CONFIGURED（不暴露路径存在性）。
  - CSRF 对 Bearer token 鉴权默认放行（浏览器不自动附带 Bearer 跨站，设计如此），故 CSRF envelope 仅在 cookie 会话生效——本地用 Bearer 无法触发，生产真实浏览器流才走该分支。
- **验证**：
  - 本地 TestClient smoke：catch-all 404 / RBAC 403 / auth 401 / Pydantic 422 全部 envelope；HTTPException(400) 经 http_exception_handler 转完整 envelope。
  - pytest：321 passed / 28 skipped / 1 预存失败（test_invalid_tenant_id_rejected，与本次无关）。
