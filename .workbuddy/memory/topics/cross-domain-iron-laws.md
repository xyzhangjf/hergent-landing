## 通用铁律（跨域，最易反复踩）
- 门面标准：新功能先问"谁付费、谁天天看"，答不上 = 不许进客户门面（藏 `设置›AI 运维`）。**one-Edit-at-a-time + grep 复核**；**scoped 提交 `git commit -F` 不带 pathspec**（技能 `hergent-scoped-commit`）。
- 🔴 **同屏数字口径必须同源**（返利分母取 `monthly_amounts`、试算传 `ref_date`；报单汇总传 `period_id`）。⚠️ 报单页「建议」名号下有**两个引擎**（系统建议=后端 `forecast_audit.py::_audit_items`，硬编码不读配方；配方建议=前端 `computeSuggestion`）→ 见 `miniprogram-and-brand-data.md`；真正同源属 **P0-b** 未做。
- 🔴 **报单域三条**：数量 = 最小销售单位、件数 = 数量÷规格；渠道价按客户身份取且下单不用；最终下单须取整。
- 🔴 **厂价 ≡ 进价 ≡ 厂家结算价（同一个量）** → **唯一判据 = `factory_price_sql()`：`factory_price` 优先、缺则取 `purchase_price`**（`COALESCE(NULLIF(COALESCE(factory_price,0),0), COALESCE(purchase_price,0), 0)`）；前端同源 `ProductArchive.vue::fpEff()`。⚠️ **两列会分叉** —— 实测 2026-09-15 `tenant_1`：`factory_price>0` **92** 个 / `purchase_price>0` **56** 个 / **权威解析后 121** 个。这是**已知设计**（v132 为「本期需付款」另建 `factory_price`，v165 用 COALESCE 统一），**挑某一列看必然得出错误结论**：我据此一度误报「厂价没落地」，读代码后被推翻。判据：**问「这个量有没有落地」，一律走权威解析函数/SQL，绝不看单列。** ⚠️ **直取 SQL 列值喂闸门的调用方会绕过它** → 必须在 SQL 里先算 `fp_eff`。**厂价条件必填**。零档案锚点 = `products.barcode` 部分唯一索引（`product_backfill_from_import`，reused 只补空、写入列是 `factory_price`）；补价入口 = 商品档案「补厂价 N」。
- 🔴 **设计主表/新字段前先 grep 已有的映射与引擎表**：报单对象字典 = `report_mapping`（`counterparty_type` 只有 store/customer/self_warehouse —— **自提 = customer，调拨 = self_warehouse**）；舟谱模板 = `routers/forecast.py` `ZT_HEADERS`/`DB_HEADERS`；条码→单位 = `forecast_barcode_units`。
- 🔴 **同一规则/集合的第二份拷贝 = 静默漂移温床** → 立刻收敛成单一常量或单一函数。⚠️ **飘移的载体常是「回落写法」**：`MAP[x] || x` / `ROLE_TEXT[r] || r` 这类兜底会把**缺配置显示得跟正常值一模一样**，肉眼永远发现不了 ⇒ 见到 `MAP[x] || x` 先怀疑，回落必须是**显式标记**（如 `未知角色( xxx )`）而不是原值。
- 🔴🔴 **给 accessor 写兜底时，兜底分支绝不能回落到 accessor 自己**（2026-09-19 预报页整页崩溃实证）。`function unitCount(){ return Array.isArray(cross.value.units) ? unitCount() : 0 }` —— 想防「读 `undefined.length`」，结果变成**自递归、没有出口**，一进页面就 `RangeError: Maximum call stack size exceeded`，被 ErrorBoundary 兜成整页「页面出错了」。**最毒之处：它造成的症状与它要防的那个（读 undefined.length）在界面上长得一模一样** —— 你会以为兜底没生效，反复加固兜底，越改越崩。判据：**兜底分支必须落到一个字面量或另一个不同名字的取值路径上**；同名的无参数自调用一律视为事故（护栏 `.workbuddy/tools/direct-self-recursion-check.py`）。
- 🔴 **「视图令牌」≠「规范角色名」，归一 ≠ 授权**（2026-09-19 角色收敛实证）。`owner/finance/dealer/promoter` 是演示期词，后端**不存在**；`normRole()` 只做**词汇归一**（owner→boss、finance→accountant），**不能**把后端不存在的名字变成有效权限。判据：**权威源必须是「会真的拒绝请求」的那份定义**（此处 `core._DEFAULT_PERMS`，且要 **AST** 取 key —— 注释里也有角色名，正则会被注释骗）。前端下拉是**发现性**，不是安全边界；边界必须落在服务端。
- 🔴 **人工维护 Excel 的合计行不可信，须按明细重算**；**系统不存合计行**（DB 无 `total_*` 列），一律渲染时现算。**列头是人名/门店名的宽表 = 报单矩阵**。
- 🔴 **注释写的口径 ≠ 代码取的口径** —— 读价格/口径类代码必须直接看 `SELECT` 列表。**新增列参与必填判定时，缺数据必须显式回退 + 回报行数，绝不静默归零**。
- 🔴 **「拿一个特例写成通用规则」是文案类错误的常见形态** → **改任何用户可见文案前，先确认字段的设计意图**；交付物与产品代码里**逐字相同的文案 = 第二份拷贝**，必须同时改。**"顺手统一成一个词"是反向纪律**：这类改动按 `grep -c 旧变体 == 0` 收口，别只改表头。
- 🔴 **标签类改动的判据要在数据层取，不能只看 DOM**（2026-09-18 v186-2 实证）。Hergent 前端里 **`col_defs[].label` 根本不显示** —— 格子悬停提示用的是该列 `hint`；label 只进 ① 保存时的校验错误提示（`badCols.push(c.label)`）② 溯源/修改日志的字段名（`_COL_LABEL`）。⟹ 只读 DOM 会**误判成通过**，也**别误判成"改了没用"**（错误提示与溯源弹窗正是用户看得到的地方）。改标签前先问一句：**这个 label 在页面上到底显示在哪？** ⭐ 配套：验证脚本的**「变更集封印」形态随轮次演进** —— 上一轮的"登记 N 条白名单"在下一轮（该轮已进 HEAD）**必然报 missing**；那是封印在提示"HEAD 推进了、登记集合该重写"，**不是代码出错**，正确做法是把白名单**收紧**成"零差异"而非放宽容差。且断言必须**双向**（单向断言在"本来就对"时也会通过 ⟹ 每条都要带 HEAD 反证）。域内全文 → `expiry-loss-domain.md §12.7`。
- 🔴 **「额外 / 增量 / 超出 / 多加」类表述必须能指出基准是谁**（2026-09-15 用户订正「均单需额外」实证）。答不上来 ⇒ 它**凭空造了一个页面上并不存在的前提** —— 读的人会去找那个基准，找不到就自己编一个，于是得出错结论。反向同理：**均摊/均值类词（"均单" / "平均"）必须能指出分母是谁**。⚠️ 这类订正**往往不是第一次提**：同一条被提两次 = 上次没被固化 ⇒ 修完必须把判据写进记忆，别只改字。域内全文 → `forecast-order-domain.md §看板文案口径`。
- 🔴 **前端的「模式开关」不得拆开摆放；「跨视图入口」不得下移到视图专属容器**（2026-09-15 v170 评估实证）。
  ① **模式开关**（进入/退出编辑态、开启/关闭某面板）：进入点与退出点必须同处一个容器（现状：`改单` 与 `取消/保存` 同在 `.card.toolbar` 的第一、二行，且改单点下去**同槽位原位变「工具箱」**）。判据：**点完之后，"我刚才按的那个按钮"去哪了、接手的东西在不在同一处？**
  ② **跨视图入口**：先看它在**另一个视图下是否仍在 DOM 里**（实测：`.grid-ctl-row` 在「逐单补录」下不存在，而「改单」按钮仍在 → 它就是跨视图入口）。**反例**：「复制报单」能下移到表格工具行，是因为它的作用域本来就只有汇总表，且它是**无状态命令**（点完即生效，没有"回来"的问题）。
  ⚠️ 与之对照 —— **容量从来不是否决理由**：动手前先量余量（本轮表格工具行 1280 余量 +299px，塞入 74px 按钮后最坏态仍 +65px），**放得下 ≠ 该放**。
- 🔴 **「零污染」类判据必须有「无写入时的阴性对照」**：`sandbox_tenant.py down` 曾用 `--src` 的**默认值**（而非 `up` 落盘的 `meta["src"]`）去算源库 → 拿 tenant_1 的指纹比 tenant_10 的计数 → **稳定假报「112 张业务表计数变了」**。**假阳性方向最坏：把干净的沙箱读成污染了真实库。** 排除真漂移三步：① 连做两次 up→down（间隔秒级）是否复现；② 该窗口内**写请求数**（nginx 非 GET）与源库 `-wal` mtime；③ 同一目标连读两次 + 序列化往返，确认判据函数本身稳定。
- 🔴 **判「承诺/必填是否成立」走 写入端 → 读取端 → 落库表 三步**，模版/UI 写「必填/拒收」必须能指到那行 `raise`。⚠️「必填缺失」表现为 HTTP 200 + `success=0`（后端回 `validation.warnings` 但前端不读）= 用户永远看不到。
- 🔴 **「零值即健康」是陷阱**：`x==0 → 健康` 先问真零还是没数据；聚合接口必须同时暴露「未纳统量」；三态 有风险→warn / 缺数据→neutral / 齐全→good。同族 **「降级即抹掉」**：降级必须另立字段回传。
- 🔴 **配置里有阈值、代码里硬编码另一套 = 口径不一致高发源**：有 `<x>_recipe` 表 → 配置是权威，读配置 fail-safe、边界与 `_sanitize_recipe` 逐字一致。
- 🔴 **判端点是否生效不信 grep，打印路由表**：后定义的 `/api/*` 会被 `routers/*` 抢先（死代码）；**静态路径必须在路径参数之前**，否则 `.../my` 被 `.../{tid}` 吃掉返 **422**。
- 🔴 **「不发插件」是政策，「有隔离」是能力 —— 政策不落成机制就等于没有**。判据：进程 OS 账号 / `HOME` 落点 / 有无沙箱。⚠️ `HOME` 必须读 `/proc/<pid>/environ`（生产 `HOME=/opt/hergent-erp`，只看 `cwd` 会误判）；`SANDBOX_AVAILABLE=True` 不是安全边界。→ 技能 `hergent-tenant-isolation-audit` §11。
- 🔴 判「某未提交改动是否早已上线」用 nginx access.log 的 `hash + 字节数` 序列，别靠包名猜。
- 🔴 **不做假旋钮：新增配置项/档位必须能被用户观察到效果，且不与既有机制重合**。判据三步：① 界面上哪个数字/哪条行为会变？答不上 = 不做。② 是否与**已有机制等价**？③ 效果是否**稳定/不反噬**？→ 只做能观察到且独立的部分，并把「为什么没做那一档」写进注释与提交信息。同族 → 技能 `hergent-capability-reality-audit`。
- 🔴 **真实租户数据异动时：先归因，再认错**。归因三证据（`/var/log/nginx/access.log`）：① **UA**（我的 puppeteer=`HeadlessChrome` vs 用户=`Chrome/138 … QQBrowser`）；② **响应体字节数**（反推打的哪个租户）；🔴🔴 **但 hergent.cn 的 nginx 已对 `application/json` 开 gzip**（`gzip on` + `gzip_types` 含 `application/json` + `gzip_comp_level 5`）⇒ **`body_bytes_sent` 是压缩后值**，只能同型对比大小，**绝不能当原始字节反推 JSON 内容**（2026-09-16 实付代价：按原始字节反推 execute 响应，最高场景 933→gz 584 全部对不上 797，白跑两轮）；
③ **referer 的 `?cb=<epoch_ms>`**（捞同会话全部请求看**动作序列**）。→ 归因错了会去「修」一个没坏的东西。
- 🔴 **我的自动化只准写隔离租户**（9997+）；真实租户（tenant_1 / tenant_10）**只读** —— 要写须**用户显式授权 + 先在线备份（`sqlite3` backup API）+ 改完逐项断言**。E2E 带 `POST/PUT/DELETE` 必须先断言租户 id 不在 `(1, 10)`；回收用**真租户逐字对照**（`ZERO_RESIDUE_OK`）证明零污染。
- 🔴 **隔离沙箱会改数据 ⇒ 有些验证在沙箱里做等于没做**（2026-09-15 实测，差点误报产品缺陷）。`sandbox_tenant.py:130` 克隆后会把**全部** `forecast_submissions.order_date` 改成今天（目的是让克隆来的报单落进「今日报单」窗口）⇒ **任何按期次/日期窗口过滤的行为全部失真**：窗口只要含今天，就命中全部报单。
  实证：`?period_id=9&start=2026-08-30&end=2026-09-15` 返回 **95 商品 / 12,713 件**、**完全不带参数也返回同样 95/12,713**、`period_id=10` 返回 0 —— 看起来像「期次筛选彻底失效」；按真实 `order_date` 手算同一 cond 只有 **4 商品 / 4 件**。根因是沙箱自己改的数据，**后端没问题**（生产 `erp_db.py` md5 与本地仓库一致）。
  **判据**：沙箱**能**验证 行取值 / 单元格渲染 / 列统计 / 筛选 / 复制 / 金额 / 布局容量 / 交互路径（与日期无关）；**不能**验证 期次归属 / 跨期不重复计入 / 时间窗口筛选 / 达成月归属 / 任何依赖 `order_date` 的口径 → 一律去**真实库只读手算**。
  ⚠️ 同族陷阱：`/tmp/sandbox_tenant.py` 会被清掉（并发会话或 /tmp 清理）→ **用前必须重传**。
- 🔴 **多参数写接口一律关键字传参**：`message_send(title, content, msg_type, sender, recipients, ...)` 的**第 4 位是 `sender`** → 把 user id 传第 4 位 = 写进 `sender`、`recipients` 永远空 → **定向退化成广播**。判据：凡「收件人/目标」类参数，签名 >3 个参数时必须 `收件人参数名=值`。
- 🔴 **同一关系被写进两个列 = 必然漂移**。**处置范式**：定一个权威列 → 收敛成**唯一实现**（SQL 表达式 + 两个方向函数）→ 读端全改走它 → 遗留列**只作兜底不许再写** → 死列（零写入方）**显式删除**（列对账只补不删，须循环 `tenant_*.db` 手工删）。
- 🔴 **同一份业务数据被拆成多个「存储键（桶）」时，必须产出「桶 × 消费方」矩阵，逐桶回答「谁读它」**（2026-09-15 返利「周期口径」实证）。`rebate_achievements.period_month` 会被写成 `2026-09` / `2026-Q3` / `2026` 三个**互不相通**的键（GET 是精确等值 `WHERE period_month=?`）：三个图表消费方**全部硬编码月键**，季/年桶的**唯一**消费方是返利合同（`period_key_for` 按规则 `period_type` 挑抽屉；全仓 3 处调用全在合同上下文）⇒ **无合同的租户 = 该桶零消费方**。**判据**：凡出现「按某维度分桶」的新设计，先列矩阵再动手；答不出「谁读它」的桶就是死桶。
  ⚠️ 配套判据：**「能填进去 + 在填报页看得见」≠「被消费」** —— 写入端 / 展示端 / 下游消费端必须**分别**验证。实测反例：往季桶注入 ¥999,999 后，「全年月度对比」达成合计 **Δ=¥0**（数据进得了库、填报页看得见、图表上静默消失）。这类「以为填进去了、主看板读不到」是最容易被掩盖的失真。
  ✅ **2026-09-15 已收口（v173，前端 `c92afa2` / 后端 `06ae645`）**：桶矩阵从 3 行塌成 1 行（月桶 → 4 个消费方全 ✅）。
  规则 `period_type` 降级为「只决定该月目标怎么取」，与存储键解耦；原下拉改成表格「**周期**」列**读数**（+ hover 说明取数逻辑与为空原因）。
- 🔴 **杀掉一个「死桶」必须三处同时收口，只改 UI = 第二条写入路径仍在**（v173 实证）。顺序与判据：
  ① **UI 入口**（删/换选择器）；② **接口写入闸**（`_norm_month_strict` 之类：显式非法值 → **422 + 中文原因**，Excel 导入逐行 `skipped` 并进 `errors`）；
  ③ **读取端取键函数**（`period_key_for` 恒返唯一合法键）。⚠️ 只做 ① 时，任何外部调用方 / 旧模板 / 脚本仍能写进死桶；
  只做 ①③ 时，数据进不去但**旧键仍在库里**。**保留「省略字段 → 回落当前期」的便利约定**（别一刀切 fail-closed，会打断既有调用方）。
  配套：批量导入必须**逐行**判定（一行非法不能拖垮整文件），且错误要给**可操作的中文原因**而不是 `invalid period`。
- 🔴 **把内部存储键暴露给用户去手工对齐 = 把系统实现细节变成用户的负担**。判断一个「口径 / 类型」选择器该不该存在，只看一问：**用户选它是为了表达业务意图，还是为了让数据落进系统要的那个键？** 若是后者（如「选按季 → 请自行填 `2026-Q3`，否则合同读不到」），正解是**让系统按业务对象的固有属性（规则的 `period_type`）自动分桶**，而不是让用户先选桶。同族症状：下拉的多个选项在界面上**渲染结果完全等价**（返利季口径 vs 年口径实测同渲染 1 行同金额、仅键字符串不同）⇒ 说明这个选择器承载的是**存储细节**而非业务语义。
  ⭐ **同一判据的推广（全站排查用）**：前端每个 `<select>` 逐个数「value 是业务标签还是存储键」—— 返利/渠道/档位/分单模式等实测**全是业务标签**（`frozenKey` 的 value 虽是英文字面量但 label 是中文），**唯一例外就是本次的「周期口径」**。判据落地后**同类问题全站只有一处**，别一看到下拉就以为有一堆。

- 🔴 **「定向失败 → 留空收件人」等于广播**：`recipients` 空 = 全租户可见。凡敏感内容投递，**取不到收件人必须返回失败且不落库**。判据：读该函数的 `return` —— 有没有一条路径是「拿不到目标还能成功」。
- 🔴 **「租户内 id」出现在主库全局表上，查询必须按 `user_tenants` 收口**：凡 `users.<某>_id` 指向租户库业务行，一律 `AND u.id IN (SELECT user_id FROM user_tenants WHERE tenant_id=?)`。
- 🔴 **租户库 `tenant_<id>.db` 里有一张陈旧的 `users` 表**（有 `employee_code`、**无 `employee_id`**，且含**主库不存在的幽灵账号**）；而 `/api/auth` ∈ `_TENANT_PUBLIC_PREFIXES` → **登录读主库**。⇒ 凡在**租户上下文**里写 `FROM users` 的代码都在读那张陈旧表（已发现 4 处），必须改走主库（`core._master_db()`）或权威函数。

### B. 表格「固定列 / 只读列」（v184b，`Forecast.vue`）

- 🔴 **给表格加冻结列，冲突面不止样式**：z-index／既有冻结列 `left` 整体右移（走 `colW()` 不硬编码）／

- 🔴 **「固定列」= 一条带不变式的机制，不是加个 `position:sticky`**（v184b 落地）：偏移必须
  **按名单依次累加 `colW()`**（禁硬编码 —— 原 `frozenShift` 传死值 `200`，而 `COL_DEFAULTS.name=210`
  ⇒ **恒偏 10px**）；**冻结区必须连续** ⇒ `visibleCols` 要**强制归位**，否则偏移算到别的列头上
  （错位/遮挡**且不报错**）；不可隐藏/删除/拖拽，规则只此一份 `isLockedCol`；⚠️ **列设置菜单的 `c`
  来自 `colOrder`（只有 `name` 带 `fixed`）⇒ 不能读 `c.fixed`**；查看态还要 `colOrderList` **透传

- 🔴 **只读列（`edit:'ro'`）必须堵「两条写路径」**：`writeCellVal` 与**绕过它的 `ctxClear`**（右键清空，

### C. 探针 / 真机验证

- 🔴 **探针坑**：`page.evaluate` 传**字符串**参数会被当表达式求值；`<select>` 须按 `aria-label` 定位；

- 🔴 **探针「假失败」两形态（编辑态网格，v184b 实测）**：① **`Delete` 清空不可达** —— `@keydown` 挂在

  拿一格本来就空的当对照，「清空后仍为空」恒真 = **空断言假 PASS**。
