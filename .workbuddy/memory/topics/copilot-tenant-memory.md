## 🔴 副驾 / 租户 / 内存（2026-10 主线，全文 `topics/cost-and-capacity.md`、`topics/backend-invariants.md` §v634/v635）
- 🔴 **租户边界 = 进程用哪个系统账号，不是开关**（v635）：`gateway_api(tid)` 读该租户 `config.yaml` 的 `platforms.api_server.extra`，端口 `18800+tid`；解析不到 ⇒ **必须 503，绝不回落根实例**。租户 1 是平台自有租户，走根实例 18765（老板要留的「副驾能改代码」只归他）。
- 🔴 **v642 A 方案：老板的 web + 企微已合并进一个进程**（根实例 `/root/.hermes`，`api_server:18765` + `wecom` 同进程）。平台租户(1) 在 `hermes_tenants` 里是**根实例的别名**：凭证/state 走 `_host_home`、PID 走 `_systemd_main_pid`、`ensure_running(1)` 直接 return None（否则 60s 保活又拉起孤立实例）、start/stop/restart 走 sudo `systemctl`。内存 2205→**1348MB**、可用 987→1855MB。
- 🔴 **v647 推送两判据**：① **判「CLI 挂住」先看调用方 stdin**——`hermes send` 在 stdin 非 TTY 时 read() 到 EOF 才干活，`_run` 的 `input=None` 会继承常开管道 ⇒ 整体挂死（我误判成企微互踢一次）；已改无 input 时 `stdin=DEVNULL`。② 🔴 **v648 推翻「不踢网关」：企微独立短连接推送会踢掉网关长连接**（`_standalone_send` 临时开 WS 订阅，同 bot 单订阅规则）——当晚逐条对时坐实（推送停⇒close 停，非服务端轮换）；每次踢 2.2s 自愈、无 846609，正常态频率低**可接受**；彻底方案 P1=推送搬进网关内 cron（deliver=wecom 走 live adapter）。③ Web 历史滤机器推送 = `_is_machine_push`（首行标题白名单 12 类 + 只作用 role=assistant；**不能按 token_count 为 NULL 判**，345 条无计数里 103 条是真实回复；**不能滤「经营副驾」**——那是 agent 回复签名）。④ **入口合并清单再加一项：cron 脚本里硬编码的 HERMES_HOME 默认值**（巡检 ALERT_HOME 已 t1→`/root/.hermes`）。⑤ `/opt/hergent-erp/{backups,var}` 要手工 chmod 700（`normalize_tenant_perms.py` 不管后端自己这两个目录）。
- 🔴 **v647 顺带**：库存预警「30 分钟一条」是**重启假象**——`_push_alert_throttled` 节流字典在内存，每次重启后端补推一次，正常一天一条。DeepSeek 余额 ¥8.68（预警线 ¥20）待充值。
- 🔴 **v648 判通道状态只认 `/root/.hermes/gateway_state.json`**（$HERMES_HOME 下）：`logs/gateway_state.json` 是无代码引用的历史遗留（已消失），曾误导判读成 disconnected。企微「5 分钟一次 closed」=推送驱动（23:40 cron 无推送⇒23:43 无 close）；aibot 纯 WS 无 HTTP 发送 API、网关 api_server 无代发端点⇒进程外推送踢连接架构上免不了；心跳 30s 排除空闲被踢；CLOSE-WAIT 陈旧 fd 无害（重启网关即清）。
- 🔴 **同一个企微 bot 只能一个 websocket 订阅**：双连报 `WeCom errcode 846609: aibot websocket not subscribed` ⇒「发消息不回/图片传不出」+ 进程 100% CPU 重连死循环（t1 曾空转 252 分钟 CPU）。卡住的网关 `kill -TERM` 无效，要 `kill -9` 且连 `sudo -u` 包装一起杀。
- 🔴 **判「后端吃多少内存」看 `ps -o rss -p $(systemctl show -p MainPID --value hergent-erp)`，不能看 `memory.current`**（v640）：那个 cgroup 住着 9 个进程，后端本体只 ~200MB，其余是 `sudo -u hergent_tN` 拉起的租户网关 + 每网关一个 MCP + `hermes send`——**cgroup 沿 fork 继承，`start_new_session` 不影响**。已迁出：`tools/tenant_cgroup.sh <tid> <high> <max> [pid]` + sudoers + `_spawn` 即搬 + `ensure_running` 自愈。
- 🔴 租户 cgroup 三坑（v640）：① `/proc/pid/cgroup` 是**相对挂载点**路径（`0::/hergent_tenants/t10`）且必须**整段相等**（`t1` 是 `t10` 前缀）；② **`sudo` 会转发信号** ⇒ 只搬 hermes 不搬 sudo 包装，`restart hergent-erp` 经 sudo 转杀网关；③ `memory.reclaim` 写不进 systemd 托管的 service cgroup（root 也不行）。
- 🔴 **顶穿 `MemoryHigh` 是 D 状态锁死，不是「慢一点」**（v640）：cgroup 内 `file=0` + `vm.swappiness=0` ⇒ 无页可回收 ⇒ `mem_cgroup_handle_over_high` 挂住每个任务。白屏/全站超时时主进程 `D`、`wchan=mem_cgroup_handle_over_high` 就是这条；**排「进程卡住」先看 wchan**，别当网络/磁盘查。swappiness 已设 10。
- 🔴 **成本 = 入口数 × 每入口常驻进程，与用量无关**（v641）：t10 演示租户 22 天没登录仍占 225MB。`state.db` 随使用线性膨胀且 **FTS trigram 放大 ~20 倍**（根实例 5923 条消息→100MB）。⚠️ 真门槛不是钱是**故障域**：一机手工挂 5 户以上，升级/重启/一户跑飞都是「影响所有人」。
- 🔴 **v645 实测：单户真实成本与 4G 机容量**（全文 `topics/cost-and-capacity.md`）：单户 **刚启动 282MB / 用过 323MB / 峰值 332MB**，且**内存不随使用量膨胀**（每轮只 +2~3MB）⇒ v641「随使用膨胀」只对 `state.db` 文件成立、对 RSS 不成立。6 并发只吃 200% 里的 **50%** ⇒ **CPU 有 4 倍余量，内存先撞墙**。这台 4G = **老板 + 3 客户**（available 1677MB）。token 首次量化：系统提示固定 **11258 tokens/轮**、失败读表重试 **48330**，`deepseek-v4-flash` ⇒ **1.4~4.5 元/月/户**；合计**一客户一台 34.5 元/月（收 500 占 6.9%）**，四户分摊只省 23 元却换 4 倍故障域 ⇒ **不划算，接客户就新开一台**。
- 🔴 **闲置租户停不掉**（v645）：`ensure_running()` 只在 `not enabled_channels and not _has_api_server` 时跳过；配了 `api_server` 的租户（每户都有 = 副驾出口）**永远不满足** ⇒ `tenant_kill.sh 10` 后 75 秒被保活拉起。⇒ 每户 282MB 是**永久固定支出**，要省只能加「休眠」判据（如最近 N 天无活动）。
- 🔴 **镜像开新客户必须先脱敏**（v645）：镜像含 `erp.db`（客户名/进货价/返利率）+ 根 `state.db`（全部对话）+ `.env`（key）⇒ 直接开机就卖 = 跨租户泄密。接客户定式：镜像 → 脱敏脚本 → 改域名/租户名 → 关老板实例起客户实例，首次把这条路走通后每客户 ≈50 分钟。
- 🔴 **改完 `hermes_tenants.py` 必须重启后端再做「杀掉观察 60s」验证**（v642 踩）：旧进程的保活会在 40 秒后把你刚杀掉的租户网关复活，看着像补丁无效。
- 🔴 **v646 合并后遗症：所有「读运行态」的地方必须 `_host_home(tid)`**（v642 只改了一半）——同步 state.db（web 看不到企微新消息）/media 白名单/配方 skills/配对读写/`_run`。但 🔴 **`_identity_kwargs` 对平台租户必须 `return []`**：切 `hergent_t1` 进不去 `/root/.hermes`（属 hergent、0700）⇒ hermes 一 import 就崩、推送全失败。合并必搬清单见 `topics/backend-invariants.md` §v646。
- 🔴 **给模型看的上下文注不进人的气泡**（v634）：Hermes 的 `[The user sent a document: …]` 落在 user 回合 ⇒ 老板看到「乱码」。渲染层抽成附件条；文件名优先解 `agent_path`，兜底解 display_name（`_E6_9C_88` 字节 hex）；**只吃英文注**，前端拼的 `【附件：…】` 原样留。
- 🔴 **气泡时间只认 `m.created_at`，三个来源必须都写**（v636）：后端 IM 同步 `select … timestamp`（Hermes 是 REAL 秒，×1000 存 ms）；前端每条 push 都带（`showDemo` 漏过）；`updated_at` **不许写 `now()`**（否则每打开一次历史就被改成"刚刚"、永远钉列表顶部）。v521(10-16) 前的旧 web 会话无法还原 ⇒ 不造假时间。
- 🔴 **「打开副驾显示最后一次对话」两级取会话**（v637）：只按 `latestSessionOfRole(当前角色)` 会 100% 落空（真实最近会话常属别的角色或企微同步会话）⇒ `latestSessionOfRole(rid) || latestSessionOverall()`，恢复后归属角色 ≠ 当前则 `setAiRole` 跟过去；「接着上次聊」仍走严格口径。
- 🔴 **副驾读表 = `spreadsheet_query._run_query`**（v638；企微端走 Hermes 自己的文件能力，所以两端表现会不同）：`by/bys`、`column/columns` **都支持多列**（交叉统计一次调完，拆两轮必错）；表头**自动探测**（舟谱/银行导出常在第 5 行），`summary` 回 `header_row`(1-based)，列名像标题就显式传它重试；单列调用仍回 `sum`+字符串 `by`（旧契约零改动）。
