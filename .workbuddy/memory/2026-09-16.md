## v176：本期预报主表「序号列冻结」（同日续，09-16 下午）

用户原话：「将商品名称前面用于显示序号的列设置为冻结列（即在水平滚动时保持该列固定可见），
并确保原有表头与其他列布局、排序及显示逻辑不受影响。」

### 隐含约束：主表**已有**冻结列机制，序号列不能直接占 left:0
只读表 `frozenKey` 默认 `'name'`（下拉可切 name / product_code / none），改单表「商品名称」
`fixed:true` + 可选 `frozenExtra`。序号列若直接 `left:0`，会与既有冻结列**重叠**
⇒ 既有冻结列的 `left` 必须整体右移「一个序号列宽」。

### 实现（`Forecast.vue` 单文件）
- 新增 `frozenShift(base)` = `(colW('seq') + (base||0)) + 'px'`，**6 个渲染点共用**
  （只读表 thead/tbody/表尾 + 改单表 thead/tbody/表尾），避免 6 份内联表达式各自漂移。
- 🔴 **必须走 `colW('seq')`，不能硬编码 46**：序号列宽可被拖拽手柄改
  （`startResize($event,'seq')` → `colWidths` + localStorage），硬编码会在用户改宽后错位。
- 序号列 sticky `left:0`，底色与既有冻结列**完全一致**（表体 `var(--bg)` / 表头 `var(--bg3)`），
  读作**一个整体冻结块**而非单染一条色带。

### z-index 裁决（本轮关键）
`.cross-tbl thead th`=7 · `thead th.frozen`=8 · `.frozen` td=6 · `td.cell-active`=4。
序号列**表头取 9**（必须高过既有 thead th 与 th.frozen，否则横向滚过来的普通表头会盖住它 ——
同为 sticky、z 相同时**后出现者胜**）、**单元格取 6**（与 `.frozen` 同级）。
行状态**自动胜出、无需在冻结规则里重复**：`.cond-warn>td` 带 `!important`；
`.td.seq-cell.row-bad`(0,3,0) > 本规则(0,2,0)。

### 🔴 顺手修掉既有缺陷：表尾「合计」行横向滚动后错位
表尾是**另一张 table**（`.col-total-bar`），靠 `--foot-sl` 整体 `translateX` 跟随表体
（它自己不滚动 ⇒ `sticky` 在里面无效）。位移对冻结列一视同仁 ⇒ 实测 `scrollLeft=600` 时
「合计」标签滑出左边界、冻结列下方显示的是**别的列**（标准售价/进价/分销价 三格）。
修复：`.col-total-bar .frozen,.col-total-bar .seq-cell{transform:translateX(calc(-1*var(--foot-sl,0px)))}`
—— `--foot-sl=0` 时是 **no-op**（静态外观零变化），这是可否顺手修的判据。
⚠️ 该规则特异性 (0,2,0) 压过 `.col-total td{background:var(--bg3)}`(0,1,1) ⇒ 会把表尾染白，
需单独再兜一条 `.cross-tbl .col-total .seq-cell{background:var(--bg3)}`。
