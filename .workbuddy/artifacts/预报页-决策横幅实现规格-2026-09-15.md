## 1. 为什么

「改单」离主表 440px、编辑态「保存」离表头 439px —— 两个痛点的**共因**是中间这块 **360px** 的返利冲刺看板（`rebateSprintOpen = ref(true)` 默认展开）。

把它的结论压进标题条下方一行 ⇒ 折叠态 **71px**，距离降到约 **151 / 150px**，且**零入口迁移、零功能损失**。

## 3. 四个数字的唯一来源（全部是现有 computed，零新增计算）

| 横幅文案 | 表达式 | 定义位置 |
|---|---|---|
| `2` 个品牌未达标 | `rebateSprint.filter(s => s.gap > 0).length` | 由 `rebateSprint`（L5635）派生 |
| 总缺口 `¥340,039` | `'¥' + fmt(sprintTotalGap)` | `sprintTotalGap` L5723 |
| 剩 `8` 次到货 | `rebateSprintOrders` | L5586（按 `rebateGlobalCadence` 估算） |
| 均单需额外 `¥42,505` | `'¥' + fmt(sprintTotalGapPerOrder)` | `sprintTotalGapPerOrder` L5724 |
| 本月时间进度 `50%` | `sprintTimeProgress.pct` | L5726（**已有**，留在标题条不动） |

### 🔴 单位必须与展开态表格同源

表格「距目标还差」列用 `fmt()` 输出**元**（`268,539` / `71,500`）。横幅若图短写成「¥34.0万」，就与下方表格成了**同一量两种单位** —— 违反跨域铁律「同屏数字口径必须同源」。

⇒ 横幅用 `¥340,039`（与表格同一函数、同一单位）。宽度只多约 14px，两种视口都富余。

> 若确实想全站改「万元」口径，那是一次**独立的、全表统一**的改动（表格列 + 横幅 + 系统建议一起），不能只在横幅上开第二套。

## 4. DOM 插入点

`Forecast.vue` L297–L354 的 `.card.sprint-card` 内部：

```
L297  <div v-if="cross.period" class="card sprint-card is-pinned">
L298-305    <div class="panel-hd"> … 标题 / 两个 tag / sprint-tp / 折叠按钮 … </div>
   ← ★ 在 L305 与 L306 之间插入决策行
L306      <div v-show="rebateSprintOpen" class="panel-body"> … 明细表 + 系统建议 … </div>
L354  </div>
```

建议模板：

```html
<!-- 决策横幅：看板结论的常驻摘要行（折叠/展开都在） -->
<div class="sprint-banner" v-if="rebateSprint.length">
  <template v-if="unmetSprintCount">
    <b>{{ unmetSprintCount }}</b> 个品牌未达标
    <span class="sep">·</span>总缺口 <b class="warn">¥{{ fmt(sprintTotalGap) }}</b>
    <span class="sep">·</span>剩 <b>{{ rebateSprintOrders }}</b> 次到货
    <span class="sep">·</span>均单需额外 <b class="warn">¥{{ fmt(sprintTotalGapPerOrder) }}</b>
  </template>
  <template v-else>
    <b>{{ rebateSprint.length }}</b> 个品牌目标<span class="ok">全部达成</span>
    <span class="sep">·</span>本月时间进度 <b>{{ sprintTimeProgress.pct }}%</b>
  </template>
</div>
```

配套新增 computed（唯一实现，避免模板里重复表达式）：

```js
const unmetSprintCount = computed(() => rebateSprint.value.filter(s => s.gap > 0).length)
```

**边界**：全部达标时不能显示「0 个品牌未达标」（读起来像故障），改说「N 个品牌目标全部达成」。

**`rebateSprintOrders` 的语义**：按全局默认到货周期估算（本期为「每 2 天」⇒ 8 次）；各品牌实际次数不同（蒙牛 8 次 / 简爱 5 次，见明细）。建议给这个词加 `:title="'按默认到货周期（每 ' + rebateGlobalCadence + ' 天）估算，各品牌精确值见明细'"`。

## 5. CSS 规格

现有相关规则（L6748–6763）：

```css
.sprint-card.is-pinned{margin:14px 0 4px;border:1px solid var(--p);box-shadow:…;background:linear-gradient(…)}
.sprint-card.is-pinned .panel-hd{border-bottom:1px dashed var(--border-subtle);padding-bottom:10px;margin-bottom:0}
.sprint-card .panel-body{padding-top:10px}
```

新增（建议值，字号/色值对齐页面现有 `--t1/--t2/--warn` token）：

```css
/* 决策横幅：一行承载「缺口 / 剩余机会 / 建议均单」，常驻显示 */
.sprint-banner{display:flex;align-items:center;flex-wrap:wrap;gap:6px;padding:9px 16px;font-size:12.5px;line-height:1.5;color:var(--t2)}
.sprint-banner b{color:var(--t1);font-variant-numeric:tabular-nums}
.sprint-banner b.warn{color:var(--war)}
.sprint-banner .sep{color:var(--border-strong)}
```

**分隔线归属调整**（关键，否则展开时会出现双线或断线）：

- `.panel-hd` 的 `border-bottom:1px dashed` **保留** → 分隔标题与决策行
- `.sprint-banner` **无边框**
- `.panel-body` **新增** `border-top:1px dashed var(--border-subtle)`

这样：折叠时 `panel-body` 被 `v-show` 隐藏 ⇒ 虚线同步消失，卡片底就是干净的一行；展开时虚线正好把「摘要行」与「明细」分开。

## 6. 交互与状态

| 项 | 现状 | 改为 |
|---|---|---|
| 默认态 | `rebateSprintOpen = ref(true)` 展开 | **默认折叠**（`ref(false)`） |
| 编辑态 | 照常展开，占 360px | **自动折叠**：`watch(() => editMode.value, v => { if (v) rebateSprintOpen.value = false })` |
| 手动展开 | 点标题条右侧 chevron | 保留；编辑态点开仍可看明细 |
| 是否记忆 | 无 | **待定**（见 §8） |

编辑态自动折叠是 A2 的后半 —— 它同时解决「保存按钮离表头 439px」，而**不做任何控件迁移**。

## 8. 未决 / 需你拍板

1. **折叠状态要不要跨会话记住？**（`localStorage`）—— 若记住，用户手滑折叠后下次进来会「少了一块」，但省高度；若不记住，每次进页面都是默认折叠、编辑态折叠，行为可预测。**倾向不记住**（预测性 > 个性化）。
2. **编辑态是「强制折叠」还是「可手动展开」？** 倾向可手动展开（不剥夺信息），但默认收起。
3. **要不要在横幅右侧加一个「一键带入加单」按钮？** 展开态里已有这条闭环（`Forecast.vue:6000` 提示 → `:6017` `r.extraQty += q`），折叠后入口消失。加了是**功能新增**（超出「搬位置」范围），需要单独评估；不加则用户要看建议得先展开。
4. 前置的落点决策本身（A2 / A1 / B / C / D / F）尚未拍板。
