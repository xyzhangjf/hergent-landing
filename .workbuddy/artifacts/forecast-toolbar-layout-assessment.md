# 预报页主工具栏 · 单行/双行布局可行性评估

> 评估对象：`hergent-cn-v2/src/pages/Forecast.vue`「本期预报」标签页主工具栏（`.card.toolbar`，模板第 14–123 行）
> 方法：复刻工具栏 DOM + 加载仓库真实 `variables.css`，用无头 Chrome 量**真实盒宽**（非估算），逐视口渲染判定行数
> 日期：2026-09-12

---

## 一、结论

| 问题 | 答案 |
|---|---|
| 能否改**双行**？ | ✅ **能，且零信息损失**。任意宽度稳定 2 行，高度 153px → 108px（**省 29%**） |
| 能否改**单行**？ | ⚠️ **非编辑态能，编辑态在 1440 屏不能**。单行需砍掉约 290px 控件宽度，必须收敛 3 处 |
| 当前为什么是三行？ | 不是设计失误，是**宽度硬约束的必然结果**——现有控件总需 1408px，你的屏幕只有 1120px |

## 三、方案 A · 双行（推荐）

### 分组

```
行 1（上下文：看哪一期 / 怎么筛）
  [─ 选择期次 ─ ▾] [⋯] [+ 新建期次]        [搜索商品/条码…] [仅显示有报单] [待审核]

行 2（动作：对数据做什么）
  [导入] [导出 ▾] [复制报单 ▾]      [改单]      [AI智能建议] [品牌 3 ▾]
  编辑态：  [导入][导出][复制报单]   [取消][回退][查错][补录商品][保存]   [AI智能建议][品牌][工具箱]
```

### 关键改动（只有 2 处）

1. **拆行**：把现有右组按语义切成两段——「搜索/筛选」上移到行 1 右侧，「数据/编辑/AI」留在行 2。
2. **状态行并入行 1 右侧**：`.tb-status-row` 从 `flex:0 0 100%`（独占整行）改为行内元素，`margin-left:auto` 右对齐。

### 为什么这样切最合理

- 符合仓库既有 `toolbar-standard.md` 的分组原则（**左筛选/视图，右动作**），不是新发明。
- 「待审核 / 已确认」是**期次的属性**，和期次选择器同层是语义正确的；它此前被迫独占一行纯粹因为宽度不够。
- 行 1 恒为"看"，行 2 恒为"做"，编辑态下按钮数量变化只影响行 2，行 1 视觉稳定——**切换编辑态时不会跳动**。

### 实测密度

| 行 | 非编辑 | 编辑 |
|---|---|---|
| 行 1 | 693px | 693px |
| 行 2 | 707px | **1102px** |

### ⚠️ 一个必须知道的边界

编辑态行 2 = 1102px，你的屏幕可用 1120px → **余量仅 18px**。
换算成侧栏宽度：`内宽 = 1368 − 侧栏宽`，行 2 放得下要求 **侧栏 ≤ 266px**。

> 侧栏默认 248px，但只要把它拖宽超过 266px，编辑态行 2 就会折行退回 3 行。
> **建议同时做一处瘦身**（任选，都能腾出 30–40px）：`AI智能建议` → `AI建议`（省 33px）或 `新建期次` 改图标按钮（省 40px）。

## 四、方案 C · 单行（激进，需取舍）

单行要砍掉约 **290px**（1440 屏）。必须做满这 3 处收敛：

| # | 收敛项 | 省 | 代价 |
|---|---|---|---|
| 1 | 搜索框 → 图标按钮（点击展开输入框） | 162px | 搜索多一次点击 |
| 2 | 「仅显示有报单」→ 图标开关 或并入筛选面板 | 81px | 可发现性下降 |
| 3 | 「导出」+「复制报单」合并为一个 `导出/复制 ▾` | 108px | 菜单多一层 |

再加**状态徽标移到上方标签行右侧**（`.module-tabs` 右侧本就全空，`margin-left:auto` 即可），可把非编辑态余量从 89px 拉到 **172px**，稳得多。

**编辑态在 1440 屏仍会是 2 行**（需 1163px，实际 1120px，差 43px）；要单行必须把「回退/查错/补录商品」收进「更多」——**这会让「查错」的红角标（如 12 个错误）消失，是关键提醒信号的降级，不建议做**。

## 五、建议

**先做方案 A（双行）**。理由：

1. 收益已经拿到大头——**省 45px / 29%**，且编辑态从 153px 降到 108px（编辑态是你抱怨的主要场景）。
2. **零功能降级**：不藏任何按钮、不改任何交互，纯布局重排，回归风险极低。
3. 方案 B 的 91px 收益要拿 3 处交互取舍去换，而其中「搜索图标化」对 428 个 SKU 的查找体验有实际影响——**不值得为多省 46px 付这个代价**。

若确实想再压一档，建议采用 **A → C 分两步**：先上双行观察一周，若仍觉得占地方，再单独评估「导出/复制合并」（这 1 处收益 108px、代价最小）走单行。

## 七、间距重做（2026-09-12 · v138 · 前端 `0bfb3de` · 已部署并推送）

### 问题（真机实测基线，1440 屏）

v137 的行1 用两个 `margin-left:auto`（`.tb-search` + `.tb-status-row`）做左右分区，
剩余空间被两个 auto 平分，形成**两段空洞**；另有一个被掩盖的缺陷：搜索框固定
194px（输入区 150px），而 placeholder「搜索商品名 / 条码（后 4 位也行）」渲染需约 230px，
**实际被截断**成「搜索商品名 / 条码（后」。

| 相邻控件 | 旧版间距（1440） | 旧版间距（1920） |
|---|---|---|
| 新建期次 ↔ 搜索框 | **246px** | 486px |
| 搜索框 ↔ 仅显示有报单 | 8px | 8px |
| 仅显示有报单 ↔ 待审核 | **251px** | 491px |

### 改法

| 改动 | 值 |
|---|---|
| `.tb-head` gap | 8px → **12px**（组间距统一 12px，组内保持 8px） |
| `.tb-search` | 移除 `margin-left:auto`；改 `flex:1 1 200px / min-width:180px / max-width:460px` |
| `.tb-search .fld` | `width:150px` → **100%**（placeholder 完整可见） |
| `.tb-status-row` | 移除 `margin-left:auto`（否则状态徽标仍会右浮） |

行1 结构（三段语义，左起连续）：
```
[期次上下文] 12px [搜索(弹性)] 12px [仅显示有报单] 17px │ 17px [状态徽标]      行尾余量
 选择期次 ⋯ +新建期次      商品名/条码        ☑         分隔     待审核
```

### 实测对比（真机 · hergent.cn 演示环境 · 侧栏 248）

| 视口 | 期次组↔搜索框 | 搜索框↔筛选 | 筛选↔状态 | 搜索框宽 | 行尾余量 | 行数 |
|---|---|---|---|---|---|---|
| 1280 | 246→**12** | 8→**12** | 171→**34** | 194→**460** | 1→**35px** | 2 行 |
| 1440 | 246→**12** | 8→**12** | 251→**34** | 194→**460** | 1→**195px** | 2 行 |
| 1920 | 486→**12** | 8→**12** | 491→**34** | 194→**460** | 1→**675px** | 2 行 |

（筛选↔状态 = 12px gap + 5px sep margin ×2 + 1px 分隔条 = 34px）
编辑态结构不变：1440 屏 2 行 106px；1280 屏编辑态 3 行 144px（与 v137 一致）。

### 关键设计取舍：横向余量放在哪？

去掉两个 auto 后，余量必然出现在「行尾」。做法是把它交给**弹性搜索框**吸收
（上限 460px），剩余部分（1440 屏 195px）留在行尾：

- **控件之间的留白 → 0**（统一 12px）✅ 用户抱怨的两处彻底消除
- **行尾空白** → 保留，是「左对齐工作条」的标准形态；1280 屏仅 35px，非常紧凑

若把搜索框上限继续调大（>520px）可进一步压缩行尾余量，但搜索框会显得过宽，判定不值。
1920 屏行尾 675px 属大屏常态（固定上限 + 左对齐）；若确需在大屏填充，正确方向不是
拉伸控件，而是让状态徽标在大屏恢复右锚（媒体查询），本轮未做。
