# v233 · 「报单单位」修复说明（2026-09-21）

> 一句话：**系统里一个商品其实有两个「单位」**（档案单位 / 报单单位），一直挤在同一格；
> 现在把它拆成两格，并且**改单位时数量会一起换**（以前只换个标签、数字不动 —— 这正是
> 你 9 月报过的那个「条/件」问题）。

> 已在生产实测：**已经在导的舟谱模板一个字节都没变**，主表「单位」列 22 行换成了正确的单位。

## 一、问题是什么（为什么「单位」会打架）

一个商品在系统里有两个不同的「单位」概念，以前**共用一列**：

| | 什么意思 | 谁在用它 |
|---|---|---|
| **档案单位** | 舟谱里的「**小单位**」（最细的那个） | 档案对账、价格档位 |
| **报单单位** | 你实际**下单**用的那个单位（可以是「组」这种中单位） | 主表「单位」列、舟谱模板「`*单位`」列 |

两者挤在一格 ⇒ 谁写进去就按谁的算，**这就是「条 → 件」问题的根**。

举你报过的那个例子（真实数据）：

> 商品 `160红枣5连杯`，规格填的是 `8`，档案里的单位是「**件**」，而报单明细里写的是「**条**」。

系统按档案显示「件」，舟谱要的是「条」⇒ **量纲差 8 倍**。

**再看一层**：档案里有 61 个商品的单位写着「件」，但**它们的大单位换算、大单位名都是空的**。
不是数据撞车，是**当初从舟谱导档案时这些商品压根没录过小单位**，导入时落了默认值「件」——
而「件」在舟谱里是**大单位**。⇒ 同一列里并排放着两种语义。

## 二、改了什么

| | 改之前 | 改之后 |
|---|---|---|
| 「单位」有几格 | 1 格（两种语义混用） | **2 格**：档案单位 + **报单单位** |
| 报单单位填哪 | 没地方填（只能在别处的条码表里维护） | **商品档案 → 报单单位**（留空 = 跟随左边的「单位」） |
| 主表「单位」列取自 | 档案单位，可能被条码表覆盖 | **统一取「报单单位」**（留空则回退档案单位） |
| 舟谱模板「`*单位`」取自 | 条码表 → 明细 → 猜名称 | **同一个「报单单位」**（与主表**同源**，不会再各说各话） |
| 🔴 改单位时「`*数量`」 | **不动**（只换标签） | **按档案换算一起换**；换不出来就**保持原样并告警** |

第三行与第四行是这个改动的关键：**主表和舟谱模板从此看同一个值**，不会再出现「主表说件、
舟谱要条」这种对不上的情况。

最后一行是安全阀：**宁可不动，也不写一张量纲可能错的单**。
换算不出来时（该商品没录中/大单位换算、规格串里也定位不到单位），系统会
**保留你填的单位和数量原样**，并在下载时的告警里**点名是哪几行**，让你去档案里补。
