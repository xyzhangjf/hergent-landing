  3. 「ID 前加 ZT / DB 编号」 —— 用 (kind, id) 两列表达了同一件事：等价于把 ZT5 / DB5 拆开，但不改 store_id 的类型（改类型要动所有读端，风险远大于收益）。舟谱模板里 ZT/DB 前缀本来就分别由「自提订单 / 调拨订单」两张工作表承担，前端不加前缀（避免动列名契约）。
    补一句实话：当前真数据其实没撞号——门店 id 在 2214～2969，仓库 id 在 1～10。但轴必须留着，否则你哪天建到第 2213 个门店就会静默出事。
  4. 「维持一店一期一单，但一人可同时报多门店 + 自己仓」 —— 维持住了。幂等键从 (store_id, period_id) 升级为 (store_id, store_kind, period_id)，所以 (7,'store') 与 (7,'warehouse') 是两张各自独立的单，「一店一期一单」的口径没被破坏。
