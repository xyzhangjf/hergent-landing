## 三、问题 2（更严重）：密码被硬限制在 8 个字符

排查 B 的前置条件时实测发现：

```python
# 旧实现
def _hpw(pw):
    return "bcrypt$" + bcrypt.hashpw((pw + SECRET).encode(), bcrypt.gensalt()).decode()
```

| 实测项 | 结果 |
|---|---|
| bcrypt 版本 | **5.0.0** |
| `ERP_SECRET` 长度 | **64 字节** |
| bcrypt 输入上限 | **72 字节** |
| → 密码可用额度 | `72 − 64 =` **8 字节** |
| 密码第 9 字符起 | **直接抛 `ValueError: password cannot be longer than 72 bytes`**（不是静默截断） |

**生产影响（修复前）**：
- 🔴 **注册**：登录页写着「密码（至少 8 位）」，用户设 9 位以上 → `_hpw` 抛异常 → **注册失败**。这是**面向新用户的真实阻断**。
- 🔴 **改密**：`POST /api/auth/password` 校验 `≥8 位` 通过后调 `_hpw(new_pw)` → 同样抛错 → **改密功能根本不可能工作**。
- 旁证：微信提审账号密码恰好都是 8 位（`Mptest@1` / `Mpsup@1`）——不是巧合，是被这个上限逼出来的。

**修复方式**（`server/core.py`）：改为「先 SHA-256 预哈希再 base64（固定 44 字节 ASCII）」彻底解除长度限制，并用 `bcrypt2$` 前缀与旧格式区分：

```python
def _bcrypt2_pre(pw):
    return base64.b64encode(hashlib.sha256((pw + SECRET).encode()).digest()).decode()

def _hpw(pw):
    return "bcrypt2$" + bcrypt.hashpw(_bcrypt2_pre(pw).encode(), bcrypt.gensalt()).decode()
```

`_verify_password` 同时支持三种格式（`bcrypt2$` / 旧 `bcrypt$` / legacy SHA-256），`_needs_rehash` 改为「非 `bcrypt2$` 即需升级」——**复用既有的登录懒迁移机制**（`auth.py:119-122`），现有用户**登录一次即自动升级，密码与体验零变化**。
