## 一、字段来源与计算/映射规则

| 项 | 结论 |
|---|---|
| 物理字段 | `products.arrival_lead_days`（**物理列早已存在**，v109 迁移建列，`INTEGER DEFAULT 0`） |
| 语义 | 该单品**下单后第几天到货**的**提前天数**。`3` = 页面显示「+3天」 |
| 计算 | **不计算**，是商品档案上的一个属性值，直接读取并格式化 |
| 写入口 | **只有一处**：预报导入的「到货周期」列（文本 → 整数，见第三节解析规则） |
| 读出口 | 前端 `/api/products/grid` 逐字段白名单下发 → 主表该列渲染 |

### 🔴 三个「天数」必须分清（本轮专门核过，别混用）

| 字段 | 含义 | 默认 | 谁在用 |
|---|---|---|---|
| **`products.arrival_lead_days`** | **本列**：下单后第几天到货的提前天数 | 0 | 本列 + 导入「到货周期」列 |
| `products.lead_time_days` | 补货算法的**提前期** | **7** | 安全库存 / 补货点公式，**不面向报单用户** |
| `rebate_target_rules.order_cadence_days`、`forecast_audit.DEFAULT_ARRIVAL_CYCLE=2` | 品牌级「每隔几天到货一次」的**频率** | 2 | 返利/到货节奏（品牌维度，也是「到货周期」这四个字，但**语义不同**） |

三者是三个量。代码注释与本文都写明了区别，避免后续被当成一个东西改。

## 二、展示格式 · 默认值 · 为空时的处理

- **展示格式**：`+N天`，例如 `+3天` / `+4天`（与用户诉求逐字一致）。
- **为空（0 或空值）**：显示 **`—`**（全角破折号，与同表其他空值口径一致）。
- **默认值**：物理列默认 `0` ⇒ 显示「—」。**不做「继承品牌默认」**：
  那会让同一格有两个来源（档案值 vs 品牌默认），与「同屏数字口径必须同源」冲突。
  **要默认值就在导入时填**。
- **文案唯一实现**：`arrivalCycleText(v)`（`Forecast.vue`）。主表列与商品档案弹层**共用同一个函数**——
  两处各写一份格式化 = 第二份拷贝 = 静默漂移。

## 三、导入模版：列名 · 位置 · 校验规则

| 项 | 结论 |
|---|---|
| **列名** | `到货周期`（无 `*`、无 `☆`） |
| **位置** | **第 8 列**：紧接商品身份列（条码/名称/规格/单位/厂价/品牌/分销价）之后、**客户列之前** |
| **必填** | **选填**（用户明确要求；与实际行为一致：留空不影响该行导入/建档/下单） |
| **示例值** | `+3天`（**示例是用户唯一会照抄的东西**，必须与页面显示同一种写法） |

### 位置为什么在这里
它本身属于「这一行商品」的属性，**不属于任何客户**。放在客户列之后会被误读成某个客户的属性。

### 能写什么（解析规则，`import_router._re_rhythm`）

| 写法 | 认不认 | 说明 |
|---|---|---|
| `+3天` / `+4天` | ✅ | **页面与模版教的写法** |
| `＋3天`（全角加号） | ✅ | 中文输入法默认全角，必须认 |
| `+3到货` | ✅ | 老写法，兼容存量模版 |
| `+3天到货` | ✅ | |
| `+ 3 天`（含空格） | ✅ | |
| 留空 | ✅ | **= 不动档案里已有的值（不清零）** |
| `3天` / `+3` / `随便` | ❌ | 静默不动（不报错、不写入） |

**为什么不收裸数字**：该列是自由文本，`+3`/`3天` 这类容易被别的语义误判（如加单标记 `+1`、保质期「3 天」）。

### 留空 vs 填写（第二遍 `UPDATE` 的行为）
```sql
arrival_lead_days = CASE WHEN ?>0 THEN ? ELSE arrival_lead_days END
```
**留空 = 不改动；填了 = 覆盖该商品旧值。** 同一商品多行时填一次即可（值相同，重复填无害）。

## 四、固定列的位置与「滚动时保持固定」的行为

| 项 | 结论 | 真机实测 |
|---|---|---|
| **位置** | 左侧冻结区第 3 位：`序号` → `商品名称` → **`到货周期`** | 列头索引 = 2（紧跟商品名称）✓ |
| **冻结实现** | `position: sticky` + `left` = **「序号列宽 + 商品名称列宽」按实际列宽累加** | `left: 256px` = 46 + 210 ✓ |
| **横向滚动** | 表头与表体该列**屏幕位置不变** | 横滚 420px 后 `540px → 540px` ✓；对照的「品牌」列 `632px → 212px`（证明滚动真的发生了） |
| **表尾** | 表尾是**另一张 table**，同样 `sticky` 且 `left` 一致 | 表尾该列 `sticky / left:256px` ✓ |
| **不可隐藏/删除/拖拽** | `isLockedCol()` 统一守卫（列设置菜单、右键菜单共用同一份规则） | 三处入口均给出提示而非静默无反应 ✓ |
| **强制归位** | `visibleCols` 把固定列强制排到最左（按 `FROZEN_COLS` 次序） | — |

### 两个顺手修掉的既有缺陷
1. **冻结偏移原本是硬编码猜值**：`frozenShift(200)` 里的 `200` 是「商品名称宽」的猜测，而实际列宽 `COL_DEFAULTS.name = 210`
   ⇒ **只要用户没拖过列宽，第二个冻结列就恒偏 10px**；把名称拖宽后偏更多。
   已改为 `frozenLeftOf()` / `frozenRight()`，按 `colW()` 实际列宽累加（真机断言 `left` 精确等于 46+210）。
2. **冻结区必须连续**：偏移是按宽度累加的，固定列一旦被隐藏/错序/拖走，`left` 就会落到别的列头上（错位遮挡且**不报错**）
   ⇒ 已把「固定列必须构成左侧连续区」做成**渲染期不变式** + 禁止隐藏/拖拽。

## 五、确保「页面显示」与「导入解析」一致（本轮的实质缺陷修复）

🔴 **修前是一处静默失败**：旧正则只认 `+3到货`，而**页面与模版对用户说的都是「+3天」**——
用户照模版填「+3天」时正则**匹配不到** ⇒ 该格静默算 0、页面永远显示「—」，**而用户以为自己填对了**。

已把正则改为同时接受四种写法 + 全角加号：

```python
_re_rhythm = re.compile(r"[+＋]\s*(\d+)\s*(?:天到货|到货|天)")
```

并**统一三处口径**：页面列名 / 模版列名 / 填写说明，全都写「到货周期」与「+3天」。

### 🔴 还修了一处「只在部分行上不一致」的缺陷
页面的行底是「本期导入登记的商品 ∪ 有报单的商品」。其中**已停用/已删除但被本期引用**的行
（off-archive，真机上带「已停用」角标）**不经过 `/api/products/grid`**，只从汇总接口的
`imported_products` 来 —— 而那个查询**没有下发 `arrival_lead_days`**，
前端 `asProdRow()` 又是一份显式白名单 ⇒ **这些行恒显示「—」，而库里与导入结果明明是 +3天**。

**真机已复现并验证修复**（沙箱 `pid=1160`，已停用 + 本期登记，DB=3）：

| | 页面显示 |
|---|---|
| 修复前 | `—` ❌（与导入不一致） |
| 修复后 | `+3天` ✅ |

修法两行：`erp_db.py` 的 `imported_products` 查询补 `COALESCE(p.arrival_lead_days,0)`；
`asProdRow()` 白名单补该字段。**本期与历史期次两条加载路径（`loadCross` / `loadMatrix`）都补**，
避免「本期显示 +3天、往期全变「—」」的单侧漂移（真机已单独验历史期次 6/6）。

### 🔴 顺带修掉一个「假操作」
右键菜单的「清空此单元格」（`ctxClear`）是**绕过 `writeCellVal` 的第二条写路径**（直接 `rw[key]=''`）。
只读列若不拦，界面会立刻显示「—」，但网格保存的字段白名单里没有它 ⇒ **一刷新又变回来**。
「清了会自己回来」比「清不动」更糟（用户会以为系统在丢数据）。已加闸门：
提示「「到货周期」由预报导入的…列决定，不能手工清空」并且**不做**。

## 六、该列是只读列（不是假旋钮）

`edit: 'ro'`（只读）：

| 行为 | 结论 | 真机实测 |
|---|---|---|
| 编辑网格里的控件 | **没有 input**（有展示、没有写入口） | 该格 `input` 数 = 0；对照同排有 33 个 input ✓ |
| 表尾合计 | **不进合计**（合计只累 `edit:'num'` 列） | 该列表尾格为空串；对照数量列表尾是数字 ✓ |
| 粘贴 / 拖拽填充 / 清除选区 | `writeCellVal` 里拦截（返回 `false`） | — |
| 清除选区的报数 | 按**实际写入成功**的格数报数（原按选区面积 ⇒ 会虚报） | — |
| 右键「清空」 | 明确拒绝并说明该去哪改 | toast 文本正确、值未变；对照可写格被真的清空 ✓ |

**为什么不做成可编辑**：本列唯一写入口是「预报导入」，后端网格保存的字段白名单里**没有** `arrival_lead_days`。
在网格里摆一个输入框就是**假旋钮**（用户改了、保存后静默回旧值、且不报错）。
