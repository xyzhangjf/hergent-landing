## 〇、判定标准

| 级别 | 判据 | 算不算「已实现」 |
|---|---|---|
| L1 | 名字里有这个词 | ❌ |
| L2 | 有文件 / 函数 / 表定义 | ❌（可能从未被调用） |
| L3 | 有调用方，路径可达 | ⚠️ 勉强 |
| L4 | **运行态可证**：进程在跑 / 表里有行 / cron 有排期 / 配置已生效 | ✅ |

**为什么定这么严**：本轮 24 项实测里，**6 项 L2/L3 达标但 L4 不成立**（承诺台账、主动推送、上传三项、收款流水、产品档位）。它们**零报错、界面无异常** —— 判断错了没人提醒你。

## 一、总体结论

BP 骨架**经得起复算**：24 项实测，**16 项运行态对得上**，包括最硬的两条 —— 返利口径唯一实现的断言数**正好 51 条**、AI 工具**零处写操作**。

但**实现侧的缺口集中在一条链上**：

```
BP 承诺的路径                     当前实现状态
────────────────────────────────────────────────
客户上传 Excel ─────────► ⚠️ 4 项承诺只通电 1 项
      ↓
算清楚（返利/货损/工资）──► ✅ 已通电，但配方库 0 行燃料
      ↓
说出来（主动推送经营卡片）─► 🔴 卡片能渲染，主动 = 0 条
      ↓
钱收回来（收款流水/账龄）──► 🔴 0 行，表都不存在
```

**一句话**：系统**能算、能说**，但**进门那一段（上传）和收钱那一段（收款）是断的**，而这两段正好是「客户每周会不会用」和「老板会不会付钱」的两个端点。

## 二、差距逐条清单

> 每项给四件事：**BP 怎么说的** → **现在什么表现（带证据）** → **影响程度** → **优先级**

### 轴 A · 产品功能

#### G1 · Excel 上传主路径：4 项承诺只落了 1 项 🔴 **P0**

- **BP 说**：第一层主路径「**现在，做到极致顺畅**：模板识别、字段映射记忆、增量导入、导入回执可撤销」
- **实测**：
  | 子项 | 状态 | 证据 |
  |---|---|---|
  | 模板识别 | ✅ | `excel_recognizer.py` 193 行，认银行/支付流水列名模式 |
  | 字段映射记忆 | ❌ | `ImportMapping.vue` 改完只在 `emit` 里活着，**不落库**，每次重认 |
  | 增量导入 | ❌ | `import_router.py`（2,460 行）里「增量 / incremental」**0 命中** |
  | 回执可撤销 | ❌ | 同上「撤销 / undo / rollback」**0 命中**（现有的是事务原子性 = 要么全成要么全败，**不是**事后撤销一次已完成导入） |
- **影响**：🔴 **高，且位置决定严重性**。BP 明写第三层连接器「等有真实客户时按客户 ERP 做」⇒ **在拿到真实客户之前，上传是唯一的门**。而验证期第 4 问的通过判据是「观察 3 家客户每周至少一次主动上传」—— 如果客户每周都要重做一遍映射、导错了还不能撤，这个判据很可能**不是被产品价值打败，而是被体验打败**，从而得出错误的否定结论。
- **优先级**：**P0**（至少做掉「映射记忆」+「可撤销」；增量可放后）

#### G2 · 收款流水：代码有、数据 0、表不存在 🔴 **P0**

- **BP 说**：第一阶段「打通『收款流水』与『库存批次』两条数据入口」，并自述这是「资金类与判断类能力的地基」
- **实测**（生产库只读）：
  | 表 | 行数 | 判断 |
  |---|---|---|
  | `payment_imports` | **表不存在** | 代码有，从未用过 |
  | `receivables`（应收） | 181 | 全是期初建账 |
  | `collection_followups`（催收跟进） | 181 | **有** ⇒ 催是真需求 |
  | `cash_flow` / `bank_accounts` | 16 / 4 | 零散 + 账户定义，非流水 |
- **影响**：🔴 **高**。路由其实齐了（`routers/` 下有 `payment_import.py` / `payment_run.py` / `collections.py`），**缺的是副驾端入口 + 真实数据**。`collection_followups` 有 181 行而收款 0 行 ⇒ 缺的不是「提醒他该收多少」，是「**他到底收回来了多少**」。顺序颠倒会「上线即误导」：账龄算不出、催收话术基于错的余额。
- **优先级**：**P0**

#### G3 · AI 输出可追溯：只有提示词约束，无代码级校验 🔴 **P0**

- **BP 说**：「给副驾问答加硬校验：数字必须指得出数据来源与口径」
- **实测**：`SOUL.md` 写着「不确定就明说、标注来源」，但**无代码级溯源**。`ai_advice_log` 记的是**问答内容**，不是「这个数来自哪张表哪几行」。BP 自己已披露「光有提示词约束不住数字」。
- **影响**：🔴 **高**。这是「AI 副驾」与「聊天机器人」的分界线，也是老板敢不敢照着数字做决策的前提。
- **优先级**：**P0**

#### G4 · 承诺台账：代码 0 命中 🔴 **P0**

- **BP 说**：「口头承诺…通用 ERP 永远不会碰它 —— 这是我们第一阶段就要碰的第三件事」
- **实测**：全库 `grep -rie "commitment | 口头承诺 | 承诺台账 | vendor_promise"` **0 命中**（含前端）
- **影响**：🔴 **高**。这是护城河第三层（最难被抄、最能留客），目前**尚未动工**。BP 时态已修正为「要碰」，叙述诚实，但能力空白。
- **优先级**：**P0**

#### G5 · 配方库：机制在，燃料 0，且无产品化入口 🔴 **P0**（机制）／**P1**（入口）

- **影响**：🔴 **高**（护城河第二层的**生长机制**）。代码写完了但没通电 —— 客户问一次能不能沉淀成口径，全靠人工。
- **优先级**：**P0**（接入口）／**P1**（跑通一轮闭环）

#### G6 · 主动推送的经营卡片：卡片有了，主动 = 0 🟠 **P1**

## 三、分阶段开发与优化计划

> **总原则**：每一阶段的产出，都必须能回答验证期四个问题中的至少一个；回答不了的不做。
> 四问：**① 谁付钱 ② 口径能不能复用 ③ 交付成本多少 ④ 数据进得来吗**

### 第 1 阶段 · 把进门和收钱两段接通（验证期第 1–6 周）

**目标**：让**上传**这条唯一入口配得上「极致顺畅」，让**收款**这条地基第一次有数据，让 AI 的每个数字**能被追到来源**，并让护城河第三层**从 0 到 1**。

| # | 任务 | 关键改动点（file-level） | 预期成果 | 验收判据（可检验） | 回答哪一问 |
|---|---|---|---|---|---|

## 六、本轮方法留痕

**差点误判两条，一条排除、一条自己错了（实现期复核抓出）**：初查发现 `pages/` 下 28 个文件、路由只挂 21 个，一度想写成「7 个页面写了但进不去」。逐个追引用后发现 4 个是**页签子组件**（挂 `Forecast.vue` 的 tab 与 `Settings.vue:163`）。
⇒ **「文件没挂路由」不等于「功能没实现」；先看它是不是被当子组件 import 了。**
🔴 但同一段推理里我又多走了一步、且**走反了**：写成「另外 3 个被通用 `Archive.vue` **取代**」。实现期复核（`Archive.vue:12-16 / :24-28`）显示它**引用**这三个当页签内容 —— 方向完全相反。若照此执行删除，会静默删掉档案页三个页签。
⇒ **「A 里有 B 的名字」有两种相反含义：`A 取代 B` vs `A 承载 B`。判据只能是「谁 import 谁」，不能是「名字出现在同一屏」。**
⇒ 教训：**结论里出现「取代 / 已废弃」这类方向性词时，必须回到 import 语句确认方向**，否则会把「容器」读成「替代品」。

**上一条沿用、本轮再次生效的纪律**：**计数不等于在用。** `cron_tasks` 有 3 行，看起来「定时任务在用」；逐行读内容才发现三条都是同一条 AI 新闻推送。凡是以「表里有 N 行」当证据的，**必须至少读一行内容**。

**能力判定要看「有几个入口」**：对账引擎 G7 不是缺能力，是**两个入口只通电了一个**。这类问题的修法往往只是配置同步，但如果不逐份比配置（`/root/.hermes/config.yaml:12` vs `/opt/hermes-tenants/hergent_t1/config.yaml:5`）、只比代码，会完全看不出来。
