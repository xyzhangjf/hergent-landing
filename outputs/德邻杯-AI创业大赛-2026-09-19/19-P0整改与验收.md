### P0-2 「数据依据」由「藏起来」改为「常显」

**改前**：后端 `/api/forecast/audit-period` **总是**返回销量新鲜度读数（`max_date` / `days_stale` /
`window_start` / `window_end` / `level`），但前端只在**不新鲜**（`level !== 'fresh'`）时才渲染 ——
结果：**数据新鲜时反而看不到依据**。

**改后**（`auditStale` → `auditFresh`）：

```js
// 新鲜与否只决定**配色**，不决定**是否显示**
const auditFresh = computed(() => {
  const f = auditData.value && auditData.value.sales_freshness
  return (f && f.level) ? f : null
})
const auditFreshAgo = computed(() => {
  const d = auditFresh.value && auditFresh.value.days_stale
  if (d == null) return ''
  return d > 0 ? `${d} 天前` : '今日'        // 0 天不写「0 天前」
})
```

| 档位 | 文案 | 配色 |
|---|---|---|
| `fresh` | 本建议依据的销量数据最新到 **9 月 25 日（2 天前）**，统计窗口 … 至 … | 中性色（`.audit-fresh-ok`，青色左竖条） |
| `notice` | 销量数据 N 天未更新（最新 …）—— 距上次销量更新已有 N 天… | 警示色（`.warn-text`） |
| `stale` | 销量数据已停更 N 天（最新 …）—— 统计窗口是 … 至 …（按数据最新日期回推…） | 警示色 + 详细说明 |

**关键设计约束（没有破）**：读数仍来自后端**同一份** `_sales_freshness`，前端**不重算**
（避免"同一事实两份实现"）。

## 三、🔴 为什么这一轮**不部署**

**部署前基线检查结果：红灯。**

```
$ git status --short -- hergent-cn-v2/src/
 M src/pages/Forecast.vue        ← 我的（本轮约 10 处）
 M src/pages/Rebate.vue          ← 并行会话
 M src/pages/Workbench.vue       ← 并行会话
 M src/components/Shell.vue      ← 并行会话
 ...共 25 个 M + 1 个 D + 5 个 ??（新文件）
```

其中 **`Forecast.vue` 一个文件就有 570 插入 / 61 删除**，远超本轮改动量 ——
说明**另一个会话正在同一个文件上工作，且有大量未上线的在途改动**。

**按纪律：隔离构建的前提是「线上 == HEAD」。这个前提不成立。**

如果此时上传我构建的 `dist`，会有两个方向的坏结果，任选其一：

- 若那些在途改动**已上线** → 我的构建会**把它们回退**
- 若那些在途改动**尚未上线** → 我的构建会**把别人没做完的半成品带上生产**

**两种都不能接受。所以本轮停在这里：源码已改好、构建已验证、产物已存档，等基线干净后一次性上线。**

> 已把本次构建产物另存 `/tmp/hergent-dist-p0-dirty-20260927-2143/`（仅作证据，**未上传**）；
> 并把被我临时移出的既有 `dist/`（53 个产物）**原样恢复**。

## 四、上线时要做什么（三步）

1. **确认基线**：`git status --short -- hergent-cn-v2/src/` —— 只应剩**已确认要上线**的改动；
   或与并行会话对齐后，共同构建一次
2. **构建 + 上传**：`npm run build` → rsync 到 `/opt/hergent-cn-v2/`（**绝不 `--delete`**）
3. **生产验证**（三条，缺一不可）：
   - `curl -s https://hergent.cn/ | grep -o 'index-[^"]*\.js'` 拿到入口 chunk
   - 该 chunk + `Forecast-*.js` 里 `grep -c "AI智能建议"` = **0**、`grep -c "补货建议"` ≥ 1
   - **真机打开预报页 → 点「补货建议」→ 截图**：确认审核窗顶部出现
     「本建议依据的销量数据最新到 YYYY-MM-DD（N 天前）」
