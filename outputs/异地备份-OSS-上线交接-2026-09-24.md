**② 建一个 AccessKey（RAM 子用户，最小权限）** ✅ **已完成（2026-09-24 22:05）**
> **根因确认**：卡点就是**第 5 步「新增授权」当时还没挂上**。补授 `hergent-backup-oss-rw` 后**立即全通**（列桶 / 上传探针 / 复读对象 三项均 OK）。
> **更正记录**：早先把该报错判为"AK 与桶**跨账号**"是**错误推断**——用 ECS 的 `owner-account-id`（1080003991103151）去比对桶账号**不成立**：备份靠 **AK 认证**，与 ECS 属于哪个阿里云账号无关；且 `does not belong to you` 这句文案在**同账号未授权**时同样出现（阿里云官方对 `Ec=0003-00000001` 的定义就是"没有相应操作权限"，首条示例即"RAM 用户未被授权"）。
1. 控制台顶部搜索 **`RAM 访问控制`** → 进入
2. 左侧「权限管理 → 权限策略」→ 右上「**创建权限策略**」→ 选「**脚本编辑**」→ 粘贴下面**这一整行** → 名称填 `hergent-backup-oss-rw` → 确定
   ```
   {"Version":"1","Statement":[{"Effect":"Allow","Action":"oss:*","Resource":["acs:oss:*:*:hergent-backup","acs:oss:*:*:hergent-backup/*"]}]}
   ```
   （该策略作用域**锁死在 `hergent-backup` 这一个桶**，不影响你账号下其它 OSS 资源）
   🔴 **必须是这一行**：上一版交接单里给的是**多行缩进版**，从渲染图复制会把缩进变成**不可见的不间断空格 U+00A0** ⇒ 控制台报 `JSON syntax error 策略内容语法错误`，而内容肉眼看完全正常。单行版无缩进 = 无污染面。
   备用粘贴源：`outputs/oss-ram-policy-ONELINE.txt`（纯 ASCII、138 字符、已用 `json.loads` 校验通过，全选复制即可）。
3. 左侧「身份管理 → 用户」→ 右上「**创建用户**」
   - 登录名称：`hergent-oss-backup`
   - 访问方式：**只勾**「**使用永久 AccessKey 访问**」
   - ❌ **不要**勾「控制台访问」（备份脚本不需要登录控制台）
4. 创建成功后页面会显示 **AccessKey ID / AccessKey Secret** → **立刻复制保存**（Secret **只显示这一次**，关掉就再也看不到，只能重建）
5. 回到该用户 → 「权限管理」→「**新增授权**」→ 选刚建的 `hergent-backup-oss-rw` → 确定

## 五、P2 备份存活告警（✅ 已完成 2026-09-24 22:16）

**要解决的问题**：2026-08-22 ~ 09-22 备份静默失败整整一个月——因为**「没有消息」和「一切正常」长得一模一样**。这是整件事里最贵的教训。

**做法**：`/opt/hergent-erp/scripts/check_backup_alive.py`，每天 **03:20** 巡检（备份 02:00 + 1h20m 余量，且与 03:00 的 hermes 检查错开），异常即推**企微**。

| 检查项 | 判据 |
|---|---|
| A 本地备份目录 | `backups/<今天>/` 存在 |
| B 文件数对齐 | ≥ `DB_DIR` 内**非空** `*.db` 数 —— **动态算，不硬编码**（实测历史上 9-06 是 11 个库、9-23 起是 8 个，写死必误报） |
| C 坏文件/体积 | 备份目录内无 0 字节文件；总体积 ≥ 源库 50%（防"文件在但被截断"） |
| D 异地副本 | `/var/log/hergent-oss-sync.log` 里有今日的 `OSS sync OK` |

**复用既有通道，零新增密钥**：走 `hermes send --to wecom`（与 `holiday_sync.py` / `llm_health_monitor.py` 同一范式，复用租户 home 已授权凭证出站），判据取 stdout JSON 的 `success`——**CLI 退出码不可信（Hermes 恒 exit 0）**。
**防刷屏**：同日只推一次（`var/backup-check/<date>.alerted`）；`--force` 可强制复推。
