# 规则「生效期」与「返利周期截止 / 剩余到货次数」口径排查

- 日期：2026-09-27
- 范围：`hergent-cn-v2`（前端）+ `hergent-erp`（后端），只读排查，**未改任何代码与数据**
- 触发：用户报「目标填 10 月、生效截止填 09-30，会不会挡掉 10 月？」以及「生效截止改成 12-31 后，预报页返利冲刺面板的返利周期截止也跟着变 12-31，剩余到货次数随之改变」

> ⚠️ 本报告遵循跨租户脱敏红线：不含金额、费率、客户名。

---

## 一、结论摘要（三句话）

1. **生效截止时间对「目标是否适用」几乎没有约束力** —— 只要规则带月度分解，适用月份就是分解本身，`effective_start/end` **根本不参与判断**。所以你填 10 月目标 + 截止 09-30，**10 月的目标、达成、返利、排行、图表全部正常**。
2. **但它在返利冲刺面板里被过度使用** —— 面板把它当成「返利活动截止日」，取**全部活跃规则**的**字符串最大值**。于是你改任一规则的截止日，整个面板的「返利周期截止 / 剩余到货次数 / 均单建议」都会跟着动。
3. **按月计算的逻辑没有被覆盖，而是被"旁路"了** —— 面板里"时间进度"按月算（正确），"返利周期截止"按跨年全局算（错误），**同一块面板内两套时间尺度**。

## 三、缺陷定位：唯一被污染的消费点

**文件**：`hergent-cn-v2/src/pages/Forecast.vue:9209-9216`

```js
// 返利活动/合同截止日：取当前冲刺所纳入规则的生效期末日最大值
const rebateCampaignEnd = computed(() => {
  const rules = (rebateRules.value || []).filter(x => x.is_active !== 0 && x.effective_end)
  if (rules.length) {
    return rules.map(r => String(r.effective_end)).sort().slice(-1)[0]   // ← 全局字符串 max
  }
  const p = cross.value.period
  return p && p.order_end ? p.order_end : null
})
```

**两个问题**：

1. **候选集合错**：取的是**全部活跃规则**的 `effective_end`，既**不按本月适用性过滤**（没过 `ruleCoversMonth`），也**不按品牌过滤**。别的品牌、别的月份的生效期会污染当前视图。
2. **语义错**：它根本不是「本月返利周期的截止日」。

**三处消费点全吃这个值**：

| 位置 | 用途 |
|---|---|
| `Forecast.vue:9219` | `rebateSprintOrders` —— 表头概览「约剩 N 次到货机会」 |
| `Forecast.vue:9277` | `daysLeft` —— 各品牌行按 `daysLeft / 各自周期` 算剩余次数 |
| `Forecast.vue:9329 / 9346` | `countWeekdayArrivalsInWindow(wds, endStr)` —— 按固定星期模式时也用它 |
| `Forecast.vue:486` | 文案「本期（返利周期截止 X）…约剩 N 次到货机会」 |

## 四、生产实测（只读复算，tenant_1）

条件：今天 2026-09-27；3 条活跃规则的 `effective_end` 均为 `2026-09-30`；冲刺月 = 最新期次（id 19）的**到货月** = **2026-10**。

## 五、对你两个问题的直接回答

### 问题 1：10 月目标 + 生效截止 09-30，会影响 10 月后续操作吗？

**不影响目标与返利计算**，但**会误导冲刺面板的「剩余到货次数 / 均单建议」**。

- 目标 / 达成 / 返利 / 计提 / 判重 / 图表：✅ 全部正常（生效期不参与）
- 冲刺面板的返利周期截止：❌ 会被这条规则的 09-30 拉低（若它是最大的那个），使剩余次数**偏少**、均单建议**被放大**

⚠️ **一个需要纠正的预期**：你以为「截止 09-30 = 只到 9 月」——**这个字段做不到**。对带月度分解的规则，想停用只能改「启用」开关（`is_active`），生效期对目标计算是**空开关**。

### 问题 2：返利周期截止应该按月最后一天吗？

**你的判断是对的。** 证据链：
- 冲刺看板算的是**月度**达成率与缺口（`sprintAchvMonth` = 到货月）
- 同屏的「本月时间进度」(`Forecast.vue:9369`) 就是**按月**算的
- 达成的存储桶（`rebate_achievements.period_month`）在 v173 已收口为**唯一月度键**
- ⇒ 唯独「返利周期截止」用了跨年全局尺度，**是本面板唯一的口径不一致点**

**按月计算逻辑没有被覆盖**，它是被**旁路**了：面板有两套时间尺度并存。

## 六、优化建议

### P0（必修）—— 把截止日改为「冲刺月月末」，与面板其余时间格同源

```js
// Forecast.vue 替换 rebateCampaignEnd
const rebateCampaignEnd = computed(() => {
  // 返利按月结算 ⇒ 周期截止 = 冲刺月（到货月）的最后一天
  const [y, m] = String(sprintAchvMonth.value || '').split('-').map(Number)
  if (!y || !m) return null
  const last = new Date(y, m, 0).getDate()      // 下月第 0 天 = 本月最后一天
  return `${y}-${String(m).padStart(2, '0')}-${String(last).padStart(2, '0')}`
})
```

- 收益：#1 的 2 次 → 18 次（正确）；不再受任何单条规则生效期影响
- 同源：# 与 `sprintAchvMonth`、`sprintTimeProgress`、达成桶**全部同为月尺度**

### P0（必修）—— 边界：窗口已关闭时不要假装还有 1 次

当前 `if (daysLeft <= 0) return 1`（`:9224` 与 `:9334` 两处）是**硬兜底**。补报历史月份时会显示"还剩 1 次到货机会"，而事实是窗口早关了。

- 原则：兜底只能用于**无法判断**（`null`），不能用于**已知为 0**
- 做法：`sprintOrders = 0`，文案改为「本期到货窗口已结束」

### P1 —— 统一「剩余到货次数」的配置来源

`arrival_count_override`（表单里的「本月到货次数」，按品牌配置）在 `Forecast.vue` 里**出现 0 次**。也就是说：你在「到货节奏」里配的数字，与面板显示的"剩余次数"**毫无关系**（面板只按 `剩余天数 ÷ 到货周期` 算）。

三个选择：
- A. 面板优先读 `arrival_count_override`（配了就按配的算，没配才按天数推）—— **更贴合你的心理模型**
- B. 让表单明确写「此项仅用于自动生成报单期次，不参与冲刺看板」
- C. 干脆从表单移除，避免误读

建议 **A**。

### P2 —— 修正「生效结束」这个字段的措辞

既然它对目标计算无约束力，标签应改为**「规则启用到」**，并在旁边加一句说明：
> 仅表示这条规则的启用窗口；月度目标与返利一律按月计算，不受此日期裁剪。

避免下次再有人以为"截止 09-30 就停用了 10 月"。

### P2 —— 后端补一处残留

`routers/rebate_rules.py:1984` 的兼容版试算仍按**日粒度**比生效期（主契约 `:2016` 已清空）。前端只走传 `rule_id` 的新契约，所以目前不影响页面；但**外部脚本 / 旧前端**走旧契约时会出现「10 月试算恒 0」。建议一并改为委托 `rule_covers_date`。

## 七、本次排查的验证方法与两个坑

**方法**：生产库**只读**（`mode=ro`）探针，**真调后端 domain 实现**（`covered_months` / `rule_covers_month`），按前端表达式**逐字复算**三种口径并排对照。未写任何数据。

**坑 1｜`sqlite3.Row` 不是 `dict`**：直接把查询行传给 `covered_months()` 时，该函数首行 `if not isinstance(r, dict): return set()` 会**静默返回空集**，`rule_covers_month` 全 `False` —— 一度看起来像"系统对所有规则都不生效"。**必须先 `dict(row)`**。

**坑 2｜结果缺键 ≠ 字段为空**：同族问题（同日早先排查小程序时也踩过）—— `.get("x")` 得到 `None` 时，可能是"查询根本没取这一列"，而不是"值确实为空"。**下结论前先确认该键在 SELECT 里存在**。
