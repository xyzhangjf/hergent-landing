## 五、审计器升级：为什么必须分「两段」

```
🔴 违规段（零假红，命中即必须清）  = BAD 枚举串 ＋ SELFREF（复述表头 / 复述表格结构）
🟡 提示段（有语境，必须人工判）    = 元素名复述（引号里是「同一屏的按钮名」＋ 动作句）
```

🔴 **不合并的理由（本轮实测）**：这条判据与**合法的空态引导**字面无法区分 ——

```
违规：点某个角色的「配置权限」，进入它自己的权限配置页      ← 按钮就在旁边 ⇒ 零增量
合法：还没有渠道。点右上角「新建渠道」开始。                ← 空态 ⇒ 有增量，UX 标准做法
```

两者都形如「点「X」…」，区别只在**用户此刻看不看得到那个 X** ⇒ **正则判不了**。
硬并入会产生 **40+ 处假红**，而**假红会让所有人学会忽略这个脚本**（v326 立此脚本时的原话）。

### ⚠️ 第一版判据我自己写错了（值得记）

我先用正则 `(点|点击)…(进入|切到|跳转)`，一次抓出 7 处。但其中：

- `点柱子可切到该月详情` ← **有用的交互提示**（用户不知道柱子可点）
- `（可点击跳转）` ← 同上

⇒ **假红**。改用**跨引用比对**才精确：句子引号里的元素名，**是否等于同一屏里某个按钮/标签的文本**。
在 ⇒ 用户眼皮底下 ⇒ 违规；不在 ⇒ 是跨屏指路 ⇒ 放行。
