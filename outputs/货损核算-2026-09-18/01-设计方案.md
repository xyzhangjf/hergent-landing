# 货损核算 · 页面与仪表盘设计方案（2026-09-18）

> 对象：`hergent.cn` → 侧栏「货损核算」(`/loss-accounting`，`LossAccounting.vue` + `routers/loss_accounting.py`)
> 定位：**月度 · 期间流水口径** —— 「这个月实际损了多少、率是多少」
> 与之区分的另一模块：`/loss` 货损计算（配方驱动的**批次效期预测**，「我的货里有多少快坏了」）
> ⚠️ 本方案**不新增任何数据表、不新造字段** —— 字段一律取自后端既有 DDL 与 `LOSS_COL_DEFS`。

---

## 一、现状基线（动笔前已核实，2026-09-18）

### 1.1 已实现（生产可用）

| 能力 | 实现 | 位置 |
|---|---|---|
| 期次（月份） | `period` = `YYYY-MM`，取自 `loss_manual_inputs` ∪ 已结账 ∪ 当前月 | `_periods()` L734 |
| 手工填报 | `PUT /manual`，幂等键 `(period, subject_kind, subject_key, col_key)` | `loss_manual_inputs` |
| 主体维护 | `PUT/DELETE /subjects`（门店 / 业务员；③④为单行组无需主体） | `loss_subjects` |
| 实时重算 | `_compute()` 每期实时算出「主体行 → 分组小计 → 公司行 → 表尾校验」 | L565 |
| 结账 / 反结账 | `POST /close` / `/reopen` | `loss_period_closed`（`_closed_map`） |
| 叫法映射 | `PUT /roles` + `loss_role_aliases`（舟谱部门/仓库名 → 系统主体） | L1134 |
| 溯源 | `GET /detail`（哪只手、什么时候填的、改过几次） | `entity_change_logs` |
| 数据体检 | `GET /health`（缺分母 / 报损未录 / 净额为负） | `data_quality` |

### 1.2 已建表但**只建不写**（导入阶段预留，见 L320 注释）

`loss_monthly`（按月物化）· `loss_daily`（日快照）· `loss_events`（流水明细）· `loss_import_batch`（批次登记）
—— 表结构已到位，**落地导入时无需再改 DDL**。

### 1.3 缺口（本方案要解决的）

1. **没有跨期端点** ⇒ 无法画「按月的趋势」（现有端点全是单期）。
2. **页面没有月列表** ⇒ 只能一期一期切下拉框看，看不到「哪个月不正常」。
3. **没有任何图表** ⇒ 趋势/构成/排行全靠读表格。
4. `import_ready: False` ⇒ 导入层未落地（本方案只做「入口与落点设计」，不含实现）。

## 二、数据字段（全部为既有字段，附来源）

### 2.1 维度键（决定"这一行是谁的"）

| 字段 | 类型 | 说明 | 来源表 |
|---|---|---|---|
| `period` | TEXT `YYYY-MM` | **一级维度 = 月份**，一切按月存储与查询的键 | `loss_manual_inputs.period` |
| `subject_kind` | TEXT | `store` / `operator` / `direct` / `wastage` / `company` | 同上 |
| `subject_key` | TEXT | 主体键（③④公司行用哨兵 `_SINGLE`） | 同上 |
| `subject_label` / `note` | TEXT | 显示名 / 备注 | `loss_subjects` |
| `is_active` / `sort_no` | INT | 停用主体仍参与历史期次，只是新期次不再出现 | `loss_subjects` |

### 2.2 可录入金额（9 列，`LOSS_COL_DEFS` 中 `editable: True`）

| 列键 | 中文 | 归属 | 单位（存 → 显） |
|---|---|---|---|
| `store_sales_amt` | 本期销售额 | ① 门店行的**分母** | 元 → 万元 |
| `store_return_amt` | 退货额 | ① 分子主项 | 元 → 万元 |
| `op_from_good_amt` | 良品仓发货额 | ② 业务员行的**分母** | 元 → 万元 |
| `op_to_loss_amt` | 调至临期仓额 | ② 分子主项 | 元 → 万元 |
| `op_loss_sale_amt` | 临期销售 | ② 抵扣项（业务员**自售**） | 元 → 万元 |
| `direct_amt` | 直调临期仓额 | ③ 单行组分子 | 元 → 万元 |
| `direct_loss_sale_amt` | 临期销售 | ③ 抵扣项（直调后在临期仓卖出的） | 元 → 万元 |
| `wastage_amt` | 报损额 | ④ 单行组分子 | 元 → 万元 |
| `company_sales_amt` | 公司销售金额 | 公司行**分母** | 元 → 万元 |
| `loss_wh_sale_amt` | 临期仓销售总额 | 公司行抵扣（含自售**+其他渠道**） | 元 → 万元 |

> 🔴 **③④ 没有分母 ⇒ 不给率**。这不是缺字段，是有意：`direct`/`wastage` 两组强行算率就是「凭空造出来的分母」。

### 2.3 派生列（5 列，`editable: False`，前端**不得渲染输入框**）

`gross_amt`（毛额）· `net_amt`（净额 = 毛额 − 抵扣）· `rate_gross`（毛率）· `rate_net`（净率）· `loss_wh_sale_other_amt`（临期仓其他渠道 = 总额 − 各业务员自售之和）

> 🔴 后端注释原文：「False = 只读列（前端不得渲染输入框，否则又是一个**假旋钮**）」。

### 2.4 口径 / 配置 / 质量

| 字段 | 位置 | 用途（也是仪表盘的筛选维度） |
|---|---|---|
| `pricing` | `loss_config['pricing']` = `cost` \| `sale` | **计价口径**：成本价（进货价）/ 售价。切换会让**所有金额**变 |
| `data_quality` | `_compute` 输出 `JSON[]` | 每行的不可信原因（缺分母 / 报损未录 / 净额为负） |
| `is_closed` / `closed_at` / `closed_by` | `_closed_map` | 结账态 = 该月数字**已冻结**，是趋势图的"可信度"标记 |
| `updated_at` | 每表 | 「数据截至」时点 |

### 2.5 导入阶段将启用的字段（表已建好，此处只登记设计）

| 表 | 关键字段 | 用途 |
|---|---|---|
| `loss_import_batch` | `period, kind, file_name, file_md5, declared_from, declared_to, row_total, row_ok, row_rejected, reject_detail, imported_by/at, revoked_*` | **幂等键 = `(period, kind, file_md5)`**：同文件重传报「已导入」；整批可撤销 |
| `loss_events` | `event_date, kind, event_subtype, doc_no, src/dst_wh_*, subject_*, barcode, product_*, qty, unit_price, pricing, amount, amount_source, batch_id, row_seq` | 流水级明细（可钻到单据/商品） |
| `loss_monthly` | 2.2 全部金额 + `rate_num, rate_num_gross, rate_den, loss_rate, loss_rate_gross` + `data_quality, computed_at, is_closed, closed_at/by` | **按月物化快照**（建议：仅结账时写，见 §4.4） |
| `loss_daily` | `period, snap_date, row_kind, subject_key, rate_num, rate_den, loss_rate, computed_at` | **日快照**（驱动"月内日走势"） |

## 三、录入方式（三路并存，页面要能同时容纳）

### 3.1 手工填报（已实现，第一优先）

- **流程**：点「手工录入」→ 可填格变输入框 → 填数 → 「保存并重算」→ 派生列由服务端重算 → 退出录入态。
- **主体行前置**：①门店 / ②业务员 需先有主体（录入态下 `+ 添加门店 / 业务员`）；③④ 是单行组，直接填。
- **写路径有闸**：零改动时「保存」按钮 `disabled`；毛额/净额/率不接受手工填写（工具条原文：「毛额 / 净额 / 货损率由系统在保存后重算」）。
- **幂等**：`(period, subject_kind, subject_key, col_key)` UPSERT，重复保存不产生重复行。
- **留痕**：每次写入落 `entity_change_logs`（`loss_manual_input`），`GET /detail` 可逐行溯源。

### 3.2 Excel 导入（预留，`import_ready: False`）

- **两阶段**：`POST /import/preview`（只解析+校验+列映射确认，不落库）→ 用户确认 → `POST /import/execute`。
- **落点**：`loss_events`（流水级）+ 回填 `loss_monthly`；批次登记 `loss_import_batch`。
- **幂等**：`(period, kind, file_md5)`；重传同文件 → 明确提示「该文件本期已导入」，不静默覆盖。
- **可撤销**：`revoked_at / revoked_by`，整批撤销（不是逐行删）。
- 🔴 **导入能填什么，设计上要划死**：
  - 可以导入 —— ①门店退货、②业务员仓调拨（舟谱有流水）
  - **永远手工** —— ③良品仓直调临期仓、④报损（**舟谱没有这两类数据**，硬导只会造假数）
  - 公司行的两个分母（`company_sales_amt` / `loss_wh_sale_amt`）也走手工或「从流水汇总后人工确认」
- **叫法映射先于导入**：舟谱的部门/仓库名先经 `loss_role_aliases` 归位；未命中的名字进「待确认」清单，**不许静默丢弃**。

### 3.3 口径与状态维护

- 计价口径切换（成本价 / 售价）→ 全站金额随之变；`PUT /config`。
- 结账（`POST /close`）→ 该月冻结，趋势图标记为「已结账（可信）」；录错可反结账（`POST /reopen`，会留痕）。
- 数据体检（`GET /health`）→ 列出缺分母/报损未录的行。

## 四、展示结构（按月存储与管理）

### 4.1 页面四段式

```
① 期次与口径条   月份选择 · 结账状态 · 数据截至 · 计价口径 · 工具栏七键
② 【新增】月列表   12 个月横向/纵向一览：净额 · 净率 · 环比 · 结账态 · 完整度 · 操作
③ 【新增】仪表盘   指标卡 + 柱状图 + 副图（见 §五）
④ 单月详情表      现有 4 组结构不变（①门店 ②业务员 ③直调 ④报损 + 公司行 + 表尾校验）
```

**为什么加②月列表**：现有一期一选的交互，看不到「哪个月不正常」。月列表把 12 个月压成一眼，异常月（净率高、未结账、缺分母）高亮，点击即切换到该月详情。

### 4.2 月列表列设计

| 列 | 内容 | 视觉规则 |
|---|---|---|
| 月份 | `2026-09` + 是否当前月 | 当前月带「本月」标 |
| 货损净额 | 万元 | 正数红、负数绿（负数=抵扣超过损失，是好事） |
| 货损净率 | % | 无分母显「—」，**不显 0.00%** |
| 环比 | 金额用 **%**、率用**百分点** | 🔴 两者单位不可互换 |
| 结账态 | 已结账 / 未结账 | 未结账=灰标；已结账=绿标 |
| 完整度 | 缺 N 项 | 有缺口=琥珀标，鼠标悬停列出缺什么 |
| 操作 | 查看 / 结账 / 重算 | 与主表同源动作 |

### 4.3 三种"没有数"要分清（贯穿所有展示）

| 显示 | 含义 | 绝不能写成 |
|---|---|---|
| `—` | 该格无分母，率算不出（③④、缺分母时） | `0.00%` |
| `未录入` | 该格没填过（如报损） | `0`（「0 元 ≠ 本月无货损」） |
| `0` | 确实填了 0 | 与"未录入"混为一谈 |

### 4.4 `loss_monthly` 的定位建议（重要）

- **不要**在每次保存时物化 `loss_monthly` —— 那会形成**第二份口径**，与实时 `_compute` 漂移（本项目铁律：第二份拷贝 = 静默漂移）。
- **建议**：仅 `POST /close` 时物化一次，定位为「**结账快照**」= 当时数字被冻结的证据；趋势图默认读实时 `_compute`，并可选「按结账快照对比」（体现"这个月后来被改过"）。

## 五、仪表盘设计

> 位置：单月详情表**之上**（页面③段）。所有金额单位**万元**，率单位 **%**。
> 数据源：新增 `GET /api/loss/accounting/trend`（见 §六）；未落地前可先用现有 `bootstrap` 循环取数（不推荐，N 次请求）。

### 5.1 ⭐ 主图：按月货损趋势柱状图（用户点名要的）

| 元素 | 内容 |
|---|---|
| 类型 | **分组柱 + 折线（双轴）** |
| X 轴 | `period`（月份，`2025-10 … 2026-09`），按时间正序 |
| 左轴（柱，万元） | 两根柱：**货损毛额**（琥珀）、**货损净额**（主色青） |
| 右轴（线，%） | **公司行货损净率**（紫），细线 + 数据点 |
| 交互 | 悬停出 tooltip：毛额 / 抵扣 / 净额 / 净率 / 是否已结账 / 数据完整度；点击柱子 → 切到该月详情 |
| 空月处理 | 无数据的月**不画 0 柱**，画浅灰虚线占位 + 「未录入」字样 |

🔴 **两条不可违反**：
1. **柱（万元）与线（%）必须双轴并各自标注单位** —— 共轴会把"率"读成金额。
2. **右轴只画公司行净率**：③④没有分母，不参与率的图；把 ③④ 混进率序列等于自造分母。

### 5.2 副图（3 张，按价值排序）

| # | 图 | 回答的问题 | 数据源 |
|---|---|---|---|
| A | **货损构成堆叠柱**：按月堆 ①门店退货 + ②业务员仓调 + ③良品仓直调 + ④报损 | 「损失从哪来」哪一块在变大 | trend 的分组小计 |
| B | **临期抵扣对比**：按月分组柱 毛额 / 临期销售抵扣 / 净额 | 「抵扣救回了多少」 | trend 的 company 明细 |
| C | **主体 Top 排行**（横向条形，按净额降序 Top 10） | 「谁的货损最重」 | trend 的主体明细 |

### 5.3 备用图（数据到位后再上）

| 图 | 前置条件 |
|---|---|
| 月内日走势折线（当月每天净率） | 需新增 `loss_daily` **写入点**（recompute / 保存时快照）；表已建但**目前无人写** |
| 数据完整度热力图（月份 × 分组，标缺分母/报损未录） | 只需 trend 返回 `data_quality`，**无前置依赖**，可与 A/B 同期上 |
| 计价口径对比（成本价 vs 售价两条净率线） | 需 trend 支持一次返回两种口径（成本略高） |

### 5.4 指标卡（5 张）

| 卡 | 主值 | 副值 | 备注 |
|---|---|---|---|
| 当月货损净额 | 万元 | 环比 **%（金额比金额）** | 主指标；负数=好事，绿色 |
| 当月货损净率 | % | 环比 **个百分点** | 🔴 率的变化**必须**写「个百分点」 |
| 当月货损毛额 | 万元 | 其中临期抵扣 | |
| 临期销售抵扣 | 万元 | 占比 = 抵扣 / 毛额 | 「挽回了多少」 |
| 数据完整度 | 已录 N / 应录 M | 是否已结账 | 悬停列缺项 |

> 第 2 张卡是这套设计的**文案雷区**：率从 1.8% 到 2.1% 是「上升 **0.3 个百分点**」，写成「上升 0.3%」会被读成相对涨幅，两个数差一个数量级。

### 5.5 筛选维度（6 个，全部联动）

| 维度 | 选项 | 影响 |
|---|---|---|
| 期次区间 | 近 3 月 / 近 6 月 / 近 12 月 / 本年 / 自定义起止 | X 轴范围 |
| 计价口径 | 成本价（进货价） / 售价 | **所有金额**随之变（同屏必须同源） |
| 含未结账月 | 开 / 关（默认**开但标记**） | 关掉后需提示「已隐藏 N 个未结账月」，不许静默少画 |
| 主体维度 | 全部 / 按分组（①②③④）/ 单个门店 / 单个业务员 | 图与卡的数据范围 |
| 指标切换 | 净额 / 毛额 / 率 | 主图 Y 轴与卡片主值 |
| 是否补空月 | 开 / 关 | 关 = 跳过无数据月；开 = 画「未录入」占位 |

## 六、后端改动清单（按优先级）

| 优先 | 改动 | 说明 |
|---|---|---|
| **P0** | `GET /api/loss/accounting/trend?from=&to=&pricing=` | 跨期只读序列。**必须复用 `_compute(c, p)`**，不许另写一份数学（否则又是一次静默漂移）。返回每期：`company{...}` + `groups[].subtotal` + `is_closed` + `data_quality[]` |
| **P0** | 前端：月列表 + 柱状图 + 5 张指标卡 + 6 个筛选 | 用户点名要的部分 |
| **P1** | 副图 A/B/C（构成堆叠 / 抵扣对比 / 主体排行） | 全部可由 trend 派生，**无新端点** |
| **P1** | 数据完整度热力图 | 只需 trend 返回 `data_quality` |
| **P2** | `loss_daily` 写入点（重算/保存时快照） + 月内日走势折线 | 表已建，缺写 |
| **P2** | `loss_monthly` 结账物化 + 结账快照对比视图 | 见 §4.4 |
| **P2** | 导入层落地（`import/preview` + `execute`） | 独立工作流，落地后 ①② 有流水支撑，仪表盘自然更准 |

⚠️ **新端点必须登记 RBAC**：`/api/loss/accounting/trend` 会落进已有 `/api/loss` 前缀 → `stock` 模块，**零登记**（前缀匹配）；但若日后把前缀拆细，需重新登记，否则 fail-closed 403。

## 八、本方案**不做**的事（避免误解）

1. **不新增数据表**、不改 DDL —— 导入阶段要用的 4 张表已就位。
2. **不删 `/loss`（货损计算）能力** —— 本轮只收导航入口；路由保留，批次效期预测仍是独立能力。
3. **不给 ③④ 造分母** —— 图表里它们只会出现在"金额"类图，不会出现在"率"类图。
4. **不把无数据月画成 0** —— 一律「未录入」占位。

### 原型里有意放进去的 4 个"设计证明点"

1. **2026-04 是空月** —— 主图画浅灰虚线占位 + 「未录入」，折线在该处**断开**；月列表显示「—」与「未录入」标。
   证明的是「无数据 ≠ 0」这条规则**在图上真的表达得出来**。
2. **2026-09 未结账** —— 柱子上方标「未结账」，月列表灰标；关掉「含未结账月」后会**明确告知隐藏了几个月**（不静默少画）。
3. **双轴各自有刻度** —— 左轴万元、右轴 %；只标一个 `%` 号不算数（读数靠猜）。
4. **③④ 不出现在率的序列里** —— 右轴折线只画公司行净率；③④ 只出现在金额类图。

> ⚠️ 原型内所有数值为**演示用示例数据**（页面顶部有醒目提示），不是生产真实数据。
