## 2. 根因（已取证）

### 2.1 主因：过程事件**事件名不匹配**，14 个全被丢弃

抓原始 SSE（一次「查库存」对话）帧类型统计：

```
DATA text                    x1067   ← 最终答案
EVENT hermes.tool.progress   x14     ← 🔴 过程/工具事件（Hermes 原生）
DATA other                   x15
DATA finish=stop / DONE      x1
```

事件真实字段：
```json
{ "tool": "terminal", "emoji": "💻", "label": "ls -la /opt/hergent-erp/ ...",
  "toolCallId": "call_02_…", "status": "running" | "completed" }
```

但 `client.js` 里只认 OpenAI Responses 风格：
```js
if (onTool && pendingEvent === 'response.output_item.added') { ... }
```
⇒ **事件名对不上** ⇒ `onTool` 永不触发 ⇒ `m.tools` 恒为空 ⇒ 过程无从显示。

**叠加问题**：`m.progress`（ProgressSteps「算工资三步」那套 UI）**只在 `showDemo()` 里被赋值**，真实链路从未写入 ⇒ 即使有工具数据也走不到那套 UI。

### 2.2 次因：等待期本来就"没有文字可流"

Hermes 的工作方式是**先静默跑工具循环、最后才生成答案**：
- 工具阶段：26–36 秒，**只有 `hermes.tool.progress`，没有 text 帧**
- 生成阶段：文本增量 0.6 秒内全部到达

⇒ 「看不到流式输出」在工具阶段是**客观无内容**；在生成阶段是**模型太快**。

## 5.5 追加：工具执行情况「回复中展开 / 结束后自动收起」（2026-09-25 17:2x）

**老板反馈**："能否做成跟 WorkBuddy 一样 —— 回复的时候显示工具调用情况，回复结束后只显示答案、把工具调用情况隐藏。"

**已实现**（节奏对齐 WorkBuddy）：
| 阶段 | 表现 |
|---|---|
| **回复中** | 工具明细**自动展开**，标题为「正在执行 N / N 步」，逐条显示 执行中 / 已完成 耗时；容器描边高亮 |
| **回复结束后** | **自动收起**，只剩答案 + 一行摘要「✓ 工具执行情况 11 / 11 步 2.8s ▾」 |
| 任意时刻 | 点那一行可**手动展开/收起**（手工操作后不再被自动逻辑覆盖） |

**实现要点**：三态开关 `openTools`（`-1` 未干预跟随流式 / `i` 手动展开 / `-2` 手动收起）；`toolsLive(i)` 判据 = `store.chat.streaming && i === 最后一条`。

**验证（探针 `tools/tools-autocollapse-probe.mjs`，12/12）**：
- 回复中：`body=1`、标题「正在执行 1 / 1 步」✅
- 回复结束（等待自动收起 39.5s）：`body=0`、`streaming=false`、标题回到「工具执行情况 11 / 11 步 2.8s」、步骤计数仍在（**数据没丢，只是收纳**）、答案完整（375 字）✅
- 再点一下又能展开 ✅；0 控制台报错 ✅

**🔴 探针自身踩的两个坑（值得复用）**：
1. **不能用「`.typing` 消失」当"回复结束"判据** —— 第一个字到达时 typing 就没了，但流式仍在继续，此时工具**理应**保持展开，会误判成"没收起"。
2. **收起后 `.cp-tool` 行不再渲染 ⇒ 计数会变 0**，所以判据只能是 `body===0`；「数据是否还在」要改看标题里的「N / N 步」。

部署：`Shell` 双侧 md5 `f1db4a8c…`。
