# 企微对话在 Web「历史对话」看不到 —— 根因与修复

日期：2026-09-25　·　结论：**根因是两套存储互不相通 + 缺归属映射；已打通并验证**

---

## 1. 现象
老板用企业微信给副驾发「你好」，副驾回复了；但在 Web 端点「历史对话」**看不到这段对话**。

---

## 2. 根因（已取证）

**是两条互不相通的存储链：**

| | 存储 | 证据 |
|---|---|---|
| **Web 副驾对话** | ERP **租户库** `chat_sessions`（`WHERE user_id=?`，`user_id` = username） | `routers/ai_assist.py:167` 建表；`list_sessions` 只查本表 |
| **企微对话** | **Hermes 租户家目录** `state.db` | `/opt/hermes-tenants/hergent_t1/state.db`：`sessions` **1 行**（`source=wecom`、`user_id=ZhangJunFeng`、`title=经营副驾功能介绍`、`message_count=77`）+ `messages` 77 行 |

⇒ Web 历史**从来不读 Hermes 的库**，所以企微聊完在 Web 上永远看不到。

**还有一块缺失（这才是关键）**：系统里**没有**「平台身份 → ERP 用户」的映射 ——
- `ai_channel_pairings` 只是一条**配对码**记录（`role_id=copilot, channel=wecom, code=WXNGGM9L`），**不带 ERP 用户**；
- `platforms/pairing/wecom-approved.json` 只记「批准过 `ZhangJunFeng`」，也不绑用户。

⇒ 所以这**不是一个能一行修好的 bug，而是缺一块功能**：IM 会话没有主人。

---

## 3. 修复（已上线并验证）

**做法：读 Hermes 库 → 同步进租户库 `chat_sessions`（幂等 upsert），复用既有 UI 全链路**（列表 / 明细 / 搜索都不用改）。

| 要点 | 说明 |
|---|---|
| 位置 | `routers/ai_assist.py` 新增 `_sync_im_sessions()`，在 `list_sessions` 列表前调用 |
| 只读 Hermes | `file:{state.db}?mode=ro` 只读打开，不干扰正在写的 Hermes |
| 幂等 | `INSERT … ON CONFLICT(user_id, session_id) DO UPDATE`，`session_id = im:<渠道>:<Hermes会话id>` |
| 溯源 | 标题加渠道前缀，如 `[wecom] 经营副驾功能介绍` |
| **剥围栏** | 导入时剥掉 ```cards / ```clarify / ```proposal / ```reminder 等**控制标记**，历史气泡里不会出现 `{"show":[]}` |
| **归属（保守）** | 归到本租户的 **boss/admin** ⇒ **只让老板看到**。宁可少给，也不把某人的私聊外泄给同事 |
| 容错 | 整段 `try/except`，同步失败**绝不**让历史面板打不开 |

**验证**

| 检查 | 结果 |
|---|---|
| boss 列表 | ✅ 出现 `im:wecom:20260911_153316_f57750b7｜[wecom] 经营副驾功能介绍`，**置顶** |
| 明细 | ✅ **76 条**，第一条正是截图里的「你好」 |
| 控制标记 | ✅ 已剥（无 `cards` / `show` 残留） |
| **隔离** | ✅ supervisor 列表里 `im:` 条数 = **0**；直接按 id 取 → **HTTP 404** |

---

## 4. ⚠️ 已知边界（诚实说明，需你决定是否继续做）

1. **同租户多人的 IM 对话会都归到 boss**：因为没有「IM 身份配对」，无法区分是谁的企微号。
   ⇒ 需要补一个「IM 身份 ↔ ERP 用户」配对（可复用既有配对码流程，把配对结果落成映射）。
2. **企微会话里混着运维告警**：实测该会话 76 条里有「Hergent 运维自检」「⚠️ AI 出口预警（余额偏低）」等**系统推送**，它们也以 assistant 消息落在这个会话里。
   ⇒ 历史里会出现运维告警，看着像对话。可选处理：① 告警改走**独立渠道/会话**（更干净）② 按已知告警模板前缀过滤（有误伤风险）。
3. **同步时机**：目前是**打开历史时懒同步**（幂等、成本低）。如需实时，可加 cron。

---

## 5. 围栏外泄（已修主因 + 纠正一个错误建议）

截图里企微那条回复**把 `cards` 围栏原文发给老板了**（`{"show": []}`）。

### 5.1 🔴 先纠正我上一条建议
我先前建议「给出站钩子剥围栏」—— **这条路走不通**。取证：`gateway/hooks.py` 的
`async def emit(...) -> None` **返回 None、handler 的返回值被忽略**，`run.py:13147` 也只是
`await self.hooks.emit("agent:end", …)`。⇒ **Hermes 的钩子是只观察、不可改写**。
（另：`_sanitize_gateway_final_response(platform, text)` 只做**密钥脱敏 + 供应商错误替换**，不认识我们的围栏协议；改它 = 打补丁 Hermes，会被升级静默覆盖。）

### 5.2 真正的病根：**SOUL.md 主动要求输出空意图**
原文（`SOUL.md` 第 61-62 行）：
> `show 取值：… ；纯文字回复写 {"show":[]}。`
> `示例：…问"帮我写一份周报正文"→ 末尾 ```cards {"show":[]} ```。`

⇒ 模型在**纯文字回复**时被明确要求输出 `{"show":[]}` —— **这个空意图不携带任何信息，却会在 IM 渠道原样露出来**。这是截图那段噪声的来源。

### 5.3 修复（已上线并验证）
把三份 SOUL.md 都改掉（精确断言替换 + 备份）：
- `/opt/hermes-tenants/hergent_t1/SOUL.md`（**IM 渠道真正读的那份**）
- `/opt/hermes-tenants/_seed/SOUL.md`（新建租户的模板）
- `/root/.hermes/SOUL.md`（**Web 副驾走的那份**）

改为：**没有卡要展示时完全不输出围栏**；示例改成「周报正文 → 纯文字、不加围栏」；并补一句
**围栏是内部标记，任何渠道都不要在正文里解释或复述它**。

**验证（真实调用，Web 路径）**
| 问题 | 修复前 | 修复后 |
|---|---|---|
| 「帮我写一段话…（只要正文）」 | ` ```cards {"show":[]} ``` ` ❌ | **无围栏** ✅ |
| 「这个月货损多少？」（应出卡） | 出卡 | ✅ 仍出 ` ```card {"type":"loss",…} ` |
| 「算一下这个月工资」（应出卡） | 出卡 | ✅ 仍出 ` ```proposal … ` |

⇒ **空意图噪声消除，卡片能力无回归。**

### 5.4 ⚠️ 仍未解决：**真卡片意图在 IM 上仍会露出来**
- 当回复**确实要展示卡片**时（如 ` ```cards {"show":["loss"]}`），企微里仍会出现那段代码块。
- 根因：**模型不知道自己在哪个渠道**（`prompt_builder` 里的 `platform_name` 是**操作系统**，不是聊天渠道；未找到渠道注入的证据）⇒ 提示词做不了"按渠道区分"。
- 真解需 Hermes 侧：给 `_sanitize_gateway_final_response` 增加**租户可配置的出站剥离规则**（或让钩子可改写返回值）。**建议作为需求提给 Hermes。**

### 5.5 🔴 顺带发现：**SOUL.md 有三份拷贝，会漂移**
`/root/.hermes/SOUL.md`（Web）· `/opt/hermes-tenants/hergent_t1/SOUL.md`（该租户 IM）· `/opt/hermes-tenants/_seed/SOUL.md`（新租户模板）。
三者 md5 **各不相同**，内容却高度重合（本次三份都要手改）。
⇒ 任何提示词改动都必须**三处同步**，否则会出现"网页改了、企微没改"的静默不一致。建议做一份「权威源 + 下发」机制（类似技能的 seed 同步）。
