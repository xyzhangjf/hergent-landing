## 一、这批做了什么

### ① 数量格候选：上期同格值 / 本期其它客户常用值（清单 P2-1 / 任务 #540）

| 项 | 内容 |
|---|---|
| **作用** | 点进数量格时，下拉里直接给出「上期这家店订了多少」「本期别的店订了多少」，点一下就填进去 |
| **适用场景** | 每周重复报单 —— 绝大多数客户的量**与上期接近**，照着上期改比从空白开始敲快得多；新客户则参考"同商品别人订多少" |
| **为什么必须先解决"口径"** | 「上期量」有三种可能的口径：**按客户**、**按商品汇总**、**按全部**。表格里现成的「上期量」列是**按商品汇总**的 —— 直接拿它当候选，会让每家店的候选都变成"这个商品全国总量"，**整表误报漏订**。所以必须用 `sources[].store` + `sources[].qty` 重建**按客户**索引 |
| **数据来源** | `/api/forecast-submissions/summary`（**后端无需改动**，该接口的 `sources[]` 本来就带 `store` + `qty`） |
| **性能取舍** | 全表 **3276 个数量格**，若每格挂一份 `<datalist>` 就是上万节点。做法：全局只保留**一份** `#opt-qty`，靠 `:key="qtyOptKey"` 在换格时**销毁重建** |
| **触发时机** | 挂在 `@focus`（`onFocusCell`）上，**不能挂 `mousedown`** —— 键盘跳格只走 focus，挂 mousedown 等于"用键盘的人没有候选" |
| **降级** | 取数失败**静默降级**（不弹错）：候选是**增益信息**，取不到就当没有，不能把好端端的报单流程变成一个错误弹窗 |

**真机锚定读数**：锚定格 `{"行":4,"列":12,"客户":"王琴","上期量":84}` → 候选 `["上期 84（v212沙箱上期-勿动）"]`；同格对比**该客户 84 / 该商品合计 420 / 涉及 11 个客户** —— 三个数不同，证明取的确实是"按客户"。

### ② 软警告分级：疑漏订 / 疑超放量（清单 P2-2 / 任务 #541）

| 项 | 内容 |
|---|---|
| **作用** | 把"**可能**填错"的格子标一个**黄角标**（右上角），鼠标悬停/手指点击都说清**为什么可疑** |
| **与红角标的分工** | **红 = 一定错**（左上角，如数量超上限）｜**黄 = 可能错**（右上角，如漏订）｜填充柄在**右下角**｜左下不占 —— 四个角各有归属，不打架 |
| **两档判据** | **疑漏订** = 上期该客户有量 · 本期 0 · **同行其它客户已报**（`rowTotal > 0` 是**必要前提**）；**疑超放量** = 本期 ≥ 上期 × 倍数阈值（阈值界面可改，默认 5，最小 2） |
| **为什么漏订判据必须带行前提** | 去掉 `rowTotal > 0`，一进编辑态就是**满屏黄**（整行都没报的商品全亮）⇒ 警告立刻贬值成噪音。真机上：**10 个黄角标 / 3276 个数量格 = 0.3%** |
| **可单独关** | 两类各自有开关（右键菜单里），阈值落 `localStorage`（关了浏览器还在） |
| **性能** | 判据一次性成图（computed `Map`）而不是逐格现算 —— 真机实测改一格后 **832ms** 内角标出现；若退化成逐格现算（O(N²×M)）会跳到秒级 |

**真机文案读数**（这两句就是用户会看到的原文）：
- 疑漏订：`黄家伟 在「v212沙箱上期-勿动」报了 12，本期还是 0（同商品其它客户已报 6）。确认不订可忽略。`
- 疑超放量：`本期 840 是「v212沙箱上期-勿动」的 84 的 10.0 倍，请确认是否促销 / 新增渠道。`

### ③ 选区批量填同值的**可见**入口（清单 P2-3 / 任务 #542）

| 项 | 内容 |
|---|---|
| **作用** | 框选一片格子后，**屏幕上直接出现**「批量填入」输入框 + 「填入」按钮（右键菜单里也有一份） |
| **适用场景** | 一家客户要订同一个数填一片；或者把一片"遗留的 0"统一改成同一个值 |
| **真相** | 这个功能（`Ctrl+Enter` / `batchWrite`）**早就在代码里**，缺的**只是"看得见"** —— 用户不知道有这个快捷键，等于没有 |
| **入口位置** | 选区统计条上（刚框完一片时眼睛落着的地方）+ 右键菜单「批量填入相同值…」 |
| **不新写写循环** | 两个入口都复用 `batchWrite`（`Ctrl+Enter` 那条**已被生产验证过**的写入口），避免"同一条规则两份实现" |

**这一项在真机上抓出了 4 个真缺陷**（见 §四）—— 是本批最值钱的部分。

## 四、🔴 真机首跑 18 项失败里，抓出的 4 个**产品真缺陷**

首跑 18 项红，**其中 15 项是我自己探针的假红**（见 §五），**4 项是产品真缺陷**。这 4 个正是"必须真机跑"的理由 —— 它们**在离线护栏里全绿**，靠读代码推演发现不了。

### 🔴① 框选一片空格子时，整条统计条连同新入口**一起消失**

- **判据错了**：统计条的 `v-if` 挂在 `selStats` 上，而 `selStats` 在"选区内没有数字"时 `return null`。
- **后果**：「**框选一片空格子 → 填同一个数**」—— 这正是批量填入**最主要的用法** —— 功能在**真正需要它的那一步消失**，而且**不报错、不出提示**。静默缺入口比报错更难发现。
- **修法**：`v-if="selRange"`（有选区就显示）；新增 `selCellCount` computed 表达**选区面积**；格数恒显示。
- **顺带确立的一条**：「选区**面积**（几格）」与「选区里**有几个数字**」是**两件事**，必须分开算 —— 批量填入的入口看面积，求和/平均看数字。

### 🔴② 统计条**落在屏幕外**（真机 `可见: false`）

- **几何真相**（探针实测）：表格自己是 `max-height:72vh` 的滚动盒，而**整页又在 `MAIN.content`（`overflow-y:auto`）里滚**，页面比可视区高 **~574px** ⇒ 1600×950 视口下统计条落在 `top: 1200`（`innerHeight` 只有 950）。
- **试过并否掉的方案**：`position:sticky; bottom:0` —— **真机实测无效**（`top` 仍是 1200）。原因是它是 `.grid-area` 的**最后一个子元素**，包含块底边就在它下面，**sticky 无处可移**。
- **最终修法**：`position:fixed; left:var(--sidebar-w,248px); right:0; bottom:0; z-index:40`；全屏层 `.grid-area.is-fs .sel-stat{left:0}`（全屏层占了整个视口含侧栏位，铺满全宽否则左边缘凭空缺一块）；打印样式加进 `display:none`。
- **为什么是 `var(--sidebar-w)` 而不是写死 248**：该变量由 `Shell.vue` 写在 `documentElement` 上，且**侧栏可拖拽调宽** ⇒ 自动跟随，侧栏改了宽度浮层不会盖住导航。

### 🔴③ 恒显示「求和 0 / 平均 0」

- **真因**：数量格的初值**大量是 `0`（不是空串）** ⇒ 逐格算出来的 `sum` 恒为 0。
- **后果**：恒显示「求和 0」既是**纯噪音**，还容易被用户读成"**里面全是 0（有数据）**"—— 与事实相反的暗示。
- **修法**：`<template v-if="selStats && selStats.sum !== 0">`，**格数提到最外层恒显示**（格数是"会被写入多少格"，这个信息任何时候都有意义）。

### 🔴④ `batchWrite` 报**选区面积**而不是**实际写入成功数**

- **真机实测**：12 格的选区里只有 **11 格**是数量格（更早一次样本里只有 **4 格**），提示却报「已批量写入 **12** 个单元格」。
- **真因**：`writeCellVal` 会**跳过只读列**（条码 / 规格 / 单位 / 到货周期 / 厂家编码…）。提示的个数与实际变化对不上 ⇒ 用户会以为「**有些格没填进去**」而**反复重试**。
- **修法**：`if (writeCellVal(ri, ci, val)) n++`，只数成功的。
- **⚠️ 最值得记的一点**：**同一个坑 v184 已经在「清空」(`clearRange`) 上踩过并修掉了**（那里有注释），`batchWrite` **当时漏了** —— 典型的「**同一条规则两处实现、只修一处**」。现在两处同口径，并加了一条护栏（D16）**同时守两处**。

## 五、本轮探针自己出的坑（值得记住，因为它们伪装成"功能坏了"）

### 🔴 最贵的：`p.evaluate` 返回的是**字符串**

18 项失败的主根因。探针内部已经 `JSON.stringify` 过一层，我直接读 `prevInfo.id` ⇒ 恒 `undefined` ⇒ 拼出 `period_id=undefined` ⇒ 后端 **422** ⇒ 真值表全空 ⇒ **S-4 / S1-0a / S1-0b / S2 四连 / S3-11·12 / S6-2 一路连锁假红**（15 项）。
**修法**：显式 `JSON.parse`，并**单独断言取数成功** —— 取数失败必须**在这里**就露出来，不能传染到后面。**这类"取数失败伪装成功能坏了"是探针最贵的假象。**

### 🔴 从 label 里解析数字时，期次名里也带数字

label 形如 `上期 240（v212沙箱上期-勿动）`，期次名里含 **212**。「去掉『上期 』前缀后取全部数字」会拼成 **`240212`** ⇒ **锚定永远不成立**（S1-0b / S1-2 / S1-3 / S3-11 全跟着假红）。
**修法**：只认紧跟在「上期 」之后的 `[\d.]+`。

### 🔴 `.ctx-ipt` 选择器**误命中**同菜单里的「超放量倍数阈值」输入框

`.ctx-ipt` 在文件里共 **6 处**（阈值 / 表头重命名 / 新增列 / 筛选 / 列宽…）⇒「Esc 退回菜单了吗」这类断言会被**阈值输入框**误命中，**假绿过一次**。
**修法**：给填入框加**区分性类名** `ctx-ipt-fill`。

### 🔴 FATAL 分支没关浏览器 ⇒ **进程永不退出**

无头 Chromium 吊住事件循环，日志停在中途、任务"运行中"数分钟 —— 看起来像**卡在某一步**，实际是**已经崩了**。
**修法**：`let BROWSER = null` + `catch(async (e) => { … await BROWSER.close() })`。

### 🔴 分支从未跑到 = 缺陷被藏住

`JSON.parse(await ...).catch is not a function` —— 对**已解析出来的数组**调 `.catch`。这个分支**以前从没跑到过**（它原在 `if (anchor)` 内，锚定失败时整段不执行）。
**教训**：锚定失败时**后面的分支也跟着不执行** ⇒ 一个假红会**掩盖**它下面所有断言的真实状态。所以 S2 段改成**自己先聚焦一格**（每段自带前置，结论才可归因）。

### 差集工具的用法纠正（非产品问题）

- 第①层**用错工具**：`dist-bytes-diff.py` 要的是**两个文件**，第①层应该用 `dist-pair-check.py`（两个目录）。
- **中文串差集的「期望新增词」传错**：传了 `已选 格`（这两个是**既有**词，不是新增），脚本正确报「期望出现却没出现」—— 脚本是对的，是我传错了。
