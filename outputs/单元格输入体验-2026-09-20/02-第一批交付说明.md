## 一、这批做了什么

### ① 商品名称列补全候选（清单 P1-1）

| 项 | 内容 |
|---|---|
| **作用** | 新增/修改商品行时，输入几个字就能从**全量商品主档**（285 条）里选到正确名字，无需手打「友芝友益生菌红枣风味酸牛奶圆周杯100g*8杯*12组」 |
| **适用场景** | **每一次新增商品行**；也用于核对已有行的名字写法 |
| **为什么这条最值钱** | 保存时 `prodPayloadOf` 会把 `name` 一起走 `productsApi.bulkUpsert` **回写商品档案** ⇒ **名字打歪一次就等于给档案里添一条错商品**（比"打错字"严重得多：下游对账/返利/统计都会带上它） |
| **实现** | 商品名格加 `:list` 指向共享 `datalist#opt-prodname`；候选来自 `/api/products/grid` 的全量主档；下拉里显示「名称 · 规格」，便于区分同名不同规格 |
| **顺带修的缺陷** | 这一格的 `input` **原本没有变更钩子** ⇒ 改了商品名**不进撤销栈**（`_pendingCell` 只在 `onCellChange` 里被消费），Ctrl+Z / 「回退」都还原不了，也不点亮状态条。已补 `@change` |

**⚠️ 一个刻意的取舍**：候选用**原生 datalist**（浏览器自带），因此只支持**名称模糊匹配**，**不支持按条码后四位或拼音首字母搜**。那需要自建候选面板（绝对定位 + 键盘上下选 + 层级处理），是独立一轮的工作量 —— 先上价值最高的部分。

### ② 数量格 / 单价格的移动端数字键盘（清单 P1-2）

| 项 | 内容 |
|---|---|
| **作用** | 触屏设备（平板 / 手机开网页）点数量格**直接弹数字键盘**，不必在字母键盘里找数字 |
| **适用场景** | 仓库 / 冷库里用平板报单；销售在客户店里用手机补单 |
| **现状对照** | **小程序端早就有**（`inputmode="numeric"` + 步进器），**Web 端一直漏着** |
| **覆盖** | 数量格 / 加单格 = `numeric`；单价格 = **`decimal`**；主档数字列 = 按「该列是否整数」动态给 |

**⚠️ 为什么单价格必须是 `decimal` 而不是 `numeric`**：单价有 `step="0.01"`（两位小数）。给成 `numeric` 会让**安卓上的小数点键消失** ⇒ 用户永远填不了小数价。护栏专门守这一条（不只要求"有 inputmode"，还要求它**不是** numeric）。

### ③ 触屏可读的错误原因（清单 P1-3）

| 项 | 内容 |
|---|---|
| **作用** | 出错的格子上出现一个**可点击的角标**，点它直接弹出完整原因 |
| **适用场景** | **平板 / 手机**（那里根本没有"悬停"）；桌面侧也顺带把"哪一格错了"标得比纯红框显眼 |
| **原状的痛点** | 错误原因一直只挂在 `<td title>` 上（**悬停**才出来）⇒ 触屏读不到；要查原因还得滚到表格下方看「查错」清单 |
| **位置** | **左上角** —— 右侧垂直中线是行徽标（`.name-badges`）的地盘、右下角是填充柄（`.fill-handle`），只有左上角完整空闲 |
| **层级** | `z-index:5`，**必须低于粘性列的 6** —— 否则横向滚动时角标会浮在冻结列上面 |

### ④ 顺带修复：商品名的改动现在会登记

见 ① 的"顺带修的缺陷"。**这一条改前会红、改后绿**（见 §三）。

## 四、本轮探针自己出的坑（值得记住）

### 🔴 最贵的一个：探针「退出码 0 + 日志 0 字节」
首次运行 v211 探针，**日志文件 0 字节、退出码 0** —— 看起来完全像"功能坏了"，实际是**日志根本没落盘**。两个原因叠加：

1. **`process.exit()` 会丢弃尚未 flush 的 stdout**（stdout 重定向到文件/管道时是异步写）⇒ 结尾必须用 `process.exitCode = n`，让 Node 自然退出。
2. **IIFE 是"发射后不管"的**（`(async () => {...})()` 未被 await）⇒ 内部抛错时，未接住的 rejection 也会在输出落盘前带走进程 ⇒ 必须 `.catch()` 兜住并打印栈。

真凶是**截图目录不存在时 `fs.mkdirSync` 抛错**。已把这一步包进 `try/catch` 并**显式失败打印**（前置条件不成立就要把话说清楚，不能表现成"什么都没发生"）。

### 两处假红（都是探针判据的错，不是产品的错）
- **命中测试用 `===` 比较**：角标里包着 `<Icon>`（svg），点它中心命中的是**那个 svg 子元素** ⇒ 判据改成 `el.contains(top)`。
- **读状态条的时机错**：原生 `<input>` 的 `change` 在**失焦时**才触发，打完字不移开焦点就去读 ⇒ 必然读到「尚未修改」。修法是**先点到另一个格**再读（且必须点"另一个"格，点回原格焦点压根没走）。
