## 二、病根：为什么 v350 修完了，结构上还会漏

v350 修的是两个具体的 P0（自我锁死、切视图静默丢输入）。修法是**在两个视图里各补一份判据**。这治了病，没治病根 —— 病根是**权限页有两个写入口**：

| 入口 | 写的数据形态 | 走的接口 |
|---|---|---|
| 矩阵视图「批量总览」 | **list 形态** `perms[角色] = [模块…]` | `POST /api/role-permissions` |
| 角色详情视图 | **dict 形态** `perms[模块] = {read, create, update, delete}` | `POST /api/role-permissions/detail` |

两套形态写同一行数据 ⇒ **同一安全规则必须在两处各实现一遍**，日后再改只改一处就必然漏一份（v350 的自我锁死就是这么来的）。

> 本仓铁律：**同一安全规则必须单一实现**。多写入口 = 多份规则 = 必漏一份。

## 三、这次改法的本质：用结构消除问题，而不是再补一份判据

**直接删掉第二个写入口**（「批量总览」页签整块移除）。矩阵撤掉后：

- `POST /api/role-permissions` 在本页**不再有任何调用方**（端点本身保留，不动后端）；
- `isLockedModule` 只剩详情视图**一个**消费方 ⇒ 规则物理上只存在一份，**不可能再漏**；
- 这些随之全部删除（它们只服务于横向矩阵，撤掉后就是"没有界面的写路径"）：
  `collapsedGroups` / `toggleGroupCollapse` / `groupChecked` / `toggleGroup` / `groupedModules` / `togglePerm` / `savePerms` / `permSaving`。

「看」的需求没被丢掉 —— 降级为**只读弹窗**「查看对比」：里面只有 `✓` / `—` 两种标记，**零 input、零 checkbox、零 @change、零 v-model**，唯一按钮是「关闭」。

## 五、「不折叠」怎么落的

原「更多」那 11 行曾拍板保留折叠（v349）。本次改由**域页签**呈现，理由写进了代码注释：

> 页签本身就是"点一下就到那一类"的入口，再叠一层"先展开再找"是多余的两次点击。
> 「11 行会淹掉上面 10 个功能」这个问题，已由页签解决。

实现上：`permView.js` 的 `PERM_MORE_GROUP` **删掉 `collapsed: true`**；`Settings.vue` 删掉折叠机制；改由 `.domtabs` 一次只显示一个域的行。

**为什么页签安全、而 v350 的矩阵不安全**：页签一次只显示一个域的行，页面上**没有任何跨域批量控件**（「整行全选」只作用自己那一行）⇒ 不存在 v350 那种"作用范围 ≠ 用户所见"的风险。

**页签上的数字在搜索态下改显命中数**（`domainCount(g)`）：无命中的域自然露出 `0`，用户知道该点哪个 —— 否则"页签里什么都没有"会被当成坏了。探针 H5 实测：搜「算工资」后页签变 `["经营0","核算1","配置0","更多0"]`。

## 六、顺手必须一起修的一条：登录端并入本页保存

矩阵的「保存权限」按钮撤掉后，登录端卡片就留在了详情页顶部。若点「保存」只存功能权限、不存登录端 = **界面说假话**（这正是本项目最忌讳的形态）。

修法：`saveRoleDetail` 同时发 `POST /api/role-permissions/end`，并且：

- **只在真改过时才发**（与 `endBase` 快照比对）；
- body **只含当前这一个角色**（旧代码是 for 所有角色逐个 POST ⇒ 会把别的角色一起写一遍）。

探针 G 段实测：勾「库管」的手机端 → 点保存 ⇒ 发出 **1 条** `POST /api/role-permissions/end`，body = `role_name="库管" allow_mini=true`，回执「「库管」的权限已保存（含登录端）」。

## 八、部署侦察里我自己判错了一次（如实记录）

**错在哪**：我用 `comm` 比"本地构建 vs 生产 assets"的差集，得出「**52 个待上传**」。

**为什么错**：`comm` 要求两侧**排序规则一致**。macOS 的 `sort` 与 Linux 的 `sort` 在 `- _ .` 这些字符上的 collation **不同** ⇒ 两侧虽然都"排过序"，却不是同一种序 ⇒ `comm` 输出的是**垃圾**。

**怎么发现的**：同一个文件名（`Archive-FHZG7KfX.css`）竟**同时**出现在"生产缺失"清单和"生产 08:46 批次"清单里 —— 自相矛盾。这才回头怀疑工具。

**改用的正确判据**（本仓铁律：**比字节不比名**）：

```
[A] 同名且同字节          : 26
[B] 同名但内容不同(危险)  : 0
[C] 本地有、生产无此名    : 30
    [C1] 名字新、字节生产已有 : 0
    [C2] 名字新、字节也新     : 30   ← 真需上传
```

**顺带把"30 个 chunk 改名"这件事彻底解释清楚了**（chunk 名受 hash 级联影响，名本身什么都判不了）：

```
Settings.vue 改 → Settings chunk 改名
              → 入口 chunk 内嵌的 __vite__mapDeps 文件名清单变 → 入口改名
              → 所有 import 入口的 chunk 改名
```

所以恰好 **26 个字节不变**（22 个 CSS + 4 个不 import 入口的叶子工具 `arrival/favicon/printable/useMonthlyAchv`）。

**证伪手段**（把"只是改名"变成可证的事实）：把两侧 chunk 内所有带 hash 的文件名引用抹成占位符后逐字节比 —— **31/33 完全相同**；剩 2 个是 `Settings`（我的改动，+142 字节）与 `index`（差异只有两处 **minifier 导出别名换序** `Bl as aq, mh as ar` ↔ `mh as aq, Bl as ar`，零代码差异）。

> **结论**：当前工作树减去本轮改动，与线上构建的源码**逐字节相同** ⇒ 本次上线**只带本轮改动，没有夹带任何外来在途改动**。

**另有一次小事故（当场自纠）**：用 `scp $FILES` 批量上传时漏了 zsh 的特性 —— **zsh 不对未加引号的变量做词分割**，30 个文件被当成 1 个文件名 ⇒ chunk 没传上去，而 `index.html` 已传 ⇒ **线上入口短暂指向尚未上传的 chunk**。发现后立即用数组 `"${FILES[@]}"` 补齐，30 秒内恢复。教训：批量传文件用数组或 `xargs`，不要指望 `$VAR` 词分割。

**还有一次"重复造轮子"**：我这轮手写的「归一化逐 chunk 比对」脚本，其实技能 `hergent-frontend-deploy-verify` 里**早已固化**（v336 的 `scripts/assets-scope-diff.py` ＋ v339 的 hex-only 判据）。**根因是我没先查已有工具就动手**。已把这一条写回技能（新 §0「先查已有工具，别重造」）。
