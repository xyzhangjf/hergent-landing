## 二、变更（为什么这么做）

### 为什么「忘记密码」不能真的完全自助

核查后确认系统里**没有任何可信身份凭据**可用于免登录验证：短信网关是占位域名 `sms-api.example.com`；`REGISTER_MODE=invite` 时 `send-code` 直接 400；生产 5 个启用账号里真实手机号 0 个（2 个是 `mptest`/`mptestsp` 假值）。且补手机号会牵动**已提交、正在审核**的备案材料与隐私申报。

⇒ 把「完全自助」重构为「**管理员发一次性码 + 员工自助设密码**」。这个方案的责任边界反而更好：**管理员全程不知道员工最终密码**（现有 `/api/users/{uid}/password` 是管理员直接指定明文）。

### 每条安全设计都有理由

| 设计 | 取值 | 理由 |
|---|---|---|
| 码长度 | **6 位数字** | 员工要能听人念出来手敲 |
| 有效期 | 30 分钟 | 够线下转达，又不至于长期滞留 |
| 一次性 | **CAS**（`WHERE used_at=''` + `rowcount` 判定） | 并发下只有一个请求能消费成功 |
| 错误上限 | 5 次后**当场作废** | 本地验证 T3 抓出的真缺陷，见下 |
| 存储 | `SHA256(code + SECRET)` + `hmac.compare_digest` | 库被读走也拿不到码 |
| 重发 | 生成新码自动作废该用户旧码 | 同用户只留最新一张有效码 |
| 改密成功 | **清空该用户全部会话** | 忘记密码场景下账号可能已被他人掌握 |
| 留痕 | `audit_log` 记成功与失败 | |

### 一个必须记住的落库位置

`password_reset_codes` 与 `users` 一样是**主库表**。免登录路径没有租户上下文，`get_db()` 落主库；若建进 `tenant_N.db`，`/api/auth/forgot-reset` 就**查不到码**（静默不生效）。

### 后端四文件各自改了什么

- `password_reset.py`：`ensure_tables` / `issue_code_for_user` / `reset_password_with_code` / `count_open_codes`
- `routers/auth.py`：新增免登录 `POST /api/auth/forgot-reset`
- `server.py`：① `CSRF_EXEMPT_PATHS` 加 `/api/auth/forgot-reset`（未登录请求既无 Bearer 也无 CSRF cookie，不豁免会被中间件 403）② 新增 `POST /api/users/{uid}/reset-code`（admin/boss）
- `core.py`：`_init_users()` 里调 `password_reset.ensure_tables(conn)`

### 小程序侧的三处缺口的修补

审计发现原小程序有四个真实缺陷，本次一并修掉：

1. **小程序完全不读 `require_password_change`** → 强制改密闸门在小程序侧形同虚设。现在登录后消费该字段并进强制改密页。
2. **小程序登录页写着「首次登录请修改密码」，但小程序没有任何改密入口** → 文案改为「**首次登录需修改初始密码**」，并新增改密页 + 「我的」页入口 + 登录页「忘记密码？」。
3. **两条管理员重置路径策略分叉**（`/api/users/{uid}/password` 只要 4 位且不写 `password_changed`；`/api/auth/reset-password` 要 8 位 + 字母数字）—— 本次新增的重置码路径统一走 `_validate_password` 口径（8 位 + 字母数字）。
4. **防杀进程绕过**：改密没做完就杀掉小程序再重进时 token 仍在 ⇒ `login.js` 的 `onLoad` 也拦一道；原密码暂存 `app.globalData.loginPw`（**内存不落盘**），拿不到时显示原密码输入框。

## 六、需确认事项

1. **请你在微信开发者工具里点一次「编译」** —— 小程序没有 CLI 构建通道，新页面 `pages/password` 与 `pages/forgot` 必须由人点编译才会出现在预览里。建议顺手走一遍：登录 → （收到强制改密）→ 改密 → 杀掉小程序重进（应被拦回改密页）→ 「我的」→ 修改密码 → 退出 → 登录页「忘记密码？」→ 用管理员发的码重置。
2. **平台侧两件仍待你做的**（与上次备案收尾同一批）：配「用户隐私保护指引」（只勾**剪切板**）、配 request 合法域名 `https://hergent.cn`。
3. **重置码的值班口径**：码只在管理员点「生成重置码」的那一次显示，关掉弹窗就再也看不到，需重发；**生成新码会自动作废同一个人此前所有未使用的码**。
4. 小程序端**未分配网页端权限的员工**可以自助改密了，但「重置码」仍必须由**有网页端 admin/boss 权限的人**生成 —— 若日后希望值班人员（如 supervisor）也能发码，需要单独调整该端点的权限门禁。
