# 角色权限 ↔ 员工权限：该不该联动？（需求判读与设计）

> 版本：**v312**（2026-09-28 上线）
> 对应老板原话：*「设置里的角色权限是否应该与编辑员工时的权限配置联动：在设置中为角色配置权限后，编辑员工并为员工分配该角色时，应自动继承对应权限。……当前角色权限配置只有小程序权限选项，缺少 Web 端权限选项，且页面布局不合理。」*

---

## 一、先给结论

**该联动 —— 而且事实上有一半已经联动了。** 你感觉"没联动"的原因不是继承坏了，而是**少了一整条轴**：

| 权限轴 | 你现在的实际行为 | 结论 |
|---|---|---|
| ① **能用哪些功能**（经营分析 / 预报 / 人事档案 / 返利……） | 员工**本来就没有**自己的模块权限表 —— 权限**全部**长在角色上，员工绑了角色就继承 | ✅ **已经在联动**，无需改 |
| ② **能从哪个端登录**（电脑端 / 手机端） | 只写在**程序代码**里，客户改不了 —— 所以你在页面上**根本看不到**这两个选项 | ❌ **这才是缺口** |

所以你举的例子——

> 「若给业务员角色仅配置了小程序权限，则该员工只有小程序权限，没有 Web 端权限」

—— 这句话落到系统里其实是**两件事**：
- **"业务员能用哪些功能"** → 早就是角色说了算 ✅
- **"业务员能不能登电脑端"** → 以前客户改不了，只能来找我们改代码 ❌

本轮做的就是**把第二件事交还给你**，并把两件事在页面上**摆明白**。

---

## 二、设计（一句话：把"端"做成和"模块权限"一样的可配置项）

### 2.1 和现有模块权限**完全同一套范式**

| | 出厂默认 | 你的租户能改 |
|---|---|---|
| 模块权限（早就有） | 程序内置一份默认权限表 | 「设置 › 权限」里能改，改完存你自己的库 |
| **登录端（本轮新增）** | 程序内置一份默认端政策 | 「设置 › 权限」里能改，改完存你自己的库 |

⇒ **出厂默认只能"兜底"，你配过的永远优先。** 任何角色、任何客户都能有自己的配法。

### 2.2 页面上怎么呈现（照你给的舟谱截图思路）

「设置 › 权限」整页重做成**两段**，**上面一段是"端"、下面一段是"功能"**：

```
┌─ 设置 › 权限 ────────────────────────────────────────────────────────┐
│                                                                      │
│  ① 登录端（这个角色的人能从哪进）                    ← 本轮新增         │
│  ────────────────────────────────────────────────                    │
│  角色      允许用电脑端   允许用手机端   新账号的默认可登录端            │
│  业务员        ☐            ☑            仅手机端      [恢复]          │
│  主管          ☑            ☑            两端都能登    [恢复]          │
│  老板          ☑（锁）      ☑            两端都能登    [恢复]          │
│                                                                      │
│  ② 功能权限（这个角色的人能干什么）                  ← 原来就有，加了一列  │
│  ────────────────────────────────────────────────                    │
│  功能项              手机端   业务员  主管  老板                       │
│  经营分析             有       ☐      ☑     ☑                        │
│  本期预报             有       ☑      ☑     ☑                        │
│  人事档案              —      ☐      ☐     ☑                        │
│                                                                      │
│                                            [ 保存权限 ]               │
└──────────────────────────────────────────────────────────────────────┘
```

**关于那个只读的「手机端」列**（说人话）：
它标的是"**这个功能，手机小程序里到底有没有**"。这一列**不能勾**，因为它不是配置 ——
小程序里有哪些功能是**小程序代码写死的**。如果做成能勾的，就会出现"页面显示开了、小程序里其实没有"的**假开关**。
所以这里只**如实标注**，免得你在电脑端配了半天、结果手机上没有。

### 2.3 三个"防把你锁在门外"的保险

「登录端」这张表是**唯一一张能把人锁在门外**的表 —— 配错了，那个人连改回来的页面都打不开。所以做了三道闸：

1. **电脑端和手机端不能同时关**。关完 = 这个角色谁都登不进来，包括你自己。
2. **老板 / 管理员这两个角色的"电脑端"不许关**。保证永远有人能进后台改配置。
3. **万一库里出现了"两端全关"的脏数据，系统按出厂默认放行**（宁可放宽，不把人锁死）。

## 三、"联动"到底怎么落地（你最关心的那步）

### 3.1 新建账号：**自动继承角色配的端** ✅

在「档案管理 › 员工档案」点新建账号，选好角色后：

- 「可登录端」这一栏**自动预填成该角色在「设置 › 权限」里配的默认端**；
- 栏位下面会用小字写明**这个默认值是从哪来的**（例如"来自「设置 › 权限」中「业务员」的配置"）；
- 你**可以手动改**（比如临时给某个人开电脑端）—— 手改的以你为准。

### 3.2 已经开出去的账号：**不动它**，只提醒 ＋ 一键对齐

这是本轮**刻意**的设计取舍：

> **改角色政策，不会去动已经在用的人的登录方式。**

原因很直白：你哪天想把"业务员"收紧成只能手机端，如果系统立刻把所有在职业务员踢下电脑端，
**他们连单都报不了**。所以：

- 改角色政策 ⇒ **只影响以后新开的号**；
- 但系统会**主动告诉你谁不一致**：在员工档案里，如果某人的实际登录端和角色政策不一样，
  会显示一条提示 ＋ 一个「**与角色配置一致**」按钮，你想对齐就点一下，**一次改一个，你说了算**。

### 3.3 一个容易忽略的细节（已处理）

以前的逻辑是"前端拿到一个默认值就提交给后端"。这有个隐患：
如果你刚在「设置 › 权限」改了政策，而某个页面还拿着**旧的**默认值提交 ⇒ **会把你刚配的政策悄悄覆盖回去**。

处理方式：**只要没手动改过，提交时就不带这个字段**，让后端按你配的政策取值。
—— 从根上避免"界面看着改好了，其实被覆盖了"。

## 四、这次没做的事（明确边界）

| 项 | 为什么不做 |
|---|---|
| **员工级的"端"批量覆盖 / 批量对齐** | 已有单个人的一键对齐；批量操作风险高（一次动几十人），先看你要不要 |
| **模块级的"端"勾选**（让某个功能单独只在电脑端有） | 小程序里有哪些功能是**小程序代码**决定的，做成勾选就是假开关 |
| **客户自定义角色** | 本轮只覆盖系统内置角色；自定义角色走"出厂默认兜底"，等你说要再补 |
| **小程序端也能改这些配置** | 权限配置是后台操作，手机端不该开这个口子 |
