## 一、三个根因（都已修）

### P0-1 「定稿」列是**恒假判据**（老板看到的自相矛盾的真身）

`forecast_order_board` 的 `finalized` 读：

```sql
SELECT 1 FROM forecast_audit_decisions WHERE period_start=? AND period_end=? LIMIT 1
```

而那张表是**已废弃的「审核台定稿量」**：

- 生产实测 `tenant_1.forecast_audit_decisions` **0 行**，而 5 个期次 `status` **全是 closed**；
- 唯一写它的 `forecast_audit.py::adopt`，**界面自己写着**「历史流程，仅用于追溯」；
- ⇒ 该列**永远显示「未定稿」**，与同屏「状态 = 已关闭」给出**相反结论** —— 而两列说的是同一件事。

**附带同族病灶**：即便那张表有行，判据键用的是**可改的日期窗口**（期次改一次 `order_end` 就永久失配）。
v279 已把加单归属改成 `period_id`，**这里漏改**。

**修法**：定稿 = `status == 'closed'`（全站唯一口径），由调用方按 `p["status"]` 直接判定，不再绕第三张表。

### P0-2 自动关单会**撤销人工操作**

```python
elif now_str >= ca:          # 过点后每轮无条件重试
```

而 `_auto_period_close` 只查「open 且日期匹配」、**无豁免** ⇒ 人工重开 **2~5 分钟**内必被撤销。
生产日志实证（2026-09-27 期次 #19）：

```
20:04:53 人工重开 → 20:07:31 自动撤销（2 分 38 秒）
20:12:25 人工重开 → 20:17:34 自动撤销（5 分 09 秒）
```

**修法**：自动路径加 `AND COALESCE(reopened_at,'')=''` 豁免。

### P0-3 自动关单**零留痕**

`_auto_period_close` **直调 db 层、不经端点** ⇒ 端点上的 `_audit_period_op` **全被绕过**；
而 `forecast_periods` **没有任何关闭时间列** ⇒「这期谁在何时怎么关的」只能翻 `journalctl`，
**日志一滚，答案永久丢失**。

## 二、老板拍板的三项改造

### ① 推送出口定在「人确认的那一次」

自动关单**不推**加单/减单通知 ⇒ 期次标「尚未推送」＋手动推送按钮。

> 理由（已写进 docstring）：自动关单 11:00，而 v305 授权改单可改到 12:00
> ⇒ 11:00 推的是**一小时后还会被改掉**的版本，而推送**不可撤回**。

### ② 付款口径改走「报单合计 + 加单」

- 唯一实现：`routers/product_targets.period_order_amount()`，`/payments/compute` 与 `/payments/preview` **共用**
  （两处各写一份必然漂移，而这笔钱要拿去付厂家）。
- 旧口径同样读那张 **0 行表** ⇒ `order_amount` 恒 0 ⇒ `gap = max(0, 0−balance) = 0`
  ⇒ 旧前端显示**绿色**「需付款 ¥0」——数字 0、颜色绿、零报错，**而真实值约 ¥4657**。
- 叠加缺陷：旧前端读 `r.need_to_pay`、后端只返回 `need_pay` ⇒ 三元判断**恒走 else**
  ⇒ 恒绿色，且「确认已付款」按钮**永不出现**。**两个缺陷叠加，界面看起来完全正常。**

### ③ 「重开」拆成「解锁编辑」+「恢复报单」

v219 的「重开」同时做了两件性质完全不同的事：

| 语义 | `mode` | `status` | 销售小程序报单通道 | 适用场景 |
|---|---|---|---|---|
| **解锁编辑** | `unlock` | **不动**（保持 closed） | 照旧**关着** | 「我只要改一个错数」（绝大多数） |
| **恢复报单** | `full`（默认） | 回 `open` | **重新打开** | 确实要让销售补报（= 原 v219 行为） |

- 默认值取 `full` = **向后兼容**（旧调用方不带 `mode` 时行为逐字不变）。
- 🔴 **期次本来就 open 时只返回 True、绝不写 `reopened_at`** —— 否则种下
  「本期永不被自动关单」的静默副作用。

## 三、新增的数据结构（五列）

`forecast_periods` 新增，**权威建表 DDL ＋ `_safe_migrate` 两处齐**（`CREATE TABLE IF NOT EXISTS`
不给已存在的表补列 —— 本项目铁律）：

| 列 | 语义 | 关键设计 |
|---|---|---|
| `closed_at` / `closed_by` | 关闭时刻 / 操作人（自动 = `'系统'`） | 🔴 留痕**只在真跃迁（open→closed）时写**，重复点不刷新 |
| `closed_mode` | `'manual'` \| `'auto'` | 两条路径**行为不同**（自动不发通知）⇒ 不落库就 = 同一 status 两种含义不可判 |
| `reopened_at` | 最近一次**人工重开/解锁**时刻，**同时是自动关单撤回键** | 只写「人已接管」；关闭时不回填；已 open 时不写 |
| `alloc_pushed_at` | 加单/减单通知**最后一次真正推送**时刻 | 用**时刻**不用布尔（要能答「哪期没推」「上次何时推」） |

**存量迁移负担：零** —— 四库实测这些列都不存在，`ADD COLUMN ... DEFAULT ''` 一律成功；
存量行读出空串，语义 =「历史期次没有留痕」，**如实**。

## 八、本轮方法论收获（已写入技能）

1. **生产 `assets/` 是历次构建并集 ⇒ 按「逻辑名」取文件会撞上旧批次**
   （症状一眼可辨：比对输出里**同一个 SPA 引用了 3 个不同的入口 chunk**）
   ⇒ 正解 = **mtime 圈定生效批次**，判据是两个数字必须对上：
   `生产生效批次文件数 == 本地 dist 文件数` 且配对后 **`本地独有 == 0` 且 `生产独有 == 0`**。
   修正前「33 变 / 1 独有 / 145 仅生产有」→ 修正后「29 变 / 0 / 0」。
2. **级联 vs 真实改动 = 「归一化文件名后逐字符比对」**：
   `NORM = r'-[A-Za-z0-9_\-]{8}\.(js|css)'`（⚠️ 字符集**必须含 `-`**，否则
   `Shell-Bs-L7rJE.js` 这类含连字符的哈希产生**假阳性**）。
   ⚠️ **不要**用 `difflib(autojunk=False)` 直接比 400KB 压缩文件（实测 **2 分钟跑不完**）。
