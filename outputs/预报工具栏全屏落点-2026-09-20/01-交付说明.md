**日期**：2026-09-20　**状态**：已上线（生产 hergent.cn）
**用户诉求**：
> ①「将『改单』按钮及其点击后弹出的所有功能按钮统一移动到表格工具栏中，使改单及改单后出现的功能按钮
>   能够在一屏内完整展示，同时确保工具栏内所有内容仅占一行，不出现横向滚动条。」
> ②（澄清）「因为用户大概率会用**全屏功能**来查看和修改预报订单，所以要把这些按钮放在表格工具栏，
>   便于用户在全屏模式下直接操作，**不需要退出全屏模式才能进行操作**。」
> ③（拍板）方案 **A：全屏专属**。

## 一、你遇到的到底是什么问题（根因）

全屏层是不透明图层：

```css
.grid-area.is-fs{position:fixed;inset:0;z-index:1000;background:var(--bg);padding:12px}
```

它铺满整个屏幕，把**主工具栏整条盖住** —— 而「改单」按钮正挂在主工具栏上。

**真机取证**（对按钮中心做 `elementFromPoint`）：

```
btnBox  = [1148, 208, 74, 32]   ← 按钮确实在 DOM 里、坐标也正常
topEl   = ""                     ← 但最上层是一个无 class 的元素（全屏层）
hitIsBtn = false                 ← 点不到
```

⇒ **按钮看得见位置、但物理上点不到**。这解释了你说的「全屏时要退出才操作得了」。

修复后同一测试：`topEl = "btn btn-sm btn-primary"`、`hitIsBtn = true` ✅

## 二、为什么只能是「全屏专属」（方案 A）

不是偏好，是**实测放不下**（生产 hergent.cn，5 视口）：

| 塞入编辑组后 | 1280 | 1366 | 1440 | 1680 | 1920 |
|---|---|---|---|---|---|
| **全屏**（可用宽 = 视口 − 24） | −139 | −53 | +21 | +261 | +501 |
| **非全屏**（要扣侧栏 248 + 页面 40 + 卡片 36） | −433 | −347 | −273 | −33 | +207 |

（负数 = 会折行，单位 px）

非全屏 1440 的那一行只有 1122px，而编辑组自身就占 428px。**「两态都搬」与「只占一行」数学上冲突。**
而全屏层 `inset:0` 不吃侧栏与内边距 ⇒ **可用宽多约 300px**，这才是「全屏放得下」的物理原因。

### 🔴 最贵的一条：让位判据必须三条件齐全

```js
const fsRowHosting = computed(() => gridFullscreen.value && viewMode.value === 'cross' && !crossLoading.value)
```

- 漏 `!crossLoading` ⇒ **死按钮**：重新加载时 `.grid-area` 整块被骨架替换、全屏层消失，
  而此时主工具栏那份已让位 ⇒ 屏幕上**一个「改单」都没有**，点了没反应**且不报任何错**。
- 漏 `viewMode === 'cross'` ⇒ 逐单补录视图下表格工具行不在 DOM，同样无入口。
- 做成「让位」（不渲染）而不是「两份并存」：被全屏层盖住那份**仍在 Tab 序与读屏里**（重复控件）。

### 全屏专属收紧清单（非全屏一个像素不动）

| 手法 | 省 |
|---|---|
| 计数徽标 → 图标形态（文案进 `title` + `aria-label`，**信息不丢**） | ~150 ×2 |
| 隐藏行首那条装饰分隔条（**编辑组前面那条保留**） | 19 |
| 行距 8 → 6 | ~24 |
| 缩放控件 `compact`（－/＋/重置仍在，能力不丢） | 66 |
| 编辑组按钮横向内边距 12 → 9 | ~30 |

**为什么收紧量比评估时说的 139px 大得多**：评估只算了「塞入编辑组」这一项，真机抓出两个漏算的变量 ——
① **状态条宽度随文案变**（实测 clean 74 / dirty 110 / saved 97 px）；
② **两个计数徽标可同时出现**（勾「仅显示有报单」+ 未勾「显示全部商品」）。
⇒ 最坏态比评估时的稳态宽约 230px。

### 离线不变量护栏 `v209-fs-toolbar-verify.mjs` — **36/36**
