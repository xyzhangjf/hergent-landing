## 三、根因

### 唯一根因：全仓从未声明 `color-scheme`

```bash
$ grep -rn "color-scheme" src/
(空 —— 一次都没有出现)
```

原生控件的**弹窗部分**（日历年历、月份选择、时间列表、`<select>` 下拉、滚动条）由**浏览器自己绘制**，
既不在 DOM 里、也不受页面 CSS 影响，唯一控制手段是 CSS 标准属性 **`color-scheme`**。

它没被声明 ⇒ 浏览器按默认的「浅色」绘制所有原生控件 ⇒ **深色模式下弹窗恒为白底**。

### 为什么"输入框本体是深色、只有弹窗是白的"

各控件类都用 CSS 变量，本体会跟着主题走，所以视觉上很割裂：

```css
.input{ background:var(--bg3); }   /* 深色下 = #3a3a3c 深灰 ✓ 本体正常 */
.fld  { background:var(--bg);  }   /* 深色下 = #1c1c1e 近黑 ✓ */
```

而**弹窗**是浏览器画的浅色层 ⇒ 用户看到「深色输入框 → 点开一片白」。这正是所报现象。

### 同族发现（一并核实，非本次问题）

- `input,select,textarea{...color:var(--t1)}`（`variables.css:228`）——**全局已保证字色**，故输入框内文字在深色下一直可读。
  本轮曾顺手给 `.input` 补 `color:var(--t1)`，核实后发现**与既有生效值完全相同、纯冗余**，已按最小改动原则**回退**。
- `::-webkit-calendar-picker-indicator` 未单独处理 —— **不需要**：`color-scheme` 生效后浏览器会自动把日历图标反色。
- 全仓硬编码白色背景共 8 处，均为**滑块圆点**（开关上的白点，设计如此）与浅色标签底，**不属日期选择器**，未改动。

## 四、修复方式

**只改「根属性」，不逐个组件改样式**——这是本问题的正解，因为 118 处控件共用同一机制。

| # | 文件 | 位置 | 改动 | 作用 |
|---|---|---|---|---|
| 1 | `src/styles/variables.css` | `:root{}` 顶部 | `color-scheme:light;` | 浅色态下原生弹窗按浅色绘制 |
| 2 | `src/styles/variables.css` | `:root.dark{}` 顶部 | `color-scheme:dark;` | **深色态下原生弹窗按深色绘制（本问题的修复本体）** |
| 3 | `index.html` | `<meta name="theme-color">` + 内联脚本 | 加 `id` ＋ `MutationObserver` 同步 | 浏览器 UI 配色（移动端地址栏/状态栏）随主题切换，此前恒为浅色 `#f5f5f7` |

改动规模：`variables.css` **+9 行**、`index.html` **+11 −1 行**；**零组件级改动**。

```css
/* 改动 1、2 的实际内容（variables.css） */
:root{
  color-scheme:light;
  ...
}
:root.dark{
  color-scheme:dark;
  ...
}
```

```html
<!-- 改动 3 的实际内容（index.html） -->
<meta name="theme-color" content="#f5f5f7" id="meta-theme-color">
...
function syncThemeColor(){
  var mc=document.getElementById('meta-theme-color');
  if(mc){mc.setAttribute('content', de.classList.contains('dark')?'#1c1c1e':'#f5f5f7');}
}
syncThemeColor();
new MutationObserver(syncThemeColor).observe(de,{attributes:true,attributeFilter:['class']});
```

> 🔴 **为什么不改 `store/index.js` 里的 `setTheme()`**：该文件当时（15:12）**正被另一个会话编辑、且带未提交改动**
> ⇒ 按并行会话纪律**不碰**。改用 `MutationObserver` 监听 `<html>` 的 class 变化实现同样效果，
> 动态同步内聚在 `index.html` 一处，**风险面最小**。

### 判别力自证（避免"探针恒绿"）

1. **反例必须红**：生产旧包两态都是 `normal` ⇒ 探针能识别"没修"。若探针恒绿，这里就会假通过。
2. **`data-v-*` 对照项**：`.ap-in` 带 scoped 与不带 scoped 的背景分别为
   `rgb(44,44,46)`（= `--bg2` 深色值，说明 scoped 样式命中）与 `rgb(59,59,59)`（浏览器默认底）
   ⇒ 证明注入元素与真实页面元素**等价**，不是"我造了个假元素"。
3. **踩坑记录**：第一版探针读 `meta` 恒为浅色值——原因是 `MutationObserver` 回调是微任务、读取太早。
   已改为「改完 class 等 60 毫秒再读」后转为正确值。**这是探针自身的假红，不是产品问题。**

### 两个点名界面的确认结论

- **「报单配置」**：它由 `Forecast.vue` 的 `config` 页签渲染，其内日期/时间控件为
  `AutoPeriodBlock.vue`（3 个 `time`）与 `ReminderConfig.vue`（3 个 `time`），另有新建期次的 `date`。
  → 实测评级：深色 `dark` ✅ **已修复**
- **「商品目标」**：`ProductTarget.vue` 的 2 个 `month` 控件（`.fld.pt-fld-m`），其样式与上述控件
  同属构建产物 `Forecast-Cylyj27n.css`。
  → 实测评级：深色 `dark` ✅ **已修复**

> 说明：`color-scheme` 是**根继承属性**，只要 `<html class="dark">` 成立，页面上**任何**原生控件都生效，
> 与具体页面/组件无关。以上实测正是对这一点的现场印证。
