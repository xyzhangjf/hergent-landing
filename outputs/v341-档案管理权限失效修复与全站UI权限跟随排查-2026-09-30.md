## 一、一句话结论

你报的「撤了主管的档案管理权限，郝洋登录后仍看得见档案管理」——**根因不是权限没保存，而是前端侧栏入口的判据与权限页的开关不是同一个东西**。已修复并**已上线**：现在「设置 › 权限」里撤掉「档案管理」，该角色的侧栏入口**当次刷新后即消失**（真机 ② 实测 0 个；把权限加回则入口重新出现，真机 ③）。

同时全站排查发现并修复了**同族的另外 5 处**（副驾斜杠命令 + 4 处「配置驱动跳转」缺守卫 / 硬编码角色）。只余 1 处**纯注释过时**未动（该文件此刻有并行会话的在途改动，留作下一批单独订正）。

> 本次沉淀的规律：**凡「跳转路径来自配置表 / 后端下发 / 数组」的入口最容易漏判据** —— 写代码的人手上没有具体 path，于是只判了"这个能力开通了吗"，漏了"**当前这个人**有权限吗"。`ready`（租户级）与 `canSee`（账号级）**不是同一件事**。

## 二、根因（为什么会"撤了还看得见"）

档案管理入口的显示由**两条轴**共同决定（`hergent-cn-v2/src/constants/pages.js`）：

| 轴 | 含义 | 读什么 | 谁在管 |
|---|---|---|---|
| `roles` | 这一页**天然只给哪几类人** | 角色白名单 `BIZ_ROLES` | 产品内置，权限页改不动 |
| `module` | 本租户**有没有买/开这个能力** | 后端权限模块 | 你在「设置 › 权限」勾的就是它 |

修复前那一行是这样写的：

```js
'/archive': { title: '档案管理', moduleAny: ['hr','crm','data','stock'], roles: BIZ_ROLES }
```

`moduleAny` = **四个模块里有任意一个就显示**。于是：

1. 你在权限页撤掉的是**「档案管理」= `data` 模块**（数据轴）；
2. 但主管**还持有 `stock`**——这是 v332b 为了让主管能用「货损核算」特意授予的；
3. `moduleAny` 一看 `stock` 还在 → **判定"这一页他还有用" → 入口照常显示**。

**一句话**：入口问的是"你手上还有没有一个档案类的模块"，而你以为入口问的是"档案管理这个能力你开不开"。两句话长得像，其实不是同一句。

## 三、修复内容（2 处，共 3 个文件）

### ① 档案管理入口（你报的那个）

`hergent-cn-v2/src/constants/pages.js`

```diff
- '/archive': { title: '档案管理', moduleAny: ['hr','crm','data','stock'], roles: BIZ_ROLES, cat: 'biz' }
+ '/archive': { title: '档案管理', module: 'data',                          roles: BIZ_ROLES, cat: 'biz' }
```

改成**单值 `data`** —— 与权限页那一行开关**同源**。撤 `data`，入口消失。

子页签（员工/客户/品牌/商品/仓库/价格 六条）**保持原样各自登记**，因为它们本来就该各判各的（员工要 `hr`、客户要 `crm`、仓库要 `stock`、价格只有老板/管理员/会计）。这一层不动，不会出现"进得去档案管理、点页签却 403"。

同批更新了 6 处**注释**（`pages.js` 5 处 + `Archive.vue` 1 处）——旧注释还在解释"为什么必须用 `moduleAny`"，与代码相反，留着会害下一个人改回去。

### ② 副驾斜杠命令（排查中发现，同族）

`hergent-cn-v2/src/components/CopilotDrawer.vue`

副驾输入框里敲 `/` 会弹快捷指令，其中「跳转页面」那类**只判了模块轴，漏了角色轴**：

```diff
- SLASH_COMMANDS.filter(c => (!c.module || store.canModule(c.module)) && ...)
+ SLASH_COMMANDS.filter(c => (!c.module || store.canModule(c.module)) &&
+   (!c.path || canSee(c.path)) && ...)     // ← 新增：跳转类命令必须过入口判据
```

**这个缺口长什么样**：`/预报` 这条命令**没配模块**（`{ cmd:'/预报', path:'/forecast' }`），于是「模块轴」那半句短路放行 ⇒ **任何角色**都能在副驾里看到 `/预报`；但 `/forecast` 的角色名单只放管理员/老板/主管，业务员或租户自建角色**点了会被弹回工作台**。这就是本项目定义的「**假入口**」（入口在、点进去被拒）。同族还有 `/返利政策`。

修完：这两条命令对不在名单里的角色**直接不显示**，而不是"显示了再拒绝"。

## 五、零回归论证（谁受影响、谁不受影响）

修复是**纯收紧**，且只动了「容器入口由谁裁决」这一句：

| 角色 | 撤 data 前 | 撤 data 后 | 说明 |
|---|---|---|---|
| **主管** | 正常 | **入口消失**（原来不消失 ← 本次修复的目标） | 唯一"撤后仍持其它档案模块"的业务岗 |
| 会计 | 正常 | 入口消失 | 一致性提升（原来撤 data 也不消失） |
| 业务员 | 正常 | 入口消失 | 同上（业务员已收紧为仅小程序，实际不在网页端影响面） |
| 管理员 / 老板 | 正常 | 入口消失 | 持有 `"*"` 全权限，**实际不会走到"撤 data"**；用例 C07/C08 仅作逻辑验证 |
| 员工 / 司机 / 导购 / 分销商 | 无入口（角色门槛） | 无入口 | 与模块无关，**完全不受影响** |

**结论：不撤权限的人，行为一模一样；撤了权限的人，入口按预期消失。** 六个页签的独立判据未动，页面内不会出现新的 403。
