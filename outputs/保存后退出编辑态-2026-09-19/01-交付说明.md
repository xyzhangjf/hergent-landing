## 二、变更

**只动一个文件**：`hergent-cn-v2/src/pages/Forecast.vue`（无后端、无 DDL、无迁移）

### 2.1 把「退出编辑态」收敛成唯一收口（核心）

改动前 `exitEdit()` 一个函数既管「用户点取消」又内联了退出动作。改动后拆成三个：

```
leaveEdit()            ← 唯一收口：editMode=false / loadingEdit=false / errListOpen=false
                          / pagingOn=false / loadCross()（回到只读）
  ├─ exitEdit()            用户点「取消」→ 有未保存改动时二次确认
  └─ exitEditAfterSave()   保存成功 → **永不确认**
```

🔴 **为什么不能让保存路径复用 `exitEdit()`**：它有 dirty 判据，会弹
「放弃本次编辑？未保存的改动将不会提交」—— 内容刚刚落库，这句话**纯属误导**
（与 v201 修掉的那处是同一个坑，只是入口从「用户点取消」变成「系统自动退出」）。

🔴 **为什么不做成带参函数**：模板里是 `@click="exitEdit"`（不带括号），
Vue 会把 **MouseEvent** 当第一个实参传进来 —— 改签名就要同步改模板，
稍不留神就是「取消按钮悄悄跳过确认框」。独立函数零耦合。

🔴 **为什么 `loadCross()` 刻意不 `await`**：与「取消」路径保持完全一致的行为。
若在此 await，`loadCross` 的异常会冒泡进 `saveEdits` 的 try/catch ⇒
**明明保存成功了却弹「保存失败」**，比不刷新严重得多。

### 2.2 基线快照必须挪到退出之前

```js
// 改前：await loadEditGrid() 之后才 clone(cross.value)
// 改后：
lastSavedSnap.value = clone(cross.value)   // ← 此时 cross 还是编辑态对象
exitEditAfterSave()                        // ← 之后 loadCross 会重建 cross.value
```

`leaveEdit()` 会把 `cross.value` 重建为**只读态**对象（字段集与编辑态不同：
没有 `_new` / `casePrice` 这类编辑态专有字段）。顺序颠倒 ⇒ clone 到残缺基线 ⇒
「回退到上次保存」会退歪。

### 2.3 订正 4 处已被推翻的注释

「保留编辑态本身是有意的」这个前提被本次改动推翻，涉及注释全部改写
（`` :115 `` 模板注释 / `:3244` loadEditGrid 时机 / `:5283` v201 段开篇 / `:5296` 基线机制）。
**注释不得与实现矛盾** —— 本项目的铁律。

⚠️ 但 `dirtySinceSave` / `lastSavedAt` / 状态条**保留未删**：编辑态里反复改单时，
「有未保存的改动」仍是用户离开页面前唯一能看到的警告。
