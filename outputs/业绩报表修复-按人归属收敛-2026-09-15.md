## 二、病灶（两个错叠乘，缺一都解释不了"全 0"）

### 病灶 1：名单取自「租户库那份陈旧 `users`」

`get_db()` 在租户上下文里指向 `tenant_N.db`，而那张 `users` 是主库的历史副本：

| tenant_1.db 的 `users` | 主库 `users`（本租户在册） |
|---|---|
| admin / boss / **accountant** / **sales** / **warehouse** / **driver** | admin / boss / mptest / mptestsp / 18671058882 |

加粗的 4 个账号**主库里根本不存在** —— 它们**永远登不进去**（登录走 `/api/auth`，
在 `_TENANT_PUBLIC_PREFIXES` 里 → 中间件强制 `set_tenant_context(None)` → 读主库）。
报表却拿这张表当统计名单 → **统计对象整个错位**。

### 病灶 2：`operator_id` 存的是**人名**，报表却拿 id 去比

```
sale_orders.operator_id 分布（tenant_1）： '张俊峰' → 580 单 / ¥2,141,396.50
routers/sales.py::_operator_for_role() 注释：
    "We use display_name to stay consistent with the existing operator_id
     convention (historical orders + RMA all store the display name)."
```

而三个报表用的是 `operator_id = CAST(users.id AS TEXT)` / `str(users.id)`
→ 与 `'张俊峰'` **永不相交**。

> 本轮**不迁移历史数据**：人名口径是既有约定，且 `_operator_for_role()` 会继续按人名写。
> 正确做法是让**读取端同时认三种存法**。

## 三、改动（2 文件，+227 / −61）

### 新增唯一实现（`server/erp_db.py`，`employee_account_map` 之后）

```
SO_ACTIVE_STATUSES     = ('delivered','signed')   口径常量，与 profit/sales/BI 报表同一套
sales_roster()         名单：**主库** users ⨝ user_tenants，同名账号合并为一个人
sales_roster_index()   匹配索引 by_name / by_username / by_uid / by_key
sales_operator_owner() operator_id 任意存法 → (归组键, 是否绑定账号)
sales_operator_stats() 唯一数据源：按人聚合 sales/orders/customers/order_received/cash_income
```

**匹配序**：① 精确 `display_name` → ② 精确 `username` → ③ 纯数字 → `uid` → ④ 都命中不了 → 原样返回。

第 ④ 类**不丢弃**，以 `bound=False` 单列一行 ⇒ **Σ(sales) 恒等于该期间全量订单金额**（有断言）。
这条是「降级即抹掉」铁律的落地：宁可多一行「未填写经手人」，也不许业绩被静默吞掉。

### 三个函数改走唯一实现（对外字段一个没动）

- `get_salesperson_report()`：补 `status IN SO_ACTIVE_STATUSES`（原实现**无状态过滤**，与 profit/sales/BI 口径不一致）
- `get_sales_leaderboard(month)`：三个 top 榜**过滤 0 值**（无单时返回 `[]`，而不是「🥇某某 ¥0」），回传 `month` / `has_data`
- `calculate_commissions(month)`：`min_sales` / `rate_pct` 补 None 兜底

### 消除第二份拷贝（`server/db/queries/reports.py`）

`get_sales_leaderboard()` 在这里有**第二份拷贝**（同 bug 独立演化），被
`db/queries/finance.py::get_dashboard_full()` 调用 —— 即 **`/api/dashboard/full` 的龙虎榜走的是它**。
现改为**惰性委托** erp_db 的唯一实现，两条路径**恒等**。

> 必须函数体内惰性 import：erp_db → db.queries.finance → db.queries.reports，模块级反向 import 会成环。

## 五、口径澄清（**不是 bug**，别误以为没修好）
