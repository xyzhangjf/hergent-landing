# SOUL.md 收敛为「单一权威源 + 自动下发」

日期：2026-09-25　·　状态：已上线并验证

---

## 1. 要解决的问题

`SOUL.md`（副驾的人格/协议层）在生产上有**三份拷贝**，且它们分属**两个不同的 Hermes**：

| 路径 | 谁在读 |
|---|---|
| `/root/.hermes/SOUL.md` | **全局 Hermes** —— **Web 副驾**走这条 |
| `/opt/hermes-tenants/hergent_t<N>/SOUL.md` | **租户 Hermes** —— **企微/飞书等 IM** 走这条 |
| `/opt/hermes-tenants/_seed/SOUL.md` | 新租户的播种模板 |

🔴 实测它们**确实漂移过**（本次修围栏外泄时，只改了租户那份，用 Web 一测"看着没生效"，差点误判）。
而**提示词改漏一份 = 某条渠道静默沿用旧规矩**，症状极难发现（"网页改了、企微没改"）。

---

## 2. 方案

**权威源 = 仓库里的 `server/prompts/SOUL.md`**（随代码做版本管理），后端负责**下发**与**漂移体检**：

- 新增 `server/soul_sync.py`：`status()` 体检 / `sync()` 下发（也可直接 `python3 soul_sync.py [--apply]`）。
- 新增两个管理员端点：`GET /api/ai/soul-status`、`POST /api/ai/soul-sync`（`admin`/`boss` 才可调）。

**安全纪律**：只覆盖 `SOUL.md` 一个文件 · 内容相同**不写**（幂等） · 覆盖前**备份**为 `SOUL.md.bak-<时间戳>` · 全程**绝不抛错**。

---

## 3. 🔴 过程中撞到的两个真问题（都已解）

### 3.1 ERP 服务带 systemd 沙箱，**进不了 `/root`**
第一次下发时全局那份报 `Permission denied`；更糟的是**体检接口直接 500** ——
即"体检本身静默失效"，正是本仓库反复吃过的亏。

**解法（双管齐下）**：
1. **全局那份改成软链**（部署时由 root 一次性设置）：
   `/root/.hermes/SOUL.md -> /opt/hergent-erp/prompts/SOUL.md`
   ⇒ 它**结构上不可能漂移**，也不需要应用去下发。
2. **体检/下发逐目标容错**：异常一律转成状态（`unreachable` 并带原因），**接口永不 500**。

### 3.2 「沙箱不可达」≠「下发失败」
沙箱下应用**连 `lstat` 都做不到**，于是每次 `sync()` 都把全局那条报成 `failed` —— 这是**噪声，不是事实**（它已是软链，本就不需要下发）。
**解法**：结果分四桶 —— `updated` / `unchanged` / `unreachable`（附原因）/ `failed`；`ok` 只看 `failed` 是否为空。

## 4. 验证（生产实测）

| 检查 | 结果 |
|---|---|
| 体检接口 | ✅ `200`，逐目标如实：`global=unreachable(沙箱)`、`seed=same`、`t1=same` |
| 下发分桶 | ✅ `ok=True` · `updated=[]` · `unchanged=[seed, t1]` · `unreachable=[global(Web)]` · **`failed=[]`** |
| **漂移闭环** | ✅ 往 `_seed` 追加脏行 → 体检 `in_sync=False drift_count=1` → 下发 → 复检 `in_sync=True` |
| 备份 | ✅ 生成 `SOUL.md.bak-<时间戳>` |
| 权限门禁 | ✅ `supervisor → 403`、匿名 `→ 401` |
| 四份 md5 | ✅ **全等** `b3036bcd7c27…` |

## 5. 用法

```bash
# 体检（只读）
cd /opt/hergent-erp && python3 soul_sync.py
# 下发
cd /opt/hergent-erp && python3 soul_sync.py --apply
```
或调接口（管理员）：`GET /api/ai/soul-status` / `POST /api/ai/soul-sync`。

**日常改提示词的流程（新）**：
1. 改仓库 `server/prompts/SOUL.md` → 部署到 `/opt/hergent-erp/prompts/SOUL.md`；
2. 跑一次 `soul_sync.py --apply`（或调接口）；
3. 跑一次体检确认 `in_sync=true`。

---

## 6. ⚠️ 残留边界（诚实说明）

1. **全局那条软链，应用侧无法校验**（沙箱进不了 `/root`）：如果哪天有人把软链换成普通文件，体检仍会报 `unreachable` 而**不会报 drift** —— 这是个盲区。
   建议：在 root 侧的巡检里加一条 `readlink /root/.hermes/SOUL.md` 校验（一行命令），或把它纳入既有的每日巡检任务。
2. `_seed/SOUL.md` 仍会被 `hermes_tenants.ensure_home()` 按"缺失才播种"复制给新租户 ⇒
   **新租户拿到的是当时 seed 的内容**；若 seed 已与权威源一致，则无差别（现已一致）。
   建议把「新租户开通」也接一次 `soul_sync`，或直接在 `ensure_home` 里改为从权威源取。
3. 本次改动**未提交**：`server/prompts/SOUL.md`（新增）· `server/soul_sync.py`（新增）· `server/routers/ai_assist.py`（新增两端点）。
