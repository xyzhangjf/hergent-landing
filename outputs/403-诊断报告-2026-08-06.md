**结论**：✅ 已修复上线，全路径恢复 200

## 一、错误发生的具体场景（实测确认）

| 路径 | 状态 | 说明 |
|---|---|---|
| `https://erp.hergent.cn/`（根目录） | **403** | 前端入口无法访问 |
| `/assets/main-*.js` / `.css` | **404** | 静态资源不存在 |
| `/api/health`（API） | **200** | 后端服务完全正常 |
| `http://47.113.224.140:8700/`（后端直连） | 502 | 直连端口被拦（安全组），但经 nginx 反代正常 |

**场景判定**：错误出现在**前端静态层**（根目录 + 静态资源），**不是 API 接口**，**不是后端服务**。这是"网站打不开但接口正常"的典型前端部署问题。

---

## 二、根本原因（完整因果链）

```
本地 static/dist/ 构建产物不完整（缺 index.html + assets/）
        │  疑似上次 vite build 被中断 / emptyOutDir 清空后写入不完整
        ▼
部署脚本 rsync -a --delete /tmp/dist-new/ /opt/hergent-erp/static/
        │  --delete 用"残缺源"同步，把服务器上"源里没有"的文件全部删除
        ▼
/opt/hergent-erp/static/index.html 和 assets/ 被删除
        ▼
nginx location / 找不到 index 文件 + autoindex off
        ▼
返回 403 Forbidden（nginx 语义：目录请求无 index 且禁止列目录 = 403，而非 404）
```

**为什么是 403 而不是 404**：nginx 处理 `GET /` 时先尝试 `index index.html;`，文件不存在后检查 `autoindex`（默认 off，禁止列出目录）——两者都不满足时返回 **403 Forbidden**。这是 nginx 的标准行为，不是权限问题。

1. **重新构建完整产物**：`cd static && VITE_BASE=/ npm run build` → dist 恢复完整（index.html + assets/main-*.js + css + vendor）

## 八、预防措施（部署防呆，强烈建议固化到脚本）

```bash

# deploy.sh — 前端部署防呆
```
