## 一、交付（做了什么）

| # | 事项 | 结果 |
|---|---|---|
| P0-1 | 修「加单/减单通知送错人」 | 收件人改由**员工 → 登录账号**的映射解析；**取不到账号就不发**，不再静默错投 |
| P1-1 | 推送出口从「保存」搬到「关闭期次（= 定稿）」 | 保存草稿**不再发通知**（原来每保存一次发一轮，收件箱被刷屏）；点「确定定稿」才推，且**重复点不会重发** |
| P1-1 | 「定稿」确认弹窗 | 标题改为「**确认定稿 · 关闭期次**」，两个按钮：「取消，继续修改」/「确定定稿」；弹窗里**明说会把加单/减单明细推给相关人员**；推送中转圈显示「定稿并推送中…」 |
| P1-2 | 「一键分摊」按钮 | 编辑态「加单(箱)」格右侧出现「**分摊**」，弹出**预演台**：列出业务员 / 预报量 / 既定占比 / 加单量，可**直接改占比或加单量**（两边联动），另有「恢复档案原比例」 |
| P1-3 | 「分不满」界面点名 | 加单标记出现第四态，如 `加6 ⚠差3`；鼠标悬停说明缺口来源（占比合计不足 / 有人报量不够被夹到 0） |
| P0-2 | 小程序消息页 | 「我的」新增「**我的通知**」入口（带未读角标）；报单页顶部出现未读通知条；点进去可看全部/未读、下拉刷新、翻页、一键全读 |

**为什么加单/减单只走「关闭期次」**：原来的「保存」是**改草稿**的动作 —— 你每改一轮就保存一次，等于每改一次就把通知重发一遍。而真正算数的终态「关闭期次」（弹窗原文本来就写着「关闭 = 定稿」）此前**一条通知都不发**。现在正好反过来。

**关于「改占比会改档案」**：分摊窗里改占比 = 改这个商品的**目标分解档案**（本月所有期次都跟着变，即"全周/全期生效"），窗内已明确提示；只想改这一次的加单量、不动档案，就改「加单(箱)」那一栏。

## 五、需确认事项

1. **小程序要在微信开发者工具里上传**（网页端部署不含小程序）。上传后建议先在体验版走一遍：登录 → 报单页看顶部有没有通知条 → 「我的 → 我的通知」能否打开。
2. **员工要能收到通知，必须在「员工档案」里关联登录账号**。没关联的员工**收不到**（这是刻意的：宁可不发，也不发错人）。要不要我列出「目前没有关联账号的员工」清单？
3. **通知只发给被加/减单的人**，没分到量的人不打扰（0 箱的通知是噪音）。
4. **改占比 = 改整个月的目标分解档案**（不只是本期）。窗内已有提示；若你希望「只改本期」也能选，需要再开一个「本期专用占比」的存储位 —— 本轮**没做**，按你选的 A1（全周/全期生效）落地。
5. 三端代码**均未提交**；后端 `erp_db.py` 是与其它在途工作共改的混合文件，我会按既有惯例**不单独提交**，等那片工作在途的作者一并入库。
