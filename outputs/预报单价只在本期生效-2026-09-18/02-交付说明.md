# 「单价(厂价/箱)」改为「只在本期生效」— 交付说明（2026-09-18）

## 一、交付

用户口径（本次变更的原始诉求）：

> 只在本期生效

即：在预报汇总表里手工录入的「单价(厂价/箱)」，**只影响本次报单（本期）的金额**，
不再反推写回商品档案、**不影响其他期次**。

| 行为 | 变更前（v190，当天早些时候上线） | 变更后（v191，本次） |
|---|---|---|
| 录入的价影响哪里 | 反推成厂价写回**商品档案** ⇒ 影响**所有期次**金额 | 存进**本期**的行级补充值 ⇒ **只影响本期** |
| 商品档案厂价 | 被改写（含字段级留痕） | **一字不动**（要改请去商品档案页） |
| 其他期次的金额 | 跟着一起变 | 完全不受影响 |
| 保存后刷新/换人打开 | 从档案读回 | 从**本期**读回（一样看得见） |
| 清空再保存 | 档案里的价被改写成原值 | 本期值归 `NULL` ⇒ 回到「按档案厂价自动算」 |

## 二、变更

### 后端（`hergent-erp`，2 个文件）

1. **`server/erp_db.py`** — 给「行级预报补充值表」`forecast_extra_qty` 加一列
   `case_price REAL DEFAULT NULL`（存「元/箱」；`NULL` = 未录入）。
   三层兜底，缺一层就会在某类库上炸：

   | 层 | 位置 | 作用 |
   |---|---|---|
   | 新建库 | `init_db` 的 v108 建表语句内加列 | 新库直接带该列 |
   | 存量主库 | **独立**一条 `_safe_migrate('v190_forecast_case_price')` | 迁移块首条 ALTER 失败会吃掉整块后续，故必须独立 |
   | 存量租户库 | `_ensure_forecast_tables()` 里建表 + 兜底 ALTER | `CREATE TABLE IF NOT EXISTS` **不给已存在的表补列**（本项目铁律）——租户库只有这一条路 |

   > 顺带修掉一个既有隐患：`forecast_extra_qty` 此前**只**由 `init_db` 的 v108 迁移创建，
   > 而 `summary` 会 `LEFT JOIN` 它 ⇒ 迁移没跑到的租户库会直接 `no such table` 崩掉汇总。
   > 现与 `forecast_audit_decisions` / `forecast_period_confirm` 同级惰性建表，理由相同。

2. **`server/routers/forecast_submissions.py`** — `save-matrix` 的行级 upsert 带上 `case_price`：
   - 非正数一律归 `NULL`（与前端「> 0 才算手工录入」同判据，避免两边语义分叉）；
   - `ON CONFLICT ... DO UPDATE SET case_price=excluded.case_price` ⇒ **清空后再保存会写回 NULL**；
   - 唯一键含 `(period_start, period_end, product_id)` ⇒ **天然按期次隔离**，这正是「只在本期生效」的机制来源。

3. **`server/erp_db.py::forecast_submission_summary`** — 两条 SQL 分支（带/不带日期窗口）
   都下发 `case_price`，且**不加 `COALESCE`**：未录入必须保持 `NULL`，不能变成 `0`，
   否则「0 元/箱」与「没录价」就得靠猜（零值即健康类陷阱）。

### 前端（`laozhangai-product`，1 个文件 `Forecast.vue`）

| # | 变更 |
|---|---|
| 1 | **摘除写档案通道**：删掉 `saveEdits()` 里的 `batchFactoryPrice(...)` 整段与 `casePriceToFactory()` 反推实现 |
| 2 | **改走本期通道**：save-matrix 载荷 `rows[]` 增加 `case_price: Number(r.casePrice) > 0 ? Number(r.casePrice) : null` |
| 3 | **两条行映射都注入** `casePrice`：`loadEditGrid`（编辑网格，新增 `casePriceByPid`，从 summary 的 rows 取、**取非空值而非累加**——单价是「价」不是「量」）与 `loadCross`（只读汇总表） |
| 4 | 文案三处改口径：表头悬停说明、网格下方口径说明（`.cross-amt-note`）、录价框悬停提示（`priceTitle`），一律改成「只在本期生效」 |
| 5 | 草稿键 `DRAFT_MASTER_KEYS` 去掉 `factory_price`（不再是用户编辑的字段；留着反而会让草稿把旧厂价带回来覆盖新档案值），保留 `casePrice` |
| 6 | 缺规格提醒改文案（不再提「未写回商品档案」） |

> 两条公式未动，仍是用户口径：`最终下单(箱) = 合计(箱) + 加单(箱)`；
> `下单金额(厂价) = 最终下单(箱) × 单价(厂价/箱)`。
