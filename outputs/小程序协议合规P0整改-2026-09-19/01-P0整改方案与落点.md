## 二、三处硬发现（都有证据）

### 发现 1：隐私弹窗从来没有样式 —— 你「看不到」是真的

`login.wxml` 里引用了 `privacy-mask` / `privacy-box` / `privacy-body` / `p-btn` 这组类名，
但**全仓没有任何一处 CSS 定义它们**（在整个 `miniprogram/` 目录里检索，只命中 `login.wxml` 自身）。

后果：弹窗没有全屏遮罩、没有白色卡片、没有滚动区，只会渲染成**登录卡片下方的一坨裸文字**。
你看到它也不会认为那是「隐私协议弹窗」——这与你反馈的「没看到」完全吻合。

> 这条已写成**防回归断言**（校验脚本 B 组第 4 项）：只要类名再次只出现在 wxml 而无 CSS 定义，脚本立刻报错。

### 发现 2：「保存期限」三份文本全都没有

《个人信息保护法》第 17 条列举的必告知事项里，**保存期限**与「目的、方式、种类」并列。
而三份文本（平台申报版、弹窗版、网页端版）**都只有「注销后删除」**——
那是**删除的触发条件**，不是**保存期限**。两者不能互相替代。

已补：账号信息在存续期间保存；预报业务数据自产生之日起保留用于核算与对账；
注销或要求删除时 **30 日**内删除或匿名化。

### 发现 3：小程序和网页端是两个产品，协议不能互相搬

| | 网页端 | 小程序 |
|---|---|---|
| 产品名 | Hergent · AI 经营副驾 | 小赫智体报单助手 |
| 数据来源 | 你上传 Excel / 连接器同步 | 员工手机填报 |
| 设备信息 | 采集登录 IP、浏览器类型、操作日志 | **不采集** |
| 大模型 | 数据传给 Hermes + DeepSeek 生成分析 | **无 AI 功能** |
| 注册 | 自助注册 | 管理员后台开通 |

网页端 `privacy.html` 里那些描述**在小程序侧一样都不发生**。
把那份照搬过来 = **申报了并未发生的收集行为**（多申报），与「少申报」同样是风险。

所以小程序的两份协议是**新写的**，不是复制的。
（网页端那两份保持不动——它们服务网页端，本身是准确的。）

## 四、非必要项是怎么拆的（不是只改文案）

**光把文案标成「非必要」是假拆分**——用户点了「同意并继续」之后依然关不掉，那句承诺就无法兑现。

所以做了三件事：

1. **弹窗内视觉区隔**：非必要项单独成块（青绿色底），标题直写「不同意也不影响你使用本程序」。
2. **真的能关**：`utils/track.js` 加了 `statDisabled()`，上报前先查；
   `wx.reportAnalytics` 不再无条件调用。已用真实逻辑验证 4/4（见第六节）。
3. **随时可撤回**：「我的提交 → 隐私设置」内可关闭统计、可撤回全部同意。
   撤回会清掉同意标记并退回登录页，登录页重新弹窗。

另外把「本机网络类型」从原段落里**挪出来单独说明**——它本就不上传不存储，不属于个人信息，
原文与「微信原生统计」混在一起，会让人误以为两项都不能拒绝。

> ⚠️ 注意：**撤回同意 ≠ 撤回预报单**。后者是业务动作（把提交的单子撤回来），在「我的提交」列表里。
