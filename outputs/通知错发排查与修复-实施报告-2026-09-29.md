# 通知错发排查与修复 —— 实施报告（v330）

**日期**：2026-09-29 ｜ **状态**：**已上线**（后端，`/opt/hergent-erp`）
**触发**：老板报障「刚登录刘小顶的小程序账号，发现他收到大量与他无关的系统通知」

## 一、结论先说：根因不在"发送"，在**"收件人维度从未建立"**

`message_center` 原先只有**人级定向**一个轴（`recipients`），而**空值被当成「广播 = 全租户可见」**。

| 时间 | 发生了什么 | 结果 |
|---|---|---|
| 2026-09-14 | 建立 `recipients` 定向（空 = 广播，非空 = 只给某人） | 当时**只有老板一人用 Web 工作台** ⇒ 广播无害 |
| 2026-09-29（v318） | 把**同一个接口**接到了**小程序**「我的通知」页 | 销售每天必开小程序 ⇒ **广播变成全员可见老板的经营告警** |
| 今天 | 刘小顶（`sales`，仅小程序）登录 | 看到 **21,351 条** |

**生产实测（改前）**

| 指标 | 读数 |
|---|---|
| 租户 1 通知总数 | **21,352** |
| 刘小顶**可见** | **21,351 条 = 100.0%** |
| `recipients` 分布 | `''`（广播）= **21,350 条**；真正定向的只有 **2 条** |
| 噪音构成 | 库存预警 13,355 ＋ 应收逾期提醒 7,924 ＝ **99.7%** |
| 内容敏感度 | 🔴 **不是"噪音"是"泄密"**：第一条正文＝「永辉民发店(¥177,014)、襄阳一中（三绿）XYB(¥67,764)、美团优选(¥47,710)，逾期总额 **¥1,315,656**」 |

**现场复现**（今天，用同角色账号打真接口）：`GET /api/messages` → **HTTP 200**，第一条就是上面那条应收逾期。

### 为什么"看起来像发对了"却全错：`sender` 被误读成收件人

界面上显示「会计 / 经营副驾 / 运营主管」，看着像"发给这些角色"；
**实际那是 `sender`（发送者标签）**，与收件人无关。写端 21 个调用点**全部只传了 `sender`**：

```python
db.message_send("库存预警", msg, "warning", "经营副驾")   # 第 4 位是 sender；recipients 默认 ""
```

⇒ 全部落成广播，而读端"广播 = 全租户可见"。

### 同源的两个附带缺陷（本轮一并处理/报告）

1. **`is_read` 是共享行上的单列，没有 per-user 维度** —— 任何一个人点「全部已读」，
   全租户（含老板）的未读一起清空。
   生产实证：`/var/log/nginx` 全量只有 **4 次** `read-all`，其中 **今天 21:56:46 那次来自小程序**
   （iPhone/微信、referer `servicewechat.com`）；同一时刻库里 21,350 行 `is_read=1`。
2. **定时任务结果通知把老板的私人任务原话广播给全员** ——
   `_execute_scheduled_task` 的 `message_send` 不带 `recipients`，而任务标题就是用户原话
   （生产 39 条：「**你帮我设个定时任务，每天上午8点把当日AI方面的重大新闻发给我**」）。

## 二、各角色「通知接收规则」（本轮定稿）

判定**两轴、从窄到宽**，唯一实现在 `db/queries/finance.py::message_visible()`：

```
① recipients 非空  ⇒ 只给这些人（人级定向：催报 / 工资条 / 定时任务结果）
② recipients 为空  ⇒ 按 event_key 查受众规则表 ⇒ 用户的**任一角色**在受众里即可见
③ 查不到（新事件忘了登记）⇒ 只给管理端 admin,boss
```

| 事件类型（`event_key`） | 受众 | 依据 |
|---|---|---|
| 盈亏快报 / 经营日报 / 经营卡简报 | `admin,boss,accountant` | 经营结果 = 老板与会计的账 |
| 应收逾期提醒 / 异常支出预警 / 合同到期提醒 | `admin,boss,accountant` | 钱的账（含金额，不给业务员） |
| AI 经营洞察 / 今日经营洞察 / 档案健康检查 | `admin,boss` | 是"给我看的结论"，不是待办 |
| 客户流失预警 | `admin,boss,sales,supervisor` | 业务线要跟进客户（不含金额） |
| 库存预警 / 效期预警·紧急 / 效期预警·提醒 | `admin,boss,accountant,supervisor,staff` | 执行面，要有人动手 |
| 本期报单已开放 / 预报催单 / 预报·新期次 | `admin,boss,sales,supervisor,distributor,staff` | 🔴 报单是**小程序那批人**自己的活 |
| `forecast_remind_emp_*` / `forecast_period_open_*` / `forecast_extra_alloc` | 同上（且**逐人定向**优先） | 催报按人发 |
| `定时任务·*` | `admin,boss`（兜底）；**正常由 `recipients` 定向给创建者** | 私人任务，结果只给设的人 |
| 未登记 | `admin,boss` | fail-closed 对业务员，**对老板绝不隐藏** |

🔴 报单线受众**必须覆盖 `sales/staff/distributor/supervisor` 四个角色** —— 它们正是
`core.ROLE_LOGIN_SCOPE` 里能在**小程序**登录的角色；漏掉 `distributor`/`staff`
＝ 有人**该报单却收不到催报**，那与"错发"是同一枚硬币的两面（一个多给、一个少给，都静默）。

# 追加：v330+1（同日续）—— 两个新报障

## 一、唐成（分销商）打开通知页 403：我上一轮只给了**受众**，没给**模块门禁**

**老板报障**：「我用他的账号登录小程序，他的小程序我的通知里显示『读取通知失败：权限不足：
你的角色『distributor』没有『首页看板』的使用权限』。」

### 根因：**通知有两个门，v330 只开了第一个**

| 门 | 谁管 | v330 状态 |
|---|---|---|
| **受众门**（这条通知该给谁） | `finance.message_visible()` | ✅ 已把 distributor 放进报单线受众 |
| **模块门**（能不能打开收件箱） | `core._check_perm` + `_PATH_MODULE_MAP` | ❌ `/api/messages` 归 `dashboard`，而 distributor 只有 `["data"]` |

生产权限实测：`distributor = ["data"]`、`staff = ["data","stock"]`。

### 为什么不能走那两条"省事"的路

| 省事做法 | 为什么错 |
|---|---|
| `"/api/messages": "data"` | `accountant = [dashboard,accounts,reports]` **没有 data** ⇒ 把会计挡在门外（而应收逾期/异常支出的受众正是会计） |
| 给 distributor 加 `dashboard` | `dashboard` 还管 `/api/dashboard`、`/api/today`（首页看板 = 经营数据）⇒ **过授权** |

### 正解：拆出独立窄模块 `messages`（与 v296 拆 `payroll` 同款）

按 **v296/v328 五项同步纪律**落（缺一处 = 全员 403 或"权限名与功能不一致"）：

| # | 落点 | 内容 |
|---|---|---|
| ① | `core._ALL_MODULES` | += `messages`（权限页能勾到） |
| ② | `server._PATH_MODULE_MAP` | `"/api/messages": "messages"`（匹配 = 首个 `startswith` 命中即停 ⇒ `/briefing`、`/read-all`、`/{mid}/read` 一并覆盖） |
| ③ | `core.MODULE_IMPACT` | += `messages`（entries/feeds 都空，但**不等于"勾了没变化"**：勾了才读得到通知数据） |
| ④ | `server.list_modules` 标签表 | += `"messages":"消息通知"` |
| ⑤ | 🔴 **迁移脚本回填 `role_permissions`** | `perms_for` = `{**_DEFAULT_PERMS, **租户自定义}` 是**按角色整表覆盖**（tenant_1 的 distributor 就存着 `["data"]`）⇒ **不迁 = 代码改了也白改** |

外加 `core.MINI_MODULES` 补 `messages`（小程序 v318 起真在调 `/api/messages`；
该常量上方注释明确要求"日后小程序加了新模块必须回来补这一项"）。
⚠️ 权限缓存 **无 TTL** ⇒ 迁完**必须重启**才生效。

**上线读数**：生产 vs 我改前本地 **SAME**（无他人在途改动）⇒ 整文件覆盖；
迁移干跑 → 落库 **17 行**（主库 1 ＋ tenant_1 9 ＋ tenant_10 7，含自定义角色「库管」）；
重启 `active` / `health=200` / **异常 0 行**。

**验证**：
- 唐成（distributor）、店员（staff）`messages` ✅；**dashboard 仍不给** ⇒ **无过授权** ✅
- 其余 8 个角色回归 ✅；`/api/messages` 与三个子路径**全部解析到 `messages`** ✅
- 销售账号端到端仍 `HTTP 200`（total=1）

🔴 **纪律**：**给人"通知受众" ≠ 给人"打开收件箱的钥匙"**。改通知可见性时
**必须同时查 RBAC 模块门禁**；否则会出现"名单里有他、他却进不去"。

⚠️ **已知缺口（v330 副作用，未修）**：**自定义角色**（如 tenant_1 的「库管」）
不在受众规则表 ⇒ 落到 `DEFAULT（admin,boss）` ⇒ **看不到任何通知**。
建议：受众规则表支持"自定义角色 → 受众"配置，或按该角色**拥有的模块**推受众
（有 `stock` ⇒ 库存/效期类）。

## 二、没给唐成设商品目标，报单却提示「有 1 个有目标的商品还没填 …533.333包」

### 真数据（生产 tenant_1）

| 项 | 值 |
|---|---|
| 唐成看到的目标 | 商品目标 **#4**「0蔗糖5连包 +3到货」 |
| 该目标 | 月份 **2026-10**（＝到货月）、**1000 箱** |
| **承接人** | 刘小顶 250 / 刘善涛 250 / 张俊峰 250 / 程欢欢 250 |
| **唐成在其中吗** | ❌ **不在**；且 `users.employee_id = 0`（**未关联员工档案**） |

### 根因：均单是**整期全量**口径，不按人过滤

`avg_target` 取 `product_targets WHERE period_month=? AND status='active'` ⇒
**每个**报单人都拿到同一个**团队**参考值；而文案写成「**有 1 个有目标的商品还没填**」
＝ **拿别人的目标、以"你的目标"的口吻对唐成说话**。

### 修法：**服务端出判据，前端决定提不提醒**

- 后端 `avg_target` 新增 `is_holder`（= 当前用户 `resolve_employee_id()` 是否落在本期
  `product_target_alloc` 名单里；`employee_id=0` 一律视为**非承接人、不猜**）
  与 `holder_employee_id`。
- 小程序 `fill.js`：`(this._avgHolder === false)` ⇒ 跳过未达标提醒。
  🔴 **只认明确的 `false`** —— 老后端不返回该字段时**照常提醒**，绝不能"降级即抹掉"。
- 判据为什么必须在服务端：归属（`employee_id` ↔ `alloc`）只有后端知道，
  前端再算一遍就是"同一规则的第二份拷贝"。

**验证（生产只读）**：承接人 = `[4,6,7,10]` ⇒
刘小顶 `employee_id=4 → is_holder=True`（照常提醒）、
唐成 `employee_id=0 → False`（不再提醒）、mptest `11 → False`；
到货月锚点仍 `target_month=2026-10` / `report_month=2026-09` ✅。
