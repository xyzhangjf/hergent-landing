## 二、变更（`Forecast.vue`）

1. **新增 `sprintPaceOf(ach)`** —— 三态判定的**唯一**实现。返回 `{state, pp, cls, text, hover}`；
   前置条件：`ach != null` 且时间进度 `frac > 0`（到货月未开始不做比较，返回 `null` 不渲染）。
2. **`sprintBarClass()` 改为复用 `sprintPaceOf()`** —— 此前着色单独写了一份 `ach >= frac`，
   会让差 0.03 个百分点的一行出现「文案写落后、进度条却判绿」的自相矛盾（同屏口径必须同源）。
3. **`sprintTimeProgress` 增 `pct1`（1 位小数）**，页头「本月时间进度」与决策横幅改用它 ——
   否则文案里的差值（0.4）与页头整数（57%）对不上，用户自己一算就是矛盾的。
   （旧整数版 `pct` 至此**已无任何引用**，保留未删：删它需再走一次「重建 + 部署生产」，
   而收益只是清掉一个死字段，不抵再次触碰生产的风险。已登记为「下次因别的原因重建 `Forecast.vue` 时顺手清理」。）
4. **进度单元格新增 `.sp-pace` + 自适应测量**：
   判据 = `el.scrollWidth <= el.clientWidth`（真实 DOM 尺寸，不用 canvas 估算）；
   放不下时加 `.is-hidden`（`visibility:hidden`，保留占位 → 行高不跳动、显隐不引起表格重排）。
   重测时机：`onMounted` / `window.resize` / `[rebateSprint, rebateSprintOpen, sprintTimeProgress]` 变化。
5. **模板**：`.sp-bar` 挂 `:title="paceHint(s)"`（**仅放不下时**返回提示，避免与可见文字重复）；
   CSS 新增 `.sp-pace` 五条规则（含三个状态色）。
6. **v182 单位改动**：`head` 拼接里 `' 个百分点'` → `'%'`（产物净 **−12 字节**：13B → 1B）；
   同步把注释从「为什么必须用百分点」改为「按用户指定用 %，靠 hover 算式消歧」。
7. **注释修正（v181）**：初版 CSS 注释写「`width:100%` ⇒ 文案不会撑宽该列」，实测**撑了 72px**，已改为实测数值。

`nowrap` 文案会被浏览器按 min-content **撑宽该列**：

这**正是文案能直接显示的原因**（撑到刚好放下），所以没有"修"它。
实测四档视口：**其他列均未换行、页面无横向滚动**。
