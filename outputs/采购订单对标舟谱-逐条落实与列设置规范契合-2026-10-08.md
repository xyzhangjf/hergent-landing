## 二、逐条改动点

### P0-1 列表页列设置 —— **规范本身**

这就是「列设置开发规范」的基准实现，后续每条涉及列的改动都以它为尺子。

| 规范条款                                                                                                                                            | 落实位置                  |
| ----------------------------------------------------------------------------------------------------------------------------------------------- | --------------------- |
| 齿轮 = `<button class="col-cfg gear">` + 线性 `<Icon>`，**长在序号列表头**的 `.th-in` 里、是该格唯一按钮；⛔ 不放工具栏                                                      | `InvPurchaseList.vue` |
| 序号列 = `.seq-th` / `.seq-cell` / `.seq-num`，样式唯一源在 `variables.css`；取值 `offset + i + 1`（服务端分页 ⇒ 跨页连续）；**不在列清单里**                                  | 同上 + `variables.css`  |
| 面板 = `.col-menu` + `.col-menu-list` + `.col-menu-reset`，`position:fixed`，位置与限高由 `useColMenu` 按齿轮 `getBoundingClientRect()` **现算**（不写死 top/left） | `useColMenu.js`（唯一实现） |
| 宿主页白名单 = `/forecast`（v400 基准）＋ `/inventory/purchase`（v408 起）                                                                                    | `UI-SPEC.md` §2.6.1   |

🔴 **一条贯穿全轮的硬约定**：`on` = 默认是否显示，**默认集 = v403 原有的 15 列**；  
新增列一律 **默认收起**。对应报告「✗ 明确不做」第 2 条：**不硬编码满列**。

### P0-5 / P0-6 加列（经办人 / 部门 / 入库时间）

- 后端：`erp_db.py` 加列 **两处**（主库 `_safe_migrate` ＋ 租户列清单）—— 缺一列在租户库上当次启动就没有。
- `received_at` 语义从 `audit_time` 里**拆出来**（原来一个字段背两种语义：审核时刻 vs 到货时刻）。  
  历史单**不回填**：生产实测 81 张单里 79 张 `status='received'` 而 `audit_time` **全空**，  
  改了不会让任何已在展示的值消失（零回退）；而且拿 `audit_time` 回填等于把语义混淆写进数据。
- 契合：**这两条只加列，没有动列表的列清单** —— 真正进列表是 P1-7。

### P1-3 三个筛选（含一个生产实测纠正）

生产实测：`purchase_orders` 81 行 `source` **全部是空串** ⇒ 「单据来源」三个选项对现有 100% 数据筛不出东西。  
⇒ 加 **`__none__` 哨兵**（后端分支 + 前端 `PO_SOURCE_OPTIONS` 加「未标注来源」），  
并在探针里做**前后端哨兵同一性**的契约检查（从前端源码抽值比对后端判据）。

### P1-4 打印设置

主按钮 + 下拉三项：`打印并计数`（`print_count += 1`）/ `直接打印`（**不计数**，重打补打用）/ `刷新打印次数`。  
探针实测：`doPrint(false)` 调计数接口 **0 次**而 `window.print()` 1 次；挖掉 `if (count)` 的**反例确实变成 1 次**。

顺带纠正一处错误注释：`ADD COLUMN … DEFAULT 0` 会把**已有行填 0**（本机 scratch 库复现确认），  
所以「历史单 `print_count` 是 NULL ⇒ 必须 COALESCE」是错的 —— COALESCE 保留为**防御**（防不带 DEFAULT 的 ADD COLUMN）。

### P1-5 上一条 / 下一条 + 导出

- 后端新函数 `purchase_order_neighbors(oid)`：口径**只有一条 = 全库 `id DESC`**（不跟随筛选，界面写明「全部采购单」）。  
  探针实测：**跳过 id 空洞**（prev/next 都不等于 `oid±1`）；`nb(999999) is None`；改 `ORDER BY` 的反例确实变值。
- 导出：新建 `src/utils/csv.js` 作为 **CSV 唯一实现**，顺带修掉 `new Date().toISOString()` 的  
  **UTC 文件名 bug**（中国 UTC+8 ⇒ 北京时间凌晨 0–8 点导出的文件名标**前一天**），改用本地日期戳。

### P1-6 明细行「历史」

同一份 `purchase_order_logs` 加行级过滤 `?product_id=`，**不另起一份实现**。  
🔴 行级归属只认**能归属的**：入库按 `batch_trace.product_id`（精确）；退货只有商品名 ⇒ 按名字回对，  
**对不上就不挂**（绝不"猜一个最像的"）；建单 / 审核 / 付款**天生没有行维度** ⇒ 行级视图里不出现。  
🔴 修一个真坑：`@click="openLogs"` 会把 `MouseEvent` 当第一个实参 ⇒ `Number(event)` = `NaN` ⇒ 过滤静默失效、还照常返回整单日志。

### P1-7 列表补列（本轮）

| 列                      | 来源                         | 后端改动      |
| ---------------------- | -------------------------- | --------- |
| 入库时间 `received_at`     | P0-6 已加的列，`SELECT po.*` 已带 | **零改动**   |
| 创建时间 `created_at`      | P0-1 已加进列清单                | **零改动**   |
| 标记 `mark`              | P0-1 已加进列清单                | **零改动**   |
| **审核人 `auditor_name`** | ❗**全系统此前没记过**              | **真留痕改动** |

「审核人」的四环留痕链（缺一环那列就恒 `—` = 静默失效）：

1. 加列 `auditor_id`（主库 + 租户库**两处**）；
2. `purchase_order_approve(oid, auditor_id='')` —— 原来**连操作人入参都没有**；
3. 两个调用方传当前登录人（🔴 其中 `routers/purchase.py` 的 `_auth(request)` **返回值原先被丢弃**）；
4. 端点层解析 `auditor_name`（复用 `_creator_names`，内部 id 不流到界面）；日志视图「审核」事件补上操作人。

口径：`CASE WHEN COALESCE(auditor_id,'')=''` **只在为空时写**（幂等保留**首次**审核人）；  
反审核**同时**清 `audit_time` 与 `auditor_id`（否则「无审核时间却有审核人」= 矛盾事实）。

**与列设置规范的契合**：两列都登记在唯一源 `PO_COLS`，**默认收起**，列宽硬值  
（本表 `table-layout:fixed`，宽度权威只能是 `<colgroup>`）；表头 / 列宽 / 数据行 / 合计行 / 面板  
**全部由 `visibleCols` 派生** ⇒ 加列**不用改模板**。探针验：默认可见列仍是 **15** 列（改造前后观感零变化），  
且 `loadCols` 会把「新登记的列」追加到已存 order 末尾 ⇒ **老用户（localStorage 存过列设置）也能看见新列**。

### P1-8 上传附件（本轮）

🔴 **报告的成本估计不成立**：实测基建早就在 —— `attachments` 表主库/租户库**都有**、  
`db.attachment_create` / `get_attachments` 已写好、`/api/attachments` 四端点（含 magic-byte 嗅探）都在。

本轮真正做的三件事：

1. **补两颗缺失的函数** `attachment_get_one` / `attachment_delete` —— 🔴 **真漏洞**：  
   `server.py:5288 / 5302` 一直在调它们，但它们**从来没被定义过** ⇒ 既有下载与删除端点**必 500**。  
   没暴露只因生产 `attachments` **0 行**（没人传过附件）—— 教科书级「恒空 = 静默失效」。  
   `attachment_delete` 只在**无其它行引用同一 file_path** 时才删盘上文件  
   （同名覆盖会让两行指向同一文件，直接删会造幽灵记录）。
2. **采购单附件走带归属校验的 psi 端点**（4 个，文件头清单同步 23 → **27**）：  
   既有通用端点只 `_auth` ⇒ 任意登录用户传别人的 `ref_id` 就能列/下/删别人的附件。
3. **前端详情页附件区**：列表 / 上传 / 下载 / 删除。

三个必须记住的点：

- 下载**不走** `/uploads/...`：nginx 只挂了 `/static/`，那个 URL 压根打不开（存了也白存）。
- 下载**不能** `<a href>`：鉴权是 Bearer 头（token 在 localStorage），浏览器跳转不带它 ⇒ 401。  
  ⇒ 新增 `apiBlob`（`client.js` 唯一实现，fetch → blob）。
- **同名附件明确拒绝**：磁盘名按文件名拼，同名会覆盖旧文件 ⇒ 拒绝并给出原因，不替用户静默改名。

### P1-9 采购结算单实体（本轮，2026-10-09）

报告原话：「我们现在用 `receivables` 一行代替。若要对账，需结算单实体」。你已拍板**要建实体**。

**先核查，避免重复造**（本仓纪律）：三个既有东西都不是它 ——  
`receivables(type='ap')` 是**每张采购单一行的应付台账**；`ap_invoices` 是**发票**（票面金额/税/三单匹配，生产 **0 行**、只被 `routers/rfq.py` 调用）；`payment_batches` 是**付款批次**（付钱）。  
⇒ 确实是全新实体，新增两张表 `purchase_settlements` / `purchase_settlement_items`。

🔴 **刻意划的边界（写进代码注释，免得后面被当成漏）**：  
**结算单只到「已确认」，不碰钱**。付款仍走 `purchase_payment_create`。  
结算是「对账」、付款是「出纳」—— 一张单同时做两件事，同一笔钱就有两条写入路径，迟早对不上。

四条「一」，是本实体的立身之本：

| 要害                  | 落地                                                     | 探针实测                          |
| ------------------- | ------------------------------------------------------ | ----------------------------- |
| 一张单据**只能进一张**未作废结算单 | 四道硬拦（非草稿不可改 / 供应商必须一致 / 跨单占用 / 本单内重复 + UNIQUE 索引）      | 跨单拒，且原因里带上**占用它的那张单号**（可查可追）  |
| 金额**快照**            | 明细存 `doc_no`/`doc_date`/`amount` 三份拷贝                  | 源单金额改成 5000，结算单**纹丝不动**（1450） |
| 金额**唯一实现**          | `_settlement_recalc`，写 `amount_total` 的 SQL 全仓**恰好一处** | 口径 `入库 − 退货 + 调整`             |
| 错加了**有出路**          | 作废 ⇒ 占用释放                                              | 作废后同一张单可以进新结算单                |

🔴 **本条最值钱的一条**：候选单据**不能**按 `purchase_returns.status` 过滤 ——  
那列从建表到现在**从没被任何代码写过**（全仓两处 INSERT 都不带它）⇒ 过滤会让退货**全部消失、零报错**。  
探针用反例自证：加过滤后退货数 **1 → 0**。

端点 **27 → 36**（9 个新端点，文件头清单同步）；前端新页 `InvPurchaseSettle.vue`（12 列 / 默认 9 列），  
侧栏落位在 **「往来」组** —— 那是 v390 建区时预留的**空组**，本条才填上第一项。

**与列设置规范契合**：新页成为**第三个齿轮宿主** ⇒ 按「五、D」纪律**落地即登记三处**  
（实现 / UI-SPEC 白名单 2 页 → **3 页** / 自检 `GEAR_HOSTS`），并补了 D2b2（齿轮逐页计数）、  
D6e2（防出现第二份定位实现）。⚠️ 该表**不给冻结列下拉**：只有序号/列/操作三段、没有冻结区  
⇒ 按 v393 纪律，不提供永远不生效的下拉。

### 8.4 🔴 四条硬口径（后来人别改歪）

1. **`pull()` 必须把 `ok` 与 `cfg` 分开返回**，不能只返回 cfg。
   「云端没有」与「网络失败」长得一模一样（都是 null），但该做的事**相反**：

   | 情况 | 返回值 | 该做什么 |
   | --- | --- | --- |
   | 云端没有 | `{ok:true, cfg:null}` | 把本地那份**推上去**（用户此前调好的列不能白调） |
   | 网络失败 | `{ok:false, cfg:null}` | **什么都别做** |

   混成一个 null ⇒ 弱网/离线时静默用本地值**覆盖云端**，而且下次联网也回不来
   （本地那份已经成了"最新"）。这是**数据损失**，不是同步。探针 A5/A6/B4/B5/B6 专测这条。

2. **响应形态异常 = 失败**，不是"云端没有"。网关插了 HTML 502、后端未升级（响应里没有 `pref`
   字段）时若当成"云端没有"，就会把本地覆盖上去。探针 A4/B7。

3. **整体覆盖，不做逐字段合并**。列配置是一个整体（顺序 + 可见性 + 冻结列互相约束），
   合并会产生"顺序来自 A 设备、可见性来自 B 设备"的**第三种状态**，两边都没见过它。

4. **失败只留痕、不弹提示**（`console.warn`）。拖一下列不是一次**显式保存**动作，用户没有
   "正在提交"的心智模型，为此弹 toast 是噪音 —— 对照 `Forecast.vue` 的「保存为方案」：
   那是显式动作，所以它失败时**必须**如实提示。两者处理**刻意不同**。

### 8.5 为什么 RBAC 要豁免这条路径（不豁免就是 403）

它服务三个**跨模块**的页面：预报汇总表（`data`）、采购订单列表 + 采购结算单列表（`inventory`）。
而 `/api/ui` 未登记在 `_PATH_MODULE_MAP` ⇒ fail-closed `MODULE_NOT_CONFIGURED`。
挑任何一个模块去登记**都是错的**：

- 归 `inventory` ⇒ 只有预报权限的角色**存不上自己的列设置**；
- 归 `data` ⇒ 只有进销存权限的角色同样存不上。

⇒ 与 `/api/ai/sessions` 那条豁免**完全同构**：它只读写**自己的界面偏好**，
不触碰任何业务数据。认证仍由中间件强制 + 端点内 `_auth` 二次兜底；
租户隔离由连接层保证（表在**租户库**）。用**完整前缀**匹配，不是 `/api/ui` 一整段。

### 9.3 🔴 五条硬口径（后来人别改歪）

1. **打印原语只留一份，且它刻意不含 `busy` 守卫。**
   `doApprovePrint` 在审核时已经把 `busy=true`，如果 `_printNow` 内部再判一次 `busy`，
   成品就是「审核成功了、纸没出来」——**而且零报错**（典型静默半截）。互斥由**调用方**负责。
   反例探针 E10/E11 双向自证。
2. **审核失败 ⇒ 一张都不打印。**
   印一张状态还写着「待审批」的单给供应商，比不打印更糟（供应商会照没经过审批的量备货）。
   所以先取审核回执、确认 `ok_count`，再打印。
3. **先刷新再打印。**
   审核改的是**状态 / 审核时间 / 审核人**三样，不刷就印，纸上的状态还是「待审批」（库里已是草稿）。
   顺序探针 E2 逐位置断言。
4. **打印前先把 `?print=1` 从 URL 摘掉，且只认首次。**
   不摘 ⇒ 用户按一次 F5 就又印一张、`print_count` 再 +1 —— 而那个计数正是判断
   「这批货到底打没打给供应商」的唯一依据，不能被刷新污染。摘参数发生在打印**之前**（探针 F2 定序）。
5. **「审核并入库」只推进到"拉起入库确认"，绝不替用户写库。**
   审核发生在**货到之前**（审的是价与量），入库发生在**货到之后**。合成一个不可逆动作，
   诱导的就是"货还没到先把账做上" ⇒ **库存虚增**（且批次/效期多半是空的，临期预警与 FEFO 一起失真）。
   ⇒ 审核成功后只调 `doConfirm()`（它自带二次确认与"有几行没登记批次"的提醒）。
   🔴 调它之前**必须先把 `busy` 放开** —— 真身 `doConfirm` 自带 `busy` 守卫，拿 `true` 进去会直接
   return，成品又是「审核好了、确认没出来」且零报错。探针 H8/H9 定序自证。

### 10.4 🔴 六条硬口径（后来人别改歪）

1. **数量与单价必须成对是小单位**：`quantity` 折小单位、`unit_price` 折「元 / 小单位」。
   只折数量不折价 ⇒ 退货金额差 ratio 倍，**且零报错**（与 v409 在 `confirm` 里那条同源）。
   可退预览给的就是这一对默认值，前端**不许再乘除一次**。
2. **可退上限的唯一实现在后端**（`purchase_order_return_preview`）。前端那道校验是
   *提前告知*，拦不住直接打接口的人 —— 而退货是**不可逆**的库存动作。
3. **ratio 读快照，不现查商品档案**：换算是**下单那一刻**的事实；档案后来改了比值，
   退货时再查会与「入库到底进了多少」对不上。
4. **`returned` 必须在「可退单」白名单里**：v408（P0-3）的口径是「只要有退货就落 `returned`」，
   部分退货的单也会变 `returned`；只放 `received/partial` ⇒ 那张单**退不了第二批**
   （搜不到 = 静默假否定）。
5. **新端点走 `/api/psi`，不复用 `/api/purchase-returns`**：后者归 `buying` 模块
   （业务员/会计都持有）⇒ 用它等于把「进销存只给老板」的闸门当场作废；
   且它的错误分支写成 `return HTTPException(...)`，**客户端拿到的是 500 而不是那句 detail**。
6. **`kind`/`from_po`/`copy` 必须 computed + watch**：`/inventory/purchase/new` 是**同一条 path**，
   `?kind` 变了 vue-router **复用同一个组件实例** ⇒ `onMounted` 不再跑，页面停在旧模式且零报错。
   （与 v403 的 `oid`/`kind` 是同一类坑。）

外加一条**刻意不做**：预览**不返回「可退总数量」** —— 不同商品的小单位不同（袋/瓶/盒），
跨商品求和是一个**没有意义的伪指标**。只回金额。

### 11.3 🔴 七条硬口径（后来人别改歪）

1. **`extra` 空则不进 INSERT 列清单**：这是本仓**第六次**用这个范式。一个字段都不填时，
   建单 SQL 与改动前**逐字一致** —— 老接口、老调用方、老测试全部零影响。
2. **加数据库列必须两处都写**（主库 `_safe_migrate` + 租户库列对账清单）。
   只写一处的症状是"公司自家库有、新开租户没有"，**且零报错**。
3. 🔴 **采购单域 `protected=True` ⇒ `_ensure` 一行都不写**。⚠️ 这条**必须靠反例证明**：
   探针 **C1** 把 `tgt["protected"]` 改成 `PROTECTED_COLUMNS` 后，采购单域被写入 **5 行**系统列
   （原为 0）—— 否则"零写入"这个断言可能是**恒真**的（因为压根没跑）。
4. **类型一律按字符串发出**（建单页数字字段也不 `Number()`）：
   `Number('abc')` = `NaN` ⇒ `JSON.stringify` 变 `null` ⇒ 后端当「清空」⇒
   **用户填了乱字符、保存后字段是空的、零报错**。发原字符串则由后端唯一实现报 400。
5. 🔴 **详情页 `saveExtra` 送「全部」字段（含空串），不是"只送改动过的"**：
   空串在后端是「**清空该字段**」，而"没提交这个键"是「保持原值」。
   只送改动键 ⇒ 用户把某格删空后保存，**界面空、库里还有**（静默假成功）。探针 **FE-G16** 反例自证。
6. 🔴 **列表页 `onMounted` 必须"先拉定义、再同步云端"**：`applySaved()` 以"已知列"过滤云端那份顺序，
   反序会让自定义键被当**未知列整个滤掉**，只能作为"新列"补到**末尾**（顺序静默丢失、零报错）。
   探针 **FE-C2a/C2b** 把这个差异真跑出来了。
7. **`mergeCustomCols` 必须是增量的**（只补缺的键），**不能重跑 `applySaved()`**：
   后者会以云端/本地那份配置为基准**整片重建** `colOrder`，而用户可能已经拖过列 ⇒
   覆盖 = **静默丢掉用户的调整**。
