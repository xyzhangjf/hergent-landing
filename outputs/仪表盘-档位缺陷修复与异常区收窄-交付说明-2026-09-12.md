## 二、变更

### ① 修缺陷：非阶梯规则不再显示伪造的「档位」，已达标行不再出现负数

**根因**（`Rebate.vue:1881` 附近，原 `dashBase` 的档位分支）：
```js
let curTierPct = 0, nextTierPct = null, toNextGap = 0
if (r.trigger_mode === 'tiered') { ... curTierPct = cur ? Number(cur.from_pct) : 0 ... }
else {                                  // ← 非阶梯分支只更新 nextTierPct
  const threshold = Number(r.trigger_threshold) || 1.0
  nextTierPct = threshold
}
```
`curTierPct` 被初始化为 `0` 后，**在 `else` 分支从未被更新** → 任何非阶梯规则（`on_target`，达标即返）都渲染成
「档位 **0.0%** → 100.0%」；而 `0%` 档在业务上根本不存在（它是初始值的泄漏）。

连带后果更严重：已达标行（110%）的 `estRebateNext - estRebate` 为 **负数** →
显示「多赚 **¥-2,400**」，还被 `val-ok` 染成**绿色** —— 语义彻底反了。

**修法（三层）**：
1. **按模式分述**：新增 `hasTiers = isTiered && tiers.length > 0`，模板据它决定渲染哪一支
   - 有档位 → 沿用「档位 X → Y，多赚 ¥Z」
   - 无档位 → 改述「**达标可得 ¥X**」（X = 达标后的返利，语义与数字都成立）
   - 并且**阶梯规则但没配档位**（`tiers_json` 空）时退回无档位口径，避免出现「未达首档 → 满档」这种怪话
2. **未达任何档时如实表述**：`curTierText` 在没命中任何档时显示「**未达首档**」，不再冒充 0% 档
3. **负数兜底**：展示层新增 `nextGain = Math.max(0, estRebateNext - estRebate)`，为 0 时整段不渲染

**修复过程中自查出并修掉的第 2 个问题**：首轮验证时「阶梯未达首档」显示成
「档位 未达首档 → **满档**」—— 因为原实现 `idx = -1 → nxt = null` 直接落到「满档」，
**把首档整个跳过了**。改为：未命中任何档时 `nxt = tiers[0]`。
现在文案是「档位 未达首档 → **30.0%**，多赚 ¥9,000」—— 对落后目标而言，这恰恰是最该看到的数字。

### ② 异常区只保留「列表里看不出来的」问题

**判据**：异常区的存在理由应是「发现列表发现不了的问题」；若它只是复述列表已有的内容，
就退化成**需要用户二次核对的摘要** —— 而摘要与明细一旦不一致，用户会开始怀疑数据。

| 原三类 | 现处置 | 理由 |
|---|---|---|
| 未填报（`nodata`） | **删除** | 达成列表里那一行本来就写着 `0.0%` + 红色条；KPI「生效目标」数为分母提供旁证 |
| 预计不达标（`risk`） | **删除** | 列表里是红色预警行 + KPI「预警规则 N」；异常区再报一遍是同一个数出现三次 |
| **规则重复（`conflict`）** | **保留** | 两条同月目标在列表里**看起来都正常**，正文任何位置都看不出来 → 这才是不可替代的职责 |

连带清理（不让死代码留下）：
- `onAnomalyClick` 删掉 `nodata` / `risk` 两个分流分支，只留 `conflict`
- 条目图标由三元收敛为固定的 `alert-triangle`，动作文案固定为「看规则 →」
- **删除专为「看预警→闪烁定位达成行」服务的 `.rank-flash` 样式 + `@keyframes rankFlash`**（该入口已不存在）
- 删除随 `nodata` 一起失效的 `.da-item.warn .da-ic{color:var(--war)}`
- 同步 3 处已失效的注释（含「未填报引导并入异常区」的旧描述）
