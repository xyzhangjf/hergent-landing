## 一、链路逐环节

```
[1 注册入口] → [2 参数校验] → [3 身份校验] → [4 账号创建] → [5 初始化] → [6 登录态]
    ✅              ✅            ❌ 断点          ✅            ✅(有瑕)      ✅(有瑕)
```

| 环节 | 实现位置 | 结论 | 证据 |
|---|---|---|---|
| **1 注册入口** | `Login.vue` 登录页「免费注册」页签 | ✅ 存在且已上线 | 表单 = 公司名 / 手机号 / 密码 + 协议勾选（未勾选则按钮禁用，PIPL 明确同意）。`register()` 调用 `POST /api/auth/register` |
| | | ⚠️ **表单没有验证码输入框** | 前端把 `code` 硬编码为 `'888888'`（`api/client.js:80`），用户即便收到短信也无处填写 |
| **2 参数校验** | `routers/auth.py:254` + `core._validate_password` | ✅ 三层齐全 | ① pydantic `AuthRegister`；② 公司名≥2 / 手机≥10 / 密码≥8；③ 密码须含数字+字母；④ 限流：同手机号与同 IP 各 10 分钟冷却 |
| **3 身份校验** | `routers/auth.py:276-285` | ❌ **断点** | 见下节拆解 |
| **4 账号创建** | `erp_db.register_user_and_tenant` | ✅ 正确 | 一次写入三处：`users`（role=`boss`、`password_changed=1`）+ `tenants`（plan=`free`、max_users=5）+ `user_tenants` 关联。重名公司 → `该公司名已注册`；用户名冲突自动加随机后缀 |
| **5 初始化** | `tenant_db_init` + `seed_demo_data` | ✅ 建库干净 / ⚠️ 种子数据有瑕 | 新租户库 **283 张表**、币种 6 条；**`users`/`tenants`/`audit_logs` 均为空**（未复制主库凭据，这点做得对）。但种子数据见「四、附带缺陷」 |
| **6 登录态** | `routers/auth.py:291-311` | ✅ 可用 / ⚠️ 一处不一致 | 注册即签发 token（uuid4）+ `sessions` 有效期 24h + 下发 `erp_token`/`hergent_tenant` cookie；前端存 localStorage 并显式传 `X-Tenant-Id`。**但响应不返回 `csrf_token`**（登录会返回）——目前靠 Bearer 请求绕过 CSRF 校验才没炸，一旦改成 cookie 认证立刻断 |

### 3 号环节为什么必然失败（三重互锁）

```
前端：code 硬编码 '888888'（无输入框）
   ↓
后端：ENV=production 且 ALLOW_SELF_REGISTER 未设置 → 走短信分支
       if code != getattr(db, "_sms_code_cache", {}).get(phone, ""):  → 400
   ↑
_sms_code_cache 全代码库仅此一处引用，从未被定义、从未被写入 → 恒为 ""
```

同时 `send-code` 走的是**另一套写入位置**（`db.set_config("sms_code_"+phone, code)`），短信网关还是占位域名 `sms-api.example.com`、`SMS_API_KEY` 未配置 → **生产根本不会发出任何短信**。

**三者互锁，导致自注册 100% 不可用。** 实测证据：

- `curl -X POST https://hergent.cn/api/auth/register`（携前端同样的 `code=888888`）→ `HTTP 400 {"detail":"短信验证码错误或已过期"}`
- 生产 `audit_logs` 中 `action LIKE '%注册%'` 的记录数 = **0**
- 生产 7 个租户全部是测试/演示账号，最近创建时间 `2026-08-16`（即演示租户），**6 月至今无一个真实客户注册进来**

> 用户侧的实际体验：登录页上「免费注册」页签公开可见，任何人填完表单点「注册并开始使用」→ 报「短信验证码错误或已过期」，且没有任何验证码输入框可补救。

## 二、数据隔离验证（业务数据：通过）

用**公开演示入口**（`POST /api/auth/demo-login`，无需凭据）取得真实会话，对生产发起越权测试：

| # | 攻击向量 | 结果 |
|---|---|---|
| 1 | `X-Tenant-Id: 1`（他人租户） | ✅ `403 TENANT_FORBIDDEN 无权访问该租户` |
| 2 | `?tenant_id=1` 查询参数 | ✅ `403` |
| 3 | 伪造 `Cookie: hergent_tenant=1` | ✅ `403` |
| 4 | `X-Tenant-Id: tenant_1`（注入非数字） | ✅ `400 TENANT_INVALID` |
| 5 | 完全不带租户上下文 | ✅ 回落自身租户 10，返回**自己**的数据 |
| 6 | 代码层：`check_user_tenant` | ✅ 自己 True / 他人 False；`get_user_tenants` 仅返回自身租户 |
| 7 | 代码层：切换租户上下文后读 `contacts` | ✅ 两租户客户名完全不同（真隔离）；租户库 `users`/`tenants` 表为空 |

**隔离机制本身设计是对的**：租户上下文用 `contextvars.ContextVar`（并发安全，非模块全局变量）；每个租户独立 `tenant_<id>.db` 文件；`tenant_middleware` 在**进入业务路由之前**用 `check_user_tenant` 做归属校验且 fail-closed；`check_user_tenant` **无角色后门**（admin 也不例外）。

## 三、但是：发现 4 个隔离/暴露缺陷

### 🔴 缺陷 1：平台元数据对任何 boss 角色开放（实测可复现）

`GET /api/tenants` 与 `GET /api/users` 的判定是 `role in ("admin", "boss")`。

问题在于 **每个自注册用户拿到的角色就是 `boss`**，而**公开演示账号也是 `boss`** —— 结果：

```
用「演示账号」（任何人点一下按钮即可获得）：
GET /api/tenants → HTTP 200，返回全部 7 个租户
   {id, name, subdomain, contact_phone, plan, is_active, created_at}  ← 含客户手机号
GET /api/users   → HTTP 200，返回全部账号
   {id, username, display_name, role}                                 ← 含真实账号名册
GET /api/tenants/1 → HTTP 200（他人租户的套餐/最大用户数/创建时间）
```

**任何人可以枚举出你的全部客户是谁、电话多少、什么套餐、什么时候注册的，以及你有哪些账号。** 业务数据没漏，但客户名单本身就是资产。

> 根因：`routers/platform.py` 的 router 前缀是 `/api`（不是 `/api/platform`），于是 `/tenants`、`/users` 落到 `_PUBLIC_PATHS` 里的 `/api/tenants` 前缀上，**中间件层的鉴权被跳过**，只剩端点内的 `_auth`/`_admin` 把关，而后者把 `boss` 等同于管理员。

### 🔴 缺陷 2：自动建库会整库复制主库（含口令哈希）

`db/connection.py:_ensure_tenant_db` 用 `src.backup(dst)` —— 这是**含数据的整库备份**，不是「只复制 schema」。触发条件是「租户 id 对应的库文件不存在」。

生产物证：`/opt/hergent-erp/tenant_tenant_1.db`（约 10 MB）

| 表 | 主库内容 | 该文件内容 |
|---|---|---|
| `users`（含 `password_hash`） | 6 | **3**（`bcrypt$…` 哈希） |
| `tenants`（含客户手机号） | 7 | **7**（全部租户） |
| `contacts` / `products` / `sale_orders` | 12 / 6 / 8 | **12 / 6 / 8** |

文件名本身还暴露了**路径拼装缺陷**：`tenant_id` 一旦是非数字字符串（如 `seed_demo.py:57` 的 `f"tenant_{tid}.db"`），就会拼出 `tenant_tenant_1.db` 这种任意文件名。影子库已完整复现该机制。

危害有二：① 「新租户库」里躺着别人的用户口令哈希与全部客户名单；② 万一某客户库丢失，系统不报错，而是**悄悄用别的数据把它填满** —— 静默的数据污染。

### 🟠 缺陷 3：`/api/tenants/{tid}` 子接口是半成品且缺校验

| 端点 | 实测 | 原因 |
|---|---|---|
| `GET /api/tenants/1/usage` | `500` | 调用不存在的 `db.tenant_usage_stats` |
| `GET /api/tenants/1/members` | `500` | 调用不存在的 `db.tenant_member_list` |

`usage` 是 `/api/tenants` 列表接口用来 enrich 用量统计的依赖 —— 也就是说，**列表接口的用量字段目前是静默缺失的**（`except → debug` 吞掉）。

更需警惕的是 `POST/DELETE /api/tenants/{tid}/members` **只做 `_auth`，完全没有租户归属校验**：这些函数一旦补全，就是「任何人可增删他人租户成员」的越权面。

### 🟡 缺陷 4：审计无法按租户归属

`audit_logs` 表结构 = `id / user_name / action / module / ref_id / detail / created_at / prev_hash / current_hash` —— **没有 `tenant_id` 列**。注册事件只写一行 `action="自助注册: <公司名>"`，且**不记录 IP / User-Agent**（登录事件反而记了 IP）。你现在无法回答「这个租户最近做过什么」。

## 五、作为开发者，你怎样追踪「谁注册了」

### 现在就能用的（只读 SQL，无需新代码）

| 数据源 | 字段 | 能回答 |
|---|---|---|
| 主库 `erp.db` → `tenants` | `id / name / subdomain / contact_phone / plan / max_users / is_active / created_at` | **这就是「谁注册了」** |
| 主库 → `users` | `username / display_name / role / is_active / created_at` | 管理员账号与开通时间 |
| 主库 → `user_tenants` | `user_id / tenant_id` | 账号↔租户归属 |
| 主库 → `sessions` | `created_at / expires_at / ip_address / user_agent_hash / last_activity` | 真实活跃度（可算「注册后有没有再来」） |
| 主库 → `audit_logs` | `action="自助注册: X"`、`登录成功 (IP: …)` | 注册/登录流水（**注册事件无 IP**） |

```bash
# 一条命令看全量注册情况（生产只读）
ssh root@47.113.224.140 "cd /opt/hergent-erp && sqlite3 -header -column erp.db \
  'SELECT t.id,t.name,t.contact_phone,t.plan,t.created_at,
          (SELECT COUNT(*) FROM user_tenants ut WHERE ut.tenant_id=t.id) AS users
   FROM tenants t ORDER BY t.id DESC;'"
```

### 现成的接口壳（但权限过宽，先别依赖）

- `GET /api/tenants` —— 列表 + 用量（用量函数缺失 → 现为 500）
- `GET /api/users` —— 名册
- `POST /api/platform/onboard` —— **一键开通新客户**，替代 SSH 手工开号，`Settings.vue` 里已经在用

### 目前的追踪缺口

1. **没有注册事件表** —— 无法记录注册 IP / UA / 来源渠道 / 邀请码 / 落地页
2. **没有激活漏斗** —— 不知道「注册了但一份数据都没导」的比例（这才是北极星）
3. **没有租户级活跃汇总** —— 全靠手工 join `sessions`
4. **没有到期/配额视图** —— `plan`、`max_users` 落了库但没人用

## 六、要不要搭管理后台：要，但不是现在第一步

**判断：需要，但优先级排在「修注册」之后。** 理由：现在跑通的客户数是 **0**，后台做得再漂亮也没有数据可管；而注册修好后，前 5~10 家客户用一条 SQL 就够管。建议把它当作「客户数 > 20 或开始收费」时的 P1 投入。

### 分层建议

| 层级 | 内容 | 何时做 |
|---|---|---|
| **P0** | 注册/激活漏斗看板 + 用户/租户**只读**名册 + 一键开通（已有 `onboard`）+ 停用/延期 | 注册修复后立刻（1 个页面） |
| **P1** | 租户健康度（最近登录 / 近 7 日活跃 / 单据量 / 导入次数 / 存储）+ 到期与套餐 + 到期提醒 | 客户数 > 20 |
| **P2** | 用量计费基础（对齐你的 B 端分层定价） | 开始收费时 |

### 后台核心功能与数据维度

| 维度 | 字段 | 用它回答的问题 |
|---|---|---|
| **身份** | 公司名 / 管理员账号 / 手机号 / 注册时间 / 注册来源 | 谁注册了、从哪来 |
| **归属** | tenant_id / 套餐 / 最大用户数 / 到期日 | 算钱、配额、续费 |
| **活跃** | 首次登录 / 最近登录 / 登录 IP / UA / 近 7 日登录次数 | 真在用还是白注册 |
| **激活** ⭐ | 首次导入时间 / 导入条数 / 首个业务单据时间 / 已启用模块数 | **北极星指标：激活率**（注册→见到自己数据的转化） |
| **用量** | 各模块单据量 / 导入次数 / 存储占用 / API 调用数 | 计费与容量规划 |
| **风险** | 同 IP 多租户 / 注册 IP 聚集 / 异常导入 / 登录失败率 | 防刷与风控 |

### 三条设计红线（务必遵守）

1. **后台必须独立鉴权** —— 新增 `platform_admin` 角色 + 独立入口（子域或独立部署）。现有的 `/api/tenants` 对 `boss` 开放是**错的**，先收紧。
2. **后台默认不直读租户业务数据** —— 只读元数据与统计口径。要看客户明细必须做成**显式、留痕的代登录（impersonation）**，并写审计。这是合规红线（你的三条红线之一：合规禁踩）。
3. **每个租户一行，可导出 CSV** —— 你现在最需要的是「一张表看清所有客户」，不是复杂 BI。

## 七、建议动作（按优先级，请选一个方向）

### 先修注册（三选一）

| 选项 | 做法 | 优点 | 代价 |
|---|---|---|---|
| **A 立即打开** | 生产 `.env` 加 `ALLOW_SELF_REGISTER=1`，配合 888888 固定码 | 10 分钟上线 | **任何人可白注册**（含刷号），必须同时加限流与人工审核 |
| **B 接真短信** | 换掉占位网关 + 统一 `_sms_code_cache` 读写 + 前端补验证码输入框与 60s 倒计时 | 正解，可长期放量 | 需接短信服务商（实名/签名报备） |
| **C 邀请码制** ⭐ | 后台生成一次性邀请码，注册页加入「邀请码」输入框，校验通过即建租户 | **最贴合你「先验证需求再放量」的节奏**；天然回答「谁通过哪张码来的」；无需短信成本 | 需在后台加码的生成/核销（约半天） |

**若只能选一个：C。** 它同时解决了「身份校验」与「用户溯源」两个问题，且不会把注册口子敞给互联网。
配套：在选定之前，**先把前端「免费注册」页签隐藏**（或点击后提示「暂为邀请制」），避免有人注册失败后对你的产品失去信任。

### 再修隔离缺陷（建议一并做，都是小改）

1. `/api/tenants`、`/api/users` 的判定从 `role in (admin,boss)` 收紧为 `platform_admin`，并把 router 前缀从 `/api` 改成 `/api/platform`（顺带消掉与 `_PUBLIC_PATHS` 的前缀碰撞）
2. `_ensure_tenant_db` 改为**只复制 schema**（对齐 `tenant_db_init` 的 `iterdump` 过滤写法），或直接复用 `tenant_db_init`
3. 补 `tenant_usage_stats` / `tenant_member_list`（或先删掉这两个死端点），并给 members 写操作加归属校验
4. `audit_logs` 增 `tenant_id` 列；注册事件补记 IP/UA
5. `register_user_and_tenant` 去掉 `seed_demo_data()`（或改为「用户主动选择载入示例数据」）；修 `sale_order_create` 传参错位；更新 `onboard` 的过期提示语
