## 二、编辑规则（一处定义，前后端同值）

| 项 | 规则 |
|---|---|
| 字段载体 | `products.arrival_lead_days`（v109 就已存在的物理列，INTEGER，默认 0） |
| 写法 | 直接填数字：`5` → 显示 `+5天`。也接受 `+5` / `+5天` / `＋5天`（全角） |
| 取值范围 | **0 ~ 365 的整数**。上界 365 只为挡住「把售价/数量填到这一格」；低温奶实际 1~7 天 |
| 小数 / 负数 / 超界 | **拒绝**：提示「到货天数请填 0~365 之间的整数」，且**不发写请求**（真机已验证零请求） |
| 留空 / 填 0 | **= 取消设置**，该商品回到「未设」（预报主表显示 `—`） |
| 未设置时的显示 | 档案页显示灰色「**未设**」（可点）；预报主表显示「—」（纯展示，不可点） |
| 详情弹层 | 显示 `+N天` / `—`（只读展示，不承担「点它就能改」的引导） |

### ⚠️ 两个「留空」语义**故意不同**，不是不一致

| 场景 | 留空的意思 | 为什么 |
|---|---|---|
| **预报导入**（模版第 8 列） | 留空 = **不改动**已有值（不清零、不影响该行导入。） | 成百行的批量动作，「空格子」多半只是「这行没意见」 |
| **商品档案**（行内编辑） | 留空 = **取消设置**（清成 0） | 用户**专门点开某一格**的定向动作，留空只能是「我要清掉它」 |

两边都各自有显式提示：导入写在模版「填写说明」里，档案页写在保存后的 toast 里
（「已取消设置（该商品在预报主表显示「—」）」）。

## 三、现在「到货周期」有几个写入口

```
预报订单导入 模版第 8 列  ──┐
                            ├──► products.arrival_lead_days ──► 预报主表列（只读）
商品档案 该列的行内编辑    ──┘                              └──► 档案页 / 详情弹层
商品档案 → 新增表单（可填）──┘                               └──► 导出 xlsx
```

三个展示面**共用同一个** `arrivalCycleText()`（`src/utils/arrival.js`）——
不会再出现「主表显示 +3天、档案页显示别的」这类漂移。

**商品导入模版（档案管理的「导入」）没有加这一列，这是有意的**：
那条导入走 `product_create`（纯 INSERT），对**已存在条码**的行会撞 `idx_products_barcode`
唯一索引并落进逐行 `errors[]`，即**不更新存量商品**。加进去只会让人以为能「导出→改→导回来」
批量回写，实际一条也改不动 —— 那是**假旋钮**。

## 四、顺带发现、但**没有动**的两处（等你决定）

   看起来像**某次导入把排期文本错填进了「商品名称」列**。要不要清理，属于数据问题，我没动。
