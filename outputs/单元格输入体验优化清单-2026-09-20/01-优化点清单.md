# 预报订单编辑网格 · 单元格输入体验优化清单

> 日期：2026-09-20 ｜ 对象：`Forecast.vue` 编辑网格（`.edit-tbl`）
> 方法：先核实**当前实现**（读源码，不凭印象），只列**尚未落地**的项。
> ⚠️ 项目里已有的《Excel填表体验分析与复刻清单.md》**已明显过时** —— 它列的 P0（列类型校验 + 错误徽标 + 表头吸顶）与多项 P1（双击进入编辑、选区 Ctrl+Enter 批量写入、Delete 清选区、Shift+点击框选）**现在都已经上线**。本清单是它的**新一轮**，并补上它没覆盖的三个维度：**自动补全、格式识别、多端交互**。
> 边界红线（沿用）：不造通用电子表格 —— 不做公式引擎、不做任意合并单元格。

---

## 0. 先看结论

**三条最值钱的**（按「减少录入摩擦 + 减少订错」排序）：

| # | 优化点 | 为什么最值钱 |
|---|---|---|
| 1 | **商品名称列补全**（现在**完全空白**，要手打全名） | 经销商 90% 的行是「上周订过的同一个品」。系统**已有完整商品主档 + 条码后四位搜索**，只是没接进这一格。 |
| 2 | **数量列「上期值 / 常用值」候选** | 报单是**周期性重复**动作。有候选 ⇒ 多数格子一键落数，不必逐格回忆。 |
| 3 | **软警告（异常检测）接入单元格** | 现在只有「红＝错」。经销商真正需要的是**「黄＝可疑」**：本周是上期的 8 倍、这个客户平时不订这个品。数据系统里都有（对比期次 / 主动预警 / 健康分），**但一格都没接进输入反馈**。这也是「AI 经营副驾」定位最能打的地方。 |

**另外两条属于「数据安全」级，优先级实际高于体验**：

- **多端校验同源**（Web 拦截了、小程序没拦 → 脏数据照样落库）
- **多端并发编辑同一期次的冲突提示**（Web 与小程序同时改 ⇒ **最后写入覆盖，静默丢数**）

## 1. 现状盘点：已经落地的（**不必再做**）

| 维度 | 已具备 |
|---|---|
| 输入方式 | 单击全选内容 / 双击·`F2` 进入输入态（定位光标）/ `Esc` 退回（v210）｜整块粘贴｜填充柄拖拽｜`Ctrl+D` 向下填充到空行前 |
| 数据校验 | 单格校验（**7 类**：非数字 / 负数 / 非整数 / 数量过大 / 商品名称必填 / 条码重复 / 取值不在候选中）｜**红框即时**｜行号标红｜错误清单（分组 + 筛选 + 点击跳转）｜保存前拦截 |

| 快捷操作 | 方向键 / `Enter`（±`Shift`）/ `Tab`（±`Shift`）/ `F2` / `Esc` / `Home` / `End` / `PageUp·Down` / `Ctrl+方向键` / `Ctrl+A·Z·Y·C·X·D·Enter` / `Delete` ｜右键菜单 ｜快捷键帮助浮层（首次自动弹） |
| 其他 | 草稿自动缓存（刷新可恢复、恢复范围如实告知）｜列筛选 / 品牌筛选 / 唯一值筛选｜列宽调整｜缩放｜全屏 ｜冻结列 ｜合计吸底 |

> 结论：表体已经是成熟的「Excel 式业务网格」。下面只列**真缺口**。

## 2. 七个维度的优化点

### 一、输入方式

#### 1.1 数量格补 `inputmode`（触屏弹数字键盘）— 价值 ★★★★☆
- **作用**：点数量格直接弹**数字键盘**，不用在字母键盘上找数字。
- **适用场景**：仓库 / 冷库里用**平板或触屏笔记本**报单；销售在客户店里用手机开网页补单。
- **现状**：**小程序端已有** `inputmode="numeric"`，**Web 端漏了** —— 两端手感不一致。
- **成本**：极低（加属性）。

#### 1.2 单位换算输入（"2箱" → 自动换算）— 价值 ★★★★★（需产品决策）
- **作用**：经销商的心智单位是**箱 / 件**，不是「小单位数量」。现在输 `12箱` 会被**明确拒绝**（错误文案就是「如「12箱」请改为 12」）⇒ **每次录入都要人工心算换算**，这是纯摩擦。
- **适用场景**：客户说「来两箱」，老板直接敲 `2箱`。
- **现状**：系统**已有**箱 ↔ 小单位换算（`rowBoxes()`、规格、`unitCount()`），**能力具备，只差输入侧识别**。
- **建议做法**：不是静默换算（有歧义风险），而是**识别 + 就地确认**：「识别到 2 箱 = 20（小单位），按 Enter 采用 / 按 Esc 保留原文」。
- **风险**：规格异构（记忆里 288 个档案中 192 个规格是**描述串**、30 个为空）⇒ **换算无定义的品必须退回原行为**，不能强算。

#### 1.3 步进微调（+ / −）— 价值 ★★★☆☆
- **作用**：报单常见形态是「上次的量 ± 几个」。有加减按钮就不必全格重输。
- **适用场景**：老客户、稳定品。
- **现状**：`type="number"` 有原生上下箭头，但格子窄、箭头太小、触屏难点；**小程序端已有 `stepper`，Web 端没有**。

#### 1.4 让"选区批量填同值"有可见入口 — 价值 ★★★★☆
- **作用**：`Ctrl+Enter`（选中一片 → 输一个值 → 全部写入）**已实现**，但**只存在于快捷键** ⇒ 不记快捷键的用户根本不知道它存在。
- **适用场景**：「把所有选中的客户列都填 10」。
- **建议**：接进**右键菜单**与工具栏，并给一句提示（已实现的功能不该靠口口相传）。

#### 1.5 复核：单格粘贴是否也走净化 — 价值 ★★☆☆☆（**待实测**）
- **疑点**：千分位净化（`parseNumInput`）只作用于**整块粘贴的解析路径**；在**单个格子里**直接粘贴走**浏览器原生行为**，`type="number"` 对 `1,234` 可能直接清空。若成立，则是「同一件事有两条路径、只有一条做了净化」。
- **建议**：先实测确认，再决定是否在单格 `@paste` 上也挂净化。

### 二、自动补全

#### 2.1 🔴 商品名称列补全 — 价值 ★★★★★（**最值钱的一条**）
- **作用**：新增商品行时，输入 2–4 个字就出候选（支持**名称模糊 + 条码后四位 + 拼音首字母**），选中即带出规格 / 单位 / 条码。
- **适用场景**：**每一次新增商品行**。现在必须手打「蒙牛红枣酸牛奶100g*10桶」这类全名 —— 慢，且极易打出**重复商品行 / 无名商品**。
- **现状**：`cell-name` 这一格**没有任何候选**（`input` 上既无 `list` 也无 `@change`）。而系统里**已有**：完整商品主档、商品搜索面板（已在用「条码后四位」搜索）。
- **额外收益**：这是**从源头治理重复商品行**的手段（比对账时再去合并划算得多）。
- **注意**：改这一格会**同时修掉一个静默缺陷** —— 商品名 input 没有 `@change`，所以**商品名的改动不进撤销栈**（`_pendingCell` 不记录），改了 Ctrl+Z 撤不回来。

#### 2.2 数量列「上期值 / 常用值」候选 — 价值 ★★★★★
- **作用**：点进数量格时给出候选：**上周同客户同商品值**、上期值、本列 Top3 常用值。
- **适用场景**：周期性报单（本产品**核心场景**）。报单本质是「在上一期基础上微调」。
- **现状**：数量格无任何候选。
- **数据来源**：系统已有对比期次能力（`compareBaseId`）与上期数据，取数成本低。

#### 2.3 候选下拉的智能化（现在只有"全量静态"）— 价值 ★★★☆☆
- **作用**：候选应**输入即过滤、高频优先、最近使用置顶**；现在是**一次性给全部选项**（品牌列 `datalist`），品牌一多就要滚动找。
- **适用场景**：品牌/规格/口味这类枚举列。
- **补充**：可加 Excel 的 `Alt+↓` 展开**同列已有值**，服务自由文本列。

#### 2.4 候选来源应统一（不要每列各写一套）— 价值 ★★★☆☆
- **作用**：商品主档、品牌档案、规格，应走**同一个候选服务**，避免「A 列有下拉、B 列没有」的零散状态。

### 三、数据校验

#### 3.1 🔴 软警告分级：从「红＝错」扩展到「黄＝疑」— 价值 ★★★★★（差异化护城河）
- **作用**：错误之外增加**可疑提示**（黄）：
  - 本格数量 **> 上期 5 倍**（异常放量）
  - 本格数量 **= 0 但有历史**（**可能漏订** ← 经销商最怕这个）
  - 该客户**历史上不订这个品**
  - 订量 **远超安全库存**（超订预警）
- **适用场景**：报单结束前的**自查**；也适用于文员审核。
- **现状**：只有「错误」一档。**系统里已有全部原料**：对比期次、主动预警、货损预警、健康分、缺资料标记 —— **但没有一格接进单元格输入反馈**。
- **为什么高价值**：漏订 / 超订造成的损失**远大于**格式错误。而且这正是「AI 经营副驾」相对普通 ERP 的**差异化卖点**。

#### 3.2 校验上限应从「前端硬编码」改为「可配置」— 价值 ★★★☆☆
- **作用**：现在单格上限 `999999` 是**前端写死的常量**。应支持**按列 / 按客户**配（例：某客户单次上限 20 箱）。
- **适用场景**：连锁客户有单次订货上限；不同品有最小起订量。
- **附带**：前端限制**可被绕过** ⇒ 必须确认**后端也校验**（前端只是体验层）。

#### 3.3 「待修正 N 处」角标延迟 1.5 秒 — 价值 ★★☆☆☆
- **作用**：红框是**即时**的，但角标与错误清单有 **1500 毫秒节流** ⇒ 改完一格要等一下才知道「还剩几处」。
- **适用场景**：长表逐格改错的收尾阶段。
- **建议**：改到最后一格时应当**立即**更新（或缩短节流）。

#### 3.4 保存前预检 + 一键修复 — 价值 ★★★★☆
- **作用**：错误清单已能定位，但缺**批量修复**：「一键取整」「一键清空所有非法值」「只保留合法行」。
- **适用场景**：从 Excel 粘进来 50 行、其中 12 行是非整数 —— 逐个改很痛苦。

#### 3.5 跨格一致性校验 — 价值 ★★★☆☆
- **作用**：把**加单 vs 正单**、**合计(箱) vs 合计(小单位)** 的口径互证做成校验（这两个口径过去都出过事故）。
- **适用场景**：报单提交前的最后一道闸。

### 四、格式识别

#### 4.1 🔴 全角数字 / 中文数字自动转换 — 价值 ★★★★★（**中文用户最高频的隐性错**）
- **作用**：中文输入法下极易打出全角「１２３」。现在它的报错是「必须是数字」—— 用户看着屏幕上**明明是数字**，只会觉得系统坏了。
- **适用场景**：**所有中文输入法用户**，尤其是打「10」后忘切半角的每一次。
- **现状**：净化只处理千分位逗号，**不处理全角 / 中文数字**。
- **建议**：输入/失焦时**静默转半角**（无歧义，可直接转）；中文数字（「一二三」）可先提示再转。

#### 4.2 带单位串：从"只拒绝"到"识别并引导" — 价值 ★★★★☆
- 同 **1.2**（单位换算输入）。

#### 4.3 粘贴时的**列映射确认**— 价值 ★★★★☆
- **作用**：粘贴/导入 Excel 时，**先把「第几列 → 哪个字段」摆给用户看**，错了当场改，而不是错位一位就静默错列。
- **适用场景**：从舟谱 / 厂家系统 / 客户微信表**粘 20–200 行**（这正是本产品的核心数据入口）。
- **现状**：粘贴路径有**表头自动识别**（含阈值收紧），但**识别结果不可见、不可改**。而**导入流程已有「列映射确认」界面**（本项目技能库内）⇒ **两条路径应当同源**。

#### 4.4 表达式输入（`2*3+1`）— 价值 ★★☆☆☆
- **作用**：经销商算量时会用「3件+2件」这种写法。
- **注意**：属锦上添花，且需防误把编码当算式 ⇒ 只在**明确的数值列**启用。

#### 4.5 `type="number"` 对编码类字段的副作用 — 价值 ★★☆☆☆
- **作用**：数字输入框会**吞前导零**（`007` → `7`）、可能触发科学计数。对「数量」无害，但若**编码/条码类**字段用它，会破坏数据。建议编码类一律文本型。

### 五、快捷操作

| 项 | 作用 | 适用场景 | 价值 |
|---|---|---|---|
| **`Ctrl+Shift+方向键`（选中到边界）** | 现在的 `Ctrl+方向键` 是**移动**到边界，不是**选中**到边界 | 快速框选一整片客户列 | ★★★★☆ |
| **`Ctrl+Home / Ctrl+End`** | 跳到表格首格 / 末格 | 长表两端往返 | ★★★☆☆ |
| **「跳到最后一处有数据」** | 报单最常做的是「从上次填到的地方继续填」。现在只能 `PageDown` 近似 | 每天报单的**第一个动作** | ★★★★☆ |
| **撤销栈可见** | 现在 `Ctrl+Z` 可用，但**不知道能退几步、退的是什么**。非技术用户误操作后会狂按 Ctrl+Z，**越退越乱** | 每次误操作 | ★★★★☆ |
| **双击列边界自适应列宽** | 现在只能手动拖或右键设像素值 | 商品名长短不一时 | ★★☆☆☆ |
| **`Alt+Enter` 格内换行** | 备注类文本列 | 写退货原因 / 备注 | ★★☆☆☆ |
| **快捷键帮助的常驻入口** | 已实现首次自动弹，但缺一个随时可查的入口 | 用户想复习快捷键时 | ★★★☆☆ |

### 六、错误提示

#### 6.1 🔴 触屏读不到错误原因 — 价值 ★★★★☆
- **作用**：错误原因现在是**悬停提示**（`<td title>`）⇒ **触屏 / 平板完全读不到**；且悬停对非技术用户不直观。
- **建议**：加**格内角标**（像 Excel 的绿色三角）+ **点击 / 长按即显原因**。
- **适用场景**：与 **1.1** 同一批（平板报单场景），应一起做。

#### 6.2 从错误清单跳过去后应"闪一下" — 价值 ★★★☆☆
- **作用**：现在点一条错误会选中并滚动到那一格，但**没有临时高亮** ⇒ 用户点完还要自己在屏幕上找红框。
- **建议**：跳转后让该格**闪烁 1 秒**。

#### 6.3 错误清单可导出 — 价值 ★★★☆☆
- **作用**：文员/督导要把错处**发给销售去改**，现在只能截图或口述。
- **适用场景**：多角色协作（销售填、文员审）。

#### 6.4 保存被拦时明确"还剩几处" — 价值 ★★☆☆☆
- **作用**：保存失败时应直接说「还有 7 处待修正，已为你展开清单」，而不是笼统「保存失败」。

### 七、多端交互

#### 7.1 🔴 两端校验与候选**必须同源** — 价值 ★★★★★（数据安全级）
- **作用**：Web 端与小程序端是**两个独立录入面**，若校验规则、候选来源**各写一套** ⇒ 必然出现「Web 拦住了、小程序没拦」。
- **适用场景**：销售在小程序填、经销商在 Web 端审（**本产品就是这种分工**）。
- **建议**：校验规则与候选**下沉到后端作为唯一权威**，两端只做展示层。这与「Skill 下沉后端计算」的既定架构一致。

#### 7.2 🔴 并发编辑同一期次的冲突提示 — 价值 ★★★★★（数据安全级）
- **作用**：Web 与小程序同时改同一期次 ⇒ 现在可能**最后写入覆盖，静默丢数**。
- **适用场景**：老板在电脑上改单、销售同时在手机上报单。
- **建议**：至少给「此期次已被他人修改，请刷新」提示；更进一步用版本号做乐观锁。

#### 7.3 两端输入控件对齐 — 价值 ★★★★☆
- **作用**：小程序端已有**数字键盘 + 步进器**，Web 端没有；Web 端有**粘贴/填充/撤销**，小程序端用不了。同一个「填数量」动作，两端效率差一个量级。
- **建议**：**取长补短**，把步进器与 `inputmode` 给 Web（见 1.1 / 1.3），把「上期值候选」给两端（见 2.2）。

#### 7.4 移动端键盘遮挡 — 价值 ★★★★☆
- **作用**：手机上键盘弹起会**遮住正在编辑的格子**；而编辑表是**内部滚动容器**，常规的「滚动到可视区」可能不生效。
- **建议**：用 `visualViewport` 感知键盘高度并让位。

#### 7.5 触屏手势 — 价值 ★★★☆☆
- **作用**：编辑网格的**拖框选**在触屏上不成立（桌面版从输入框中间起拖也不成立 —— 已实测确认，见下方"既有局限"）；双指缩放与内置缩放的关系也需理顺。

#### 7.6 弱网 / 离线填报 — 价值 ★★★★☆
- **作用**：经销商常在**仓库 / 冷库**（信号差）报单。草稿已存本地（好），但**缺"离线可提交队列"** ⇒ 断网时改的东西网一恢复若处理不当可能丢。

## 3. 建议落地顺序

### 第一批（建议立刻做 · 低风险高收益）
1. **商品名称列补全**（含顺手修掉「商品名改动不进撤销栈」）
2. **数量格 `inputmode` + 触屏可读的错误原因**（平板场景一次补齐）
3. **全角数字转换**（几乎零风险，中文用户天天受益）

### 第二批（核心体验 · 需取数）
4. **数量列「上期值 / 常用值」候选**
5. **软警告（异常检测）接入单元格** ← 差异化卖点，建议做成**配方驱动**（不同客户规则可不同）
6. **让"选区批量填同值"进右键菜单**（功能已有，只缺入口）

### 第三批（数据安全 · 需后端配合）
7. **两端校验/候选同源**
8. **并发编辑冲突提示**

### 第四批（打磨）
9. 跳最后一处有数据 / 撤销栈可见 / `Ctrl+Shift+方向键` / 错误跳转闪烁 / 保存前预检一键修复 / 列上限可配

### 明确**不做**（红线）
- 公式引擎（用「计算列自动派生」替代，比让用户手填公式更稳）
- 任意合并单元格（会破坏数据模型与复制粘贴/权限逻辑）

## 4. 需拍板的取舍

1. **单位换算输入（1.2）**：我建议**做**，但必须"识别 + 确认"而非静默换算，且规格无定义的品**退回原行为**。做不做请你定。
2. **软警告阈值**：是**全局默认**还是**配方里可配**？我建议配方可配（契合多客户差异化）。
3. **验证范围**：以上清单是**读源码得出的**，落地前每一条都应在**真实租户的沙箱**里做真机取证（本轮 v210 已验证过这套方法可靠）。
