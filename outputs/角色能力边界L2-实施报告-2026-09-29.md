# 角色能力边界（L2）：从「换头像」到「服务端裁决的能力边界」

> v319 · 2026-09-29 · hergent-erp（后端）+ hergent-cn-v2（前端）
> 前情：`outputs/AI团队角色切换-设计评估-2026-09-29.md`（诊断出"切角色 = 只换头像"）

---

## 一、一句话结论

**角色的「技能包 / 数据范围 / 权限档」三轴，从"前端拼装的字符串"搬到了"服务端裁决"。**
角色不再只是人格标签：它现在决定 AI **能碰什么、能看哪些数据、能不能动手**，
而且这条边界由后端在每次请求时按「角色 ∩ 用户权限 ∩ 租户 AI 模式」现算，前端说了不算。

---

## 二、三轴与「空值 = 继承现状」（本轮最关键的设计决定）

| 轴 | 字段 | 空值语义 | 收窄方向 |
|---|---|---|---|
| 技能包 | `ai_roles.skills` | 空 ⇒ **继承全部技能包** | 角色配置 ∩ 技能包目录 |
| 数据范围 | `ai_roles.data_scope` | 空 ⇒ **继承用户自身的模块权限** | 角色配置 ∩ **用户模块权限** |
| 权限档 | `ai_roles.guard` | 空 ⇒ **继承租户 AI 模式** | 角色配置 ∩ **租户 AI 模式** |

🔴 **三轴的默认值都"什么都不改变"** —— 这是"上线对存量租户零行为变化"的唯一保证。
若把空值当"没有权限"，老板一升级就发现经营副驾不会订货了，**且零报错**（本项目最贵的一类失效）。
该不变量由单测 `test_B1_blank_means_inherit_all` 看守，并有反例对照
（把空值改成"没技能"⇒ 测试必须报红，实测报红）。

收窄方向都是"∩"：**角色不能给用户他本来没有的东西，也不能突破租户的 AI 模式**。

## 五、本轮抓到的两个真 bug（都是测试抓的，不是推测）

### ① 我把 AI 模式的取值域写错了

`role_caps` 里我凭印象写成 `settings` 表 + 默认 `"full"`。真实实现是
**`system_config` 表、取值 `auto / readonly / disabled`**，且 `erp_db.get_ai_mode()` 现成可用。
若照原样发布：`mode_allows_execute` 恒为 False ⇒ **所有角色都被降级成"只给建议"，零报错**。

### ② 剥离前端人设时"只试了一个前缀"（端到端测试抓的）

前端 system = 「人设 + 附加上下文」。后端要剥掉人设、留下上下文。
我只按"**完整人设（含格式协议）**"匹配 —— 当**前端人设与后端不一致**时
（角色刚被改过 / 前端缓存了旧版本），匹配失败 ⇒ **整段保留 ⇒ 同一段人设下发两遍**。
修法：`role_caps` 额外返回 `persona_raw`（未加协议的原始人设）作为**第二候选前缀**，
`strip_role_prefix` 先长后短依次尝试。

### 顺带一处架构缺陷

前端 system 原本混在 `messages[0]` 里，后端读的是独立字段 `d.system`
⇒ 后端的权威拼装**会被整条绕过**，而现象上一切正常。已在后端改为"先剥离 messages 里的 system 再加回"，
并由 `test_E5_system_in_messages_is_stripped` 看守。

   真隔离需要"工具 → 业务模块"的映射表，且 AI 取数主路径（Hermes 自己的工具/SQL）不在本仓可拦范围内。
4. 🔴 **另发现一个安全洞（本轮未修，需你拍板）**：Hermes 的 `hergent-erp-tools` 技能里写着
   认证方式是 `sqlite3 /opt/hergent-erp/erp.db "SELECT token FROM sessions ORDER BY rowid DESC LIMIT 1"`

   而 `/api/bot/*` 只验 token 不验模块 ⇒ 理论上存在**跨租户读写**的可能。
   修它要动 Hermes 技能内容（会改变 AI 行为）与 bot 鉴权，已超出"加能力轴"的范围，等你决定。

## 九、v319b 补丁：顶栏头像与角色选择器对齐（老板实测发现）

**老板反馈**：「角色头像不一致啊，要跟输入框角色选择器里的头像对齐」。

### 病根
副驾头部写死了品牌 logo：

```html
<img class="cp-ai-img" src="/favicon.svg" alt="Hergent" />
```

⇒ 切角色时**顶栏纹丝不动**，而输入框胶囊、消息气泡、角色菜单里都在显示当前角色的自定义头像 ——
同一个抽屉里"三处头像各说各话"。

### 修法（一处模板 + 一处 CSS）
顶栏改成与其余三处**同一套渲染**（自定义 PNG 优先、否则 emoji），容器样式统一到 `.msg-avatar` 那套
（圆形底 + 居中）：

```html
<span class="cp-ai-img" :title="(currentRole && currentRole.name) || ''">
  <img v-if="currentRole && currentRole.custom_avatar" :src="avatarUrl(currentRole)" class="cp-ai-img-png" alt="">
  <template v-else>{{ (currentRole && currentRole.avatar) || '🚀' }}</template>
</span>
```

并加了 `:title`（hover 显示角色名）——切完鼠标一悬停就知道现在是谁在答。

  **中文串双向无差**（本轮没加文案，只改渲染）⇒ **零夹带**

### 验证定式（本地 12/12 + 反例 4/12；生产真机 10/10）
🔴 **判别力双向都跑了**：同一探针在**旧包**（`dist-v319`）上 **4/12**（8 条红，含"顶栏不再指向品牌 logo"
变成 `favicon img=1`），在新包上 **12/12**。

🔴 **本轮抓到一个"探针自己的假绿"**（比产品 bug 更值得记）：

```js
// ❌ 错：在 .cp-ai-img **内部**找 favicon img
page.locator('.cp-head .cp-ai-img').locator('img[src*="favicon"]')
```
旧版的 `.cp-ai-img` **本身就是**那个 `<img src="/favicon.svg">` ⇒ 在它内部找 `img` **恒为 0**
⇒ 该断言在**旧包上也 PASS**（本应报红）。改成从整个头部找（`.cp-head img[src*="favicon"]`）后，旧包立刻变红。

🔴 **第二个坑：头像"指纹"必须覆盖两种形态**。真机 4 个角色**全部** `custom_avatar=1`
⇒ 渲染的是 `<img src="/api/ai/roles/<id>/avatar">`，**`innerText` 恒为空**。
只取 `innerText` 会同时造成两种错误：
- "两处头像相等" → 变成 **`"" == ""` 的恒真断言**（白测）；
- "头像是角色头像（非空）" → **假红**（当时报 8/10，差点误判成产品没修好）。

正解 = 指纹函数 `img.src || innerText`，两处都取。

🔴 **第三个坑：md5 不能用来判"两张图是否相同"**。顶栏 32px、胶囊 18px ⇒ 元素截图 md5 **必然不同**
（尺寸不同）。正解是比 **`img.currentSrc` + `naturalWidth/Height`**：
实测切换前后两侧均为 `256×256`、`complete: true`、`currentSrc` 逐字相同 ⇒ 同一张图、只是显示尺寸不同。
（我一度在整页截图上凭肉眼判断"两个小人颜色不一样"，靠这组元数据 + 元素级截图才排除 —— **别拿"看着像"当结论**。）
