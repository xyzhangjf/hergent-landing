## 摘要（一句话）

**自注册「已实现」但当前是邀请制（非开放）；「定价」有两套并存但都没有标价闭环；
「付款」完全不存在** —— 落地页的充值按钮是**未定义的死按钮**，后端积分充值/扣费两个端点
**因变量未定义必然抛 500**，且从未发生过任何一笔积分交易（生产流水 **0 行**）。

## 一、用户自注册流程 —— ✅ **已实现（但为邀请制，非开放注册）**

### 1.1 入口点

| 层 | 位置 | 说明 |
|---|---|---|
| 前端 UI | `hergent-cn-v2/src/pages/Login.vue:13` | 登录/注册切换 tab，文案「**免费注册**」 |
| 前端 UI | `Login.vue:44` | 注册表单（`<form v-else key="register" @submit.prevent="doRegister">`） |
| 前端 API | `hergent-cn-v2/src/api/client.js:102` | `export async function register(company, phone, password, { inviteCode = '', smsCode = '' })` |

| 后端端点 | `routers/auth.py:361` | `@router.post("/register")` |

### 1.2 触发条件与调用链

```
Login.vue「免费注册」tab
  → client.js::register()                        [client.js:102]
  → POST /api/auth/register                      [auth.py:361]
      ├─ _v(AuthRegister, d)                     Pydantic 入参校验
      ├─ 公司名 ≥2 / 手机号 ≥10 / _validate_password(密码)     [auth.py:372-381]
      ├─ _rate_limited("register:phone:…") / (":ip:…") 各 60s   [auth.py:389]
      ├─ 按 REGISTER_MODE 分派：invite / sms / open           [auth.py:405-417]
      │    └─ invite: invite_codes.reserve(码)   原子占用名额，防并发超发
      ├─ db.register_user_and_tenant(company, phone, password) [erp_db.py:13805]
      │    ├─ INSERT users (username, password_hash, display_name, role='boss', password_changed=1)
      │    ├─ INSERT tenants (name, subdomain, plan='free', max_users=5)

      │    └─ tenant_db_init(tid)                               ← 建租户库
      ├─ invite_codes.record_use(...)             核销流水（哪张码→哪个租户/账号/IP/UA）
      ├─ INSERT sessions (token, expires_at=+24h)              [auth.py:436-440] 自动登录
      └─ 下发 4 个 cookie：__Host-csrf / csrf_token / erp_token / hergent_tenant
```

### 1.3 注册涉及的核心逻辑

| 维度 | 实现 | 位置 |
|---|---|---|
| **校验** | 公司名 ≥2 字；手机号 ≥10 位；密码走**唯一实现** `_validate_password`（≥8 位且须含字母+数字） | `auth.py:372-381` |
| **节流** | 手机号、IP **各 60 秒**（原 600s，2026-09-12 调低） | `auth.py:389` |
| **准入** | `REGISTER_MODE` = `invite`（默认）/ `sms` / `open` | `auth.py:405` |
| **持久化** | `users` + `tenants` + `user_tenants` + **新建租户库** `tenant_<id>.db` | `erp_db.py:13805+` |
| **权限** | 新账号角色 = **`boss`**（自注册即最高权限，**无人工审核**） | `erp_db.py:13832` |
| **会话** | 注册即**自动登录**：写 `sessions`（24h）+ 下发 token/csrf/租户 cookie | `auth.py:436-448` |
| **审计** | `db.audit_log(…, f"自助注册: {company}", "auth")` | `auth.py:442` |

### 1.4 外部依赖

| 依赖 | 状态 |
|---|---|
| 短信通道 | **当前不需要**（`mode=invite`）。代码里 `sms` 分支原样保留，改环境变量即启用、**前端零改动** |
| 邀请码 | `routers/invite_codes.py`（原子占用 `reserve` / 归还 `release` / 核销 `record_use`） |

⚠️ **历史上曾 100% 失败**（代码注释自述，`auth.py:398`）：
> 原实现在生产恒走短信分支校验 `db._sms_code_cache[phone]`，而该属性全代码库只有这一处读取、
> 从未被定义或写入 → 恒为空 → **自上线起注册 100% 失败（HTTP 400）**。

### 1.5 线上实测（本次执行）

| 请求 | 结果 |
|---|---|
| `POST /api/auth/register` 无效邀请码 | **400** `{"detail":"邀请码无效，请向发码人确认"}` |
| `POST /api/auth/register` 密码 `onlyletters`（缺数字） | **400** `{"detail":"密码需要同时包含数字和字母"}` |
| `GET /api/auth/register-mode` | **200** `{"mode":"invite","need_invite":true,"need_sms":false,"hint":"邀请码制（内测阶段）…"}` |

⇒ 返回的是**业务校验 400**（而非代码崩溃 500），证明**注册链路代码是通的**。

## 二、定价与商业模式 —— ⚠️ **两套并存，都没有标价闭环，付款流程不存在**

### 2.1 第一套：租户套餐（`tenants.plan`）

| 项 | 位置 |
|---|---|
| 权威能力表 | `core.py:1533` `_PLAN_CAPS = {free/pro/enterprise → {view, export, api, max_users}}` |
| 派生函数 | `core.py::plan_caps(plan)` / `tenant_plan(tid)` / `user_plan_caps(user, tid)` |
| 存储 | `tenants.plan`（`erp_db.py:13079` 建表，`DEFAULT 'free'`）、`tenants.max_users` |
| 下发 | `GET /api/auth/permissions`、`/login`、`/me` 带 `plan` + `capabilities` |
| 展示 | `GET /api/platform/plans`（`routers/platform.py:956`，只读转发 `_PLAN_CAPS`） |
| 后台可改 | `hergent-admin` 租户管理下拉 + `PUT /api/platform/tenants/{id}` |

🔴 **`_PLAN_CAPS` 里没有任何价格字段** —— 套餐只有**能力差异**（能否导出 / API / 成员上限），
**没有金额**。也就是说：**套餐是"权限档位"，不是"价格档位"**。

### 2.3 🔴 积分写端点**代码级损坏**（两处，必然 500）

`routers/credits.py` 里，两个写端点都**先赋值给 `body`、随后却读 `d`**：

```python
# POST /api/credits/consume        routers/credits.py:47-50
try: body = await request.json()          # ← 赋值给 body
...
amount = d.get("amount", 0)               # ← 读 d（未定义）⇒ NameError ⇒ HTTP 500

# POST /api/credits/purchase       routers/credits.py:77-80
try: body = await request.json()          # ← 赋值给 body
package_id = d.get("package_id")          # ← 读 d（未定义）⇒ NameError ⇒ HTTP 500
```

（已用 grep 逐行确认：文件内**不存在** `d = …` 赋值。）

### 2.4 🔴 即便修好 `d`，`purchase` 也**没有任何支付验证**

```python
# routers/credits.py:83-91
pkg = next((p for p in pkgs if p["id"] == package_id), None)
new_balance = acct["balance"] + pkg["credits"]     # ← 直接加余额，无任何付款校验
db.credits_record_txn(uid, "purchase", pkg["credits"], new_balance, ...)
```

⇒ 任何已登录用户调用 `POST /api/credits/purchase` 即可**白拿积分**。
（当前被"演示租户只读闸门"意外挡住一部分，但正常租户不受影响。）

## 三、关联关系 —— ⚠️ **注册与定价几乎无关联，积分系统是孤岛**

| 关联点 | 是否实现 | 证据 |
|---|---|---|
| 注册时绑定套餐 | ✅ **部分**：新租户写死 `plan='free'`、`max_users=5` | `erp_db.py:13838-13840` |
| 注册响应下发套餐能力 | ✅ **有**：返回 `plan` + `capabilities`（派生自 `_PLAN_CAPS`） | `auth.py:452-465` |
| 注册时初始化**积分账户** | ❌ **无**（`register_user_and_tenant` 内无任何 `credits` 调用） | grep 无命中 |
| 注册时触发**计费初始化** | ❌ **无** | 同上 |
| 注册时**权限分配** | ✅ 有：角色固定为 `boss` + 写 `user_tenants` | `erp_db.py:13832` |
| AI 使用**扣积分** | ❌ **无**：扣分只存在于 `credits.py::consume`（且该端点 500），**没有任何业务链路调用它** | grep `credits_*` → 仅 `credits.py` 自身 |
| AI 调用记录 | ⚠️ 有，但**只是可观测性**：`ai_engine.py:341 _llm_log()` → 落 `llm_call_log`（主库跨租户），**不做扣费** | `ai_engine.py:341-371` |

**两个"说到没做到"的地方**（文案与实现不符）：

1. `hergent-cn-v2/src/components/CommandPalette.vue:70` 注释：
   > AI 已从"人人可用"改为**按需开通**（消耗积分有成本，默认只给管理员/老板）
   —— 后半句（按需开通）成立；**前半句"消耗积分有成本"不成立**（无任何扣分实现）。
2. 落地页承诺「**新用户注册即送 500 积分**」—— 落点只在 `electron-shim.js` 里 `toast("注册成功！已赠送 500 积分")`，
   **后端不落库、不建账户** ⇒ 纯前端文案。

## 四、结论标注

### ✅ 已确认实现（有代码依据 + 实测）

1. **自注册流程**（含前端入口、后端端点、校验、节流、邀请码准入、建租户/账号/关联、自动登录、审计）
   —— `auth.py:361` / `erp_db.py:13805` / `Login.vue:13`，**实测返回业务 400 而非 500**
2. **注册方式可配置**（`invite` / `sms` / `open`，改环境变量、前端零改动）—— `auth.py:405-417` + `register-mode` 端点
3. **邀请码机制**（原子占用防并发、失败归还、核销流水）—— `routers/invite_codes.py`
4. **套餐能力分层**（free/pro/enterprise 的能力表 + 派生 + 下发 + 后台可改）—— `core.py:1533`
5. **积分数据模型**（三张表 + 包定义 + 余额/流水查询端点）—— `erp_db.py:16427` / `credits.py`
6. **平台侧开租户且配账号**（`POST /api/platform/onboard`，建租户+建管理员+关联+回传密码）—— `routers/platform.py:177`
7. **注册流水可追溯**（后台「注册流水」页）—— `hergent-admin/src/views/Registrations.vue`

### ❔ 无法确认（证据不足，不做结论）

- 历史付费用户数 / 是否曾有真实收款（**推断为 0**：无支付实现 + 交易流水 0 行，但**未找到历史收款记录**，故不写死）
- 落地页 `submitRecharge` 是否为"曾实现后被删"（当前**无定义**是事实；"为什么没有"无法从代码判断）

### ❌ 缺失 / 未实现（明确）

| # | 缺失项 | 判断依据 |
|---|---|---|
| 1 | **开放注册** | 生产 `REGISTER_MODE=invite`；`open` 模式在生产还需 `ALLOW_SELF_REGISTER=1`，代码里该开关为默认关 |
| 2 | **任何付款/收款流程** | 无支付网关集成；落地页 `submitRecharge`/`refreshQR` 无定义（死按钮）；微信按钮 `disabled` |
| 3 | **积分扣费能力** | `POST /api/credits/consume` 读未定义变量 `d` ⇒ 必然 500；且无任何业务链路调用 |
| 4 | **积分充值能力** | `POST /api/credits/purchase` 同样读未定义变量 `d` ⇒ 必然 500；即便修复也**无支付校验** |
| 5 | **套餐标价** | `_PLAN_CAPS` 只有能力布尔值，**无金额字段** |
| 6 | **注册时初始化计费** | `register_user_and_tenant()` 内无 `credits` 相关调用 |
| 7 | **AI 使用计费** | `llm_call_log` 只做 tracing；全仓无"AI 调用 → 扣积分"的调用点 |
| 8 | **积分数据归属口径** | 表在**主库与租户库都存在**，实际读写走租户库（`get_db()`）⇒ 主库那份未被使用；跨租户同一用户会**各记一份** |

## 五、对本结论的自我限制（避免误导）

- 本报告只覆盖**代码与线上端点**，不覆盖商务侧（是否线下收款、是否有微信转账等外部安排）。
- 「积分端点必然 500」是**静态代码推断**（`d` 未定义），**未在生产实测**：
  实测需带正常租户凭据调用写端点，会产生数据副作用，故**未执行**。
  如需 100% 确认，建议**在测试租户**上打一次 `POST /api/credits/purchase` 观察返回值。
- 落地页与主站的关系：落地页 `/var/www/hergent-landing` 的注册入口指向 **`https://erp.hergent.cn`（旧前端）**，
  而 AI 副驾是 **`hergent.cn`（新前端 cn-v2）** —— 两者**不是同一个前端**，
  落地页引导过去的注册页与本次核查的 cn-v2 注册页**是两套实现**。
