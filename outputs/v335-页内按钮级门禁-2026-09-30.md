## 二、🔴 最重要的一条设计判据：「门禁用**接口模块**，不用**页面模块**」

`constants/pages.js` 的 `module` 只决定**入口显不显示**，与接口归属**经常不同**。若照页面模块写门禁，会造出「假入口」——按钮亮着、一点 403。实测分歧：

| 页面 | 页面 `module` | 写接口实际归属 |
|---|---|---|
| 客户档案 | `crm` | **data**（`/api/contacts`） |
| 员工档案 | `hr` | **data**（账号六件套 `/api/users/*`） |
| 渠道与价格 | `null` | **data** |
| 库存效期补录 | `stock` | **data**（`/api/import/*`） |

**这条判据已被真机探针活体证明**：把 `data` 收窄成 `["read"]` 后，`/data-fill` 页面（页面模块 `stock`）**入口仍在、页内「选择文件」按钮消失**。

### 动作 = HTTP 方法，不是业务语感

`GET=read`／`POST=create`／`PUT·PATCH=update`／`DELETE=delete`，另有 `server._READ_ONLY_POST` 白名单把「用 POST 做的查询」纠偏成 `read`。反直觉实例（按业务语感写就会「门禁撒谎」）：

- **「停用 / 启用」「重置密码」「撤销导入」「保存价格矩阵」「结算」「申领」「审核通过 / 驳回 / 冲销」** ⇒ 全是 **`create`**（走 POST）。
- 「编辑规则」按钮其实是**两种动作**：新建走 POST、编辑走 PUT ⇒ 同一按钮须按状态二选一（本轮唯一非字面量落点，见下）。

## 三、变更清单

### 1) 门禁机制定义处 —— `src/store/index.js`（v334 已埋，本轮复核）

```js
function canDo(module, action) {
  if (!module || !action) return true          // 代码缺陷 ⇒ 放行
  const pa = permActs.value
  if (!pa) return true                         // 不知道 ⇒ 不隐藏（fail-open）
  const star = pa['*']
  if (Array.isArray(star)) return star.includes('*') || star.includes(action)
  const acts = pa[module]
  if (!Array.isArray(acts)) return false       // 该角色没有这个模块（fail-closed）
  return acts.includes('*') || acts.includes(action)
}
```

三态纪律：`null` = 不知道 ⇒ **放行**；`{}` = 已确认没有 ⇒ **收窄**（形态守卫 `Object.keys(pa).length` 不可省）。

### 2) 两个新增 helper（`Forecast.vue`）

因 `/forecast` 的报单矩阵保存按钮同时受三重条件约束，抽成 computed 避免散落：

```js
const importBlockedReason = computed(() => (canDo('data', 'create')
  ? (periodDeadlinePassed.value ? lockHint.value : gateReason('导入预报订单'))
  : '当前角色没有「报单数据 · 新增」权限，不能导入预报订单'))
const canImport = computed(() => !noOpenPeriod.value && !periodDeadlinePassed.value && canDo('data', 'create'))
const canSaveMatrix = computed(() => canDo('data', 'create'))
const saveDisabled = computed(() => !canSaveMatrix.value || noOpenPeriod.value || periodDeadlinePassed.value)
```

### 3) 唯一「非字面量」落点 —— `Rebate.vue` 保存合同按钮

```html
<!-- 新建走 POST /api/rebate-contracts ⇒ create；编辑走 PUT …/{cid} ⇒ update。
     同一按钮两种方法，不能只取其一。
     保留按钮、置灰而非 v-if：这是表单最后一步，凭空消失会让用户以为「填完了却没了下一步」。 -->
<button v-else class="btn btn-primary"
        :disabled="!canDo('sales', editingContractId ? 'update' : 'create')" @click="saveContract">保存</button>
```

这一处**正是护栏 C6 判据的由来**（见下节）。

### 4) 写控件「置灰」而非「消失」的场景（系统化，非随手）

| 场景 | 处理 | 理由 |
|---|---|---|
| `Rebate` 合同弹窗保存（表单最后一步） | `:disabled` | 消失会让用户以为「填完了却没下一步」 |
| `Rebate` 达成三格 / 月度输入框 | `:disabled` / `:readonly` | 需保留表的形状 |
| `Forecast` 报单矩阵保存 | `:disabled` + `:title` 提示 | 按钮位置稳定，用户能读到原因 |
| `Forecast` 报单角标（note-badge） | 保留角标、不可点 | 角标是信息，不是操作 |
| `LossAccounting` 计价口径 `<select>` | `:disabled` | 同上 |
| `Forecast` 审批流五按钮 | `:disabled` 叠在既有状态条件上 | 不破坏原有状态机 |

## 四、静态护栏：`v335-button-gate-check.py`

**为什么必须有**：`canDo('M', …)` 里模块键写错时 `canDo` 是 **fail-closed** ⇒ **整页按钮消失**，而构建通过、运行期零报错、人工极难发现。护栏是本轮唯一的自动化防线。

### 六条判据

| 判据 | 内容 |
|---|---|
| **C1** | 动作 ∈ {create, update, delete} |
| **C2** | 模块 ∈ 后端 `_PATH_MODULE_MAP` 值域（**AST 直读 `server.py`，不维护第二份清单**） |
| **C3** | 逐文件模块白名单（`FILE_RULES`，含计数）—— 防「模块张冠李戴」 |
| **C4** | 用了 `canDo(` 必须已在作用域引入 |
| **C5** | 计数写死；新文件必须登记（防漏挂/多挂） |
| **C6** | **非字面量必须原样登记在 `NON_LITERAL_ALLOW`** |

### 五条反例自证（全 ✓）

```
[✓] C2 能证伪：错模块 `sale` 被拦截
[✓] C1 能证伪：错动作 `read` 被拦截
[✓] 正确写法 `data/create` 放行（不过敏）
[✓] 页面里写通配 `*` 被拦截
[✓] C6 能证伪：非字面量（三元）被拦截
```

### 🔴 C6 的由来（本轮最有价值的产出之一）

护栏首次运行报 `Rebate.vue 计数 32 ≠ 写死的 33`。**根因不是漏做门禁，而是护栏自己的盲区**：字面量正则看不见三元表达式 ⇒ **护栏给不出它看不见的那一类错误的判决**。加 C6（`ANY_CALL_RE` 抓全形态 − 字面量命中 = 必须登记）后，这条 C6 抓到的是**护栏自己的盲区**，不是代码的错。

**教训（已回灌技能）**：护栏的第一版设计必须假设「它会对某一类输入失明」，并把该类输入显式列为待登记项。

## 五、真机验收：`v335-button-gate-e2e.mjs`（17 项全绿）

### 为什么必须做（否则本轮等于没验）

生产 `/api/auth/permissions` 实测下发：

```json
{"dashboard":["read","create","update","delete"],
 "sales":["read","create","update","delete"],
 …,
 "data":["read","create","update","delete"]}
```

—— 库库存的是**旧格式 `list`**，后端 `normalize_perms_shape` 把它**展开成全动作**。于是：
- ✅ **零回归**：门禁今天**不隐藏任何按钮**（「不影响已有权功能」由**数据**保证）
- ⚠️ 但 **「门禁有效」未被证明** —— 页面一切正常，既可能是「门禁正确放行」，也可能是「门禁压根没生效」

⇒ **「零回归」与「门禁有效」会互相掩盖**，必须用响应改写把后者排掉。

### 做法：响应改写（不改生产数据）

拦截 `/api/auth/permissions`，只改**交给前端的那份 JSON**，把指定模块的动作收窄成只读。

### 结果

```
① 基线（不改写）         「选择文件」在=1；两个返利入口按钮在=1+1
                        自证 data/sales 各 4 个动作
② 收窄 data⇒read        自证收到 data=["read"]、sales 仍 4 个
                        页面未白屏（标题 1 + 未门禁「下载模板」1）
                        ★「选择文件」消失=0
                        ★对照组 /rebate 两按钮仍在=1+1（跨模块不塌陷）
                        入口数 4==4（页面模块 stock，不随 data 收窄）
③ 再收窄 sales⇒read     自证收到 sales=["read"]
                        页面未白屏（h3 1 + 未门禁「试算」1）
                        ★ 两个返利入口按钮都消失=0+0

零写入：非 GET 去重集合 = ["/api/rebate-rules/simulate-batch"]
        （仅页面自身的只读试算 POST，见第六节）
结果：17 通过 / 0 失败
```

### 探针自身的两条纪律（本轮踩过，已回灌）

**🔴 a) 必须强制整页重载到指定路由。** 第一版用 `page.reload()` —— 它留在**上一次**的 hash 上，于是 `/data-fill` 的「按钮消失」是**页面不对**造成的**假阳性**（把好产品报成坏产品，与放过坏产品一样贵）。改用 `?v=N#/hash`：查询串变化 ⇒ 必然整文档重载，hash 再定路由。

**🔴 b) 每阶段必须自证刺激真的落地。** 断言页面**实际收到**的 `permissions_detail` 形态（数字写死），否则「改写装置没生效」也会让正例通过。

**🔴 c) 断言值必须归一化。** 第一版把 `https://host/path` 与 `/path` 直接比 ⇒ 判据恒报失败，看起来像「有越权写入」，其实是探针自己比错了。

## 六、🔴 真实产品发现：只读 POST 白名单漏了兄弟端点

`server.py::_READ_ONLY_POST` 已登记 `/api/rebate-contracts/simulate`（返利模拟测算），但**未登记兄弟端点 `/api/rebate-rules/simulate-batch`**。

事实取证：
- `routers/rebate_rules.py:2059` 文档原文：「批量返利试算…**把返利算法唯一留在后端**」；同族 `/simulate` 注明「What-if 用，**不落库**」⇒ **纯计算、零落库**。
- 但白名单里没有它 ⇒ RBAC 中间件按 HTTP 方法判成 **`create`**。

**两个后果**：
1. 动作轴被污染：「收窄 `sales` 的新增动作」会连带堵掉一个**纯计算**端点。
2. **实际影响**：`/rebate` 页面**默认 tab（仪表盘）一加载就发 11 次** `POST /api/rebate-rules/simulate-batch`（全年 12 个月矩阵）。角色若被收窄成只读，**这一页一打开就会 403**，且前端 `catch` 吞掉 ⇒ **图表静默空白、零报错**。

**修法（待拍板，见第九节）**：在 `_READ_ONLY_POST` 补 `/api/rebate-rules/simulate`（`startswith` 前缀匹配，一并覆盖 `-batch`）。

## 九、需确认事项（沿承 v334，每条都影响别人正在用的东西，不擅自决定）

### ① 生产库权限值仍是旧格式 ⇒ 门禁今天不隐藏任何按钮

`erp.db`(1 行) / `tenant_1.db`(9 行) / `tenant_10.db`(7 行) 的 `role_permissions` **全部是旧格式 `list`**，新格式 `dict` 为 **0**（接口层由 `normalize_perms_shape` 展开成全动作）。
