## 一、冗余字段 / 按钮 / 功能的梳理与删减建议

### 1.1 建议删除（有确证）

| 2 | 图例 ① | `灰轨道＝目标 / 预估应返` | **与副标题逐字相同** → 删 |
| 3 | 图例 ④ | `深色段＝超出目标的部分` | 与副标题「深色段＝超出部分」同义 → 删 |
| 4 | 销量图 note | `柱高＝实际销量` | 第 3 遍讲柱高；紧邻小标题已写「销量达成」→ 删 |
| 5 | 返利图 note | `柱高＝实际返利金额` | 同上 → 删 |

#### R2【列表序号圈 `rr-rank`】

`Rebate.vue` 模板：`<span class="rr-rank">{{ idx + 1 }}</span>`；样式 `.rank-row.risk .rr-rank{background:rgba(var(--dan-rgb),.15);...color:var(--dan)}`。

- v151 已把「**返利达成排行**」改名为「返利目标达成」，并明确「混排品牌/商品、金额/数量，**不构成同质可排名集合**」；
  但序号圈留着 ⇒ 在**风险优先排序**下，序号会被读成「名次」，而**第 1 条恰恰是最危险的那条**。
- 风险行还把序号圈**染成红色**，视觉上更像"警示标记"而不是序号。
- 品牌筛选（`dashItemsFiltered`）重算后序号会**重排**，"第 N 条"的清单语义也随之失效。

**建议**：删除序号列；若确要保留"清单序号"，改为中性灰的状态点（`·`），避免与红色语义冲突。

---

#### R3【列表行内「距目标」是第三次表达】

实测一行完整文本：

```
1  测试月度品牌目标  测试品牌  [预警]  0.0%
   9月目标 ¥900,000 ｜ 已填报 ¥0 ｜ 距目标 ¥900,000 ｜ 达标可得 ¥72,000 ｜ 预计返利 ¥0 [看算式]
   ⚠ 预计月底仅达成 0.0%，建议补单/催款
```

`距目标` = `目标 − 已填报`，而**两个操作数就在左边紧邻**；`900,000 − 0` 是最容易心算的一种，信息量为零。

**建议**：删除**未达标行**的「距目标」段（`gapLabel === '距目标'`），空出的位置让给不可推导的信息（见二·增补 ★★☆「返利率」）。
⚠️ **注意不要误删**：v154 G5 已把**已达标行**的「距目标 ¥0」换成了「**超出 ¥X**」——超出行请**保留**，那是继续冲量的真实增量。
判据：按 `gapLabel` 分支，`'超出'` 保留，`'距目标'` 删除。

### 1.2 建议修改（口径 / 语义）

#### R5【页面主语缺失 —— 本轮最重的一条】🔴

**页面标题 =「实际返利仪表盘」，但 KPI 主数是「本月预估返利」，全页没有任何「实际返利」KPI。**

同一屏上并存 4 个"返利"，标签只差一个字：

| 数字 | 来源 | 性质 |
|---|---|---|
| KPI「本月**预估**返利」 | `simulate-batch`（按**当前填报达成**试算） | 推算值 |
| 列表「**预计**返利」 | 同上，逐行 | 推算值 |
| 图表「**实际**返利」柱（填充） | `rebate_achievements.actual_rebate` | **实际填报** |
| 图表灰轨道「预估应返」 | `simulate-batch`（按 **100% 目标**） | 推算值 |

**后果**：经销商最想知道「这个月到底能到手多少钱」，而这一屏给不出唯一答案；两个"预"字标签也不自证口径。

**建议**：
1. **KPI 增「本月实际返利」** —— 数据**已在手**：`achievements` 每行都带 `actual_rebate`，
   `/api/rebate-achievements?month=YYYY-MM` 已按当前统计月份加载（`loadAchievements()`），**零新接口**。
2. KPI「本月预估返利」标签改为「**本月应返**（按当前达成推算）」，让它自证口径。

🔴 **口径红线**："本月实际返利"必须与同页其余 KPI **同源同分母**（即同为「本月生效规则」集合）。
现成范式：达成填报侧 `buildAchvRows()` 已有一份按月求和（`Rebate.vue:1678` 的 `aRebate`），
**不要在仪表盘再写第二份口径**，应把它提到共用的纯函数里（同 `monthTargetOf` 的处理方式）。

| 2 | 图表图例 ③：`虚线＝本月时间进度应完成的金额` |
| 3 | 图表当前月柱上的虚线 `pace-line` |
| 4 | 列表图例 ③：`时间进度（虚线）` + 每行的 `rr-bar-mark` |
| 5 | hover 明细：`时间进度 60.0%` |

**判断**：#1 与 #3/#4 的虚线是**定量锚点，保留**；#2 与 #4 的两处图例文字各删一条（虚线已在图上，不必再用文字指认）。
⚠️ 属**可选项** —— 若删，需确认色觉障碍用户仍保有文字路径（v156 的注释专门为这点保留了 hover 成句）。

#### R7【品牌筛选候选集含无关项】

`chartBrandList` = `/api/brands?include_inactive=1` 的**全部档案品牌** ∪ 规则里出现过的品牌名
（`Rebate.vue:1477`）⇒ 含**已停用**品牌，且与"本期是否有目标"无关。

**后果**：选中一个本期无目标的品牌 → 图表与列表**全空**，而 KPI 不变（KPI 刻意不受筛选影响）——用户会以为页面坏了。

**建议**：候选以「本年度**确有品牌目标**的品牌」为主，档案品牌降级为分组；或至少在无目标的品牌后标注「（本期无目标）」。

- **C1** 删图表内 4 条重复说明 → 见 R1。

    **本轮不建议合并回去**。
  - **建议**：① 首月之前 / 末月之后的尾部空月**不占槽位**（或压缩为灰底窄条），12 槽自适应为「数据区间 ±1 个月」；

  建议灰轨道加深一档，或对"有目标无达成"的月份在柱底加 0 值提示。

### 2.2 增补（按业务价值排序）

## 三、整体美观与易用性优化方向

### 3.1 视觉重心错位（最值得改的一条）

实测配比：卡片 937px 中，**图表 562px（60%）｜KPI 100px｜列表 138px**。
在"就只有 2 根柱"的真实情形下，**页面最重的一块最空**。

**目标配比**：KPI 100 ／ 图表 ~420 ／ 列表与异常 其余，
阅读顺序也应随之明确：**先答"这个月怎么样"（KPI）→ 再答"全年走势"（图表）→ 最后答"具体谁要管"（列表）**。

### 3.2 色彩与语义

- **三色同屏且缺中性基调**：青（money KPI + 销量柱）、红（预警 KPI + 风险行 + 序号圈）、灰（空柱 + 轨道）。
  当前 0 达成时几乎全屏青 + 红；且 `¥0` 用 `kpi-hero.money` 的**青色渐变**呈现，看着像"有数据"。
  → 建议 `totalEstRebate === 0` 时 money 卡去掉青色渐变，改中性底 + 灰数字。
- **风险行的红色信号过多**：序号圈红 + `预警` 红标签 + 条形红 + `预计月底仅达成` 红 chip。
  v154 G3 已删掉 38px 红底横幅（方向正确）。→ 建议红色**只保留 2 处**（标签 + chip），
  条形颜色归还给 v151 定下的"节奏"语义，序号圈改中性。

### 3.3 布局与密度

| 位置 | 问题 | 建议 |
|---|---|---|
| 页头（40px） | 只有品牌筛选 + 统计月份，**缺页面级动作** | 补「去填报本期达成」主按钮（现仅空态有），把"发现问题→解决问题"闭环补齐 |
| 列表标题行（21px） | 塞了：标题 + 图例 4 项 + note + 跨页链接，密度过高 | 图例留 2 项，note 并入 hover；（窄屏已有 `.dash-legend-note{width:100%}` 兜底） |
| 图表图例 | 1024 视口**换行成两行**（`深色段＝超出目标的部分` 被挤下去），产生锯齿边 | 采纳 R1 删到 2 条即自然单行 |
| 列表仅 1 行时 | 卡片下方大片留白 | 用 2.2 的增补信息填充，**用信息填，不用空白填** |

### 3.4 易用性

- **跨页链接丢失上下文**：「实时达成（含预报贡献）→」实现为 `location.hash = '#/forecast'`（`goSprint()`），
  不带品牌筛选 → 用户在预报页看到的是**全品牌口径**，与刚才筛选的那一个对不上。
  → 建议携带参数（`#/forecast?brand=X`）。
- **统计月份控件风格不一致**：用原生 `<input type="month">`，Mac Chrome 下回显 `2026年09月` 并带日历图标，
  与图表年份选择器（`<select>`）视觉语言不统一（截图可见）。
  → 建议改为「‹ 2026年09月 ›」左右箭头 + 下拉，与图表年份控件对齐。
