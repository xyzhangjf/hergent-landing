## 一、丙 —— 「小程序账号」→「登录账号」（纯文案 + 适用端标注）

**问题**：员工档案里「小程序账号」「小程序权限」等字样写死共 7 处。而同一个账号**两端通用**
（网页端 + 预报小程序），文案把范围说小 ⇒ 用户在网页端场景**找不到入口**。

**改法**：

| 位置 | 改前 | 改后 |
|---|---|---|
| 页头副标题 | 维护员工底薪与**小程序权限**… | 维护员工底薪与**登录账号权限（网页端 / 小程序通用）**… |
| 表头 | 小程序账号 | **登录账号** |
| 弹窗区标题 | 小程序账号 | **登录账号** |
| 开账号提示 | 登录预报小程序 | 可用此手机号 + 密码登录**网页端**与**预报小程序** —— 同一个账号，能进哪些页面由下方角色决定 |
| 停用弹窗 | 其小程序登录账号… | 其**登录账号**… |

**顺带补齐角色下拉**：8 项，每项标注适用端，例：
`员工（仅小程序 · 报单 / AI 对话 / 库存）` · `会计（仅网页端 · 账务 / 报表 / 营销）`

> **「标了小程序」的角色集必须 == 后端有 `data`/`chat` 权限的角色集**
> （`admin / boss / sales / staff / supervisor`）。这条是硬断言，不是文案偏好 ——
> 标注比权限多说一个角色，用户就会按标注去开一个「开了也登不进去」的账号。

## 二、丁 —— 角色白名单（把「能写进任意角色名」的口子关掉）

**问题**：两个写入口此前**只校验「非空」**，外部字符串原样写进 `users.role`：

- `PUT /api/users/{uid}/role`（改角色）
- `POST /api/forecast-submissions/staff-accounts` → `erp_db.staff_account_create`（开账号）

而前端下拉里含 `boss`（几乎全开）与 `admin`（`_DEFAULT_PERMS['admin'] = ['*']`）
⇒ **任何 admin/boss 都能一键造出新的全权限账号**（提权面）。

**改法**：判据只写一份，放在 `core.py`：

```python
def known_roles():
    return set(_DEFAULT_PERMS.keys()) | set(ROLE_PERMS.keys())

def normalize_role(role, default=None):
    r = str(role or "").strip()
    return r if r in known_roles() else default
```

三处接线（改角色 API / 开账号 API / `staff_account_create` INSERT 紧邻处）。
非法值返回 `400 角色不合法：xxx。可选角色：admin、boss、accountant、sales、guide、driver、staff、supervisor`。

**两个设计取舍（都写进了代码注释）**：

1. **不另抄一份角色名表** —— 再抄一份就是下一个漂移源。判据 = 后端会真的拒绝请求的那份定义。
2. **取 `_DEFAULT_PERMS ∪ ROLE_PERMS` 而不是只用前者** —— `_check_perm` 查的是 `ROLE_PERMS`，
   写不进权限表的角色等于**「每个模块都 403 的僵尸账号」**（能登录、什么都打不开）。
   取并集是为了兼容「本租户自定义角色」。

**⚠️ 白名单不解决的部分（需拍板）**：它只关掉「写进任意角色名」，
**不阻止 admin/boss 给别人派 `admin`** —— 那是策略问题，属业务决定。

## 三、角色清单漂移收敛（同根因，三处）

**根因**：角色清单在四处各抄一份、四处都漏（员工档案 / Forecast / 小程序 / Settings）。
漏项的载体是 `MAP[x] || x` 这种写法 —— **缺 key 不报错、把英文原样吐出**，
与「正常英文值」无法区分 ⇒ 永远没人发现。

| # | 漂移 | 后果 | 修法 |
|---|---|---|---|
| 1 | `Forecast.vue` 的 `ROLE_LABELS` / `COLUMN_PERMISSIONS` 用了**后端不存在**的角色名（`owner`/`finance`/`promoter`/`dealer`，supervisor 叫「督导」） | 一旦 `bizRole` 真接上登录角色，**分销价列对所有真实角色（含老板）隐藏**，且界面上无处可改回来 | 统一到规范角色名；`COLUMN_PERMISSIONS.dist_price = ['admin','boss','accountant']`；`ENTRY_ROLES = ['admin','boss','accountant','sales']` |
| 2 | 小程序 `roles.js` 缺 `driver`/`guide`/`staff`，且 `accountant` 叫「财务」、`sales` 叫「销售」 | 三种角色显示为裸英文；同一角色两端叫法不同 | 补齐 8 角色，译名与网页端**逐字一致** |
| 3 | `roleText` / `roleName` 回落成原值（`\|\| role`） | **静默失败载体**：缺配置时看起来「正常」 | 改为显式 `未知角色( xxx )` —— 让漂移在界面上**可见** |

**新增前端唯一来源** `hergent-cn-v2/src/constants/roles.js`（8 规范角色 + 4 历史视图令牌 + `normRole` 归一）。
`normRole` 只做**词汇归一**（`owner→boss`、`finance→accountant`），**不能**把后端不存在的名字变成有效权限 —— 这条是本轮最容易搞错的地方。

**`canSeeCol` 失败方向取「宁可多显示」**：

```javascript
const allow = COLUMN_PERMISSIONS[key]
if (!allow) return true
const r = normRole(bizRole.value)
if (!isCanonicalRole(r)) return true   // 角色未知 ⇒ 不隐藏（本层不是安全边界）
return allow.includes(r)
```

> ⚠️ **本层目前是空转的**：全仓**没有任何地方给 `store.user.role` 赋值**（`Shell.vue` 只同步了 `user.name`）
> ⇒ `bizRole` 实际只取 localStorage 遗留值或默认值，两者都指向「全可见」。
> 也就是说「列级权限」现在既不隐藏任何列、也不构成任何保护。日后真接上会**立刻生效**。
> 且它**只是前端展示级隐藏**（列头、导出、接口照旧）—— 真正的列级隔离必须做在后端。

## 四、🔴 附带发现：预报主表整页崩溃（已修并上线）

**现象**：一进 `#/forecast` 就是整页「页面出错了　Maximum call stack size exceeded」。

**定位链**：真机探针 `body.innerText` 只有 43 字符 → 钩 `console.error` 拿到真实栈：

```
RangeError: Maximum call stack size exceeded
    at ae (Forecast-9MgijsDY.js:1:40996)
    at ae (Forecast-9MgijsDY.js:1:41003)   ← 递归 8 层
```

从构建产物反查源码，落在 `Forecast.vue` 的 `unitCount()`：

```javascript
// ❌ 原实现：自递归、没有出口
function unitCount() { return Array.isArray(cross.value.units) ? unitCount() : 0 }
// ✅ 本意显然是「返回客户列个数」
function unitCount() { return Array.isArray(cross.value.units) ? cross.value.units.length : 0 }
```

**定性**：用改前的生产包 `Forecast-DBH6sVK2.js` 正则扫描，**同样命中**
`function ae(){return Array.isArray(f.value.units)?ae():0}` ⇒ **该崩溃在我部署前就已上线**，
属并发会话 v199/v199b 的在途改动（`hidden_units`），**不是本轮引入的回归**。

**教训**：给 accessor 写兜底时，**兜底分支绝不能回落到 accessor 自己** ——
症状与它要防的那个（读 `undefined.length`）在界面上**长得一模一样**，只会更难查。
已入护栏（见下）。

## 七、本轮引入的护栏（防复发）

1. **`role-registry-consistency-check.py` 升级为 28 条硬断言**，新增：
   - 前端两页面**不得自带角色表**（防「护栏只看一处、漂移从另一处进来」）
   - `COLUMN_PERMISSIONS` / `ENTRY_ROLES` 的值**必须是规范角色名**
   - 「标了小程序」的角色集 **==** 后端有 `data`/`chat` 权限的角色集
   - `roleName` / `roleText` **不得回落成原值**（静默失败载体）
   - 跨面译名**逐字一致**
2. **`direct-self-recursion-check.py`（新）** —— 扫「`return` 表达式内无参数自递归」。
   两处必须做的实现细节，都是实测踩出来的：
   - **必须剥注释**（本轮的示例代码就写在源码注释里，第一版把注释当真代码报了出来）
   - **必须认正则字面量**（本仓有 `/[",\n]/` 这类写法；不认就会把正则里的 `"` 当字符串起始，
     与后面代码**错位配对**、吞掉几千行 ⇒ **漏报**）
3. **`dist_normalized_diffcheck.py` 增加「同一 chunk 改名」识别** —— Vite 会给被多处引用的共享
   chunk 挑**某个成员模块**的名字命名：本轮新增 `constants/roles.js` 后，283 kB 的 xlsx 共享 chunk
   就从 `arrival-*` 改名成 `roles-*`。**别当成「删了一个 + 加了一个」**。
4. **`hunk_index.py`（新）** —— 出一张「hunk 旧侧起始行 → 首条新增行」索引表。
   用于在**几百个脏项的长期工作区**里区分「本轮改动」与「并发会话在途改动」。
