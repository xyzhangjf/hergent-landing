# 商品档案页面对比与优化方案

> 对比基准：舟谱云管家「编辑商品」页面 vs Hergent 当前商品档案页面（含 v237/v238 已上线的中单位/大单位显示与编辑）  
> 日期：2026-09-21

---

## 一、整体结论（先说结论）

舟谱是把「商品档案」当成**ERP 核心主数据**来做的：字段全、tab 多、单位与价格体系完整，适合复杂业务，但信息密度高、学习成本也高。  
我们的页面目前更像「商品清单 + 快速编辑」：列表清爽、行内改价/改周期效率高、提交安全（diff 留痕），但**编辑弹窗还缺少系统性的信息分层**，单位、价格、业务控制字段混在同一屏，随着字段增加会越来越难用。

**优化方向**：吸收舟谱的「信息架构 + 单位体系 + 价格矩阵」，保留我们的「列表效率 + diff 提交 + 修改记录」。

---

## 二、各维度差异对比

### 2.1 信息架构

| 维度 | 舟谱 | Hergent（当前） | 差异说明 |
|------|------|-----------------|----------|
| 页面组织 | 5 个 Tab：基本信息 / 售价管理 / 图文详情 / 供应链信息 / 自定义标签 | 单页列表 + 编辑弹窗（所有字段平铺） | 舟谱按「主数据 → 价格 → 图文 → 供应链 → 自定义」分层；我们所有字段堆在一个弹窗 |
| 单位体系 | 独立「单位信息」区块，小/中/大单位各一张卡片 | 刚补了「包装单位层级」4 个输入框，但无条码、无默认单位 | 舟谱单位是业务控制单元；我们目前只是「名称 + 换算比」 |
| 价格体系 | 「售价管理」Tab，按单位展示批发/零售/最低/进价矩阵 | 编辑弹窗内平铺「标准售价 / 进价 / 分销价」 | 舟谱能看清同一商品在不同包装层级下该卖什么价 |
| 业务控制 | 业务范围（可销售/可退货/可采购）、状态、起订量、顺序号 | 只有「启用/停用」 | 我们缺少对采购、退货、销售的独立开关 |
| 扩展信息 | 图文详情、供应链信息、附件 | 无 | 舟谱支持图片、供应商、附件，我们为空白 |

### 2.2 页面布局

| 维度 | 舟谱 | Hergent（当前） | 评价 |
|------|------|-----------------|------|
| 列表页 | 无传统列表，直接进入编辑详情 | 传统表格列表，支持分页、筛选、行内编辑 | **我们更优**：经销商日常是「找商品 → 改一个字段」，列表效率更高 |
| 详情/编辑页 | Tab 横向切换，每个 Tab 内容一屏到两屏 | 单屏长表单，分「商品身份 / 包装单位 / 品牌别名 / 价格 / 库存效期 / 描述 / 状态」 | 舟谱扩展性更好；我们当前字段少时尚可，超过 15 个字段后 scrolling 疲劳 |
| 视觉分组 | 蓝色分组标题 + 卡片边框 + 标签页 | 灰色小标题 + 表单行 | 舟谱层级感强；我们偏朴素 |
| 操作按钮 | 底部「保存 / 保存并新增」 | 底部「保存 / 取消」+ 行内快捷编辑 | 我们保存路径更收敛，符合 diff 提交设计 |

### 2.3 字段展示

#### 舟谱有、我们暂无的字段

- 小单位条码 / 中单位条码 / 大单位条码
- 默认采购单位 / 默认销售单位 / 默认赠送单位
- 移动端开单可选（控制销售/主管在小程序能看到哪些单位）
- 业务范围：可销售 / 可退货 / 可采购
- 顺序号、起订量（小单位）
- 原产地
- 商品助记名

#### 我们有、舟谱没有的字段

- 到货周期（我们单独成列，舟谱没有）
- 进价历史回退显示（「取进价」状态）
- 批量补进价工具
- 修改记录（字段级审计）
- 报单单位（舟谱没有独立的「报单单位」概念，靠默认销售单位实现）

### 2.4 交互流程

| 维度 | 舟谱 | Hergent（当前） | 评价 |
|------|------|-----------------|------|
| 进入编辑 | 点击 Tab 进入详情页 | 列表行尾点「编辑」 | 我们路径更短 |
| 改一个字段 | 需在详情页找到字段、保存 | 列表行内直接改品牌/进价/到货周期 | **我们大幅领先**：减少 80% 点按 |
| 改价格 | 进入「售价管理」Tab，逐行填 | 编辑弹窗内改一个「进价」 | 舟谱能同时维护多单位多价格；我们快捷但维度少 |
| 提交安全 | 整表提交 | 只提交 diff 字段 + 留痕 | **我们更优**：不误覆盖、不造假记录 |
| 批量操作 | 导出/导入 | 批量补进价 + Excel 导入 | 基本持平 |

### 2.5 视觉设计

| 维度 | 舟谱 | Hergent（当前） | 评价 |
|------|------|-----------------|------|
| 色彩 | 蓝白主色，分组标题蓝色高亮 | 白灰主色，按钮蓝 | 舟谱层级引导强；我们更素 |
| 卡片 | 单位信息用卡片包裹 | 表单行直接排列 | 舟谱「小/中/大单位」三张卡片一眼可辨；我们刚补的 4 个输入框还比较散 |
| 表格 | 价格矩阵用表格展示 | 列表用表格，弹窗不用表格 | 价格矩阵天然适合表格 |
| 信息密度 | 高 | 中 | 我们当前对新手更友好 |

## 三、我们的优势（必须保留）

1. **列表 + 行内编辑**：经销商日常是「找商品 → 改一个字段」，行内改价/改品牌/改到货周期效率最高。
2. **diff 提交**：只提交真正改过的字段，避免误覆盖、不留假修改记录。
3. **修改记录**：字段级审计，可追溯。
4. **批量补进价**：针对快消品「到货后才知道真实进价」的场景，痛点抓得准。
5. **报单单位概念**：把「档案显示单位」和「实际下单单位」分开，避免 v217 的单位混乱复发。

---

## 四、我们的劣势（需要补齐）

1. **编辑弹窗缺少 Tab 分层**：所有字段平铺，字段一多就乱。
2. **单位体系不完整**：只有单位名 + 换算比，缺各层级条码、缺默认采购/销售/赠送单位、缺移动端开单可见性。
3. **价格管理维度少**：没有按单位展示的价格矩阵，也没有改价权限配置。
4. **业务控制字段缺**：没有可销售/可退货/可采购开关，没有起订量、顺序号。
5. **扩展页空白**：图文详情、供应链信息、附件上传都没有。
6. **列表列开始拥挤**：新增中单位/大单位后，小屏下横向空间紧张。

---

## 五、优化方案

### 5.1 优化目标

在不牺牲「列表效率」和「提交安全」的前提下，把商品档案升级为**结构清晰、单位完整、价格可管、未来可扩展**的 ERP 主数据页面。

### 5.2 关键改进点（按优先级）

#### P0 · 立刻做（本周）

**① 编辑弹窗改 Tab 结构**

把现有平铺表单拆成 4 个 Tab：

| Tab | 包含内容 |
|-----|----------|
| 基本信息 | 名称、规格、条码（只读）、厂家编码（只读）、单位、报单单位、分类、品牌、别名、状态、业务范围、顺序号、起订量 |
| 包装单位 | 小/中/大单位卡片（单位名 + 条码 + 换算比）+ 默认采购/销售/赠送单位 + 移动端开单可选 |
| 价格 | 进价、标准售价、分销价；为未来「按单位价格矩阵」预留入口 |
| 库存效期 | 安全库存、保质期、到货周期、描述 |

预期效果：信息分组与舟谱对齐，弹窗不再一眼看不到底。

**② 包装单位区块改成三张卡片**

参考舟谱布局：

```
┌─────────────┐  ┌─────────────┐  ┌─────────────┐
│  小单位      │  │  中单位      │  │  大单位      │
│  单位：杯    │  │  单位：组    │  │  单位：件    │
│  条码：____  │  │  条码：____  │  │  条码：____  │
│              │  │  换算：1组=8杯│  │  换算：1件=96杯│
└─────────────┘  └─────────────┘  └─────────────┘
```

下面再放一排：
- 默认采购单位：[下拉：小/中/大]
- 默认销售单位：[下拉]
- 默认赠送单位：[下拉]
- 移动端开单可选：☑ 小单位  ☑ 中单位  ☑ 大单位

预期效果：单位体系与舟谱同构，报单/采购/销售不再混淆。

**③ 列表页列宽优化**

当前中单位/大单位列较宽，建议：
- 中单位列标题改为「中包装」，内容格式保持 `条 · 1条=5杯`
- 大单位列标题改为「大包装」，内容格式保持 `件 · 1件=40杯`
- 名称列适当收窄，规格列收窄，给新列让出空间
- 小屏下隐藏「描述」「别名」等非关键列（当前本来就没显示，保持即可）

预期效果：列表不因为新增两列而拥挤。

#### P1 · 近期做（2–4 周）

**④ 新增「价格矩阵」能力**

在「价格」Tab 内增加一个子表格：

| 单位 | 批发价 | 零售价 | 最低售价 | 进价 | 允许业务员改价 | 允许查看成本 |
|------|--------|--------|----------|------|----------------|--------------|
| 杯   | 1.5    | 1.7    | 0.95     | 0.88 | ☑              | ☑            |
| 组   | 12.1   | 13.8   | 7.6      | 6.9  | ☑              | ☐            |
| 件   | 145.2  | 165.6  | 91.2     | 82.8 | ☑              | ☐            |

后端需要新增 `product_unit_prices` 表或扩展现有价格字段；先做小单位/中单位/大单位三行即可。

预期效果：与舟谱「售价管理」Tab 对齐，满足多单位定价需求。

**⑤ 增加业务范围控制**

在「基本信息」Tab 增加三个 checkbox：
- ☑ 可销售
- ☑ 可退货
- ☑ 可采购

与「启用/停用」是不同维度：停用 = 完全不可用；业务范围 = 可用但限制在哪些单据里出现。

预期效果：控制商品在采购/销售/退货单据中的可见性。

**⑥ 增加顺序号、起订量**

- 顺序号：整数，控制列表默认排序
- 起订量（小单位）：控制采购/报单时的最小下单量

预期效果：与舟谱对齐基础控制字段。

#### P2 · 未来做（按需）

**⑦ 图文详情 Tab**
- 商品主图、详情图上传
- 小程序端商品展示用

**⑧ 供应链信息 Tab**
- 供应商、厂家、原产地、供货周期

**⑨ 自定义标签 Tab**
- 用户自定义字段扩展

**⑩ 附件上传**
- 合同、质检报告等文件挂在商品下

## 七、实施建议

1. **先做 P0 三件套**：Tab 化 + 包装单位卡片 + 默认单位。这是当前最痛的点，改完后编辑弹窗立刻清爽。
2. **默认单位字段后端先行**：`default_purchase_unit` / `default_sale_unit` / `default_gift_unit` 需要在 `products` 表加列，前端再接 dropdown。
3. **价格矩阵放在 P1**：需要新增数据模型，且涉及小程序/报单/返利多处读价逻辑，影响面大，单独一轮做。
4. **业务范围控制后端影响**：改完后需要同步检查采购单、销售单、退货单、小程序商品列表的过滤条件。
5. **保持 diff 提交**：新增字段后，`EDIT_FIELDS` 和 `FIELD_CN` 同步登记，继续沿用「只提交真改过的字段」。

---

## 八、预期效果

- **信息架构**：从「单屏长表单」升级到「Tab 分组详情」，与舟谱同构，扩展性大幅提升。
- **单位体系**：小/中/大单位各含名称、条码、换算比，再叠加默认单位和移动端可见性，彻底解决报单/采购/销售的单位混淆。
- **价格管理**：从单一价格字段升级到按单位价格矩阵，支撑多层级定价。
- **列表效率**：保留行内编辑和快速筛选，列宽优化后不因字段增加而拥挤。
- **提交安全**：继续保留 diff 提交 + 修改记录，避免舟谱式「整表保存」带来的误覆盖风险。
