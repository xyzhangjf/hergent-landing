## 六、R7 补充落地 —— 品牌筛选候选收窄为「本年度确有品牌目标」

- **提交**：**`de41bd6`** — 3 文件，+63 / −9（`Rebate.vue` / `BrandFilter.vue` / 工具脚本）
- **生产**：已部署；归一化差集 29 项里**仅 1 项真变化**（`Rebate-HASH.js 177788 → 178255`），3 个关键文件 md5 双侧逐个相同

### 问题

候选原本取「品牌档案全量（含已停用）∪ 规则里出现过的品牌名」。档案里那些**本年度没有目标**的品牌被选中后，图表与「返利目标达成」列表全空、而顶部 KPI 仍照常显示 ⇒ 用户以为页面坏了。

### 改法

| 文件 | 改动 |
|---|---|
| `Rebate.vue` | `chartBrandList` 判据换成与图表消费方 `buildYearMatrix` **逐字同源**的两个测试：`∃ m ∈ 1..12` 使 `achvRuleActiveInMonth(r, y, m) && monthTargetOf(r, y, m) > 0` ⇒ 候选里出现的品牌，图表必然画得出至少一根柱 |
| `Rebate.vue` | 新增 watch：候选随「年份切换 / 规则增删」变化后，把**已选中但已不在候选**里的品牌剔掉并 toast 告知 —— 否则会留下看不见的筛选（chip 与徽标都不显示它、图表却空着） |
| `BrandFilter.vue` | 新增 `emptyText` prop，区分「搜索无结果」与「候选本身就是空」两种空清单 |

**两条关键约束**（已写进代码注释）：

1. 判据**不得**依赖 `chartBrandSel` —— `buildYearMatrix` 的 `measure` / `kept` 会随选中态变化，一旦引用就成环（候选 → 选中 → measure → 候选）
2. `ruleActiveInMonth` 必须 import **起别名** —— `Rebate.vue:2165` 另有一份同名本地实现（走本地时区），同名 import 会编译失败；而改用它又会与 `buildYearMatrix`（走 `Date.UTC`）错配

### 实测（本地打桩五场景 + 生产真机两路，全绿）

| 场景 | 期望 | 实测 |
|---|---|---|
| ① 2026 候选（档案 3 个、只有 A 有目标） | 只 `有目标品牌A` | ✓ B / C 被收窄掉 |
| ② 选中 A | 按钮 label 变品牌名 | ✓ `有目标品牌A` |
| ③ 切到 2025（B 有目标） | 候选变 B + A 被剔除 + toast | ✓ 「已取消筛选：有目标品牌A（2025 年无品牌目标）」 |
| ④ 切回 2026 | 候选恢复 | ✓ |
| ⑤ 规则全空 | 「本年度暂无品牌目标」 | ✓（非「没有匹配的品牌」） |

**生产真机**：打桩路**逐项复现本地结果**（证明生产包含本逻辑）；真实数据路候选 = `['测试品牌']`，与 tenant 10 唯一品牌规则一致。

### 口径说明（不是缺陷，记录备查）

「本年度」= `ruleActiveInMonth` 的日期范围判据，**不看 `target_year`**。年度规则若不填 `effective_start/end`（如 tenant 10 的「测试品牌」：`period_type=year`、日期为空、`monthly_amounts={'08','09'}`），则在**任何年份**都算有目标 ⇒ 候选在所有年份都出现。这与 `buildYearMatrix` 完全一致（同一对函数），故候选不会出现「图表画不出」的品牌。**刻意不加 `target_year` 过滤**：加了会把这类规则整个滤掉、候选直接变空。
