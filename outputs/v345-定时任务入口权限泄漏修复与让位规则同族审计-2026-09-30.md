## 一、一句话结论

你报的「郝洋的账号不该看到我的定时任务」——**不是权限没保存，也不是他的角色名单写错了**。

`/cron` 这一行同时写了「只给老板和管理员」（角色名单）和「要持有定时任务模块」（模块轴），但**漏了最关键的一道锁**。于是规则里的「用户配置优先」那一档被踩中：**只要你在权限页动过主管的权限，那道角色名单就会被让位掉**，改由模块轴单独裁决。而主管**确实持有定时任务模块**（不是谁勾的，是系统在 v296 拆模块时按「他原本调得通这个接口」自动补的），于是入口就漏了出来。

**已修**：`/cron` 加上锁 ⇒ 主管的侧栏入口消失，**连手敲网址也被拦回工作台**（这点比上一轮的档案管理更彻底）。真机验收 16/16 全绿。

## 三、根因：让位规则吞掉角色名单

### 3.1 入口判据长什么样

```
canSeePage(path, role, canModule, customRoles):
  ① 角色这一关（roleGateOpen）
       · 没写角色名单            ⇒ 过
       · 在名单里                ⇒ 过
       · 有产品硬锁 lock          ⇒ 不过
       · 没配模块                ⇒ 不过
       · 本租户没改过该角色权限    ⇒ 不过
       · 本租户改过该角色权限      ⇒ 【让位】过 ← 漏洞在这一档
  ② 模块这一关：必须有（或任一有）对应模块
```

`/cron` 原来的写法是：

```js
'/cron': { title:'定时任务', module:'cron', roles: ADMIN_ROLES }   // 没有 lock
```

`ADMIN_ROLES` 只有 admin 与 boss。**名单外的人本来进不来** —— 直到第 ③ 档「让位」把他放进来，接着模块轴一看「他持有 `cron`」，两道关都过了。

### 3.2 生产真值（只读查库，不是推断）

`ssh` 生产只读打开租户库：

| 角色 | 是否持有 `cron` | 是否持有 `bid` | 是否被改过权限（会触发让位）|
|---|---|---|---|
| **supervisor（郝洋）** | **持有**（read/create/update/delete 全给）🔴 | 持有 | **是** |
| boss | 持有 | 持有 | —（在名单里）|
| accountant | 不持有 | **不持有** | 是 |
| sales | **不持有**（实测调 `/api/cron` 返回 403 `MODULE_DENIED`）| 不持有 | 否 |
| 库管（自定义）| 不持有 | 不持有 | 是 |

⇒ 三个条件在**主管**身上同时成立：被改过权限 ＋ 持有 `cron` ＋ 不在名单。**这就是他看得见的原因。**

### 3.3 那个 `cron` 是谁给的？

不是你在权限页勾的。v296（9 月 27 日）把 `/api/cron` 从「档案管理」这个粗模块里拆出来时，按「谁原本调得通这个接口」给 **boss / sales / staff / supervisor 都补了 `cron`**（迁移脚本的目标角色表写得很明确）。

更关键的一步在**你撤主管「档案管理」权限的那次保存**：权限页保存的是该角色**当时的完整权限集**，于是迁移补进来的 `cron` **被一并落库、固化成一条显式授权**。此后主管持有 `cron` 就是「客户勾过的」，让位规则放行得更加理直气壮。

**一句话**：入口问的是「你有没有定时任务这个模块」，你以为它问的是「定时任务这一页该不该给主管看」。**两句话长得像，不是同一句。**

## 四、修复

`hergent-cn-v2/src/constants/pages.js`：

```diff
- '/cron': { title:'定时任务', module:'cron', roles: ADMIN_ROLES, cat:'admin' },
+ '/cron': { title:'定时任务', module:'cron', roles: ADMIN_ROLES, lock: true, cat:'admin' },
```

**为什么是加锁，而不是把他加进名单**：

1. `ADMIN_ROLES` 的注释原文就写着「**只要配置类页面（价格 / 接入 / 定时任务）—— 老板与管理员**」。你的意图和产品写法本来就一致，**是执行漏了一处**。
2. 同族的 `/ai-hub`、`/roles`、`/settings` 三行**都已经有这把锁**（它们挂的 `chat` 模块人人都有，不加锁就会被让位）。`/cron` 挂 `cron` 模块，当时以为「这是窄模块，没人有」，于是漏了 —— **而主管恰好有**。
3. 加锁的语义是「连客户配置也放不开」。定时任务是**租户级配置页**（页面副标题：AI 副驾的定时任务，结论可推送企业微信），本就不该给到非管理岗。

**影响面**：主管 / 会计 / 业务员 / 员工 / 司机 失去本页入口；老板与管理员不受影响。对这些人而言此前是「误得」，不是既有业务能力。
